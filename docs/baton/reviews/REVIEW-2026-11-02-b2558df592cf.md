## Findings

### P0: architecture fixture configs never committed (M5-01, M5-02, M5-03; `.gitignore:50`)

Scenario: `.mapx/` is ignored, so the 16 files under `tests/fixtures/arch-{rules,config}/*/.mapx/` are untracked (`git ls-files … | grep -c .mapx/` gives 0). On a fresh clone of `b2558df`, `npx vitest run tests/arch-*.test.ts` gives 12 failed and 28 passed (`TypeError: Cannot read properties of null (reading 'layers')`). Reproduced: yes, by the reviewer on a clone; this reviewer confirmed with `git check-ignore -v`.

Resolution: fixed. `.gitignore` re-includes `*.jsonc`, `architecture.baseline.json` and `architecture/` under `tests/fixtures/**/.mapx/`, while a scan's `mapx.db` stays ignored (checked). `tests/fixtures-tracked.test.ts` fails when any file under `tests/` is ignored; mutation-checked, it fails with the negations removed. A clone of HEAD plus the working-tree changes passes 4 files and 42 tests. **The 16 files still have to be committed.** The same root cause affects users (`mapx init` ignores `.mapx/`); the owner accepted that (D030).

### P1: Go embedding regression (M0-17-R5; `src/parsers/generic-wasm-parser.ts:196`, `src/core/scanner.ts:2467`)

Scenario: `import "example.com/m/api/v1"` (`package v1`) and `"…/internal/db"` (`package database`), then embedding `v1.UnimplementedFooServer` or `*database.Store`. Base `24902da` linked both; `b2558df` linked neither. Reproduced: yes, by the reviewer (HEAD against base) and by this reviewer's new test.

Resolution: fixed. When no import matches by name, the parser passes the unaliased imports as candidates, and the scanner links only if exactly one candidate project package declares the type. Tests added to `tests/legacy-language-accuracy.test.ts`: both edges, plus an ambiguous negative (two candidates both declaring `Logger` give no edge). They failed before the fix; the file passes 44/44.

### P1: Architecture profile shows its pills as HTML text (M4-24; `src/ui/main.ts:4365-4373`)

Scenario: M4-24 wrapped `renderYesNo(…)` (fixed markup) in `escapeHtml`, so every profile showed `<span class="profile-pill-bool no">No</span>` as text. Reproduced: yes (reviewer probe; the new smoke assertion failed with 0 of 3 pills).

Resolution: fixed. Unescaped again; `renderYesNo` added to `SAFE_CALLS` in `scripts/ui/check-escaping.ts`; `tests/ui/smoke.spec.ts` requires 3 pills and no `<span` text. The escaping check, its unit test, and the smoke and XSS specs pass (13).

### P1: stale architecture membership after a count-preserving sync (M5-03; `src/arch/membership.ts:158`, `src/arch/elements.ts:271`)

Scenario: the stamp read `getMeta('last_scan_time')`, which is never written (the scanner writes `last_scan_time:<repo>`), so it was only the three counts. Changing `namespace App\Domain` to `App\Infrastructure` and syncing returned the cached membership, with `Money` still in Domain. Reproduced: yes (reviewer probe; the extended cache test failed).

Resolution: fixed. `scanStamp()` in `elements.ts` reads every `last_scan_time%` row and is shared by `membership.ts`. The cache test adds a comment-only edit plus sync; it failed before the fix and passes 17/17 now.

### P1: arch scorer hides a correct finding behind a duplicate (M5-01; `scripts/eval/score-arch.ts:93`)

Scenario: duplicates were dropped by a key without `edgeType` before rows were matched, and a labelled `edgeType` must match. An `import` finding reported before the labelled `instantiation` finding gave matched 0, reported 1. Reproduced: yes (reviewer probe; new test failed).

Resolution: fixed. Findings are grouped, and a row matches any member of a group; each group counts once. New test added; 11/11 pass; the baseline is unchanged at 0.0.

### P1: the test suite writes into the checkout (M4-09; `tests/mcp-coverage.test.ts:364-425`)

The reviewer reproduced it with sentinels (`check-test-cwd.mjs tests/mcp-coverage.test.ts` exits 1). Orphaned `mapx.db-wal`/`-shm` files without a `mapx.db` also sit in the checkout's `.mapx/`.
