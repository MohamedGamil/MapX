# M2-06-R2 — HTTP pairing honours Route::domain

## Identification

Milestone: M2; priority: P2; risk: medium; estimate min/expected/max: 1/2/4 h; area: remediation (http).
Sources: `docs/baton/reviews/REVIEW-2026-10-31-2db08bd25e13.md` (P2 table), `docs/baton/reports/M2-06-R1.md` ("Review").

## Objective

A call with a host pairs only with routes on a matching domain.

## Dependencies

M2-06-R1 (hard). No approval gate.

## Scope

Review finding (reproduced with `review-F/pair-probe.ts` semantics): two `/users` routes under `Route::domain('admin.example.com')` and `Route::domain('api.example.com')`. A call to `https://api.example.com/users` pairs with the admin route through the lexicographic tie-break, and still does when only the admin route exists. `pairCall` never reads `route.metadata.domain`, which Laravel already emits (M1-07-R2).

- `pairCall` skips a route with a `domain` when the call's URL has a host the domain does not serve.
- **Domain pattern** (`domainPattern`, cached):
  - literal labels compare case-insensitively;
  - a `{param}` label matches exactly one label (`[^.]+`, as Laravel compiles domain parameters);
  - an unevaluated `{dynamic}` part matches any text, because MapX cannot know it;
  - a scheme or port written in the domain is ignored.
- **Unchanged:** routes without a domain, and calls without a host (relative URLs go to whichever host serves the page).
- **Fixture** (`tests/fixtures/vue-http`): the Laravel fixture already has `GET /ops/v3/status` on `Route::domain('ops.example.com')` (L123, M1-07-R2). Two labels exercise it in a real scan:
  - **L47 `domain-mismatch`:** the `api.example.com` client calls `ops/v3/status`. Expected unmatched.
  - **L48 `domain-match`:** a new `VITE_OPS_URL=https://ops.example.com` client calls the same path. Expected `HomeController@opsStatus`.

## Out of scope

- Making a route's literal domain a workspace host on its own. Hosts still come from `.env*`, client base URLs and `settings.http.hosts` (M2-06-R1).
- Registration order between a domain route and a domain-less route with the same URI (Laravel takes the first registered). A tie still falls to the lexicographic order.
- Non-Laravel host constraints (Express vhost, Django hosts).

## Implementation plan

- `src/frameworks/http/pairing.ts`: `domainPattern()` and the domain check in `pairCall`.
- `tests/http-pairing.test.ts`: the review scenario in both route orders, the admin-only case, a local host, `{account}` wildcards (one label, case), a `{dynamic}` domain, domain-less routes and relative calls. The fixture's unmatched-call list gains L47.
- Fixture: `vue3/src/services/domains.ts` (new), `labels.json` (L47, L48), `vue3/.env` (`VITE_OPS_URL`).
- `docs/cli-reference.md`: one sentence on domain matching in the pairing rules.

Blast radius: `pairCall` is called only from `Scanner::pairHttpCalls` (`src/core/scanner.ts`) and tests. The impact output is in the report.

## Expected outputs

The fix, the tests, the fixture labels, `docs/baton/reports/M2-06-R2.md`.

## Acceptance criteria

1. A call to `https://api.example.com/users` pairs only with a `/users` route whose domain matches (`{param}` domain segments as wildcards), never with an admin-domain route. Tests: "pairs a call with the route on its own domain, never with an admin-domain route", "treats {param} domain segments as one-label wildcards, case-insensitively", and fixture L47 in "reports the unserved and unmounted-route calls as unmatched".
2. The HTTP scorer gate holds. The registered scorer command exits 0 and does not drop: identical totals on the pre-task fixture, and precision 1.0 on the extended fixture (0.976 before the fix).
