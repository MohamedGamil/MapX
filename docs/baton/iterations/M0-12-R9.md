# M0-12-R9 — Python namespace packages are not search roots for absolute imports

## Identification

Milestone: M0; priority: P2; risk: low; estimate 1/2/3 h; role: import resolution.
Sources: `docs/baton/reports/M0-12-R7.md` (independent review, reviewer J).

## Objective

`import json` in a namespace package (PEP 420, no `__init__.py`) or below a regular package never resolves to a sibling `json.py`.

## Dependencies

M0-12-R7 (hard), DONE.

## Scope

`resolvePythonImports` builds the absolute-import roots from the file's ancestors.
- **Before:** every ancestor without `__init__.py` was a root.
- **Now:** a folder is no root when it is a package or inside one (below the topmost `__init__.py` folder). The workspace root is always a root (D018: a source-root rule from the first version was removed after review).
- **Unchanged:** a script's own folder with neither above it stays a root (`py/scripts/run.py` importing `helpers`).

## Out of scope

`sys.path` settings from configuration (`PYTHONPATH`, `[tool.setuptools] package-dir`).

## Acceptance criteria

1. `import json` in `py/pkg/data/reader.py` (`pkg` has `__init__.py`, `data` has not) gives no edge to `py/pkg/data/json.py` (`tests/legacy-imports.test.ts`).
2. `import logging` in `ns/src/nsp/app.py` (no `__init__.py` anywhere) gives no edge to `ns/src/nsp/logging.py`, while `import nsp.logging` does (same test).
3. A script folder with a sibling module imported by name still resolves (`py/scripts/run.py`, existing case).
