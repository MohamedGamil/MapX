# M0-05-R4 — MCP parity for Laravel relationships and bindings

## Identification

Milestone: M0; priority: P2; risk: medium; estimate min/expected/max: 2/3/5 h; role: MCP / CLI surface.

## Objective

`mapx_query` lists a model's Eloquent relationships and `mapx_dependencies` lists a provider's abstract → concrete bindings, exactly as `mapx query` and `mapx deps` already do (review 2026-10-31, P2).

## Dependencies

M0-05-R2 (hard, DONE): `modelRelations` / `describeRelation` and the CLI bindings block.

## Scope

- Move the CLI's binding rendering into a shared helper next to `modelRelations` (`src/core/relations.ts`), so the CLI and MCP render bindings with one function.
- `mapx_query`: class results gain a `relationships:` block (same lines as the CLI).
- `mapx_dependencies`: a file with `binding` edges gains a `Bindings (abstract → concrete):` block.
- Tests in `tests/legacy-laravel-surface.test.ts` that drive both tools through a real MCP client (`InMemoryTransport` + `buildServer`) on the scanned 11-file Laravel fixture.
- `docs/mcp-integration.md`: document the two new blocks.

## Out of scope

- File-name resolution in `mapx_dependencies` (`AppServiceProvider` → path); the MCP tool keeps taking an indexed path. Not part of this criterion.
- Hook-edge verifiability and middleware-group expansion (M0-05-R2 findings, separate tasks).

## Implementation plan

1. `src/core/relations.ts`: add `fileBindings(store, file)` returning `{abstract, concrete, bindingType}` rows and `describeBinding`.
2. `src/cli.ts`: `deps` uses the helper (output unchanged).
3. `src/mcp.ts`: `mapx_query` and `mapx_dependencies` append the blocks.
4. Tests first: they must fail on the current `src/mcp.ts`.

## Expected outputs
