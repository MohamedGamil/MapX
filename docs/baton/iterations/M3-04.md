# M3-04 — `<script setup>` macros and composables

## Identification

Milestone: M3; priority: P1; risk: medium; estimate min/expected/max: 6/10/14 h; role: parser / graph resolution.
Sources: docs/reports/2026-10-30-laravel-vue-coverage-findings.md §3 item 11, §4 item 9; the edge contract in `iterations/M3-01.md`; reports M3-01, M3-02 and M3-03.

## Objective

A Vue component's interface (`props`, `emits`) is readable from its component symbol, and a composable `useX()` and the functions destructured from its result link to the composable's file through the import, not by name.

## Dependencies

- M3-01 (fixture): `tests/fixtures/vue-sfc`, `scripts/eval/score-edges.ts`, floors in `tests/vue-sfc.test.ts`. DONE.
- M3-02 (interface): `componentSymbol()` and the `metadata.vue` resolution hint (`resolveVueReference` in the scanner). Delivered on develop.
- Parallel lanes: M3-05 (Vuex / Pinia, rules 7 and 8) and M3-06 (router, rule 9) edit `vue*.ts` and maybe `scanner.ts`. This lane keeps its logic in its own module and its hooks small.

## Scope

Edge-contract rules owned here (iterations/M3-01.md, "Edge contract"):

- **Rule 1 metadata.** The component symbol's `metadata` gets `props: string[]` and `emits: string[]` (and `exposes: string[]` for `defineExpose({ … })`, not scored) when the component declares them:
  - `defineProps<{ id: number }>()` (type literal, or a same-block `interface` / `type` alias), `defineProps({ … })` (object keys), `defineProps([ … ])` (strings), each also inside `withDefaults(…)`;
  - `defineEmits<{ (e: 'a', …): void }>()` (call signatures, union literal types), `defineEmits<{ a: [x: number] }>()` (3.3 named tuples), `defineEmits([ … ])`, `defineEmits({ … })`;
  - Options API `props:` / `emits:` (array or object) fill them too (not scored).
- **Rule 4, composables in script code.** In a Vue SFC's script blocks:
  - a call to an imported `useX` (named or default import, not a Pinia `use…Store`, which rule 8 / M3-05 owns) resolves through its import to `useX` in the imported file;
  - a call to a name destructured from an imported call (`const { persist } = usePreferences()`) resolves to the inner function `persist` in that module's file, within the scope of the destructuring. Value flow is followed no further.
  Both use M3-02's `metadata.vue` hint, so they fail closed: no fallback to global name lookup. This makes `persist` / `addReply` principled (M3-02 noted they resolved only because their names are unique).
- Floors: `script-setup-macro` raised to its labelled count; `composable` stays at its labelled count; precision must not drop.

## Out of scope

- Pinia `useXStore()` and store actions (rule 8), Vuex (rule 7): M3-05. Router (rule 9): M3-06.
- Value flow past one destructuring (`const p = usePrefs(); p.persist()`), composables re-exported through barrel files (fail closed, recorded as a limitation), `defineSlots`, `defineModel`, `defineOptions`, props from imported types.
- Template calls (already resolved through M3-02's regex `destructured` bindings).

## Implementation plan

- `src/parsers/languages/vue-script-setup.ts` (new): tree-sitter analysis of one script block (`analyzeScriptBlock`) returning the interface (props, emits, exposes) and the composable bindings with their scopes; `annotateComposableCalls(analysis, refs)` attaches `metadata.vue` hints to matching `call` references; `mergeInterface()` folds the blocks' interfaces into the component symbol's metadata.
- `src/parsers/languages/vue.ts`: two small hooks (analyse each script block; set the component metadata).
- Shared tree-sitter helpers: `withScriptTree`, `optionsObject`, `keyOf`, `valueOf`, `stringValue` from `vue-ast.ts` (extracted by M3-05, which landed during this lane; the first draft exported them from `vue-options.ts`).
- `src/core/scanner.ts` (added during the lane): `resolveVueReference`'s `from` lookup goes through `moduleMember()`, which follows up to three barrel re-exports and, for an alias specifier the import resolver cannot place (`@/x` where `@` is `resources/js`, `~/x`, `#/x`), the repo's module whose path ends with `/x`. Without these, routing composables through their import would lose edges that the old name lookup found (barrels, Laravel's `@` alias).
- Tests: `tests/vue-script-setup.test.ts` (unit tests of the macro forms; end-to-end temp workspace with a same-name trap: a second module defining `persist` / `useUser`); a fixture trap file and negative label in `tests/fixtures/vue-sfc`; raise the `script-setup-macro` floor.
