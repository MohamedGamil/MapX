# M7-05-R1 — First Pages deployment: the environment refuses main, and the site base path has the wrong case

## Identification

Milestone: M7; priority: P1; risk: low; estimate min/expected/max: 1/2/3 h; role: CI. Remediation of M7-05 (DONE is terminal: this is the defect record).

## Objective

The Pages workflow deploys from the branch the `github-pages` environment allows, and the site is built for the address Pages really serves.

## Defects

1. **The deploy was refused.** The first run, on `main`, failed: "Branch "main" is not allowed to deploy to github-pages due to environment protection rules." The environment has one custom branch policy, `develop` (GitHub derives it from the default branch, which is `develop`). M7-05 had assumed `main` without reading the environment (it listed this as a likely first-run failure but did not check).
2. **The base path had the wrong case.** The repository is `MapX`. A Pages address is case-sensitive in that segment: a public check showed `/TypeScript-Website/` served and `/typescript-website/` a 404. The site was built for `/mapx/`, copied from the lowercase name in `package.json` without checking, so every asset URL would have been a 404 once a deploy succeeded.

## Fix

- The workflow triggers on `develop` and its deploy job is guarded for `refs/heads/develop` (owner decision, asked 2026-11-07; the other option was to add `main` to the environment's allowed branches).
- The default base is `/MapX/`, and the Pages build sets `SITE_BASE` from `github.event.repository.name`, so a rename or a case difference cannot recur.
- The tests read `DEFAULT_BASE` instead of twenty `/mapx/` literals; one test pins the case, with the reason.

## Out of scope

- Changing the repository's environment settings (not needed with develop), a custom domain, the gamil.io certificate.

## Verification

- `npx vitest run tests/site-workflow.test.ts tests/site-build.test.ts`
- `npx playwright test -c playwright.site.config.ts`
- `npm run site:build`
- `npm run check`

## Recovery

Revert the task commit. Nothing is deployed until the owner pushes to `develop`.
