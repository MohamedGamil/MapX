# M5-02 — Architecture config: JSONC schema, loader, extends/parameters, validate-config

## Identification

Milestone: M5; priority: P1; risk: low; estimate min/expected/max: 6/8/12 h; area: arch, config.
Sources: `docs/research/deptrac/02-abstract-feature-model.md` AR-11 (configuration document), AR-14 (views), AR-05 (policy operators); Deptrac `imports`/`parameters` semantics in `01-deptrac-capabilities.md` §8; D013 (file name and location).

## Objective

A typed, validated in-memory `ArchitectureConfig` loaded from `.mapx/architecture.jsonc` (and `.mapx/architecture/<view>.jsonc`), with `extends`, `%parameter%` substitution and semantic validation, plus a published JSON Schema for editor completion. Every later M5 task consumes this type instead of raw JSON.

## Dependencies

None. M5-03 (hard) consumes it. The fixture configs written in M5-01 are its first real inputs, but M5-01 is not a dependency: M5-02 ships its own minimal test documents.

## Scope

1. **`src/arch/schema.ts`:** the `ArchitectureConfig` TypeScript types for AR-11: `extends`, `parameters`, `scope { types, exclude }`, `policy { inferred, inheritDependencies, uncovered }`, `visibility { internalTags, nativeMarkers }`, `layers[] { name, group?, overlay?, selectors[], private?[] }`, `rules` (layer → allowance list; an allowance is a string with the `+` / `!` prefix or `{ allow, types, severity }`; `*` as a key), `baseline`, `report { groups, hidden }`. Selector keys are the AR-04 list; unknown keys are errors (no silent typos).
2. **`schemas/architecture.schema.json`:** generated from or hand-kept in step with `schema.ts`, with a test that every selector key and policy option in the types appears in the schema. Shipped in the npm package.
3. **`src/arch/config.ts`:**
   - `loadArchitectureConfig(dir, { view? })` reads JSONC with the same parser `workspaces` uses (M0-10-R1), resolves `extends` depth-first (relative files, and `mapx:preset/<id>` ids resolved through a registry that M5-17 fills; unknown ids are errors), later documents override layers by `name` and merge `rules` per source layer;
   - `%name%` substitution from `parameters` in `name`, `path` and `package` selector values;
   - semantic validation returning **all** errors at once, each with a JSON-pointer path: unknown layer in `rules` or in a `layer` selector, unknown selector key, `+` cycle (named, e.g. `A → B → A`), circular `extends`, duplicate layer name, overlay layer used as a rule source, `parameters` reference with no value.
   - a `ConfigError` carrying the list, used by M5-05 for exit code 3.
4. **`tests/arch-config.test.ts`:** fixtures under `tests/fixtures/arch-config/` (valid base + view + preset-id case; each error case as its own document) asserting exact error paths and messages; a round-trip of the AR-11 example document.

## Out of scope

- Selector evaluation and layer membership (M5-03); rule evaluation (M5-04).
- The `mapx check` CLI and `arch validate-config` surface (M5-05, M5-08) — this task exposes the loader only.
- Shipping presets (M5-17): the `mapx:preset/` resolver takes a registry and ships empty.
- A Deptrac YAML importer (recorded out of scope in `05-requirements.md`).

## Implementation plan

New files `src/arch/schema.ts`, `src/arch/config.ts`, `schemas/architecture.schema.json`, `tests/arch-config.test.ts`, `tests/fixtures/arch-config/**`. One existing file: `package.json` `files` gains `schemas/` (M4-05 also edits `package.json` for the build; the change is one array entry and does not conflict). No change to `src/core/config.ts`; the architecture config is a separate document. Blast radius nil for existing behaviour; confirm with `npx tsx src/main.ts impact loadConfig` that nothing routes through the new module.

## Expected outputs

The four source/test files, the schema, the config fixtures, and `docs/baton/reports/M5-02.md`.

## Acceptance criteria

1. Invalid documents yield all errors at once with JSON-pointer paths (test: a document with four distinct errors produces exactly four entries, in document order); `+` cycles are reported as errors naming the cycle.
2. `extends` chains resolve depth-first with later files overriding layers by name and merging rules; circular `extends` is an error naming both files (tests with a three-file chain and a two-file cycle).
3. `%parameters%` substitute in `name`, `path` and `package` selector values; an unresolved parameter is an error with the selector's pointer.
4. `schemas/architecture.schema.json` ships in the npm package (`scripts/check-package.ts` lists it) and validates the AR-11 example document.
