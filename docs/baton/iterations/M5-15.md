# M5-15 — Dashboard Architecture view and /api/arch endpoints

## Identification

Milestone: M5; priority: P3; risk: medium; estimate min/expected/max: 10/12/16 h; role: dashboard and API engineer.

## Objective

The dashboard shows the architecture rules of `.mapx/architecture.jsonc` (M5-01…M5-16): a layer diagram whose edges drill down to the concrete dependencies (file:line), a layer DSM coloured by policy, a filterable findings table, health tiles, and a declared-layer overlay on the graph. Three read-only endpoints serve it: `/api/arch/report`, `/api/arch/layers` and `/api/arch/edges`.

## Dependencies

M5-05 (hard, `mapx check` and its report), M5-13 (hard, `layerGraph`/`layerDsm`). Uses M5-08's introspection (`layerMembers`, `layerDependencies`, `unassignedElements`) and M5-16's `ruleSmells` on the same evaluation. No approval gate.

## Scope

- **API (`src/ui-server.ts`)**, every endpoint GET-only in effect and writing nothing:
  - `/api/arch/report`: `{ configured, valid, … }`. With a valid configuration: the M5-13 layer graph and layer DSM built from the report `mapx check` builds (baseline applied), health figures (violations, warn-level, baseline debt, uncovered, unassigned, rule smells; `trend: null`, since no snapshot stores architecture counts), the findings `mapx check --report-uncovered --report-skipped` would show (allowed ones only counted) and M5-16's rule smells, all from one evaluation (`ctx.evaluation()`).
  - `/api/arch/layers`: each layer with size, group, colour and hidden flag, and per file its non-overlay layers (the overlay); unassigned files. `?layer=L` gives L's members with the selector that matched (`layerMembers(…, { why: true })`).
  - `/api/arch/edges?from=A&to=B`: the concrete dependencies of the pair (`layerDependencies`), each marked `skipped` when the report baselined it.
  - **No configuration:** 200 `{ configured: false, hint }` naming `mapx arch init`. **Invalid configuration:** 200 `{ configured: true, valid: false, errors }`. Unknown layer: 404; missing `from`: 400.
  - **Repos (M4-21):** the rules are evaluated over the whole workspace, as `mapx check` does. `repo=<name>` (404 when unknown) narrows the findings, members, unassigned files and concrete edges to that repo; the graph, DSM and health stay workspace-wide, and the view says so.
- **View (`src/ui`)**: the Architecture tab gets sub-tabs, "Overview" (the existing content) and "Layer rules" (new): health tiles, a layer diagram (Cytoscape, already bundled: groups as compound nodes, edges per status), the layer DSM, the findings table with kind, rule, layer and verifiability filters, a drill-down panel (edge → dependencies, layer → members with selector). Rows open the file in the graph's details panel. The graph toolbar gets a "Declared layers" overlay toggle with a legend; unassigned files grey.
- **Escaping:** every layer name, path, message and selector goes through `escapeHtml`, and `scripts/ui/check-escaping.ts` passes.

## Out of scope

- Writing or editing the configuration from the dashboard (read-only, M4-22; `mapx arch init` is M5-17).
- Architecture trends over time: no snapshot stores architecture counts; a store change would be its own task.
- Views (`.mapx/architecture/<view>.jsonc`) in the dashboard: the default configuration only.
