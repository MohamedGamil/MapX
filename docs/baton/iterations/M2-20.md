# M2-20 — CommonJS `require` of a local module gives import edges

## Identification

Milestone: M2; priority: P1; risk: medium; estimate min/expected/max: 3/6/10 h; role: parser and resolver engineer.

## Objective

`const x = require('../x')`, `const { f } = require('./y')` and `require('./z').g()` give file-to-file import edges and import-bound call edges, as ES imports do. `module.exports = …`, `module.exports.f = …` and `exports.f = …` count as the module's exports. A package require (`require('express')`, `require('node:fs')`) stays external (M2-08-R3).

## Dependencies

None registered. Builds on M2-08 (import-bound calls), M2-08-R1 (barrels, D032 sync), M2-08-R3 (externals never link project symbols), M2-09 (member-assigned functions) and M2-12 (calls on new instances, the closed-chain rule).

## Scope

- **Import edges.** A `require('<string>')` call is an `import` reference in the JS and TS queries (both TS grammars), resolved like an ES import specifier. A computed specifier (`require(name)`) gives none.
- **Bindings.** `const x = require('./x')` (whole module), `const { f, g: h } = require('./y')` and `const f = require('./y').f` bind names to the module. A whole-module binding called bare (`x()`, `new X()`) resolves to what `module.exports = X` exports. The declarator the parser turns into a function symbol (`const X = require(…)`, M0-17-R5) no longer shadows its own binding.
- **`require('./z').g()`**: a query pattern and parser metadata (`required`); the scanner links the module's export `g`, or no edge.
- **Exports.** `module.exports = function name() {}` and `module.exports = class Name {}` declare `name` / `Name` (JS symbols query). `module.exports = { a, b: c, m() {} }`: `b` resolves to `c`; a key whose value is no declaration links nothing rather than a homonym. An ES default import of a CommonJS module takes `module.exports = X`.
- **Barrels.** `module.exports = require('./a')` and passing on a required name (`module.exports = { f }`, `exports.f = f`) are followed, and count as barrels for sync.
- **Externals.** A package require keeps M2-08-R3's behaviour; `require('pkg').f()` is an external-reference candidate.
- **Sync.** With import edges in place, D032 re-parses requirers when a required module's export signature changes.
- `EXTRACTOR_VERSION` → 20 (18 and 19 are Lane E's).

## Out of scope

- TS `import x = require('./x')` (already an import), AMD `define`, `require.resolve`, `require.context`.
- `module.exports = { ...require('./a') }` spreads and `Object.assign(module.exports, …)` (name lookup, as before).
- An anonymous `module.exports = function () {}`: no symbol, so its bare-call requirer links nothing.
- Name lookup from scripts (CommonJS files are scripts for M2-08-R3's global rule), unchanged.
- `src/core/import-resolvers.ts` (Lane E); JS specifiers resolve through `resolveImportPath` in scanner.ts.
