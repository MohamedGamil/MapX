# M2-08-R4 — Sync follows a file turning from module to script

## Identification

Milestone: M2; priority: P2; risk: low; estimate min/expected/max: 2/3/6 h; role: resolution engineer.

## Objective

When a JS/TS file turns from an ES module into a script, or a module gains `declare global` names, the names it now puts in the global scope link the files that use them by name, after `sync` as after `scan --force`.

## Dependencies

M2-08-R3 (hard, DONE): the global-scope rule (`globalScopeFilter`) and the `globalScope` metadata with `globalScopeReferrers`, which cover the opposite direction.

## Cause (probe, 2026-11-04)

A synthetic workspace was scanned with the real CLI on `develop@b6a7103`, once without git (hash sync) and once committed (git sync):

- `legacy/plain.ts` is a module: `export function plainGlobal()`. `legacy/use.ts` calls `plainGlobal()` with no import. No edge, as `scan` gives (an ES module's un-imported name reaches only scripts and `declare global` names).
- `g/decl.ts` is `export {}; function declared()`, and `g/use.ts` calls `declared()`. No edge either.
- Both providers are edited into scripts (the `export` lines removed). `sync` says "Updated 2 files … 0 edges updated" in both modes; the edges stay absent. `scan --force` gives `legacy/use.ts#usePlain -> plain.ts#plainGlobal` and `g/use.ts#useDecl -> decl.ts#declared`.

Cause: `globalScopeReferrers` re-parses the files with edges *into* the changed file when its recorded `globalScope` differs. A file that should *gain* an edge has none yet, and the store keeps no trace of the name it looked for: a reference that resolved nowhere produces no edge, and `external_ref_candidates` holds only names bound by an import from outside the project, never a bare un-imported name.

## Scope

- **Record what each parse looked for.** When `globalScopeFilter` reaches its last branch for a bare name, the name is one the ES module neither imports nor declares and which no auto-import tool supplies: it can reach only scripts and `declare global` names. The parse records these names in `files.metadata.globalNameRefs` (sorted, omitted when empty; the file row is replaced by every re-parse, so a name no longer reached is gone), as `unresolvedImports` does for M2-08-R2. The names are recorded whether or not an edge resulted.
- **Find the files to re-parse.** `globalScopeReferrers` already compares a changed file's recorded `globalScope` with its new text. It now also computes the names the file gained (`gainedGlobalNames`):
  - now a script: every identifier in its text. A script's symbols (functions, every declarator of `var a, b`, class and object-literal methods, member assignments) are reachable by bare name, and the sync runs before the file is parsed, so the identifiers are used as a complete, cheap superset (decided in the review: the first version's regex missed the second declarator and the members);
  - a module: the `declare global` names the recorded key lacks (all of them after a script). `declaredGlobalNames` now reads every declarator of a `const`/`let`/`var` list and `function *gen`, which also makes `scan` agree with this;

  One pass over the files whose metadata contains `"globalNameRefs"` then adds every file recording one of the gained names. All three sync paths (`scan` incremental, git sync, hash sync) reach it through `importerReferrers`.
- **Cost.**
  - A sync with no changed JS/TS file, or none whose global-scope key changed, adds nothing (a metadata read per changed JS/TS file, as before).
  - A sync with one that gained names reads the metadata of the files holding any `globalNameRefs` once (a `LIKE` scan of `files.metadata`, the shape `newModuleReferrers` already uses for `unresolvedImports`), and parses the JSON of those only. No file is parsed that does not record one of the gained names; the whole workspace is never re-parsed.
  - Storage: one short JSON array on each ES module that references an un-imported, un-declared bare name. It is empty for most files, and the array is bounded by the file's distinct such names.
  - A file turned script over-reports gained names (every identifier, references included), which can re-parse a file that only shares a name the script merely uses. That costs one extra parse, never a wrong edge; a turn from module to script is rare.
- **`EXTRACTOR_VERSION` 24 → 25**, since unchanged files in an older index lack the record: the next scan or sync re-parses everything once.

## Out of scope

- **A new declaration in any file** (a new script, or a new global function appended to an existing script) does not re-parse files that reference its name. The same record could serve it, but the trigger and the new-file path (`takeReferrers`, `newModuleReferrers`) differ, and no task owns it yet; the M2-08-R3 limitation stands for it, and is recorded in the report as a follow-up.
- **Sync, other inputs** (a bare specifier becoming a workspace package, a new file under `baseUrl`): M2-08-R3's limitation, unchanged.
- **A name reached through a base class in another file** (`resolveClassName` with the base's file) is not recorded.
- **Rename or move into a script, and a new declaration in any file:** M2-08-R9.
- **References that resolve through `Vue`/`Svelte` sources, receivers, or auto-import tools:** they never reach the global branch, so they record nothing.

## Acceptance criteria

1. A module edited into a script: after `sync`, a file that calls its now-global function by name has the same edge as after `scan --force`, with git sync and with hash sync; only the edited file and that user are re-parsed (`Updated 2 files`), not a bystander that records another un-imported name. Test: "a module edited into a script …" in `tests/import-bound-externals.test.ts`, run for `git` and `hash`.
2. A module whose `declare global` block gains a class: after `sync`, a file that names the class by name links it, equal to `scan --force`, `Updated 2 files`, for both modes. Test: "a `declare global` block gaining a class …".
3. A module edit that gains no global name re-parses only the edited file (`Updated 1 files`); a file that stopped naming the name is not re-parsed (the record is cleared on re-parse); a script that stays a script keeps its referrers' edges. Tests: the last three in the same `describe.each`.
5. `npm run eval` holds every floor with the printed numbers unchanged, and the MapX self-scan edge dump is unchanged apart from edges that were already missing relative to `scan --force`.
