# M0-02-R2 — Inbound edges survive a file disappearing and coming back; filters in sync and JSON export

## Identification

Milestone: M0; priority: P1; risk: medium; estimate min/expected/max: 4/6/10 h; role: scanner (incremental indexing, glob filters), exporters.

## Objective

Incremental scans restore edges into re-added files, and every path (scan, sync, every export format) honours the filters.

## Dependencies

M0-02-R1 (hard), DONE. The review's `shouldExcludeDir` rewrite stays, and its test "prunes directories named by a pattern, and only those" must keep passing.

## Scope

- **P1: inbound edges into a deleted-then-restored file.** Deleting a file drops every edge into it. When the file comes back, its referrers are unchanged, so no scan path re-parses them, and the edges stay lost until `--force` (a branch switch triggers this).
  - Whenever the scanner removes a file, it now records the files whose edges pointed at it, in `meta removed_files:<repo>`.
  - When the file is indexed again, by `scan` or by `sync` (git or content-hash), those referrers are re-parsed once.
  - With git, `sync` diffs against the last scanned commit, so a file deleted and restored in the working tree with HEAD unchanged was never re-indexed at all. `sync` now also re-checks the recorded removed paths on disk.
- **P2: `sync` ignored config filter changes.** `sync` compares the effective filters with `meta scan_filters:<repo>` (M0-02-R1). When they differ, it runs the full-scan path, which re-parses everything once.
- **P2: the JSON export kept clusters and memberships of excluded files.** `GraphExporter.exportAsJSON` now filters memberships to the exported files and clusters with `filterClustersToFiles`, the filter TOON and LLM already use. A TOON test is added, since its cluster filter mutant survived the review.
- **P2: Laravel default excludes could not be dropped one by one.** `settings.laravelDefaultExcludes` accepts `true` (default), `false`, or the list of default patterns to apply. Defaults are scoped to a non-root repo's path, `**/*.blade.php` included, so they cannot reach sibling repos. Documented in `docs/configuration.md`.
- **P2: scan-time `./` and Windows-style patterns.** Patterns are normalised (`\` → `/`, leading `./` dropped) in the shared matcher and in directory pruning. Tested at scan time.

## Out of scope

- A new file that satisfies references which never resolved before (it was never deleted): referrers are not known. That is the general "unresolved references" problem and needs a stored reference index.
- Git renames (`R old new`): `getChangedFiles` reports only the new path. This is noted as a finding.
- Recomputing `fileCount` for clusters that keep some exported files.

## Implementation plan

- `src/core/store.ts`: `getReferrers(path)` returns the distinct source files of edges into a path.
- `src/core/scanner.ts`:
  - `removeFiles(repo, paths)` replaces the three deletion loops and records referrers;
  - `takeReferrers(repo, paths)` consumes them;
  - the full, hash and git paths re-parse the referrers;
  - the git path re-checks recorded removed paths;
  - `filterSignature(repo)` is shared by scan and sync;
  - `effectiveExcludes` gets the list form and the prefix fix;
  - pattern normalisation in `buildMatcher` and `shouldExcludeDir`.
- `src/exporters/graph-exporter.ts`: filter clusters and memberships.
- `src/types.ts`: `laravelDefaultExcludes?: boolean | string[]`.
- `docs/configuration.md`: document `laravelDefaultExcludes` and pattern normalisation.
- `tests/legacy-globs.test.ts`: end-to-end tests (temp workspace → real `init`/`scan`/`sync`/`export` → store or output).

## Acceptance criteria

1. The inbound edges of `app/Services/UserService.php` (from `User.php` and `UserController.php`) return, identical as (source, target, type) triples, after it is deleted, scanned and restored. This holds for plain `scan`, for `sync` without git (content hash), and for `sync` in a git repo, both after a working-tree delete/restore and after a branch switch.
2. `sync` after `app/Services/**` is added to, and then removed from, `excludePatterns` gives the same files and edges as `scan --force`.
3. `export --format json --exclude 'app/Models/**'` lists no membership of an `app/Models/` file and no cluster made only of excluded files. The TOON export drops the `App.Models` cluster.
4. `laravelDefaultExcludes` set to the default list without `public/**` indexes `public/index.php` while Blade views stay excluded. A non-root Laravel repo's defaults are prefixed with its path, including `**/*.blade.php`. The setting is documented.
