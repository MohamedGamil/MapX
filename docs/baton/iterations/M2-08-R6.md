# M2-08-R6 — A bare specifier never resolves to a relative project file

## Identification

Milestone: M2; priority: P2; risk: medium; estimate min/expected/max: 2/4/6 h; role: resolution engineer.

## Objective

`import x from 'express'` and `require('express')` in a JS, TS, Vue or Svelte file never resolve to `./express.js` or another file found by reading the specifier as a path from the repo root. A bare specifier resolves only through a `paths` or `baseUrl` entry of the nearest tsconfig/jsconfig, or a bundler alias MapX reads.

## Dependencies

M2-08-R3 (hard, DONE): the `baseUrl` probe and the "positively outside" rules this builds on. M2-20 (DONE) made `require('x')` an import reference, which is how the defect reached CommonJS.

## Cause (probe, 2026-11-04)

A synthetic workspace was scanned with the real CLI on `develop@3afa180`. At the repo root: `express.js`, `components/Button.tsx` and `lib/thing.js`; `package.json` lists `express`; no tsconfig, no alias.
- `server.js` with `import express from 'express'; import { thing } from 'lib/thing'; import { Button } from 'components/Button'` got three import edges (`express.js`, `lib/thing.js`, `components/Button.tsx`) and a verified call edge for each of the three calls.
- `legacy.js` with `require('express')` and `require('lib/thing')` got import edges to `express.js` and `lib/thing.js`, and a verified call edge `b call express.js#express`.

Under a CRA jsconfig (`{"baseUrl": "src"}`, `cra/src/utils.js`), `import { helper } from 'utils'` and `import * as u from 'utils'` keep their import and call edges (verified, and inferred for `u.helper()`).

Cause: `resolveImportPath` (`src/core/scanner.ts`) ends its candidate list with the specifier itself, `bases.push(target)`, for a bare specifier as well as a relative one. After the aliases and the `baseUrl` entry fail, `express` is probed as the repo-root path `express(.js|.ts|/index.js …)`. M2-20 routed `require('x')` through the same function, so CommonJS got the defect as well. Node and tsc never do this: a bare specifier names a package unless `paths`, `baseUrl` or an alias maps it.

## Scope

- **`resolveImportPath`:** for a JS, TS, Vue or Svelte importing file, a specifier that is neither relative (`.`) nor absolute (`/`) is no longer probed as a path from the repo root. Aliases (`paths` including `*` patterns, bundler aliases, `@/` and `~/` fallbacks) and the `baseUrl` entry still come first and unchanged. A root-relative URL (`/lib/thing.js`, as Vite serves it) is a path and still probes. Files of other languages keep the fallback: a C `#include "util.h"` and a shell `source lib.sh` resolve through it.
- **Both import and `require`:** one code path (M2-20), one fix; both are tested. A Vue SFC and a Svelte component take the same path and are covered.
- **Workspace packages (added by the independent review):** a bare specifier naming a workspace package (a folder holding indexed files whose package.json `name` it is, as `npmWorkspacePackageNames` already reads them) resolves to that folder, after `paths` and `baseUrl`. `name` is the package entry: `exports` (`.` as a string or the `import` / `default` / `require` / `node` / `types` condition), `module`, `main`, `types`, then `index` and `src/index`. `name/sub/path` is an `exports` subpath or pattern (`./utils/*`), then `<folder>/sub/path`. The probe adds the usual extensions and `index` files. It works for nested folders and names that differ from the folder (`packages/core` named `@acme/kernel`). Before the review the first version of this change dropped these edges; at `develop` they resolved only by accident, through the root probe, for packages in root folders.
- **`baseUrl` in a referenced tsconfig (review):** a solution-style tsconfig.json (`{"files": [], "references": [...]}`) takes its `baseUrl` from the first referenced config that has one, as `paths` already follow `references`.
- **Sync:** the unresolved-import record (M2-08-R2) is unchanged, since bare specifiers were never recorded. Sync and `scan --force` now agree where they diverged: a project `express.js` added later linked `app.js` on `scan --force` but not on sync.
- **`EXTRACTOR_VERSION` 26**, so an index that holds the false import edges is rebuilt.

## Out of scope

- **M2-25 limitation, a baseUrl one-segment import and a destructured call** (`import u from 'utils'; const { helper } = u; helper()` loses its by-name edge). It is not the same mechanism. The loss is in the parser (`isPackageSpecifier(spec, true)` in `src/parsers/generic-wasm-parser.ts` drops the reference at parse time, before any resolver or tsconfig is known), not in import resolution. The task's own example, `import { helper } from "utils"` under `{"baseUrl": "src"}`, already keeps its edges and is tested here as a guard. A fix needs the parser to hand the specifier to the scanner; registered as M2-25-R1.
- **By-name lookup for an import MapX cannot place** (`import { thing } from 'lib/thing'` beside a project `lib/` folder keeps a by-name call edge, M2-08-R3's "unknown" rule). It is not a resolution of the specifier: the import itself gives no edge.
- **Root-level module folders without MapX-readable config** (`NODE_PATH=.`, webpack `resolve.modules: [__dirname]`, jest `moduleDirectories: ["<rootDir>"]`, Deno `deno.json` import maps): such imports lose the accidental root-relative edge. Owner: M2-08-R11. Its known effects are in the report.
- **A destructured call through a one-segment baseUrl import** (the M2-25 limitation above): owner M2-25-R1.
- **Workspace packages only a manifest `workspaces` glob declares:** MapX takes any folder with an indexed file and a package.json `name`; it does not check the root's `workspaces` list.
- **PHP `require` / `include`**, which use `resolveRequirePath`: a different language and function.

## Implementation plan

1. Tests first, in `tests/import-bound-externals.test.ts` (new `describe` blocks, real `init` and `scan`): local `express.js`, `lib/thing.js`, `components/Button.tsx` at the root, and
   - ES import and CommonJS require of `express`, a Vue SFC and a Svelte component: no import edge and no call edge into `express.js`;
   - relative `./express` and `./lib/thing` still link; a root-relative `/lib/thing.js` and a C `#include "util.h"` still link;
   - a CRA `baseUrl` app: `components/Button`, one-segment `utils` and `express` (a project file under `baseUrl` shadows the package, as in tsc) resolve;
   - a tsconfig with `paths` (`@lib/*` and a `*` pattern) and a vite alias still resolve;
   - sync after adding `express.js` equals `scan --force`.
2. `src/core/scanner.ts`: stop pushing the bare specifier into `bases` for a JS-family importing file; resolve a workspace package name (`workspacePackageTargets`). `src/core/js-aliases.ts`: `baseUrl` follows `references` (`tsBaseUrl`).
3. Bump `EXTRACTOR_VERSION`.
4. `npm run eval` before and after, a self-scan diff of the JS/TS cross-file edges (import edges included), mutation checks.

## Acceptance criteria

1. **Import and require of a package name give no project edge** (tests "an import of express gives no project edge…", "a require of express gives no project edge…", "a Vue SFC and a Svelte component…"). Input: a local `express.js` and no mapping; output: no import edge to `express.js`, no call edge to it.
2. **Relative specifiers, root-relative URLs and other languages' bare paths still link** (tests "a relative import of the same files still links", "a root-relative URL import still resolves to the file", "a C include of a bare file name still links the file").
3. **`baseUrl` resolves, with a folder and without** (test "a baseUrl import resolves, one segment…"): `components/Button`, `utils`, and a one-segment name that is also a package (`express`) resolve to files under `baseUrl`.
4. **`paths` (`*` pattern included) and a bundler alias still resolve** (tests "tsconfig `paths`…", "a bundler alias…").
5. **Workspace packages resolve** (test "a workspace package name and subpath import link its files…"): a root-folder package, a nested scoped package with another name and an unindexed `main`, an `exports` entry and pattern, and `module` before `main`; a name that is no package links nothing.
6. **A referenced `baseUrl` resolves** (test "a baseUrl in a referenced tsconfig resolves a bare import").
7. **Sync equals scan --force** (test "a project express.js added later…").
8. **The eval holds.** `npm run eval` exits 0 with edges precision no lower than before.
9. **The self-scan** of MapX's JS/TS edges changes only by removing edges that are wrong; each is checked against its source.
