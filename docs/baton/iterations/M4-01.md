# M4-01 — Recall/precision scoring in CI

## Identification

Milestone: M4; priority: P1; risk: low; estimate min/expected/max: 3/5/8 h; role: test and CI tooling.

## Objective

One command, `npm run eval`, scores the three labelled fixtures against floors recorded in one file. CI runs it as its own job and fails when any floor is missed.

## Dependencies

Hard: M1-01 (routes fixture and scorer), M2-02 (HTTP fixture and scorer), M3-01 (Vue SFC fixture and scorer), and the 2db08bd remediation tasks (D015), all DONE. M5-18 has an interface dependency on this task, through `.github/workflows/ci.yml`.

## Scope

- **`scripts/eval/floors.json`, the single record of floors.** Each scorer gets an entry:
  - `fixture`: the fixture directory;
  - `min` / `max`: floors and ceilings on the scorer's `totals` metrics;
  - optional `patterns`: per-pattern `min` / `max` on the scorer's pattern metrics, where `"*"` gives the default for every pattern and a named pattern overrides it.

  The values are the numbers measured on `develop@ccfbad5`:

  | Scorer | Floors |
  | --- | --- |
  | Routes | URI, handler and attribute recall 1, precision 1, false positives 0, `strictParams` |
  | HTTP | call-site, URL and pairing recall 1, pairing precision 1 |
  | Edges | recall 1, precision 0.99 (measured 117/118 = 0.9915; the test floor of 0.95 rises), false positives ≤ 1; per pattern recall 1 and false positives 0, except `composable` ≤ 1 |
- **`scripts/eval/run-eval.ts` (`npm run eval`).**
  - Runs each scorer's existing exported scan and score functions in process, and checks each result against its floors.
  - Prints one table per scorer: metric, value, floor, and pass or FAIL.
  - Notes each value above its floor, so floors can be raised.
  - Appends a Markdown summary to `$GITHUB_STEP_SUMMARY` when that variable is set.
  - Options: `--json` prints a machine-readable result, and `--floors <file>` uses another floors file.
  - Exit codes: 0 when every floor holds, 1 on any regression, 2 on a usage, floors-file or scan error. A floors file naming an unknown scorer, metric or pattern is a usage error, never silently skipped.
- **The three fixture tests take their floor values from `floors.json`** (`tests/laravel-routes-fixture.test.ts`, `tests/http-pairing-fixture.test.ts`, `tests/vue-sfc.test.ts`), so a floor changes in one place. Checks that are not floors stay in the tests (exact params, flagged negatives, per-pattern label counts).
- **CI:** a new `Eval` job in `.github/workflows/ci.yml`, which needs `lint` and runs `npm run eval`.

## Acceptance criteria

1. **Passing run.** On the current tree, `npm run eval` exits 0 and prints, for each of routes, HTTP and edges, every floor-protected metric with its value and floor (CLI output in the report).
2. **Regression fails.** Breaking a detector so that a floor-protected recall drops makes `npm run eval` exit 1 and name the metric. Mutation check, recorded in the report: a route-extraction break, and a Vue template-handler break.
3. **Single source.** A floor exists only in `floors.json`. The three fixture tests import it, so editing a floor there is the only way to change it. Shown by `grep` in the report, and by the tests passing with a floor read from the file.
4. **Bad floors are rejected.** A floors file with an unknown scorer, metric or pattern, or a ratio floor outside [0, 1], makes `npm run eval` exit 2 before scanning. Tested in `tests/eval-floors.test.ts`.
5. **`--floors` CLI run.** With `--floors` pointing at a file that holds only HTTP, with `min.callSiteRecall` 1 and `max.unlabelled` 0, the run exits 1 and reports only `unlabelled 1 > 0` (`tests/eval-floors.test.ts`).
6. **CI job.** `.github/workflows/ci.yml` has an `Eval` job (`needs: lint`) that installs and runs `npm run eval`. A structural test of the job block shows it: no YAML parser is installed, and none is added as a dependency.
