# M5-03 — Element view, core selectors and layer membership with selector trace

## Identification

Milestone M5; P1; risk medium; estimate 8/10/14 h. Sources: `docs/research/deptrac/02-abstract-feature-model.md` AR-01 (element and granularity), AR-03 (layer), AR-04 (selectors), AR-12 (multi-layer).

## Objective

An element view over the stored index, with a qualified name for every symbol in every built-in language. The core selectors are evaluated on it, and the layer membership they give is computed once per (scan, configuration), with a trace of the selector that matched.

## Dependencies

- M5-02 (hard): the loaded `ArchitectureConfig`.
- M5-01 (fixture): the `tests/fixtures/arch-rules` apps.

## Scope

1. **`src/arch/elements.ts`:** `buildElementView(store, dir)` gives one element per indexed file and per symbol.
   - **Element fields:** `id`, `kind`, `qualifiedName`, `file`, `repo`, `language`, `symbolKind`, `scope`, `role`, `roleConfidence`, `clusters`, `frameworkParts`, `topLevel`.
   - **Frameworks:** framework parts are derived from stored edges (AR-04 table).
   - **`qualifiedName(language, input)`:** one normalisation per built-in language; a path-based `path#Name` fallback where there is no namespace. Documented in the module and in `docs/architecture-rules.md`.
2. **`src/arch/selectors/`:** these selectors, each a pure function of the element and the view, returning the match and the matching path inside the selector:

   | Selector | Matches on |
   | --- | --- |
   | `path` | glob or `/regex/` on the workspace-relative path |
   | `name` (+`kind`) | regex on the qualified name; symbols only |
   | `layer` | membership in another layer |
   | `all`, `any`, `not` | composition |
   | `role` (+`confidence`) | the file's role |
   | `cluster` | the file's clusters |
   | `repo` | the file's repo |
   | `workspacePackage` | the nearest manifest name |
   | `language` | the file's language |
   | `framework` | parts derived from edges |

   Selectors owned by later tasks (`extends`, `implements`, `inherits`, `mixes`, `inheritanceDepth`, `decorator`, `docTag`, `member`, `package`, `builtin`, `ambient`) never match here and are reported as unsupported.
3. **`src/arch/membership.ts`:** `layerMembership(view, config)`, following AR-01's granularity rule:
   - a symbol's layers are those its selectors match, file-level selectors judged on its file;
   - a file's layers are those whose selectors match the file, plus its top-level symbols' layers.

   It also covers:
   - **`private`** selectors per layer;
   - **overlays** kept apart;
   - **`explain(element)`:** the trace: layer, selector path, `via` (the file itself, or a top-level symbol);
   - **`getMembership`:** memoised by the scan stamp and a hash of the layers and parameters.

## Out of scope

- Rule evaluation and findings (M5-04).
- The selectors listed above as unsupported: M5-09 (hierarchy), M5-10 (decorators and doc tags), M5-19 … M5-24 (packages, builtins, ambient).
- Resolving Go cross-package references (a resolver gap found by M5-01).

## Acceptance criteria

1. Every listed selector has unit tests on the PHP, TS and Python fixture apps (`tests/fixtures/arch-rules`), each with negative cases (`tests/arch-selectors.test.ts`).
2. `qualifiedName` normalisation is documented and tested for every built-in language, with the path-based fallback where there is no namespace (the same test, table-driven over the registry).
3. Membership for the fixture is computed once per scan and configuration pair: a second call returns the cached result (a counter shows one computation); a changed configuration or a new scan recomputes it (test).
4. On the fixture apps, every element's layers equal the layers the M5-01 rows imply for it, including the multi-layer `OrderId` and the empty `Reporting` (test).
