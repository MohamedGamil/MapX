## Objective

Python, Rust and Go imports link the files the language loads in four cases M0-12-R4 got wrong.

## Dependencies

- M0-12-R4 (hard): the per-language resolvers and the `{file, symbol}` hits. DONE.

## Scope

All in `src/core/import-resolvers.ts`:

- **Python absolute imports.** The search roots are the workspace root and every ancestor of the importing file, as before, except a directory holding `__init__.py`. Python 3 has no implicit relative imports, so inside a package `import json` is the stdlib, not `pkg/json.py`. A script directory without `__init__.py` stays a root, since Python puts it on `sys.path`.
- **From-import comments.** `# …` comments are stripped from the name list of `from pkg import (a,  # c\n b)` before it is split.
- **Rust bin crates.** `src/bin/*.rs` is a crate root, like `main.rs` and `lib.rs`: its `mod x;` and `use x::…` look beside it, and `crate::` starts at `src/bin`.
- **Quoted go.mod.** `module "example.com/q"` (or a backquoted raw string) gives the module path without the quotes.

## Out of scope

- Other Cargo crate roots (`tests/*.rs`, `examples/*.rs`, `benches/*.rs`): not in the finding; recorded as a follow-up in the report.
- PEP 420 namespace packages (no `__init__.py`): their directories still act as roots, as before.
- `src/core/scanner.ts` (other lane): no change needed.

## Implementation plan

`resolvePythonImports` (roots, name list), `resolveRustImport` (`crateRoot`, `moduleDir`, the `crate::` walk), `resolveGoImport` (module regex). Blast radius (`mapx impact`, scan of this worktree): `resolvePythonImports` → `resolvePythonImport`; `resolveRustImport` and `resolveGoImport` report no callers because they are reached through the `LANGUAGE_RESOLVERS` table; `importResolverFor` → `Scanner::resolveReferencesWithMap` (HIGH), `writeParseResultWithMap`, `resolveReferences` (MEDIUM), `_scanFullForRepo`, `writeParseResult` (LOW). The output contract (`ImportHit`) is unchanged.
