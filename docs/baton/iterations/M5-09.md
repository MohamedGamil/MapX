# M5-09 — Hierarchy and member selectors (transitive ancestry, depth, members)

## Identification

Milestone M5; P2; risk medium; estimate 6/8/10 h; role: arch and parsers. Sources: `docs/research/deptrac/02-abstract-feature-model.md` AR-04 (`extends`, `implements`, `inherits`, `mixes`, `inheritanceDepth`, `member`) and AR-02 (inherited dependencies, `policy.inheritDependencies`, `via`); `01-deptrac-capabilities.md` (type-hierarchy collectors, inheritance flattening).

## Objective

Layers can select types by their ancestry and their members, transitively and cycle-safely, across languages, including ancestors outside the workspace; and, with `policy.inheritDependencies`, a subclass answers for the dependencies of its in-workspace ancestors, each such finding naming the inheritance path in `via`.

## Dependencies

- M5-03 (element view, selectors, qualified names): DONE. M5-03-R1 (selector three-valued logic, qualified names per language): DONE.
- Interface: M5-10 (symbol metadata path), M5-11 (shared evaluator chain), M5-19 (external reference candidates, which name PHP's external bases).

## What the index holds (probe, before the change)

Probe of PHP, TS, Python, Java, C#, Kotlin, Go, Ruby, Scala, Dart, Rust, Swift and C++ (scratch workspace, real `init` and `scan`):

- `extends` / `implements` edges exist only when the base resolves to an indexed file. Targets: PHP the FQN, others the short name. Kotlin and C# tell `extends` from `implements` syntactically, Python and Ruby store every base as `extends`, Scala stores `with T` as `extends`, Go stores struct embedding as `extends`.
- External bases leave no edge. PHP alone stores them as M5-19 candidates (`kind` `extends`/`implements`, FQN through `use`). TS and Python store the import candidates that name them; Java and Kotlin only the source's `import` lines.
- Each type symbol's `signature` is its declaration's first line, which holds the base list in every language above but Go.
- Gaps: TS `abstract class` is no symbol (so neither it nor the edges to it exist), TS and PHP `interface A extends B` store no edge, PHP `use Trait;` is not recorded, Rust `impl T for S` has no source symbol, C++ stores wrong class signatures.

## Scope

1. **Parsers** (extractor version 11): TS `abstract class` declarations are symbols with their `extends`/`implements` edges; TS and PHP interface `extends` edges; PHP trait uses as `metadata.mixins` (FQNs) on the using class or trait.
2. **Ancestry** (`src/arch/selectors/hierarchy.ts`): per view, each type's direct bases from (a) stored `extends`/`implements` edges, (b) the declared base list of its signature, which adds bases outside the index as *external* ancestors named through PHP candidates, TS/Python import candidates, or Java/Kotlin `import` lines, else as written, and gives `with` (Scala, Dart) its mixin hop, and (c) PHP `metadata.mixins`. Closure by breadth-first search over (node, path-kind) states: finite with cycles.
3. **Selectors**: `extends` (a path of `extends` hops), `implements` (a path with an `implements` hop), `mixes` (a path whose last hop is a mixin), `inherits` (any path), `inheritanceDepth` (longest chain ≥ N), `member` (an own member's name matches a regex). Ancestor values: a name or trailing namespace segments, case-insensitive, or `/regex/flags`. An external base named only as written also matches a qualified value it ends. Symbol-level: inapplicable to files.
4. **Explanation**: a hierarchy match carries its chain; `arch which`, `layers --why` (CLI text and JSON, MCP) show it.
5. **`policy.inheritDependencies`**: the evaluator derives, for each type with in-workspace ancestors, its ancestors' dependencies with the type as source, decided by the same AR-08 chain; findings carry `via` (the inheritance path) unless the type has the dependency itself.
6. Schema, config validation (regex values) and `docs/architecture-rules.md` in step.
