# M2-04 — URL constant, template and conditional resolution

## Identification

Milestone: M2; priority: P1; area: http. Sources: report §4 items 12–13; D008.

## Objective

Resolve file-local and imported string constants, template literals with constant parts, split-line arguments and ternary URLs (one edge per branch).

## Scope and plan

Delivered together with M2-05 in a single evaluator, `src/frameworks/http/url-resolver.ts`, because nearly every fixture call needs both: a constant or template, and a client base URL. The scanner's `scanHttpCalls` fills `url` (and `baseURLUnresolved` when the base can't be evaluated) on each D008 record.

- **M2-04:** string literals, `+` concatenation, template literals, file-local and exported or imported string constants. Unknown substitutions become `{}`; a URL with no literal part stays unresolved.
- **M2-05:**
  - base expressions: literals, constants, `process.env.X` and `import.meta.env.X` (from the app's `.env`, `.env.local`, `.env.development` and `.env.production`, nearest first), and configured `baseURL`;
  - joining follows axios `combineURLs`: an absolute request URL wins, otherwise the trailing `/` of the base and leading `/` of the path collapse to one;
  - `fetch` has no base.

## Out of scope

Pairing (M2-06); runtime-built URLs (function results, object lookups).

## Acceptance criteria

1. const BASE = 'settings/x'; api.get(`${BASE}/${id}`) resolves to /settings/x/{} (url field), for file-local and imported constants.
2. Each branch of a conditional URL (split into call sites by M2-03) resolves to its own url.
3. On the M2-02 fixture, every label whose URL needs no base URL resolves (url recall for patterns constant-local, constant-imported, template, fetch, axios-direct, conditional), measured by score-http.ts.

## Verification

- `npx vitest run tests/http-pairing-fixture.test.ts`
- `npx vitest run tests/http-url-resolution.test.ts`
- `npm run check`

## Recovery

Revert url-resolver.ts and the scanner change; records go back to having no `url`.
