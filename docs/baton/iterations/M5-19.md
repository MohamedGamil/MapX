# M5-19 — External references store: capture unresolved out-of-workspace references

## Identification

Milestone: M5; priority: P1; risk: medium; estimate min/expected/max: 4/6/9 h; role: scanner and store.

## Objective

Unresolved import and call references whose target lies outside the workspace are kept in a new `external_refs` table, never as edges. It closes gap G3 of `docs/research/deptrac/03-mapx-gap-and-integration.md` (§2) with the mitigation of §4: a separate table, so edge counts, metrics and PageRank stay as they are. Decomposed from epic M5-12 (D019).

## Dependencies

M5-03 (hard), M5-03-R1 (hard), M5-01 (fixture), M4-03 (interface: `src/core/scanner.ts`). All DONE. No approval gate.

## Scope

- **Store.** Migration 10 adds the table `external_ref_candidates` and the view `external_refs`, which holds the candidates decided external. A row is one reference from a workspace file that gave no edge and may name something outside the workspace:
  - `file_path`, `repo` and `line`: where the reference is;
  - `source_symbol`: the enclosing function, method or class (`Class::method`), or null at module level;
  - `specifier`: what the file names, as it names it. That is the npm specifier (`pg`, `node:fs`, `@scope/pkg/sub`), the Python module (`flask`, `os.path`), the Go import path (`fmt`, `github.com/x/y`), or the PHP class or function (`Illuminate\Support\Facades\Route`, `strlen`);
  - `symbol`: the name used from it (`Pool`, `Client.connect`, `default`, `*` for a namespace import), or null for the module as a whole;
  - `kind`: the reference type (`import`, `require`, `call`, `instantiation`, `extends`, `implements`, `param_type`, `return_type`);
  - `ecosystem`: `npm`, `composer`, `pypi` or `go`, the manifest family that attributes it;
  - `external` (0/1): the decision;
  - `metadata` (JSON): a PHP function's namespaced candidates, a facade's target class.
  - Columns for M5-20 … M5-23, left null here so those four lanes need no migration of their own: `package`, `origin` (`package`, `builtin` or `ambient`), `direct`, `dev`, `attribution` (`lock` or `manifest`).
  - Store API:
    - `replaceExternalRefs`, `getExternalRefs` (the view), `getExternalCandidates`, `setExternalDecisions`, `deleteOrphanExternalCandidates` and `getPhpDeclaredNames`;
    - `deleteEdgesForFile`, `deleteFile`, `resetRepoForScan` and `deleteRepo` delete candidates with the edges.
- **Capture** (scanner, per file, in the same transaction that writes the file's edges, so the kill-safety rules of M0-02-R10/R11/R12 hold unchanged). Candidates are references that gave no edge and are:
  - JS/TS/Vue/Svelte: imports, export-from statements and requires whose specifier has a package's form, and the uses they bind;
  - Python: absolute imports no indexed file satisfies, and the uses they bind;
  - Go: imports and package-qualified names;
  - PHP: classes and functions, but not member calls or language constructs.
- **Decision**, against the workspace as it stands:
  - npm: no alias, workspace package name or indexed file satisfies the specifier;
  - Python: the top-level name is no module or folder holding Python files;
  - Go: outside every workspace module and resolving to no package;
  - PHP: no workspace declaration with the name, and for a class no PSR-4 root covering it.
- **The decision is made again at the end of every scan and sync**, without parsing, because other files decide it (review of the first commit).
- **Extractor version 9** (8 is M5-10): an index built before this re-parses once, so its external references fill without `--force`.
- **Fixture:** external imports and uses in `tests/fixtures/arch-rules` (ts, python, go, php), labelled by hand in `tests/fixtures/arch-rules/expected-externals.json`.

## Out of scope

- Package attribution, direct/transitive and dev/prod, builtin and ambient classification, lockfiles: M5-20 (npm), M5-21 (Composer), M5-22 (pip/Poetry/uv), M5-23 (Go modules). The columns exist; nothing fills them.
- `package`, `builtin` and `ambient` selectors, uncovered externals and vendor confinement in `mapx check`: M5-24.
- Ambient globals (`process.env`, `window`, `$_GET`): no reference is extracted for them today; M5-20/M5-21 own their capture.
- Other languages (Java, Kotlin, Scala, Rust, Ruby, C#, Dart, …): no ecosystem task covers them yet; their unresolved imports stay uncaptured.
- A CLI or MCP surface for `external_refs`: M5-24 reads the table through the arch engine.

## Implementation plan

- `src/core/store.ts`: migration 10, the store methods, deletion with edges.
- `src/core/external-refs.ts` (new): the row type, the ecosystem of a language, the candidate form of a JS specifier, the PHP constructs, the JS import clauses of a module text and the Python bindings.
- `src/core/import-resolvers.ts`: `pythonImportOutsideProject`, `phpNameOutsideProject` and `goImportInWorkspaceModule`.
- `src/core/scanner.ts`:
  - collect candidates in `resolveReferencesWithMap` for references that give no edge, and write them in `writeParseResultWithMap`;
  - `decideExternal`;
  - `decideExternalRefs` at the end of `scanFull` and `scanIncremental`.
- `src/core/extractor-version.ts`: version 9.
- `tests/external-refs.test.ts`, fixture files and labels.

## Expected outputs

## Acceptance criteria

1. A store migration adds `external_refs` (file, line, specifier, symbol, kind); a scan of the arch-rules fixture fills it for every unresolved bare-specifier import. Test: the rows of each app equal the labels in `expected-externals.json` exactly (identities, not counts), and a store at schema 9 migrates to 10.
2. MapX self-scan edge counts, metrics and PageRank are unchanged: the same tree scanned with the code before and after, fingerprints of edges, cluster metrics, smells and PageRank compared (report).
3. Sync keeps `external_refs` equal to `scan --force`, on the git and hash sync paths (e2e):
   - after edits, deletions and renames;
   - after an interrupted sync;
   - when another file decides externality: a workspace package, a Python package, a PHP namespace, a root module, tsconfig paths or a go.mod.
