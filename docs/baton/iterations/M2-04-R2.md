# M2-04-R2 — Scoped URL constants; dotenv quoting and expansion

## Identification

Milestone: M2; priority: P1; risk: medium; estimate min/expected/max: 2/4/6 h; role: static analysis (JS scoping, dotenv).

## Objective

A URL constant resolves to the declaration in scope, or to nothing; `.env` values are read and expanded as Vite reads them.

## Dependencies

M2-04-R1 (hard), M2-05 (hard). Both DONE.

## Scope

- **Scoped constants (P1, review 2026-10-31).** `fileConstants` kept one map per file, so two functions each declaring `const url` resolved both calls to the last value and paired the wrong route `[exact]`. The resolver now records every binding of a file with its scope:
  - `const` / `let` / `var` declarations, including destructuring and non-literal initialisers;
  - function, method and arrow parameters.
  
  A call sees the innermost binding of each name that encloses the call. Only a `const` whose whole initialiser is a literal has a value. A shadowing binding with no value (a parameter, `let`, or a computed `const`), or two bindings of the same scope that disagree, leave the name unresolved. Declarations inside comments no longer count.
- **Call offsets.** `extractHttpCalls` gives each call site its offset in the file, which the scanner uses for the lookup and does not persist (D008 record shape unchanged).
- **dotenv (P2).** `parseDotenv` follows dotenv 16 / Node's `parseEnv`, which Vite uses:
  - a quoted value keeps only what is inside the quotes, even when a `# comment` follows;
  - an unquoted value ends at `#`;
  - quoted values may span lines, and `\n` in double quotes is a newline.
  
  `expandDotenv` performs dotenv-expand's `${VAR}`, `$VAR`, `${VAR:-default}`, `${VAR-default}`, `${VAR:+alt}` and `\$` across the env files consulted for the file.

## Out of scope

- Pairing changes, including calls with no literal segment (M2-06-R1).
- Values from the shell environment at build time. A reference to a variable that no env file defines leaves the value unresolved; Vite would substitute `''`.
- Vue CLI's older dotenv 8–10 rules, which keep inline comments. One Vite-compatible parser serves both.
