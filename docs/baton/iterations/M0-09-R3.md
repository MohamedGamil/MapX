# M0-09-R3 — Agent files: line endings, legacy edited blocks and JSONC merges

## Identification

Milestone: M0; priority: P1; risk: medium; estimate min/expected/max: 4/6/9 h; area: agents.
Sources: `docs/baton/reviews/REVIEW-2026-10-31-fb75474ba377.md`, `specs/features/F17-llm-integration-files.md`.

## Objective

Agent file updates are idempotent and never corrupt or silently replace user content.

## Dependencies

M0-09-R2 (hard). Builds on the review's `needsConsent()` (`src/agents/generator.ts`); the "user-written agent files are never replaced without consent" tests must keep passing.

## Scope

- P1: CRLF files. Sentinel regexes accept `\r\n`, the body hash and the up-to-date comparison ignore line endings, and a block written into a CRLF file uses CRLF.
- Every generated file ends with a newline.
- `agents update` writes only files that already exist (no `instructions`/companion creation).
- A hashless legacy block whose body differs from the current template is treated as edited (needs consent) whatever its version.
- A second (duplicate) mapx block is removed when the first is updated, and counts toward the edited check.
- `stripJsoncSyntax`: trailing-comma and unquoted-key rewrites are string-aware. A merge that drops JSONC comments says so in the CLI and MCP output.
- Aider: `.aider.conf.yml` with a top-level `read:` key outside the mapx block is not given a second `read:` key. It is never written, and the output says to add AIDER.md by hand.
- `companionMcpConfigs` uses an explicit `mcpConfigs` list on the provider template instead of matching provider names.

## Out of scope

- Continue format. Continue's documented config (`config.yaml` with `name`/`version`/`schema`, `context`, `prompts`, `mcpServers`) does not load `.continue/mapx.yaml`, `contextProviders` or `slashCommands`. F17 prescribes exactly that file, so changing it needs an owner decision to amend F17 (`specs/` is frozen, D001). Reported as a finding.
- Preserving JSONC comments through a merge (loss is reported instead).

## Implementation plan

- `src/agents/generator.ts`: line-ending-aware markers and hash; final newline; `plan(..., { onlyExisting })`; legacy rule; duplicate blocks; YAML key conflict status `key_conflict`; `droppedComments` on MCP actions; explicit companion configs.
- `src/agents/templates.ts`: `mcpConfigs` on `ProviderTemplate` (zed, antigravity: the configs each already received).
- `src/parsers/static-file-parser.ts` (and its copy in `src/parsers/parse-worker.ts`): string-aware JSONC normalisation.
- `src/cli.ts`, `src/mcp.ts`: skip and explain `key_conflict`; warn on dropped comments; `update` uses `onlyExisting`.
- Tests: `tests/legacy-agents.test.ts`, `tests/legacy-agent-templates.test.ts` (real CLI end to end).

## Expected outputs

Code above, regression tests, `docs/baton/reports/M0-09-R3.md`.

## Acceptance criteria

1. Generating twice on CRLF files yields one block per file and agents list reports current.
2. Every generated file ends with a newline; text appended after generation stays on its own line after update.
3. A JSONC settings file with `"**/[,]"` and comments keeps its string values (comments preserved or the loss documented in the output).
4. agents update only touches files that exist.
