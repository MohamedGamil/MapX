# M4-08 — Strict flag handling in score-routes and score-http

## Identification

Milestone: M4; priority: P3; risk: low; estimate min/expected/max: 1/2/3 h; role: test tooling.

## Objective

`score-routes.ts` and `score-http.ts` reject malformed command lines with exit 2 and a message, before scanning, as `score-edges.ts` already does.

## Dependencies

The hard dependencies are DONE: M1-01 and M2-02 (the scorers), plus D019's order, after M4-01 and M4-03. Source: `docs/baton/reports/M3-01.md`, review finding.

## Current behaviour (`develop@1391d31`)

Both scorers read `--name value` with `Number(args[i + 1])` and take the first non-flag argument as the fixture. So:
- `--min-recal 1` is ignored, so no threshold is checked;
- `--min-recall=1` is ignored;
- `--min-recall abc` becomes `NaN`, and every comparison with it passes;
- `--min-recall 1.5`, a repeated flag, a missing value and a second positional argument are all accepted.

## Scope

- **New shared module, `scripts/eval/args.ts`: `parseScorerArgs(args, { booleans, thresholds })`.** It takes a fixture plus known boolean flags, and threshold flags of kind `ratio` (in [0, 1]) or `count` (an integer ≥ 0). It throws on each of these, with a message naming the flag:
  - an unknown flag, or the `--name=value` form;
  - a repeated flag;
  - a missing value, a value that is not a number, or a value out of range;
  - an extra positional argument, or a missing fixture.
- **Each scorer exports its parser:**
  - `parseRoutesArgs`, with flags `--json`, `--strict-params`, `--min-recall`, `--min-precision` and `--max-fp`;
  - `parseHttpArgs`, with flags `--json`, `--min-recall` and `--min-precision`.

  `main` parses before any scan, and exits 2 printing the message and the usage line. Threshold semantics are unchanged.

## Out of scope

- `score-edges.ts`, which already parses strictly, with per-pattern thresholds.
- `npm run eval` (M4-01), which has its own strict options.

## Acceptance criteria

1. **Rejected arguments.** For both parsers, each of the following throws a message naming the flag (unit tests in `tests/laravel-routes-fixture.test.ts` and `tests/http-pairing-fixture.test.ts`):
   - an unknown flag (`--min-recal 1`);
   - `--min-recall=1`;
   - a repeated `--min-recall`;
   - `--min-recall` with no value, or followed by another flag;
   - `--min-recall abc`;
   - `--min-recall 1.5`;
   - `--max-fp 0.5` or `-1` (routes);
   - two positional arguments;
   - no fixture.

   The routes parser also rejects `--strict-params` given twice.
2. **Accepted arguments.** Valid command lines parse to the expected fixture, flags and numbers (same tests).
3. **CLI exit code.** `npx tsx scripts/eval/score-routes.ts tests/fixtures/laravel-routes --min-recal 1` exits 2, with the message, in under 5 s, so before any scan; the same holds for `score-http.ts`. Tested by spawning each CLI.
4. **No regression.** `npm run eval` and the fixture floors still pass.
