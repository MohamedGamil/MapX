# M5-24 — Package, builtin and ambient selectors; uncovered and vendor-confinement reporting

## Identification

Milestone: M5; priority: P2; risk: medium; estimate min/expected/max: 4/6/9 h; role: architecture rules.

## Objective

Architecture rules can select what a workspace depends on outside itself, by package, built-in and ambient access (AR-04). `mapx check` decides those dependencies like any other (AR-08), and reports two kinds of finding:
- **Uncovered external dependencies:** externals by default, built-ins only with `policy.uncovered.builtins`.
- **Vendor confinement:** a vendor layer only some layers may use, a `private` package selector, and an overlay of dev-only packages production layers deny.

This closes gap G3 of `docs/research/deptrac/03-mapx-gap-and-integration.md` on the rules side. The `external_refs` view (M5-19) and its attribution (M5-20 to M5-23) supply the data.

## Dependencies

All hard and all DONE:
- M5-20, M5-21, M5-22 and M5-23: `external_refs` filled for npm, Composer, pypi and Go.
- M5-04: the evaluator.

## Scope

- **External elements** (`kind: 'external'`, src/arch/elements.ts):
  - There is one per ecosystem, origin, name, direct and dev of the `external_refs` rows. The name is the package, or for a built-in its package (`node:fs`, `ext-pdo`, `python:os`, `fmt`). An unknown package is named by its specifier.
  - They sit in `view.externals`, beside the file and symbol elements, never among them. Each external reference keeps its row in `view.externalRefs`.
- **Selectors** (src/arch/selectors/external.ts). Each matches external elements only, and every file or symbol selector is inapplicable on an external:
  - `package` (glob), with optional `dev` and `direct`: a package by name (origin `package`; one no input provides by its name as written, review of M5-24);
  - `builtin` (`true` or a name glob): origin `builtin`;
  - `ambient` (`true` or a name glob): origin `ambient`.
- **Membership:** it covers external elements, so a vendor layer is not an `empty-layer`, and `private` selectors apply.
- **Evaluation:**
  - Each external reference whose source is in scope and in a layer is decided by the AR-08 chain, with its kind as the edge type.
  - Uncovered targets follow `policy.uncovered`: `externals` for packages, `builtins` for built-ins and ambient access.
  - A finding's target carries `external: { ecosystem, origin, package, direct, dev }`, with an empty `file`.
- **Report:** layer file counts leave externals out, and a Go package import is never subsumed by an external finding.
- **Introspection:**
  - layer listings show externals (`kind: external`);
  - `mapx arch allowed` and `mapx_arch_allowed` accept an external by name (`pg`) or as `<ecosystem>:<name>` (`npm:pg`).
- **Smells** (AR-18, `Source: rules`):
  - `vendor-leak`: a `private-layer` violation on an external;
  - `dev-dependency-in-prod`: non-test code uses a dev-only package;
  - `undeclared-dependency`: code uses a package its manifest does not list directly.
- **Fixture:**
  - The existing apps' default configurations now report their external dependencies as uncovered. Those rows are labelled, derived by hand from `expected-externals.json` and the granularity rules.
  - Four new apps (`ts-vendor`, `php-vendor`, `python-vendor`, `go-vendor`) configure a vendor layer, a private package and a dev-only overlay. Their rows cover uncovered, vendor confinement and dev-dependency findings, and their external references are labelled in `expected-externals.json`.
- **Surfaces:**
  - schemas;
  - `docs/architecture-rules.md`: a separate "External dependencies" section;
  - `docs/cli-reference.md` and `docs/mcp-integration.md` where the output changes.

## Out of scope

- Extracting ambient globals (`process.env`, `window`, `$_GET`, `os.environ`). That needs parser support and an extractor-version bump, which is a follow-up. Today the `ambient` selector sees what is stored: cgo's `C`.
- A `multi-layer` warning for an external in several layers. It is decided against each.
- Cargo, Maven, NuGet and the other ecosystems: nothing attributes them yet.
