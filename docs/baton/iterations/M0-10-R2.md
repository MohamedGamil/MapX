# M0-10-R2 — Workspace table and discovery edge cases; stronger workspace tests

## Identification

Milestone: M0; priority: P2; risk: medium; estimate min/expected/max: 2/4/6 h; role: CLI / MCP workspace surface.

## Objective

Every registered folder gets the right HEAD, type and identity, and the workspace tests catch regressions in the HEAD per repo, the `export --all` sections and `crossRepoEdgeCount`. These are the review 2026-10-31 P2 findings on M0-10-R1, including the mutants that survived.

## Dependencies

M0-10-R1 (hard, DONE).

## Scope

- **HEAD and type** (`src/core/workspace-summary.ts`):
  - A registered folder with no `.git` of its own (for example a monorepo package) reports no HEAD. Before, it reported the enclosing repo's HEAD.
  - Such a folder is typed `folder` instead of `peer`.
- **De-duplication:** registered-path identity resolves symlinks (`WorkspaceManager.repoKey` / `canonicalPath`) in:
  - init;
  - `workspaces list/discover/sync/add`;
  - `Config.addRepo`;
  - `repoType`;
  - mapx_workspaces discoveries.

  A symlink to a registered repo is therefore not registered or indexed twice.
- **Never-scanned repos:** `status --all` shows `unscanned` for a registered repo that has never been scanned. Before, it showed `clean`.
- **`export --all` headings:** each repo's export nests two levels below its `## <repo>` heading, so its `# Mapx` and `## Files` headings no longer sit at the same level as the workspace's own sections.
- **MCP parity** (review description):
  - `mapx_workspaces` returns `root`, and `headSha` (F18's name) instead of `headCommit`;
  - `mapx_export {all}` is the equivalent of `export --all`;
  - `mapx_dependencies {crossRepo}` is the equivalent of `deps --cross-repo`.

  The CLI and MCP share `workspaceExport` and `crossRepoDependencies`.
- **Discovery edge case found while building the fixture:** without a TTY, `workspaces sync` reached the monorepo/nested multiselect, which cancelled, and then exited before registering anything. Without a TTY it now skips those prompts and registers the rest.
- **Tests** (`tests/legacy-workspaces.test.ts`):
  - every repo in the fixture has its own commit, so the HEADs are distinct;
  - the fixture adds a plain package folder and a symlink to the submodule;
  - the cross-repo edges are asserted by identity, `crossRepoEdgeCount` exactly, and the `export --all` sections and headings exactly;
  - there is a separate never-scanned workspace.

## Out of scope

- The spec's other `RepoSummary` fields: absolute `path`, `relativePath`, `isRegistered`, `isInitialised`.
- Cleaning up configs that already contain a duplicate.
- `*.code-workspace` one level up (an M0-10-R1 limitation).

## Implementation plan

Tests first, against the current code. Then `workspace-manager.ts` (`canonicalPath`, `repoKey`), `workspace-summary.ts` (type, HEAD, shared export and cross-repo helpers), `config.ts` (`addRepo` de-dup), `cli.ts` and `mcp.ts`. Update the docs (`cli-reference.md`, `mcp-integration.md`).

## Expected outputs

The code changes above, the strengthened tests, the `repoKey`/`canonicalPath` stubs in the mocked CLI and MCP suites, and `docs/baton/reports/M0-10-R2.md`.

## Acceptance criteria

1. A plain folder shows no HEAD (`-` in the table and `status --all`, `headSha: null` over MCP). A symlink to a registered repo is not registered twice, by `sync` (via `.code-workspace`) or by `add`, and none of its files are indexed. A never-scanned repo shows `unscanned`.
2. The tests use repos with distinct HEADs, and assert the `export --all` file sections and `crossRepoEdgeCount` exactly.
