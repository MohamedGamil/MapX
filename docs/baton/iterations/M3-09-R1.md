# M3-09-R1 — JS/TS aliases stop at the app's own boundary

## Identification

Milestone: M3; priority: P1; risk: medium; estimate min/expected/max: 3/5/8 h; role: import resolution.
Sources: `docs/baton/reviews/REVIEW-2026-10-31-2db08bd25e13.md` (P1, remediation registered), `docs/baton/reports/M3-09.md`, `docs/baton/reports/M3-12.md`.

## Objective

An app folder with its own package.json, tsconfig/jsconfig or bundler config resolves aliases from its own configuration (or the `@/` → `src/` fallback), never from a parent project's.

## Dependencies

- M3-09 (hard): the shared resolver `jsAliasTargets`. DONE (disputed by the review).
- M3-12 (hard): the HTTP pass and vue-router detector use it. DONE (disputed by the review).
- Parallel: another lane edits `src/core/scanner.ts`. This lane does not touch it. Render, route and navigate edges reach the resolver through `Scanner.resolveImportPath`, so the change to `js-aliases.ts` covers them.

## Reproduction (develop@00407d6)

Laravel root: `package.json`, and a `vite.config.js` with `'@'` → `/resources/js`. Nested Vue CLI app `frontend/`: its own `package.json`, no alias config. Same-path traps exist under `resources/js/`. Reviewer B's probe (`review-B/p-boundary.ts`) was rebuilt as an e2e test:

- `frontend/src/main.js` imports `resources/js/App.vue`;
- `<NavBar />` in `frontend/src/App.vue` renders `resources/js/components/NavBar.vue`;
- the route record in `frontend/src/router/index.js` and the `<router-link>` in `App.vue` both reach `resources/js/views/Home.vue`.

The HTTP pass follows `@/api/client` to the root's client, so it uses the wrong base URL.

The cause is in `jsAliasTargets`. It walks upwards until *any* folder's config declares a matching alias, so the walk passes the app's own `package.json`.

## Scope

- **App root.** This is the nearest folder, from the importing file upwards, that holds a `package.json` or a bundler config (`vite.config.*`, `vue.config.*`, `webpack.config.*`, `webpack.mix.js`).
- **Compiler `paths`.** They come from the nearest folder holding a tsconfig/jsconfig, with its relative `extends` chain and `references`. The lookup goes no further than the app root. The nearest config decides even when it declares no `paths`, as in TypeScript. A tsconfig alone (`tests/tsconfig.json`) is not an app root.
- **Bundler aliases.** They come from the app root's bundler configs only. An app root that has only a `package.json` declares none.
- **Order.** Compiler `paths` come before bundler aliases. The `@/` fallback is unchanged.
- **P2 parser defects.**
  - Every call of a chained `config.resolve.alias.set(…).set(…)` is read.
  - Backslash separators in a literal path (`path.resolve(__dirname, 'resources\\js')`) become `/`.
- **The legacy-imports case "the nearest config decides"** is corrected. `web/` has its own `vite.config.js`, so the root config's `~` no longer applies to it.
- **Docs.** `docs/framework-integration.md` gains an "Import aliases (JS / TS)" section. `docs/getting-started.md` gets the Imports bullet.

## Out of scope

- tsconfig `include` / `files`, `extends` from npm packages, `package.json` `imports`, Nuxt / SvelteKit / Quasar configs (as M3-09).
- The navigation route table and the global component registry crossing app folders: M3-08-R1.
- Any change to `src/core/scanner.ts`.

## Implementation plan

- `src/core/js-aliases.ts`:
  - `dirAliases` reports whether a folder has a tsconfig/jsconfig (`compiler`, null without one) and whether it is an app root (`bundler`, null when it is not).
  - `jsAliasTargets` walks up once. It takes the first `compiler` it meets and stops at the first app root.
  - `bundlerRules` follows `.set()` chains.
  - `aliasPath` normalises backslashes.
- Blast radius (`npx tsx src/main.ts impact jsAliasTargets`, worktree scan): HIGH `Scanner::resolveImportPath` and `resolveImport` (`client-calls.ts`). MEDIUM: `resolveReferencesWithMap`, `vueResolveContext`, `resolveVueReference`, `moduleMember`, `resolveNavigation`, `vueGlobalComponents`, `scanFrameworkRoutesAndHooks`, `VueRouterDetector::extractRoutes`, `collectProviders`, `receiversFor`, `importedConstants`, `buildRouteTable`, `THIS_MEMBER_STEPS`, `resolveStoreTarget`. Signatures are unchanged. `bundlerRules` and `aliasPath` reach only `dirAliases` → `jsAliasTargets`.
