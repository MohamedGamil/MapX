# M5-17 — `mapx arch init`: inference from roles/clusters/frameworks and first presets

## Identification

Milestone: M5; priority: P2; risk: medium; estimate min/expected/max: 10/12/16 h; role: architecture-rules and DX engineer.

## Objective

A new adopter gets a reviewed-by-human starting configuration in minutes (AR-15). `mapx arch init` infers one from the index (MapX roles and the archetype's `LAYER_ORDER`, or the primary clusters), annotates it with the observed layer graph, or starts from a shipped preset (`mapx:preset/<id>`). It can write a baseline of today's violations so that day one is green. `mapx_arch_init` (M5-14) and the CLI share one engine.

## Dependencies

- M5-04 (hard, DONE): `buildReport`, `layerEdges`, policy expansion.
- M5-06 (hard, DONE): `renderBaseline`, the default baseline path.
- M5-14 (DONE): `mapx_arch_init` and `src/arch/propose.ts`, which this task replaces. Its contract stays: writes only with `write: true`, refuses a view that leaves `.mapx/architecture/`, never overwrites without an explicit `force`.
- M5-10 (DONE): the `decorator` selector the NestJS preset uses.

## Scope

1. **One engine, `src/arch/infer.ts`.** `inferArchitecture(store, workspace, { from, preset, baseline, repoPaths })` returns a proposal: the JSONC text, the layers with their file counts, the observed layer graph (dependencies per layer pair, allowed or not), the violations the proposal would report, the baseline text when asked, and its issues. Every proposal is loaded through `src/arch/config.ts` (presets and `extends` resolved), then evaluated on the index with `buildReport`, so issues are exactly what `mapx arch validate-config` and `mapx check` would report.
   - `from: roles` (default): one layer per role in `LAYER_ORDER[archetype]`, `{ role }` selectors, "may depend downward" rules. Unchanged from M5-14, plus comments with the observed dependencies of each layer and rule.
   - `from: clusters`: one layer per primary cluster (directory clusters, `{ cluster }` selectors); the rules freeze the observed cluster graph, so new cross-cluster dependencies fail.
   - `from: framework`: the preset of the framework the codebase profile detected (`laravel`, `nestjs`, `django`); exit 3 when none is.
   - `preset: <id>`: a config that `extends` `mapx:preset/<id>`, with the preset's path parameters inferred from the indexed paths, and for `ddd-contexts` one layer per bounded-context folder.
   - `baseline: true`: the violations of the proposal on today's index, rendered by `renderBaseline`, written to the default baseline path (`.mapx/architecture.baseline.json` or the view's).
2. **Presets** in `src/arch/presets/*.jsonc` (layered, clean, hexagonal, ddd-contexts, feature-sliced, laravel, nestjs, django), registered as `PRESETS` in `config.ts`. They are embedded in `src/arch/presets/index.ts`, generated by `scripts/gen-arch-presets.ts`, because tsup does not bundle and the bun binary has no source tree; a test keeps the two in step.
3. **Writing, `writeProposal`.** Dry run by default. With write: refuses an existing configuration (or baseline) without `force` (exit 3, a message naming the file), refuses a view outside `.mapx/architecture/`, refuses a proposal with issues.
4. **CLI `mapx arch init [path] [--from roles|clusters|framework] [--preset <id>] [--baseline] [--write] [--force] [--view v] [--sync] [--format text|json]`.** Dry run prints the JSONC on stdout and a summary on stderr; `--json` prints the result object `mapx_arch_init` returns.
5. **MCP `mapx_arch_init`** gains `from`, `preset`, `baseline`, `force` and `sync`; it calls the same engine.
6. **Docs:** `docs/cli-reference.md`, `docs/architecture-rules.md` (presets, init), `docs/mcp-integration.md`; `mapx check`'s "no configuration" message now points at `mapx arch init`.

## Out of scope

- The other AR-15 presets (onion, mvc, mvvm, symfony, express, fastapi, rails, spring, aspnet, flutter, nextjs, vue): later tasks.
- Hierarchy selectors (`extends`/`implements`, M5-09) in presets: M5-09 was not on develop when this was planned. Presets use paths, decorators and framework parts.
- Feature-sliced "no cross-imports between slices of one level" and ddd-contexts' "only through Contracts": both need per-slice layers or private selectors; the presets name the limitation.
- Dashboard (M5-15), rule smells (M5-16).

## Acceptance criteria

1. On the Laravel route fixture (M1-01) and a NestJS fixture, `mapx arch init --preset <id> --write` yields a config that `mapx arch validate-config` accepts and whose `mapx check --format json` has `configErrors: []` and exit other than 3 (`tests/arch-init.test.ts`). Every other preset does the same on its synthetic fixture.
2. `mapx arch init --baseline --write` followed by `mapx check` exits 0 (roles on the arch-mcp fixture, which has a violation, and a preset with violations).
3. Dry run by default: without `--write` the workspace is byte-identical; with `--write` the files are created; over an existing file without `--force` exit 3 with a message and nothing changes; `--force` overwrites.
4. Output is byte-stable: two runs give identical bytes.
