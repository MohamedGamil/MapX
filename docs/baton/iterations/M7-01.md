# M7-01 — Site scaffold, brand theme and one-command build (site/ workspace)

## Identification

Milestone: M7; priority: P1; risk: low; estimate min/expected/max: 5/8/12 h; role: docs tooling and front-end build.

## Objective

An isolated `site/` VitePress workspace carrying the MapX brand, a sync step that copies the published docs into it, and `npm run site:build`, which writes a static site under `site/.vitepress/dist` whose links honour a configurable base path.

## Dependencies

None. M7-02 (docs), M7-03 (landing) and M7-05 (deploy) all hard-depend on this task.

## Decisions taken here (agent defaults; the owner may overrule, see Follow-up)

- **Generator: VitePress 1.6.4 (MIT).** It builds Markdown guides as they are, has local search, a home layout and a Vue theme for the landing page. Alternatives considered: Astro Starlight (heavier, a second framework in the repo) and a hand-written generator on esbuild plus a Markdown library (more code to own, no search).
- **Isolation:** `site/` has its own `package.json` and lockfile. The root install, `npm run check`, `tsup` and the published tarball do not see it. `site/` is also excluded by the `files` whitelist; `.npmignore` gets `site/` for belt and braces.
- **Base path:** `SITE_BASE`, default `/mapx/`, for https://mohamedgamil.github.io/mapx/. A custom domain later means `SITE_BASE=/` and `SITE_URL`, with no code change.
- **Single source of truth:** guides stay in `docs/`. The site never holds a second copy in git: `scripts/site/sync-docs.ts` copies them into `site/docs/` (gitignored) before each build.
- **Theme:** brand `#ff02fe` and the dashboard slate palette (`src/ui/styles.css`), system font stack as in the dashboard (no web-font requests). Brand magenta fails WCAG AA as text on white, so on light backgrounds it is used for fills and borders, with a darker tone for text. M7-06 holds the axe check that proves it.

## Scope

- `site/package.json` (private, `vitepress` pinned exactly, scripts `build`, `dev`, `preview`) and its lockfile.
- `site/.vitepress/config.ts`: title, description, base from `SITE_BASE`, `cleanUrls`, GitHub social link, nav (Docs, npm; no About entry, see D045), footer ("MapX is created by Mohamed Gamil", a link to https://gamil.io, the licence), `lastUpdated` off (no git history dependency in CI shallow clones).
- `site/.vitepress/theme/`: extends the default theme with brand tokens (CSS only; no components yet, M7-03 owns those).
- Placeholder `site/index.md` (home layout with title and one link) and `site/docs/index.md` (generated entry listing the guides). VitePress writes `404.html` itself. M7-02 and M7-03 replace the content.
- `scripts/site/sync-docs.ts`: copies the allowlisted guides into `site/docs/`. In this task the allowlist is a constant of the 11 guide filenames and the sync copies them unchanged; M7-02 adds link rewriting.
- Root `package.json`: `site:sync`, `site:build` (sync, then `npm --prefix site run build`), `site:dev`. `.gitignore`: `site/.vitepress/cache`, `site/docs/` (generated), `site/node_modules`. `.npmignore`: `site/`.
- `tests/site-build.test.ts`: builds into a temp directory (private `TMPDIR` rules apply, see `tests/helpers/run-tmp.ts`) and asserts the output.

## Out of scope

- Docs link rewriting, sidebar, search, edit links and version display: **M7-02**.
- Landing content and components: **M7-03**. An About page: dropped by the owner (D045); **M7-04** is CANCELLED.
- Deploy and CI workflows: **M7-05**. Sitemap, SEO, axe and size budgets: **M7-06**. Screenshots: **M7-07**.
- Adding `site/` to `npm run check` beyond the build test: not planned; `site/node_modules` is absent in the baseline.

## Implementation plan

1. `npm view vitepress` and install it under `site/` (`npm install --prefix site --save-exact vitepress@1.6.4`). Record the lockfile.
2. Write `config.ts` reading `SITE_BASE` (normalised to a leading and trailing slash) and `SITE_URL`.
3. Brand theme CSS from the dashboard tokens, light and dark.
4. `sync-docs.ts` and the root scripts.
5. Failing test first (`tests/site-build.test.ts` before the config exists), then make it pass.
6. Blast radius: new files only, plus `package.json` scripts and the two ignore files. `mapx_impact` is not applicable (no symbol of `src/` changes); the tarball is checked by `npm pack --dry-run --json`.

## Expected outputs

`site/package.json`, `site/package-lock.json`, `site/.vitepress/config.ts`, `site/.vitepress/theme/{index.ts,brand.css}`, `site/index.md`, `scripts/site/sync-docs.ts`, `tests/site-build.test.ts`, `docs/baton/reports/M7-01.md`.

## Acceptance criteria

1. `npm run site:build` after `npm ci --prefix site` exits 0 and writes `index.html`, `docs/index.html` and `404.html` under the output folder. `tests/site-build.test.ts` builds into a temp directory and asserts the three files.
2. With `SITE_BASE=/x/` every `href` and `src` in `index.html` that is root-relative starts with `/x/`; with the default it starts with `/mapx/` (test scans the built HTML).
3. `npm pack --dry-run --json` lists no path under `site/`, and `npm run check` exits 0 with `site/node_modules` absent.
4. The footer of the built home page and docs index says MapX is created by Mohamed Gamil and links https://gamil.io with `rel="noopener"`; the nav has no About entry and no `/about` page is built. The 404 page is rendered in the browser, so M7-06 checks its footer. The default theme hides the footer on pages with a sidebar, so `brand.css` overrides that (M7-02 tests it with a sidebar).
5. Mutation check: setting the base to `/` in the config fails criterion 2's test.

## Verification

Registered commands, all of which must exit 0:

- `npx vitest run tests/site-build.test.ts`
- `npm run site:build`
- `npm run check`

Manual evaluation: the owner opens `npm run site:dev` once to judge the look. Automation does not replace it.

## Superseded, 2026-11-07 (M7-05-R1)

The default base path described above (`/mapx/`, address `https://mohamedgamil.github.io/mapx/`) was wrong: the repository is named `MapX` and a Pages address is case-sensitive in that segment. The default is now `/MapX/` and the Pages build sets it from the repository name. Criterion 2 of M7-01 ("with the default it starts with `/mapx/`") is read as "with the default it starts with `DEFAULT_BASE`", which `tests/site-build.test.ts` checks and pins to `/MapX/`. See `reports/M7-05-R1.md`.
