# M5-26: the index records the extractor version that built it; an older index counts as stale

## Identification

Milestone: M5; priority: P2; risk: low; estimate min/expected/max: 2/3/5 h; role: index integrity.

## Objective

An index built by an older extractor counts as stale:
- `mapx check` exits 4 and says to rescan;
- the other commands warn;
- any scan or sync re-parses every file of such a repo once.

The motivating cases are an index from before M5-25 (no Go cross-package instantiation edges) and one from before M2-08-R1 (different import-bound call edges). Either would make `mapx check` under-report with no signal.

## Dependencies

M5-05 (hard, DONE).

## Scope

- **`src/core/extractor-version.ts` (new):** `EXTRACTOR_VERSION` (1). It is bumped when a change makes an unchanged file index differently. It also exports `outdatedRepos(store, repoNames)`: the scanned repos whose `meta extractor_version:<repo>` is missing or lower.
- **`Scanner`:**
  - the full path re-parses every file of a repo whose version is outdated, as it does for changed filters (`reparseAll`);
  - a sync of such a repo takes the full path;
  - a completed, uninterrupted full-path scan records the version.
- **`mapx check`:** after the no-index checks, an outdated repo exits 4 with "built by an older MapX … run `mapx scan`, or `mapx check --sync`". `--sync` runs the sync, which re-parses fully.
- **Other commands:** `checkAndPrintStaleness` (CLI) and `getMcpStalenessWarning` (MCP) add an older-index warning.

## Out of scope

- Detecting which extractor change matters to which file: one version for the whole index.
- **M5-05-R1:** walk-based staleness for the other commands.

## Acceptance criteria

1. **Recording:** a scan records `extractor_version:<repo>` = `EXTRACTOR_VERSION`; an interrupted scan does not (`tests/index-version.test.ts`).
2. **`mapx check`:** an index whose recorded version is lower, or missing, makes `mapx check` exit 4 with the rescan message. `mapx check --sync` re-parses every file and records the version; the next `mapx check` passes the staleness gate (test).
3. **Other commands:** the CLI staleness warning and the MCP warning name the older index. An index with the current version gets neither (test).
4. **One-time cost:** a second sync after the upgrading one re-parses nothing (test).
