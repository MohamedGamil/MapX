# M5-03-R2 — Qualified names: C++ in .h headers, several C# namespace blocks, one-line C++ namespaces

## Identification

Milestone M5; P2; risk low; estimate 2/4/6 h; role: parser and architecture-view maintainer. Remediation of the three limitations recorded in `reports/M5-03-R1.md` ("Limitations" and "Not fixed").

## Objective

C++ classes in `.h` headers, symbols in a C# file with several namespace blocks, and calls inside a one-line C++ namespace get the qualified names and source symbols of their own block.

## Dependencies

M5-03-R1 (hard, DONE). No approval gate.

## Findings (reproduced by a probe scan before the change)

Probe: `inc/order.h` (`namespace acme { class Order { … }; }`), `c/util.h` (a pure C header with an `extern "C"` guard), `cs/Two.cs` (`namespace A { class X … } namespace B { class Y … }`), `cpp/line.cpp` (`namespace a::b { void f() {} void use() { f(); } }`), scanned with `npx tsx src/main.ts scan`.

| Case | Before | Cause |
| --- | --- | --- |
| C++ class in `.h` | file language `c`; **no symbols at all** (the C grammar cannot parse `namespace`/`class`) | `.h` is a C extension in `src/languages/registry.ts` |
| C# two blocks | `A.X`, `A.X.Run`, `A.Y`, `A.Y.Go` | `src/arch/elements.ts` takes the file's first namespace symbol for every symbol |
| One-line `a::b` | the call edge `f` has source symbol `a::b` | the scanner picks the smallest line range covering the call; the namespace and `use` both span one line, and the namespace comes first |

## Scope

As revised after the independent review of the first commit (`a289b89`, 1 P1 and 5 P2s; see the report).

1. `src/languages/registry.ts`: `isCppHeader(text)`, a conservative and linear rule. A `.h` header is C++ only when C++-only syntax appears outside every preprocessor conditional. That syntax is `namespace X {`, a `class X {`/`class X :` declaration, `template <`, access labels, `using namespace` or `extern "C++"`. The rule is applied after joining continuations and stripping comments and literals, and it treats a whole-file include guard as depth 0. It reads only the file's own text, with no sibling lookup. `getLanguageForFile` stays pure.
2. `src/core/scanner.ts`: the header decision is made from the content the scan already read (`discoverFiles`, `getFileInfo`), cached per path and content hash. `languageOf` prefers the stored language for `.h` files.
3. `src/parsers/generic-wasm-parser.ts` makes two changes:
   - each C# and Scala declaration stores `metadata.namespace` from the syntax tree: the file-level clauses, then the enclosing blocks, or `''` for the global namespace;
   - a reference inside a one-line function or method takes that function as its source symbol.
4. `src/arch/elements.ts`: a symbol's namespace is its stored `metadata.namespace` when present (`''` gives the path form), else the file's first namespace.
5. `src/core/extractor-version.ts`: bump by one, to 5 (develop took 4 for M5-25-R1).
6. Tests in `tests/arch-selectors.test.ts` (real scan and unit), covering:
   - a guarded C++ header;
   - a guarded C header with C++ glue in conditionals;
   - C# blocks (two blocks, nested, on one line, a global type, file-scoped);
   - Scala packages (nested and chained);
   - the one-line `a::b` call edge;
   - the header rule on every review case;
   - linear time.

## Out of scope

- The scanner's line-range source-symbol rule for multi-line symbols (unchanged).
- C++ header forms the conservative rule does not use (`virtual`, `enum class`, `constexpr`, `nullptr`, `static_cast`, `.hpp` includes, …): such headers stay C (report, Limitations).
- Kotlin `package` capture, C++ in-class declarations, Java/C# nested-type chains (M5-03-R1 limitations, unchanged).

Plus: a pure C header stays `c` with its symbols and call edge (non-regression).
