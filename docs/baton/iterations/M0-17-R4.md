# M0-17-R4 — Calls on library and DOM receivers do not link to same-named project symbols

## Identification

Milestone: M0; priority: P2; risk: medium; estimate 3/4/6 h; role: resolution precision.
Sources: `docs/baton/reports/M3-10.md` (findings outside the task).

## Objective

`axios.create()`, `_.get()`, `fetch()` and similar library or runtime calls never link to a project function of the same name.

## Dependencies

M3-10 and M0-17-R3 (hard), both DONE.

## Scope

- **Parser** (`src/parsers/generic-wasm-parser.ts`): a call on an identifier receiver (`obj.method()`) records the receiver in `metadata.receiver`. The scanner removes it before storing the edge.
- **Scanner** (`resolveReferencesWithMap`), for JS, TS and Vue files:
  - **npm-package receivers:** a call whose receiver the file binds by an `import`, `import * as` or `require` of an npm package (a bare specifier that no project file resolves, aliases included) is skipped.
  - **Global functions:** a plain call to a global function (`JS_GLOBAL_FUNCTIONS`: `fetch`, the timers, `structuredClone`, `atob` and others) is skipped, unless the file imports or declares that name.
  - **Bindings:** they are read from the file's text by `jsImportBindings`.
- **Already safe before this task:** property chains (`el.classList.remove()`) were never captured, and built-in method names (`find`, `map`, `get` on Map) were skipped by the parser.

Blast radius: every JS/TS/Vue call reference. Checked with the three scorers, the full suite, and a self-scan of MapX's sources (below).

## Out of scope

- Typed receiver resolution (`r: Repo; r.save()` still resolves by name).
- Calls on renamed imports (`import { create as makeIt }`), which never resolved before either.

## Acceptance criteria

1. `axios.create()`, `el.classList.remove()`, the global `fetch()`, `_.get()`, `lo.get()` (`import * as`) and `qs.remove()` (`require`) give no call edge to the project's `create`, `remove`, `fetch` or `get` (`tests/legacy-language-accuracy.test.ts`, e2e).
2. `r.save()` on a project-typed receiver, `repo.save()` on a project instance, and `fetch()` where the file imports or declares its own `fetch` still resolve (same file).
3. The edges, routes and HTTP scorers do not drop, and MapX self-scan call-edge changes are listed and justified (report).
