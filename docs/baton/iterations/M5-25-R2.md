# M5-25-R2 — Go methods with a generic receiver are indexed

## Identification

Milestone: M5; priority: P2; risk: low (medium after review 1: Go call resolution changes); estimate min/expected/max: 1/2/3 h, about 5 h with review 1; role: parser engineer.

## Objective

`func (p Pair[K, V]) Swap()` gives a method symbol `Swap` with scope `Pair`, so `gen.Pair[int, string]{}.Swap()` links it. After review 1, the extra methods must not make calls on Go variables link homonyms in packages the caller does not import.

## Dependencies

M5-25-R1 (hard, DONE): calls on a qualified literal carry the literal's package and type (`goType`), and the scanner resolves them to the method of that type in the imported package's directory.

## Cause

Recorded in `reports/M5-25-R1.md` (Limitations). The method pattern of `queries/go/symbols.scm` matches a receiver type that is a `type_identifier` or a `pointer_type` of one. A generic receiver is a `generic_type` (`Pair[K, V]`), or a `pointer_type` of one, so its methods are not symbols, and calls to them link nothing.

**Review 1 (P1):** a Go call on a variable or parameter (`x.Swap()`) carried no metadata, so the scanner resolved it by name alone, nearest file first. The new generic methods became candidates in packages the caller does not import. `var x legacy.Pair; x.Swap()` moved from legacy's Swap to gen's, and `func F(c *legacy.Conn) { c.Close() }` linked gen's `Box::Close`, both `verified`. The by-name resolution predates the task.

## Scope

- `queries/go/symbols.scm`: two more receiver alternatives, `(generic_type type: (type_identifier) @symbol.scope)` and the same under `pointer_type`.
- **Review 1:**
  - `src/parsers/generic-wasm-parser.ts`: every Go selector call that is not on a package records `goReceiver`. When the code writes the value's type, the call also records that type (`goType`) and, for a qualified type, its import (`goPackage`). The type comes from the nearest declaration (a receiver, parameter or result; `var x T`; `var x = T{}`; `x := &pkg.T{}`; or a package-level `var` of the file). Generic arguments and pointers are unwrapped, and a local literal's type is taken too (`Box[int]{}.Get()`).
  - `src/core/scanner.ts`:
    - A typed call resolves through `resolveGoQualifiedType` to the method of that type, in the imported package or in the caller's own package.
    - A value with no written type, or one whose type is an interface, resolves by name (`resolveGoMethodByName`). Only methods declared in the caller's package or in a package its file imports count, and the result is `inferred`.
- `tests/go-qualified-instantiation.test.ts`: two synthetic workspaces, each scanned with the real CLI.
- `src/core/extractor-version.ts`: `EXTRACTOR_VERSION` 13 (11 is M5-09 and 12 is M5-21), with a comment line.

## Out of scope

- Inferring the type of a call's result (`svc := build(); svc.Run()`), of a range variable, or of a chained call. These stay by name, now within the file's reach and `inferred`.
- The `CHANGELOG.md` entry: the integration owner writes it; the report carries the sentence.
