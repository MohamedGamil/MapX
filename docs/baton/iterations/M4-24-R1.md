## Scope

1. **Static check, values not names.** Remove `NUMERIC_NAMES`, `TRUSTED_NAMES` and the fragment-name pattern. An identifier is safe when every value that reaches it is safe, resolved with the TypeScript checker (scope-correct, not by name):
   - a variable: its initializer and every `=`, `+=`, `||=`, `??=` assignment;
   - a parameter: the argument at every call site of its function in the file (a function also used as a value, or a destructured parameter, is unsafe); the index parameter of an array callback is numeric;
   - a call to a function declared in the file: every value it returns.
   `escapeHtml` is the only trusted helper; the other helpers in `SAFE_CALLS` are judged by their return values.
2. **Concatenation and sinks.** A `+` chain with a tag in one of its string literals is checked like a template literal. Every value written to `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write` or `srcdoc` must be safe, whether it is a template, a concatenation or a variable.
3. **Unit tests** (`tests/ui-escaping.test.ts`): concatenated `innerHTML`/`insertAdjacentHTML`, and unescaped values assigned to the names the old check trusted (`durationStr`, `val`, `count`…), are flagged; the review's mutations m2/m3 are reproduced.
4. **`src/ui/main.ts`:** values the new check cannot prove safe are escaped (or passed through `num`), without escaping markup.
5. **Browser spec** (`tests/ui/xss.spec.ts`, helpers in `tests/ui/harness.ts`): the XSS workspace gains a handler (`[PageController::class, 'show<payload>']`), a symbol name (a Vuex action keyed `'save<payload>'`), a registered repo whose folder name carries the payload and calls the backend with axios (HTTP tab), and config values (a user exclude pattern, an unknown key and an invalid value). The spec opens every tab listed in the page's navigation and fails if one was not opened.
