# M2-08-R2: sync re-parses importers whose JS/TS import a new file now satisfies or shadows

## Identification

Milestone: M2; priority: P2; risk: low; estimate min/expected/max: 2/3/5 h; role: incremental resolution.

## Objective

When sync adds a module that changes what an existing import resolves to, the importer is re-parsed, and the edges equal `scan --force`. Two cases:
- an import that named a module nothing satisfied;
- a file such as `utils.ts` that now takes precedence over an existing `utils/index.ts` (file before folder index since M2-08-R1).

## Dependencies

M2-08-R1 (hard, DONE).

## Scope

- **`Scanner.resolveImportPath`:** while a file's references resolve, it records each relative or alias import it cannot resolve. The record is the module path with its extension stripped.
- **`writeParseResultWithMap`:** keeps those paths in `files.metadata.unresolvedImports`. The upsert before every re-parse resets them.
- **`Scanner.newModuleReferrers`:** for a JS/TS/Vue/Svelte module not yet indexed, it collects:
  - the files whose record names its path (or, for an `index` file, its folder);
  - for a non-index file, the importers of `<path>/index.*`.

  It is called in the full path, the git sync and the hash sync.
- **`Store.filesWithMetadataText`:** a `LIKE` pre-filter over file metadata.

## Out of scope

- Python imports.
- Bare package specifiers that a new workspace package would satisfy.

## Acceptance criteria

1. **Missing module:** a file imports `run` from a missing `../lib/missing`; `missing.ts` is added. After sync, the call links `missing.ts`, and call edges equal `scan --force`, in git and hash sync (`tests/import-bound-calls.test.ts`).
2. **Shadowing file:** an import of `../lib/utils` resolves to `utils/index.ts`; then `utils.ts` is added. After sync, the call links `utils.ts`, equal to `scan --force` (test).
3. **Unrelated module:** a new module no import names re-parses no other file ("Updated 1 files"; test).
