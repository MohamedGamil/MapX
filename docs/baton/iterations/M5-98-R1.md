# M5-98-R1 — `mapx check --since <git-ref>`: judge only what changed (ratchet)

## Identification

Milestone: M5; priority: P2; risk: medium; estimate min/expected/max: 4/8/12; role: TypeScript CLI engineer.

## Objective

`mapx check --since <ref>` reports and judges only the findings whose dependency is written in a file changed since the git ref, so CI can ratchet without a baseline or a second scan (REQ-ARCH-021). CLI, MCP (`mapx_arch_check since`) and docs agree.

## Dependencies

M5-06 (hard): baselines, `--compare`, the report's `selection`. M5-08-R1: git refs never reach a shell.

## Scope

- "Changed" is `getChangedFilesSinceBranchPoint` (review fix): `git diff --name-status <base>`, `<base>` being `git merge-base <ref> HEAD` (the ref itself when the histories are unrelated), so a ref that moved on after the branch left it does not count; committed, staged and unstaged edits, both paths of a rename; a git failure after the ref resolved is exit 3. Plus untracked files not ignored; `.mapx/` is never source. A workspace whose root is no repository works through its registered repos (`changedSince`).
- Decision: a finding counts when its **source** file changed. A dependency is written in its source file, so a changed target alone does not make an existing dependency new. This replaces the MCP filter's "source or target" for `since`, so the CLI and MCP agree. Non-dependency findings (a layer with no source) are dropped; configuration and baseline errors always stay (exit 3).
- Composition: the filter runs after evaluation, so `--baseline` and `--compare` skip first (their skipped findings are filtered the same way under `--report-skipped`), `--layer`/`--rule` narrow as before, every `--format` renders the filtered report, and the exit code follows AR-17 on it. `--generate-baseline` refuses `--since`. A base report narrowed by `--since` is refused by `--compare`. The report's `selection` records `since` when given.
- Safety: the ref is validated once (not empty, no leading `-`, no whitespace, quotes or shell characters) before the index is touched, by a function shared with MCP; git runs through `execFileSync` argument arrays only.

## Out of scope

A second scan at the ref (the original REQ-ARCH-021 wording): the index is not rebuilt at the ref; `--compare` remains the tool for "new relative to a base report".
