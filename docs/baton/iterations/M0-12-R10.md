# M0-12-R10 — Svelte templates: calls, event handlers and child components

## Identification

Milestone: M0; priority: P2; risk: medium; estimate min/expected/max: 3/5/8 h; role: parsers. Source: the M0-12-R8 report (Limitations), owner Q&A D019.

## Objective

A `.svelte` template's expressions give call references, its event handlers handler references and its component tags render edges, by the exact rules of `.vue` templates.

## Scope

**`svelteTemplateReferences` in `src/parsers/languages/svelte.ts`.** It works on the source with the scripts, `<style>`, comments and `<svelte:head>` scripts blanked.

Calls come from:
- `{expr}` blocks;
- block headers: `{#if}`, `{:else if}`, `{#each}`, `{#await}`, `{#key}`, `{@const}`, `{@render}`;
- attribute values, both `{…}` and quoted strings with `{…}`;
- `use:` actions.

A handler named by itself (`on:click={save}`, Svelte 5 `onclick={save}`) is a call of it. An inline handler (`onclick={() => remove(1)}`) contributes the calls it makes.

Never resolved, because they are local to the template:
- each-block items and indexes;
- `let:` names;
- `{@const}` names;
- `{:then}` / `{:catch}` values;
- snippet names and parameters.

`{@html}` and `{@debug}` are skipped.

**Resolution.** The references carry the Vue resolution hint (`metadata.vue`):
- a call goes to the component's own function, else to the module it imports the name from, never by name elsewhere;
- a capitalised or dotted tag gives a render edge to the file its import resolves to, through a barrel for `import * as ui` / `<ui.Button>` (`moduleMember`).

The scanner's render branch accepts `.svelte` targets, alongside `.vue`.

## Out of scope

- Svelte 5 runes semantics beyond the existing script handling (M0-12-R8).
- Global component registries, which Svelte doesn't have.

## Acceptance criteria

1. **Calls** (e2e, `tests/svelte.test.ts`, "Svelte templates …"):
   - `{format(1)}`, `on:click={save}` and `onclick={() => remove(1)}` give call edges owned by the component, to the imported `format` and to the component's own `save` and `remove`.
   - The each-block alias `{item()}` is not linked, although the component declares `item()`.
2. **Renders:** `<Child />` and `<ui.Button />` give render edges to `Child.svelte` and, through the barrel, to `ui/Button.svelte`.
3. **Ignored text and no regressions:**
   - References inside `{@html}`, comments and `<style>` are ignored, although the component declares those names (`helper`, `remove`);
   - the edges scorer does not drop (`npm run eval`);
   - the M0-12-R8 parity test still holds for script edges.
