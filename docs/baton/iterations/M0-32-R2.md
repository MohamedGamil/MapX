# M0-32-R2 — Cycle smells keep their path order; small follow-ups from integration

## Identification

Milestone: M0; priority: P2; risk: low; estimate min/expected/max: 1/3/4 h; role: TypeScript maintainer (analysis, HTTP extraction, packaging, parsing).

## Objective

Stored cycle smells list their files in cycle order; the HTTP line lookup and the package `files` list are guarded by tests; the parse worker stops carrying a stale JSONC copy.

## Dependencies

M0-32-R1, M2-06-R1, M0-07-R2, M0-09-R3 (all hard; their reports are the sources). No approval gate.

## Scope

Four findings recorded as limitations in the source reports:

1. **Cycle order (M0-32-R1).** `ArchitectureAnalyzer.analyze()` built its dedup key with an in-place `sort()`, so every stored smell's `involvedFiles` came back sorted, and a cycle `[e, d, e]` was stored as `[d, e, e]`. The key is now computed on a sorted copy, and a cycle smell's `involvedFiles` is its path without the closing repeat (`[e, d]`), in path order.
2. **Multi-line bundle (M2-06-R1, mutant M14).** The large-bundle timing test is single-line, so a quadratic `slice(0, i).split('\n')` line lookup survived it. Add a many-line variant that a quadratic lookup fails.
3. **Package files (M0-07-R2).** `package.json` `files` gets `"!dist/mapx-*"`, so the bun binaries are never packed even if they sit in `dist/`. Test: a throwaway package with the repo's real `files` and fake binaries passes `scripts/check-package.ts` and does not list them.
4. **Shared JSONC parser (M0-09-R3).** `src/parsers/parse-worker.ts` imports `stripJsoncSyntax` from `static-file-parser.ts` instead of keeping its old regex copy, which rewrote `key:` inside strings and so dropped `$ref`/`extends` of such JSON files when parsed in a worker.

## Out of scope

- The worker's other duplicated static extractors (markdown/HTML/CSS/YAML) versus `StaticFileParser`: not in the findings.
- Changing what the dedup treats as a duplicate (still type + set of files).

## Implementation plan

- `src/core/architecture-analyzer.ts`: dedup key from `[...files].sort()`; `involvedFiles: [...new Set(cyclePath)]`.
- `tests/architecture-scc.test.ts` (fast part): pin path-ordered, deduplicated `involvedFiles` on the known graph and on the 20,000-file chain.
- `tests/http-client-calls.test.ts`: many-line bundle timing test (CPU budget and 10x-input ratio).
- `package.json`: `"!dist/mapx-*"` in `files`.
- `tests/legacy-distribution.test.ts`: fixture package with the real `files` list.
- `src/parsers/parse-worker.ts`: import the shared `stripJsoncSyntax`, delete the copy.
- `tests/worker-parsing.test.ts`: a JSON file with `"{ key: v }"` in a string and a `$ref`, parsed through `parseWithWorkers`, yields the `$ref` reference like the main-thread parser.

3. `package.json` `files` excludes `dist/mapx-*` binaries (`tests/legacy-distribution.test.ts`).
4. `parse-worker.ts` uses the shared JSONC parser (`tests/worker-parsing.test.ts`).
