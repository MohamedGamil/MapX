# M4-28 — Release documentation for 0.3.9: README, docs and CHANGELOG cover every change since 0.3.5

## Identification

Milestone: M4; priority: P1; risk: low; estimate min/expected/max: 4/8/12 h; role: technical writer with the CLI, MCP and architecture-rules surface at hand.

## Objective

Before the v0.3.9 tag (D035, D036), the root README presents every feature MapX provides today, every `docs/*.md` page matches the code, and the CHANGELOG entries since 0.3.5 are complete, grouped and readable.

## Dependencies

Hard: M5-24, M2-08-R3, M5-15, M5-18 (all DONE). No approval gate; the release itself (G-RELEASE) stays owner-initiated (D007).

## Scope

- **README.md:** a feature overview table linking each feature to its doc page (languages and count, frameworks and routes, HTTP pairing, the parse worker pool, external references and package attribution for npm, Composer, pip/Poetry/uv and Go, architecture rules with `mapx check`, exit codes, CI reporters, baselines, selectors, `mapx arch init` and presets, `mapx arch graph`, rule-derived smells, the dashboard and its Architecture view, the 39 MCP tools, workspaces, agent integration, the CLI logo); a quick start that runs as written in an empty folder; an architecture-rules section; a corrected commands table, language table, storage and configuration summary.
- **docs/*.md:** every CLI command and flag in docs/cli-reference.md, every MCP tool and parameter in docs/mcp-integration.md, settings and environment variables in docs/configuration.md, language tiers in docs/getting-started.md, docs/adding-languages.md and docs/architecture.md, framework count and an HTTP pairing section in docs/framework-integration.md, the per-ecosystem attribution sources in docs/architecture-rules.md.
- **CHANGELOG.md:** [Unreleased] grouped by feature area under Added, Changed and Fixed; stale wording removed; every user-visible change since v0.3.5 covered.
- **tests/docs-surface.test.ts:** a cheap test that keeps the CLI and MCP docs, the stated counts and the docs' relative links in step with the code.

## Out of scope

- Code changes. Doc/code mismatches that are code bugs are reported, not fixed.
- The root CLAUDE.md generated block (the owner hand-edits it); the regenerating command is reported.
- Version bump, `[0.3.9]` section, tag and release (owner, D007, D035).
- docs/baton (other than this spec and the report), docs/research, specs/.

## Implementation plan

1. Script the checks: walk `buildCLI()` against docs/cli-reference.md (per command section and in reverse), list the MCP tools through an in-memory client against docs/mcp-integration.md, compare settings (`src/types.ts`, `src/core/config-report.ts`) and `MAPX_*` variables with docs/configuration.md, languages (`mapx lang list`, `supportedLanguageCount()`) and framework detectors (`FrameworkRegistry`) with the docs.
2. Fix every gap the scripts and a read-through find.
3. Rewrite the README's top half; run the quick start verbatim in a temp folder.
4. Regroup the CHANGELOG with a script that places every existing entry exactly once.
5. Turn the scripted checks into `tests/docs-surface.test.ts`; mutation-check it.
