# M4-22 — Read-only config view in the dashboard

## Identification

Milestone M4; P2; risk medium; estimate 6/10/16 h. Decision D027.

## Objective

The dashboard shows the effective configuration: repos, include and exclude patterns, parse workers, PHP facade map, HTTP clients and hosts, user languages. Each value is marked default or user-set, with validation warnings.

## Background

D027: read-only first; editing would be a later task with its own write API.

## Dependencies

- M4-21 (hard)

## Out of scope

Editing config (a later task with its own write API, D027).

## Acceptance criteria

1. /api/config returns the effective settings with each value's source (default or user), the repos and user languages, and validation warnings, such as an invalid parseWorkers or an unknown setting (tests/ui-server.test.ts).
2. The server exposes no write method for config: POST, PUT, PATCH and DELETE on /api/config answer 405 (test).
3. A Config tab renders the settings, sources and warnings (tests/ui).

## Verification

- `npx vitest run tests/ui-server.test.ts`
- `npm run test:ui`
- `npm run check`
