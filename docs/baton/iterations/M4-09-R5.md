# M4-09-R5 — No test leaves temp folders: a suite-wide check

## Identification

Milestone: M4; priority: P2; risk: low; estimate min/expected/max: 2/3/4 h; role: test infrastructure engineer.

## Objective

A vitest global teardown and Playwright's global teardown assert that a run leaves nothing in the temp directory its tests used, naming each leftover, and the tests that leaked clean up. An interrupted run (SIGINT, SIGTERM, SIGHUP) leaves nothing either, the built-CLI mirror `mapx-cli-*` of `tests/helpers/e2e.ts` included.

## Dependencies

M4-09-R3 (hard, DONE): the per-file `afterAll` check of `external-refs.test.ts`, which this generalises to the whole suite. M4-09-R2 (DONE): `scripts/baton/check-test-cwd.mjs`, the opt-in private-TMPDIR wrapper.

## Cause (measured 2026-11-04, `develop@f417439`)

- **Nothing asserted it for the suite.** `npm test` ran in the shared `/tmp`. `check-test-cwd.mjs` gives a run a private TMPDIR but is not part of `npm run check`, and only `external-refs.test.ts` counted its own folders. The finding of 2026-11-03 (437 `mapx-*` and 123 `playwright-artifacts-*` folders in `/tmp`) is what accumulates from failed, killed and interrupted runs, which skip `afterEach`/`afterAll`.
- **Measured leaks of a passing run.** (`npm run check` first: `TMPDIR=/tmp/m5chk npm run check` exited 0 after the vitest teardown was in, and left 4 `baton-review-test-*` and 2 `baton-scan-*` folders from `npm run test:skills`; they are the biggest groups in the shared `/tmp`, 1,984 and 1,206 entries.) `TMPDIR=/tmp/m5t1 npx vitest run` (156 files, 3,235 passed, 4 skipped, exit 0) left one folder besides the tools' caches: `tmp.DmaaLZhlFL/mapx-9.9.9`. It is made by the self-extracting installer of `scripts/make-installer.sh`, which `tests/installer-replace.test.ts` runs: the installer unpacks into `mktemp -d` and then `exec`s `install.sh`, which drops its EXIT trap. No `mapx-arch-*`, `mapx-e2e-*`, `mapx-bench-*` or `mapx-extrefs-*` folder remained. `TMPDIR=/tmp/m5t2 npm run test:ui` left nothing (47 passed; `arch.spec.ts:85` failed on the unchanged tree, see Out of scope).
- **Interrupted runs.** SIGINT on `npx vitest run tests/arch-since.test.ts` left `mapx-cli-*`, `mapx-e2e-*` and `mapx-arch-since-out-*` in the private folder, because `afterAll` does not run (M4-30 review).
- **A long private TMPDIR breaks tsx.** The first private run used a path of about 120 characters: `tsx` puts a unix socket in `$TMPDIR` (limit ~107 bytes) and 7 CLI tests failed with `node:net:2368`. The private folder is therefore made under the OS tmpdir the run started with.

## Scope

- **`tests/helpers/run-tmp.ts`:**
  - `isolateTmp()` makes `<tmpdir>/mapx-run-tmp-XXXXXX` in the runner's main process and sets TMPDIR, TMP, TEMP and `MAPX_RUN_TMP` to it before any worker starts. Workers and the CLIs they spawn inherit it (verified: `os.tmpdir()` in a vitest fork, in a Playwright worker, and in a spawned node child all return it).
  - It also removes the folder on SIGINT, SIGTERM and SIGHUP and marks the run interrupted. vitest's setup passes `exitOnSignal`, so the runner exits (129, 130, 143) after the sweep whatever else listens: vitest's own listener (signal-exit) re-kills only as the sole listener, so ours alone would keep a runner that got SIGHUP alive. Playwright runs its teardown, so there ours exits only when nothing else listens.
  - The path is absolute (`resolve(tmpdir())`), so a relative TMPDIR names one folder for every child.
  - When `MAPX_RUN_TMP_OWNED` names the current TMPDIR (set by `scripts/baton/check-test-cwd.mjs`, which owns and checks its folder) no second folder is nested, to keep tsx's socket path short. Worst case: macOS's `/var/folders/xx/<30>/T` is ~49 characters, the wrapper adds `/mapx-check-cwd-tmp-XXXXXX` (27), our folder `/mapx-run-tmp-XXXXXX` (20) and tsx `/tsx-501/<pid>.pipe` (~19): 115 nested against a 104-byte `sun_path`, 95 without nesting. On Linux the same sum is 4+27+19 = 50.
  - `finishTmp(dir, label)` lists what the run left, ignoring the tools' caches (`node-compile-cache`, `v8-compile-cache*`, `tsx-<uid>`, `playwright-transform-cache-*`), removes the folder, and, unless interrupted, sets `process.exitCode = 1` and throws a message that names every leftover with its first entries and the test or script files that name its prefix.
- **`tests/global-teardown.ts`** (vitest `globalSetup`, registered in `vitest.config.ts`) and **`tests/ui/global-teardown.ts`** (`playwright.config.ts` `globalTeardown`, with `isolateTmp()` first in `tests/ui/global-setup.ts`).
- **`npm run test:skills`** (the other half of `npm run check`) runs under `scripts/baton/check-test-cwd.mjs --cmd`, which gives it a private TMPDIR and fails naming a leftover. Its two files (`baton-scan.test.mjs`, `review-scope.test.mjs`) made `baton-scan-*` and `baton-review-test-*` folders and never removed them: a `TMPDIR=/tmp/m5chk npm run check` left 6 of them. They now remove them in `after`.
- **`tests/installer-replace.test.ts`:** the installer processes run with TMPDIR inside the test's own folder, so the unpacked archive goes with it.
- **`tests/global-teardown.test.ts`:** real, tiny vitest and Playwright projects run in temp folders (see Acceptance).
- One line in `.claude/skills/baton/SKILL.md` (section 3) and a CHANGELOG entry.

**Approach and why.** A private folder per run, not a before/after snapshot of the shared tmpdir: other agent sessions and test runs create `mapx-*` folders in `/tmp` meanwhile (a snapshot would flake), `/tmp` held 15,000+ entries, and the folder can be removed whole, so failed or killed runs stop accumulating. It also makes a single-file `npx vitest run tests/x.test.ts` safe: it gets its own folder. A cold tsx cache costs nothing measurable (`vue-stores.test.ts` 20 s with, 32 s without, on a noisy machine).

## Out of scope

- **The self-extracting installer's own leak** (`exec` drops the EXIT trap, so every real run of `mapx-*-installer.sh` leaves its extracted archive in `$TMPDIR`): the test contains it; the script is a product change for the owner.
- **vitest's own `<tmpdir>/<21 characters>` folder**, left by vitest when SIGINT ends a run: vitest's, made before any global setup.
- **`playwright_chromiumdev_profile-*` and `com.google.Chrome*` folders in the shared `/tmp`** from killed browsers: the private folder covers the browsers a run starts; old ones are untouched.
- **A SIGKILL or a crashed runner:** no hook runs.
- **`arch.spec.ts:85` (Violations tile shows 23, expects 16)**, failing on the unchanged tree: bisected by the integration owner to M2-12 (6498e16); fixed by M2-12-R1.
- **The perf budgets** (M4-24-R1, M6-09): not changed.
- **Old leftovers in the shared `/tmp`:** not deleted.

## Acceptance criteria

1. After `npm run check` and `npm run test:ui`, no entry remains in the temp directory the run started with (the teardowns assert their private folder is empty); removing one test's cleanup fails the teardown naming that folder. Shown by mutation: `tests/config.test.ts` without its `rm` fails with `mapx-config-test-…/ <- tests/config.test.ts`; `tests/ui/harness.ts` `stop()` without `rmSync` fails with `mapx-ui-smoke-…` and `mapx-ui-config-…`.
2. The run's tests and spawned CLIs see the private folder, and other processes' folders in the shared tmpdir never count (`tests/global-teardown.test.ts`: "is wired in", "does not look at the shared tmpdir").
3. A run stopped by SIGINT, SIGTERM or SIGHUP leaves nothing in its starting temp directory (vitest's own folder aside) and, for Playwright, is not reported as a leak (`tests/global-teardown.test.ts`, 3 signals × 2 runners, sent to the whole process group). A signal sent to the runner process alone ends it at once with exit code 129, 130 or 143 under both runners.
5. Under `check-test-cwd.mjs` no second private folder is nested, and a relative TMPDIR gives an absolute private folder (`tests/global-teardown.test.ts`, `tests/check-test-cwd.test.ts`).
4. The tools' caches are not leftovers; a leftover from a child process (`mktemp`) is named too.
