# M3-05-R2 — Pinia hooks of any name in plain modules; Vuex arrow members in imported objects

## Identification

Milestone: M3; priority: P2; risk: low; estimate min/expected/max: 1/2/4 h; role: Vue store resolution.
Sources: `docs/baton/reviews/REVIEW-2026-11-02-b2558df592cf.md` (P2 item 6, M3-05-R1 DEFECTIVE), `docs/baton/reports/M3-05-R1.md`.

## Objective

Store calls link from TS/JS modules that import only a store hook, and Vuex arrow-function members in an imported object get symbols whatever the file name.

## Dependencies

- M3-05-R1 (hard): `fallback` Pinia targets, `parts` and `memberObjects`. DONE.

## Reproduction (develop@28dc907)

Both defects come from `src/parsers/languages/vue-stores.ts`:

1. **Gate.** `annotateStoreRefs` runs the store pass on a `.ts`/`.js` module only when `STORE_HINT` matches (a `use…Store` name, `dispatch(`, …) or when a hook call sits in a module importing `vue` / `pinia`. A composable that imports only `useWish` from `../stores/wish` matches neither, so `w.add()` keeps its name-lookup edge and `wish.clear()` (a built-in method name the generic extraction skips) gets no edge.
2. **Member files by name.** `memberObjects` gives arrow-function members a `method` symbol only in `getters.js` / `actions.js` / `mutations.js`, or for `export const actions = { … }`. A module with `actions: userActions` imported from `./userActions` records the part, but `userActions.js` has no `fetchUser` symbol, so `ctx.defines` fails and `mapActions('user', ['fetchUser'])` gives no edge.

The new e2e tests are run against the baseline before the fix (results in the report).

## Scope

- **Gate:** a hook call in a module that imports a hook (`use[A-Z]…`) from a project specifier (relative, absolute or `@/`, `~/`, `#/`) also runs the pass. Resolution is unchanged: an imported any-name hook stays a `fallback` target, confirmed from the store file's `piniaHooks`; a composable that is not a store keeps its default edges.
- **Member objects whatever the file name:** in a plain module (not a component, not a Vuex model), an exported object (default or named) whose members are all functions with a Vuex member's first parameter gives its arrow-function members `method` symbols:
  - an action's context: `context` / `ctx`, or an object pattern naming `commit`, `dispatch`, `rootState` or `rootGetters` (or `state` / `getters`);
  - a mutation's or getter's `state`.
  The kind (symbol scope) comes from the file or export name when it says `actions` / `getters` / `mutations`; otherwise from the signature (context → actions; `state` with an expression body → getters, with a block → mutations). The existing name-based files keep their behaviour. The gate admits files with such a first parameter.
