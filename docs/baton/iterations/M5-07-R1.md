# M5-07-R1 — CI reporters locate files from the repository root when the workspace is a subfolder

## Identification

Milestone: M5; priority: P2; risk: low; estimate min/expected/max: 1/2/3 h; role: CLI and CI integration engineer.

## Objective

When the MapX workspace is a folder below the root of its git repository (a monorepo package), the SARIF, GitHub, CodeClimate and JUnit reports name files from the repository root (`sub/app/x.php`), so GitHub code scanning, PR annotations, GitLab Code Quality and test reports point at the right files.

## Dependencies

M5-07 (hard, DONE): the CI reporters and their shared `locate`.

## Cause

Recorded in `reports/M5-07.md` (Limitations): every CI format writes workspace-relative paths. GitHub and GitLab resolve them from the checkout root, so in a monorepo whose workspace is `sub/` they name files that do not exist.

## Scope

- `src/core/git-tracker.ts`: `getRepoPrefix(dir)`, the folder's path from its repository's top level (`git rev-parse --show-prefix`, an argument array through `execFileSync`, as every git call there), `''` at the top level or outside git.
- `src/arch/reporters/context.ts`: `ReportContext.pathPrefix`; `locate` puts every location (source file, a stale entry's baseline, the configuration file) under it, normalised (`sub/../bl.json` is `bl.json`). SARIF's `targetFile` property follows.
- `src/cli.ts`: one line, the check's report context gets `pathPrefix: getRepoPrefix(dir)`. The reporters have no other way to learn the workspace folder (the report carries no root), so this line is outside `affectedFiles` and is the only change there.
- `tests/arch-reporters.test.ts`: a real `git init` repository with the workspace in `sub/`; the four formats checked against the JSON report's paths; a workspace at a repository root.
- `docs/cli-reference.md`: the CI formats section says paths are from the repository root.

## Out of scope

- Messages (`<file>#/entries/0` in a stale entry's message) and the `table` and `json` formats stay workspace-relative: they are read with the workspace, and the JSON report is the `--compare` input.
- A multi-repo workspace outside git (repos below the workspace): no single repository root; paths stay workspace-relative.
- JUnit has no `file` attribute on `<testcase>`: the Jenkins xUnit XSD the reporter is validated against does not allow one. The JUnit file locations are the `path:line` line of each testcase's body, which follows the prefix.
- `CHANGELOG.md`: the integration owner writes it (lane rule); the report carries the sentence.

## Implementation plan

1. Write the failing end-to-end test (temp git repository, workspace in `sub/`).
2. Add `getRepoPrefix`, `pathPrefix` and the prefixing in `locate`; pass it from the CLI.
3. Docs; mutation-check; registered commands and the full suite.
