# M2-08-R1 — Import-bound calls: export-from barrels in sync, and no fallback past a project import

## Identification

Milestone: M2; priority: P2; risk: medium; estimate min/expected/max: 2/4/6 h; role: resolution and incremental scanning.

## Objective

Sync re-links the importers of `export … from` / `export *` barrels as `scan --force` does. A JS/TS call whose name is imported from a project module that neither declares nor re-exports it links nothing, never another file's same-named symbol. The 2026-11-02 review found both in M2-08.

## Dependencies

M2-08 (hard, DONE).

## Scope

Attempt 1 was reverted (`reports/M2-08-R1.md`). Attempt 2 follows the owner's decision D032.

- **`queries/{typescript,javascript}/references*.scm`:** `export_statement` with a `source` gives an `import` reference, so a barrel has import edges to the modules it re-exports.
- **`src/core/js-source.ts` (new):**
  - `scanJs`: JS/TS text without comments, found outside string, template and regex literals and JSX text (in `.tsx`, `.jsx` and `.js` files), with a brace-balance flag;
  - `scanModule`: the same, reading only a `.vue` or `.svelte` file's `<script>` blocks;
  - `exportSkeleton`: the module's top level with function, method and arrow bodies emptied, including bodies after a return type; an unbalanced scan keeps everything;
  - `jsExportSignature`: a hash of the skeleton, every declared function, class, interface, enum and type-alias name (nested ones are indexed too), and whether the module has CommonJS exports.
- **`Scanner.findExport` (JS/TS):** returns "absent" when:
  - the scan balanced its braces, and the name does not occur in the module's skeleton;
  - the module has no CommonJS or `export =` exports (`exports` anywhere, compiled forms included);
  - every `export *` target resolves within the project and is itself absent.

  `resolveImportedCall` maps absent to no edge. Anything uncertain keeps the name-lookup fallback. `defaultExportName`, `isBarrel` and `importBindings` read the text through `scanJs`.
- **D032, sync cost:**
  - each parse of a JS/TS file records its export signature in `files.metadata.exportSig`;
  - `importerReferrers` walks a changed JS/TS module's importers, and those behind its barrels, only when the signature differs from the recorded one, or none is recorded;
  - other languages keep the M2-08 walk.
- **Deleted modules:** `removeFiles` queues the importers of a removed module, and those behind its barrels, in `pending_referrers:<repo>` in the removal transaction; the same sync takes them.
- **Barrels:** `import { x } from …; export { x }` counts as a barrel.
- **Resolution order:** `probeModule` tries the file's extensions before `/index.*`, as Node and TypeScript do.

## Out of scope

- **Python:** `from m import x` where `m` lacks `x` (`__getattr__`, star imports); the Python walk is ungated, as before.
- **A new file satisfying an import that did not resolve before:** the importer is not re-parsed (pre-existing; registered as a follow-up).
- **Vue and Svelte modules:** no signature is recorded, so they keep the M2-08 walk.

## Acceptance criteria

1. **Barrel sync:** a module behind an `export { run } from` barrel, and one behind an `export *` barrel, gains the imported name; sync then links the importer's call to it, and the call edges equal `scan --force` (`tests/import-bound-calls.test.ts`).
2. **Absent name:** a name imported from a project module that declares it nowhere at its top level, nor behind its `export *` targets, gives no call edge. CommonJS or compiled exports, a name at the top level, an export-star target outside the project, or a local export alias keep name lookup. Each condition has its own case.
3. **Literals and comments:** a `/*` inside a string or a regex literal, and an apostrophe, URL or `/*` in JSX or Vue template text, hide no re-export or import; a commented-out default export names nothing.
4. **D032, in both git and hash sync:**
   - body-only edits of two modules behind a barrel, one with a return type, re-parse only those two ("Updated 2 files");
   - gaining an export re-parses the module, both barrels and their four importers ("Updated 7 files"), and so does removing or renaming one;
   - a barrel edited in the same sync, a JSX module gaining an export, and deleting the module each leave edges equal to `scan --force`.
5. **Resolution order:** `./utils` resolves to `utils.ts` when `utils/index.ts` exists too.
6. **No regression:** the edges, routes and HTTP scorers hold their floors (`npm run eval`).
