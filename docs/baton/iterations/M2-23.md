# M2-23 — Laravel database/ and resources/views/ PHP files get edges

## Identification

Milestone: M2; priority: P2; risk: medium; estimate min/expected/max: 2/4/8 h; role: parser and resolution engineer.

## Objective

PHP files under `database/` (migrations, seeders, factories) and `resources/views/` (plain PHP and Blade) give the edges that name a class when they are indexed, so the `laravel` preset's Database and Views rules are exercised. Whether the directories are indexed at all stays the documented, configurable Laravel default (`laravelDefaultExcludes`).

## Dependencies

None. Found by M5-17-R1 (`reports/M5-17-R1.md`, "Finding (review round)"). Related, out of scope: M2-22, M2-28.

## Cause (probe, 2026-11-04, `develop@41a94ed`)

A copy of `tests/fixtures/arch-init/laravel11` (`composer.json` with `laravel/framework`, `artisan`), initialised the way the e2e helper does (`init --no-suggestions`) and scanned with the real CLI:

- **Indexed, no edges.** `database/factories/OrderFactory.php` and `database/seeders/DatabaseSeeder.php` are indexed with their symbols (`OrderFactory`, `$model`, `definition`, `DatabaseSeeder`, `run`) and have 0 edges, though `use App\Models\Order;`, `new Order(...)` and `Order::factory()` are in them. The same lines in `app/Actions/CreateOrder.php` give an `import` and a `call` edge. Moving the seeder to `app/Seeders/` did not change it, so the folder is not the cause: the content is.
- **Cause 1 (php.ts, F10).** After a file's classes are classified (`laravelRole` migration, seeder or factory, from the folder or from `extends Migration|Seeder|Factory`), `references.length = 0` drops every reference of the file. F10 meant to remove the schema builder's noise (`$table->id()`).
- **Cause 2 (php.ts, F10).** `parse()` returned `{ symbols: [], references: [] }` for any `.blade.php` file. The Blade file `resources/views/orders/index.blade.php` (`@php use App\Models\Order; @endphp`) is indexed (language `php`, role `pages`) with no symbols and no edges.
- **Cause 3 (config.ts).** The migration `database/migrations/2024_01_01_000000_create_orders_table.php` was not in the index at all: `Config.init` adds `PHP_INIT_EXCLUDES` (`**/migrations/**`, `**/seeds/**`, `**/storage/**`) to any project with a root `composer.json`, also to a Laravel app that declined the Laravel excludes.
- **Cause 4 (queries).** `X::class` is no reference in any PHP file: `$this->call(OrderSeeder::class)` (a seeder in the same namespace, no `use`), `protected $model = Order::class` and `@inject` name a class and give no edge, unless a `use` line names it.
- By default, `mapx init` on a Laravel app (non-TTY, or the prompt's default yes) adds `database/{migrations,seeders,factories}/**`, `resources/views/**` and `**/*.blade.php` to the excludes (`LARAVEL_DEFAULT_EXCLUDES`, F10), which is why a real Laravel index has empty Database and Views layers. The prompt called Blade "not yet supported".

## Scope

1. **Edges that name a class in migrations, seeders, factories and views.** In a file of one of those roles, and in any file under `resources/views/` (plain PHP or Blade), the PHP parser keeps every reference. `X::m()`, `new X`, `use`, `extends`, `implements`, type hints, function calls, relations, dispatches and bindings are kept. A method called on an object (`$x->m()`) is kept only when the syntax gives the receiver's class, and then it links that class's method and never falls back to name lookup (`noFallback` metadata, read by `resolveNewReceiverCall`): `$this->m()` (the class around, walked as `self::m()`, M2-16), `$m->m()` for a parameter with a class type (`Mailer`, `?Mailer`) that the function never writes (a closure reads it through `use`, an arrow function directly), `$this->prop->m()` for a typed or constructor-promoted property, and `(new X())->m()`, whose chain ending in a vendor base (Eloquent's `Model`) no longer falls back to name lookup (M2-12's open chain). Any other member call (an untyped `$x->m()`, `$table->id()`, `Order::query()->where()->total()`, `$this` in a view or in an anonymous class, M2-22) is dropped, since it would link every method of that name in the project.
2. **A method of a migration, seeder or factory is no by-name target.** `up`, `down`, `run` and `definition` are called by the framework; an untyped `$app->down()` in app code no longer links `database/migrations/…#down` (symbol-index entries flagged by `laravelRole`; the class walk of `$this->m()` still sees them).
3. **`X::class` in those files.** A new query capture reads `Class::class` (a name or qualified name, not `self`/`static`/`parent`). In the files of scope 1 it is an `import` reference to the class (resolved through `use` and the namespace, as an instantiation is), with `metadata.classConstant`. In every other PHP file it is still no reference (a generic `::class` edge changes every PHP index and is not this task).
4. **Blade.** `src/parsers/languages/blade.ts` turns a `.blade.php` source into PHP with the lines of the file kept: `@php … @endphp` and `@php(…)` blocks, `{{ }}`, `{{{ }}}` and `{!! !!}` echoes, `@use('Class'[, 'Alias'])` (a `use` statement) and `@inject('name', 'Class')` (names its class) become `<?php … ?>`; raw PHP tags stay; `{{-- --}}`, `@verbatim` and `@{{ }}` are blanked; every other directive stays text. The PHP parser reads the result.
   - A directive starts at a non-word character (`webmaster@php.net` is text), and `@php`, `@use` and `@inject` take the parenthesis after spaces or tabs only (`@php`, a newline, then `(` is a block), as Blade's own regex does.
   - **Cost/benefit.** About 120 lines, no dependency, and no new grammar. It gives a view its dependencies on models, services and controllers, which is what the Views layer of the preset checks (`Views: ["Models"]`). A full Blade grammar (`@if ($a)`, `@foreach ($xs as $x)`, `@include('view')`, `<x-component>`) would link views to views and components; that needs a name-to-file resolver for view names and component classes and is a follow-up, not needed for the layer rules.
5. **`mapx init` for a Laravel app that declined the suggestion** no longer adds `**/migrations/**` and `**/seeds/**` (only `**/storage/**`).
6. **The default exclusion stays, documented.** `LARAVEL_DEFAULT_EXCLUDES` is unchanged. `docs/configuration.md` ("Laravel default excludes"), `docs/architecture-rules.md` (the preset's limits), `docs/framework-integration.md`, the init prompt and the CHANGELOG say what is excluded, how to index it (decline, or list the defaults to keep in `laravelDefaultExcludes`) and what it then gives.
7. **`EXTRACTOR_VERSION` 32.**

## Out of scope

- **Flipping the default** (index `database/` and the views for every Laravel app): an owner decision, since it changes every existing Laravel index (file counts, clusters, roles, PageRank). Noted in the report.
- **`Foo::factory()` → `FooFactory`** (Laravel's naming convention), `Foo::m()` linking the method `m`: M2-28 owns `Foo::m()`; the class edge is what is given.
- **One-line anonymous-class source attribution** (`return new class extends Migration { … }` on one line): M2-22. A multi-line anonymous migration works: its calls take the method (`up`) as source, with no class scope.
- **`$this->m()` in an anonymous class** (a Volt component, `return new class extends Migration { … }`) and other receivers a local analysis would type (`$x = new X(); $x->m()`, a method's return type, `Order::query()->where()->total()`): the member call stays dropped there. M2-22 owns anonymous-class attribution.
- **Blade directives with PHP arguments** (`@if`, `@foreach`, `@can`), **view names** (`@include`, `@extends`, `view('orders.index')`), **`<x-component>`**: follow-ups.
- **`X::class` in every other PHP file.**
- **Other frameworks' migration folders** (Doctrine, Phinx under `/migrations/`): they take the same rule as Laravel's, since the parser classifies by folder. Their `use` and `new X` edges are now kept; nothing else changes.

## Acceptance criteria

1. **A migration, a seeder and a factory give their edges** (test "a migration calling a model…", "a seeder calling a factory…", "…other seeders by ::class…", "a factory gives an edge to its model…"): the anonymous and the named migration reach `app/Models/Order.php` (and `User.php`); `OrderSeeder` reaches `OrderFactory.php` (`import` and `call`) and `Order.php` (`instantiation`); `DatabaseSeeder` reaches `OrderSeeder.php` and `UserSeeder.php` (both by `X::class`, same namespace, no `use`); `OrderFactory` and `UserFactory` reach their model whether `$model` is written with a `use` or fully qualified.
2. **Member calls link the class the syntax gives, never a name** (tests "column calls by name never reach…", "a typed parameter, a typed property, `$this` and `new X` give their method, verified", "an untyped receiver, a reassigned parameter and a chain end in no by-name edge", "a view names no class…", "a method of a migration, seeder or factory is no by-name target…"): `Pricing` declares `id`, `string`, `name`, `count`, `create` and `save`; no migration, seeder, factory or view reaches `Pricing.php` through them. In a seeder, `$m->send()` (`Mailer $m`), `$this->mailer->dispatchMail()` (promoted), `$this->helper2()`, `(new Mailer())->dispatchMail()` and the typed property, closure and arrow-function forms give `verified` edges to their method; an untyped `$any->m()`, a reassigned parameter, `(new Order())->save()` past Eloquent's base, `Order::query()->where(1)->total()` and a view's `$this->m()` give none (an `Other` class declares the same names). An untyped `$app->down()`, `$m->up()`, `$s->run()` and `$f->definition()` in `app/` reach no file under `database/`, also after a `sync`.
3. **Blade** (tests "a Blade view gives the edges of its PHP blocks…", "a plain PHP view…", "a Blade file never links…"): the view reaches `Order.php`, `User.php` and `Pricing.php` through `@php use`, `@use`, `@inject`, echoes and an `@php` block; a commented, `@verbatim` or `@{{ }}` `Ghost` class gives no edge and no external reference; `$order->name()` and `$order->count()` link nothing; a view without PHP has no edge; a plain `resources/views/plain.php` gives its class edge and not `$x->name()`. Per piece (tests "Blade views are read as Blade does" and "bladeToPhp"): an address `foo@php.net` is text, `@php`, a newline and `(` is a block, `{{{ }}}` is an echo, `@php(…)` is one statement, `@@php` is escaped, `@use('X', 'Alias')` binds the alias, `@php` inside `@verbatim` is text, and a CRLF view gives each edge on its own line.
4. **The laravel preset exercises Database and Views** (describe "the laravel preset checks Database and Views"): on the preset's own Laravel 11 fixture, `check` has the one planted violation; after adding a seeder, a migration and a Blade view that use `OrderController`, `check` exits 1 with those three files as violators.
5. **Defaults documented and configurable; init fix** (test "indexes the migrations, seeders, factories and views of a Laravel app that declined the default excludes": `**/migrations/**` is not in `excludePatterns`; the existing `tests/legacy-globs.test.ts` cases keep the default exclusion and `laravelDefaultExcludes`).
6. **No regression.** `npm run eval` prints the same numbers as before; `score-arch` on `tests/fixtures/arch-rules` is unchanged; the route fixture floors hold; `tests/arch-init.test.ts` changes only in the laravel Database count.
