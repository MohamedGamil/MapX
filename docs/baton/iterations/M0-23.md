# M0-23 — Scan summary edge count disagrees with stored edges

## Identification

Milestone: M0; priority: P2; risk: low; estimate min/expected/max: 2/4/6 h; area: scanner, cli.
Sources: `docs/baton/reviews/REVIEW-2026-10-30-baseline.md`.

## Objective

Make the scan summary report the number of edges actually stored.

Reproduced 2026-10-30: in a two-repo workspace (backend PHP + frontend JS/Vue, `mapx scan . --all`) the summary printed "Found 14 symbols, 4 edges" while `select count(*) from edges` returned 1.

## Dependencies

none.

## Scope

Find where the scan summary edge count comes from (CLI scan output) and make it the stored count; add a regression test with the two-repo fixture from the review.

## Out of scope

Changing how multi-repo scans store edges.

- `tests/scanner-summary-count.test.ts`.

Before editing, run `mapx_impact` (or `npx tsx src/main.ts impact <symbol>`) on the symbols you change and note the blast radius in the report.
