# M2-16 — PHP `self::m()`, `static::m()` and `parent::m()` calls link the enclosing class's method

## Identification

Milestone: M2; priority: P2; risk: medium; estimate min/expected/max: 2/4/6 h; role: parser and resolver engineer.

## Objective

In PHP, `self::m()`, `static::m()` and `parent::m()` link to the method m of the class around the call (or of the first class of its chain that declares it), or of its parent, on any file layout.

## Dependencies

M2-13 (hard, DONE): one-line class attribution and per-declaration namespaces. M2-12 (DONE): the class-chain walk of `(new self())->m()` that this task reuses.

## Cause (probe, 2026-11-04)

A synthetic workspace was scanned with the real CLI on `develop@cf39a4b` (`scratchpad/M2-16/probe`): `User::name` calling `self::id()` and `static::tag()`, a one-line `OneLine` class, `Child extends Base` calling `parent::boot()`, `self::base()` and `static::base()`, and a one-line `Child2`. The only edges were `Child extends Base` and `Child2 extends Base`. No call edge existed for any of the calls, on one line or several.

The cause is the reference query. `queries/php/references.scm` captures a scoped call only when its scope is a `name` or `qualified_name` (`Foo::bar()`). In the PHP grammar `self`, `static` and `parent` are a `relative_scope` node, so they match nothing: `self::m()` extracts no reference at all.

## Scope

- **Query:** a `scoped_call_expression` whose scope is a `relative_scope` and whose name is a plain `name` captures the method name (`ref.target_self_call`). `self::$f()`, `self::{'x'}()`, `self::K` (a constant), `self::$x` (a static property) and `self::class` do not match.
- **Parser (`php.ts`):** for each capture, the class around the call, read from the syntax tree:
  - the nearest enclosing class, trait or enum declaration, looking through closures and arrow functions (a closure in a method binds `self` to its class);
  - an anonymous class between the call and a named one, or no class at all, gives no reference (M2-22 owns anonymous classes; outside a class `self` names nothing);
  - `self::` and `static::` record the enclosing class's name (the scanner knows the file); `parent::` records the class its `extends` names, resolved as every other class name (`use`, aliases, the namespace in force), and none when the class extends nothing.
  - The reference is a verified `call` to the method name, with `metadata.newClass` (the class the walk starts at) and `metadata.selfCall`.
- **Scanner (`resolveNewReceiverCall`):** the M2-12 walk, with two differences for `selfCall`:
  - `self` and `static` start at the enclosing class by its name (name lookup prefers the file's own declaration, so two global classes of one name in different files each reach their own methods, tested); `parent` resolves its class as `new parent()` does.
  - The method is the class's own, else the first base that declares it: PHP traits before the parent, depth first. A method no class of the chain declares gives **no edge**, whether the chain is closed or open. There is no inferred name lookup: `static::query()` of a Laravel model, whose parent `Illuminate\Database\Eloquent\Model` the project does not declare, never links a same-named project method or function.
  - Such a reference is no external-reference row either: it names a method, not the package class.
  - The edge is `verified`, with no `newClass`/`scoped` metadata.
- **Late static binding:** `static::m()` links the method the enclosing class's chain declares. A subclass that overrides m is not linked (the call may run it); it is documented, not modelled.
- **Trait conflict resolution (review):** the parser records the adaptation rules of a class's `use A, B { … }` block as `traitRules` in the class metadata: `B::x insteadof A` (the winning trait of x) and `A::x as ax` / `x as ax` (an alias, with its trait when written). A rule that only changes visibility (`x as protected`) is dropped. For a method with an `insteadof` rule the walk tries the winning trait first; a name that is an alias is looked up as the aliased trait method in the written trait, or in the class's traits in `use` order, before the parent.
- **Member map (review):** the walk reads a class's methods from a per-(file, owner) map built once per resolution phase from the symbol index, not by scanning every same-named method of the workspace for each reference (`__construct`, `get`, `save` made the scan superlinear). This also speeds M2-12's `new self` walk.
- **`EXTRACTOR_VERSION` 31** (30 for the references; 31 because a PHP class now stores `traitRules`).

## Out of scope

- **`Foo::m()` and `\Ns\Foo::m()`** (an explicit class on the left): the existing scoped-call reference, which names the class. Not changed; noted in the report.
- **Anonymous classes:** M2-22 owns their source attribution and symbols. Their `self::` links nothing here.
- **Subclass overrides of `static::m()`:** not linked (see above).
- **Sync gaining an edge:** in a workspace that is not a git repository, or a repository whose files are committed, `sync` re-parses only the changed file, so a method added to a parent does not link an unchanged child until it is re-parsed (the same holds for `(new X())->m()`, M2-12). In a repository with no commit every file counts as changed, which hides it. Left for a sync task.
- **Interfaces:** `static::make()` declared only by an interface the class implements links nothing (the walk takes traits, then the parent; interfaces are not walked, as at HEAD).
- **Two classes of one simple name in one file, in different namespaces:** a method's scope carries no namespace, so the walk takes the first. Rare, and M2-13's per-declaration namespace work is the place.
- **A trait's `self::m()` where only the using class declares m:** no edge (the trait is walked alone).

## Acceptance criteria

1. **`self::id()` in `User::name` links `User::id`** (test "self::id() in User::name links User::id, on several lines and on one"), and `static::tag()` links `tag`; the one-line class gives the same.
2. **`parent::boot()` links the parent class's boot** (test "parent::boot() links the parent class boot, multi-line and one-line"), up the chain (`parent::gp()` two levels up, `parent::__construct()`); `self::base()` and `static::midm()` reach inherited methods.
3. **Constants, static properties, `::class` and dynamic forms are no call edges**, and no edge reaches a same-named method of another class (tests "constants, static properties …", "self::helper() never links a top-level function …").
4. **Traits, abstract methods, interfaces, closures, enums, namespaces** (the matching tests): a trait method through `self::`, the class's own winning over the trait's; an abstract method's declaration; an interface constant is no call; a closure binds `self`; `self::from()` of an enum links nothing, `self::make()` links `make`; `parent::` resolves through `use` and the namespace.
5. **A vendor parent links nothing** (test "a vendor parent links nothing …"): `parent::boot()` and `static::query()` of a class extending `Illuminate\Database\Eloquent\Model` give no edge and no external-reference row, though the project declares `App\Support\Model` with those methods.
6. **Anonymous classes** give no edge to the class around them.
7. **Sync** drops the edge when the chain loses the method, and links it when the caller is re-parsed, as `scan --force` does.
8. **`npm run eval` holds** (exit 0, numbers as printed, before and after).
