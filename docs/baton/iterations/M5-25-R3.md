# M5-25-R3 — Go: an unversioned local replace outside the workspace is external

## Identification

Milestone: M5; priority: P2; risk: low; estimate min/expected/max: 1/2/4 h; role: resolver engineer.

## Objective

A go.mod `replace X => ../../outside/y` whose target folder is outside the MapX workspace makes imports of X external rows attributed to X, not internal. A replace whose target folder is inside the workspace stays internal.

## Dependencies

M5-25-R1 (hard, DONE): local `replace` directives reach the other module's packages. M5-23 (hard, DONE): Go attribution, and versioned replaces applied to their version only. M5-23-R1 (DONE): the module path of an unreadable go.mod from the folder layout.

## Cause

`goLocalReplaces` (`src/core/import-resolvers.ts`) returns every `replace M [v] => ./dir` directive whose target starts with `.` or `..`, joined to the go.mod's folder, wherever it lands. `goImportInWorkspaceModule` then counts the replaced module as the workspace's, so `decideExternal` drops its candidates: no row. The go.work reader already skips `use` folders outside the workspace; the replace targets of a go.mod or go.work do not.

## Scope

- `src/core/import-resolvers.ts`: `goLocalReplaces` keeps a directive only when its target folder lies inside the workspace or a registered repo, by its real path (`ImportContext.localDir`, supplied by the scanner; review). This covers go.mod and go.work, versioned and unversioned directives.
- `src/core/manifests/go.ts`: a module replaced by a local directory is attributed `manifest`: go.sum never holds a directory's hash (review; the first delivery gave `lock` when go.sum was complete).
- `src/core/scanner.ts`: `goLocalDir`, the real-path test against the workspace root and the registered repos.
- `tests/external-refs.test.ts`: e2e scans with outside and inside targets, versioned and unversioned, in a go.mod and a go.work; a repo registered above the root; symlinks; the go.sum states.

## Out of scope

- An absolute replace target (`=> /abs/y`). The resolver never treated one as the workspace's, so its imports are already external rows. Whether an absolute path lies inside the workspace is not checked.
- Reading the replacement folder outside the workspace (never done, as for go.work `use`).

## Implementation plan

1. Write the failing test with the real `Scanner` over a temp workspace: the Go import rows and the import edges of `svc/cmd/main.go`.
2. Filter the outside targets in `goLocalReplaces`; set the attribution of a local replacement.
3. Decide the extractor version: the externality and attribution are decided at the end of every scan and sync from the stored candidates (M5-19), so a bump is needed only if parse-time output changes.
4. Mutation-check; registered command; typechecks.

Test "a local replace outside the workspace …".
