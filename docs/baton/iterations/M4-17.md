# M4-17 — Dashboard look and feel: design system, themes, responsive and accessible

## Identification

Milestone M4; P1; risk medium; estimate 6/10/16 h. Decision D027.

## Objective

Give the dashboard a consistent design system (tokens for colour, type, spacing, radius, elevation), light and dark themes, a responsive layout and accessible contrast and focus, across every tab.

## Background

D027. Scope and priorities come from the M4-16 audit.

## Dependencies

- M4-16 (hard)
- M4-19 (hard)

## Out of scope

The logo (M4-18); performance (M4-20); new views (M4-21 to M4-23).

## Acceptance criteria

1. styles.css defines colours, type scale, spacing, radii and shadows as CSS custom properties, and no colour literal appears outside the token blocks (a check script, run by the UI tests).
2. Light and dark themes follow prefers-color-scheme, with a toggle that persists; in both themes axe reports no serious or critical violations, colour contrast included, on every tab (tests/ui).
3. At 390, 1024 and 1440 px wide no tab scrolls horizontally, and the sidebar collapses on narrow screens (tests/ui).
4. Every navigation item and control is reachable with Tab and shows a visible focus ring (tests/ui).
5. Each M4-16 P1 finding owned by this task is resolved, with before/after screenshots in the report; the bundle stays under its gzipped ceiling (check-package).

## Verification

- `npm run test:ui`
- `npx tsx scripts/check-package.ts`
- `npm run check`
