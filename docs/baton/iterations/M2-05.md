# M2-05 — Base URL resolution

## Identification

Milestone: M2; priority: P1; area: http. Sources: report §4 items 12–13; D008.

## Objective

Read baseURL from factories, .env* (VUE_APP_*, VITE_*) and config modules, and join with axios semantics.

## Scope and plan

Delivered together with M2-04 in a single evaluator, `src/frameworks/http/url-resolver.ts`, because nearly every fixture call needs both: a constant or template, and a client base URL. The scanner's `scanHttpCalls` fills `url` (and `baseURLUnresolved` when the base can't be evaluated) on each D008 record.

- **M2-04:** string literals, `+` concatenation, template literals, file-local and exported or imported string constants. Unknown substitutions become `{}`; a URL with no literal part stays unresolved.
- **M2-05:**
  - base expressions: literals, constants, `process.env.X` and `import.meta.env.X` (from the app's `.env`, `.env.local`, `.env.development` and `.env.production`, nearest first), and configured `baseURL`;
  - joining follows axios `combineURLs`: an absolute request URL wins, otherwise the trailing `/` of the base and leading `/` of the path collapse to one;
  - `fetch` has no base.

## Out of scope

Pairing (M2-06); runtime-built URLs (function results, object lookups).

## Acceptance criteria

1. baseURL '/api/' joined with 'x' and with '/x' both give /api/x.
2. VITE_API_URL from .env.development is used when the factory reads import.meta.env.VITE_API_URL.

## Verification

- `npm run check`

## Recovery

Revert url-resolver.ts and the scanner change; records go back to having no `url`.
