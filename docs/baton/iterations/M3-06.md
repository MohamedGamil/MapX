# M3-06 — Vue Router navigation edges

## Identification

Milestone: M3; priority: P1; risk: medium; estimate min/expected/max: 5/8/12 h; role: parser / graph resolution.
Sources: docs/reports/2026-10-30-laravel-vue-coverage-findings.md §3/§4 item 11; `iterations/M3-01.md` (Edge contract, rule 9); reports M3-01, M3-02 and M3-07.

## Objective

Programmatic and declarative Vue Router navigation becomes part of the graph: `router.push({ name })`, `this.$router.push('/path')` and `<router-link :to>` give a `navigate` edge from the caller to the component the target route renders, in Vue 2.7 and Vue 3.x. The vue-router detector's route edges reach the real component file.

- M3-02 (hard, DONE): the component symbol (rule 1), ownership (rule 2) and the template tokenizer in `src/parsers/languages/vue-template.ts`.
- M3-07 (DONE): nested `package.json` activates vue-router for the fixture's sub-apps.

## Scope

Edge-contract rule 9 (iterations/M3-01.md):

- **New `ReferenceType` `navigate`** (`src/types.ts`).
- **Parser side** (`src/parsers/languages/vue-navigation.ts`, new; one hook in `vue.ts`):
  - script: `router.push` / `router.replace(…)` where `router` is bound to `useRouter()` or `this.$router`, or imported from a `router` module; `this.$router.push` / `replace(…)`; `useRouter().push(…)`;
  - template: `<router-link>` / `<RouterLink>` with `to="/path"`, `:to="'/path'"`, `:to="{ name: 'x' }"` or `:to="{ path: '/x' }"` (also `v-bind:to`); `$router.push(…)` inside a template expression;
  - the target is a route `name` (string literal) or a `path` (string literal, or a template literal whose `${}` parts stand for one whole segment each). Anything else gives no reference.
  - The reference has no owner; rule 2 (`assignOwners`) gives it the enclosing member or the component.
- **Scanner side:** a per-resolution-phase route table per repo, from the repo's JS/TS files that hold a route array (`routes: [ … ]`): each record's full path (with `children` prefixes), `name`, and component (`component: X` through X's import or `const X = () => import(…)`, `() => import('…')`, `require('…')`, `components: { default: X }`), resolved with the scanner's import resolver. A `navigate` reference resolves only through that table:
  - by name: the record with exactly that name;
  - by path: the record whose path equals the target, else the most specific record whose `:param` segments match;
  - a record with a `redirect` (string or `{ name }`) and no component is followed (bounded);
  - when several router files define the target with different components, the router file nearest to the caller wins; still ambiguous → no edge;
  - the edge goes to the component `.vue` file, `target_symbol` = its component symbol, and carries `route: { file, name, path }` in its metadata. A name never selects a component by similarity.
- **Detector defect:** the vue-router detector resolves `component: X` through X's import in the router file (new optional `ScanContext.resolveImport`), and lazy `import()` / `require()` specifiers through the same resolver (aliases, missing extensions). A `.vue` handler's symbol is its component symbol.
- **Survives a scan:** `navigate` is not in `deleteFrameworkEdgesForRepo` / `dropFrameworkEdgesForRepo`, and the route registry (the source of `routes`) never sees it; status counts it under its own type.

## Out of scope

- Navigation from plain `.js` / `.ts` modules (stores, guards, composables): not part of rule 9's fixture; a follow-up if wanted.
- Named-route constants (`{ name: ROUTES.HOME }`), string concatenation (`'/x/' + id`), `router.go()`, navigation guards, `<router-view>` render edges.
- `trace` following `navigate` edges (not in `DATA_BEARING_EDGES`).
- Script-setup macros (M3-04), Vuex / Pinia (M3-05).

## Implementation plan

- `src/types.ts`: `navigate` in `ReferenceType`; optional `ScanContext.resolveImport(specifier, fromFile)`.
- `src/parsers/languages/vue-navigation.ts` (new): `navigationReferences(source)` (parser), `routeRecords(text)` / `componentBindings(text)` (shared with the detector), `matchRoute(target, records, sourcePath)` (scanner).
- `src/parsers/languages/vue-template.ts`: export the template tokenizer helpers (`maskBlocks`, `templateRange`, `templateNodes`); no behaviour change, `router-link` stays a non-render built-in.
- `src/parsers/languages/vue.ts`: one hook pushing `navigationReferences(source)` before `assignOwners`.
- `src/core/scanner.ts`: a `navigate` branch in `resolveReferencesWithMap`, the per-repo route table (`vueRouteTable`) reset with the other per-phase caches, `resolveImport` in the detector context.
- `src/frameworks/detectors/vue-router.ts`: import-based component resolution.
- Tests: `tests/vue-navigation.test.ts` (unit + e2e: scan, sync, `routes` CLI/MCP, status); fixture labels for the detector fix (`router-record`) and raised floors in `tests/vue-sfc.test.ts`.
