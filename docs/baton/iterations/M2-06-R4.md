# M2-06-R4 — Route domains are workspace hosts for HTTP pairing

## Identification

Milestone: M2; priority: P2; risk: low; estimate min/expected/max: 1/2/4 h; area: remediation (http).
Sources: `docs/baton/reviews/REVIEW-2026-11-02-b2558df592cf.md` (P2 item 9, M2-06-R2 row of the verdict table); background in `docs/baton/reports/M2-06-R2.md` ("Limitations").

## Objective

A literal `Route::domain` host pairs absolute-URL calls to it without a `.env` naming that host.

## Dependencies

M2-06-R2 (hard, DONE). No approval gate.

## Scope

Review finding (reproduced): `Scanner.workspaceHosts()` builds the set of the workspace's own hosts from `settings.http` (`hosts`, client `baseURL`s) and URLs in `.env*` values only. A backend route on `Route::domain('partners.example.com')` declares that the workspace serves that host, yet `axios.get('https://partners.example.com/partners/v1/feed')` stays unmatched until a `.env` names the host. The scorer fixture works around this with `VITE_OPS_URL` (L48).

- **`src/frameworks/http/pairing.ts`:** `routeDomainHosts(routes)` maps each host that live backend routes name literally in their `domain` (scheme and port dropped, lower-cased) to the app roots that declare it. A domain with any `{param}` or `{dynamic}` part names no single host and is skipped; so are domains of unmounted, overridden and client-side routes.
- **Who serves such a host** (independent review P1): when nothing else (`.env*`, client base URLs, `settings.http.hosts`) names it, the routes of the declaring apps serve it, and another app's routes serve it only through a matching domain with no `{dynamic}` part. Another app's domain-less routes never do. `pairCall` takes the map as `PairOptions.routeHosts`.
- **`src/core/scanner.ts`:** `pairHttpCalls` passes `routeHosts: routeDomainHosts(routes)` beside `hosts`.
- **Sync:** every sync that parses a file runs the post-scan analysis, which re-extracts routes and re-pairs every call with hosts recomputed from the new routes. A domain added or removed by a sync must re-pair as a full scan does; an e2e test checks both directions.
- **Synthetic case:** L48 (`VITE_OPS_URL`) stays as it is. The new case is an end-to-end workspace in `tests/http-pairing.test.ts` with no `.env` and no `settings.http`: a Laravel backend with `Route::domain('partners.example.com')`, a `{dynamic}` domain (`config(...)`) and a domain-less route, and a frontend calling them by absolute URL.
- **Scorer fixture:** the only literal domain in the scorer's backend (`tests/fixtures/laravel-routes`) is `ops.example.com`, already named by `VITE_OPS_URL`. The scorer case therefore adds a second, minimal Laravel app `partners-api/` inside `tests/fixtures/vue-http` (`Route::domain('partners.example.com')` → `GET partners/v1/feed`) and label **L49** `route-domain-host` (`vue3/src/services/partners.ts`, expected `FeedController@index`). Label **L50** `route-domain-foreign` calls the partners host on a path only the backend app serves (domain-less) and expects unmatched (review P2). `tests/http-pairing-fixture.test.ts` requires every labelled route to be a live route of `laravel-routes`; it also accepts the live routes the partners-api app reports when scanned alone (approved by the integration owner).

## Out of scope

- `{param}` domains (`{account}.example.com`) as host patterns: they name no single host, and a pattern such as `{sub}.{domain}.com` would admit third-party hosts. Calls to them still need a `.env` or `settings.http.hosts` entry. Recorded as a limitation.
- Non-Laravel host constraints (Express vhost, Django `ALLOWED_HOSTS`).
- Nothing else: the docs host list (`docs/cli-reference.md`, `docs/mcp-integration.md`) is updated in this task, approved by the integration owner.

## Implementation plan

- `src/frameworks/http/pairing.ts`: `routeDomainHosts()`, reusing `live` and the host normalisation of `domainPattern`.
- `src/core/scanner.ts`: `workspaceHosts(routes)`; the call site in `pairHttpCalls`.
- `tests/http-pairing.test.ts`:
  - unit: `routeDomainHosts` keeps literal domains (scheme, port, case) and drops `{param}`, `{dynamic}`, unmounted, overridden and client routes;
  - unit: another app's domain-less route never serves a host only route domains name; an `.env` host keeps today's pairing;
  - e2e (temp workspace, real `init`/`scan`, no `.env` host): a call to the literal domain pairs and gets an `http` edge; calls to a `{dynamic}` domain route's would-be hosts, and to a path only another repo serves, stay unmatched;
  - e2e sync: a sync that adds `Route::domain('…')` pairs the call; a sync that removes it unpairs it; each equals a forced full scan;
  - the fixture's unmatched-call list gains L50.
- Fixture: `partners-api/` app, `vue3/src/services/partners.ts`, labels L49 and L50, README line; `tests/http-pairing-fixture.test.ts` derives the partners-api routes from a scan.
- Docs: the host list in `docs/cli-reference.md` (pairing rules) and the `routes` entry of `docs/mcp-integration.md`.

Blast radius: `pairHttpCalls` is reached from `runPostScanAnalysis` and `refreshHttpIfInputsChanged` (every scan and sync). Only absolute-URL calls on a host a live route names literally change outcome.
