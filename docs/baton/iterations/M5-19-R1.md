# M5-19-R1 — An attribution-rules version re-decides external references without a re-parse

## Identification

Milestone: M5; priority: P2; risk: low; estimate min/expected/max: 2/3/5 h; role: indexer engineer.

## Objective

External-reference attribution records the version of its rules (`ATTRIBUTION_VERSION`, beside `EXTRACTOR_VERSION`). When MapX's attribution code changes and the version is bumped, the next sync re-decides every repo's external references from the stored candidates, without re-parsing files or bumping `EXTRACTOR_VERSION`.

## Dependencies

M5-19 (hard, DONE): `external_ref_candidates`, decided again at the end of every scan and sync (`decideExternalRefs`). M5-20 (DONE): the recorded attribution inputs (`external_inputs` in meta) and the skip of stored attribution while they stand.

## Cause

Found by M5-21-R1 (`reports/M5-21-R1.md`, "Findings outside this task"). `decideExternalRefs` keeps every stored attribution when none of the recorded manifest and lock inputs changed (`unchanged`). The record says nothing about the rules that produced the attribution, so a change to the rules alone never reaches an existing index without `scan --force` or an extractor-version bump, which re-parses every file.

## Scope

- `src/core/extractor-version.ts`: `ATTRIBUTION_VERSION`, with a comment history. Version 1 is every index whose record has no version. Version 2 covers the rule changes that shipped without one (M5-21-R1, M5-23-R1) and M5-25-R3 on this branch.
- `src/core/manifests/inputs.ts`: `ExternalInputs.rules`, the version that recorded the inputs; a record without one parses as 1.
- `src/core/scanner.ts` (`decideExternalRefs` only): stored attribution is kept only when the record's `rules` equals `ATTRIBUTION_VERSION`; every pass records it.
- `tests/external-refs.test.ts`: e2e on the git and hash syncs.

## Out of scope

- `mapx status` and the `check`/`arch` index gate do not report an index whose attribution an older rules version made. The next sync or scan fixes it. Left to the integration owner (see the report).
- Evaluation rules (M5-24-R4's opt-in): computed at check time, so they need no version (see the report).

## Implementation plan

1. Write the failing test. Scan a workspace with a PHP PECL class (`\Redis`, ambient since M5-21-R1) and a Go module. Make its stored rows what older rules gave, and record the previous rules version. Sync, and assert that the rows come out as the current rules say, 0 files are scanned, and the extractor version is unchanged. As a control, the same rows with the current version recorded stay as stored.
2. Add the version, the record field and the check.
3. Mutation-check; registered command; full suite and typechecks.
