# M5-21-R1 — Composer: classmap and files autoload attribution from vendor/ when present

## Identification

Milestone: M5; priority: P3; risk: low; estimate min/expected/max: 2/4/8 h; role: scanner and package manifests.

## Objective

When Composer's generated autoload metadata is there (`vendor/composer/autoload_classmap.php`, `autoload_files.php`, `installed.json`), a PHP class that a classmap loads is attributed to the package whose install path holds its file, and a function to the package whose `files` define it when only one can. This replaces the naming-convention heuristic for those names. PECL extensions (`Redis`, `Imagick`, `apcu_fetch`) are classified as decided in the report (M5-21 "not done").

## Dependencies

M5-21 (hard): the Composer attributor, the recorded inputs, the arch-rules Composer labels. No approval gate.

## Scope

- **Reading Composer's metadata as data.** `autoload_classmap.php` and `autoload_files.php` are arrays Composer generates (`'Class\\Name' => $vendorDir . '/pkg/name/src/X.php'`). They are parsed with a regular expression over their entries, never executed. `installed.json` (Composer 2's `{"packages": [...]}` with `install-path`, or Composer 1's list) maps each file to its package by the longest install path. Only these three files are read under `vendor/`, never a package's sources.
- **The vendor folder** is `vendor/` beside the composer.json or composer.lock that answers for the file (the nearest folder with a lock, else with a manifest). `config.vendor-dir` is not honoured (see the report).
- **Precedence.** A built-in, then a PECL name, then the classmap (exact class name, case-insensitive), then the lock's PSR-4/PSR-0 prefix, then `files` (a function no prefix covers: the one package whose `files` load it), then the existing convention and stale fallbacks. The classmap also settles sibling packages sharing a prefix (review P1-1 of M5-21) when the autoloader is optimised.
- **Lazily, cached per pass:** the three files are read and parsed only when a name reaches them, once per vendor folder per pass.
- **Inputs:** every vendor metadata path read (or probed and absent) joins the recorded inputs, so sync and the stale check notice a change (`src/core/manifests/inputs.ts` documents the set).
- **PECL decision:** see the report; a generated list of the PECL extensions of the reflected PHP.

## Out of scope

- Reading package sources under `vendor/` (never).
- `config.vendor-dir`, `COMPOSER` and `COMPOSER_VENDOR_DIR`.
- npm's `node_modules` (M5-20's policy is unchanged).
