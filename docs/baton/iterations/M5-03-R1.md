# M5-03-R1 — Qualified names from real scans; `not` over symbol-level selectors

## Identification

Milestone M5; P1; risk medium; estimate 6/9/14 h. Remediation of M5-03 (review `reviews/REVIEW-2026-11-02-b2558df592cf.md`, "P1 (open)"). Sources: AR-01, AR-03 in `docs/research/deptrac/02-abstract-feature-model.md`. A hard dependency of M5-04, M5-09 and M5-19.

## Objective

Element qualified names equal the documented form on a real scan in every namespace or module language. A `not` over a symbol-level selector does not pull files into a layer.

## Findings to fix (reproduced by a probe scan of one file per language before the change)

| Language | Stored before | Cause |
| --- | --- | --- |
| C++ | `acme::Order` for nested `namespace acme { namespace domain {` | first namespace symbol taken as the file namespace; `namespace a::b` not captured |
| Ruby | `Invoice` for `module Billing; module Core; class Invoice`; `class Billing::Receipt` missing, its method unscoped | no nesting; `scope_resolution` names not in the query |
| Elixir | `pay` without its module | no nesting |
| Dart | `domain.Order` for `library acme.domain` | the query captured the last identifier |
| Rust, Python in a subfolder | `crate::rsub::crate1::src::…`, `pysub.svc.src.app…` | module root was the repo; no caller passes `repoPaths` |
| Scala | `Util.x` was `x` (top-level function) | `object_definition` not an enclosing type |

Also: `{all:[{path},{not:{name}}]}` put every file in the layer; the file-private-via-symbol branch had no test; `language: typescript` missed `.tsx`.

## Scope

1. `queries/cpp/symbols.scm`: `nested_namespace_specifier` namespaces. `queries/ruby/symbols.scm`: `class`/`module` named by `scope_resolution` (name = last constant, scope = qualifier). `queries/dart/symbols.scm`: the whole `dotted_identifier_list`. `src/parsers/generic-wasm-parser.ts`: Scala `object_definition` encloses methods.
2. `src/arch/elements.ts`: C++, Ruby and Elixir use the `scoped` rule: the qualified name is the enclosing container's (by line range) plus the stored scope when it differs, plus the name. Python and Rust module paths start at the nearest `pyproject.toml`/`setup.py`/`setup.cfg` or `Cargo.toml`. `topLevel` in scoped languages: not inside a type, and not a member.
3. `src/arch/selectors/index.ts`: an `inapplicable` result (symbol-level selector on a file, or a selector not evaluated yet); `not`, `all` and `any` propagate it; `typescript` matches `tsx`.
4. Tests in `tests/arch-selectors.test.ts`; docs in `docs/architecture-rules.md`.

Out of scope: Kotlin `package` capture (documented path fallback, unchanged); C++ in-class method declarations (`void run();`), which the parser does not store as symbols; Java/C# nested-type chains (scope only, as before).

## Blast radius

The query changes alter stored symbols for C++ (one more namespace symbol per `a::b` namespace), Ruby (compact-named classes and modules now stored, their methods scoped), Dart (library symbol name) and Scala (object members become methods scoped to the object). Every scan is affected; `npm run check` and `npm run eval` (edges recall/precision) are the regression guards.

## Acceptance criteria

1. A real-scan test per namespace or module language (PHP, Java, C#, C++ nested and `a::b` namespaces, Ruby nested and compact modules, Elixir, Dart library, Rust crate in a subfolder, Python package in a subfolder, Go, Scala, Kotlin fallback) asserts the stored-symbol qualified names (`tests/arch-selectors.test.ts`, "documented qualified name").
2. On the PHP fixture, with Domain = `app/**` minus names ending `Controller`, `OrderController.php` is in Controller only and `Order.php` in Domain through its class; `not`/`all`/`any` of an inapplicable selector do not match a file.
3. File-level private membership through a top-level symbol is asserted for the Application/Internal files of the PHP, TS and Python apps, and the test fails when the branch is removed.
4. `language: typescript` and `ts` match `.ts` and `.tsx` files; `tsx` only `.tsx`.
