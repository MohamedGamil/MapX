# M3-02 — Vue template pass

## Identification

Milestone: M3; priority: P1; risk: medium; estimate min/expected/max: 10/14/16 h; role: parser / graph resolution.
Sources: docs/reports/2026-10-30-laravel-vue-coverage-findings.md §3 item 10, §4 item 8; the edge contract in `iterations/M3-01.md`.

## Objective

MapX reads a Vue SFC's `<template>`: event handlers and calls in bindings become `call` edges, and component tags become `render` edges to the child component, so a component's template is part of the graph in both Vue 2.7 and Vue 3.x.

## Scope

Edge-contract rules owned here (iterations/M3-01.md, "Edge contract"):

- **Rule 1, component symbol.** Every `.vue` file gets one symbol: name = basename without `.vue`, kind `class`, scope `null`, lines 1 … last line. It is built by an exported `componentSymbol()`, so M3-04 can add `props` / `emits` to its `metadata`.
- **Rule 2, ownership.** A reference in a named function or member keeps that member as its owner; everything else in the SFC (template, top-level `<script setup>` code, the direct body of `setup()`, component options) belongs to the component symbol. Value declarations (`const prefs = …`) and `setup` no longer own references.
- **Rule 4, template calls → `call`.** `@event="save"`, `@event="save(x)"`, `v-on:`, modifiers, calls in bound attributes (`:x`, `v-bind:`, `v-if`, `v-show`, `v-for` sources, custom directives) and in `{{ }}` interpolations. The target is, in order: a symbol of the same SFC (members, `<script setup>` functions and constants such as `emit`, functions returned from `setup()`); a function destructured from an imported call (`const { format } = useCurrency()`) in that module's file; in `<script setup>`, a named import in its module's file; then, in an Options API component, the `this.x()` steps of M3-03 (`vueThis` scope from `vue-options.ts`: mixins in Vue's merge order, then map helpers). Otherwise no edge (fail closed). `$`-prefixed helpers, property reads and member calls (`cart.clear()`) are not template calls.
- **Rule 5, component tags → `render`.** A non-native, non-built-in tag (PascalCase or kebab-case) registered locally (the `components` option, or any `<script setup>` import) or globally (`Vue.component('Name', X)` / `app.component('Name', X)`, X followed through its import, `require(…)` or `() => import(…)`) gives one `render` edge per child to the child `.vue` file's component symbol. HTML comments are ignored. Also the Laravel / Vite auto-registration idiom: `require.context(dir, deep, /\.vue$/)` or `import.meta.glob('./dir/**/*.vue')` in a file that calls `.component(…)` with a computed name registers every `.vue` file under `dir` by its basename.

Resolution design: the parser attaches a resolution hint (`metadata.vue`) to template references; the scanner resolves hinted references only through it (same file, the hinted modules, or the global registry), never by global name lookup, and does not store the hint on the edge. The global registry is built once per resolution phase and repo from the repo's JS/TS files that call `.component(`.

## Out of scope

- `this.x()` resolution and mixins for script code (rule 6): M3-03.
- `defineProps` / `defineEmits` metadata (rule 1 metadata, `script-setup-macro`), composable resolution in script code: M3-04.
- Vuex and Pinia (rules 7, 8): M3-05. Router navigation and `<router-link>` (rule 9): M3-06.
- Nested `package.json` detection: M3-07.
- Pug templates, `<component :is>`, recursive self-reference by `name`, components re-exported through barrel files, Nuxt path-prefixed auto-import names.

## Acceptance criteria

1. `@click="save"` yields a `call` edge from the component symbol to the component's own `save` (fixture labels `template-handler`, e.g. v2-004, v2-005); the same-named `save` in another component is never the target (negatives v2-013, v2-014, v3-010).
2. `<UserCard/>` registered locally or globally yields a `render` edge to `UserCard.vue` (patterns `component-local`, `component-global`, `v-model-component`); a registered tag inside an HTML comment gives none (negatives v2-025, v3-016).
3. Works for both the Vue 2.7 and Vue 3.x apps: every pattern above found in full in both `vue2/` and `vue3/`, and `component-symbol` 6/6.
4. Precision does not drop below the M3-01 baseline (62.5%), no other floor drops, and no new false positive.
