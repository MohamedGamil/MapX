# M4-21 — Multi-repo workspaces in the dashboard

## Identification

Milestone M4; P1; risk medium; estimate 6/10/16 h. Decision D027.

## Objective

The dashboard shows every registered repo: a workspace overview, a repo switcher, and repo-scoped views, with cross-repo edges marked.

## Background

D027. The UI server reads only the primary repo (config.repo) for clusters, profile, smells, DSM and metrics.

## Dependencies

- M4-17 (hard)

## Out of scope

The config view (M4-22); the HTTP view (M4-23).

## Acceptance criteria

1. /api/repos lists every registered repo with path, files, symbols, edges, last scan time and git state; on a 3-repo fixture the counts equal the store's (tests/ui-server.test.ts).
2. Clusters, profile, smells, DSM, metrics, symbols, routes and the graph accept ?repo=<name> (default: as documented), each tested on the 3-repo fixture.
3. The dashboard has a repo switcher (All plus each repo), kept in the URL, and a workspace overview; switching repo changes the graph to that repo's files, and cross-repo edges are drawn distinctly (tests/ui).

## Verification

- `npx vitest run tests/ui-server.test.ts`
- `npm run test:ui`
- `npm run check`
