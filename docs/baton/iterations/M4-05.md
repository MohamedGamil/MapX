# M4-05 — Build the dashboard only for release and serve, not on every install

## Identification

Milestone: M4; priority: P2; risk: low; estimate min/expected/max: 3/4/6 h; role: build tooling.

## Objective

Installing the package's dependencies (`npm ci` / `npm install`) no longer bundles the web dashboard. The dashboard is built when a package is produced (`npm pack`, `npm publish`, the release binaries) and when the dashboard is served from source.

## Dependencies

The hard dependencies are DONE. D019 orders this task after M4-01, M4-03 and M4-08. Source: `specs/KNOWN_ISSUES.md` § Building and Packaging: "invoked when needed … before release, or before serving UI in development environment".

## Current behaviour (`develop@ac26e66`)

`"prepare": "npm run build:npm"`, where `build:npm` is `tsup && tsx scripts/build-ui.ts`. So every `npm ci` bundles the dashboard (esbuild, about 690 KB gzipped).

Where the bundle is already built explicitly:
- the CI `build` job (`npm run build:npm`);
- the publish workflow (`npm run build:npm`);
- the release binaries (`make package-all` → `build-ui` → `bun run build:npm`);
- `make ui` (`npm run build:npm`).

Two places rely on `prepare`: the CI `test` job's package check, which says "npm ci already ran prepare (build:npm), so dist/ is current", and `npm run ui` from source, which serves whatever `dist/ui` an install left behind.

## Scope

- **`package.json` scripts.**
  - New `build:ui` runs `tsx scripts/build-ui.ts`, and `build:npm` becomes `tsup && npm run build:ui`.
  - `prepare` becomes `tsup` only, so `npm link` and git installs still get `dist/main.js`.
  - New `prepack` runs `npm run build:ui`, so `npm pack` and `npm publish` tarballs contain `dist/ui/main.js`.
  - A git dependency's install, `npm link` and `file:` installs run only `prepare`, and so have no dashboard. Independent review found this (P1). The owner chose to document it (D020): `npm run build:ui` adds it, and the server says so when the bundle is missing.
- **Development serve, in `src/ui-server.ts`.** When the server runs from source (a `.ts` module), `ensureDevBundle(root)` builds the bundle before serving if `dist/ui/main.js` is missing, or older than any file under `src/ui/`. It runs `scripts/build-ui.ts` with the repository's tsx, logging `Building the dashboard…`. An installed package (`dist/`) or a compiled binary never builds.
- **CI.** The `test` job runs `npm run build:npm` before `scripts/check-package.ts`.
- **Found while measuring (added to scope).**
  - `npm pack` runs `prepack` before `prepare`, and tsup's `clean: true` then deleted the bundle `prepack` had just built. `tsup.config.ts` now cleans with `['!ui/**']`, which keeps `dist/ui`.
  - `scripts/build-ui.ts` logs to stderr, because npm prints lifecycle output on stdout, inside `npm pack --json`. tsup's own output there was already present before this change.
- **CLI only.** The development build runs only when the CLI asks for it (`startUiServer({ devBuild: true })` from `mapx ui` and `mapx serve --ui`). Tests that start the server from source never build: on a fresh CI install, two such suites could otherwise build `dist/ui` at the same time.

## Out of scope

- The release-binary packaging (`Makefile`, `scripts/package.sh`): it already builds the dashboard explicitly.
- Dashboard size: D006, M0-15-R2.

## Acceptance criteria

1. **Install.** In a clean clone with `dist/` absent, `npm run prepare` (what `npm ci` runs) produces `dist/main.js` and no `dist/ui/`. Measured in a scratch clone sharing `node_modules`, and recorded in the report. `tests/package-scripts.test.ts` checks that no install lifecycle script (`preinstall`, `install`, `postinstall`, `prepare`) references `build-ui` or `build:ui`.
2. **Packing.** In the same clone, `npm pack --dry-run --json` lists `dist/ui/main.js` (`prepack` built it), and `npx tsx scripts/check-package.ts` passes. Measured and recorded. The test asserts that `prepack` builds the UI.
3. **Development.** `uiBundleStale(root)` is true when the bundle is missing, or older than any `src/ui` file, and false otherwise (unit test with mtimes in a temp dir). Starting `mapx ui` from source in the scratch clone, with no `dist/ui`, builds it and serves `main.js` with HTTP 200 (measured).
4. **Publishing.** `publish-npm.yml` still runs `npm run build:npm`, and `npm run build:npm` followed by `npx tsx scripts/check-package.ts` exits 0 in the checkout.
5. **CI.** The `test` job in `ci.yml` runs `npm run build:npm` before the package check (test).
