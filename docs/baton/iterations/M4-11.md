# M4-11 — A persistent, controlled worker pool

## Identification
Milestone M4; P1; risk medium; estimate 4/8/14 h. Decision D025.

## Objective
One pool of parse workers serves every parse batch of a scan or sync run, and, in `mapx serve`, successive tool calls. Its lifecycle is explicit.

## Scope
1. **`src/core/worker-pool.ts`:**
   - Workers start lazily up to the requested size.
   - Jobs are queued, and workers are reused across `parse()` calls.
   - Per-run context (ignored symbols, facade map, user languages, asset root) goes in a context message carrying a version, and each worker caches it by version.
2. **Lifecycle:**
   - **Idle timeout:** default 60 s, overridable with `MAPX_WORKER_IDLE_MS`. Timers are `unref`'d, so the CLI exits without waiting for them.
   - **Crash:** a crashed or exited worker is replaced, and its in-flight files are parsed again.
   - **Abort:** `abort()` terminates the pool.
   - **Shutdown:** `close()` terminates the pool.
3. **Scanner:** takes an optional pool. Without one, a scan or sync run creates a pool and closes it in `finally`. The MCP server holds one process-level pool, which its scanners share.

## Out of scope
- Sizing policy (M4-13).
- Language affinity (M4-12).
- Batching (M4-14).
