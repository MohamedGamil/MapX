## Objective

Call and type edges follow callables bound from factories, package-qualified embedded types and nested C++ definitions.

## Dependencies

- M0-17-R2 (hard): the callable filter in `resolveSymbolToFile` (constants and variables of JS/TS/Python are not call targets). DONE.
- M0-17-R3 (hard): local arrows and JS/TS binding kinds. DONE.
- Kept intact: `metadata.receiver` on member calls (M0-17-R4) and nearest-declaring-file resolution (M0-02-R7).

## Scope

- **Callable bindings (parser side).** `GenericWasmParser` gives a module-level JS/TS declarator or Python assignment whose value is a call, a name or a member (or a Python lambda) the kind `function`. A literal value stays `constant`/`variable`, so M0-17-R2's scanner filter keeps working unchanged. Vue SFCs are excluded: there `const total = computed(…)` is reactive state, and value declarations own no references (`vue-template.ts`, rule 2).
- **Local-binding guard.** Because more bindings are now call targets, `name()` on a plain parameter or a plain local (`const`/`let`/`var`, Python assignment) of an enclosing function or block makes no reference in JS/TS (outside `.vue`) and Python. This keeps M0-17-R2's AC1 (`config()` on a parameter) true when the module binding is call-made.
- **Block arrows and class expressions.** A function-valued declarator inside a block (`if`, bare block, `for`, `try`, `switch`) is no symbol; a TypeScript namespace body still counts as module level. `export const Klass = class {}` is a `class` named by its binding.
- **C++.** `queries/cpp/symbols.scm` captures a qualified definition name at any depth. The parser names it by the innermost name (`a::b::c::D::g` → `g`, `ns::K::~K` → `~K`) and scopes it by the innermost qualifier.
- **Go.** A package-qualified embedded type carries `metadata.goPackage` (the import path, found by alias or package name). The scanner (companion patch, `src/core/scanner.ts`) resolves that import. A project package links the type declared in that package's directory; a standard-library or third-party package links nothing. `goPackage` is removed from the stored edge metadata.
- **Docs.** `docs/adding-languages.md` "Constants as call targets" and a new "Qualified names" section now describe what the code does.

## Out of scope

- Scope analysis beyond plain parameters and plain locals (destructured bindings, closures over outer function locals declared later, `global`/`nonlocal`).
- Go qualified composite literals (`pkg.T{}`) and qualified calls (`log.Println()`), which still resolve by name.
- Member-call receivers bound to call-made values (`p.start()` stays an inferred name-only edge).

## Acceptance criteria

1. Calls to `export const useAppSelector = useSelector`, a `createAsyncThunk(…)` result and a Python `functools.partial` value link to the binding; a constant or variable is skipped only when its value is a literal. Tests: `legacy-verifiability` "calls reach callables bound from a factory call or another name (M0-17-R5)", "a call on a parameter or local variable does not reach the module function of that name (M0-17-R5)"; `legacy-language-accuracy` "JavaScript, TypeScript and Python: a binding to a call, a name or a member is a function; a literal stays a value".
2. `type S struct { log.Logger }` gives no extends edge to a project Logger unless the import resolves to a project package. Test: `legacy-language-accuracy` "Go: `log.Logger` and a third-party Logger give no extends edge; a project package does" (end to end).
3. `void a::b::c::D::g()` and `ns::K::~K()` give symbols. Test: "C++: any depth of qualifiers and qualified destructors give scoped methods".
4. A block-scoped arrow at module level is not a top-level function, and `export const Klass = class {}` gives a class symbol with an instantiation edge from `new Klass()`. Tests: "JavaScript and TypeScript: a block-scoped arrow is no symbol; a class expression is a class", "TypeScript: `new Klass()` reaches `export const Klass = class {}`" (end to end).
