# M0-20-R2 — NestJS class segmentation ignores comments, strings and generics

## Identification

Milestone: M0; priority: P1; risk: medium; estimate min/expected/max: 2/4/6 h; area: remediation (frameworks/nestjs).
Sources: `docs/baton/reviews/REVIEW-2026-10-31-fb75474ba377.md`, `specs/features/F36-nestjs-decorators.md`.

## Objective

Attribute NestJS decorators to the right class whatever comments, strings or generics the file contains.

## Dependencies

M0-20-R1 (hard). No approval gate.

## Scope

- `classSegments()` finds class headers and balanced bodies on a copy of the file in which comments and string or template contents are blanked to spaces (same length, newlines kept), so `class X {`, quotes and braces in comments or strings no longer count.
- The class header is found by a small scan that skips generic `<…>` (including `{ … }` object types and `=>` inside generics) before the body's `{`.
- Decorator detection (`@Controller`, route verbs, `@Use*`, `@Resolver`, GraphQL, message and websocket decorators) runs on the blanked text and reads argument text from the original, so commented-out decorators are ignored and a `name:` inside a description string does not win.

## Out of scope

- A full TypeScript parse (tree-sitter) of decorators.
- Other detectors' string/comment awareness (Laravel route walker is M1-03-R1).

## Implementation plan

- `src/frameworks/detectors/nestjs.ts`: add `maskCode()` (comments, strings, templates with `${}` nesting, regex-literal heuristic), a generic-aware `classHeaders()` scan, and make `classSegments()` / `decoratorCalls()` work on `{ text, masked }` pairs.
- `tests/legacy-nestjs.test.ts`: end-to-end fixture (temp workspace → `mapx init` → `mapx scan` → `mapx routes --json` and the `edges` table) covering every acceptance criterion, plus the brief's extra cases (`Repository<User>`, `Promise<Map<string, {a: number}>>`, decorators with object literals, a string containing `class X {`).

## Expected outputs

- Fix in `src/frameworks/detectors/nestjs.ts`.
- Regression tests in `tests/legacy-nestjs.test.ts`.
- `docs/baton/reports/M0-20-R2.md`.

## Acceptance criteria

1. A controller preceded by a JSDoc containing "class" keeps its routes.
2. An apostrophe or an unbalanced brace in a comment inside a controller does not leak its prefix to a later plain class (no phantom route) and does not misattribute routes.
3. A controller with a generic `<T extends { id: string }>` keeps its routes.
4. `@Query(returns => Post, { description: "the post's name: 'x'" })` keeps the method name as operation name.
