# M0-07-R4 — The self-extracting installer removes its unpacked archive

## Identification

Milestone: M0; priority: P2; risk: low; estimate min/expected/max: 1/2/3 h; role: release engineer.

## Objective

Running a `mapx-*-installer.sh` leaves nothing in `$TMPDIR`: the unpacked archive is removed after `install.sh` finishes, whatever its exit status, and the installer exits with `install.sh`'s status.

## Dependencies

M0-07-R3 (hard, DONE): the installer exports `MAPX_INSTALLER` so the uninstall hint names the installer, not the temp copy. M4-09-R5 (hard, DONE): found the leak, and contains it in the test's own `TMPDIR`.

## Cause (probe, 2026-11-04)

`scripts/make-installer.sh` writes the installer. The installer unpacks the payload into `mktemp -d`, sets `trap _cleanup EXIT`, and ends with `exec "$_INST" ...`. `exec` replaces the shell process, so the EXIT trap never runs. On the pre-fix script, `TMPDIR=<empty dir> sh mapx-9.9.9-test-installer.sh --local` (stub `install.sh`, exit 0 or exit 7) leaves `tmp.XXXX/mapx-9.9.9/install.sh` behind; 8 of the 15 tests in `tests/installer-replace.test.ts` fail on it (6 new ones, plus the existing installer test once it asserts the folder is empty, plus the real-`install.sh` failure case).

## Scope

- `scripts/make-installer.sh` (the `sh` template): drop `exec`. The scope arguments are folded into `"$@"` with `set --` (one call site, spaces intact). `install.sh` runs as a background child with `<&3` (a copy of the caller's stdin: a background job gets `/dev/null` otherwise, and `install.sh` prompts with `read`), then `wait`; the installer exits with its status. The EXIT trap removes the folder.
- HUP, INT and TERM traps, installed right after `mktemp -d` (so extraction is covered; dash runs no EXIT trap when a signal kills it), forward TERM to the child when there is one, wait for it, remove the folder and exit 129 / 130 / 143 (the codes `install.sh` uses for INT and TERM). A signal that hits the whole process group (Ctrl+C) reaches both; one sent to the installer alone is forwarded.
- A closed stdin (`<&-`): `exec 3<&0` aborts dash and bash, so the copy is tried in a subshell first and falls back to `/dev/null`.
- `MAPX_INSTALLER` is untouched: it is the installer's own path, outside the folder.
- `tests/installer-replace.test.ts`: the contained `TMPDIR` stays (it protects the other tests) and is asserted empty after the installer run; a new `describe` builds installers around a stub `install.sh`.

## Out of scope

- A `SIGKILL` of the installer leaves the folder (no shell can trap it).
- The PowerShell installer: it already removes its folder in `finally`.
- Piped use (`curl | sh`): `$0` is not the file; the installer has never supported it.

## Acceptance criteria

1. A built installer run with a private `TMPDIR` leaves it empty after a successful install and after a failing one, and exits with `install.sh`'s status (stub exit 0 / exit 7; real `install.sh` with an unknown option exits 1). Test: `tests/installer-replace.test.ts`.
2. SIGTERM / SIGINT / SIGHUP sent to the installer while `install.sh` runs stops it, waits for it (it is gone when the installer exits), removes the folder, exits 143 / 130 / 129. The same signals during extraction remove the folder and exit the same codes.
3. Arguments with spaces and the caller's stdin (menu choice, `install.sh` prompt) reach `install.sh` intact, a closed stdin does not abort the installer, and `MAPX_INSTALLER` is the installer file, not a path in the removed folder.

## Verification

- `npx vitest run tests/installer-replace.test.ts`
- `npm run check`

Also by hand: a pty run (Python `pty`) of an installer with a stub `install.sh` that prompts: menu choice and prompt answered on the terminal, status 5 returned, `TMPDIR` empty.
