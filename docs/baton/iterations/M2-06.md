# M2-06 — Pair client calls with backend routes across repositories

## Identification

Milestone: M2; priority: P1; risk: medium; estimate 10/14/16 h; area: http, graph.
Sources: report §4 items 14 and 15; D008. Dependencies: M2-04, M2-05, M2-01 (hard), M1-98 (quality).

## Objective

Each D008 record gets `route` (the live backend route it reaches) or `null` (unmatched), and paired calls become `http` edges from the calling file to the route handler. The pairing is workspace-wide, so it works whatever order repos are scanned in.

## Scope

- `src/frameworks/http/pairing.ts` (pure): `pairCall(record, routes)`.
  - Candidates: live routes only (`reachable !== false`, not `overridden`), with a method in the route's set (`GET|POST`, `ANY`).
  - Paths are compared segment by segment, after stripping the host, query string and hash from the client URL. A route `{param}` or `{param?}` matches any segment; a client `{}` matches a route parameter (preferred) or a literal (weaker); literal segments must be equal.
  - Best match by (literal-to-literal matches, parameter alignment); confidence `exact` | `parametric` | `suffix`.
  - When `baseURLUnresolved` is set, the URL is matched as a path suffix (`suffix`).
- **Scanner:** after each repo's post-scan, `pairHttpCalls()` reloads `routes.json` and `http-calls.json`, re-pairs every record, rewrites the file, and rebuilds every `http` edge. Edges are `source_file` = calling file, `target_file` / `target_symbol` = handler, `repo` = the calling file's repo, metadata `{ httpVerb, uri, route, line, confidence }`.
- **Types and store:** `'http'` in `ReferenceType`; `store.deleteEdgesByType`, `graph.dropEdgesByType`.
- **Surface:** `mapx routes --clients [--unmatched] [--json]` and `mapx_routes { clients: "all" | "unmatched" }`, plus the matching docs.

## Out of scope

`postMessage` (M4-02); Vuex dispatch-by-name; non-Laravel backends work through the same `routes.json` but are not measured here.

## Acceptance criteria

1. Fixture pairing recall ≥ 80% and precision ≥ 95% (`score-http.ts --min-recall 0.8 --min-precision 0.95`).
2. The unserved calls (L09, L22) and the call to the unmounted route (L12) are reported as unmatched (`route: null`) and listed by `mapx routes --clients --unmatched`.
3. `{id}` and `{slug}` are interchangeable: the client `/api/v1/people/{}` pairs with the route `/api/v1/people/{person}`.
4. The call to the overridden `GET /api/dup` pairs with the winning handler `PostController@newDup`.
5. Scanning the frontend repo before the backend repo still pairs (multi-repo order test).
6. `http` edges exist in the store for paired calls only, with the handler as `target_symbol`.
