# M0-04-R2 — PHP resolution never maps vendor names to app files; tree-sitter $listen

## Identification

Milestone: M0; priority: P1; risk: medium; estimate min/expected/max: 5/8/12 h; role: PHP/static-analysis engineer.

## Objective

PHP import and class resolution is precise on stock Laravel apps: a name resolves to the file declaring that class in that namespace, or to nothing.

## Dependencies

M0-04-R1 (hard, DONE). Builds on M0-12-R3/R4 (import index, per-language precision) and the Laravel detector rework (M1-03-R1, M1-05-R1/R2, M1-07-R1).

## Scope

- `resolvePhpImport` (`src/core/import-resolvers.ts`): the file declaring the imported type in the imported namespace (from the symbol index and each file's namespace); else the composer.json PSR-4 path; else the whole FQN as a path suffix. Never the importing file itself, never a path suffix that drops namespace segments.
- `resolveSymbolToFile` (`src/core/scanner.ts`): a namespaced PHP name only resolves to a file declaring that short name in that namespace. A per-phase file → namespace map is built with the symbol index.
- `php.ts`: `$listen` is read from the `property_declaration` node (string-keyed and class-constant keys, comments and docblocks ignored); `use function` / `use const` stay out of the class table; double-quoted `bind("…")` arguments are captured; a comment before the first argument does not garble targets; `event(new \X)` and `\Event::dispatch(new X)` are dispatches.
- Tests: exact import edges on a stock Laravel skeleton; FQN with no file resolves to nothing; `$listen` docblock / string keys; worker parity compares metadata, verifiability and file metadata; `--verified-only` asserts a route-derived number that changes when routes are inferred.

## Out of scope

- MCP parity for relationships and bindings (M0-05-R4).
- Route-file middleware edges for `->middleware(X::class)` and closure routes that mention `::class` are only done if they fit; otherwise reported as left over.

## Implementation plan

1. Reproduce: stock skeleton e2e test (self-imports, Illuminate → app) and homonym test; `$listen` docblock / string-key test; strengthen worker and metrics tests. All fail first.
2. Import resolver and scanner namespace map.
3. `php.ts` fixes.
4. Mutation-check each new test; routes scorer before/after; full suite and typecheck.

## Acceptance criteria

1. A stock Laravel skeleton (Kernel, Authenticate, EventServiceProvider, Handler) has no import edge from a file to itself and no `Illuminate\` name resolved to an app file; import edges are asserted exactly.
2. A use-imported FQN with no matching file resolves to nothing rather than to a homonym in another namespace.
3. `$listen` is read from the property declaration node: a docblock example is ignored and the string-keyed form yields bindings.
4. The worker parity test compares edge metadata, verifiability and file metadata; the `--verified-only` test fails when route verifiability is forced inferred.
