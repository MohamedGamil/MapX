# M3-08-R1 — Vue app boundary: one global registry and route table per app folder, whatever the root manifest lists

## Identification

Milestone: M3; priority: P1 (review 2026-10-31); risk: medium; estimate 4/6/8 h; role: Vue resolution.
Sources: `docs/baton/reviews/REVIEW-2026-10-31-2db08bd25e13.md` (M3-08 FALSELY COMPLETE; route table crossing app folders, reviewer B), `docs/baton/reports/M3-08.md`.

## Objective

A Vue app folder (one with its own `package.json`) sees only its own global components and route records. This holds also when the repo root's `package.json` lists `vue` or `vue-router`.

## Dependencies

M3-08 and M3-11 (hard), both DONE.

## Scope

- **App folder.** `vueScope` used the folders whose `package.json` *activated* vue-router (M3-07). With `vue` or `vue-router` in the root manifest, the detector is active for the whole repo, so every file got the scope `''` and one registry. A file's app folder is now its nearest folder holding a `package.json` (up to the repo folder), cached per resolution phase.
- **Route table.**
  - The table was built per repo from every JS/TS file, so `shop/` navigated to `admin/`'s routes, and `frontend/` to a router file under `backend/`.
  - It is now built per app folder, from files of that folder where vue-router is active (repo-wide, or within its M3-07 scopes).
- **First registration wins.** It now does so by file path: the registry was built in file-map order, which differs between a fresh index and a sync.

Blast radius: private `vueScope`, `vueGlobalComponents` and `resolveNavigation` in `src/core/scanner.ts`. They are reached from `resolveVueReference` (render edges) and `resolveReferencesWithMap` (navigate edges). `src/parsers/languages/vue-navigation.ts` and `src/frameworks/framework-registry.ts` (listed in `affectedFiles`) needed no change.

## Out of scope

- More navigation forms: M3-11-R1.
- Framework detection when `package.json` files are indexed: M3-07-R1.

## Acceptance criteria

1. Two apps (`apps/a`, `apps/b`, each with a `package.json`) under a root `package.json` that lists `vue` (devDependencies) or only `vue-router`:
   - a tag registered only in app A gives no render edge in app B;
   - app B's own registration of a shared name wins for app B;
   - sync equals `scan --force`.

   Covered in `tests/vue-template.test.ts`, two cases.
2. A route record defined only in app A gives no navigate edge from app B, by name or by path. A folder where vue-router is not active (`backend/` beside `frontend/`) is never a navigate target, also from inside it. Covered in `tests/vue-navigation.test.ts`.
3. When two files of one app register the same name, the same registration wins after a fresh index and after any incremental history (`tests/vue-template.test.ts`).
4. `docs/cli-reference.md`, `docs/framework-integration.md` and the CHANGELOG describe the app boundary, and the edges scorer does not drop.
