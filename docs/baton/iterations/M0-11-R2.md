# M0-11-R2 — Staleness uses the scanner file rules; precise import-only dependants and callee lines

## Identification

Milestone: M0; priority: P1; risk: medium; estimate: see `docs/baton/TASKS.json`; role: core/CLI engineer.

## Objective

The staleness warning reports only files a scan would index, so it clears after `mapx update`. `impact` lists an import-only dependant only when that file imports the changed symbol. `callees` prints the called method's own line, or no line at all.

## Dependencies

M0-11-R1 (hard, DONE; review 2026-10-31 found it DEFECTIVE). The review's PHP `getSymbolLineInFile` fix in `store.ts` must keep working.

## Scope

- **Staleness (`src/core/staleness.ts`).** New untracked files go through the scanner's own rules, shared through exports from `src/core/scanner.ts`:
  - `DEFAULT_IGNORE` names and dot-prefixed path segments;
  - directory pruning (`shouldExcludeDir` semantics);
  - effective excludes, including Laravel's defaults for `framework: laravel` unless declined;
  - `includePatterns`;
  - the language check.
  
  The filters come from the last scan's stored `scan_filters:<repo>` meta, which includes CLI `--include`/`--exclude`. When that meta is missing, they are computed from `.mapx/config.json`. Files are attributed to the repo whose path contains them.
- **Impact.** An import-only dependant counts only if its source mentions the symbol's short name as a whole word. The import edges carry only the module specifier, not the imported names.
- **Callees (CLI and MCP).**
  - `store.getSymbolLineInFile(file, name, scopeHints)` takes the declaration whose scope matches `Scope::name`.
  - Otherwise the line of the single homonym whose scope is one of the classes the caller references in that file (`new B(); b.save()` resolves to `B::save`).
  - Otherwise the line of the only declaration, or null when the name is ambiguous or unknown.
  - With no line, the output prints `@ file` without `:line`. The call-site line is never used.
- **Globals.** Tests for `new Date()` in `.cjs`, `.cts` and `.svelte`.

## Out of scope

- M0-05-R4 and M0-10-R2 (same lane).
- Resolving receiver types in the parser (`target_symbol` stays unscoped for method calls).
- Gitignored files: staleness keeps `--exclude-standard`, while the scanner walk does not read `.gitignore`.

## Implementation plan

- `src/core/scanner.ts`: export `DEFAULT_IGNORE`, `isExcludedDir` (the body of `shouldExcludeDir`), `effectiveExcludesFor(settings, repo, cliExcludes)` and `isScannablePath(rel, excludes, includes)`.
- `src/core/staleness.ts`: per-repo filters, applied with `isScannablePath` and `getLanguageForFile` (shebang fallback for extensionless files).
- `src/core/impact-analyzer.ts`: word check on the importer's source.
- `src/core/store.ts`: scope-aware `getSymbolLineInFile`.
- `src/cli.ts`, `src/mcp.ts`: pass the hints and drop the `meta.startLine ?? 1` fallback.
- Tests in `tests/legacy-impact-staleness.test.ts`: real git workspaces, the real CLI.
