# M3-07 — Framework detection from package.json files below the repo root

## Identification

Milestone: M3; priority: P2; risk: medium; estimate min/expected/max: 2/4/6 h; role: scanner / framework detection.

## Objective

A repo whose framework manifest sits in a sub-folder (a `frontend/package.json` listing `vue`, an `api/package.json` listing `@nestjs/core`) gets that framework's detection for the files under that folder, and only those files. A Vue sub-app must not turn on Vue handling (the `vue-router` ignore list, route extraction) for a PHP backend in the same repo.

## Dependencies

- M3-01 (fixture): `tests/fixtures/vue-sfc/` and the edge scorer; M3-01's report found the defect (only the root `package.json` enables detection) and worked around it with `roots` in `expected.json`.

## Scope

**Why detection is root-only today.** `package.json` and `composer.json` are in the default `excludePatterns` (`src/core/config.ts`), so they never reach the scanned file list. `hasPackageJsonDependency` / `hasComposerDependency` (`src/frameworks/utils.ts`) look for manifests in that list and fall back to the root file, so only the root manifest is ever read.

**Contract.**

- `FrameworkDetector` gains an optional `manifestDependencies: { manifest: 'package.json' | 'composer.json'; names: string[] }`.
- `FrameworkRegistry.detectActiveFrameworks(projectRoot, files, options?)` keeps its return value (the active detectors). A detector whose `detect()` is true is active for the whole repo, exactly as before. When `detect()` is false but a manifest below the repo root lists one of `manifestDependencies.names`, the detector is also active, scoped to the folders holding those manifests. The scopes are reported through `options.scopes` (a `Map<detectorName, string[]>` of workspace-relative folders); a detector absent from the map is active for the whole repo.
- Candidate manifest folders are the folders of scanned files (and their ancestors below the repo root), so excluded folders (`node_modules/`, `vendor/`) are never consulted and no extra directory walk is needed.
- The scanner applies scopes in the two places where activation has an effect:
  1. the framework ignore lists (`buildIgnoredSymbols`, today only `vue-router`) apply only to files inside the detector's scopes;
  2. route and hook extraction (`scanFrameworkRoutesAndHooks`) runs a scoped detector only on files inside its scopes.
- `frameworks.json` and the codebase profile keep listing framework names; a framework forced on through `frameworks.json` stays whole-repo (override semantics unchanged).

**Detectors given `manifestDependencies`:** the package.json ones whose detection is only a dependency check (vue-router, nestjs, nextjs, react-router, tanstack-router, sveltekit), and the composer ones with the same root-only check (symfony, yii).

**Laravel** already finds apps below the root on disk (`findLaravelRoots`, depth 3, used by `detect()` and its mount graph), so it is not root-only. It stays whole-repo: its mount graph legitimately resolves route files outside the app folder (`loadRoutesFrom` of a sibling module), and it has no ignore list, so whole-repo activation has no cross-language side effect. Recorded in the report.

**Express** is left as is: its `detect()` also pre-scans files for router prefixes relative to the repo root; activating it from a nested manifest without that pre-scan would be a half-working detector. Recorded in the report.

## Out of scope

- The scorers (`scripts/eval/score-*.ts`) and the fixture labels do not change.
- Workspace-relative vs repo-relative paths in detectors of multi-repo workspaces (existing detectors join repo root with workspace-relative paths); this task resolves its manifests against the workspace root and does not touch the others.
- Vue SFC parsing (M3-02 … M3-06).

## Implementation plan

- `src/types.ts`: `manifestDependencies` on `FrameworkDetector`.
- `src/frameworks/utils.ts`: `findNestedManifestScopes(workspaceRoot, repoPrefix, files, manifest, names)`.
- `src/frameworks/framework-registry.ts`: nested activation and scope reporting in `detectActiveFrameworks`.
- Detectors listed above: declare `manifestDependencies` (and reuse the names in `detect()`).
- `src/parsers/ignored-symbols.ts`: scoped ignore lists (`buildScopedIgnoredSymbols`, `ignoredSymbolsForFile`).
- `src/core/scanner.ts` (minimal): cache scopes next to the cached detectors, build scoped ignore lists, pick the per-file ignore set in both parse paths, filter extraction by scope.
- `src/parsers/parse-worker.ts`: per-job ignore set.
