# M0-02-R12: a full scan killed after its index transaction keeps referrers and changed files

## Identification

Milestone: M0; priority: P2; risk: medium; estimate min/expected/max: 2/4/6 h; role: incremental scanning.

## Objective

A full scan killed after its index transaction commits, and before its parse results are written, leaves every file it was re-indexing for the next scan or sync to re-parse, as M0-02-R10 does for both syncs.

## Dependencies

M0-02-R11 (hard, DONE).

## Scope

- **`Scanner._scanFullForRepo`:**
  - the index transaction upserts each file with null content and blob hashes, and `last_scanned` unset (`UNSCANNED`);
  - the transaction of each parse batch writes the file's hashes with its parse result (`setFileHashes`).
- **`Store.setFileHashes` (review fix):** it takes `scannedAt`, the time the content was read (each path's start), not the time the result is written. This holds in the full scan and in both syncs.
- **Effect of a kill in between:**
  - the files stay "changed", so the next scan or sync re-parses them;
  - those files include the referrers whose `removed_files:` records the index transaction consumed, as M0-02-R11 deferred them.

## Out of scope

- Other records consumed elsewhere: `movedReferrers` and the Vue registry (M0-02-R11 limitations).

## Acceptance criteria

1. **Restored file:** in git and hash mode, `b.ts` is deleted, scanned and restored. A full scan then dies writing its first parse result. The next full scan and a sync end with symbols and edges equal to `scan --force`, including `src/a.ts a → src/b.ts b` (`tests/sync-interrupt.test.ts`).
2. **Changed file:** in git and hash mode, a file whose full scan died gets its new symbols from the next full scan (test).
3. **No extra work:** an uninterrupted second full scan writes no parse result (test).
4. **Edits during parsing:** in git and hash mode, a file edited while a full scan or a sync parses it is reported stale afterwards (`findStaleFiles`; test).

## Verification
