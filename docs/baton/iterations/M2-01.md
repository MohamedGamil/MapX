# M2-01 — Fail-closed cross-language name resolution

## Identification

Milestone: M2; priority: P0; risk: medium; estimate min/expected/max: 4/6/10 h; area: scanner, resolution.
Sources: `docs/reports/2026-10-30-laravel-vue-coverage-findings.md`.

## Objective

No call edge links a JS/TS/Vue source to a PHP symbol (or the reverse) by name alone.

Report §3 item 13 / §4 item 15. Not reproduced on a minimal fixture at 7e5aa19: resolveSymbolToFile filters by areLanguagesCompatible (scanner.ts:1259). The filter is skipped when the source language is unknown (sourceLang null) and when called without sourcePath (framework ScanContext, scanner.ts:1422). Start with a spike reproducing the pilot's ~10k edges from its patterns (member calls on imported objects, Vue options API, multi-repo); then make the filter fail closed.

## Dependencies

none.

## Scope

Spike (≤ 2 h): try to reproduce name-only JS/Vue→PHP `call` edges using the report's patterns — member calls on imported objects (`api.get`), Vue Options API `this.save()`, `this.$http.save`, multi-repo `scan . --all`, and a `.vue` file while the Vue grammar is not installed (unknown source language). Then make `resolveSymbolToFile` fail closed: with an unknown source language or no `sourcePath`, only return candidates whose language is known and compatible, or null. Pass the route file as `sourcePath` from the framework `ScanContext` (`scanner.ts:1422`).

## Out of scope

HTTP pairing (M2-03…M2-06), which is the legitimate cross-language bridge. Changing which JS-family languages are mutually compatible.

## Implementation plan

- `tests/cross-language-resolution.test.ts` — two-repo fixture under a temp dir, scanned through the scanner, asserting 0 JS-family↔PHP call edges, plus a unit test of the unknown-language path.

Before editing, run `mapx_impact` (or `npx tsx src/main.ts impact <symbol>`) on the symbols you change and note the blast radius in the report.
