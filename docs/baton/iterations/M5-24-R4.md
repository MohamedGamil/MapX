# M5-24-R4 — Uncovered packages are opt-in

## Identification

Milestone: M5; priority: P1; risk: medium; estimate min/expected/max: 3/5/8 h; role: architecture rules (evaluator, configuration).

## Objective

`mapx check` reports a package that no layer covers as uncovered only when the configuration opts in: `policy.uncovered.externals: true`, or a `package` selector in any layer. Without that, packages are out of scope and `--fail-on-uncovered` ignores them (owner decision D039, reversing M5-24's default).

## Dependencies

M5-24 (hard, DONE). No approval gate.

## Scope

- **Configuration** (`src/arch/config.ts`, `src/arch/schema.ts`): `policy.uncovered.externals` keeps its type. When no document of the `extends` chain sets it, the loader resolves it to whether a merged non-overlay layer has a positive `package` selector in its `selectors` or `private`, directly or inside `all`/`any` (not under `not`; D039 addendum, from the review). An explicit value, `true` or `false`, wins. The evaluator, `mapx arch allowed`, the MCP tools and the dashboard all read the resolved value, so they agree with check without further change.
- **`mapx arch allowed`:** the `out-of-scope` reason for a package names the opt-in.
- **`mapx arch init`:** it keeps proposing the `Packages` layer (`{ "package": "*" }`). The layer is a package selector, so the draft opts in, and the layer covers every package, so day one passes. Its comment no longer says check would fail without it.
- **Smells:** `vendor-leak` exists only on a `private` package selector, so it already needs the opt-in. `undeclared-dependency` and `dev-dependency-in-prod` describe the manifest, not layer coverage, and never change check's exit code, so they do not need the opt-in.
- **Docs and schema:** `docs/architecture-rules.md` (the policy, its default, the examples and the init note) and the `policy.uncovered.externals` description in `schemas/architecture.schema.json`.
- **Fixture:** the existing apps (ts, php, python, go, workspace) have no package selector. Their 52 `uncovered` rows on packages become `none` rows (negatives), each listed in the report. The vendor apps use package selectors, so their rows stay.
