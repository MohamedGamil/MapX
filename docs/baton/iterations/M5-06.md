# M5-06 — Baseline (generate, match, stale-entry errors) and `--compare <report>` ratchet

## Identification

Milestone: M5; priority: P1; risk: low; estimate min/expected/max: 5/7/10 h; role: CLI and static-analysis engineer.

## Objective

Let a team adopt architecture rules on code that already breaks them, and keep the debt from growing:
- a **baseline** file freezes today's violations (they become `skipped`), and an entry that no longer matches anything is an error, so the baseline can only shrink;
- **`mapx check --compare <base-report.json>`** fails only on violations whose fingerprints the base revision's JSON report does not contain, so CI ratchets without a committed baseline.

## Dependencies

- M5-05 (hard, DONE): `mapx check`, the JSON report and the AR-17 exit contract.
- M5-04 (DONE): finding fingerprints (AR-09).
- No approval gate.

## Scope

- **Baseline file** (`src/arch/baseline.ts`), JSON, `version: 1`:
  - `entries`: `{ fingerprint?, rule?, source?, target?, edgeType? }`. An entry needs a fingerprint, or all four readable keys (the fingerprint is then computed from them). When both are given they must agree;
  - `skip_violations`: Deptrac's element-pair form, `{ "<source element>": ["<target element>", …] }`, which matches any violation between the two elements, whatever its rule or edge type.
- **Loading:** the configuration's `baseline` (relative to the workspace), else `--baseline <file>`, else the default `.mapx/architecture.baseline.json` (`.mapx/architecture/<view>.baseline.json` for a view) when it exists. A named file that does not exist, invalid JSON or an invalid entry are configuration errors (exit 3).
- **Matching:** a violation whose fingerprint, or element pair, is in the baseline becomes `skipped` (`skippedBy: "baseline"`). `layerEdges` counts it as skipped.
- **Stale entries:** an entry that matched no violation becomes an `error` finding with rule `stale-baseline` (exit 3). Its ends are resolved to files when the elements still exist.
- **Generation:** `mapx check --generate-baseline [file]` evaluates without any baseline and writes every violation as `{ fingerprint, rule, source, target, edgeType }`. The output is sorted and byte-stable, ends in a newline and has no timestamp. It exits 0 once written (3 and 4 as for a check).
- **`--compare <report.json>`:** reads a JSON report (`mapx check --format json` on the base revision). A violation whose fingerprint is in it becomes `skipped` (`skippedBy: "compare"`). Other failing findings (warnings under `--fail-on warn`, uncovered under `--fail-on-uncovered`, `multi-layer` errors) do not fail when their fingerprint is in it. Configuration and stale-baseline errors always fail. An unreadable or invalid report is exit 3.
- **The report schema** gains the optional `skippedBy` on findings.
- **Docs:** `docs/cli-reference.md` and `docs/architecture-rules.md`.

## Fingerprint

The first 16 hex characters of sha256 over `JSON.stringify([rule, source, target, edge type])`, plus `[source repo, target repo]` when either end is outside the root repo. This is revised after review 2 (P1-1, P1-2).
- Symbol-level ends are qualified names, with a method lifted to its class.
- File-level ends (an import's importing file, an import path's target file) are workspace-relative POSIX paths. They are never the file's only symbol, so adding a symbol to either file keeps the fingerprint.
- Repos are workspace-relative paths, and the root repo is left out.
- There is no line number, no layer and nothing machine-specific. So a moved line, a re-scan, another machine or a Windows checkout gives the same fingerprint.
- Renaming or moving a class, or moving a file (which re-keys every path-named element: TS, JS), is a new dependency. This is intended and documented.
