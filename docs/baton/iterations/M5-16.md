# M5-16 — Rule-derived smells and single-source layer violations

## Identification

Milestone: M5; priority: P2; risk: medium; estimate min/expected/max: 6/8/12 h; role: architecture analysis.

## Objective

When a workspace has `.mapx/architecture.jsonc`, `mapx_smells`, `mapx arch` (and its `--smells`/`--violations` views) and the dashboard's `/api/smells` take their `layer-violation` smells from the rule evaluator, the single source of truth, instead of the role-order heuristic (`FlowValidator`), and gain the AR-18 smells derived from the rules. Without a configuration nothing changes.

## Scope

Sources: AR-18 (`docs/research/deptrac/02-abstract-feature-model.md`) and §3.3 of `03-mapx-gap-and-integration.md`.

1. **One source for layer violations (§3.3).**
   - No configuration: the stored smells, byte for byte (no `source` field either).
   - A configuration: `layer-violation` smells come from the report's violations (after the baseline, as `mapx check`), one smell per source file → target file. The stored role-order violations are dropped.
   - `policy.alsoInferred: true`: the role-order violations are kept too, marked `source: "inferred-roles"`, except on a file pair a rule violation already reports.
2. **AR-18 smells, `source: "rules"`:**
   - `layer-cycle`: a strongly connected component of the observed layer graph (Tarjan, the analyzer's own);
   - `dead-allowance`: an allowance the configuration writes for the pair (explicit, or the layer a `+` names) that no dependency uses, as `mapx arch unused` counts uses;
   - `weak-allowance`: the same, used by 1 or 2 stored edges;
   - `layer-skip`: an allowed dependency whose only grant is inherited through `+M` (M a non-empty layer): the source bypasses M;
   - `unstable-layer-dependency`: Martin's Stable Dependencies Principle per layer pair, I(source) < I(target), with Ca/Ce counted over elements, as Martin counts classes;
   - `abstractness-distance`: D = |A + I − 1| > 0.7 for a coupled layer with types (A = interfaces and traits over top-level types);
   - `deprecated-usage`: an evaluated edge into an element tagged `@deprecated` (or a member of one).
3. **Integration in `src/core/architecture-analyzer.ts`** (`currentSmells`), used by the CLI, MCP and `/api/smells`, computed when read: an edited configuration takes effect without a rescan, and a multi-repo workspace is evaluated once all repos are indexed. The scan still stores the role-based smells as before.

## Implementation plan

- `src/arch/smells.ts` (new): `ruleSmells(ctx, report)` → the AR-18 smells.
- `src/core/architecture-analyzer.ts`: `currentSmells(store, dir, repos, primary, repoPaths)`: stored smells, or the single-source merge; a configuration that cannot be loaded keeps the stored smells and adds an `architecture-config` smell.
- `src/arch/schema.ts`, `src/arch/config.ts`, `schemas/architecture.schema.json`: `policy.alsoInferred` (default false).
- `src/cli.ts` (`mapx arch`), `src/mcp.ts` (`mapx_smells`), `src/ui-server.ts` (`/api/smells`): read through `currentSmells`; text output gains `Source:` and `Layers:` lines only for smells that have them.
- Docs: `docs/architecture-rules.md` (Smells), `docs/cli-reference.md`, `docs/mcp-integration.md`.
