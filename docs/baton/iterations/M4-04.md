# M4-04 — Scanner: no redundant walk, and no post-scan when a sync changes nothing indexed

## Identification

Milestone: M4; priority: P3; risk: medium; estimate min/expected/max: 6/9/14 h; role: scanner performance.

## Objective

A sync whose git changes leave nothing to re-parse or remove finishes without parsing or post-scan analysis. Full and incremental scans no longer read and hash every file a second time just to list workspace paths.

## Dependencies

All are DONE, including M4-03 (D019 order).

## Measurement before planning (2026-11-01, `develop@e4fc861`, 16 cores, load average 2–5)

Workspaces: the generated TypeScript workspace from M4-03 (`scripts/bench/scan-scaling.ts` layout) at 8,000 and 16,000 files, and a MapX self-copy (613 files).

| Phase (in process) | MapX self | 8,000 files | 16,000 files |
| --- | --- | --- | --- |
| `discoverFiles`, warm (cold) | 0.08 s (0.20 s) | 0.53 s | 1.1 s (3.8 s) |
| `runPostScanAnalysis` | 0.70 s | 3.3 s | 7.0 s |

**Post-scan analysis.** It scales linearly. Its profile at 16,000 files is synchronous CPU work: cluster metrics 2.4 s, architecture analysis 1.7 s, HTTP call scan 1.1 s, cluster detection 1.0 s. Running these steps "concurrently" on one event loop cannot shorten them, so the original objective's concurrent post-scan steps are dropped.

**The directory walk.** It is linear, and about 6% of a scan when warm. The parallel walk is dropped too: it can only win on a cold cache, while the redundant walk below costs a full walk on every scan and sync.

**What does cost time.**
- `scanFull` and `scanIncremental` both pre-walk every repo with `discoverFiles`, which reads, stats and md5-hashes every file, only to fill `workspaceFileMap` with paths. A full scan then walks and reads everything again, and a sync reads everything for nothing.
- A git sync whose listed changes are only noise still runs the full post-scan. Noise means files the walk never indexes, such as the untracked `.gitignore` that `mapx init` writes, or `.idea/`. Real-world working trees nearly always have such files, so a "no-op" `mapx sync` costs the whole post-scan.
  - Measured at 16,000 files with git, a no-op sync took 10.4 s with three untracked noise files, of which 5.7 s was `runPostScanAnalysis`.
  - The hash-based sync of the same files took 3.5 s.
  - A probe repo with only its untracked `.gitignore` reported "Updated 1 files" on every sync.

## Scope

1. **Paths-only pre-walk.** `discoverFiles(…, { pathsOnly: true })` returns the files the walk would index (path and language) without reading, stat-ing or hashing them. `scanFull` and `scanIncremental` fill `workspaceFileMap` with it.
2. **Git sync early exit.** While selecting changes, `_scanIncrementalForRepo` notes whether any listed change is a post-scan input. An input is a re-parse, the removal of an indexed file, or a scannable file with no parser, such as `requirements.txt` or `go.mod`, which framework detection reads. When none is, after the referrer step has added nothing, it finishes like its existing no-change return:
   - it records `last_scan_commit` and `last_scan_time`;
   - it refreshes HTTP pairing if its inputs changed;
   - it skips parsing and post-scan.

   Dot files and files under excluded or default-ignored folders are never post-scan inputs. The scan walk never reads them, and `.env` (HTTP base URLs) is covered by the HTTP inputs fingerprint.

## Out of scope

- A parallel directory walk and concurrent post-scan steps: dropped, as measured above.
- Making the post-scan steps themselves faster (cluster metrics, architecture analysis): a follow-up, if wanted.

## Acceptance criteria

1. **Paths-only walk.** `discoverFiles(…, { pathsOnly: true })` returns exactly the paths and languages of the full walk, in the same order, on a fixture tree. The tree has nested and excluded folders, dot files, a nested git repo and an extensionless shebang script. The paths-only walk reads no file content, except shebang heads (`tests/scan-redundancy.test.ts`).
2. **Early exit on noise.** In a git repo after a scan, a sync with only untracked non-scannable files (`.gitignore`, `.idea/workspace.xml`, `dist/out.js`) emits no `parse` or `cluster` progress, and returns `filesScanned` 0 (test).
3. **Inputs still trigger post-scan.** A sync with an untracked `requirements.txt`, an edited source file, or a deleted indexed file still runs post-scan (`cluster` progress) (test). After the noise sync, edges equal `scan --force` (test).
4. **Identical results.** Edges and symbols are byte-identical before and after on the MapX self-copy and the 16,000-file workspace, both for a forced scan and after a sync sequence (sorted dumps in the report).
5. **Measured, not CI.** Recorded in the report: a no-op sync with noise at 16,000 files (10.4 s before), a no-op scan (10.9 s before), a forced scan, and a hash sync (3.5 s before). None of them may be slower.
