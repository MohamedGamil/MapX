# M1-07-R2 — RouteServiceProvider mounts walked like other providers; prefixes, names and domains evaluated

## Identification

Milestone: M1; priority: P1; risk: medium; estimate min/expected/max: 4/6/10 h; area: remediation (laravel).
Sources: `docs/baton/reviews/REVIEW-2026-10-31-2db08bd25e13.md` (reviewer D, probes `review-D/p5-rsp.mjs` and `p6-rspattrs.mjs`), `docs/baton/reports/M1-07-R1.md`, `M1-03-R1.md` and `M1-05-R1.md` (COMPLETION DISPUTED sections).

## Objective

Every route mounted from `app/Providers/RouteServiceProvider.php` is either evaluated (reachable, with its evaluated prefix, name prefix and domain) or, when its mount cannot be evaluated, reported with reachability unknown. It is never reported as unreachable, and its URI never contains PHP text.

## Dependencies

M1-07-R1, M1-03-R1 and M1-05-R1 (all hard, all DONE). No approval gate. M0-04-R6 runs after this task on the same files.

## Reproduction (develop@00407d6)

- `review-D/p5-rsp.mjs`: in the RSP, a glob loop with `->group($file)`, a `require` and a `loadRoutesFrom` leave `/shop`, `/required` and `/loaded` `unreachable`, without middleware or prefix.
- `review-D/p6-rspattrs.mjs`:
  - `Route::prefix(config('app.api_prefix'))` gives `/config('app.api_prefix')/users`, and `"admin/{$this->version}"` gives `/admin/{$this->version}/panel`. Neither is flagged dynamic.
  - The RSP's `->name('api.')` is dropped (`users`, not `api.users`), and so is `->domain('admin.example.com')`.
- Cause: `buildMountGraph` skips the RSP in the provider walk. `parseRouteServiceProvider` reads only `Route::…->group(<path>)`, keeps `prefix()` raw, and ignores `name()` and `domain()`.

## Scope

- `buildMountGraph` walks the RSP with `walkRouteFile(…, { provider: true })`, like every other provider. Its mounts become the app's entry points in walk order, with `mountedBy` set to `RouteServiceProvider.php:<line>`. The walker's unresolved lines join the app's unresolved mounts.
  - A mount that sets no namespace gets the provider's `$namespace`. Without one it gets `App\Http\Controllers`, as the legacy parser did.
  - `parseRouteServiceProvider` and `resolveRoutePath` are deleted.
- The `routes/web.php` and `routes/api.php` default mounts apply only when no entry point declares anything. When the RSP mounts something that cannot be evaluated, they no longer apply. The app's graph is kept even when its only mounts are unresolved, so its route files get reachability unknown.
- `chainAttributes` evaluates `->namespace(<expr>)`. Previously it took the raw text, for example `$this->namespace`.
- `laravel-mounts.ts`:
  - Class property declarations are recorded as `this->name` and visible to every method. Static properties are skipped.
  - `$this->p`, `"{$this->p}"` and `"$this->p"` read the property, never a local that shares its name.
  - With path context, an assignment of any expression `phpString` can evaluate (`$routes = base_path('routes/x.php');`) is recorded, so `->group($routes)` resolves.
- Scorer: a live or conditional label may carry `name`, `domain` and `dynamic`. Each one must equal the matched route's value. `attributeRecall` is reported, and `--min-recall` applies to it.

## Out of scope

- Middleware parameters and Kernel aliases (M0-04-R6).
- `require_once`, require cycles, trailing slashes and `Route::match` (M1-03-R2).
- Routes declared directly in a provider (closures inside `Route::group(function …)` in the RSP). As before, no provider's own routes are collected.
- Reassignments to an unevaluable value do not shadow an earlier value. Variables are not scoped per function. Both behaviours predate this task.
