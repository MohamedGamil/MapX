# M0-02-R13 — A package.json edit re-parses only the files its change affects

## Identification

Milestone: M0; priority: P2; risk: medium; estimate min/expected/max: 2/4/8 h; role: sync / resolution engineer.

## Objective

Sync re-parses a JS/TS/Vue/Svelte file after a package.json change only when a field that its resolution reads changed for it, and not Python files, nested packages with their own manifest, or files the field does not reach. `scan --force` output and a full scan's output stay as they are.

## Dependencies

M3-05-R3 (hard, DONE): the finding. M0-02-R8 (the config tracking this narrows), M0-17-R4, M2-08-R3, M2-08-R6, M2-08-R11, M3-05, M3-08-R1, M3-09-R1 (the readers it must keep correct).

## Cause (probe, 2026-11-04)

A synthetic workspace (root manifest, a nested package with its own manifest, three TS files, a Python file) was scanned with the real CLI on `develop@9ea18f4`, then a package.json was edited and synced, one edit at a time (`scratchpad/M0-02-R13/probe.sh`):

| Edit | Files re-parsed (before) |
| --- | --- |
| root `version` | 4 of 5 sources: `src/a.ts`, `src/b.ts`, `packages/admin/src/c.ts` (nested, own manifest), `py/x.py` |
| root `scripts` | the same 4 |
| root adds `pinia` (no file mentions it, none calls a store hook) | the same 4 |
| nested `version` | the nested file |

On a copy of npm's own `node_modules` (700 files, 231 manifests, root manifest added) a root `version` bump re-parsed 598 files, a nested `version` bump 48.

The cause is `configReferrers` (M0-02-R8): it hashed package.json (and pnpm-workspace.yaml) together with the folder's other configs into one signature per folder, and re-parsed every JS/TS/Vue/Svelte/Python file under a folder whose signature moved, nested packages included. The manifests above the workspace root (M3-05-R3) re-parsed every source.

That whole-subtree re-parse also covered a reader the first version of this iteration missed (independent review, P1-1, P1-2): the **framework detectors**. A `vue` or `vue-router` dependency activates the vue-router detector, whose ignore list (`ref`, `computed`, `watch`, `setup`, `provide`, `inject`, `t`, `te`, `tm`, `rt`, `d`, `n`, `useStore`, `defineStore`, `useRoute`, `useHead`, ...) `buildScopedIgnoredSymbols` hands to **every** parse, of every language (`ignoredSymbolsForFile`; a detector active for the repo covers `['']`, one a nested manifest activates covers that folder). A manifest that gains or loses the dependency changes what each file's parse drops, so those files must be re-parsed; narrowing the signatures to the fields above alone left sync different from `scan --force` (`scratchpad/review-M0-02-R13/scen3.cjs`, `scen5.cjs`).

## What resolution reads of a package.json (every reader in `src/`)

| Reader | Fields | Walk | Files affected |
| --- | --- | --- | --- |
| Store-library gate, `storeDependencies` (M3-05, M3-05-R3), called by the parsers for a file with store hints | `dependencies`, `devDependencies`, `peerDependencies` (vuex, pinia); `workspaces` / `pnpm-workspace.yaml` `packages` of a root | nearest manifest that declares dependencies, then the first workspace root above that lists the package, up to the repository root (above the MapX workspace too) | JS/TS/Vue files of the package whose text has the hint the changed library is read for |
| `autoImports` (M2-08-R3) | the same three sections, for `nuxt`, `nuxt3`, `nuxt-edge`, `@nuxt/bridge`, `unplugin-auto-import`, `unimport` | every manifest from the file's folder up to the workspace root (no shadowing) | JS/TS files below it |
| `dirAliases` (M3-09-R1), `jsAliasTargets`, `jsBaseUrlTarget` | `name`, the three sections (any dependency, a `BUILD_TOOLS` name) | each folder's kind (none, package, app) decides where the alias walk stops and which folder `@/` falls back to | files whose nearest app folder or nearest package folder changed |
| `readDirRoots` (M2-08-R11) | `jest` (moduleDirectories, modulePaths, rootDir), `scripts` (a `NODE_PATH=` value only) | nearest declaration at or above the folder | files whose nearest declaration changed |
| `isNpmPackage` / `npmPackageAt` (M0-17-R4), used by `jsImportBindings`, `outsideProject`, the module-root late roots | `name`, and the version kind (registry, or `workspace:` `file:` `link:` `portal:` path) of a dependency in any of the four sections | per imported package name: the first manifest from the file's folder upward that is named it or lists it | files that import that name, where the nearest answer changed (so a nested manifest that lists the name shadows an outer change) |
| `npmWorkspacePackages`, `workspacePackageTargets` (M2-08-R6), `jsExternalSpecifier` | `name` of manifests below the root; `exports`, `module`, `main`, `types` of the package | global table, name to folder | files anywhere that import the name, when its folder or entry changed |
| `vueManifestKind` (M3-08, M3-08-R1) | `name`, dependencies, `peerDependencies` (vue), `exports`, `module`, `scripts` (`--target lib`) | nearest boundary manifest | tracked on its own by `vueScopeMoves` (`vue_dir_scopes`), unchanged here |
| `decideExternalRefs`, `NpmAttributor` (M5-19, M5-20) | dependency sections, lockfiles | per run, from the manifests as they stand, for every candidate row | no re-parse: re-decided each run from the input hashes and `ATTRIBUTION_VERSION` |
| Framework detectors: activation of `vue-router` (`dependencies` / `devDependencies` naming `vue` or `vue-router`: the repo root's manifest for the whole repo, else each nested manifest for its folder; `detectActiveFrameworks`), the one detector with an ignore list (`IGNORED_SYMBOLS_BY_FRAMEWORK`) | `dependencies`, `devDependencies` | the repo root, else every folder holding scanned files and its ancestors below the root | **every** file of any language in the folders it covers, when its text holds a name the activation added to or removed from its ignore set (`ignoreReferrers`) |
| Other detectors' activation, routes and hooks, arch, profiler, cluster engine | various | recomputed whole each sync, or no parse | no re-parse (no other detector has an ignore list; `facadeMap` and user languages come from `.mapx/config`, not a manifest) |

No reader uses `version`, `description`, `keywords`, `license`, `engines`, `type`, `imports`, `browserslist`, `files`, `bin` or `scripts` other than `NODE_PATH=` (and `--target lib`, tracked by the Vue scope).

## Scope

`configReferrers` no longer hashes package.json or pnpm-workspace.yaml into the folder signature, and no longer keeps `^` keys for the manifests above the workspace root. It signs what the readers above take, two kinds of entry per folder holding a package.json (the workspace root always counts), and compares them per file:

- **`\0view:<dir>`**, what walk-ups that do not depend on the specifier see for the files in the folder down to the next manifest: `<vuex bit><pinia bit>|<hash of auto-import flag, nearest app folder, nearest package folder, nearest jest declaration, nearest NODE_PATH declaration>`. The gate bits are what `storeDependencies` answers for the folder (so a workspace root's pinia, a `pnpm-workspace.yaml` and a manifest above the MapX workspace are all in it). Each file's old and new view (the nearest manifest folder in the old and in the new record) are compared:
  - the hash differs: the file is re-parsed;
  - only a gate bit differs: re-parsed when its text holds the hint the changed library is read for (`storeGateMatters`: known store code or Vuex members for vuex, a project hook call for pinia).
- **`\0pkg:<dir>`**, what depends on the specifier an import names: `n` the package name, `d` the registry or local kind of each dependency with a string version, `e` the entry fields. A file is re-parsed when it quotes a name (`'pkg'`, `'pkg/sub'`) whose meaning changed: the nearest manifest from its folder up that names or lists it answers differently in the old and the new facts, or the workspace package table (name to folder and entry) moved for it. Nested manifests that list the name shadow an outer change by the walk itself.
- **`\0ign:<framework>`**, the frameworks with an ignore list that are active (asked of `detectActiveFrameworks` itself, with the files the parse will see: the index and the files this sync adds) with the folders they cover, as JSON. `ignoreReferrers` compares each indexed file's ignore set under the old and the new record; a file whose set changed is re-parsed when its text holds one of the names added or removed (whole-word match). It reads each such file once and keeps nothing; it reads nothing when no entry moved. Every language is a referrer for this signal only: Python and the other languages still depend on no other package.json field.
- `#manifests` marks a record of this layout. A record from before (no marker) is compared the way it was written, for that one sync: the folders are hashed again with package.json and pnpm-workspace.yaml first (HEAD's name order) and the folders above the workspace root under `^` keys, and a change is followed as `develop` followed it (everything below the folder); a tsconfig, bundler config, jest config or `__init__.py` edit in the window is therefore not lost. The new layout is recorded in the same sync (test "sync after the config record of an older MapX", with an index built by `develop`'s code for the evidence).
- Python files never depend on a package.json field other than through the ignore list above. The end-of-run recording does not compare (`compare = false`).
- The folders `manifestInputs` visits include the files a sync adds, so a workspace package that arrives together with its files is in the name table when an importer elsewhere is judged (review P2-2). `configReferrers` is async for the detector question.
- `exports`, `module` and `scripts` also feed the Vue scope: `vueScopeMoves` tracks that on its own and still re-parses the files whose scope moved (test).

## Out of scope

- A manifest in another registered repo that a workspace package's importers in this repo depend on: `configReferrers` is per repo, as before (found, not fixed).
- A lockfile, `node_modules` listing or `.git` created after a long-running `mapx serve` started (the process caches of M3-05-R3).
- `pnpm-workspace.yaml` as a signature of its own folder: it is read through the gate view now; nothing else reads it. A `lerna.json`, `rush.json` or Nx workspace is not read by the gate (M3-05-R3).
- External attribution (M5-19, M5-20): unchanged, re-decided every run.
- Narrowing the tsconfig, bundler-config and `__init__.py` signatures: they keep re-parsing everything below their folder.

## Implementation plan

1. `src/core/js-aliases.ts`: export `manifestRootKind` and `packageModuleRoots` (what `dirAliases` and `readDirRoots` already computed from a manifest) and the `RootDecl` type; the readers call them, so tracking and resolution cannot drift.
2. `src/parsers/languages/vue-stores.ts`: split the hint test out of `storePass` and export `storeGateMatters(path, text, changedBits)`.
3. `src/core/scanner.ts`: `manifestInputs` (entries, facts, views), `manifestReferrers` (per-file comparison), `ignoreActivation` / `ignoreReferrers` (the detector ignore lists), the folder signatures without package.json / pnpm-workspace.yaml / `^` keys, the legacy-record comparison. `src/frameworks/framework-registry.ts`: `detectActiveFrameworks` takes `only`.
4. Tests first, in `tests/scanner-config-referrers.test.ts`.

## Acceptance criteria

1. **Fields no resolution reads re-parse nothing** (test "a git sync / a hash sync of package.json fields no resolution reads"): `version`, `scripts`, `description`, `keywords`, `license`, `engines`, a dependency range bump, a dependency moved between sections, a dependency no file imports, a nested manifest's `version` and `scripts` re-parse 0 files, the nested package and the Python file included; sync equals `scan --force`.
2. **Adding or removing pinia re-parses the governed modules** (test "… after pinia is added to or removed from package.json"): exactly the module calling a project hook and the store module importing pinia, not the other sources, the nested package or the Python file; the hook call links as `scan --force` links it.
3. **A nested package with its own manifest is not re-parsed by its parent's edit** (tests "leaves a nested package with its own manifest alone", "re-parses the files that import it, not a nested package that lists it itself", "follows a NODE_PATH script … leaves a nested package with its own NODE_PATH alone", "re-parses a package that takes the enclosing app's aliases, not a nested app of its own"): its own dependency, store gate (unless the root lists it as a workspace), NODE_PATH and build tool shadow the parent's.
4. **Fields that do affect resolution re-parse what they affect, and sync equals `scan --force`**: a dependency gained, lost or turned into a `workspace:` link (importers, a nested file that lists nothing included); a workspace package's `main`, `exports` and `name` (importers in other packages, not the package's own files); a `NODE_PATH` script and a jest `moduleDirectories` key; a build tool among the dependencies; a nested manifest removed and added back; a monorepo root above the MapX workspace (version and scripts re-parse nothing; pinia re-parses the gate's callers).
5. **An older record** is only recorded once, without re-parsing, and later changes are followed (test "sync after the config record of an older MapX").
6. **A Vue scope that a `scripts` edit moves** still re-scopes (test "a package.json edit that moves a Vue scope").
7. **Gaining or losing the vue-router detector re-parses what it changes, in any language** (tests "after vue or vue-router is added to or removed from package.json"): adding or removing `vue` or `vue-router` re-parses the files holding an ignored name (`ref`, `t`, `watch`, `d`, ...), JS/TS and Python alike, and not the files that hold none; `vue-router` joining `vue` re-parses nothing; a nested manifest covers its folder only; sync equals `scan --force`.
8. **A workspace package that arrives with its files is seen by importers elsewhere** (test "after a workspace package arrives with its files"), and dropping `module` / `types` from the entry fields or `optionalDependencies` from the dependency kinds is caught by a test.
9. **An older record does not hide other config edits** (test "with another config edited in the window"): a tsconfig `baseUrl` edit made between the old version's last sync and the first new sync is followed. A folder whose name starts with `#` is compared like any other.
10. **A full scan's output is unchanged**: dumps of edges, symbols, external-reference candidates and files over MapX's own tree and a tree of npm packages are byte-identical between `develop` and the change.
