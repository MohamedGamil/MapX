# M7-03 — Landing page: hero, capabilities, install, integrations

Milestone: M7; priority: P1; risk: low; estimate min/expected/max: 5/8/12 h; role: front-end and docs.

## Objective

The home page says what MapX is and how to start on one screen, with every count read from the code at build time, never typed.

## Dependencies

M7-01 (hard, DONE).

## Design decisions

- **Facts at sync time.** `scripts/site/site-facts.ts` exports `siteFacts()` and, run by `site:sync`, writes `site/.vitepress/facts.json` (gitignored). It computes: the version (`VERSION`), the MCP tool count and names (`buildServer()` through an in-memory client, as `tests/docs-surface.test.ts` does), the languages (`getBuiltinLanguages()`: every non-static one, TSX counted as TypeScript), the framework detector count (`FrameworkRegistry`), the preset ids (`PRESETS`) and the agent targets (`TEMPLATES`, without the generic, instruction and Continue/Aider helper keys). Display names for languages and agents are constants in the same file; an id without a name stops the sync, so a new language cannot appear unnamed on the page.
- **VitePress never imports `src/`.** The theme components import `facts.json`. This keeps the site build free of native modules (better-sqlite3, tree-sitter).
- **Text, not typed numbers.** Components format counts from the facts. Prose that names a number uses the fact.
- **Install block text equals the README.** The commands (`npm install -g @mgamil/mapx`, `npx @mgamil/mapx init`, the quick-start lines `init`, `scan`, `export`, `query`, `callers`, `impact`, `arch init`, `check` and `sync`, and the Claude Desktop MCP configuration) are read from README.md by the facts generator, from its fenced blocks, so the landing cannot drift; the test compares them again.
- **Layout.** The default theme's `home` layout supplies the hero. A `Landing` component, placed through the `home-hero-after` slot (which exists only on the home layout), holds the stats strip, the four capability cards (local index, answers instead of file reads, fast and incremental, architecture rules in CI; in the component so their counts come from the facts), the install block with copy buttons, the MCP snippet, the language grid, the integrations list and a closing call to action. Light and dark themes come from the brand tokens (M7-01); nothing needs JavaScript to read.

## Scope

- `scripts/site/site-facts.ts`, called from `sync-docs.ts`'s CLI entry (or the `site:sync` script).
- `site/index.md` (hero, features), `site/.vitepress/theme/Landing.vue` and small components, theme `index.ts` registering the slot.
- Per-page head tags for the home page: `description`, Open Graph title, description and image (`og:image` points at the logo for now; a generated card is M7-06).
- Tests: `tests/site-landing.test.ts` (facts against the sources, README equality, built HTML) and `tests/site/landing.spec.ts` (layout, themes, first screen).
