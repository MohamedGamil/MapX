# M4-27: Lua files parse correctly after the first one in a process

## Identification

Milestone: M4; priority: P1; risk: medium; estimate min/expected/max: 2/4/6 h; role: parser correctness.

## Objective

Every `.lua` file of a scan parses without errors and yields its references, on the main thread and in workers, whatever was parsed before it.

## Dependencies

M4-26 (hard, DONE). The lane found the defect while testing M4-26.

## Finding

- **Symptom:** `wasm/tree-sitter-lua.wasm` (ABI 13, downloaded prebuilt) parses only the first Lua source of a process correctly. Every later parse has ERROR nodes, for example `local M = {}` read as an unterminated string, and therefore no references. That holds even with a fresh `Parser` or a freshly loaded `Language`.
- **Cause:** the grammar's external scanner (`src/scanner.c`) allocates its state with `malloc`, and `deserialize` ignores the zero-length state that starts a parse, so state leaks from one parse into the next.
- **Why it looked like a race:** scans of mixed workspaces lost Lua call edges only sometimes. Under load, the main thread parsed more files, and in a different order, than the workers did.

## Scope

- **`scripts/build-wasm.ts`:**
  - per-grammar `patches`: exact replacements in a copy of the source, each required to match once;
  - a patched grammar must be built from source and is never copied or downloaded prebuilt.
- **Lua patch:** `calloc` for the state, and a reset on an empty `deserialize`.
- **`wasm/tree-sitter-lua.wasm`:** rebuilt with `npm run build:wasm` (tree-sitter CLI 0.23.2, emsdk 3.1.64 in Docker).
- **`EXTRACTOR_VERSION` 3:** the next sync re-parses every file once (M5-26).
- **`tests/grammar-health.test.ts`:** a health test for every bundled grammar.

## Out of scope

- **`wasm/tree-sitter-vue.wasm`:** it throws "resolved is not a function" on `{{ }}`. VueParser does not use it; the test lists it as excluded, with the reason.

## Acceptance criteria

1. **Repeated parses:** the same Lua sample parsed repeatedly, two different Lua files, and Lua after Java in one process each give no ERROR nodes and the expected references (`tests/grammar-health.test.ts`).
2. **Every grammar:** every bundled grammar parses its sample three times in one process, after all grammars are loaded, with identical error-free trees. An excluded grammar is listed with its reason (test).
3. **Real scan:** a scan of three Lua files gives each file its call edge (e2e).
