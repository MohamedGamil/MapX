# M1-05-R2 — Laravel resources: singleton, scoped, middlewareFor, per-route prefix/domain keys

## Identification

Milestone: M1; priority: P2; risk: low; estimate min/expected/max: 2/4/6 h; role: PHP/Laravel static analysis.

## Objective

The remaining resource registration forms, and route-level `prefix`/`domain` keys, match Laravel's router.

## Dependencies

M1-05-R1 (hard, DONE on develop). Source: `docs/baton/reports/M1-05-R1.md` (Limitations).

## Scope

1. `Route::singleton`, `Route::apiSingleton`, `Route::singletons([...])`, `Route::apiSingletons([...])`: Laravel's singleton defaults (`show`, `edit`, `update`), `->creatable()` (adds `create`, `store`, `destroy`), `->destroyable()` (adds `destroy`), apiSingleton's `only` default (`store`, `show`, `update`, `destroy`), nesting (`photos.thumbnail` → `photos/{photo}/thumbnail`, no wildcard for the singleton), `/` prefixes, the options array and the chained `only`/`except`/`names`/`name`/`parameters`/`middleware` calls already modelled for resources.
2. `->scoped([...])`: the URI is unchanged (Laravel keeps plain wildcards); each route records the binding fields of the wildcards it carries (`metadata.bindingFields`), as `ResourceRegistrar::setResourceBindingFields` does.
3. `->middlewareFor($methods, $middleware)` and the `middleware_for` option, with PendingResourceRegistration's merge rules in both orders with `->middleware()` (`Router::uniqueMiddleware`), for resources and singletons.
4. `'prefix'` and `'domain'` keys in a single route's action array. A route-level prefix (action key, or a `->prefix()` chained on the route) is applied by the Route constructor after the group prefix, so it goes in front of it: `Route::group(['prefix' => 'g'], fn () => Route::get('y', ['prefix' => 'x', ...]))` is `x/g/y`. The action key wins over a chained `prefix` attribute (`array_merge($attributes, $action)`); an action `domain` wins over the group domain.

Ground truth: a fresh `composer require laravel/framework` (12.70.2) in the session scratchpad, driven by a scratch oracle script over synthetic route files only. No private or pilot code, and nothing from any other project's `vendor/`.

## Out of scope

- `withoutMiddleware`/`withoutMiddlewareFor`/`excluded_middleware` (Laravel keeps them in `Route::middleware()` and removes them only when gathering).
- `Route::resourceParameters()`, `ResourceRegistrar::verbs()`, `->missing()`, `->withTrashed()`, `->where()`.
- Explicit `{post:slug}` wildcards in a plain route URI (MapX keeps the raw text; Laravel's `uri()` strips the field).
- Last-wins semantics for repeated chained RouteRegistrar attributes on groups (`Route::middleware('a')->middleware('b')`).
- Merging resource/singleton `update` into one `PUT|PATCH` route (kept as two routes, as in M1-05-R1).

## Implementation plan

- `src/frameworks/detectors/laravel.ts`: `ResourceOptions` gains `creatable`, `destroyable`, `bindingFields`, `middlewareFor`; `parseResourceOptions` reads `middleware_for` (and `creatable`/`destroyable`); `expandResourceRoute` takes a kind (`resource` | `singleton`) with Laravel's per-kind defaults and URIs, applies per-action middleware and binding fields; `processRouteChain` recognises the singleton verbs and chain calls, and computes route-level prefix/domain from the action array, the pre-verb attribute and post-verb calls.
- `tests/laravel-mounts.test.ts`: one e2e workspace (real `mapx init`/`scan`, `routes --json`) whose full list (method, URI, name, handler, middleware, domain, binding fields) must equal the oracle's.
- `tests/fixtures/laravel-routes`: labelled singleton and route-prefix patterns (live and absent), appended without changing existing labels.
