## Scope

- **Mount graph (`buildMountGraph`).** Files are loaded depth first, in PHP's execution order, so the walk knows PHP's included-files table at each point.
  - `require_once` / `include_once` of a file already loaded is skipped. After a conditional load only, it is kept and flagged conditional.
  - A mount of a file that is still loading (a require cycle) is skipped, whatever the include form. Each route is reported once. The depth cap stays as a backstop.
- **Route keys (`processRouteChain`).** `'/'` or `''` under a prefix gives the prefix itself (`Router::prefix` trims the joined URI), so a later `Route::get('admin')` overrides `prefix('admin')` + `get('/')`. `Route::get('', …)` is a route.
- **Resources (`expandResourceRoute`).** A resource segment that can't be evaluated gets a `{dynamic}` wildcard, never `{{dynamic}}`. The route is flagged dynamic.
- **`Route::match`.** Each verb is evaluated as a PHP string, from an array or a single string. If a verb can't be evaluated, the method is `ANY`, flagged dynamic.
- **Invokable controllers.** `Route::get('x', X::class)` gives `X@__invoke`. So does a class-name string outside a `Route::controller()` group (Laravel's `RouteAction::parse` / `makeInvokable`; inside such a group, the string names a method).
- **Dynamic flag.** Any `{dynamic}` part of a URI flags the route, a partly dynamic segment such as `zone{dynamic}` too.
- **Names.** A route name or name prefix that can't be fully evaluated keeps `{dynamic}` in place of the unknown part (`->name(config('x'))` → `{dynamic}`, `"z.{$this->zone()}."` → `z.{dynamic}.`). This applies to `->name()`/`->as()`, `'as' =>` in groups and in action arrays.
- **Variable bindings (`laravel-mounts.ts`, `stringAssignments` / `varsAt`).**
  - `.=` appends to a known value, otherwise the value is unknown.
  - `??=` keeps a known value. It assigns only to a function or closure local that nothing named earlier in that function (no parameter, `use`, foreach, …). Anything else is unknown, top-level code included, since a required file shares its includer's variables.
  - `$this->prop = …` in a method holds from the write to the end of that body. Everywhere else the property is unknown, because methods may run in any order.
  - Each function or closure body is a scope barrier. Inside it, the enclosing locals are hidden except its `use` captures; `$this->` properties cross it. Arrow functions (`fn`) have no barrier: PHP gives them the enclosing scope.

## Out of scope

- Laravel adds HEAD to every GET route. MapX reports GET, as before.
- `Route::get('x', ['uses' => 'X'])` without `@` as an invokable.
- A property written in `__construct` is treated like any other method's write (unknown elsewhere).
- Integer properties (`protected $num = 3`) are still not evaluated.
- Pairing with `Route::domain` belongs to M2-06-R2.
