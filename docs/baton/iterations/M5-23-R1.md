# M5-23-R1 — An unreadable go.mod keeps the module's own imports internal

## Identification

Milestone: M5; priority: P3; risk: low; estimate min/expected/max: 1/2/3 h; role: scanner and package manifests.

## Objective

When a go.mod is there but cannot be read (no permission, or a folder), imports of the module's own packages stay internal, with their import edges, recognised by the folder layout. Only third-party imports become unknown external rows, flagged `manifest` (M5-23 limitation "An unreadable go.mod").

## Dependencies

M5-23 (hard): Go attribution, `goImportOutsideProject`'s `exists` check, `readWorkspaceText` treating an unreadable file as absent. No approval gate.

## Scope

- **The module path of an unreadable go.mod, from the folder layout** (`goModuleByLayout`, `src/core/manifests/go.ts`): each import `M/rel` of the module's non-test Go files whose `rel` is a package folder of the module (relative to the go.mod's folder) votes for `M`. A path is inferred only when exactly one candidate has votes, from at least two distinct folders (amended after review); otherwise the imports stay unknown rows as before. A standard-library path never votes. Files under a nested go.mod belong to that module and never vote.
- **Resolution** (`src/core/import-resolvers.ts`): `resolveGoImport` and `goImportInWorkspaceModule` take the inferred path where go.mod's `module` line is unreadable. As a result, an own package resolves to its folder (an import edge), and a missing own package (`example.com/app/internal/gone`) is the workspace's (no row).
- **The context** gains an optional `exists(path)` (`ImportContext`). The scanner passes it, cached per resolution phase.
- **Extractor version** 18 (16 before the rebase onto develop's M2-12/M2-13): edges of unchanged files change under an unreadable go.mod.

## Out of scope

- Telling the module path of a module that imports none of its own packages: there is no layout evidence. It stays unknown, as before.
- `local replace` directives of an unreadable go.mod: they cannot be read.
- Go call resolution's by-name fallback (`resolveGoQualifiedType`, lane B's area): unchanged; own imports now resolve before it.

## Implementation plan

- `src/core/manifests/go.ts`: `goImportPaths(text)` and `goModuleByLayout(imports, packageDirs)`, pure.
- `src/core/import-resolvers.ts`: `goModuleIn(dir, ctx)` (the `module` line, or the layout's path when go.mod is present but unreadable, cached per file set and folder); used by the two Go walks.
- `src/core/scanner.ts`: `exists` in the two resolver contexts (`importContext`, `resolveModuleImport`), `workspaceExists` cached with the text cache.
- `tests/external-refs.test.ts`: e2e scans (go.mod chmod 000; go.mod a folder) and unit tests of the two functions.
