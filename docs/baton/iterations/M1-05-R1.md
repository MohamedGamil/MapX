# M1-05-R1 — Laravel resources: array options, nested and plural registration; array handler attributes

## Identification

Milestone: M1; priority: P2; risk: medium; estimate min/expected/max: 2/4/6 h; role: PHP/Laravel static analysis.

## Objective

Every resource registration form yields Laravel's route set: URIs, parameter names, handlers, route names and middleware.

## Dependencies

M1-05 (hard, DONE). Builds on M1-03-R1 (masking walker) and M1-07-R1 (reachability), both integrated on develop.

## Scope

From the review 2026-10-31 (P2, M1-05):

1. Third-argument options of `Route::resource` / `apiResource`: `only`, `except`, `parameters`, `names`, `as`, `middleware`, `shallow`.
2. Nested resources `photos.comments` → `photos/{photo}/comments/{comment}`, with `parameters` applying to every segment, and `->shallow()`.
3. `Route::resources([...], $options)` and `Route::apiResources([...], $options)`, with class-constant or string controllers.
4. Array handlers without `uses` (`['as' => …, 'middleware' => …, function () {…}]`, `['middleware' => …, [C::class, 'm']]`) keep their name and middleware.
5. Group name prefixes (`Route::name('admin.')->group(...)`, `['as' => 'admin.']`), nested and across `require` mounts, applied to plain and resource route names.

The ground truth is the real Illuminate router (Laravel 12.70.2, vendor code only), driven by a scratch oracle script over synthetic route files. Its output is copied into the tests as the expected route list.

## Out of scope

- Merging resource `update` into one `PUT|PATCH` route: the detector keeps two entries (existing tests and pairing depend on it); tests expand Laravel's `PUT|PATCH` accordingly.
- `Route::singleton`, `->scoped()` binding fields, `middlewareFor`, `withoutMiddleware`, `'prefix'`/`'domain'` keys inside a single route's action array.
- The scorer (`score-routes.ts`) does not compare names or middleware; those are covered by e2e tests.

## Implementation plan

- `laravel.ts`: a PHP array-entry parser; `ResourceOptions` gains `names`, `as`, `middleware`, `shallow`; `expandResourceRoute` follows `ResourceRegistrar` (prefix from `/`, nested URI from `.`, wildcards per segment, shallow names, route names, defaults order, apiResource `only` default); `processRouteChain` reads the options array, `Route::resources` dictionaries, array handlers and name prefixes; group frames carry `names` through the walker stack, `chainAttributes`, `parseGroupAttributes` and mounts.
- Fixture `tests/fixtures/laravel-routes`: new labelled patterns for options, nesting/shallow, `resources`/`apiResources` and array handlers without `uses`.
- `tests/laravel-mounts.test.ts`: one e2e workspace whose full route list (method, URI, name, handler, middleware) must equal the oracle's.
