# M5-24-R2 — External elements: multi-layer warning and inherited dependencies

## Identification

Milestone: M5; priority: P2; risk: low; estimate min/expected/max: 2/4/6 h; role: architecture rules (evaluator, report).

## Objective

An external element (package, built-in, ambient) that several layers select gets the same `multi-layer` warning as an internal element, naming both layers. Under `policy.inheritDependencies`, a type answers for the external dependencies of its workspace ancestors too, with the inheritance path in `via`.

## Dependencies

M5-24 (hard, DONE), M5-09 (hard, DONE). No approval gate.

## Scope

- `LayerMembership.multiLayerExternal` lists external elements in more than one non-overlay layer. `buildReport` turns each one that is the target of a decided dependency into a `multi-layer` finding (a warning, an error under `policy.strictLayers`), once per external element and layer set.
- `evaluateEdges` collects each external reference by the type its source belongs to, and derives the ancestors' references for the type: once per (type, external, kind), through the shortest path, with `via`, no line, and not when the type or its file has the reference itself. References of kind `extends` and `implements` are not inherited: the inheritance itself is decided where it is declared (as for workspace ancestors).
