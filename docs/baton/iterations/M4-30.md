# M4-30: CLI-spawning arch tests stay within their timeouts under load

## Identification

Milestone: M4; priority: P2; risk: low; estimate min/expected/max: 3/5/8 h; role: test infrastructure.

## Objective

`tests/arch-reporters.test.ts`, `tests/arch-baseline.test.ts` and `tests/legacy-metrics-edges.test.ts` pass at load 25+ instead of hitting vitest's 30 s timeout 1 to 3 times per full run. The fix removes setup work; it does not raise timeouts across the board.

## Dependencies

None. D039 makes this the first task of the defect batch.

## Measurement first (quiet machine, load 5, each file alone, before the change)

| File | Wall | `mapx` spawns | init / scan | Slowest test |
| --- | --- | --- | --- | --- |
| arch-reporters | 81.3 s | 119 (103 `check`) | 8 / 8 | 16.6 s |
| arch-baseline | 47.6 s | 69 (57 `check`) | 5 / 5 | 6.4 s |
| legacy-metrics-edges | 36.5 s | 51 | 3 / 3 | 5.1 s |

- A spawn costs ~630 ms on average, whatever the command. A scan costs only ~150 ms more than `--version`.
- A CPU profile of `src/main.ts --version` under tsx: 333 ms in tsx itself (resolving and loading the sources), against ~200 ms for tsx to start a one-line file.
- So the setup (init and scan) is ~22 s of 165 s. The time goes into starting the CLI: ~150 s across 239 spawns, nearly all of them assertions' own `check`, `edges` and `metrics` calls.

## Scope

- **`tests/helpers/built-cli.ts` (new):** `buildCli()`. Once per test process, esbuild transpiles src/ (unbundled ESM, as tsup does for the npm build) into a temporary mirror of the repository:
  - src/ as `.js`, beside its non-TypeScript files;
  - the other top-level entries as symlinks, so the `import.meta.url` lookups (VERSION, wasm, the parse worker, the agents stub) resolve as in a checkout.
- **`tests/helpers/e2e.ts`:** `useBuiltCli()`, which is opt-in per file, like `useParseWorkers`. While a file uses it, every `mapx*` runner starts `node <mirror>/src/main.js` instead of `node --import tsx src/main.ts`. The mirror is removed after the file.
- **The three files** call `useBuiltCli()`.
- **Shared fixtures**, where a test reads a scan rather than making one:
  - arch-baseline: one scan of APP serves both describes that need it, and each gets its own copy. The "separate scan elsewhere" stays a separate scan;
  - arch-reporters: the invalid-configuration test copies the scanned workspace and replaces its configuration, which only `check` reads.
- **Timeouts:** set per file from the stress run's measured worst case, with the measurement in a comment. If the default 30 s still covers the worst case several times over, it stays, and the comment records why.
- **Assertions are unchanged.**

## Out of scope

- Moving the other e2e files to `useBuiltCli` (a follow-up if wanted).
- Caching identical CLI calls. Several assertions run the same command twice on purpose ("twice", "byte-stable").
- Production code.

## Acceptance criteria

1. With 16 busy-loop node processes (load ≥ 16), the three files pass 10 of 10 runs. The stress script kills its loops on exit, and the runs are logged in the report.
2. Their total wall time on a quiet machine drops. Before and after are in the report, measured the same way (`M4-30-measure.sh`: each file alone, with the spawn count).
3. A broken reporter (the SARIF uri) and a broken baseline rule each make their test fail.

## Verification

- `npx vitest run tests/arch-reporters.test.ts tests/arch-baseline.test.ts tests/legacy-metrics-edges.test.ts`
- `npm run check`

## Recovery

Revert the task commit. The helpers are opt-in, so no other test depends on them.
