# M4-25 — Compact terminal logo for init, scan and sync

## Identification

Milestone: M4; priority: P2; risk: low; estimate min/expected/max: 2/4/6 h; role: CLI and terminal rendering.

## Objective

`mapx init`, `mapx scan` and `mapx sync` (alias of `update`), in the CLI only, open with the MapX text-art logo at half its width and height. Every row of the art is kept as a half cell, so its shading, highlight stripe and inner hole stay visible (owner request, D031).

## Dependencies

M4-18 (hard, DONE): the text-art logo, `renderBanner` and `printBanner` in `src/branding.ts`.

## Scope

- **Compact mark:**
  - **Grid:** the 64×23 `LOGO_ART` read as a grid of shade levels (space 0, ░ 1, ▒ 2, ▓ 3, █ 4), padded to an even number of rows. It is drawn at 32×12 in half blocks: column pairs are averaged, and each pair of rows becomes the top and bottom half of one cell.
  - **24-bit colour:** each half is `#ff02fe` mixed toward the background at its level. The background is dark unless `COLORFGBG` names a light one (its last field 7 or 15). Empty halves keep the terminal's own background.
  - **256-colour terminals:** each colour is the nearest xterm-256 code.
  - **`NO_COLOR`:** shade characters averaged 2×2 (32×12), with no escape codes.
- **When it shows:** as before, only on a TTY without `MAPX_NO_BANNER`. The width threshold drops to 32 columns.
- **Where it shows:** `init` (instead of the 64×23 art), `scan`, and `update`/`sync`, each before its other output.

## Out of scope

- MCP tools and `mapx serve`: no banner (owner: CLI only).
- `mapx workspaces sync` (registers repos; not the scan `sync`), `watch` and other commands.
- Changing `assets/brand/mapx-logo.txt`, the logo symbol or the dashboard (M4-18 assets).

## Implementation plan

- **`src/branding.ts`:**
  - `logoLevels()`: the art as a level grid.
  - `compactMark(mode)`: the `truecolor` / `256` / `plain` renderings, with a light flag.
  - `renderBanner` uses the compact mark; `MARK_WIDTH` is 32.
  - `LOGO_ART` and its sync test stay.
- **`src/cli.ts`:** call `printBanner()` first in the `scan` and `update` actions.
- **`tests/branding.test.ts`:**
  - decode the 24-bit output back to levels and compare it with the column-pair average;
  - dimensions;
  - each colour mode and the light background;
  - the conditions;
  - pseudo-terminal end-to-end tests for init, scan and sync;
  - piped scan and sync.
- **`docs/cli-reference.md`:** the banner paragraph.

Blast radius (grep, since the repo's own index is absent): `renderBanner` is used in `src/branding.ts` and `tests/branding.test.ts`; `printBanner` in `src/cli.ts` (init).

## Expected outputs

`src/branding.ts`, `src/cli.ts`, `tests/branding.test.ts`, `docs/cli-reference.md`, `CHANGELOG.md`, `docs/baton/reports/M4-25.md`.

## Acceptance criteria

1. The compact mark is 32 columns by 12 rows. Decoding its 24-bit half-block cells gives exactly the source art averaged over column pairs, with every source row kept (`tests/branding.test.ts`).
2. Colour:
   - 24-bit colour mixes `#ff02fe` toward a dark background, or toward a light one when `COLORFGBG` reports it;
   - without 24-bit support, each half uses the nearest xterm-256 colour;
   - under `NO_COLOR`, the mark is plain shade characters averaged 2×2, 32 by 12.

   Shown by tests.
3. No mark when the output is not a terminal, `MAPX_NO_BANNER` is set, or the terminal is narrower than 32 columns (tests).
4. In a pseudo-terminal, the real CLI prints the mark first for `init`, `scan` and `sync`, before their other output. Piped, `scan` and `sync` print no mark and no escape codes (end-to-end tests). MCP tools print none: the banner is called only from `src/cli.ts`.
