# M0-07-R5 — The documented `curl … | sh` install works

## Identification

Milestone: M0; priority: P2; risk: low; estimate min/expected/max: 1/3/5 h; role: release engineer.

## Objective

`curl -fsSL https://github.com/MohamedGamil/mapx/releases/latest/download/mapx-<platform>-installer.sh | sh`, the command README.md and docs/getting-started.md show, installs MapX. The docs and the installer cannot drift: every shell-installer command the docs show is run by a test against a locally built installer.

## Dependencies

M0-07-R4 (hard, DONE): the installer runs `install.sh` as a child with the caller's stdin on fd 3, traps HUP/INT/TERM after `mktemp -d`, and removes its folder on every exit. All of it stays.

## Cause (probe, 2026-11-04)

`scripts/make-installer.sh` writes a self-extracting installer that locates its payload with `awk '/^__PAYLOAD__$/{...}' "$0"` and `tail -n +N "$0"`. Run as `sh installer.sh`, `$0` is the file. Run as `curl … | sh`, `$0` is the shell (`sh`, `dash`, `bash`), so:

```
$ cat installer.sh | sh -s -- --local        # also dash, bash; the real 79 MB mapx-linux-x64-installer.sh
awk: cannot open sh (No such file or directory)
```

It fails before and after M0-07-R4 (found by that review); README.md lines 127 and 130 document exactly that command.

## Decision: make it work piped, not change the docs

| | (a) installer works when piped | (b) docs say download, then run |
| --- | --- | --- |
| Command users copy | the conventional one-liner, already in the README | `curl -fsSLo i.sh URL && sh i.sh` |
| Cost | the template needs a pipe-safe layout and a prompt source | none in code, two docs lines |
| Risk | shell-specific read-ahead of the script (below) | none |
| Prompts | must read the terminal, not the pipe | unchanged |

(a) is chosen: `curl | sh` is the path people expect and the one already documented, and the risk is containable with a pad and tests under dash, bash and busybox sh. Downloading a file and running it still works, unchanged.

## Scope

`scripts/make-installer.sh` (the `sh` template):

- **One function.** The logic moves into `_mapx_installer`, called on the last line before `exit 1`. A shell reading its script from a pipe parses and runs it line by line; with the logic in a function nothing after the call is parsed, and the payload is never executed as shell.
- **File or stream.** `$0` is the installer file when its name is not a shell's (`sh`, `bash`, `dash`, `ash`, `zsh`, `ksh`, `mksh`, `pdksh`, `yash`, `posh`, `busybox`, `fish`, `csh`, `tcsh`, with a leading `-` ignored) and it is a file whose lines include `# mapx-installer-header`. A file named like the shell in the current folder (an untrusted checkout) is therefore never taken for the installer when the script is piped (`$0` is `sh`); `sh installer.sh`, `./installer.sh` and `bash dir/x.sh` are still file runs. Otherwise the script is on stdin (`curl | sh`, `sh -s`, `sh < file`). A corrupted file (header, no marker) still stops with "Payload marker not found" instead of waiting on stdin.
- **No payload to read.** Not a file and stdin a terminal (`bash <(curl …)`, `sh -c "$(curl …)"`): the installer stops at once with "No installer payload to read: run the downloaded file …, or pipe it", before it asks or unpacks, instead of reading the terminal.
- **Payload before prompts.** The archive is read and unpacked into the private folder before the menu is shown, so a sender (curl) is never left blocked on a full pipe while the user answers, and the quit and uninstall answers do not close the pipe on it.
- **Payload from stdin.** The payload is the text after the `__PAYLOAD__` line on stdin, filtered with awk, and streamed through `base64 -d | tar xz` into the private `mktemp -d` folder, so there is no copy of the 80 MB on disk. A shell has read some of the script ahead by then (dash: one 8 KiB read; bash on a pipe: nothing; others: up to a pipe buffer), and those bytes are gone from stdin, so the marker comes after a pad of 160 KiB of comment lines placed after the `exit`. What is left of the pad on stdin is skipped. A cut-short download has no marker or a short archive and stops with "Failed to extract archive".
- **Prompts.** fd 3 is the prompt input and `install.sh`'s stdin. From a file it is the caller's stdin as in M0-07-R4. From a pipe stdin is the script, so it is `/dev/tty`; with no terminal (CI, Docker; `/dev/tty` cannot be opened) it is `/dev/null` and the installer asks nothing: no menu, a user install (`--local`) with a line saying how to choose. An `install.sh` prompt then gets no answer, which is a no (below).
- **Hint.** From a pipe there is no installer file for `install.sh`'s "Uninstall:" hint. `MAPX_UNINSTALL_HINT` carries the command that runs the installer again (`curl -fsSL …/mapx-<platform>-installer.sh | sh -s -- --uninstall`). A file run keeps `MAPX_INSTALLER` (M0-07-R3).
- The traps, the child with `<&3`, `wait`, the exit status and the folder removal of M0-07-R4 are unchanged.

`scripts/templates/install.sh`: a `read` that reaches end of input (a pipe with no terminal) is a no instead of a silent `set -e` exit (overwrite, shell-config and data-removal prompts). Declining to overwrite says `--force` skips the question. The uninstall hint prefers `MAPX_UNINSTALL_HINT`.

`README.md`, `docs/getting-started.md`: the documented commands stay, with the prompt behaviour when piped (terminal answers; none means user install and no overwrite without `--force`), the `sh -s --` form for options, the four published platforms, an install with `--prefix`/`--force`, and an uninstall.

Tests: `tests/installer-replace.test.ts` runs the doc commands as written (see Acceptance); `tests/docs-surface.test.ts` ties docs to `scripts/package.sh` (asset names, platform list), `install.sh` (options) and the installer's hint; `tests/helpers/installer-docs.ts` reads the commands from the docs.

## Out of scope

- The PowerShell installer: the README and docs show no `irm … | iex` or `.ps1` command, so there is nothing to verify (grep of README.md and docs/); `make-installer.sh ps1` reads its payload from an embedded here-string, not from `$PSCommandPath`, so it has no `$0` problem. No Windows run.
- Checksum or signature verification of the downloaded script (not asked for; no signing exists).
- SIGKILL leaving the folder (M0-07-R4 limitation).
- A real `make package-linux` build in CI; the manual probe used the 0.3.9 archive in `dist/release` with the new template.

## Acceptance criteria

1. Every `curl … | sh` command in README.md and docs/getting-started.md, run as written with a `curl` that serves a locally built installer for the URL's platform, in a private HOME and TMPDIR and with no terminal, exits 0, installs the binary and data into the private prefix (default `~/.local`, or `--prefix`), and leaves `$TMPDIR` empty; the uninstall command removes them. Test: `installer-replace.test.ts`, "the commands README.md and docs/getting-started.md show".
2. The piped script installs under every `sh` present (dash, bash, busybox sh) and as `sh < file`, with the data files, and leaves `$TMPDIR` empty. Test: "`cat installer | … -s -- --local` installs…", "`sh < installer`".
3. With a terminal (pty), a piped installer asks the menu, the prefix and `install.sh`'s prompts there and honours the answers; "q" quits, Enter takes the user install. Without one it asks nothing, installs for the user, and refuses to overwrite an existing `mapx` unless `--force` (exit 1, old binary intact, message names `--force`).
4. A cut-short download and a script cut before its marker fail with "Failed to extract archive" and leave `$TMPDIR` empty; a corrupted installer *file* still fails with "Payload marker not found"; SIGTERM/SIGINT/SIGHUP during a piped extraction remove the folder and exit 143/130/129.
5. The payload marker lies at least 64 KiB after the last line the shell runs (the pad).
6. The docs and the installer agree: each doc command names an asset `package.sh` publishes, the README lists the published platforms, each option after `sh -s --` is parsed by `install.sh` and in its help, and the hint the piped installer prints is the documented uninstall command. Test: `docs-surface.test.ts`.
7. All M0-07-R4 tests still pass.
8. A file named `sh`, `bash` or `dash` in the current folder, carrying the installer header, is not taken for the installer by `cat legit | <shell> -s -- --local`: the legitimate binary installs and the hint is the curl command. `sh installer.sh`, `./installer.sh` and `bash dir/x.sh` still run as files (`MAPX_INSTALLER` in the hint).
9. On a terminal, `bash <(cat installer)` and `sh -c "$(…)"` exit 1 at once with "No installer payload to read", ask nothing and leave `$TMPDIR` empty.
10. With a terminal, the sender has written the whole script before the menu: quitting with `q` leaves `cat` finished, not killed by SIGPIPE.

Known limits, not fixed: a download cut inside the header comments or right after the function's closing brace, before the `_mapx_installer "$@"` line (a window under 100 bytes), runs nothing and exits 0, the standard `curl | sh` trade-off (every other cut fails with "Failed to extract archive").
