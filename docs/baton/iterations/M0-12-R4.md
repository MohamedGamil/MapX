# M0-12-R4 — Import resolution precision for Ruby, Java, Python, C#, Rust and Go

## Identification

Milestone: M0; priority: P2; risk: medium; role: scanner and parser maintainer.

## Objective

Every import case named by review 2026-10-31 produces exactly the edge the language means: the right target file, or no edge at all.

## Dependencies

M0-12-R3 (hard; builds on its once-per-scan `ImportIndex`). Sources: `reviews/REVIEW-2026-10-31-fb75474ba377.md`, `specs/features/F20-language-expansion.md`.

## Scope

Each case below gets a test asserting the exact `source → target` edge, or that there is none.

- **Ruby.** `require_relative` resolves only relative to the file, so a missing file gives no edge (the parser marks it `./x`). Plain `require` searches load paths: `lib/` under each ancestor directory, plus a directory that is itself a load path (`lib`, `spec`, `test`). It never searches the file's own directory otherwise, so `lib/a/json.rb` does not capture `require 'json'`.
- **Java multi-module.** Among same-suffix candidates, pick the one sharing the longest directory prefix with the importing file, not just the first path segment.
- **Python.**
  - Aliased imports (`import a.b as c`) are captured; before, they produced no reference at all.
  - `from pkg import a, b` yields one edge per distinct target file.
  - Sibling modules and packages resolve: `from . import x`, `from ..pkg import y`, and src-layout siblings.
  - `target_symbol` names the module (`pkg.a`), not the whole statement.
- **C#.**
  - `using static Ns.Type` resolves to the file declaring `Type` in `Ns`: a name that is no namespace is read as a type, since C# forbids both under one full name.
  - `using A = Ns` aliases are captured.
  - `global::` is stripped.
  - Nested `namespace Outer { namespace Inner {} }` declares `Outer.Inner`.
  - When several files declare a namespace, the edge goes to the files declaring a type the source uses, falling back to the first file.
- **C# store fallback.** The separate store query was redundant, because `buildSymbolIndex` already loads every stored symbol. It is replaced by the index with kinds. A sync where only the importing file changes proves that namespaces declared in stored files still resolve.
- **Rust.** `mod foo;` links `foo.rs` or `foo/mod.rs`. A uniform path (`use foo::Bar`, where `foo` is a child module) resolves relative to the current module. External crates still give no edge.
- **Go.** A nested module importing its parent module's package resolves through the enclosing `go.mod`.
- **Resolver API.** Resolvers return `{file, symbol}` hits (zero or more). The scanner writes one edge per hit, with `target_symbol` set to the hit's symbol.

## Out of scope

- PHP resolution (`Illuminate\…`, first-segment preference): M0-04-R2.
- Rust `use a::{B, C}` split into several symbols; Java wildcard imports.

## Implementation plan

- `src/core/import-resolvers.ts`: hit API, per-language fixes, built on `indexOf`.
- `src/parsers/generic-wasm-parser.ts`: the Ruby `require_relative` marker and C# nested namespace names.
- `queries/python/references.scm`: aliased imports. `queries/c-sharp/references.scm`: aliases. `queries/rust/references.scm`: `mod foo;`.
- `src/core/scanner.ts`: one edge per hit; symbol index entries carry `kind`; `typeFiles`, `namespaceFiles` and `referencedNames` in the resolver context.
