# M4-26 — A symbol whose name contains a dot opens by its exact name

## Identification

Milestone M4; priority P2; risk low; estimate min/expected/max: 1/2/3 h; role: store and query surface.

## Objective

`Store.getSymbolByName` finds a symbol whose own name contains a dot (a JS string-keyed member such as `'api.get'`, Lua `M.foo`) without losing what the scoped reading (`Class.method`) finds, so `mapx node`, MCP `mapx_node` and the dashboard's `/api/symbol` route open it, and its callers and callees are listed.

## Dependencies

- M4-24 (hard, DONE).

Source: `reports/M4-24-R1.md` (the symbol-name payload has no dot; follow-up on `getSymbolByName`).

## Scope

1. **What the parser produces.** A real scan of `api.get = function () {}` or `obj.method = () => …` produces no symbol for the assignment. A string-keyed member of an object literal does: `export const actions = { 'api.get': (ctx) => … }` gives a `method` named `api.get` with scope `actions`, and its call edges have `source_symbol = 'actions::api.get'`. Lua `function M.foo()` gives `M.foo` (no scope), with call edges to `M.bar`.
2. **Lookup rule** (revised after review, owner's decision). One private resolver in `src/core/store.ts`, shared by `getSymbolByName`, `getCallersOfSymbol` and `getCalleesOfSymbol` (the three copies of the split logic today). `getSymbolByName` prefers the scoped reading (`Scope::name` / `Scope.name`, exact then normalised, as today) and falls back to the exact `name`; callers and callees take the union of both. A name ending in a file extension is kept whole only when a file of that path exists.
3. **Seeds and impact.** `ContextBuilder` falls back to a symbol lookup when a dotted seed is not a file; `ImpactAnalyzer`'s importer check searches for the matched symbol's stored name.
4. **Callers.** Every caller goes through these three methods: `mapx node`/`callers`/`callees`/`impact` (`src/cli.ts`), MCP `mapx_node`/`mapx_callers`/`mapx_callees`/`mapx_impact`/`mapx_batch` (`src/mcp.ts`), the dashboard `/api/symbol/:name` (`src/ui-server.ts`), `ImpactAnalyzer` and `ContextBuilder`. None of them parses the name itself before the store, so no caller changes; CLI and MCP stay in step.
5. **Tests** (`tests/store-extended.test.ts`): a temp workspace, real `mapx init`/`scan`, then the CLI, MCP `mapx_node` and `GET /api/symbol/…`: `api.get` opens the actions member with its callee; Lua `M.bar` opens (its callers are pinned at store level, with synthetic rows in the scanned shapes); `Class.method`/`Class::method` and `Runner.go` open the class method; on a collision (`Server.Start` as a Go method and a JS key) node opens the method, and callers and impact keep `main`; impact importers and context seeds of dotted names.

## Out of scope

- Extracting a symbol from a member assignment (`api.get = function () {}`): a parser change, not a lookup one.
- Resolving `actions.api.get` (scope and dotted name joined by `.`): ambiguous; `actions::api.get` already works.
