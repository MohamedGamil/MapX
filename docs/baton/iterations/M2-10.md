# M2-10: Lua method calls with `:` and `self` give call edges

## Identification

Milestone: M2; priority: P2; risk: low; estimate min/expected/max: 1/3/4 h; role: reference resolution.

## Objective

`obj:method()` and `self:other()` in Lua give call edges to the method declared by `function T:method()`, as `M.foo()` already links to `function M.foo()`. `.luau` type syntax is reported as a known limitation, or parsed if that is trivial.

M2-11 ("Lua locals and self fields are not module constants") is folded in at the integration owner's request, after the independent review.

## Dependencies

M4-27 (hard, DONE): before it, only the first Lua file of a process parsed.

## Finding (before the change)

- `function Account:withdraw(n)` gives the function symbol `Account:withdraw`, scope null.
- `self:log(n)` and `acct:withdraw(1)` are already extracted as calls, because `(call (variable))` matches a method call too. Their target names are `self:log` and `acct:withdraw`.
- No symbol has those names, so neither call resolves and there is no edge.
- `function run()` (a global function) gives no symbol at all.
- `self.balance = …` and locals inside functions give constants. A call on such a line is credited to the constant: `run::acct`.

## Scope

- **Parser (`src/parsers/languages/lua.ts`, Lua only):** a `:` call names its receiver's table, and where that table lives, when the file tells it. Names resolve through the enclosing functions, innermost first.
  - **`self`:**
    - it is `T` inside `function T:m()` or `function T.m(self)`;
    - an inner function with its own `self` parameter is not `T`'s method.
  - **Other names:**
    - a parameter is unknown;
    - a name the function assigns is bound by every assignment there:
      - `{…}` makes it a table, `local` or global;
      - `T.new()`, `T:new()` and `setmetatable(…, T)` make it an instance of `T`;
      - `require(…)` makes it a module;
      - a loop variable, any other value, or disagreeing assignments make it unknown;
      - `local x` without a value only declares it.
    - a name declared nowhere in the file is a global table.
  - **Result:** the target is `T:m`, with `luaTable` set to `local`, `global` or `require`. An unknown receiver keeps its text and links nothing.
- **Scanner (`resolveLuaMethodCall`):**
  - a `local` table matches `function T:m` or `function T.m(self)` in its own file only;
  - a `global` table matches in its own file, else in the nearest file of its own repo that does not declare `T` local at top level;
  - a `require` binding matches the exact name (`T:m`, else `T.m`), as before M2-10;
  - no method-name fallback.
- **`queries/lua/symbols.scm` (M2-11):**
  - constants come from top-level statements only;
  - a local function value inside a function stays a symbol;
  - `function run()` is a function symbol.
- **`EXTRACTOR_VERSION` 4.**
- **`tests/lua-calls.test.ts`:** end-to-end scans of a Lua workspace and a two-repo workspace.

## Out of scope

- **Lua `require("a.b")` resolution to a project file:** a require-bound receiver keeps the parent's exact-name match, which may pick a homonym module.
- **Metatable inheritance:** `setmetatable(Derived, {__index = Base})` is not followed.
- **`.luau` type syntax:** the bundled Lua grammar gives ERROR nodes. A Luau grammar would be a new bundled wasm.

## Acceptance criteria

1. `function Account:withdraw(n) self:log(n) end` and `acct:withdraw(1)` give call edges to `Account:log` and `Account:withdraw` (e2e).
2. `npm run eval` holds every floor.
3. M2-11:
   - `function run() local acct = Account.new() acct:withdraw(1) end` gives source symbol `run` for both calls, and no constant `acct`;
   - module-level `local M = {}` and `M.VERSION = 1` keep their symbols.
4. Review decisions:
   - built-in and unknown receivers link nothing;
   - local homonym tables never link across files or repos;
   - an inner `self` parameter and function-scoped bindings are honoured.
