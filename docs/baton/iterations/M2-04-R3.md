# M2-04-R3 — HTTP URL follow-ups: shadowed baseURL constants, nested dotenv defaults

## Identification

Milestone: M2; priority: P2; risk: low; estimate 1/2/3 h; role: HTTP pass.
Sources: `docs/baton/reviews/REVIEW-2026-10-31-2db08bd25e13.md` (P2 table), `docs/baton/reports/M2-04-R2.md`.

## Objective

A client's `baseURL` constant is looked up in the scope where the client is created, and nested dotenv defaults expand as Vite's `loadEnv` does.

## Dependencies

M2-04-R2 (hard), DONE.

## Scope

- **Scoped baseURL.** `axios.create({ baseURL: BASE })` keeps the offset of its `axios.create` (`baseURLAt`, on clients and providers; it is not persisted). The scanner evaluates the base with `constantsFor(file, baseURLAt)`. Before, it used the whole-file constants, so a function-local `BASE` gave way to the top-level one. Configured clients (`settings.http.clients`) have no offset and keep the whole-file lookup.
- **Nested defaults.** `expandDotenv` matched `${…}` with `[^{}]+`, so `${A:-${B:-/deep}}` was left as literal text. It now scans each `${` to its matching brace, and the default or alternative is expanded recursively.

Files: `src/frameworks/http/url-resolver.ts`, `src/core/scanner.ts` (`scanHttpCalls`) and `src/frameworks/http/client-calls.ts`. The last is outside `affectedFiles`, but the creation offset is recorded where clients are found.

## Out of scope

- A base URL built at runtime.
- Shadowing through destructuring.

## Acceptance criteria

1. `const BASE = '/wrong'` at the top level and `function seven() { const BASE = '/api/v7'; axios.create({ baseURL: BASE })… get('/z') }` give `/api/v7/z`. A `BASE` parameter leaves the base unresolved (`/q`, `baseURLUnresolved`), never `/wrong` (`tests/http-url-resolution.test.ts`, real scan).
2. `${VITE_NOPE:-${VITE_NOPE2:-/deep}}`, `${VITE_NOPE:-${VITE_API_URL}/x}` and `${VITE_API_URL:+${VITE_SINGLE}/alt}` expand as Vite's `loadEnv` does. The fixture is compared with `loadEnv` itself in "matches Vite loadEnv on the same file".
3. The HTTP scorer gate holds.
