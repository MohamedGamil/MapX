# M0-12-R8 — Svelte script blocks: symbols and references through the JS/TS parsers

## Identification

Milestone: M0; priority: P2; risk: medium; estimate min/expected/max: 4/6/10 h; role: parsers.
Sources: `docs/baton/reports/M0-11-R3.md` (D016), `specs/features/F20-language-expansion.md`.

## Objective

A `.svelte` file gives the symbols and references of its `<script>` blocks, as a `.vue` file does, and the docs claim only what is extracted.

## Dependencies

- M0-11-R3 (hard): found the gap and pinned the old behaviour (D016). DONE.

## Reproduction (baseline: develop@00407d6 plus `base10.patch`)

`tests/svelte.test.ts` fails 5/5 before the fix. `src/Counter.svelte` (a `context="module"` and an instance `<script lang="ts">`) gives two class symbols named `Counter`, one per script element (lines 1–7 and 9–22), and no edges at all, while `src/twin.ts` with the same code gives five (two calls, three imports).

## Scope

- **`src/parsers/languages/svelte.ts` (new), `SvelteParser`.**
  - Each `<script>` block (instance, `context="module"`, Svelte 5 `module`) goes to the TypeScript parser when `lang="ts"` / `lang="typescript"`, else to the JavaScript parser.
  - The parse uses the `.svelte` path, so the `.vue`-only exceptions of `GenericWasmParser` do not apply: the block is read like a `.ts` / `.js` module.
  - Lines are offset into the `.svelte` file. HTML comments are blanked first, so a commented-out `<script>` is not read.
  - One component symbol (class, named after the file, lines 1 to the last line). It owns the references outside any function, through Vue's `assignOwners`.
  - `export let` bindings keep the kind a `.ts` binding gets (`variable`, or `function` for a function or call value) and get `metadata.prop`. The component's `metadata.props` lists them, as a `.vue` component's does.
- **`src/parsers/parser-registry.ts`:** `svelte` → `SvelteParser`. The task named `src/parsers/parser-factory.ts`, which does not exist; the registry is where parsers are chosen.
- **`queries/svelte/*.scm`:** comments say they are not used for extraction. The grammar and queries stay, because the parse worker pre-loads every bundled grammar and its fallback walk needs them.
- **References** go through the scanner unchanged: `isJsOrTs` and `JS_MODULE_SOURCE` already count `.svelte`, so relative and aliased imports, the built-in globals skip and the M0-17-R4 receiver skip apply.

## Out of scope

- Template references (`{foo()}`, `on:click={bar}`, `<Child/>` render edges). They were optional, and are not added.
- Svelte 5 `$props()` destructuring as props, and `$:` reactive declarations as symbols.
- `svelte.config.js` `kit.alias`.
- Calls from other files to a Svelte value binding: see Follow-up. Fixing it needs `src/core/scanner.ts`, another lane's file.

## Blast radius

`npx tsx src/main.ts impact SvelteParser` (worktree scan):
- HIGH: `createParser`.
- MEDIUM: `getParserForFile`.
- LOW: `Scanner::parseOnMainThread`, `parseFile` (worker).

`impact createParser`: `getParserForFile` (HIGH), then both parse paths. Only `.svelte` files take the new branch.

## Acceptance criteria

1. A `.svelte` file with `<script>` and `<script context="module">` gives their functions, classes, constants and `export let` props as symbols, at `.svelte` lines. E2E, both parse paths (workers and `--no-parallel`).
2. Its relative and aliased imports and its calls give edges as a `.ts` file would. `new Date()` and `fetch()` give no edge to same-named project symbols. E2E, including the updated M0-11-R3 test in `tests/legacy-impact-staleness.test.ts`.
3. README.md, docs/getting-started.md and docs/framework-integration.md describe Svelte extraction as delivered.

## Follow-up

Calls from other files to Svelte value bindings: an unimported `MAX()` or `title()` in a `.ts` file links to a `.svelte` constant or variable, though it would not link to one in a `.ts` file. The fix is one line in `src/core/scanner.ts`, adding `'svelte'` to `VALUE_SYMBOL_LANGUAGES`. It was verified in a scratch copy, with a test ready for the integrator (see the report).
