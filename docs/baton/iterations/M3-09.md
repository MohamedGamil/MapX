# M3-09 — JS/TS import aliases from tsconfig/jsconfig paths and Vite/webpack alias config

## Identification

Milestone: M3; priority: P2; risk: medium; estimate min/expected/max: 2/4/6 h; role: import resolution.
Sources: `docs/baton/reports/M3-04.md` ("Findings outside this task").

## Objective

A JS/TS/Vue import through a path alias (`@/x`, `~/x`, `#x`) resolves to the file the project's own configuration names. Laravel projects (`@` → `resources/js`) and repositories with several apps get their render, mixin, composable and import edges. Before this change, `@/` was hard-wired to `<workspace>/src/`, and only for `.vue` sources.

## Dependencies

- M3-04 (hard). DONE. Its path-suffix fallback in `moduleMember` is superseded by this task.

## Scope

- **Configs, read statically.** Nothing is executed.
  - `tsconfig.json` / `jsconfig.json`: JSON with comments and trailing commas. `compilerOptions.paths` resolve relative to `baseUrl`, else relative to the declaring config. Relative `extends` chains are followed (string or array). `references` are read when the root config has no `paths` (create-vue's `tsconfig.app.json`).
  - `vite.config.{ts,js,mts,mjs,cts,cjs}`, `vue.config.{js,cjs}`, `webpack.config.{js,cjs}`, `webpack.mix.js`: literal entries only. This covers `alias: { … }`, `alias: [{ find, replacement }]`, `mix.alias({ … })` and `config.resolve.alias.set(k, v)`. Accepted values are a string (a leading `/` is relative to the config's folder, as Vite and Laravel use it), `path.resolve` / `path.join(__dirname, '…')`, and `fileURLToPath(new URL('…', import.meta.url))`.
- **Order of resolution.** Start from the importing file's folder and walk upwards. The first folder whose config declares an alias matching the specifier decides. Within a folder, `compilerOptions.paths` come before bundler aliases. Matching follows TypeScript: an exact pattern wins, then the longest prefix. A bundler key `k` covers `k` and `k/…`, and `k$` covers `k` only.
- **Fallback.** With no matching alias, `@/x` resolves to `src/x` under the nearest `package.json` folder, then under the workspace root (today's behaviour). The bare specifier is tried after that, as before.
- **Applies to:** every JS/TS/Vue/Svelte source, through `Scanner.resolveImportPath`. Import edges, M3-02 render hints, M3-03 mixins, M3-04 composables and M3-06 route components all go through it.
- **M3-04's path-suffix fallback** (`resolveAliasBySuffix`) is removed. See the report.

## Out of scope

- `extends` from npm packages, `package.json` `imports` (`#x` subpath imports), Nuxt / SvelteKit / Quasar alias configs, aliases computed at runtime, and RegExp `find` keys.
- The HTTP pass's own `resolveImport` (`src/frameworks/http/client-calls.ts`). It has no config access; this is recorded as a finding.

## Implementation plan

- `src/core/js-aliases.ts` (new): `jsAliasTargets(target, sourcePath, ctx)`, the JSONC parser, tsconfig and bundler readers, and TypeScript-style matching, with a cache per file set and folder.
- `src/core/scanner.ts`: `resolveImportPath` tries the alias targets, then the specifier. The extension probing moves to `probeModule()`. `aliasContext()` builds the file set and config reader. `resolveAliasBySuffix` is removed.
- Tests: `tests/legacy-imports.test.ts` (unit tests for each config form plus an end-to-end test with four apps), and `tests/vue-script-setup.test.ts` (a Laravel app with a vite.config.js, checking render, mixin and composable edges).

## Acceptance criteria

1. `@/x` resolves through tsconfig/jsconfig `paths` (with `baseUrl` and `extends`), else through a statically readable vite / vue.config alias, else through `src/`. There is an end-to-end test for each: `apps/shop`, `apps/admin` / `apps/old`, and `apps/legacy`.
2. A Laravel `@` → `resources/js` alias in vite.config.js resolves render, mixin and composable imports in a `.vue` file (end-to-end test).
3. Aliases are scoped to the nearest config folder: four apps with different `@` roots each resolve to their own file (end-to-end), plus the unit test "the nearest config decides".
4. The edges, routes and HTTP scorers do not drop.
