# M0-04-R5 — PHP global function calls and require/include produce edges

## Identification

Milestone: M0; priority: P1; risk: medium; estimate min/expected/max: 2/4/6 h; role: PHP parser / resolution.

## Objective

A PHP call to a plain or namespaced function gets a `call` edge to the file declaring that function, and `require` / `include` (all four forms) get an edge to the included file. Today both produce nothing.

## Dependencies

- M0-04-R3 (hard): PHP resolution by declared namespace (`phpNamespaces`, strict namespaced match), built on M0-04-R2.

## Scope

**Root causes (reproduced on develop@580546a).** `main.php` with `require_once "helpers.php"`, `include __DIR__ . '/lib/util.php'`, `require_once('helpers.php')` and calls to `helper_fmt()` / `util_join()` gives zero edges. The parser emits only one reference: `require helpers.php`, from the parenthesised form.

1. **Query, calls.** `queries/php/references.scm` has no capture for `function_call_expression`, so plain function calls are never references. Only `event()` / `dispatch()` are matched, for F12.
2. **Query, includes.** The `require*` / `include*` patterns accept only `(parenthesized_expression (string))`. The usual `require_once "x.php";` (no parentheses), double-quoted strings (`encapsed_string`) and `__DIR__ . '/x.php'` (a `binary_expression`) are never captured.
3. **Resolution, includes.** PHP has a module import resolver, so the scanner routes `require` references to `resolvePhpImport`, which treats the path as a namespace name and finds nothing.

**Contract.**

- **Function calls.** The parser emits a `call` reference for `function_call_expression` with a `name`, `qualified_name` or `relative_name` callee (not `$f()`), and attaches the candidate FQNs in PHP's resolution order (`ExtractedReference.phpFunction`, not stored):
  - `\App\fmt()` → `App\fmt`;
  - `use function App\fmt; fmt()` → `App\fmt` (aliases and group `use function` too);
  - `Sub\fmt()` → the `use`-expanded first segment, else `<current namespace>\Sub\fmt`;
  - `namespace\fmt()` → `<current namespace>\fmt`;
  - unqualified `fmt()` in namespace `N` → `N\fmt`, then the global `fmt` (PHP's fallback); in the global namespace → `fmt`.
- The scanner resolves a reference with `phpFunction` only to a `function` symbol (never a method, class or constant) declared in a PHP file whose namespace equals the candidate's namespace (`''` for global). It takes the first candidate with a hit, preferring the calling file. `target_symbol` is the matched candidate (`helper_fmt`, `App\Support\fmt`). Built-ins (`strlen`, `array_map`) are declared nowhere in the workspace, so they get no edge, and a method of the same name is never a target.
- **Includes.** All four statements capture their argument expression. The parser evaluates string literals (single- or double-quoted, without interpolation), `__DIR__`, `dirname(__FILE__)`, `dirname(__DIR__)` and `.` concatenation, and parentheses. A path built from `__DIR__` is emitted as `__DIR__/…`, a plain string as written. Anything else (variables, constants) is skipped.
- The PHP import resolver treats a path-like target (`/` or `.php`; a namespace never contains either) as an include. `__DIR__/x` resolves against the including file's folder only. A plain relative path resolves against that folder, then the workspace root, mirroring PHP's include-path search with the entry script in the root. The edge type stays `require`, the import-family edge type Ruby and Lua already use, which the impact analyser, role classifier and cluster engine treat like `import`.

## Out of scope

- An import edge for `use function App\fmt;` itself (the call edge is delivered; the `use` line resolves only to types, as in R2).
- `include` through `include_path`, constants (`APP_ROOT . '/x.php'`) or variables.
- Calls through `call_user_func('name')` or string callables.

## Implementation plan

- `queries/php/references.scm`: a `function_call_expression` capture; include and require patterns over any argument expression.
- `src/parsers/languages/php.ts`: a `use function` table, function-name candidates, include-path evaluation.
- `src/types.ts`: `ExtractedReference.phpFunction?: string[]`.
- `src/core/import-resolvers.ts`: `resolvePhpInclude`, dispatched from the PHP resolver.
- `src/core/scanner.ts` (small): one branch in `resolveReferencesWithMap` and a `resolvePhpFunction` helper.

## Acceptance criteria

1. `function run() { return helper_fmt(1); }` with `helper_fmt` declared in a `require_once`-d file gives `call` run → helpers.php#helper_fmt; a call inside a class method gives `Runner::go` → helpers.php#helper_fmt (e2e).
2. `require_once "helpers.php"`, `require_once('helpers.php')`, `include __DIR__ . "/lib/util.php"` and `require dirname(__DIR__) . '/…'` give `require` edges to the resolved files; a missing file gives none (e2e).
3. `use function App\Support\fmt; fmt()` and `\App\Support\fmt()` resolve only to the `fmt` declared in `App\Support`, never to a homonym in another namespace or a method; an unqualified call in namespace N falls back to the global function; `strlen` / `array_map` give no edge (e2e).
