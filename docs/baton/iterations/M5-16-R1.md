# M5-16-R1 — score-arch scores smells

## Identification

Milestone: M5; priority: P3; risk: low; estimate min/expected/max: 2/4/6 h; role: evaluation (scorer, fixture labels).

## Objective

The arch-rules fixture labels its expected smells (rule-derived and package smells), and `score-arch --json` reports recall and precision per smell kind.

## Dependencies

M5-16 (hard, DONE), M5-24 (hard, DONE); M5-16-R2 (the same smells module).

## Scope

- `tests/fixtures/arch-rules/expected-smells.json`: a separate block of labels. `complete[app]` names the kinds whose labels are complete for the app (every smell of the kind is a row, or the app has none); only those are scored. Each row has its `evidence`.
- `scripts/eval/score-arch.ts`: `scoreSmells`, `loadExpectedSmells`, smells read in process after the scan (`currentSmells`, the configuration and baseline applied), a `smells` section in `--json`, lines in the text output, and the usual `--min-recall` and `--min-precision` thresholds.
- Labels are derived from the fixture sources and the existing labels (`expected-findings.json`, `expected-externals.json`) by reasoning, never from the tool's output.

## Out of scope

- Labels for `dead-allowance`, `weak-allowance`, `unstable-layer-dependency` and `abstractness-distance`: they need per-edge counts and metric values.
- Floors in `floors.json`: `npm run eval` does not run score-arch, so there is nothing to floor.

## Implementation plan

1. Labels, scorer, tests (`tests/arch-fixture.test.ts`).
2. A defect the labels expose in `dev-dependency-in-prod` is fixed in `src/arch/smells.ts` with a test in `tests/external-refs.test.ts`.
3. `docs/benchmarking.md`.

## Expected outputs

`expected-smells.json`, `scripts/eval/score-arch.ts`, tests, docs, `docs/baton/reports/M5-16-R1.md`.
