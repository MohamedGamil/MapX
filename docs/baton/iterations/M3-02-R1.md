## Identification

Milestone: M3; priority: P2 (review 2026-10-31); risk: medium; estimate 3/4/6 h; role: Vue resolution.

## Objective

Names the template binds itself, and `this` inside nested non-component functions, never resolve to component members or to same-named functions elsewhere.

## Dependencies

M3-02 and M3-03 (hard), both DONE.

## Scope

- **Template element tree** (`src/parsers/languages/vue-template.ts`, `templateNodes`). The pass read a flat list of opening tags. It now keeps a stack of open elements: closing tags pop to their match, and void and self-closing tags never open. Each tag and interpolation carries `locals`, the names the template binds around it:
  - `v-for` aliases (also destructured, with an index), visible on the element's own attributes and its children;
  - `slot-scope` (and Vue 2.5 `scope` on `<template>`), likewise;
  - `v-slot` / `v-slot:name` / `#name` props, visible to the children only.

  The `v-for` source is read in the outer scope (`outerLocals`).
- **Calls** (`templateReferences`). A handler or call whose name is in `locals` gets no reference.
- **`v-pre`.** A `v-pre` element and its subtree yield no node. That means no call, render or navigate reference: `navigationReferences` reads the same nodes.
- **Custom blocks** (`templateRange`). Only a top-level `<template>` counts. Any other top-level block is skipped as raw text up to its closing tag, as the SFC compiler reads it, so a `<template>` shown inside `<docs>` or `<i18n>` is ignored.
- **Nested functions** (`src/parsers/languages/vue-options.ts`, `collectThisCalls`).
  - `this` is the component inside the functions the options literal holds (through objects, pairs and arrays only: members, hooks, `watch` handlers, computed `get` / `set`, inline mixins) and in arrow functions within them.
  - Any other non-arrow function (a callback `function () {}`, a nested object's method, a nested `function` declaration) rebinds `this`, as does an arrow held by the literal itself.
  - These calls go to `reboundCalls`. `annotateThisCalls` gives them a `vueThis` that no step resolves, so they get no edge instead of the default name lookup. Before, a rebound call in a nested object's `run: function () {}` was taken for the component's.

No scanner change was needed: a `vueThis` that resolves to null already gives no edge (`scanner.ts` takes the Vue branch whenever `resolveThisMember` returns anything but `undefined`).

Blast radius (`mapx impact`, before the change):
- `templateNodes` and `templateRange` → `templateReferences`, `navigationReferences` → `VueParser.parse`, `navigatesTo` → `Scanner.vueRegistryReferrers`;
- `collectThisCalls` → `analyzeOptionsComponent` → `annotateThisCalls`, `VueParser.parse`.

The new `TemplateTag.locals` fields are additive; `vue-navigation.ts` needed no edit.

## Out of scope

- `<component :is="X">` render edges, Pug templates, `this` aliases (`const self = this`): unchanged.
- Shadowing by `<script setup>` locals or JS scoping inside template expressions (`items.map(save => save())`): not modelled.

## Acceptance criteria

1. v-for aliases, v-slot/#slot destructured props and slot-scope names never resolve to same-named component methods. Tests in `tests/vue-template.test.ts` › "template scopes, v-pre and custom blocks (M3-02-R1)": "never gives v-for aliases or slot props a call reference, in the scope they bind" (parser) and "gives no edge to a same-named method on a real scan" (e2e). Fixture labels v2-113, v2-114, v3-112, v3-113.
2. v-pre subtrees produce no edges, and a top-level custom block containing `<template>` before the real template does not replace it. Tests "skips v-pre subtrees: no calls, renders or navigation inside" and "reads the top-level <template> block, not a <template> shown inside a custom block", plus the e2e. Fixture labels v2-110, v2-111, v2-112, v2-115.
3. `this.x()` inside a nested `function () {}` within a method is not resolved by name to another file. Tests in `tests/vue-options.test.ts` › "this.x() inside nested functions (M3-02-R1)": "splits component this.x() calls from rebound ones" (parser) and "never resolves a rebound this.x() by name to another file (real scan)". Fixture label v2-116.
4. The edges scorer does not drop. Checked on the original fixture (byte-identical output) and on the extended one, before and after.
