# M2-08-R3 — Names imported from an external module never link to a same-named project symbol

## Identification

Milestone: M2; priority: P1; risk: medium; estimate min/expected/max: 2/4/8 h; role: resolver engineer (JS/TS).

## Objective

In JS/TS, a reference to a name bound by an import from a package or builtin module (`import { join } from 'node:path'`) gets no edge to a same-named project symbol, and a bare name an ES module neither imports nor declares (a global such as the DOM `Node`) does not link by name to a declaration of another project module.

## Dependencies

M2-08-R2 (hard, DONE). Sources: reports M2-08-R1, M2-08-R2, M5-18.

## Scope

- **Import-bound externals:** in `Scanner.resolveReferences`, a JS/TS/Vue/Svelte reference (any kind but `import`/`require`) whose bare name, or whose receiver, is bound by an import that `decideExternal('npm', …)` calls external (a package, `node:x`, a bare builtin such as `path`) gives no edge. It goes to the M5-19 external-reference path (`noteExternal`), which is unchanged.
- **Globals in an ES module:** in a `.ts/.tsx/.js/.jsx/.mjs/.cjs/.mts/.cts` file with a top-level `import` or `export`, a bare identifier the file neither imports nor declares is resolved by name only among files that put names in the global scope: the file itself, a file with no top-level `import`/`export` (a script, a global `.d.ts`), or a file whose `declare global { … }` block declares the name. Another ES module's declaration is never a candidate. A name imported from outside the workspace that the file also declares resolves only in the file itself.
- **Exemptions:** names the file declares (including destructured variables and dynamic-import `.then` parameters), `.vue`/`.svelte` sources (template expressions and SFC auto-imports), and any source under a package.json that depends on an auto-import tool (`nuxt`, `nuxt3`, `nuxt-edge`, `@nuxt/bridge`, `unplugin-auto-import`, `unimport`) keep name lookup.
- `EXTRACTOR_VERSION` bumped by one, with its comment line.

## Out of scope

- Member calls on an unbound receiver (`x.join()`): method lookup by name, unchanged.
- Names imported from a project module that `findExport` cannot find: name lookup stays (M2-08-R1).
- External-reference recording and attribution (M5-19 … M5-23).
- Framework-specific edges (Vue `vueHint`, `this.x`, stores; navigation).
