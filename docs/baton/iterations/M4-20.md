# M4-20 — Dashboard performance on large workspaces

## Identification

Milestone M4; P1; risk medium; estimate 6/10/16 h. Decision D027.

## Objective

Make the dashboard load and render large graphs faster, with targets set from the M4-16 baseline.

## Background

D027. Candidates: lazy-load the layout engines (elk, cola, dagre, fcose) on first use, compress and trim API payloads, render large graphs progressively.

## Dependencies

- M4-16 (hard)
- M4-19 (hard)

## Out of scope

Visual design (M4-17); new views (M4-21 to M4-23).

## Acceptance criteria

1. The initial gzipped JavaScript the dashboard loads is at least 30% smaller than the M4-16 baseline (check-package and the report).
2. On the ~2,000-node fixture, time to an interactive graph is at least 30% below the M4-16 baseline, and no main-thread task during loading exceeds the target set in the report (tests/ui/perf.spec.ts, Performance API).
3. /api/graph for that fixture is served compressed and at least 30% smaller on the wire than the baseline (test).

## Verification

- `npm run test:ui`
- `npx tsx scripts/check-package.ts`
- `npm run check`
