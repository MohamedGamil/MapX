# M2-04-R4 — Same-named axios clients in one file keep their own baseURL scope

## Identification

Milestone: M2; priority: P2; risk: low; estimate min/expected/max: 1/2/4 h; role: HTTP pass.
Sources: `docs/baton/reviews/REVIEW-2026-11-02-b2558df592cf.md` (M2-04-R3 DEFECTIVE, finding 7), `docs/baton/reports/M2-04-R3.md`.

## Objective

Each call uses the baseURL of the client binding in its own scope; a parameter shadowing the constant gives no value.

## Dependencies

M2-04-R3 (hard), DONE.

## Scope

- **The defect.** `receiversFor` adds one receiver per `const api = axios.create(…)` in the file. `extractHttpCalls` runs each receiver's pattern over the whole file and claims each call offset for the first receiver that matches it. With two functions each declaring `const api = axios.create({ baseURL: BASE })`, every `api.get` takes the first client and its `baseURLAt`. M2-04-R3's scoped base lookup then evaluates `BASE` in the first function, giving `/local/a`, `/local/b`, `/local/c` instead of `/local/a`, `/top/b` and an unresolved `c`.
- **The fix.** A client created in the file records the block its binding is visible in: the innermost `{…}` around the declaration in the masked source, or the whole file at top level. That is the same rule `fileBindings` uses for constants. Receivers with the same pattern are compared per call:
  - the innermost in-file client whose block contains the call owns it;
  - if no block contains the call, the call goes to a same-named receiver without a block (an import or a configured receiver), and otherwise to the first one, as before.
- **After the independent review of the first attempt:**
  - declarations are matched on the masked source;
  - factory aliases are scoped like clients;
  - a file whose masked braces do not balance gets no scopes, which is the M2-04-R3 behaviour;
  - receivers are grouped by pattern, scopes come from one pass, and `createBaseURL` reuses the masked text, so the cost is near-linear.
- The scanner already evaluates a client's base at its `baseURLAt` (M2-04-R3). Once the right client owns the call, that evaluation gives the right value, so `scanner.ts` needs no change.

## Out of scope

- A parameter or other non-client binding named like a client that shadows it (`function f(api) { api.get(…) }` beside a top-level client) is still taken as the client, as before.
- Clients bound by destructuring or reassignment.

## Implementation plan

- `src/frameworks/http/client-calls.ts`: `Receiver` gains an optional `scope` range; `receiversFor` computes it for in-file `axios.create` bindings; `extractHttpCalls` gives each call to the receiver that owns it.
- `tests/http-url-resolution.test.ts`:
  - an end-to-end scan with the review's case (two functions plus a parameter);
  - a file with one top-level client called from several functions;
  - the review's comment, string, factory-alias and unbalanced-TSX cases;
  - a time-bounded test with 2,000 clients.
