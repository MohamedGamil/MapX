# M2-29 — Laravel migrations, seeders, factories and views are indexed by default

## Identification

Milestone: M2; priority: P2; risk: low; estimate min/expected/max: 1/2/4 h; role: config / indexing engineer.

## Objective

A repo with `framework: laravel` indexes `database/migrations/`, `database/seeders/`, `database/factories/`, `resources/views/` and `*.blade.php` without configuration. `storage/`, `bootstrap/cache/`, `public/` and `vendor/` stay excluded.

## Dependencies

M2-23 (hard, DONE) made these files give edges. D043 is the owner decision (2026-11-05): they are included by default.

## Cause

`LARAVEL_DEFAULT_EXCLUDES` (F10) excluded these five patterns at scan time for every Laravel repo. `mapx init`'s Laravel suggestion also wrote them into `excludePatterns`. As a result, the `laravel` preset's Database and Views layers were empty unless the user opted in.

## Scope

- **`src/core/config.ts`:** `LARAVEL_DEFAULT_EXCLUDES` keeps `storage/**`, `bootstrap/cache/**`, `public/**` and `vendor/**`. The five dropped patterns become `LARAVEL_FORMER_DEFAULT_EXCLUDES`.
- **`src/cli.ts`:** init's suggestion lists only the remaining four, and says that `database/` and the views are indexed.
- **`src/core/config-report.ts`:** the former defaults, written by an earlier init, are still reported as patterns MapX wrote (`source: default`).
- **Existing indexes:** an index built with the old defaults gains the files on its next `scan` or `sync`. The effective excludes are part of `meta scan_filters:<repo>` (M0-02-R1), so the change takes the full-scan path once. There is no code change for this, but it has a test.
- **Docs:** `docs/configuration.md`, `docs/architecture-rules.md` and `docs/framework-integration.md`.

## Out of scope

- Rewriting a user's `.mapx/config.json`. A config whose `excludePatterns` lists the former defaults, as an earlier init wrote them, keeps them excluded. The docs and the CHANGELOG say to remove them.
- The declined-suggestion marker (`laravelDefaultExcludes: false`) is unchanged.

## Acceptance criteria

1. A `framework: laravel` repo with no `laravelDefaultExcludes` setting indexes a migration, a seeder, a factory and a Blade view. It leaves `public/` and `bootstrap/cache/` out, at the root and under a non-root repo path (tests/legacy-globs.test.ts).
2. `mapx init` on a Laravel app that accepts the suggestion writes none of the five patterns, and still writes `storage/**` and `bootstrap/cache/**` (tests/config.test.ts).
3. An index scanned with the former defaults gains the files and the migration's edge to its model on the next sync. The result equals `scan --force`, under both git and hash sync (tests/legacy-globs.test.ts).
4. Staleness follows the new rules: a new migration or Blade view is stale, a new `public/` or `bootstrap/cache/` file is not (tests/legacy-impact-staleness.test.ts). A config that lists the former defaults in `laravelDefaultExcludes` or in `excludePatterns` keeps them out (tests/legacy-globs.test.ts). The config report labels them `default` (tests/ui-server-config.test.ts).

## Verification

- `npx vitest run tests/legacy-globs.test.ts tests/config.test.ts tests/laravel-dirs.test.ts tests/ui-server-config.test.ts tests/legacy-impact-staleness.test.ts`
- `npm run check`

`npm run eval` also runs, since its Laravel fixtures are scanned with the defaults.

## Recovery

Revert the task commit. An index re-parses once more, when its effective excludes move back.
