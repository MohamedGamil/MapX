# M4-24 — Escape scanned values in the dashboard HTML

## Identification

Milestone M4; P1; risk low; estimate 2/4/8 h. Found during M4-17.

## Objective

Every value the dashboard writes into HTML from the index, scan results or the tool-call log is escaped, so a crafted name, path or route in a scanned repository cannot run script in the dashboard.

## Background

Templates in `src/ui/main.ts` interpolate route paths, handlers, hook names, symbol and file names, smell text, tool-call inputs and context files into `innerHTML` without escaping. A scanned repository controls these values. Script running in the dashboard's origin can call every `/api` endpoint, including source reads through `/api/symbol/`.

## Dependencies

- M4-17 (hard)

## Out of scope

Server-side changes, and the new views (M4-21 to M4-23), which escape from the start.

## Acceptance criteria

1. A fixture whose route path, handler, symbol name, file name and logged tool input each contain an HTML payload (`<img src=x onerror=...>`) is scanned and opened on every tab. No payload executes (a page-level flag stays unset), and each payload is shown as text (`tests/ui/xss.spec.ts`).
2. No template in `src/ui/main.ts` interpolates a value from `/api` data into `innerHTML` without `escapeHtml` or `textContent`. A check lists the `${...}` interpolations in `innerHTML` templates, and each is escaped or a number (test).
3. Removing the escaping from one template makes the XSS test fail (mutation check in the report).

- `npm run check`
