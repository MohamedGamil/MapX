# M0-04-R6 — Laravel middleware: X::class.':param', no short-name guessing, one Kernel per app

## Identification

Milestone: M0; priority: P1; risk: medium; estimate min/expected/max: 3/5/8 h; role: Laravel/static-analysis engineer.
Sources: `docs/baton/reviews/REVIEW-2026-10-31-2db08bd25e13.md` (P1), `docs/baton/reports/M0-04-R3.md` (COMPLETION DISPUTED), `docs/baton/reports/M0-05-R3.md`.

## Objective

Route middleware with parameters names its class, bare names never link by short class name, and each Laravel app's Kernel aliases and groups stay its own.

## Dependencies

M0-04-R3 (hard, disputed): class-constant middleware named through the route file's use table. This task finishes its AC2.

## Reproduction (on the integrator's baseline, before the fix)

The new tests fail on the baseline code (4 failed, 52 passed in the registered files):

- `->middleware(EnsureRole::class.':editor')` gives the raw text `EnsureRole::class.':editor`; the array form gives `App\Http\Middleware\EnsureRole` and a bogus `:admin`; `Route::middleware(X::class.":owner")` keeps `EnsureRole::class.":owner`; the `'middleware' =>` group attribute drops `:staff`.
- The scanner splits on `:` and resolves the bare part by short class name: `Unimported::class.':admin'` (no `use`) links `app/Http/Middleware/Unimported.php`, and `'Thing'` links `app/Other/Thing.php`.
- `->middleware('auth', 'verified')` keeps only `auth`. `use App\Http\Middleware\{Grouped as U2, Audit};` is not read: `U2::class` and `Audit::class` become `\U2` and `\Audit`.
- `'role:manager'` (Kernel alias with parameters) stays `role:manager`; the Kernel's `EnsureRole::class` (imported) is stored as the short name `EnsureRole` and resolved by short name.
- Two apps (`admin/`, `backend/`), each with `app/Http/Kernel.php`: the workspace context merges both Kernels, so `admin/app/Http/Kernel.php` emits backend's `auth` alias (edge to `admin/…/Authenticate.php`), and admin's route expands `auth` with backend's alias. A group member alias (`'portal' => ['team', …]`) is not expanded, so the group has no edge to EnsureTeam.

## Scope

- `src/frameworks/detectors/laravel.ts`
  - `listItem`/`listArg`: one PHP list entry is a quoted name, a class constant, or a class constant with concatenated parameters (`EnsureRole::class.':editor'` → `EnsureRole::class:editor`); a name that can't be read (`$mw`) is no entry. `listArg` reads every argument (`Route::middleware(...$middleware)`) unless the first is an array; `withoutMiddleware` reads one. The `'middleware' =>` group attribute uses the same reader.
  - `middlewareClassNames` keeps the parameters after the named class: `App\Http\Middleware\EnsureRole:editor`, as Laravel's `X::class.':editor'` evaluates.
  - `parseUseImports` reads group use (`use A\{B, C as D};`).
  - One Kernel per app root (`wctx.kernels`); `parseKernel` names class constants through the Kernel's use table and namespace and ignores commented-out entries. `resolveMiddleware` is Laravel's `MiddlewareNameResolver` (groups, nested groups, aliases, parameters after the class); routes use the Kernel of their own app and record `metadata.appRoot`.
  - Kernel hooks are parsed from that Kernel file alone, carry `metadata.appRoot`, expand group members like Laravel, resolve only namespaced names and are declared once per name and class.
- `src/core/scanner.ts` (route-middleware edges only): hook targets are keyed by app root and name, so a route uses only its own app's Kernel entries; for a PHP route file only a namespaced name falls back to class resolution.

## Out of scope

- Controller-constructor middleware (`parseControllerMiddlewares`) and `#[Middleware]` attributes: string-only, unchanged.
- Laravel 11 `bootstrap/app.php` `->withMiddleware()` aliases.
- Non-PHP route middleware (Express) keeps the old capitalised-name fallback.

## Acceptance criteria

1. `->middleware(EnsureRole::class.':editor')` and `[EnsureRole::class.':admin', 'auth']` give the middleware `App\Http\Middleware\EnsureRole` with parameters `editor`/`admin` and no `:admin` entry. Test: `tests/laravel-mounts.test.ts` "M0-04-R6 … names each middleware class with its parameters, and keeps every variadic argument".
2. A name without a namespace separator that is not a Kernel alias or group never links by short class name: `Unimported::class.':admin'` without a use and `'Thing'` give no edge. Test: "… links the route file to each named middleware class, never by short class name" (exact edge list).
3. `->middleware('auth', 'verified')` keeps both names, and `use App\Http\Middleware\{X as U2};` resolves `U2`. Same two tests.
4. Two Laravel apps keep separate Kernel aliases and groups: an alias declared only in app A gives no edge from app B's routes or Kernel. e2e: `tests/legacy-hook-verifiability.test.ts` "two Laravel apps keep their own Kernel aliases and groups".
