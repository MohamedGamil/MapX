# M0-02-R3 — Git renames, nested-repo diffs and symlinked nested repos in incremental sync

## Identification

Milestone: M0; priority: P2; risk: low; estimate min/expected/max: 2/4/6 h; role: scanner (incremental indexing, git tracking).

## Objective

`sync` after a git rename leaves no stale path, and nested or symlinked repos resolve diff paths correctly.

## Dependencies

M0-02-R2 (hard), DONE. Sources: `docs/baton/reports/M0-02-R2.md` (renames, subdirectory repos) and `docs/baton/reports/M0-10-R2.md` (the scanner's nested-repo skip compares unresolved paths).

## Scope

- **Git renames.** `getChangedFiles` reports a rename (`R<score> old new`) by its new path only, so `sync` never removes the old path. A rename now carries `oldPath`, and the scanner removes it (files, symbols, edges) alongside indexing the new path.
- **Repos nested in a larger git checkout.** `git diff --name-status` prints paths relative to the git top level and lists changes outside the repo; the scanner resolves them against the repo root. The diffs now use `--relative`, so paths are repo-relative and limited to the repo, as `git ls-files --others` already is.
- **Symlinked nested repos.** `discoverFiles` compares registered roots with `resolve`, so a repo registered through a symlink is not recognised when the walk reaches its real folder: a plain folder is indexed twice, and a git checkout triggers the "unregistered nested git repository" warning. Roots are compared by canonical path (`canonicalPath`, M0-10-R2).
- **legacy-globs timeout.** Find why `tests/legacy-globs.test.ts` approaches its 30 s timeout under load and make it faster, without raising the timeout.

## Out of scope

- Copies (`C old new`) keep the old path, which is correct; only the new path is indexed.
- Paths git quotes (`core.quotePath`, non-ASCII names). Not reported by the review.
- Cleaning existing symlinked duplicate registrations (M0-10-R2 limitation).

## Implementation plan

- `src/core/git-tracker.ts`: parse `R` lines into `{ path: new, oldPath: old, status: 'renamed' }`; add `--relative` to both `git diff` calls.
- `src/core/scanner.ts`: the git sync path removes `oldPath` of renames; `discoverFiles` canonicalises registered roots and walked directories.
- `tests/legacy-globs.test.ts` (or a new e2e file): rename, nested-repo and symlink e2e tests; speed up the slow tests.
- `tests/git-tracker.test.ts`: unit test for rename parsing and `--relative`.

## Expected outputs

Fix, regression tests, `reports/M0-02-R3.md`.

## Acceptance criteria

1. After `git mv a.ts b.ts` and a commit, `sync` indexes `b.ts` and removes `a.ts` (files and edges), matching `scan --force` (e2e test).
2. In a repo nested inside a larger git repo, `sync` after a change indexes the changed file under the right repo-relative path (e2e test).
3. The scanner's nested-repo check treats a symlink to a registered repo as the same repo (test).
4. legacy-globs tests finish under their timeout on a loaded machine (no single test above 15 s locally).
