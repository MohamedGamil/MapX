# M5-14 — MCP tools mapx_arch_check/_layers/_allowed/_explain/_init and agent templates

## Identification

Milestone: M5; priority: P1; risk: low; estimate min/expected/max: 6/8/10 h; role: MCP and architecture-rules engineer.

## Objective

AI agents get the architecture rules through MCP (AR-19): they can run the check, look up layers and membership, ask before writing an import whether it is allowed (with alternatives), have a decision explained, and get a proposed configuration. Every tool wraps the library functions behind `mapx check` and the `mapx arch` subcommands, so the CLI and MCP give the same answers. The agent templates tell agents to call `mapx_arch_allowed` before adding a cross-module import.

- M5-05 (hard, DONE): `mapx check`, `runArchitecture`, `shownReport`, `exitCode`.
- M5-08 (hard, DONE): `src/arch/introspect.ts` (`layerSummaries`, `layerMembers`, `whichLayers`, `unassignedElements`, `isAllowed`).
- M5-02-R1 (hard, DONE): `mapx_arch_validate_config`; the tool count starts from 34.

## Scope

1. **Five MCP tools** (34 → 39). Each returns JSON by default and caps lists, reporting the totals. A failure is a tool result with `isError: true` and `{ error, exitCode }`, where `exitCode` has its AR-17 meaning: 3 for configuration and usage errors, 4 for a missing or stale index. Failures are never JSON-RPC errors.
   - `mapx_arch_check`: `runArchitecture` with `shownReport` and `exitCode`, as `mapx check --format json`. It takes `view`, `layer`, `rule`, `failOn`, `report*` and `sync`. Two filters exist only on MCP: `file` (a path prefix or glob over finding ends) and `since` (a git ref, through `changedSince`). It adds `exitCode`, `total`, `limit` and `truncated`. Violations are a normal result carrying `exitCode: 1`, not an error.
   - `mapx_arch_layers`: `layerSummaries`; with `layer`, `layerMembers` (`why`, `nested`); with `unassigned: true`, `unassignedElements` (`kind`, `path`). Member lists are capped by `limit`.
   - `mapx_arch_allowed`: `isAllowed`, as `mapx arch allowed --json`. AR-19 `alternatives` are added to the library answer, so the CLI gets them too: the allowed layers that already expose a matching symbol (a supertype of the target, or a symbol whose name the target's name ends with).
   - `mapx_arch_explain`: `whichLayers` for an element (the selector trace). With `layer`, whether each match is in it and through which selector. With `to`, the `isAllowed` rule trace for the dependency.
   - `mapx_arch_init`: a role-based proposal. It maps MapX roles to layers and turns `LAYER_ORDER[archetype]` into "may depend downward" rules (the first two bullets of AR-15 inference), validated with `validateArchitectureText`. It returns the JSONC and writes `.mapx/architecture.jsonc` (or a view) only with `write: true`, and never over an existing file.
2. **One index gate.** `openCurrentIndex` in `src/cli.ts` becomes `indexGate` in `src/arch/index-gate.ts`. `mapx check`, `mapx arch …` and the MCP tools then refuse a missing, unscanned, stale or outdated index in the same way. The CLI's messages are unchanged.
3. **Agent templates.** Every tool list gets the five tools, and the counts become 39. A short "Architecture rules" workflow says: before adding an import across modules, call `mapx_arch_allowed`. The same changes go into `src/agents.stub.md`, README.md, docs/mcp-integration.md, docs/architecture.md and the `mapx serve` banner.
