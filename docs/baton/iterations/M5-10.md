# M5-10 — Capture decorators/attributes and doc tags in symbol metadata (tier 1)

## Objective

Parsers store each symbol's decorators, attributes or annotations and its doc-block tags in `symbols.metadata`, for PHP, TS/JS, Python, Java, Kotlin and C#. The architecture `decorator` and `docTag` selectors evaluate on them.

## Metadata shape (the contract M5-11 and later presets read)

Both keys are present on a symbol only when non-empty; every other symbol's metadata is unchanged.

```ts
metadata.decorators?: Array<{ name: string; args: string | null; written?: string }>
metadata.docTags?:    Array<{ tag: string; value: string }>
```

**`decorators`**, in source order:

| Field | Value |
| --- | --- |
| `name` | The name without its sigil (`@`, `#[`, `[`), arguments or type arguments; qualifiers kept as written with the language's separator: `Controller`, `app.route`, `javax.annotation.Nullable`, `System.Obsolete`, `kotlin.jvm.JvmStatic`. **PHP** names are resolved like class names: through the file's `use` imports and namespace, without a leading `\` (`#[ORM\Entity]` with `use Doctrine\ORM\Mapping as ORM` → `Doctrine\ORM\Mapping\Entity`; `#[\Deprecated]` → `Deprecated`). |
| `args` | The source text between the argument list's parentheses, trimmed, multi-line text kept as written; `''` for `()`; `null` when there is no argument list. Cut at 500 characters with `…`. |
| `written` | PHP only, present when resolution changed the name: the name as written, without a leading `\` (`ORM\Entity`, an alias `Baz`). Added by the review. |

Sources per language:
- PHP: `#[…]` attribute groups, several per group.
- TS/JS: `@x`, `@x(…)` on classes (before or after `export`), methods, fields and accessors. Comments between decorators are passed over.
- Python: `@x` on `def` and `class`.
- Java: `@X` / `@X(…)` in modifiers.
- Kotlin: `@X` / `@X(…)` in modifiers, and each of `@[A B]`.
- C#: `[X]`, `[X(…)]`, several per list. Lists with a target other than the declaration (`return:`, `param:`, `field:` …) are skipped.

Parameter decorators are not symbol decorators and are not stored.

**`docTags`**, in source order:

| Field | Value |
| --- | --- |
| `tag` | `@` plus the tag name as written: `@deprecated`, `@internal`, `@param`, `@Route` (a Doctrine-style PHPDoc annotation is a tag too) |
| `value` | The text after the tag to the next tag or the end of the block, whitespace collapsed to single spaces, trimmed; `''` when none. Cut at 500 characters. |

Sources per language:
- **PHPDoc, JSDoc/TSDoc, Javadoc, KDoc:**
  - Read from the `/** … */` comment immediately before the declaration. Decorators, attributes, annotations and other comments may sit between; code may not.
  - Block tags only: a tag starts a line (after the leading `*`), so inline `{@link X}` is not a tag.
  - Code is never a tag: ```` ``` ```` fences, `<pre>…</pre>`, multi-line `{@code …}`, and everything after `@example` (that tag's value, to the end of the comment).
  - A TS function's overload signatures give their tags to the implementation.
- **C# XML doc:**
  - Read from the run of `///` lines immediately before the declaration; plain comments between are passed over.
  - Each top-level element is a tag named `@<element>` (`<remarks>` → `@remarks`, `<inheritdoc/>` → `@inheritdoc`).
  - A `name` or `cref` attribute starts the value (`<param name="x">the x</param>` → `{tag: '@param', value: 'x the x'}`).
  - `<summary>` is the description, like a JSDoc's leading text, and `<code>` is a sample; neither is a tag.
- **Python docstrings:**
  - Read from the docstring of the `def` or `class`, dedented as `inspect.cleandoc` does.
  - A reStructuredText directive `.. name:: arg` is the tag `@name`, with the directive's argument and indented body as value (`.. deprecated:: 2.0` / `Use Order2.` → `{tag: '@deprecated', value: '2.0 Use Order2.'}`).
  - A line starting with `@tag` (epydoc style, and `@internal`) is a tag as in JSDoc.
  - Literal blocks (indented under a paragraph ending in `::`) and doctest examples (`>>>` to the next blank line) are not tags.

## Selector syntax (architecture configuration)

Both are **symbol-level**, like `name`: on a file element they are inapplicable (no match, and `not` of them no match either). A file joins the layer through its top-level symbols (AR-01).

```jsonc
{ "decorator": "Controller" }                       // name or trailing segments, case-insensitive
{ "decorator": "Doctrine\\ORM\\Mapping\\Entity" }    // a qualified name
{ "decorator": "/^(Get|Post)$/" }                    // /regex/flags on the stored name
{ "docTag": "@deprecated" }                          // the tag; the leading @ is optional
{ "docTag": "@internal", "value": "^billing" }       // and its value matches this regex
```

- **`decorator`** (rule revised by the review). A plain value matches, case-insensitively, when:
  - it equals the stored name, or is a suffix of it on a namespace boundary (`\`, `.`);
  - the same holds for the PHP `written` name;
  - outside PHP, where names are stored as written, the stored name is such a suffix of the value (`System.Obsolete` ↔ `[Obsolete]`).

  In C#, `X` and `XAttribute` match each other. A leading `@`, `\` or `#[` in the value is ignored. `/…/flags` is a regex on the name and the written name (case-sensitive unless flags say otherwise, as everywhere).
- **`docTag`** (+ `value`): the symbol has the tag (compared case-insensitively; `@` optional), and with `value` one occurrence's value matches the regex (case-insensitive unless `/…/flags`). Python: a decorator whose last segment is `deprecated` (`@deprecated`, `@typing_extensions.deprecated("…")`) counts as `@deprecated`, with its arguments as the value (AR-04).
- Overloads that are symbols (one element per qualified name and kind) carry the union of their decorators and tags; TS function overload signatures, which are not symbols, give their doc tags to the implementation.
- Traces read `selectors[0].decorator`, `selectors[1].docTag`.

`schemas/architecture.schema.json`, the loader validation (`src/arch/config.ts`: a `/…/` decorator value must compile) and `docs/architecture-rules.md` say the same.

## Scope

1. `src/parsers/annotations.ts`: `symbolAnnotations(language, node, resolve?)` reads a declaration node's decorators and doc tags from the syntax tree; per-language readers for TS/JS, Python, Java, Kotlin, C#, PHP.
2. `src/parsers/generic-wasm-parser.ts`: merges them into each symbol's metadata (TS, TSX, JS, Python, Java, Kotlin, C#; Vue and Svelte script blocks go through the TS/JS parsers). `src/parsers/languages/php.ts`: the same, with names resolved through the file's `use` table.
3. `src/arch/elements.ts`: symbol elements carry `decorators` and `docTags`.
4. `src/arch/selectors/decorator.ts`, `src/arch/selectors/doc-tag.ts`, and their dispatch in `src/arch/selectors/index.ts` (no longer in `UNSUPPORTED_SELECTORS`). `docTag.ts` exports `hasDocTag(element, tag)` for M5-11.
5. `src/core/extractor-version.ts`: 7 → 8 (metadata changes for unchanged files).

## Out of scope

- Go `// Deprecated:`, Rust `#[…]`/doc attributes, Dart, Swift, Scala, Ruby YARD (§3.7 later tiers): follow-up.
- Internal-marker evaluation (`visibility.internalTags`, native markers): M5-11.
- `deprecated-usage` smell: later M5 work.
- NestJS/FastAPI detectors keep their own decorator parsing (unchanged).
- Resolving TS/Java/Kotlin/C#/Python decorator names through imports: suffix matching covers presets; PHP resolves because Symfony's preset names FQNs.
