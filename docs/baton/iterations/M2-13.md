# M2-13 — Calls inside a one-line PHP class are indexed

## Identification

Milestone: M2; priority: P2; risk: low; estimate min/expected/max: 1/3/6 h; role: parser engineer.

## Objective

`<?php class User { public function name() { return $this->id(); } private function id() { return 1; } }` on one line gives the call edge User::name → User::id, as the same class over several lines does.

## Dependencies

None. Builds on the one-line source-symbol rule of M5-03-R2 (`docs/baton/reports/M5-03-R2.md`).

## Scope

- The cause: the PHP parser (`src/parsers/languages/php.ts`) emits its references with `sourceSymbol: null`, so the scanner attributes each one by line (`innermostByLine`). On one line the class, `name` and `id` have equal spans, the first (the class) wins, and the edge is sourced to `User`.
- The fix, the PHP equivalent of `oneLineSource` in `generic-wasm-parser.ts`: a reference inside a method or function that sits on one line takes that method or function as its source symbol, from the syntax tree (node positions), labelled as the scanner labels it (`Class::method`).
- Check JS, TS, Java and Python (lambdas) for the same problem; fix them if the mechanism is the same, otherwise list them.
- `EXTRACTOR_VERSION` 16 → 17.

## Out of scope

- Multi-line methods: the line rule already picks them.
- The external-reference rows' source (`codeSymbol` in the scanner), which stays line-based (M5-19).

## Implementation plan

- `src/parsers/languages/php.ts`: map each declaration node to its symbol label; a reference's source is the nearest enclosing one-line method or function.
- `src/core/extractor-version.ts`: 17.

## Expected outputs

`tests/php-one-line.test.ts` (e2e), the parser change, `docs/baton/reports/M2-13.md`.

## Acceptance criteria

1. The one-line class above gives the edge User::name → User::id (e2e test); the multi-line form still gives Multi::name → Multi::id.
2. `npm run eval` holds every floor.
