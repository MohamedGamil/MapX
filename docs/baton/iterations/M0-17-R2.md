# M0-17-R2 — Extraction precision: non-callable call targets, C++/C#/Go names, built-in receivers

## Identification

Milestone: M0; priority: P2; risk: medium; estimate min/expected/max: 4/6/9 h; area: remediation. Role: tree-sitter extraction, static analysis, test design.

## Objective

No call edge targets a constant or variable, and qualified names extract correctly.

## Dependencies

M0-17-R1 (hard), M0-01-R1 (hard). Both DONE.

## Scope

Review 2026-10-31 findings (P2, from M0-17-R1 and M0-01-R1):

- **Constants as call targets.** M0-17-R1 added JS/Python `constant` and `variable` symbols. Name-only resolution now links `config()` (a parameter call in `b.js`) to `const config` in `a.js`. Call and instantiation references no longer resolve to a `constant` or `variable` symbol.
- **C++ names.**
  - `template <class T> void Box<T>::f() {}` is scoped `Box<T>`; it should be scoped `Box`.
  - `void ns::K::a() {}` and `void Outer::In::z() {}` make no symbol at all; they should be method `a` in `K` and method `z` in `In`.
- **C# base list.**
  - `class E : IOException` is recorded as implements, because `IOException` matches the `I[A-Z]` interface convention. It should extend IOException.
  - Generic bases keep their arguments (`extends:List<int>`), so they never resolve to `List`.
- **Go.** A qualified embedded struct field (`struct { sync.Mutex }`) makes no extends edge.
- **JS built-in receivers.** `Math.max()`, `Date.now()`, `Array.from()` and `process.exit()` give inferred call edges to user functions named `max`, `now`, `from` and `exit`.
- **DOT.** A file pair is styled by its first edge, so a pair with both a verified and an inferred edge of one type is drawn dashed or solid depending on edge order.
- **Vacuous tests (mutants survived).**
  - The built-in method skip test (`items.map()`) has no user function `map`, so it passes with the skip removed.
  - The DOT test never checks dispatch or implements styles, so a "dispatch dashed" mutant survives.

## Out of scope

- Generic bases in Java, Kotlin and TypeScript `extends` clauses, which capture only plain type identifiers. Not named by the review.
- Local function-valued declarators (`const f = () => 1` inside a function) becoming function symbols. This predates M0-17-R1.
- Receiver type inference for member calls (F01 keeps them inferred).

## Implementation plan

- `src/core/scanner.ts` (minimal, localized): the symbol index carries each symbol's kind. `resolveSymbolToFile` takes an optional "callable only" flag that drops `constant` and `variable` candidates. `resolveReferencesWithMap` sets it for `call` and `instantiation` references. Other lanes are editing this file, so nothing else changes there.
- `queries/cpp/symbols.scm`: patterns for nested `qualified_identifier` names, two and three levels deep.
- `src/parsers/generic-wasm-parser.ts`:
  - C++ out-of-line scope is the innermost qualifier, with template arguments dropped;
  - C# base-list targets drop generic arguments; `*Exception`, `*Attribute` and `*EventArgs` names are classes, not interfaces;
  - JS member calls whose receiver is a built-in global (`Math`, `Date`, `Array`, `Object`, `JSON`, `Promise`, `Reflect`, `process`, …) are skipped.
- `queries/go/references.scm`: an unnamed `field_declaration` with a `qualified_type` is extends.
- `src/exporters/dot-exporter.ts`: a file pair and edge type is dashed only when every edge behind it is inferred.
- `tests/legacy-language-accuracy.test.ts`: per-language parser cases (C++, C#, Go).
- `tests/legacy-verifiability.test.ts`: end-to-end workspace (real `init` and `scan`). It asserts exact edge identities (source file, source symbol, target symbol, target file) for the constant, built-in and DOT cases.

## Acceptance criteria

1. A parameter call `config()` makes no edge to a constant named config. Test: `legacy-verifiability` "call references never resolve to constants or variables".
2. C++ `Box<T>::f` is scoped Box; `ns::K::a` yields method a in K. Test: `legacy-language-accuracy` "C++: template and nested qualifiers".
3. C# `class E : IOException` extends IOException. Test: `legacy-language-accuracy` "C#: IOException and generic bases".
4. `Math.max()` makes no edge to a user function max; the built-in skip and edge-style tests fail when their code is removed. Tests: `legacy-verifiability` built-in receiver, built-in method and DOT tests, each mutation-checked.
