# M0-03-R3 — metrics/edges output shapes and option validation per F02/F04

## Identification

Milestone: M0; priority: P2; risk: medium; estimate min/expected/max: 3/5/8 h; role: CLI/MCP engineer.

## Objective

`mapx metrics` / `mapx_metrics` and `mapx edges <file>` / `mapx_edges` return the output contract the owner chose in D012 (F02/F04 structures with camelCase keys), and reject invalid option values instead of silently ignoring them.

## Dependencies

M0-03-R2 (hard, DONE but disputed by review 2026-10-31). Decision D012 (owner, 2026-10-31) settles the shape question.

## Scope

- **Contracts (D012):**
  - metrics JSON: `{ dir, generatedAt, summary: { files, edges, density }, files: [{ path, language, inDegree, outDegree, totalDegree, instability, pagerank }] }`.
  - metrics text: F02 header (`Metrics for:`, `Files | Edges | Graph density`), ranked `RANK FILE IN OUT TOTAL INSTABILITY` table, instability legend. `--top` default 20, `--top 0` = all, `--exclude <glob,...>`.
  - edges `<file>` JSON: `{ file, direction, incoming: [{ sourceFile, type, sourceSymbol, targetSymbol, verifiability, weight, line }], outgoing: [{ targetFile, targetRepo, type, sourceSymbol, targetSymbol, verifiability, weight, line }] }`. Without a file the flat list stays.
  - edges `<file>` text: `Edges for:`, `Incoming (n)` / `Outgoing (n)` with ←/→ arrows, a clear message when there are no edges.
- Builders and renderers live in `src/core/metrics.ts` and `src/core/edge-view.ts` so the CLI and MCP print the same thing.
- Validation: `--top abc|-1`, `--format yaml`, `--direction` without a file exit non-zero with a message (MCP returns an `isError` result).
- `store.queryEdges` accepts a type array; `mapx_edges.type` is an array in the schema (a comma string still works).
- Consumers: MCP handlers, dashboard `/api/metrics` `fileMetrics`, docs (`docs/cli-reference.md`, `docs/mcp-integration.md`, README, agents stub), mocked unit tests.

## Out of scope

- M0-11-R2, M0-05-R4, M0-10-R2 (same lane, also touch cli.ts / mcp.ts).
- Cross-repo incoming edges (edges stored under another repo that target this file); `queryEdges` stays per repo.
- Recomputing PageRank under `--verified-only` / `--exclude` (PageRank stays the graph's file score).
