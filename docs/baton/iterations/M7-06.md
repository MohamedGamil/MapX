# M7-06 — Site quality: SEO, accessibility, links and size budgets

## Identification

Milestone: M7; priority: P1; risk: low; estimate min/expected/max: 4/6/9 h; role: front-end quality.

## Objective

The built site has a sitemap, robots.txt, canonical URLs, social-sharing tags with a real 1200 x 630 card, a working 404 page, no dead links or orphan pages, no serious accessibility violations on its main pages, and a size budget.

## Dependencies

M7-02 and M7-03 (hard, DONE). The About page (M7-04) was cancelled.

## Decisions

- **Sitemap:** VitePress's built-in `sitemap` option, with the hostname `SITE_URL` + base. Page URLs come from the build, so the sitemap cannot list a page that does not exist; the test cross-checks it against the built files. The 404 page is not listed.
- **Canonical and Open Graph from one function.** The `transformHead` hook of M7-03 gains `link rel=canonical`, `og:image:width`, `og:image:height`, `og:image:alt` and `twitter:card=summary_large_image`; `og:url` and canonical are the same string by construction.
- **robots.txt is written by `buildEnd`** so its `Sitemap:` line carries the configured origin and base. Crawlers read robots.txt only at a host root, so under `https://mohamedgamil.github.io/mapx/` it has no effect; it is correct for a custom domain or `SITE_BASE=/`.
- **The card is generated, committed output.** `scripts/site/gen-og-card.ts` draws an HTML card (slate background, logo, name, tagline; system fonts) in headless Chromium and writes `site/public/og-card.png`. The build never needs Chromium.
- **One crawler for the whole site** (`tests/helpers/site-crawl.ts`): breadth-first from `index.html`, resolving links as a browser does, checking files and fragment ids, and listing built pages nothing links to. It has its own unit test on a fixture folder.
- **Accessibility:** axe-core (already a dev dependency) runs in the site Playwright config on the home page, a guide and the docs index, in both colour schemes, with serious and critical violations failing the test. Fixes go in `brand.css` and the components, never in the checks.
- **Budgets measured first.** `tests/site/budgets.json` holds the byte budgets. They are set to the value measured by this task plus a stated margin, and are never raised to make a test pass; a rise needs a reason in a report.

## Scope

- `site/.vitepress/config.ts` (sitemap, head tags, `buildEnd` robots.txt), `scripts/site/gen-og-card.ts`, `site/public/og-card.png`.
- Tests: `tests/site-seo.test.ts`, `tests/site-links.test.ts` with `tests/helpers/site-crawl.ts`, `tests/site/quality.spec.ts`, `tests/site/budgets.json`.
- Fixes for whatever the checks find (contrast, landmarks, names).

## Out of scope

- Dashboard screenshots: **M7-07**. Milestone acceptance: **M7-98**.
- Lighthouse scores (needs a network and a different tool). The budgets are bytes, not scores.
- Splitting the landing component out of the main bundle: decided from the measured budget; done here only if the budget needs it.
