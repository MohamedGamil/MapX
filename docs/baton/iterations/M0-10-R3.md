# M0-10-R3 — Workspaces: F18 fields, duplicate config cleanup, cross-repo references after workspaces add

## Identification

Milestone: M0; priority: P2; risk: low; estimate min/expected/max: 3h/5h/7h; role: CLI/MCP engineer.

## Objective

`mapx_workspaces` returns every F18 field, duplicate repo entries already in a config are collapsed, and a plain `scan --all` resolves references into a repo that was not indexed when the referring repo was last parsed.

## Dependencies

M0-10-R2 (hard, DONE). Source of criterion 3: M0-03-R4's finding. No approval gate.

## Scope

1. **F18 fields.** Each `mapx_workspaces` list entry carries `path` (absolute), `relativePath` (as registered, relative to the workspace root), `isRegistered` and `isInitialised`. Uninitialised submodules that are not registered are listed too, with `isRegistered: false`, `isInitialised: false`, as the CLI table does. `isInitialised`: the folder exists and, for a submodule, has its own `.git`.
2. **Duplicate cleanup.** `Config.load` collapses repo entries whose folders are the same (canonical path, so symlinks count), keeps the first, and saves the config. The CLI and MCP loaders print a message on stderr naming the dropped entry and the one kept, and delete the dropped entry's stored data when its name differs. `workspaces sync` loads through the same path.
3. **Cross-repo references after `workspaces add`.** The scanner records, per repo, which other repos' files were visible when the repo was parsed (`meta resolution_repos:<repo>`). When a later scan (full or incremental) sees a repo that was not visible then, it re-parses the repo once, as it already does when filters change. A repo indexed before this change with other repos present is re-parsed once.
4. Docs: `docs/mcp-integration.md`, `docs/cli-reference.md`. Drop the `--force` workaround from the M0-03-R4 test.

## Out of scope

- Re-parsing other repos' unchanged files when files are *added* to an already visible repo (the same within-repo limitation as today).
- `discovered` keeps its `isInitialized` spelling (an existing field, not an F18 RepoSummary).

## Implementation plan

- `src/core/config.ts`: duplicate collapse in `load`, `collapsedRepos` accessor.
- `src/core/workspace-summary.ts`: `applyCollapsedRepos(config, store)` (delete data, return messages); F18 fields helper.
- `src/cli.ts`, `src/mcp.ts`: call it from the loaders; `mapx_workspaces` entries.
- `src/core/scanner.ts`: `resolution_repos` meta in `_scanFullForRepo` and `_scanIncrementalForRepo`.
- Tests in `tests/legacy-workspaces.test.ts`; `tests/legacy-metrics-edges.test.ts` without `--force`.
