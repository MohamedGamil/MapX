# M5-01 — Architecture-rules fixture set and scorer (PHP, TS, Python, Go, cross-repo)

## Identification

Milestone: M5; priority: P1; risk: low; estimate min/expected/max: 10/12/16 h; area: arch, fixtures, eval.
Sources: `docs/research/deptrac/02-abstract-feature-model.md` AR-08 (evaluation order), AR-09 (finding kinds), AR-10 (baseline); `docs/research/deptrac/01-deptrac-capabilities.md` §4–5; D004 (fixtures before fixes), D013.

## Objective

A labelled synthetic fixture for architecture rules in the four tier-1 languages plus a two-repo workspace, each with a `.mapx/architecture.jsonc`, and a scorer that measures recall and precision per finding kind. It records the 0.0 baseline before any engine exists, so every later M5 task raises a measured floor.

## Dependencies

None. M5-03 (fixture), M5-10 (fixture) and M5-12 (fixture) consume it.

## Scope

1. **`tests/fixtures/arch-rules/`**, one small app per language, synthetic only (no private or pilot code):
   - `php/` (namespaces `App\Domain`, `App\Application`, `App\Infrastructure`, `App\Controller`), `ts/`, `python/`, `go/`;
   - `workspace/` with `frontend/` (TS, `fetch` calls) and `backend/` (PHP routes), registered as two repos, so the `http` edge from frontend to a `PublicApi` layer can be scored.
2. **One `.mapx/architecture.jsonc` per app** written against the AR-11 schema (M5-02 formalises it; the fixture is the schema's first consumer). Each app declares the same four layers using the selectors it can (`path` everywhere; `name` where namespaces exist; `role` and `cluster` in at least one app) and this policy:
   - `Controller → Application`, `Application → +Domain` (transitive), `Infrastructure → Domain`;
   - one `+` cycle in a deliberately broken copy (`php-broken-cycle/`) so the config error can be scored;
   - one `private: true` layer and one `@internal`-tagged element (PHP docblock, TS JSDoc, Python docstring tag, Go comment) for `private-layer` and `internal-element`;
   - a file matched by two layers (`multi-layer` warning) and an empty layer (`empty-layer` warning).
3. **`baseline.json`** in the PHP app with one entry that matches a real violation (→ `skipped`) and one stale entry (→ `error`).
4. **`expected-findings.json`:** `{ id, app, language, rule, kind, from: { file, symbol? }, to: { file, symbol? }, edgeType, note }` for every expected finding, plus negatives (`kind: "allowed"` and `kind: "none"` for same-layer edges). Keys are the fingerprint inputs of AR-09 (rule, from, to, edge type), never line numbers.
5. **`scripts/eval/score-arch.ts`:** copies the fixture to a temp dir, runs the real `mapx init` + `scan` per app (the workspace through `workspaces`), reads the findings report at `.mapx/architecture-report.json` (missing file = no findings, recall 0, not an error), and prints per-kind recall and precision as JSON with `--json`, `--min-recall`, `--min-precision` and `--app <name>` flags. Negatives reported as findings count as false positives.
6. **`tests/arch-fixture.test.ts`:** every expected entry points at an existing file and, when given, an existing symbol name; every rule in the AR-08 chain appears at least twice per language; scorer unit tests (exact rule and kind matching, negatives as false positives, missing report = recall 0); a real-scan floor test asserting the current baseline.

## Out of scope

- The engine, config loader, selectors, evaluator and CLI (M5-02 … M5-06).
- Decorator and doc-tag capture in parsers (M5-10): the `@internal` rows are expected to be *missed* at this revision and are labelled anyway.
- External, builtin and ambient references (M5-12): no `package`/`builtin` rows yet; M5-12's iterations extend the fixture.
- Java, C#, Kotlin apps (M5-09 adds hierarchy rows for Java).

## Implementation plan

New files only: `tests/fixtures/arch-rules/**`, `scripts/eval/score-arch.ts`, `tests/arch-fixture.test.ts`. No `src/` change, so the blast radius is nil (`mapx impact` not applicable). The report path `.mapx/architecture-report.json` is the contract M5-05 writes; record it in D013's successor if M5-02 changes it.

## Expected outputs

The fixture (≥ 5 apps), `expected-findings.json` (≥ 60 rows), `baseline.json`, `scripts/eval/score-arch.ts`, `tests/arch-fixture.test.ts`, and `docs/baton/reports/M5-01.md` with the 0.0 baseline per kind.

## Acceptance criteria

1. The fixture covers every rule in the AR-08 chain at least twice per tier-1 language (PHP, TS, Python, Go): `disallowed-layer`, `internal-element`, `private-layer`, `uncovered`, same-layer (no finding) and allowed; asserted by `tests/arch-fixture.test.ts`.
2. It includes a `+` transitive rule, a `+` cycle (config error), a multi-layer element (warning), an empty layer (warning), and a baseline with one matched and one stale entry (skipped + error); each has an `expected-findings.json` row.
3. The two-repo workspace case has a frontend → backend `http` edge allowed only to a `PublicApi` layer, with one allowed and one violating call.
4. `npx tsx scripts/eval/score-arch.ts tests/fixtures/arch-rules --json` exits 0 and reports recall 0 for every kind at this revision; the baseline is recorded in `reports/M5-01.md`.
5. Scorer unit tests: a reported finding on a negative row counts as a false positive; a missing report yields recall 0, not an error; `kind` and `rule` match exactly.
