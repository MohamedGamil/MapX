# M3-03 — Options API member resolution

## Identification

Milestone: M3; priority: P1; risk: medium; estimate min/expected/max: 8/12/16 h; role: parser / resolution engineer (Vue).
Sources: `docs/reports/2026-10-30-laravel-vue-coverage-findings.md` §3 item 11 and §4 item 9; edge contract rule 6 in `docs/baton/iterations/M3-01.md`.

## Objective

`this.x()` inside a Vue Options API component resolves to the component's own member, then to a member of a mixin listed in that component's own `mixins: []` (in the mixin's file), and never to another file merely because that file defines `x`.

## Dependencies

- M3-01 (fixture): `tests/fixtures/vue-sfc/` and `scripts/eval/score-edges.ts` are the yardstick. DONE.
- Parallel lanes: M3-02 (template pass, component symbol) and M3-07 (nested package.json detection). Write scope kept apart: new module `src/parsers/languages/vue-options.ts`, small hooks in `vue.ts` and `scanner.ts`.

## Scope

Contract rule 6, without its map-helper step:

1. **Parser (`vue-options.ts`).** For each `<script>` block, find the Options API object (`export default { … }`, `export default defineComponent({ … })` / `Vue.extend({ … })`, or an exported identifier bound to one). Record:
   - own members: the keys of `methods` and `computed`, and top-level function members (lifecycle hooks, `data`, `setup`). `watch` keys are not members: a watched name is a prop or data field, never a method reachable through `this`.
   - mixins: the identifiers in `mixins: [ … ]`, each with the module it is imported from (or the same file for a local constant), plus `extends: X` as the lowest-priority mixin.
   - map-helper names: local names spread from `mapActions` / `mapGetters` / `mapState` / `mapMutations` / `mapWritableState`, with helper, namespace and remote name, so M3-05 can resolve them.
   - every `this.x()` call inside the options object.
   The matching `call` references get a typed `vueThis` scope (`own`, `mixins`, `mapped`).
2. **Scanner hook.** A reference with a `vueThis` scope is resolved by `resolveThisMember` (in `vue-options.ts`) through ordered steps: own member (the SFC), mixins (latest listed first, as Vue's merge lets a later mixin override an earlier one; a mixin counts only if its resolved file defines `x`), map helper. With no hit there is no edge. The map-helper step keeps today's name lookup until M3-05 replaces it, so `vuex-map-helpers` does not regress.

## Out of scope

- Vuex / Pinia map-helper namespace resolution (rule 6's third step, rules 7–8): M3-05. This task only records the mapped names and keeps the old lookup for them.
- Template calls to mixin members (rule 4): M3-02. `vueThisScope` is exported so the template pass can attach the same scope.
- Global mixins (`Vue.mixin` / `app.mixin`), mixins of mixins, mixins re-exported through a barrel, class components: unresolved (no edge), recorded as limitations.
