# M5-23 — External references: Go modules package attribution and builtins

## Identification

Milestone: M5; priority: P2; risk: medium; estimate min/expected/max: 3/4/7 h; role: scanner and package manifests.

## Objective

Every Go row of the `external_refs` view (M5-19) says what it belongs to: the module of the build list that provides the imported package (`golang.org/x/sys` for `golang.org/x/sys/unix`), or the standard library (`fmt`, `net/http`) as a built-in; whether the file's go.mod requires that module directly or marks it `// indirect` (transitive); whether only test code uses it (dev); and whether go.sum backed the answer (`lock`) or go.mod alone did (`manifest`). ## Scope

- **Columns filled** for Go candidates decided external, in the end-of-run decision pass:
  - `origin`: `builtin` for a standard-library package; `ambient` for cgo's pseudo-package `C`; else `package`;
  - `package`: the import path for a built-in (`net/http`; standard-library paths have no dot in their first element, module paths do), `C` for cgo, else the module path, or null when no module of the build list provides the import;
  - `direct`: 1 when the file's go.mod requires the module without `// indirect`; 0 when it is marked `// indirect`, or only go.sum or another go.work module holds it, or (package null) a complete go.sum shows it is not in the build list; null for a built-in and when unknown;
  - `dev`: see the decision below; null for a built-in and an unknown package;
  - `attribution`: `lock` when a readable go.sum holds the module, `manifest` otherwise (criterion 2's flag); null for a built-in.
- **Module of an import**: the longest module path of the build list (go.mod's requirements, go.sum's modules, a go.work's other modules) that is the import path or a prefix at a `/`. A major-version element right after a module path (`/v2`) names another module, never a folder of v1. Distinct module paths cannot tie at equal length; an import that two nested modules could provide goes to the longer path, as Go resolves it once a package moved to a nested module.
- **The file's module**: the nearest go.mod from the file up to its repo's root. A go.mod or go.sum that is present but unreadable (a folder, no permission, corrupt) ends the walk: never a parent module's files.
- **Stale go.sum**: go.mod requires a module (not replaced by a local directory) whose hash go.sum (or the replacement's) lacks. That module is flagged `manifest`, and an import no module provides is unknown (`direct` null, `manifest`), never "not in the build list".
- **Directives**: `require` (blocks, single lines, `// indirect`); `replace` (the required path stays the package; go.sum holds the replacement's hash; a local directory needs none and, inside the workspace, makes the module the workspace's: no row, M5-25-R1); `exclude`, `retract`, `toolchain`, `godebug`, `ignore` change no module path and are skipped; `tool` (Go 1.24) is parsed, but a tool is a main package no code imports, so it gives no row; go.work `use` and `replace`, and go.work.sum.
- **Standard library**: a generated static list (`src/core/manifests/go-stdlib.ts`): the union of `go list std` of Go 1.22 to 1.27, without `vendor/` and `internal` packages, generated with the official `golang:<v>-alpine` Docker images by `scripts/gen-go-stdlib.sh`. A dotless path a go.mod requires (through a `replace`) is that module. Any other dotless path the list lacks is unknown, not guessed.
- **Decision: dev for Go.** Go has no dev requirements. A module is dev-only (`dev` 1) when every reference to it from the Go module (the files under the same go.mod) is in a `_test.go` file, and production (`dev` 0) otherwise. This is computed in the decision pass over all Go rows (stored or attributed now), so a file added or removed changes it with no input file changed. The `tool` directive does not make a module dev (no code imports a tool).
- **Inputs, caching, staleness, sync parity**: go.mod, go.sum, go.work and go.work.sum reads join M5-20's recorded inputs, so the skip, the stale gate and sync = `scan --force` cover them.
- **Never a crash**: the workspace reader returns null for a file it cannot read (a go.mod that is a folder made the M5-19 Go decision throw).
- **Fixture**: `tests/fixtures/arch-rules/go` gains requirements in go.mod (direct and `// indirect`), the go.sum `go mod tidy` wrote for those real modules, `infrastructure/system_probe.go` (a transitive import, an import in no module, a built-in, cgo's `C`) and `infrastructure/http_gateway_test.go` (test-only modules). Every Go row of `expected-externals.json` is labelled.

- Go call resolution in the scanner (`resolveSymbolToFile`): the defects lane.
