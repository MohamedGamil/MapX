# M5-20 — External references: npm package attribution and builtins

## Identification

Milestone: M5; priority: P2; risk: medium; estimate min/expected/max: 5/6/9 h; role: scanner and package manifests.

## Objective

Every npm row of the `external_refs` view (M5-19) says what it belongs to: the package (`pg`, `@acme/logging` for `@acme/logging/core`, `lodash` for `lodash/get`) or the Node built-in module (`node:fs` for `fs`, `node:fs` and `fs/promises`); whether the package is a direct dependency of the importing file's manifests or reaches it only through the lockfile (transitive); whether it is a dev-only dependency; and whether a lockfile backed the attribution (`lock`) or only the manifests did (`manifest`). Gap G9 of `docs/research/deptrac/03-mapx-gap-and-integration.md` for npm; the data the AR-04 `package` and `builtin` selectors (M5-24) read. Decomposed from epic M5-12 (D019).

## Dependencies

M5-19 (hard): the candidates table, its nullable `package`, `origin`, `direct`, `dev` and `attribution` columns, and the decision pass at the end of every scan and sync. M5-01 (fixture): `tests/fixtures/arch-rules`. Both DONE. No approval gate.

## Scope

- **Columns filled** for npm candidates decided external, by the end-of-run decision pass (never at parse time):
  - `origin`: `builtin` for a Node built-in module, else `package`;
  - `package`: `node:<module>` for a built-in (`fs`, `node:fs`, `fs/promises` and `node:fs/promises` all give `node:fs`), else the package name of the specifier (`@scope/pkg/sub/path` → `@scope/pkg`, `lodash/get` → `lodash`);
  - `direct`: 1 when a `package.json` between the file and its own repo's root (never above it, never another repo: review P1) lists the package in `dependencies`, `devDependencies`, `peerDependencies` or `optionalDependencies`, else 0; null for a built-in;
  - `dev`: for a direct package, 1 when the nearest manifest that lists it lists it only in `devDependencies`; for a transitive one, from the lockfile (dev-only in the dependency tree); null when unknown (no lockfile, or a package no lockfile holds) and for a built-in;
  - `attribution`: `lock` when a lockfile was read for the file, `manifest` when none exists or none is readable (the flag of criterion 2); null for a built-in.
- **Built-ins:** a static list, the union of Node 20 … 26 (`builtinModules`, with the `node:`-only modules `node:test`, `node:test/reporters`, `node:sqlite`, `node:sea`, `node:ffi`). Every `node:` specifier is a built-in; without the prefix, only exact names of the list (`fs`, `fs/promises`, `path/posix`), never `test` or `sqlite` (npm packages). No dependency on the running Node.
- **Lockfiles** (the nearest folder from the file up that holds one): `npm-shrinkwrap.json` and `package-lock.json` (v1 tree, v2/v3 `packages`, with `dev` flags), `pnpm-lock.yaml` (v5, v6, v9: importers and the package graph), `yarn.lock` (v1 and Berry: the package graph, rooted at the workspace's manifests). Read only when a transitive or dev answer needs it, never `node_modules`, never the network.
- **Sync parity:** manifests, lockfiles and the file set are read again by every completed run's decision pass, so a sync equals `scan --force` when `package.json` or a lockfile changes, appears or goes. `node_modules` is not read, so its changes cannot matter.
- **Fixture:** `tests/fixtures/arch-rules/ts` gains dependencies in its `package.json`, a `package-lock.json` and one file of further npm references (transitive prod and dev, a deep import, built-ins with and without prefix, an undeclared package, an npm package named like a `node:`-only built-in). Every npm row of `expected-externals.json` is labelled with `package`, `origin`, `direct`, `dev` and `attribution`.
- **Scorer:** `scripts/eval/score-arch.ts` also scores the attribution of the labelled external rows per ecosystem (recall, precision, misses and extras), so M5-21 … M5-23 add their rows to the same report.

## Out of scope

- Composer, pip/Poetry/uv and Go attribution: M5-21, M5-22, M5-23.
- Ambient globals (`process.env`, `window`, `fetch`): no reference is extracted for a global today; capturing them is parser work that would add candidates (and an extractor bump) beyond this task's criteria. Not in M5-20 (assigned elsewhere by the integration owner).
- Selectors over the attribution and the smells it enables (`undeclared-dependency`, `dev-dependency-in-prod`): M5-24.
- `@types/*`-only declarations, Bun's `bun.lock`, package.json `imports`/`exports` maps of external packages.

## Implementation plan

- `src/core/manifests/npm.ts` (new): Node built-ins, package name of a specifier, the three lockfile readers (to one name graph with dev flags), and `NpmAttributor`, which answers per file and specifier with caches for one decision pass.
- `src/core/external-refs.ts`: the `ExternalAttribution` type.
- `src/core/store.ts`: `getExternalCandidates` returns the attribution columns; `setExternalDecisions` writes them with the decision.
- `src/core/scanner.ts`: `decideExternalRefs` attributes every npm row decided external and writes the rows whose decision or attribution changed.
- `scripts/eval/score-arch.ts`: externals attribution score.
- Tests in `tests/external-refs.test.ts`: fixture labels, each lockfile format, missing and unreadable lockfiles, sync = force when manifests and lockfiles change, built-in list completeness against the running Node.

## Expected outputs

`src/core/manifests/npm.ts`, the changes above, fixture files and labels, `docs/baton/reports/M5-20.md`.

## Acceptance criteria

1. npm fixture rows in `tests/fixtures/arch-rules` (direct, transitive, dev-only, builtin) reach recall and precision 1.0 in score-arch (fixture labels): `npx tsx scripts/eval/score-arch.ts tests/fixtures/arch-rules --json` reports `externals.npm` recall 1 and precision 1; the e2e test compares every row's attribution with its label.
2. A missing or unreadable npm lockfile gives direct attribution from the manifest only, flagged (`attribution = 'manifest'`), never a crash: e2e tests with no lockfile, a corrupt `package-lock.json`, a corrupt `pnpm-lock.yaml` and a lockfile that is a folder.

Also held: MapX's self-scan edges unchanged; the existing score-arch kinds unchanged; sync = `scan --force` on the git and hash paths when a manifest or lockfile changes.
