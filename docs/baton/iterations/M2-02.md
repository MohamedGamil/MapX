# M2-02 — Vue 2.7 and Vue 3 HTTP client fixture with labels

## Identification

Milestone: M2; priority: P1; risk: medium; estimate min/expected/max: 5/8/12 h; area: quality, http.
Sources: `docs/reports/2026-10-30-laravel-vue-coverage-findings.md` §3 item 12, §4 items 12–14 and 18; D008.

## Objective

Synthetic Vue 2.7 and Vue 3 front ends that use every HTTP client pattern in report item 12, labelled against the M1 Laravel fixture's routes, plus a scorer that measures call-site recall, pairing recall and pairing precision.

## Dependencies

M1-01 (fixture): the backend is `tests/fixtures/laravel-routes`, reused unchanged.

## Scope

1. **Contract (D008):** the `HttpCallRecord` type and the `.mapx/http-calls.json` file, defined in the scorer.
2. **`tests/fixtures/vue-http/`:**
   - `vue2/`: Options API SFCs plus `.js` services, `.env` with `VUE_APP_ROOT_API`, and an `Api()` factory around `axios.create`;
   - `vue3/`: `<script setup>` SFCs plus `.ts` services, `.env` with `VITE_API_URL`, an `axios.create` instance, `fetch`, and a configured receiver.
   - Patterns:
     - direct `axios.get`, `fetch`, an `axios.create` instance;
     - an `Api()` factory and an alias `const api = Api()`;
     - a file-local and an imported constant, and a template literal;
     - a URL argument on the next line, and a conditional URL (one label per branch);
     - an env base URL, and a configured receiver (`apiService`);
     - a call to an unserved endpoint, a call to an overridden route (pairs with the winner), and a call to an unmounted route (unmatched).
3. **`labels.json`:** one label per expected call site, `{ id, pattern, file, method, url, route: "METHOD /path" | null }`. At least 30 labels.
4. **`scripts/eval/score-http.ts`:**
   - builds a temp workspace with `backend/` = the Laravel fixture and `frontend-vue2/` and `frontend-vue3/` = the Vue apps (parent-folder layout, relying on M1-08 nested Laravel detection);
   - runs the real `mapx init` + `scan`, reads `.mapx/http-calls.json` (a missing file means no calls);
   - scores per pattern: call sites found, URLs resolved, pairs correct, unmatched correct, wrong pairs;
   - totals: call-site recall, pairing recall and pairing precision;
   - flags: `--json`, `--min-recall`, `--min-precision`.
5. **`tests/http-pairing-fixture.test.ts`:** label well-formedness, that every non-null label route exists in the Laravel fixture labels (live), scorer unit tests, and a real-scan floor test.

## Out of scope

- Extracting call sites (M2-03), resolving URLs (M2-04, M2-05) and pairing (M2-06).
- Vuex `services[payload.service](...)` dispatch-by-name: it is dynamic and not labellable without runtime data, so it is recorded as a known limitation.
- `postMessage` (M4-02).

## Implementation plan

New files only: `tests/fixtures/vue-http/**`, `scripts/eval/score-http.ts`, `tests/http-pairing-fixture.test.ts`. No `src/` change, so the blast radius is nil.

## Expected outputs

The fixture, labels, scorer and test, plus `docs/baton/reports/M2-02.md` with the 0.3.5 baseline.

## Acceptance criteria

1. `labels.json` has at least 30 labels and covers all 13 patterns listed above, including at least 2 `route: null` labels (unserved, unmounted).
2. Every non-null label route matches a live (non-negative) label in `tests/fixtures/laravel-routes/labels.json`, asserted by the test.
3. `npx tsx scripts/eval/score-http.ts tests/fixtures/vue-http --json` exits 0 and reports call-site recall 0 at this revision; the baseline is recorded.
4. Scorer unit tests: a reported record pairing a `null` label counts as a wrong pair; `{id}` ≡ `{}` in URLs; a missing `http-calls.json` yields recall 0, not an error.

## Verification

- `npx tsx scripts/eval/score-http.ts tests/fixtures/vue-http --json`
- `npm run check` (baseline)
