# M0-05-R3 — Hook edges honour declared confidence (verifiability)

## Identification

Milestone: M0; priority: P2; risk: low; estimate min/expected/max: 1/3/5 h; role: scanner (framework hooks, F01 verifiability).

## Objective

A framework hook edge is stored `verified` when its detector declares it (`metadata.confidence = 'declared'`), as route edges already are, so `metrics --verified-only` keeps declared middleware edges.

## Dependencies

M0-05-R2 (hard), DONE.

## Scope

- **Hook edge verifiability (P2, found in M0-05-R2).** The scanner wrote every hook edge with `verifiability: 'inferred'`, ignoring the detector's declared confidence. A Laravel Kernel `$routeMiddleware` alias → middleware edge was therefore inferred, while the route file → middleware edge added in M0-05-R2 was verified. Hook edges now follow the rule route edges use: `declared` → `verified`, anything else (absent, `inferred`, numeric) → `inferred`. The stored `confidence` metadata is unchanged.

## Out of scope

- Expanding middleware groups (`web`) on routes: a separate M0-05-R2 finding, not this task.
- Changing which detectors declare confidence. Only Laravel declares hooks today (Kernel aliases, groups, service providers); NestJS, Symfony and the rest stay inferred.

## Implementation plan

- `src/core/scanner.ts`: compute the hook edge's verifiability from `hook.metadata.confidence` and use it for both the stored edge and the in-memory graph edge.
- `tests/legacy-hook-verifiability.test.ts` (new, e2e): a temp workspace with a Laravel Kernel alias and a NestJS `@UseGuards` class guard; real `init` + `scan`; assert stored verifiability per edge, and `metrics --verified-only --format json` degrees for the Kernel file.

Fix, regression test, `reports/M0-05-R3.md`.
