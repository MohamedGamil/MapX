# M2-08 — Calls resolve through the file's own imports before name lookup

## Identification

Milestone: M2; priority: P1; risk: medium; estimate min/expected/max: 5/8/12 h; role: resolution.

## Objective

A call or instantiation of a name the file imports from a project module links to that module's declaration, following re-exports. It never links to another file's same-named symbol. Names the file does not import keep name lookup.

## Dependencies

All are DONE: the M4 tasks (D019), M0-17-R4 and M0-02-R7. Sources: the `M0-17-R4`, `M0-02-R7` and `M3-11-R1` reports (reviewers K, L and O, pre-existing finding).

## Current behaviour (`develop@e1d5da0`)

`resolveSymbolToFile` picks, among every file declaring the name, the caller's own file, then the nearest by directory, then the first by path. The file's imports are used only to skip calls on npm-package bindings (M0-17-R4). So `import { create } from '../lib/utils'; create()` links a `create` in the caller's own folder. Python `from utils import create` likewise links an alphabetically earlier `aaa.py#create`.

## Scope

**Per-file import bindings,** read from the file's text per resolution phase.

- **JS/TS and the `<script>` of `.vue`/`.svelte` files.**
  - The forms read:
    - `import { a, b as c } from 's'`;
    - `import d from 's'` (the default export);
    - `import * as ns from 's'`;
    - `const { a, b: c } = require('s')`;
    - `const m = require('s')`.
  - Only specifiers that resolve to a project file (`resolveImportPath`) bind.
- **Python.**
  - The forms read:
    - `from m import a, b as c`, including a parenthesised multi-line list;
    - `from m import sub`, where `sub` is a submodule, which binds the module;
    - `import m.n as x`;
    - `import m.n`.
  - Modules are resolved with the Python import resolver, relative imports included.

**Resolution.** For a call or instantiation:

| Language | Call form | How it is resolved |
| --- | --- | --- |
| JS/TS | without a receiver | the named or default binding of its name |
| JS/TS | with a receiver (`ns.create()`) | the namespace binding of the receiver |
| Python | `x.create()` or `pkg.mod.f()` | the dotted receiver, read from the call's source line, if it is a module binding |
| Python | bare call | the named binding of its name |

The declaration is then searched in the bound file:
1. a top-level symbol with the exported name in the symbol index;
2. otherwise the re-exports, to depth 5:
   - JS: `export { a [as b] } from 's'`, `export * from 's'`, and `export { a }` of a name the file imports;
   - Python: a name an `__init__.py` imports.

The edge's target symbol is the declared name, so `make()` imported as `create as make` targets `create`. When the import's module or export cannot be found, the reference keeps the old name lookup, so nothing regresses into fewer edges.

## Out of scope

- Calls on objects (`self.x()`, `this.x()`, `obj.method()`): a receiver that is not a module binding keeps the existing rules. Type-directed method resolution is not planned.
- Other languages' import forms (Go, Java, PHP `use function`, Ruby): their own resolvers already handle module references, and call targets there are out of this task.

## Acceptance criteria

1. **JS/TS** (`tests/import-bound-calls.test.ts`, e2e). The caller's own folder also declares `create`, which name lookup would pick.
   - `import { create } from '../lib/utils'; create()` links `src/lib/utils.ts#create`.
   - So do `import { create as make }` / `make()` and `import * as u` / `u.create()`.
   - The default import `import build from '../lib/build'; build()` links the file's `export default function build`.
   - `const { create: mk } = require('../lib/utils'); mk()` links `utils#create`.
   - The re-export `import { shout } from '../lib'`, through `lib/index.ts` with `export { shout } from './impl'`, links `lib/impl.ts#shout`; `export *` is followed too.
2. **Python** (e2e). `app/aaa.py` also declares `create`.
   - `from utils import create; create()`, `from utils import create as c; c()` and `import utils; utils.create()` link `app/utils.py#create`.
   - `from pkg import mod; mod.thing()` links `app/pkg/mod.py#thing`.
   - A name re-exported by `pkg/__init__.py` (`from .impl import helper`) links `pkg/impl.py#helper`.
3. **No regression.** Unimported names keep name lookup (test). The edges, routes and HTTP scorers keep their floors (`npm run eval`). MapX's self-scan call-edge changes are listed and justified in the report.
