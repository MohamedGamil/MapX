# M4-23 — Cross-repo HTTP communication view in the dashboard

## Identification

Milestone M4; P1; risk medium; estimate 6/10/16 h. Decision D027.

## Objective

Show how repos talk over HTTP: frontend call sites paired with backend routes and handlers, unmatched calls, and a repo-to-repo flow, as for majles's frontend and backend.

## Background

D027. Builds on M2 HTTP pairing (http edges, .mapx/http-calls.json, mapx routes --clients).

## Dependencies

- M4-21 (hard)

## Out of scope

Changes to HTTP extraction or pairing themselves (M2 tasks own them).

## Acceptance criteria

1. /api/http returns the client call sites (file, line, method, URL, client), their matched route and handler (file, symbol, repo), and unmatched calls, per repo pair; on a synthetic two-repo fixture (Vue/axios frontend, Laravel backend) the pairs and unmatched calls equal mapx routes --clients --json and --unmatched (tests/ui-server.test.ts).
2. An HTTP tab lists the pairs with filters (method, repo pair, matched or unmatched) and a repo-to-repo flow diagram weighted by pair counts; selecting a pair shows both source locations (tests/ui).
3. The graph view marks http edges between repos (tests/ui).
