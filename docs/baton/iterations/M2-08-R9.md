# M2-08-R9 — Sync follows new global declarations

## Identification

Milestone: M2; priority: P2; risk: medium; estimate min/expected/max: 2/4/6 h; role: resolution engineer.

## Objective

A sync that adds a global name makes the ES modules that named it link it, as `scan --force` does: a new script, a module renamed and turned script, a function added to an existing script, a new file with `declare global`. Only the modules that named one of the new names re-parse.

## Dependencies

M2-08-R4 (hard, DONE): `files.metadata.globalNameRefs` (the bare names an ES module looked for under the global rule), `globalScopeReferrers`, `gainedGlobalNames`.

## Cause (probe, 2026-11-04, `develop@773e2a1`)

Workspace (hash mode and git mode alike, real CLI): modules `use/a.ts`, `use/c.ts`, `use/d.ts`, `use/e.ts` call `newScriptFn()`, `addedFn()`, a parameter type `LateDecl` and `movedFn()`; `lib/s.ts` is a script declaring `oldFn`; `lib/g.ts` is a module (`export var gone`). Scanned, then edited:
- (a) `lib/new.ts` added: `function newScriptFn() {}`;
- (b) `lib/g.ts` renamed to `lib/h.ts`, `export` dropped: `function movedFn() {}`;
- (c) `lib/s.ts` gains `function addedFn() {}`;
- (d) `types/decl.ts` added: `export {}; declare global { class LateDecl {} }`.

`mapx sync .`: "Updated 6 files … 1 edges updated". After it, the index lacks four edges `scan --force` gives: `a1 call lib/new.ts#newScriptFn`, `c1 call lib/s.ts#addedFn`, `D::constructor param_type types/decl.ts#LateDecl`, `e1 call lib/h.ts#movedFn` (the module-to-script edit `legacy/plain.ts` was already linked, M2-08-R4).

Cause: `globalScopeReferrers` compares a file already indexed whose recorded global-scope key changed. A new file has no recorded key, so it is skipped. A script that stays a script has the same key (`s`), so it is skipped too, though it gained a name.

## Scope

The names a new or edited script declares come from the parse the sync runs anyway, and the modules that named them are parsed in a second batch of the same sync (`reindexGlobalRecorders`, run after the first batch is written, in the incremental scan, git sync and hash sync). The first design parsed the script a second time on the main thread to find its names; the review measured it at 2.5x the sync time on 2,000 scripts and a main-thread block of up to 37 s on a bundle, so it was dropped.
- **Before the rows are replaced** (`globalScopeBefore`): for each JS/TS file to re-index, its recorded global-scope key and, for a script, its stored symbol names. While the batch is written, each file's new key is noted (`globalScopeWritten`, no extra scan: `writeParseResultWithMap` computes it already).
- **After the write:** a file whose new key is a script gains the symbols its parse found that it did not declare before as a script (all of them when new or a module before). A new module (no recorded key) gains the names of its `declare global` blocks. An indexed module whose key changed stays `globalScopeReferrers`' (it also follows edges).
- **The recorders:** the modules whose `globalNameRefs` hold a gained name and that the first batch did not parse (`globalNameRecords`, one pass over the metadata, kept for the sync). They are parsed in a second batch through the normal path (`parseFilesParallel`, worker pool included), written with their hashes, with their paths queued in `pending_referrers` until written (a sync killed in between leaves them for the next one, M0-02-R11). A body edit that adds no symbol compares two small sets and does nothing else.
- `gainedGlobalNames` (M2-08-R4) returns a module's `declare global` names and nothing for a script: a module turned script is no longer given every word of its text, so a module that merely shares a word the script uses is not re-parsed (R4's stated over-inclusion).

Parse memory (review P2): a syntax tree lives in WASM memory with no finalizer, and `parseWithQueries` never freed it: 3,000 parses of an 8 KB script took RSS from 136 MB to 2.2 GB (and made WASM abort), in the main-thread fallback of a small sync, `mapx serve`, and the pooled parse workers alike. `parseWithQueries` now returns `dispose()`, which the generic and PHP parsers call in a `finally` after reading the nodes; it frees the tree itself when a query throws; the worker's generic capture walk frees its tree on every exit.

Full-scan output: unchanged. The parse results are the same (only memory is freed) and `scanFull` with `--force` runs no second batch. No `EXTRACTOR_VERSION` bump: unchanged files index the same and no record is added.

Blast radius: `mapx impact` was not run, since the repo's own index is older than the code. By grep, `gainedGlobalNames` has one caller, `globalScopeReferrers` (called by `importerReferrers`); `reindexGlobalRecorders` is new, with the three sync paths as its only callers; `parseWithQueries` has two callers (the generic and PHP parsers), both updated.

## Out of scope

- **Callers that are not ES modules** (a script, a Vue/Svelte file) name globals freely and record nothing (`globalNameRefs` is written for ES modules only), so a new script is not followed for them. Recording every bare name of every script would cost a record per file; no task owns it.
- **Removing one of two same-named declarations** (script or global) leaves the referrers' edges dropped with the file, not re-linked to the other declaration. This is the general "removed target with another same-named symbol" gap of M0-02; it is not specific to globals.
- A name reached through a base class in another file is not recorded (M2-08-R4 limitation, unchanged).
- A `.vue` or `.svelte` file with `declare global`, a bare specifier becoming a workspace package: unchanged.

## Acceptance criteria

All in `tests/import-bound-externals.test.ts`, run for git and hash sync; each compares the synced edges with `scan --force`'s and counts "Updated N files".
1. A new script declaring a name a module calls: the edge appears, `Updated 2 files` (the script and the module), though the script also uses the name another module recorded (`bystander.ts` not re-parsed). A new script none of whose declarations a module names: `Updated 1 files`.
2. A module renamed (`git mv` or `mv`) and edited into a script: `Updated 2 files`, the edge appears.
3. A function added to an existing script: `Updated 2 files`, the edge appears. A body edit of that script, with words other modules recorded and a declaration a module names that it made before: `Updated 1 files`, and the edge of the module that names `oldFn` stays.
4. A new file with `declare global`, and a new global `.d.ts`: `Updated 2 files`, the edge appears.
5. A module edited into a script that uses a name a bystander recorded: `Updated 2 files` (the edited file and its user).
6. A global removed from a script: `Updated 2 files` (the script and the module that had the edge), equal to `scan --force`. A script removed: `Updated 0 files` (its edges go with its rows), equal to `scan --force`. (Confirms the removal direction needs no change.)
7. In-process (`a sync parses each file once, the recorders of a gained name in a second batch`): a body edit parses the script once and nothing else; a declared name adds one second batch of exactly the modules that named it; a module edited in the same sync is parsed once; the recorded names are read from the metadata once per sync; the pending queue is empty afterwards.
8. Parsing frees its syntax tree (TypeScript, JavaScript, PHP, Python, and when a query throws): `tests/parser-tree-release.test.ts` counts `Tree.delete`. 3,000 parses of a 12.8 KB script: RSS 152 MB to 188 MB (HEAD: 136 MB to 2,225 MB).
9. `npm run eval` prints the same numbers before and after; the full-scan dump of MapX's own repo is byte-identical between HEAD and the change.
