# M5-07 — CI reporters: SARIF, GitHub annotations, CodeClimate, JUnit

## Identification

Milestone: M5; priority: P2; risk: low; estimate min/expected/max: 4/6/8 h; role: CLI and CI-integration engineer.

## Objective

`mapx check` speaks the formats CI systems read natively, so an architecture violation shows up where reviewers look:
- **`sarif`:** SARIF 2.1.0 for GitHub code scanning and IDE viewers;
- **`github`:** GitHub Actions workflow commands (inline PR annotations), chosen automatically when `GITHUB_ACTIONS` is `true` and no `--format` is given;
- **`codeclimate`:** the GitLab Code Quality report (CodeClimate issues), with a configurable severity map;
- **`junit`:** JUnit XML for GitLab's and Jenkins's test reports, one suite per layer.

## Dependencies

- M5-05 (hard, DONE): `mapx check`, the report, the table and JSON reporters, the exit contract.
- M5-06 (DONE): fingerprints, skipped findings (`skippedBy`) and `stale-baseline` errors, which every format must map.
- No approval gate.

## Scope

- **Shared context** (`src/arch/reporters/context.ts`): what a CI format needs beyond the report: the configuration file (the location of findings that have no source file), what fails the run (`--fail-on`, `--fail-on-uncovered`, `--compare`), the CodeClimate severity map, the tool version and the view. Paths are workspace-relative POSIX in every format.
- **`sarif`:** one run; `tool.driver` with the rules the results use; one result per finding with `ruleId`/`ruleIndex`, `level` (error, warning, note; an allowed dependency is `kind: "pass"`, level `none`), a physical location (`%SRCROOT%`-relative URI and start line) and a logical one (the element), `partialFingerprints` carrying the finding fingerprint, and `suppressions` (`external`, accepted) for skipped findings. `automationDetails.id` separates views.
- **`github`:** `::error`, `::warning` or `::notice` with `file`, `line` and `title`, escaped as the Actions toolkit does (`%`, `\r`, `\n` in data; also `:` and `,` in properties), then the counts line. Allowed dependencies are not annotated.
- **`codeclimate`:** a JSON array of issues (`type`, `check_name`, `description`, `categories`, `severity`, `fingerprint`, `location.path`, `location.lines.begin`). The fingerprint is the finding's fingerprint. The severity comes from the finding's kind and configured severity through a map, `report.codeclimate` in the configuration (`error`, `warn`, `uncovered`, `skipped` → `info|minor|major|critical|blocker`). Allowed dependencies are not issues.
- **`junit`:** one `<testsuite>` per non-overlay layer (in configuration order), plus a suite for findings that belong to no single layer (`Domain, Shared` for a multi-layer source; `configuration`). **One `<testcase>` per finding** (decision: a testcase per rule would hide which dependency failed, and GitLab and Jenkins list testcases individually). A finding that fails the run (by the same rule as the exit code) is a `<failure>`; a configuration or baseline error is an `<error>`; a skipped finding is `<skipped>`; anything else passes, with its message in `<system-out>`. A layer with no finding gets one passing testcase, so a clean run is never an empty report.
- **CLI:** `--format table|json|sarif|github|codeclimate|junit`; the `GITHUB_ACTIONS` auto-selection; a machine format still writes a report (one `config` error) when the configuration is missing.
- **Configuration:** `report.codeclimate` in `schemas/architecture.schema.json`, `src/arch/schema.ts` and `src/arch/config.ts` (validated, merged key by key through `extends`).
- **Determinism:** no timestamps, durations, absolute paths or host names; the order is the report's.
- **Docs:** `docs/cli-reference.md` and `docs/architecture-rules.md`.

## Out of scope

- Graph reporters (`dot`, `svg`, `mermaid`, `dsm`, `toon`): M5-13.
- An MCP surface for `check`: M5-14.
- MapX enforcing its own architecture in CI, with an upload step: M5-18.
- Path prefixes for a workspace below the repository root (`--path-prefix`): not requested; recorded as a limitation.

## Implementation plan

1. Vendor the official SARIF 2.1.0 schema (OASIS, errata 01) and the Jenkins xunit-plugin JUnit XSD (MIT) under `tests/fixtures/arch-reporters/schemas/` with their notices.
2. `tests/arch-reporters.test.ts` first: unit tests on a synthetic report with hostile text (`%`, CR/LF, `:`, `,`, `<&"'`, control characters, lone surrogates), schema validation, golden files for the PHP fixture `tests/fixtures/arch-rules/php` through the real CLI, and the `GITHUB_ACTIONS` selection.
3. The four reporters and `context.ts`; `failsRun` in `src/arch/check.ts`, shared by `exitCode` and JUnit.
4. CLI wiring, the configuration key, docs.

## Expected outputs

`src/arch/reporters/{context,sarif,github,codeclimate,junit}.ts`, `tests/arch-reporters.test.ts`, `tests/fixtures/arch-reporters/**` (schemas, notices, golden files), and changes to `src/cli.ts`, `src/arch/check.ts`, `src/arch/schema.ts`, `src/arch/config.ts`, `src/arch/reporters/table.ts`, `schemas/architecture.schema.json`, the docs and the test helpers that run `mapx check` (they must not inherit `GITHUB_ACTIONS` from a CI runner).

## Acceptance criteria

1. SARIF from the PHP fixture (violations, skipped, uncovered, a stale-baseline error, warnings) and from a configuration-error report validates against the vendored official SARIF 2.1.0 schema (ajv, all errors).
2. CodeClimate fingerprints equal the JSON report's fingerprints for the same run; a warn-level violation and a configured `report.codeclimate` map change the severities.
3. Golden files for each of the four formats on the PHP fixture match byte for byte, and two runs are identical.
4. GitHub command escaping round-trips hostile text; JUnit XML is well-formed and escapes it, and validates against the Jenkins JUnit XSD where `lxml` is available.
5. `GITHUB_ACTIONS=true` without `--format` prints annotations; with `--format table` it prints the table.
