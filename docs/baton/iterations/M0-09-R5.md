# M0-09-R5 — Agent files: consent for edited hashless legacy blocks; JSONC configs already up to date

## Identification

Milestone: M0; priority: P2; risk: medium; estimate min/expected/max: 1/2/3 h; role: agent integration files.
Sources: `docs/baton/reviews/REVIEW-2026-10-31-2db08bd25e13.md` (P2 table), `docs/baton/reports/M0-09-R3.md` and `M0-09-R4.md` ("Review (review 2026-10-31, 2db08bd)").

## Objective

An edited legacy block is never removed without consent, and an MCP config that already holds the mapx entry is left untouched.

## Dependencies

- M0-09-R4 (hard): legacy `remove` actions and `needsConsent`. DONE.

## Scope

All in `src/agents/generator.ts`:

- **Hashless legacy blocks.** `docs/cli-reference.md` says a legacy block edited after mapx wrote it is removed only with consent or `--force`. `planLegacy` treated every hashless block (what 0.3.x and earlier wrote) as unedited. Now a hashless block is unedited only when its body (line endings normalised, trimmed) is one that a released version wrote: `LEGACY_BODIES['.continue/mapx.yaml']`, the Continue block with 25 (0.1.9–0.2.7), 26 (0.3.0–0.3.1) or 32 (0.3.2–0.3.5) tools, taken from the tags with `git show`. 0.1.7 used HTML sentinels, which the YAML regex never matched, so its body is not needed. `needsConsent` is unchanged, so `init`, `agents generate`, `agents update` and `mapx_agents_generate` all ask, or skip without a TTY.
- **JSONC MCP configs.** `generateMcpConfigs` compared the raw file text with `JSON.stringify` output, so a JSONC file already holding the identical entry was a `merge` and lost its comments. It now compares the parsed values (`isDeepStrictEqual(existing, merged)`).
- `docs/cli-reference.md`, `mapx agents` sections only: the Continue line names hashless blocks, and the Zed line and `agents mcp` say that an identical entry leaves the file untouched.

## Out of scope

- The CLI's skip message for a `remove` says "overwrite" (`src/cli.ts`, not in this task's files). The file is kept, which is the behaviour this task requires.
- Keeping comments when the entry does change (a real merge): still plain JSON with a warning (M0-09-R3).

## Implementation plan

`planLegacy` (`edited`), `generateMcpConfigs` (the up-to-date test), and a `LEGACY_BODIES` table. Action shapes are unchanged.
