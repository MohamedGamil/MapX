# M0-09-R4 — Continue integration in Continue's documented format (D014, amends F17)

## Identification

Milestone: M0; priority: P2; risk: medium; estimate min/expected/max: 2/4/6 h; role: agent-integration / TypeScript.

## Objective

The Continue provider writes files Continue actually loads: an MCP server block in `.continue/mcpServers/mapx.yaml` and one invokable prompt per slash command in `.continue/prompts/`. Continue never loads the F17 file `.continue/mapx.yaml` (M0-09-R3 limitation, owner decision D014).

## Dependencies

- M0-09-R3 (hard, DONE): sentinel, hash, CRLF and consent behaviour that the new files reuse.

## Scope

- `continue` template: `.continue/mcpServers/mapx.yaml` with `name`/`version`/`schema: v1` and an `mcpServers` entry running `mapx serve --dir <project>`.
- Four hidden companion templates `.continue/prompts/mapx-{impact,callers,context,sync}.md`, each with `name`, `description` and `invokable: true` front matter (the M0-09-R2 slash commands).
- Legacy `.continue/mapx.yaml`: removed (with a message) when it carries the mapx sentinel; left alone without one. An edited legacy block needs consent. `agents update` migrates a legacy-only project. `uninit` removes the legacy file too.
- `agents list` shows companion files and a pending legacy removal; the MCP tool and CLI print the removal message.
- `uninit` deletes generated files that are reduced to their template front matter (the new prompts; also Cursor/Windsurf rules).
- Docs: `docs/cli-reference.md`, `docs/mcp-integration.md`.

## Out of scope

- A Continue `context` provider for `mapx export` (Continue has no `cmd` provider; the MCP server exposes `mapx_export`/`mapx_status`).
- Hub publishing of blocks; JSON MCP configs in `.continue/mcpServers/`.
- `specs/` stays frozen (D001); F17 is amended by D014, not edited.

## Implementation plan

- `src/agents/templates.ts`: new `continue` content and filename, `companions` for the prompts, `legacyFiles: ['.continue/mapx.yaml']`, `{{PROJECT_DIR_YAML}}` (single-quoted YAML scalar).
- `src/agents/generator.ts`: `remove` action status for legacy files (`edited` → `needsConsent`), `execute` deletes, migration under `onlyExisting`, `revert` handles legacy files and front-matter-only remainders.
- `src/cli.ts`, `src/mcp.ts`: report removals; `agents list` per-file lines; `agents update` treats a legacy file as existing; generate uses `needsConsent`.
- Tests: `tests/legacy-agent-templates.test.ts` (shape validation, legacy removal), `tests/legacy-agents.test.ts` (sentinel file list, idempotence, consent), `tests/templates.test.ts` (filename).

4. `agents list`, `mapx_agents_generate` and the docs name the new files.
