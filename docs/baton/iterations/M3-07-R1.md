# M3-07-R1 — Framework detection keeps its folder scope when package.json files are indexed

## Identification

Milestone: M3; priority: P2 (review 2026-10-31); risk: medium; estimate 1/2/3 h; role: framework detection.
Sources: `docs/baton/reviews/REVIEW-2026-10-31-2db08bd25e13.md` (P2 table), `docs/baton/reports/M3-07.md` (review section).

## Objective

A detector activated by a sub-folder manifest stays scoped to that folder, also when the user's filters index `package.json` (or `composer.json`) files.

## Dependencies

M3-07 (hard), DONE.

## Scope

- **Root cause.** `hasPackageJsonDependency` / `hasComposerDependency` (`src/frameworks/utils.ts`) read every manifest in the scanned file list, and fell back to the repo root's only when the list held none. `package.json` is excluded by default, so M3-07's tests never saw it. Once a user drops that exclude, `frontend/package.json` is in the list, `VueRouterDetector.detect()` is true, and the registry activates vue-router for the whole repo: `backend/tools/routes.js` gains a route edge, and the Vue ignore list applies to backend files.
- **Fix.** Both helpers read only the repo root's manifest (`<projectRoot>/package.json`, `<projectRoot>/composer.json`), through the existing `readManifestDependencies`. A nested manifest activates a detector only through `findNestedManifestScopes`, for its folder. The `files` parameter is kept (unused) so the detectors' calls stay as they are.
- This also stops the helpers joining the repo root with workspace-relative paths in a multi-repo workspace.

Blast radius (`mapx impact`): `hasPackageJsonDependency` → the `detect()` of Express, NestJS, Next.js, React Router, SvelteKit, TanStack Router, Vue Router; `hasComposerDependency` → the `detect()` of Laravel, Symfony, Yii. Laravel also finds nested apps on disk (`findLaravelRoots`, three folders down), which is unchanged. Express has no `manifestDependencies`, so a nested Express manifest no longer activates it at all (before, it did only when manifests were indexed or a unit caller passed one).

The scanner's Vue app boundary (`vueScope`, M3-08-R1) is a separate concept and is not touched; it consumes the detection scopes only through `vueRouterActive`.

## Out of scope

- A nested `svelte.config.js` (scanned by default) or `symfony.lock` in the file list still activates SvelteKit / Symfony for the whole repo. Same class of leak through a different file; recorded as a finding.
- Folder-scoped Express (its `detect()` pre-scans router prefixes repo-wide).

## Acceptance criteria

1. With `package.json` files indexed, a `backend/` folder beside a Vue `frontend/` gets no vue-router route edges, and `detect()` reads only the repo-root manifest (e2e). Tests in `tests/vue-sfc.test.ts`:
   - "keeps Vue scoped to frontend/ when package.json files are indexed" (worker threads and `--no-parallel`): real `init` + `scan` with the `package.json` exclude removed; `frontend/package.json` is in `files`; the only route edge is the frontend one; both backend `t` symbols survive;
   - "detect() reads only the repo-root manifest, whatever manifests the file list holds" (Vue Router and Symfony detectors).
