# M0-20-R3 — NestJS: trailing commas, generic handlers, regex after a parenthesis

## Identification

Milestone: M0; priority: P2; risk: medium; estimate min/expected/max: 1/2/4 h; area: remediation (frameworks/nestjs).
Sources: `docs/baton/reviews/REVIEW-2026-10-31-2db08bd25e13.md` (P2 table), `docs/baton/reports/M0-20-R2.md` ("Review" and "Limitations").

## Objective

NestJS routes keep their path and handler name for Prettier-formatted decorators, generic handlers and regex literals.

## Dependencies

M0-20-R2 (hard). No approval gate.

## Scope

Three defects, reproduced with the reviewer's probe (`review-E/probe-nest.mts`) on the baseline:

- **Trailing comma.** `@Get(\n  ':id',\n)` gives the path `/multi/:id',`: the argument text keeps the comma, so `pathArg` strips only the leading quote. `decoratorCalls()` drops a trailing comma (outside strings, on the masked text) from every decorator's arguments, so routes, `@Use*` lists, GraphQL and message patterns all benefit.
- **Generic handler.** `async list<T>(): Promise<T[]> { return this.svc.findAll(); }` is named `findAll`: `findMethodNameAfter()` requires `(` right after the name, so it skips `list<T>` and takes the first call. It now skips a type-parameter list (`typeParamsEnd()`, balanced `<…>`, brackets skipped, `=>` does not close) before checking for `(`.
- **Regex after a condition's `)`.** `if (s) /{'/.test(s)` is masked as a division, the `'` opens a string to the end of the line, the method's `}` vanishes and the class swallows the next one (phantom route). `maskCode()` keeps a stack of open parentheses, marking those that open an `if`/`while`/`for`/`with` head; after the matching `)` a `/` starts a regex. Any other `)` (call, grouping) still precedes a division.

## Out of scope

- A `/` after `}` is still a division (block end versus object literal needs a parser).
- Nested classes inside method bodies (`class Inner { @Get(...) }` inside a handler) still yield routes on the outer controller; not in the review.
- The separate `maskCode()` in `src/frameworks/http/client-calls.ts` (HTTP pass, Vue parsers) has the same `)` limitation; reported, not changed.

## Implementation plan

- `src/frameworks/detectors/nestjs.ts`: `STATEMENT_HEAD` and a paren stack in `maskCode()`; trailing-comma trim in `decoratorCalls()`; `typeParamsEnd()` used by `findMethodNameAfter()`.
- `tests/legacy-nestjs.test.ts`: an e2e block (temp workspace → `mapx init` → `mapx scan` → `mapx routes --json`) with one file per scenario, a `*Helper` class with a phantom route after each controller, and a division guard (`Math.abs(n) / 2 + '/' + '{'`).

Blast radius (`npx tsx src/main.ts impact <symbol>` on the worktree scan):

- `decoratorCalls`, `findMethodNameAfter`: `NestJSDetector::extractRoutes`, `NestJSDetector::extractHooks` only.
- `maskCode`: the graph lists callers in `js-aliases.ts`, `vue-navigation.ts`, `vue-template.ts` and `client-calls.ts`, but those import the distinct `maskCode` of `client-calls.ts` (same name). The NestJS one is used only by `classSegments` → `extractRoutes` / `extractHooks`.

## Acceptance criteria

1. `@Get(\n  ':id',\n)` under `@Controller(\n  'x',\n)` gives `GET /x/:id` (test "drops the trailing comma of a multi-line decorator argument (AC1)").
2. `@Get() async list<T>(): Promise<T[]> { return this.svc.findAll(); }` is named `list` (test "names a generic handler after itself (AC2)", which also covers `save<K extends keyof Map<string, () => void>, V = {}>(k: K)`).
3. A regex literal after the `)` of an `if`, `while` or `for` head does not swallow the class (three AC3 tests and "no phantom route anywhere"); a `/` after a call or grouping `)` stays a division (guard test).
