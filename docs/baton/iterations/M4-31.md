# M4-31 — Test runs add no more than ten process listeners (MaxListenersExceededWarning)

## Identification

Milestone: M4; priority: P3; risk: low; estimate min/expected/max: 1/2/4 h; role: test-infrastructure engineer.

## Objective

`npm run check` prints no MaxListenersExceededWarning, because the code that adds SIGINT, SIGTERM and exit listeners to `process` removes them again when what they guard is closed.

## Dependencies

None. Source: the finding of 2026-11-03 (every full run prints "Possible EventEmitter memory leak detected. 11 SIGINT/exit/SIGTERM listeners added to [process]"), and reports/M4-09-R2.md.

## Cause

Found with `NODE_OPTIONS=--trace-warnings npx vitest run tests/cli.test.ts tests/cli-coverage.test.ts tests/arch-smells.test.ts`. Every stack is `process.once` in `loadContext` (src/cli.ts), called from a command action under `Command.parseAsync`. Each `loadContext` call adds an `exit`, a `SIGINT` and a `SIGTERM` listener to close its store, and none is ever removed. A test file that runs eleven or more CLI commands in-process (`buildCLI().parseAsync`) passes ten. The MCP server adds no process listener.

## Scope

- `src/cli.ts`: the stores `loadContext` opens are kept in one module-level set. A single `exit`/`SIGINT`/`SIGTERM` listener set closes them all; it is added when the first store opens and removed when the last one is closed. Behaviour on exit and on a signal is unchanged (close the stores; exit 130 or 143).
- `src/core/store.ts`: `Store.onClose(fn)`, called once when the store is closed, so the CLI can drop a closed store.
- `tests/process-listeners.test.ts`: a workspace initialised and scanned with the real CLI. Twelve `loadContext` calls and twelve in-process `mapx status` runs add at most one listener per event and emit no warning; closing the stores returns the counts to their starting values.
- Store mocks in tests that go through `loadContext` gain `onClose` if they need it.

## Out of scope

- Closing the store at the end of each CLI command: the CLI process exits after one command, and the exit listener closes it.
- Other EventEmitter warnings (none seen).

## Implementation plan

1. Write the failing test.
2. Add `Store.onClose` and the shared listener set.
3. Mutation-check; run `npm run check` and grep its output for MaxListenersExceededWarning; run the full suite, `npx tsc --noEmit`, `npm run typecheck`.

## Expected outputs

Changed `src/cli.ts` and `src/core/store.ts`; new `tests/process-listeners.test.ts`; `docs/baton/reports/M4-31.md`.

## Acceptance criteria

1. `npm run check` output contains no `MaxListenersExceededWarning` (grep count 0, against 6 lines before).
