# M4-28-R2 — `mapx_status` honours its exclude and include parameters

## Identification

Milestone: M4; priority: P2; risk: low; estimate min/expected/max: 0.5/1/2 h; role: CLI and MCP engineer.

## Objective

`mapx_status` applies the `exclude` and `include` patterns it accepts, and `mapx status --exclude/--include` does the same, so both report the same changed files for the same patterns.

## Dependencies

M4-28 (hard, DONE): its report found that `mapx_status` declares `exclude`/`include` and ignores them, and that `mapx status --exclude/--include` only prints them.

## Scope

- `src/core/staleness.ts`: `filterChanges(changes, dir, repoRoot, excludes, includes)`, the changes whose workspace path the given patterns keep, matched as `buildPathFilter` matches them at scan and export time (an exclude wins; with includes, only matching paths).
- `src/cli.ts` (`mapx status`, single-repo report): the git changes and the other changes are filtered by the `--exclude`/`--include` patterns before they are counted and listed.
- `src/mcp.ts` (`mapx_status`): the same filter on the same two lists. The tool now lists the changed files under its git status (the CLI's `+`/`~`/`-`/`>` lines), so the two can be compared. `exclude`/`include` accept a comma-separated string (as before) or an array of globs.
- `docs/cli-reference.md`, `docs/mcp-integration.md`: the parameters narrow the changed files.
- `tests/mcp-status-filters.test.ts`: a git workspace scanned with the real CLI, a changed file under `src/` and one under `lib/`; `mapx_status` and `mapx status` with and without `exclude: ["src/**"]` (and an include) report the same files.

## Out of scope

- `mapx status --all` (the per-repository table): its counts stay unfiltered.
- The staleness warning other tools print; it reads the configured rules only.
- tests/mcp-coverage.test.ts mocks the Store and `node:fs`, so it cannot hold a real-workspace test; it is run as the registered command.

## Implementation plan

1. Write the failing e2e test.
2. Add the helper, use it in the CLI and MCP status, list files in the MCP output, accept arrays.
3. Update both docs; keep tests/docs-surface.test.ts passing.
4. Mutation-check; run the registered command and the full suite.

## Expected outputs

Changed `src/core/staleness.ts`, `src/cli.ts`, `src/mcp.ts`, `docs/cli-reference.md`, `docs/mcp-integration.md`; new `tests/mcp-status-filters.test.ts`; `docs/baton/reports/M4-28-R2.md`.

## Acceptance criteria

1. With a changed file under `src/` (and one under `lib/`), `mapx_status` with `exclude: ["src/**"]` lists no file under `src/` and still lists the `lib/` file; without the parameter it lists both. Test: `tests/mcp-status-filters.test.ts`.
2. The changed files `mapx_status` lists equal those `mapx status` lists with the same option (`--exclude 'src/**'`, `--include 'src/**'`, none). Same test.
