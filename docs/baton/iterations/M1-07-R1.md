# M1-07-R1 — Laravel reachability is unknown, not false, for unevaluated mounts; registry keeps both duplicates

## Identification

Milestone: M1; priority: P1; risk: medium; estimate min/expected/max: 5/8/12 h; area: laravel, remediation.
Sources: `docs/baton/reviews/REVIEW-2026-10-31-fb75474ba377.md`, `docs/baton/reports/M1-07.md` (with the M1-04, M1-08 and M1-09 review notes).

## Objective

Live Laravel routes are never reported as unreachable just because their mount could not be evaluated, and the route registry keeps both sides of an override.

## Dependencies

M1-07 (hard), M1-04 (hard). M1-03-R1 is integrated (aa0c60a). No approval gate.

## Scope

- Evaluate more mount forms:
  - `module_path(name, path)` (nwidart, `Modules/<name>/<path>`), with `$this->prop` read from class string properties;
  - `DIRECTORY_SEPARATOR`;
  - `foreach (glob(<expr>) as $f) require $f;`, braced or not, expanded on disk;
  - `withRouting(then: …)` and `using: …` closures, walked like a provider;
  - `bootstrap/app.php` read through the masking lexer.
- A mount that still cannot be evaluated makes the app's unmounted route files `reachability: 'unknown'` instead of `reachable: false`. HTTP pairing keeps those routes. `mapx routes --json` gains `reachability`, and `reachable` stays a boolean that is false only when unreachability is proven.
- Route registry: the dedup key includes the declaring file, line and load order, so an overridden route and its winner (same handler) both reach `routes.json`.
- P2 items from the description:
  - the override key uses the exact URI (parameter names) plus the domain (`Route::domain`, `'domain' =>`);
  - a brace-less `if (...) require …;` or `if (...) Route::…` is conditional;
  - `if (! $this->app->routesAreCached())` is not conditional;
  - attribute routes get a line;
  - route edges keep `dynamic`, `mountedBy` and `reachability`.
- Tests:
  - the override pointer is asserted;
  - M1-08 nested detection from `composer.json` alone, with no seeded `frameworks.json`;
  - the scorer no longer credits a negative label when the route is absent; a new `absent` expectation covers route code that must never be reported (comments, strings).

## Out of scope

- Resource forms, array-handler attributes and group name prefixes (M1-05-R1).
- `withRouting(health: …)`, `commands:` and `channels:`.
- A configurable nwidart modules path (`config/modules.php`); the default `Modules` is used.

## Implementation plan

1. Fixture first: `then:` closure, glob loops (braced and brace-less), a `DIRECTORY_SEPARATOR` require, an nwidart module, and a brace-less conditional require. Labels go in `labels.json`; L48–L52 move to `absent`, and the provider-negative labels are restated under the stricter scorer. Record the failing score.
2. E2E tests in `tests/laravel-mounts.test.ts`: unknown reachability plus HTTP pairing; the duplicate with the same handler and its pointer; nested detection from composer.json; `routesAreCached` not conditional; parameter names and domain in the override key; attribute route lines; edge metadata.
3. Implement in `laravel-mounts.ts` (`phpString` extensions, `expandGlob`, `opensConditionalBlock`), `laravel.ts` (walker, `withRoutingEntries`, mount graph, `finalizeRoutes`, attribute lines), `route-registry.ts` (dedup key, view), `scanner.ts` (edge metadata), `score-routes.ts` (negative crediting, `absent`).
4. Mutation-check each new test; update `docs/cli-reference.md` and `docs/mcp-integration.md` for `reachability`.

## Expected outputs

Updated sources, fixture and tests as above, and `docs/baton/reports/M1-07-R1.md`.

## Acceptance criteria

1. `module_path`, `then:` closures, glob loops and `DIRECTORY_SEPARATOR` mounts are evaluated (fixture labels). Any mount that still cannot be evaluated marks its routes' reachability unknown, and pairing keeps them (e2e test).
2. When a route overrides another with the same handler, both appear in routes.json, and the test asserts the override pointer.
3. The M1-08 test detects a nested app from composer.json without a seeded frameworks.json.
