# M5-02-R1 — arch validate-config (CLI and MCP) and loader robustness

## Identification

Milestone: M5; priority: P2; risk: low; estimate min/expected/max: 2/4/6 h; area: remediation (arch, cli, mcp).
Source: review 2026-11-02 (`reviews/REVIEW-2026-11-02-b2558df592cf.md`, finding 11 and the drift table). Design input: `docs/research/deptrac/03-mapx-gap-and-integration.md` §3.4 (`mapx arch validate-config  # schema + semantic checks, exit 3 on errors`) and §3.5 (MCP tools return JSON by default).

## Objective

The validate-config surface M5-02 promised ships on the CLI and on MCP, and the loader reports, instead of crashing or silently accepting, the odd inputs the review found.

## Dependencies

M5-05 (hard, DONE): the AR-17 exit codes (`EXIT.config` = 3) and the `mapx check` CLI conventions. M5-14 (MCP `mapx_arch_*` tools) depends on this task.

## Scope

1. **Loader (`src/arch/config.ts`):**
   - a UTF-8 BOM at the start of a document is ignored;
   - `extends` naming a directory (or anything not a file) is a ConfigError at its `extends` pointer; a document that cannot be read is an issue, never an `EISDIR`/`EACCES` throw;
   - a view name whose file would lie outside `.mapx/architecture/` (`../../outside`) is a ConfigError, and nothing outside is read;
   - `%param%` is substituted in every string-valued selector key (`repo`, `cluster`, `workspacePackage`, `role`, `language` …), not only `name`/`path`/`package`, and an unresolved one is reported at its pointer.
2. **CLI:** `mapx arch validate-config [path] [--view <name>] [--format text|json]`, a subcommand of the existing `arch` command. It needs no index. Exit 0 when valid; 3 (AR-17) for configuration errors or no configuration, printing every issue as `file#pointer: message`.
3. **MCP:** `mapx_arch_validate_config { dir?, view?, format? }`, JSON by default (`{ valid, view, files, issues[] }`), `isError: true` when invalid or missing. Tool count 33 → 34 in templates, the stub, README and `docs/mcp-integration.md`.
4. **Docs:** `docs/cli-reference.md`, `docs/architecture-rules.md`, `docs/mcp-integration.md`.

## Out of scope

- `mapx_arch_check`, `_layers`, `_allowed`, `_explain`, `_init` (M5-14).
- `mapx arch init` and presets (M5-17).
- Validating selector values against the index (whether a `repo` or `cluster` exists): validation stays index-free.

## Implementation plan

- `src/arch/config.ts`: BOM strip in `parseArchitectureText`; `statSync` on `extends` targets; try/catch around reads; `viewProblem` guard in `loadArchitectureConfig`; substitution over every string selector key; `validateArchitectureConfig(dir, opts)` returning `{ found, path, config?, issues }` for both surfaces.
- `src/cli.ts`: `arch validate-config` subcommand; the `arch` command keeps its `[path]` action.
- `src/mcp.ts`: the tool definition and handler; the serve help's tool list.
- Tests first: `tests/arch-config.test.ts` (loader cases on `tests/fixtures/arch-config/robustness/`, CLI via the real `mapx`, MCP via an in-memory client).

## Expected outputs

The changed sources, tests and fixtures; docs; `docs/baton/reports/M5-02-R1.md`.

## Acceptance criteria

1. `mapx arch validate-config` and `mapx_arch_validate_config` print every configuration error with its JSON pointer and fail (exit 3; `isError`) on a multi-error document; exit 0 / not an error on a valid one (CLI and MCP tests).
2. A BOM-prefixed document loads; `extends` to a directory and a view leaving `.mapx/architecture/` are ConfigErrors (tests).
3. An unresolved `%param%` in any selector key is reported; a test of `path` substitution fails without it.
   Refined by the integration owner after the review: `%%` is a literal `%`; an undefined `%x%` is an error in `name`/`path`/`package` and literal text elsewhere; parameter values resolve, with cycles reported.
