# M0-10-R1 — Workspace surface (F18)

Date: 2026-10-31. From the M0-41 legacy audit (I10, FALSELY COMPLETE), implemented per D010.

## Delivered

- **`src/core/workspace-summary.ts`** (new), shared by the CLI and MCP:
  - `repoType`: `primary`; `submodule` (listed in `.gitmodules`); `vscode-workspace` (a folder of a `*.code-workspace`); otherwise `peer`;
  - `summarizeRepos`: files, symbols, edges, outgoing cross-repo edges, last scan, and HEAD (`git rev-parse --short HEAD` in each repo's own checkout);
  - `crossRepoPairs`: count and edge types per repo pair;
  - plus `timeAgo` and `table`.
- **`mapx workspaces`** (no subcommand) and **`workspaces list`** print the F18 table: Name, Path, Type, Files, Last scanned, HEAD. Uninitialised submodules get a `✗ not initialised` row and the `git submodule update --init <path>` hint. Before, `list` printed `name -> path (active)`.
- **Peers are opt-in:**
  - `workspaces discover/list/sync --include-peers`, and `mapx_workspaces { includePeers }`.
  - Without the flag, `discover` only says how many sibling repos exist.
  - Before, peers were always listed, and **`workspaces sync` registered every sibling git directory**.
- **`init --no-workspaces`:**
  - `init` now reports `.gitmodules` entries (initialised or not) and the repos of a `.code-workspace`.
  - On a TTY it asks, then registers them. Without a TTY it suggests `mapx workspaces sync`. `--no-workspaces` skips the step.
- **`status --all`:** per-repo table (Repo, Files, Symbols, Edges, HEAD, Last scan, Changed), totals, and `Cross-repo edges: N (a → b: n, …)`. Changed counts come from the staleness check (M0-11-R1), attributed through each file's repo.
- **`export --all`:** LLM format with:
  - `# Workspace`;
  - `## Repos (N)` with type, files and symbols;
  - `## Cross-repo dependencies (N edges)` per pair and type;
  - one `## <repo>` section per repo, sharing the token budget.

  The other formats already span every repo, and accept `--all`.
- **`deps <file> --cross-repo`:** `→ [repo] file (type)` and `← [repo] file (type)`, for edges whose `target_repo` differs from `repo`.
- **`mapx_workspaces`:**
  - Each repo's `type` is real; before it was always `primary` or `peer`, so submodules were typed as peers.
  - New `headCommit`, a top-level `crossRepoEdgeCount`, and `crossRepoEdges` pairs.
- **JSONC:**
  - `.code-workspace` files are parsed with `stripJsoncSyntax`. Before, `JSON.parse` failed on comments or trailing commas and the folders were silently ignored.
  - `rush.json` now uses the same parser instead of a regex strip that also cut `//` inside strings (URLs).

## Limitations

- Only `*.code-workspace` files in the workspace root are read. F18 also mentions one level up; that was not added.
- In `status --all`, untracked new files (from git in the root) are attributed to the primary repo.
- The "Changed" column covers indexed files; a submodule's own untracked files are not checked.
