# M0-02-R2 — Inbound edges survive a file disappearing and coming back; filters in sync and JSON export

Date: 2026-10-31. Source: review 2026-10-31 (P1, plus the glob-filter P2s and surviving mutants). Rebased onto develop 9b8f9f6, which had moved the file rules to `src/core/file-rules.ts` (M0-11-R2). The pattern changes live there, so the staleness check shares them.

## Before (all reproduced by the new tests on the unchanged code; 8 of 15 failed)

- **Lost inbound edges.** Delete `app/Services/UserService.php`, then `scan` or `sync`, then restore it and run `scan` or `sync`. Its inbound edges (`UserController` import and param_type, `User` import) stayed empty until `--force`.
- **Git working tree.** In a git repo, a working-tree delete and restore with HEAD unchanged left the file out of the index altogether, because `sync` only diffs against the last scanned commit.
- **Filter changes in git.** `sync` after an exclude was added to the config did nothing in a git repo: there was no change, so it returned early.
- **JSON export.** `export --format json --exclude 'app/Models/**'` still listed `app/Models/User.php` memberships (`App.Models`, `community_2`, `layer:data`).
- **Windows-style patterns.** `--exclude 'app\Services\**'` excluded nothing.
- **Laravel defaults.** Dropping one Laravel default was impossible: `laravelDefaultExcludes` was boolean only.

## Delivered

- **`src/core/scanner.ts`: removed files.**
  - Every removal now goes through `removeFiles`, on the full, git and hash paths. Before deleting a tracked file, it records the files with edges into it in `meta removed_files:<repo>`, using the new `Store.getReferrers`.
  - When such a file is indexed again, `takeReferrers` consumes its entry and those unchanged referrers are re-parsed: by `scan` (alongside new and changed files), by `sync` with content hashes, and by `sync` with git.
  - Git `sync` also re-checks recorded removed paths on disk. A path is checked only if it is in the filters, so excluded paths do not trigger work on every sync.
- **`src/core/scanner.ts`: filter changes.** `sync` compares `filterSignature` with `meta scan_filters:<repo>` and takes the full-scan path when they differ. That path re-parses everything once (M0-02-R1). The signature helper is shared with `scan`.
- **`src/core/file-rules.ts`:**
  - `normalizePattern` turns `\` into `/` and drops a leading `./`. It is applied in `buildMatcher` (scan, sync, export, staleness), `isExcludedDir` and `effectiveExcludesFor`.
  - `laravelDefaultExcludes` accepts a list: only the defaults it names apply.
- **`src/exporters/graph-exporter.ts`:** a filtered JSON export keeps only memberships of exported files, and clusters via `filterClustersToFiles`, the same filter LLM and TOON use. `summary.totalClusters` counts the kept clusters.
- **`src/types.ts`:** `laravelDefaultExcludes?: boolean | string[]`.
- **Docs:**
  - `docs/configuration.md`: `laravelDefaultExcludes`, the default list, prefix scoping, how to drop one default, and pattern normalisation.
  - `docs/cli-reference.md` and `docs/mcp-integration.md`: when `sync` / `mapx_sync` re-parse beyond changed files.
- **`tests/scanner-coverage.test.ts`:** the mocked store gained `getFile` and `getReferrers` stubs.

## Limitations and findings

- **Referrers recorded at deletion time only.** A file that changed while the target was missing and gained a reference to it is not re-parsed when the target returns. Neither is a referrer of a file that was never indexed: unresolved references are not stored.
- **Cross-repo referrers** are recorded but only re-parsed during their own repo's scan path; the git and hash paths re-parse same-repo referrers only.
- **`removed_files:<repo>` keeps one entry per removed path** until the path returns. The entries are small, but the map is never pruned.
- **Blade claim not reproduced.** The review said `**/*.blade.php` applies to sibling repos. I could not reproduce it: excludes are computed per repo and applied only to that repo's walk or diff. The pattern is left unscoped.
- **Finding outside scope (git renames).** `getChangedFiles` reports only the new path of a rename (`R old new`), so the old path stays indexed until a full scan. That is `src/core/git-tracker.ts`.
- **Finding outside scope (subdirectory repos).** For a repo inside a larger git repo, `git diff` prints paths relative to the git top level, while the scanner resolves them against the repo root. Not verified.
- **No backslash escapes.** After normalisation, a backslash in a pattern can no longer escape a glob character. This is documented.

Changelog: `sync` and `scan` now restore the edges into a file that was deleted and comes back (a branch switch, a restored file), `sync` applies config filter changes, filtered JSON exports drop excluded files' clusters and memberships, `./` and Windows-style patterns work, and `laravelDefaultExcludes` can list the Laravel defaults to keep (M0-02-R2).
