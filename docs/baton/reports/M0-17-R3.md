## Limitations

- **TypeScript gaps not fixed:** `interface I extends J` has no pattern at all (no `extends_type_clause` capture), and qualified bases (`extends ns.Base`, Kotlin `: p.Base()`) are not handled. These are separate gaps, not generic-argument defects.
- **Local arrows are dropped, not scoped.** Like local constants, they get no symbol. A call `f()` to a local arrow therefore resolves by name like any other call: to a same-named symbol elsewhere in the workspace, if one exists. Nested `function` declarations inside functions are still symbols (behaviour predates M0-17-R1).
- **More TypeScript symbols.** Every top-level TS `const`/`let`/`var` binding is now a symbol, as in JS since M0-17-R1. Call references skip them (`VALUE_SYMBOL_LANGUAGES` already listed TypeScript). Symbol counts in TS repos grow accordingly.
- **C#.** The owner is the smallest symbol of kind class, interface or struct whose lines span the reference. Two types declared on one line can pick the outer one. An unindexed target (`IDisposable`, framework types) keeps the parser's naming heuristic.
- **Callable constants** in C, Rust, Lua and Bash stay call targets by design; this is documented, not changed.

Changelog: Java and TypeScript generic bases (`extends Base<T>`, `implements Run<T>`) are extracted, `export let`/`export var` and TypeScript top-level bindings are symbols, arrows declared inside functions are no longer top-level functions, and C# base lists use the indexed target's kind to choose extends or implements (M0-17-R3).
