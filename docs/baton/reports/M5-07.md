# M5-07 — CI reporters: SARIF, GitHub annotations, CodeClimate, JUnit

Planned in `iterations/M5-07.md`. Sources: AR-16 in `docs/research/deptrac/02-abstract-feature-model.md`, §6 (formatters) of `01-deptrac-capabilities.md`, and REQ-ARCH-009 in `05-requirements.md`. Rebased on develop `0f7b25a`; revised after the coordinator's review (see Review 1).

## Delivered

`mapx check --format sarif|github|codeclimate|junit`, next to `table` and `json`. Each format is checked against its real schema or spec, writes workspace-relative POSIX paths, and is byte-stable.

**Shared (`src/arch/reporters/context.ts`, `index.ts`)**
- **`ReportContext`:** the configuration file (where a finding without a source file is located), the check options (what fails the run), the CodeClimate severity map and the MapX version.
- **Helpers:**
  - `locate`: a finding's `location` (a stale entry's baseline file), else its source file and line, else the configuration file;
  - `fails`: the exit-code rule (`failsRun`), which every format uses for its failing level;
  - `describeFinding`, `renderReport`;
  - `defaultFormat`: `github` when `GITHUB_ACTIONS` is `"true"`, no `--format` is given and the report goes to stdout.

**`sarif` (`sarif.ts`)**
- SARIF 2.1.0, one run of driver `MapX` with `version` and the rules its results use, sorted.
- **Each result:** `ruleId`/`ruleIndex` and a `level`:
  - `error` exactly for the findings that fail the run;
  - `warning` for the other violations and warnings;
  - `note` for uncovered and skipped ones;
  - for allowed ones, `kind: "pass"` at level `none`.
- **Locations:** a `%SRCROOT%`-relative URI, percent-encoded per segment, with `startLine` (1 when the finding has no line), plus the element as a logical location.
- **Identity and properties:** `partialFingerprints["mapx/v1"]` is the finding's fingerprint, and properties give the kind, layers, target, edge type and verifiability.
- **Skipped:** a skipped violation gets an `external`, accepted suppression, with a justification for a baseline or for `--compare`.
- **Views:** `automationDetails.id` is `mapx-check/` or `mapx-check/<view>/`.

**`github` (`github.ts`)**
- **Output, in order:**
  1. every finding as a plain log line (`[error] file:line rule: message`);
  2. the annotations, `::error|warning|notice file=…,line=…,title=<rule>::<message>`;
  3. the counts line.
- **Levels:** `::error` exactly for the findings that fail the run; uncovered and skipped findings are notices; allowed ones are not annotated.
- **Order and cap:** annotations are ordered by cause: configuration errors, stale entries, failing findings by severity, then the rest. At most 10 per level are annotated, and the counts line states the cut.
- **Escaping, as the Actions toolkit does it:** `%`, CR and LF in data; `:` and `,` too in properties.

**`codeclimate` (`codeclimate.ts`)**
- The JSON array GitLab Code Quality reads. Each issue has `type`, `check_name`, `description`, `categories` (Complexity, or Bug Risk for configuration and baseline errors), `severity`, `fingerprint` and `location.path`/`lines.begin`.
- **`fingerprint`:** a violation's is the finding's own (M5-06). Every other kind derives one: sha256 over `["codeclimate", kind, rule, finding fingerprint]`, first 16 hex characters.
- **`severity`** comes from the new configuration key `report.codeclimate`: `error` for the findings that fail the run, `warn` for the other violations and warnings, and `uncovered`/`skipped` by kind. The defaults follow Deptrac: `error` major, `warn` minor, `uncovered` info, `skipped` minor.

**`junit` (`junit.ts`)**
- **Suites:** one testsuite per non-overlay layer, in configuration order, then the other groups in report order: a multi-layer source (`Domain, Shared`) and `configuration`. With `--layer`, only that layer and the groups that have findings.
- **Decision: one testcase per finding,** not one per rule. A per-rule testcase would hide which dependency failed; GitLab and Jenkins list testcases individually. The rule is the class name.
- **Outcome:** `<failure>` exactly when `failsRun` holds. That is the exit-code rule, so `--fail-on`, `--fail-on-uncovered` and `--compare` apply. Configuration and baseline errors are `<error>`, skipped findings `<skipped>`, and all others pass, with the message in `<system-out>`.
- **Clean runs:** a layer without findings has one passing `no findings` testcase, so a clean run is never an empty report (Jenkins fails on an empty one).
- **Escaping:** XML 1.0 throughout. CR is a character reference; tab and LF are references in attributes. Characters XML cannot carry become U+FFFD.

**Integration**
- **`src/arch/check.ts`:** `failsRun(f, options)`, extracted from `exitCode` without changing behaviour. `exitCode` and every CI reporter share it.
- **`src/arch/baseline.ts`, `src/arch/evaluate.ts`:**
  - entries and pairs remember their JSON pointer;
  - a stale finding gets `location: { file, pointer }`, and its message names `<file>#<pointer>`;
  - the baseline is named relative to the workspace even outside it (`workspacePath`), never by an absolute path.
- **`schemas/arch-report.schema.json`:** the optional `location`.
- **`src/cli.ts`:**
  - `--format` has no default; `defaultFormat` decides;
  - it validates against `FORMATS` (exit 3);
  - it builds the context and passes `report.codeclimate` and `known`;
  - with a missing configuration, every non-table format still writes a one-error report.
- **`report.codeclimate`:** in `src/arch/schema.ts` (`CODECLIMATE_KEYS`, `CODECLIMATE_SEVERITIES`, `REPORT_KEYS`), `src/arch/config.ts` (validated with JSON pointers, merged key by key through `extends`) and `schemas/architecture.schema.json`.
- **`src/arch/reporters/table.ts`:** `countsLine` is extracted for the GitHub reporter. The output is unchanged.
- **Docs:** `docs/cli-reference.md` (synopsis, `--format`, a CI formats section with the full mapping table, exit-3 wording, examples) and `docs/architecture-rules.md` (a CI reports section with the severity map and a GitHub Actions example).

## Limitations

- **Paths are workspace-relative.** When the workspace is below the repository root (a monorepo subfolder), GitHub annotations and code scanning need the paths prefixed. No `--path-prefix` exists; this is a candidate follow-up. A peer repo outside the workspace gives `../` paths.
- **GitHub limits annotations:** 10 per level per step and 50 per job. MapX annotates the run's causes first, states the cut and logs every finding (review P1-2). For the rest, upload SARIF.
- **SARIF size:** GitHub accepts up to 10 MB (compressed) and 25,000 results per run. MapX does not truncate (documented, with how to narrow a report).
- **Baselines outside the workspace** are named by a `../` path, which depends on where the workspace sits relative to the file. On another Windows drive, only the file name is used.
- **`--report-allowed` with SARIF** emits `kind: "pass"` results. These are valid SARIF, but they are not meant for code-scanning uploads (documented implicitly: allowed findings are opt-in).
- **The lxml XSD check is conditional:** it skips where python3 lacks lxml, which is probably the case on stock GitHub runners. The strict in-test XML reader always runs.
- **No official CodeClimate JSON schema:** none is vendored, because none is published as such. The test's schema encodes the issue spec's required fields and GitLab's required set.
- **SARIF `tool.driver.version`** changes with every release. The golden test normalises it.
- **MCP surface:** none yet (M5-14 owns `check` over MCP).

## Finding outside the task

- **The JSON report is not byte-stable across checkout folders.** `source.repo`/`target.repo` in `--format json` carry the repo name, which `mapx init` takes from the folder name: `M5-07-php` in a scratch run. The CI formats added here leave the repo name out, and the fingerprints already exclude the root repo (M5-06), but two checkouts in differently named folders give different JSON bytes. The integration owner may want to register this.
