# M3-03 — Options API member resolution

Date: 2026-10-31. Base: `develop@587e887`. Lane: lane-vue-options. Implements edge contract rule 6 (`docs/baton/iterations/M3-01.md`) without its map-helper step, which stays with M3-05.

## Delivered

- **`src/parsers/languages/vue-options.ts` (new).**
  - *Parser side.* `annotateThisCalls(code, refs)` parses a `<script>` block with tree-sitter (TypeScript grammar) and finds the options object: `export default { … }`, `export default defineComponent({ … })`, `Vue.extend({ … })` or `defineNuxtComponent({ … })`, through `as` / `satisfies` / parentheses, or an exported identifier bound to one. It records:
    - own members: the keys of `methods` and `computed`, and function-valued top-level options (hooks, `data`, `setup`). `watch` keys are excluded, because a watched name is a prop or data field and is not callable through `this`;
    - mixins: the identifiers in `mixins: [ … ]` with their import specifiers (null for a local constant or an inline object), and `extends: X` as the lowest-priority entry;
    - map-helper names spread into `methods` / `computed` from `mapActions`, `mapGetters`, `mapState`, `mapMutations` or `mapWritableState`, each with its helper, namespace (string or store expression) and remote name, for M3-05;
    - each `this.x()` call inside the options object. A nested `function () {}` that is not itself a member rebinds `this`, so its calls are skipped.
    The matching `call` references get a typed `vueThis` scope. `vueThisScope(component, name)` is exported so the M3-02 template pass can attach the same scope to `@click="track"`.
  - *Resolution side.* `resolveThisMember` walks `THIS_MEMBER_STEPS` in order:
    1. own member → the SFC;
    2. mixins, latest listed first (Vue's merge lets a later mixin override an earlier one), where a mixin counts only if its resolved file declares `x`;
    3. map helper: until M3-05 replaces this step, the name-only lookup used before M3-03, so `vuex-map-helpers` keeps its 2.
    When no step resolves `x`, there is no edge. M3-05 can replace step 3 without touching the hooks.
- **Hooks.**
  - `vue.ts`: one call per script block.
  - `scanner.ts`: one branch in `resolveReferencesWithMap`, which supplies import resolution, a "file declares name" check against the symbol index, and the old name lookup.
  - `types.ts`: optional `ExtractedReference.vueThis` (`VueThisScope`, `VueMappedMember`). It is a separate field, so it never reaches edge metadata, and it survives the worker `postMessage` (the fixture scans run in workers; the e2e test runs on the main thread).
  - `vue-options.ts` loads `wasm-parser` lazily: when the scanner imported it eagerly, the fs mock in `tests/scanner.test.ts` failed at import.
- **Floors (`tests/vue-sfc.test.ts`).**
  - `mixin-method` found 1 → `labelledCount` (3);
  - `mixin-method` false positives 2 → 0 (entry removed);
  - `minPrecision` 0.6 → 0.7;
  - no other floor changed.
- **`tests/vue-options.test.ts` (new, 5 e2e tests).** A temp workspace runs the real `init` + `scan`, and the tests query `.mapx/mapx.db` by identity.

`src/parsers/ignored-symbols.ts` (listed in `affectedFiles`) needed no change. Its `computed` / `watch` / `setup` entries name Composition API functions, not the members that `this.x()` targets.

- **Hooks removed** (`scanner.ts`, `vue.ts` and `types.ts` restored from `develop`): 3 of 5 e2e tests fail (mixin array, later mixin, never by name). The other two guard behaviour that already held (same-file `save`; the map-helper fallback).

## Limitations

- **Unresolved by design (no edge):**
  - global mixins (`Vue.mixin` / `app.mixin`);
  - mixins of mixins (a mixin's own `mixins: []`: mixin `.js` files go through the JavaScript parser);
  - mixins imported through a barrel that re-exports them (`defines` checks the resolved file only);
  - specifiers under a path alias other than `@/`.
  These used to resolve by name, sometimes correctly by luck. The contract chooses precision.
- **Unchanged:**
  - class components and `this.x()` outside an options object keep the old name lookup;
  - `this.a.b()` (for example `this.$store.dispatch`) is not a `this.x()` call and resolves as before (M3-05).
- **Matching by line and name.** References are matched to `this.x()` calls by (line, name). An `other.x()` on the same line as a `this.x()` would take the `this` scope.
- **Not scored:** `extends` handling and the recorded `mapped` entries. The fixture has no `extends` case.
- **Floor conflict risk:** `minPrecision` was raised to 0.7. If a parallel lane adds unlabelled edges before M3-04, the integration owner may need to rebalance it.

Changelog: Vue Options API `this.x()` calls now resolve to the component's own member, then to a mixin listed in its `mixins` array, and no longer to an unrelated file that merely defines the same name (M3-03).
