# M5-08 — Introspection: arch layers --why, which, unassigned, deps, unused, changed, allowed

Planned in `iterations/M5-08.md`. Sources: AR-13 (and AR-17, AR-19) in `docs/research/deptrac/02-abstract-feature-model.md`, and §7 (debug and exploration commands) of `01-deptrac-capabilities.md`. Built on develop `7998775`.

## Delivered

**`src/arch/introspect.ts` (new): a library API, not only CLI printing.** M5-14 (`mapx_arch_layers`, `_allowed`, `_explain`) and M5-16 (dead and weak allowances) can call it directly. Every function returns a plain JSON-ready object, and the CLI prints that object as is for `--format json`.

| Function | AR | CLI |
| --- | --- | --- |
| `openArchitecture(dir, store, { view, repoPaths })` → `ArchContext` (config, membership, expanded policy, `evaluation()` computed once), or null without a configuration; throws `ConfigError` | — | every subcommand |
| `layerSummaries`, `layerMembers(ctx, layer, { why, nested })` | 13a | `mapx arch layers [layer] [--why] [--nested]` |
| `whichLayers(ctx, query)`, `resolveElements`, `resolveElement` | 13b | `mapx arch which <element>` |
| `unassignedElements(ctx, { kind, path, nested })` | 13c | `mapx arch unassigned` (exit 2 when non-empty) |
| `layerDependencies(ctx, from, to?)` | 13d | `mapx arch deps <from> [to]` |
| `unusedAllowances(ctx, { limit })` | 13e | `mapx arch unused [--limit N]` |
| `changedLayers(ctx, files, { withDependents })`, `changedSince(dir, ref, repoPaths)` | 13f | `mapx arch changed [files…] [--since <ref>] [--with-dependents]` |
| `isAllowed(ctx, from, to, { edgeType })` | 13g | `mapx arch allowed <from> <to> [--type T]` (exit 1 when it would be an error) |

- **Errors.** A question that cannot be answered as asked throws `IntrospectError`, with `candidates` when a name is ambiguous or a layer is unknown. The CLI exits 3 for it.
- **Shapes.** The JSON shapes are documented in `docs/architecture-rules.md#introspection`.
- **Elements.** Elements are named as in findings: a symbol's qualified name, or a file's path. A query resolves through these forms in order: an element id, an indexed path (absolute, `./` and `\` normalised), a qualified name, a scoped name (`Order::run`, `Order.run`), a top-level symbol's bare name, then any symbol's name.
- **`allowed` is `mapx check`'s own answer (revised after the review).**
  - **One evaluation path.** `src/arch/evaluate.ts` now has `edgeScope` (scope types, paths, inferred policy), `decideEdge` (the AR-08 chain plus the severity `check` gives each decision) and `decideLayers`. `evaluateEdges` and `isAllowed` both decide through them.
  - **Observed and hypothetical dependencies.** Between two elements the index connects, `allowed` uses the evaluator's own decisions on the stored edges, with their types and verifiability. Otherwise the dependency is hypothetical and verified, over `--type` or over every type in scope.
  - **The answer.** It lists one decision per edge type and source layer. The answer is the strictest of them (severity first), and `exitCode` is 1 whenever a decision is an error-level violation.
  - **The property test.** A test compares severity, exit code and `allowed` with `check`'s report for every reported pair, with and without `--type`.
- **Advisory and inferred.** An advisory pair, or an inferred edge under `policy.inferred: "warn"`, answers `allowed: false` with `severity: warn` and exits 0, as `check` would.
- **`allowedLayers`.** The answer lists the layers the source may depend on, which M5-14 can refine into AR-19 `alternatives`.
- **What `unused` counts.** `unused` counts stored edges the allowance decides: allowed ones, and the warnings an advisory allowance reports. It covers every allowance of the expanded policy (`explicit`, `+L`, `*`).

**`src/cli.ts`**
- **The subcommands.** Seven subcommands under `mapx arch`, built by one `archQuestion` helper. Each has `-d/--dir`, `--view`, `--format text|json` and `--json`, and all but `changed` have `--sync`.
- **The shared index gate.** The index gate of `mapx check` (no index, unscanned repo, stale files, outdated extractor: exit 4) is now `openCurrentIndex`. `check` and the subcommands share it, and `check`'s messages are unchanged.
- **`changed` and a stale index.** `changed` passes `allowStale`: AR-13f says no re-scan, and changed files are its input. An outdated extractor still exits 4.
- **Exit codes (AR-17).** 3 for configuration and usage errors (an unknown layer, an unresolvable or ambiguous element, a bad `--limit`, `--type` or `--since`, a missing view), 4 for the index, 2 for a non-empty `unassigned`, and 1 for a disallowed `allowed`.
- **`mapx arch [path]`.** It is untouched.

## Limitations and notes

- **No new files.** Only indexed elements and layer names resolve, so a file an agent is about to create cannot be named; its layer can. Running selectors on a hypothetical path would need a synthetic element. I left that to M5-14 if it wants it.
- **What `unassigned` lists (revised after the review).** It lists symbols, and files that declare a symbol or are an end of an evaluated edge. A code file with neither (an empty `__init__.py`) is not listed. That is the same rule the `multi-layer` warning already uses for symbol-less files.
- **`allowed` on a Go package.** A finding whose target is a Go package, named by its import path, cannot be named in `allowed`; name a file of the package instead. The property test covers TS and the PHP/TS workspace, not Go.
- **Baselines.** `allowed` applies no baseline: a baselined violation still answers `not allowed`.
- **What the counts count.** `unused` counts stored edges, while `layerEdges` in `mapx check` counts findings: one per element pair and edge type. On the fixture the two agree, but the units differ, and the docs say so.
- **The legacy goldens depend on the scan.** They capture the smells and the cluster DSM of the TS fixture. A future change to clustering or smell detection on that fixture would change them legitimately. The test's purpose is the `mapx arch` command, so regenerate the goldens only for scan changes, never to accept a change to the command.
- **A name clash.** `mapx arch <dir>` where `<dir>` is named like a subcommand (`layers`, `deps`…) now runs the subcommand. Pass `--dir` or `./layers` instead. This is documented.
- **The stale-index rule.** Every subcommand except `changed` exits 4 on a stale index, unless `--sync`, as `mapx check` does. That is strict for interactive use. It was chosen so that the `unassigned` gate and `allowed` never answer from a stale index.
- **Finding outside this task.** `docs/cli-reference.md` documents `mapx arch --json`, but the command has no such option: `error: unknown option '--json'`. I left that as is, because the legacy behaviour must not change, and the owner should decide whether to implement or drop it.
- **A commit hygiene note.** The `node_modules` symlink the brief asks for is not ignored by `.gitignore`'s `node_modules/` pattern, because a symlink is not a directory. It was kept out of the commit by hand.

Changelog: `mapx arch` gains introspection subcommands (`layers --why`, `which`, `unassigned`, `deps`, `unused`, `changed`, `allowed`), each with `--format json` and AR-17 exit codes, answering which elements are in a layer and why, what is in no layer, which edges join two layers, which allowances are unused, which layers a change touches, and whether a dependency would be allowed (M5-08).
