# M0-09-R1 — Agent integration files: correctness defects

Date: 2026-10-31. P1 from the M0-41 legacy audit (I09).

## Fixed

- **`agents generate --providers=all`:** `all` in the list now means every provider. Before, it was "No valid providers specified".
- **Frontmatter at byte 0:** Cursor `.mdc` and Windsurf rules start with `---`. The sentinel block now goes *after* the frontmatter, and updates replace only the block when the frontmatter is already in place. Before, `<!-- mapx … -->` preceded `---`, which invalidated the frontmatter.
- **Edit detection that survives version changes:** sentinels now record a hash of the generated body (`<!-- mapx v0.3.5 #<sha1-12> -->`, `# mapx v… #…`). `agents update` treats a block whose content no longer matches its own hash as **edited**, whatever its version. Before, a block that was both edited and outdated counted as a clean update and was overwritten without a prompt; this is the auditor's "edited block silently overwritten" case. Blocks written before hashes existed keep the old version rule.
- **No overwrite of an edited block without consent:** without a TTY and without `--force`, `generate` and `update` skip it with a message.
- **`agents list` per-file status:** `missing`, `current`, `outdated`, `edited` or `unmanaged`, computed from the same plan `update` runs.
- **`update --dry-run`** prints the diff of clean updates.

## Not reproduced

"Text after `<!-- /mapx -->` is joined onto that line": a probe updated all 12 provider files with trailing text and every one kept it on its own line. A regression test now guards it.
