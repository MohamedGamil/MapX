# M0-04-R5 — PHP global function calls and require/include produce edges

Date: 2026-10-31. Base: `develop@0b48551` (rebased over M3-02; work started on `580546a`).

## Root cause (reproduced first)

`main.php` was written with `require_once "helpers.php"`, `include __DIR__ . '/lib/util.php'`, `require_once('helpers.php')` and calls to `helper_fmt()` / `util_join()`, both from a function and from a method. Scanning it gave zero edges. `PhpParser.parse` returned exactly one reference: `require helpers.php`, from the parenthesised form. There were three causes, at three levels:

| Level | Cause |
|---|---|
| Query | `queries/php/references.scm` had no `function_call_expression` capture, apart from `event()` / `dispatch()` for F12. Plain function calls were never references. |
| Query | The four include patterns required `(parenthesized_expression (string))`. They missed the usual `require_once "x.php";`, double-quoted strings (`encapsed_string`) and `__DIR__ . '/x.php'` (`binary_expression`). |
| Resolution | PHP has a module import resolver, so `resolveReferencesWithMap` sent `require` references to `resolvePhpImport`. That treats `helpers.php` as a namespace name and finds nothing. So even the one captured reference gave no edge. |

## Delivered

- **Query** (`queries/php/references.scm`):
  - each `require*` / `include*` statement captures its whole argument expression;
  - a new `function_call_expression` capture accepts a `name`, `qualified_name` or `relative_name` callee, but not `$callable()`.
- **Parser** (`src/parsers/languages/php.ts`):
  - **Function calls** become `call` references carrying `phpFunction`: the candidate FQNs in PHP's resolution order.
    - `\App\fmt()` → `App\fmt`.
    - `use function App\fmt [as f]` → `App\fmt`. A new `use function` table handles group and alias forms, case-insensitively.
    - `Sub\fmt()` → its first segment expanded through `use`, else prefixed with the current namespace.
    - `namespace\fmt()` → current namespace.
    - Unqualified `fmt()` in namespace `N` → `N\fmt`, then the global `fmt` (PHP's fallback). In the global namespace → `fmt`.
    - Function calls are never rewritten as facades.
  - **Includes:** string literals without interpolation or escapes, `__DIR__`, `dirname(__FILE__)`, `dirname(__DIR__)`, `.` concatenation and parentheses are evaluated.
    - A `__DIR__` path is emitted as `__DIR__/…`, and a literal as written.
    - Variables, constants, absolute paths and URLs are skipped.
- **Type** (`src/types.ts`): `ExtractedReference.phpFunction?: string[]`. It is not stored, like `vueThis`.
- **Include resolution** (`src/core/import-resolvers.ts`):
  - `resolvePhpInclude` resolves `__DIR__/x` against the including file's folder, and a plain path against that folder, then the workspace root. It returns only an indexed file other than the source.
  - The PHP resolver sends path-like targets (containing `/` or ending in `.php`, which a namespace never does) there. Namespaces still go to `resolvePhpImport`.
- **Function resolution** (`src/core/scanner.ts`, +24 lines):
  - `resolveReferencesWithMap` gains one `phpFunction` branch.
  - The new `resolvePhpFunction` takes the first candidate that a PHP file declares as a `function` symbol in exactly that namespace (from `phpNamespaces`; `''` for global), preferring the calling file.
  - It is the same rule R2 applies to classes. Methods, classes and constants are never targets.
  - `target_symbol` is the matched candidate (`helper_fmt`, `App\Support\fmt`).
  - Built-ins are declared nowhere in the workspace, so they get no edge.

## Acceptance criteria

All four tests below are in `tests/legacy-php-resolution.test.ts` › "PHP function calls and includes". They run a real `init` + `scan` on 12 files (parsed in worker threads) and assert exact, sorted `DISTINCT` edge strings.

1. **Met.** Test: "links global function calls to the declaring file, from functions and methods". The `call` edges from `main.php` are exactly:
   - `run → helpers.php#helper_fmt`;
   - `Runner::go → helpers.php#helper_fmt`;
   - `run → lib/util.php#util_join`.

   `strlen`, `implode` and `array_map` give nothing. `count([])` does not link to the method `Runner::count`.
2. **Met.** Test: "links require and include, in every form, to the resolved file". The edges are exactly:
   - `main.php → helpers.php` (from `require_once "helpers.php"`);
   - `main.php → bootstrap/boot.php` (from `require_once('bootstrap/boot.php')`);
   - `main.php → lib/util.php` (from `include __DIR__ . "/lib/util.php"`);
   - `public/index.php → bootstrap/boot.php` (from `require dirname(__DIR__) . '/bootstrap/boot.php'`).

   `require __DIR__ . '/../missing.php'` gives none.

   **Note on edge type:** these edges keep the parser's `require` type rather than `import`. `require` is the import-family type Ruby and Lua already emit, and the impact analyser, role classifier and cluster engine treat it like `import`. The criterion says "import edge". If `import` is wanted literally, it is a one-line change in `php.ts`.
3. **Met.** Test: "resolves namespaced functions by namespace only, with the global fallback for unqualified names". The fixture declares `fmt` in `App\Support` and in `App\Other`, a global `fallback` and `local_only`, `App\Other\local_only`, and a method `App\Formatter::fmt`.
   - `use function App\Support\fmt; fmt()`, the alias `format()` and `\App\Support\fmt()` each link only to `app/Support/functions.php#App\Support\fmt`.
   - `fallback()` in `App\Http` falls back to the global `app/global.php#fallback`.
   - In `App\Other`, unqualified `fmt()`, `local_only()` and `namespace\fmt()` link to `App\Other`'s own functions, not to the global `local_only`.
   - The method `Formatter::fmt` is never a target.
   - Built-ins are covered in test 1.

   An extra test, "gives the same call and require edges when parsed on the main thread", rescans with `--force --no-parallel` and expects identical edges.
4. **Met.** The routes scorer output is byte-identical (below).

## Mutation check

The script is `mutate-r5.mjs` in the session scratchpad. Each mutation was applied alone, the new describe block was run, and the file was restored.

| Mutation | Failing tests |
|---|---|
| `function_call_expression` capture removed | calls; namespaced |
| `require_once` needs parentheses again | require/include |
| `__DIR__` not evaluated | require/include |
| PHP `require` sent to the namespace resolver again | require/include |
| Function namespace check removed | namespaced |
| No global fallback | namespaced |

On the first run, two mutations survived ("parentheses again" and "use function ignored") because the fixture masked them:

- `require_once('helpers.php')` produced the same `DISTINCT` edge as the unparenthesised form;
- `\App\Support\fmt()` in the same method produced the same edge as `fmt()`.

The fixture now gives each form its own target or method, and all 8 mutations fail.

## Limitations

- `use function App\fmt;` gets no `import` edge itself: `resolvePhpImport` resolves `use` lines to types only, as in R2. The call edges carry the link.
- `include` through `include_path`, constants (`APP_ROOT . '/x.php'`), variables and string callables (`call_user_func('fmt')`, `array_map('fmt', …)`) are not resolved.
- The current namespace comes from the file's first `namespace` declaration, as for classes. Files with several `namespace { }` blocks use the first.
- When the same global function is declared in several files (guarded polyfills), the calling file wins, otherwise the first path in sort order.

Changelog: PHP calls to plain and namespaced functions now link to the file that declares the function, and `require` / `include` statements (with or without parentheses, including `__DIR__ . '/…'`) link to the included file (M0-04-R5).
