# M4-03 — Scanner: remove quadratic phases (name resolution, resume state, fileMap rebuilds)

Date: 2026-11-01. Base: `develop@a4bd752`. Owner: claude. Iteration: `docs/baton/iterations/M4-03.md`.

## Measured cause

On a generated TypeScript workspace, a scan took 17.9 s at 8,000 files and 70.5 s at 16,000 (×3.9). In the workspace, each `src/d<i%50>/m<i>.ts` imports and calls two other files' functions, and declares a class with methods `run` and `helper`.

A CPU profile of the forced 16,000-file scan attributed 52.7 s of 85.6 s to `resolveSymbolToFile`, including 13.7 s in `languageOf` lookups. For every call to a name declared in k files, it did O(k) work (case filter, language filter, sort, `closest`) before checking the caller's own file. That is O(N²) when a name is common to every file. The spec 10 items, resume-state rewrites and `fileMap` rebuilds, did not appear in the profile.

## Delivered

- **`resolveSymbolToFile`, symbol-index path, `src/core/scanner.ts`.**
  - The name-only part is memoised per name, source language and `callableOnly`, in `nameCandidates`. That part covers the case-matched and language-compatible candidates, the files declaring the exact name, and the sorted candidate files.
  - The memo belongs to the symbol index it was built from (`nameCandidatesFor`), so a new index (phase) or one replaced in a test starts it empty.
  - A call then checks its own file with a `Set`, and gets the nearest candidate from `nearestIndex`. Lists of at most 16 files use `closest` directly.
  - The PHP namespaced branch is computed per call from the memoised candidates.
  - `releaseSymbolIndex` drops the index and its memo when a phase ends, so a long-lived (watch or MCP) scanner does not keep them between scans.
  - The extension list became the module constant `COMMON_EXTENSIONS`.
- **`nearestIndex(hits)`, `src/core/import-resolvers.ts`.** It maps each leading directory prefix to the first hit under it. The deepest prefix of the source present in the map gives the hit `closest` would return: the most shared leading directories, then input order.
- **Resume state.**
  - `scan_resume_state:<repo>` is written once, when parsing starts, with the files already complete.
  - Each resolved batch writes `scan_resume_batch:<k>:<repo>` with its own files, symbols and edges.
  - `loadResumeState` concatenates the records. `saveResumeState` (the start of a scan) and `clearResumeState` delete them with the new `Store.deleteMeta`.
  - Each clear runs in one transaction with the header write. It deletes every record the header's `totalFiles` allows, gaps included, and both loops are bounded by that count.
  - The keys end in `:<repo>`, so `removeRepo`'s meta cleanup removes them.
- **Removed:**
  - the `workspaceFileMap` rebuild in `_scanFullForRepo` and in `writeParseResult`;
  - the dead `resolveReferences`. It had no caller, and its one coverage test now calls `resolveReferencesWithMap` with the same symbols.
- **`scripts/bench/scan-scaling.ts`:** a generator plus timed real scans at the given sizes; `--max-ratio`; `--json`.
- **`tests/scan-scaling.test.ts`:** 6 tests.
- **Root `CHANGELOG.md`:** an Unreleased entry.

## Independent review

One fresh agent reviewed the change, given the criteria and the code. It worked in its own copy and changed nothing in the checkout. It found no P0 or P1.

It confirmed the following:
- **Memo invalidation:** the memo follows the index's identity. No index is changed after it is built, and second-pass, sync and watch/MCP scanners all rebuild it.
- **Cache key:** complete.
- **`nearestIndex`:** equivalent to `closest` by argument, and by its own 200,000-case property test with absolute paths, empty, `.` and `..` segments, duplicates and unsorted input.
- **Resume:** semantics equal the old ones. It checked a double interruption, an old single-key database, and `deleteRepo`.
- **Removed fallbacks:** unreachable.
- **Identical results, with its own dumps (line numbers, metadata, target repo):**
  - MapX self-scan: 8,354 edges and 2,552 symbols;
  - the three fixtures;
  - a 360-file mixed-language stress workspace (TS, JS, Python, PHP namespaces, Go, Pascal case folding, shebang scripts, more than 16 candidates, `config` as a constant, a variable and a function);
  - a two-repo scan followed by two syncs on one `Scanner`.
- **Benchmark ratio:** 1.72 at load average 46.

Its P2s, all fixed:
1. **The memo kept the last index alive after a scan.** `releaseSymbolIndex` now clears it; tested and mutation-checked (M6).
2. **Clearing was not atomic and stopped at the first gap.** A killed clear could strand records that a later resume would read. Clearing now runs in one transaction with the header write and is bounded by the header's `totalFiles`, gaps included; tested and mutation-checked (M5).
3. **Unbounded `getMeta` loops** would hang on a mock that answers every key. Both loops are now bounded.
4. **A wrong comment** said `phpNamespaces` fills during writes; it fills in `buildSymbolIndex`. The comment is corrected. The PHP branch is still computed per call, which is harmless.
5. **A stale comment** in `tests/scanner-coverage.test.ts` was removed.
6. **Byte equality is not checked in CI**, only the floors. Recorded as a limitation.

## Limitations

- **Other `symbolIndex` users.** The Vue global registry lookups (`symbolIndex.get` in the Vue and Go helpers) still filter per call. They did not appear in the profile of the generated workspace.
- **Duplicate walk.** `scanFull` walks the directory twice (once to fill `workspaceFileMap`, once in `_scanFullForRepo`). That belongs to M4-04.
- **The benchmark depends on machine load.** It is a manual measurement, not a CI test.
- **Byte equality is not checked in CI.** CI checks the floors (`npm run eval`) and the fixture tests. Byte-identical edges rest on the manual dumps above and the reviewer's.
- **Constant batch size needs equal path lengths.** The size of a batch record grows with its paths, and the test uses fixed-width paths on purpose.
