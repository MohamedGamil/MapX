## Limitations

- **Value-symbol languages.** The call-target filter applies only to JavaScript, TypeScript and Python constants and variables. These are the kinds M0-17-R1 added, and function-valued declarators there are `function` symbols. In other languages a `constant` can be callable, so those stay targets: C function-like macros (`preproc_function_def`), Rust tuple variants, Lua `local f = function…` and Bash aliases. A callable JS constant such as `const debug = require('debug')('x')` no longer gets a call edge. That matches the behaviour before M0-17-R1.
- **C#.** The rule is still a naming heuristic. An interface named `I…Exception`, or a class `IUIHandler` placed first in the base list, is misclassified.
- **C++.** Qualifiers are handled up to three levels deep (`A::B::C::f`). The owner is the innermost qualifier. A namespaced free function `void ns::f() {}` is still recorded as a method of `ns`, because the grammar cannot tell a namespace from a class there. This behaviour predates M0-17-R1.
- **JS built-in receivers.** These are matched by identifier name. A local variable named `process` or `document` that shadows the built-in loses its inferred member-call edges.
- **Found outside scope, not fixed:**
  - `export let x` / `export var x` produce no JS symbol, although `export const` does (M0-17-R1 gap).
  - A local `const f = () => …` inside a function becomes a top-level `function` symbol (predates M0-17-R1).
  - Java, Kotlin and TypeScript generic bases (`extends Base<T>`) are not captured at all.

Changelog: Calls no longer link to JS/Python constants or variables, or from built-in objects (`Math.max()`) to user functions. C++ out-of-line methods with template or nested qualifiers, C# exception and generic base classes, and Go qualified embedded structs are extracted correctly, and DOT dashes a file pair only when none of its edges is verified (M0-17-R2).
