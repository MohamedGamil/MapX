# M2-08-R4 report: sync follows a file turning from module to script

Found by M2-08-R3 (Limitations): "a module that becomes a script, or gains `declare global` names, does not re-parse files that may now reach those names by name."

## Cause

`globalScopeReferrers` re-parses the files with edges *into* a changed JS/TS file when its recorded `globalScope` differs. The files that should *gain* an edge have none yet, and the store kept no trace of the name they looked for: a reference that resolved nowhere makes no edge, and `external_ref_candidates` holds only names bound by an import from outside the project.

Probe on `develop@b6a7103` (code from `git archive HEAD`, real CLI, `scan` then edit then `sync`, hash and git modes): `legacy/plain.ts` (`export function plainGlobal()`) and `g/decl.ts` (`export {}; function declared()`) were edited into scripts; `legacy/use.ts` and `g/use.ts` call the names with no import. Both modes: `sync` said "Updated 2 files … 0 edges updated" and the index had no cross-file edge; `scan --force` then gave both (`usePlain -> plain.ts#plainGlobal`, `useDecl -> decl.ts#declared`). The same probe on the fixed code: sync gives both edges, equal to `scan --force` (hash: "Updated 4 files … 2 edges updated").

## Delivered

- `src/core/scanner.ts`:
  - `globalScopeFilter` records, per parse, each bare name that reaches its last branch (an ES module's name it neither imports, declares, nor gets from an auto-import tool) in `globalNameRefs`. `writeParseResultWithMap` writes it to `files.metadata.globalNameRefs` (sorted, omitted when empty; the file row is replaced by every re-parse).
  - `globalScopeReferrers` also collects the names a changed file gained and adds every file whose `globalNameRefs` holds one of them. It runs inside `importerReferrers`, so scan-incremental, git sync and hash sync all get it.
  - `localNamesOf` uses the new `declaredLocalNames`.
- `src/core/js-source.ts`: `gainedGlobalNames(recorded, js)` and an extended `declaredGlobalNames`:
  - now a script: every identifier in its text (a superset of its symbols: second declarators of `var a, b`, class and object-literal methods, member assignments). The sync runs before the file is parsed, so a symbol list was not available; this needs no parse;
  - a module: the `declare global` names the recorded key lacks, all of them after a script;
  - `declaredGlobalNames` reads every declarator of a `const`/`let`/`var` list inside `declare global` and `function *gen`. This changes `scan` too (a `declare global { var a, b }` now makes `b` global), covered by the extractor version bump.
- `src/core/extractor-version.ts`: 24 -> 25 with a history line, since unchanged files of an older index have no `globalNameRefs`.
- `tests/import-bound-externals.test.ts`: `describe.each` for git and hash sync, 8 tests each (16 in all), plus a unit test of `declaredGlobalNames`.
- `CHANGELOG.md` entry; `docs/baton/iterations/M2-08-R4.md`.
- TASKS.json planning fields sharpened (description, outputs, affectedFiles, acceptanceCriteria, verificationCommands incl. `npm run check`).

### Cost trade-off

- Nothing is added when no changed JS/TS file's global-scope key changed (the common case).
- When a changed file gained names: one `LIKE '%"globalNameRefs"%'` scan of `files.metadata` (the `newModuleReferrers` / `unresolvedImports` shape) plus a JSON parse of the matching rows. Only files recording a gained name re-parse; the workspace never re-parses as a whole. The test counts it: a bystander recording another un-imported name is left alone ("Updated 2 files").
- Storage: a short JSON array on each ES module that references un-imported, un-declared bare names (empty for most files).
- A file turned script gains every identifier of its text, so a file recording a name the script merely uses re-parses for nothing: an extra parse, never a wrong edge, and a module becoming a script is rare.

## Limitations

- **A new declaration in any file, and a rename or move into a script** (a new script, a global function added to an existing script, a `declare global` in a new file, `git mv` plus dropped exports) do not re-parse the files that name it; `scan --force` does. The record now exists to serve it: M2-08-R9.
- **A name reached through a base class in another file** (`resolveClassName` with the base's file) is not recorded in `globalNameRefs`.
- **Sync, other inputs** (a bare specifier becoming a workspace package, a new file under `baseUrl`): unchanged from M2-08-R3.
- **Over-inclusive gain** for a file turned script: every identifier counts, so a referrer sharing a name the script only uses re-parses without gaining an edge.
- **Found, not fixed:** `Scanner.localNamesOf` (M2-08-R3) still captures only the first declarator of `var a = 1, b = 2` and misses `function *gen`; changing it would change resolution, so it is left for its own task.
- **Not covered by a test:** the version bump itself (an older index re-parses once) is checked only by the existing index-version tests, not by one for 25.
