# M1-09 — Route line numbers, symbol targets and middleware metadata

Date: 2026-10-30. Delivered together with M1-02 … M1-09 as one detector rework (`src/frameworks/detectors/laravel.ts`, the new `laravel-mounts.ts`, and the scanner's route pass). This report covers this task's part.

## Delivered

- `RouteBinding.line` (1-based) is set for every Laravel route. `metadata` carries `name` (`->name()` or `as`), `reachable`, `overridden`/`overriddenBy`, `conditional`, `dynamic`, `order` and `mountedBy`.
- `toRouteView()` (`route-registry.ts`) normalises these for `mapx routes --json` and `mapx_routes`, so `line`, `name`, `middlewares`, `reachable`, `overridden` and `conditional` are on every route. The text table flags unreachable, overridden and conditional routes.
- Route edges keep `line`, `name`, middlewares (falling back to `metadata.middlewares`) and the flags.
- The edge target was already the controller file plus `targetSymbol` (handler) whenever the handler resolves.
- The original claim that Laravel edges lost middlewares was wrong, and has been withdrawn in the review.

## Acceptance

1. `mapx routes --json` includes line, reachable, overridden, conditional, name and middlewares per route.
2. Every Laravel route edge in the store has metadata.line, and keeps its middlewares (asserted for a route inside an auth group mounted by require).
3. The M1-01 scorer shows no regression in any other pattern.

All are met. They are covered by `tests/laravel-mounts.test.ts` (end-to-end scans through the real CLI) and by the M1-01 fixture, now with floors at 100% and exact parameter names.
