# M1-05-R1 — Laravel resources: array options, nested and plural registration; array handler attributes

Date: 2026-10-31. Remediation for the review `reviews/REVIEW-2026-10-31-fb75474ba377.md` (M1-05 DEFECTIVE, P2). Built on develop after M1-03-R1 and M1-07-R1; rebased onto develop 8db1e0f.

## Ground truth

The expected route lists come from Laravel's own router, not from reading its source. A scratch oracle script (session scratchpad, `m105r1/oracle/oracle.php`) loads the vendored `laravel/framework` 12.70.2 (`Illuminate\Routing`, read-only), registers a synthetic route file inside an `api` group and prints method, URI, name, action and middleware for every route. The e2e expectation and the new fixture labels were copied from its output. No application code was used.

The oracle also showed Laravel behaviour that the old detector got wrong and that this task now models:

- `Route::prefix('x')->resource(...)`, `Route::namespace(...)->resource(...)` and `Route::domain(...)->resource(...)` ignore the chained attribute. RouteRegistrar passes `$this->attributes + $options` to the resource, and ResourceRegistrar reads only `as` and `middleware` from them.
- `apiResource()->only([...])` replaces the API default, so `only(['index', 'create'])` registers `create`.
- `->middleware()` on a resource replaces its `middleware` option; an attribute set before the verb wins over the options array.
- An unnamed route in a named group is named with the bare prefix (`admin.`). `Route::name('admin.')->resource('docs')` gives `admin..docs.index`, and the code reproduces that.

## Delivered (`src/frameworks/detectors/laravel.ts`)

- **Options arrays.** `phpArrayEntries` parses PHP array literals (`[...]` and `array(...)`). `parseResourceOptions` reads `only`, `except`, `parameters`, `names` (one string or a per-action map), `as`, `middleware` and `shallow` from the third argument of `resource`/`apiResource` and the second argument of `resources`/`apiResources`. Chained `->names()`, `->name($action, $name)`, `->shallow()` and `->middleware()` are applied the way PendingResourceRegistration applies them.
- **`expandResourceRoute` follows ResourceRegistrar.** Everything before the last `/` becomes a URI prefix. `a.b` expands to `a/{a}/b/{b}` without the last wildcard. Every segment's wildcard is its `parameters` entry or its singular, with `-` replaced by `_`. `shallow` drops the parents from member routes and their names. Actions follow Laravel's default order, apiResource's `only` default is modelled, and each route gets its name: `[as.]<name>.<action>` or the `names` override, behind the group name prefix. Middleware is group middleware followed by the resource's `middleware` option.
- **`Route::resources([...])` / `apiResources([...])`.** One resource per `name => controller` entry, where the controller is `Foo::class` or a string, and all entries share the options array. Confidence is `declared` for each `::class` controller. Before this, the call emitted nothing without a second argument, and with one it took the options array for a controller.
- **Action arrays.** `['as' => …, 'middleware' => …, 'uses' => …]` is parsed from the handler argument itself; the old code searched every argument of the chain. Without `uses`, the handler is the first positional callable (`RouteAction::findCallable`): a closure or `[C::class, 'm']`. Middleware order is group, then action, then chained.
- **Route names.** A name is built from the group prefixes, then the action's `as` (or a `->name()` set before the verb), then every `->name()` after it. Group frames carry `names` from `Route::name()/as()->group(...)` and `'as' =>` in group arrays. The names are pushed on the walker's group stack, recorded on mount frames (`RouteMount.names`) and returned by `chainAttributes`, so a name prefix reaches files loaded by `require`, `->group(<path>)` and provider mounts. The walker no longer overwrites names with the first `->name()` argument.
- `listArg` accepts `array(...)`.

## Limitations

- `update` stays two routes (PUT, PATCH) rather than Laravel's single `PUT|PATCH` route. See above.
- Not modelled: `Route::singleton`/`apiSingleton`, `->scoped()` binding fields, `middlewareFor`/`withoutMiddleware`/`excluded_middleware`, `'prefix'` and `'domain'` keys inside a single route's action array, `Route::resourceParameters()` and global `ResourceRegistrar::verbs()` overrides, an action array's `middleware` overriding a `Route::middleware()` attribute set before the verb, and variadic `->middleware('a', 'b')`.
- `RouteServiceProvider` routes that no mount reaches still fall back to the legacy `routeServiceProvider.routes` defaults, which carry no name prefix.
- The oracle depends on a local vendored Laravel and is not part of the repository; its output is frozen into the test's `EXPECTED`.

Changelog: Laravel resource routes now honour options arrays (`only`, `except`, `parameters`, `names`, `as`, `middleware`, `shallow`), nested `photos.comments` and shallow resources, `Route::resources([...])`/`apiResources([...])`, carry Laravel's route names, and group name prefixes and action arrays without `uses` keep route names and middleware (M1-05-R1).
