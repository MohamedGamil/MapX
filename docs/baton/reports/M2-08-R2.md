# M2-08-R2 report: sync re-links imports a new module satisfies or shadows

Found while doing M2-08-R1 (pre-existing), with a related case from its review: a module that sync adds can change what an existing import resolves to. Because the importer was not re-parsed, its call kept the name-lookup target, or the folder index's declaration, until `scan --force`.

## Delivered

- **Recording:** while a file's references resolve, `resolveImportPath` records each relative or alias import that no indexed file satisfies, as a module path with the extension stripped (`src/lib/missing`). `writeParseResultWithMap` keeps the list in `files.metadata.unresolvedImports`; every re-parse starts from an upsert that resets the metadata.
- **`newModuleReferrers`:** for each new JS/TS/Vue/Svelte module it collects:
  - the files whose record names its path, or its folder when it is an `index` file;
  - the importers of each indexed module of the same path the new one may now win over: another extension, and for a non-index file the folder's `index.*`;
  - through barrels among those files, their importers, up to five levels.

  It reads every record once per call. The full path, the git sync and the hash sync add these files to their referrers.
- **Asset imports** (`.svg`, `.css`, `.json` and the like) are not recorded.
- **`Store.filesWithMetadataText`:** a `LIKE` pre-filter; each match is confirmed by parsing its metadata.

## Independent review

A fresh agent got the diff, without these conclusions. Each scenario ran scan, then the change, sync and `scan --force`, and diffed all edges. It found these clean: `./m.js` resolving to `m.ts`, tsconfig and `@/` aliases, Vue and Svelte importers, multi-repo workspaces, renames, `require`, dynamic `import()`, delete-and-re-add cycles, and record clearing. It also confirmed that `LIKE` cannot give false positives.

## Limitations

- **Python, and bare package specifiers:** out of scope.
- **Older indexes:** a file parsed before this change has no record. This task bumps `EXTRACTOR_VERSION` to 2, which also covers the M0-12-R11 and M1-07-R3 extraction changes, so the next sync re-parses every file once and creates the records (M5-26).
