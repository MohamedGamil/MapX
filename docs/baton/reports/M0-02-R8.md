## Limitations

- A name still present in the changed file's text, for example in a comment, is not counted as removed.
- A root `package.json` change re-parses every JS/TS/Vue file of the repo once.

Second review round (reviewer O):
- **P1, fixed.** A renamed function named like an `Object.prototype` member (`toString`) crashed every incremental scan, because the record's spread read the inherited function.
  - **Fix.** The record is read through own keys only (`Object.hasOwn`).
  - **Test.** "handles a renamed function named like an Object.prototype member (toString)". The mutation fails it.
- **P2, fixed.** The vanished-names record never shrank. Referrers since deleted now leave it, and a name without referrers goes with them.
- **P2, documented.**
  - A renamed name that survives as a word elsewhere in the file (a comment, a string, a key) is not counted as gone, so its callers keep the old edge until a force scan.
  - A later mention of a vanished name re-parses its referrers, which costs a parse and gives the same edges.
