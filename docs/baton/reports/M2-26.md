# M2-26 — A class destructured from a call result never links a same-named class elsewhere

Worktree branch `worktree-agent-adf7c89ff0a9af4a0`, on develop `97faf80`, after M2-25.

## Delivered

M2-25 and M2-26 share one mechanism (`boundLocally` in `src/parsers/generic-wasm-parser.ts`), so the code for both (`sourceBinding`, `declarationBinding`) is in M2-25's commit (extractor version 22, no 23: nothing changed after it). This commit holds M2-26's tests and this report.

A name destructured from a call result is local, and gets no edge, only when the call provably reaches no project symbol: it is given a package or builtin specifier (`const { Database } = load('bun:sqlite')`, `const [Database] = load('node:worker_threads')`), or its callee is imported from a package. In a function and at module level, `new Database()` and `render()` get no edge to `other/Database.ts#Database` or `other/ui.ts#render`. Anything else keeps the by-name edge, marked inferred (`const { render } = load()`, `this.service`, a local variable, a function of the file, `new Builder()`), after the integration owner's review: dropping those lost true edges. Names bound by an import stay the import's: an imported class or function, `require('../other/Database')` and `await import('../other/Database')` of a project module, and `const { build } = make()` with `make` imported (relied on by `tests/vue-stores.test.ts`) still link.

## Limitations

- `const { render } = load()` (a call with no package specifier) is not provably external, so it keeps an inferred by-name edge; the task text expected none. Only a verified edge is gone. This follows the review rule (same principle as M2-12).
- A destructuring from the result of an imported function of a package is local only when the import is a package-looking specifier (one segment, scoped, scheme, Node builtin).
- Destructured parameters are unchanged.
