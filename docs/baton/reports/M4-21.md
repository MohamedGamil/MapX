# M4-21 — Multi-repo workspaces in the dashboard

Decision D027. Before this task, the dashboard read only the primary repo for clusters, the profile, smells, the DSM and metrics, and had no repo switcher.

## Delivered

**API (`src/ui-server.ts`)**
- **`/api/repos`:** every registered repo, from `summarizeRepos` (the same as `mapx workspaces`): name, path, type, files, symbols, edges, cross-repo edges, last scan time and HEAD. It adds `git: { isGit, head, changesSinceScan }`, counting indexable changes since the repo's last scan as `mapx status` does, plus the cross-repo pairs.
- **`repo=` parameter:** `repoScope(param, config, fallback)` parses it, and `scopeOf` answers 404 for an unknown repo and 400 for `all` on a per-repo view. Defaults:
  - graph, symbols and routes default to every repo, as before;
  - clusters and smells take `all`;
  - profile, DSM and metrics are per repo, defaulting to the primary repo, as before.

  The table is in `docs/cli-reference.md`.
- **Graph:** one repo's graph holds its own files and the edges between them. File nodes carry `repo`; edges into another repo carry `crossRepo`, `repo` and `targetRepo`.
- **Routes:** filtered by the repo they were found in (`metadata.repo`; older entries count as the primary repo).
- **Metrics:** now per repo throughout. They mixed whole-store totals, top files, kinds, edge types and languages with the primary repo's file rows and graph metrics.

**Dashboard**
- **Switcher:** shown when there is more than one repo, with "All repos (n)" plus each repo. The choice is kept in the URL (`?repo=`, `history.replaceState`) and survives a reload. An unknown repo in the URL falls back to all.
- **Switching** reloads the graph, symbols (from the first page), routes and metrics, the architecture views once opened, and the sidebar figures (the chosen repo's).
- **Workspace tab:** a repo table (a name switches to that repo; the current repo is highlighted) and the cross-repo pairs with counts and edge types.
- **Scope note:** with all repos chosen, the per-repo views (Architecture, Metrics) say they show the primary repo.
- **Cross-repo edges** are dashed, pink and drawn above other edges.
- **Escaping:** the new templates pass `scripts/ui/check-escaping.ts`.

**Found and fixed on the way**
- **M2-06-R3** (its own commit, `cbd766e`): `http` edges between repos had no `target_repo`, so the web → api calls were not cross-repo edges anywhere.
- **Cluster memberships:** `/api/clusters` sent rows with `file_path`/`cluster_name`, while the dashboard reads `filePath`/`clusterName`. Community grouping and the layer lookup never matched and fell back to directories. The rows now carry both spellings. The Clusters Map's per-file membership scan, quadratic, became one map built once.

**Fixture:** `multiRepoWorkspace` / `initAndScanMultiRepo` (`scripts/ui/workspace.ts`), all synthetic:
- the primary repo: 2 TypeScript files;
- `web`: Vue and TypeScript calling the backend with axios, 3 files, its own git checkout;
- `api`: Laravel with 4 routes, a controller and a service, 4 files, its own git checkout.

## Post-acceptance defects (independent review, 2026-11-02)

A fresh agent reviewed `cbd766e`, `9aad1b7`, `3553837` and `bf534ee` in its own worktree. All 42 browser tests passed there. On M4-21 it found two P1s and one P2, all reproduced. Each fix has a test, and each was mutation-checked.

| Finding | Fix | Test (fails under the mutation) |
| --- | --- | --- |
| **P1** An unknown `?repo=` (mistyped, or a repo removed since) left every view on its 404: the switcher reset to All without reloading | `loadRepos` falls back to all repos and reloads | workspace: `?repo=nope` → switcher All, URL clean, 9 files drawn, symbols listed |
| **P1** A fast switch (web, then api) let web's late responses render last: sidebar api, graph and metrics web | `repoGeneration`: each repo-scoped loader drops a response that arrives after a newer choice | workspace: web's graph, metrics and symbols delayed 2.5 s, then api chosen → 4 api files, metrics 4, symbols only `api/` |
| P2 In All, each repo's `community_1` merged into one group with a borrowed label | communities keyed by repo (`community_1@web`); the label names the repo when there are several | (no canvas hook; by code) |

**Not changed (P2):**
- **Handler links:** from the HTTP tab under a repo scope, a handler badge in another repo opens a graph that does not draw that file.
- **Scoped graphs** drop cross-repo edges.
- **`all`:** a repo literally named `all` cannot be chosen.
- **CORS:** the existing `Access-Control-Allow-Origin: *` without a token also exposes the new endpoints to other origins. This predates M4-21.

**Also found while verifying these fixes:** a repo switch reloads the graph, and `loadGraph` reset the view to Clusters Map every time. So a view chosen during the reload, or before it (Full Codebase, then switch repo), was replaced: the switcher test intermittently counted 2 cluster nodes instead of 3 files. Reloads now keep the chosen view, and a repo switch clears the cluster drill-down and focus seed. The switcher test asserts that the Full Codebase view survives a switch.
