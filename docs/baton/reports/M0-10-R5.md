# M0-10-R5 — scan and sync with no repo named cover every registered repo

## Defect (owner report, 2026-11-01)

The owner tested the installed `v0.3.7` binary in a workspace whose `.mapx/config.json` registers three repos: the root repo, and the nested git repos `backend/` and `frontend/`. Running `mapx scan --force` at the root did not refresh either nested repo, and the rebuilt index held 8 files.

**Cause.** With neither `--repo` nor `--all`, `Scanner.scanFull` and `scanIncremental` covered only `config.repos[0]`, the root repo. The root walk skips nested repos, so the result was 8 root files.

**Reading of the owner's index** (read-only):
- **Files:** 8 files, all of repo `majles`.
- **Missing rows:** none for `backend` or `frontend`. Their earlier rows had been indexed under the root repo, as `backend/...` paths in the October MCP log, before `init` registered them separately at 15:57. `scan --force` reset the root repo, which removed those rows, and did not scan the newly registered repos.
- **Pages:** 32,324 of 32,360 pages free.

The decision is D024.

## Delivered

- **Default scope** (`src/core/scanner.ts`, `reposToScan`):
  - With no repo named, or `all`, every registered repo is covered. This applies to `mapx scan`, `mapx sync`, `mapx_scan` and `mapx_sync`.
  - `--repo` / `repo` still names a single repo.
- **Missing folders.** A registered repo whose folder is missing is skipped with a warning (`[mapx] Skipped repo <name>: its folder <path> does not exist…`), and its index rows are kept. This came from the review; see P1 below.
- **Help text:** the CLI `--repo`/`--all` options and the MCP `repo`/`all` schema text describe the default.
- **Docs:** `docs/cli-reference.md` (scan, sync, multi-repo notes) and `docs/mcp-integration.md` (`repo`/`all` for `mapx_scan`/`mapx_sync`).
- **Changed test:** `tests/legacy-globs.test.ts` ("keeps a registered folder repo… after a plain sync") assumed that a plain sync covered only the primary repo.
  - The primary-only step now names the repo with `--repo`, and still asserts that the nested repo's files stay with that repo.
  - The plain sync now expects the nested repo's added file.
- **Changed mock:** `tests/scanner.test.ts` (stale lock) used a mocked `existsSync` that answered `false` for the repo's own folder. It now answers `true`; otherwise the missing-folder skip dropped the repo.

## Verification

| Command | Exit | Result |

| `npx vitest run tests/workspace-default-scope.test.ts` | 0 | 5 passed |
| `npm run check` | 0 | 106 files; 1,866 passed, 1 skipped (run with M0-06-R2's changes in the tree) |

`tests/workspace-default-scope.test.ts` works on a real CLI workspace: a root repo with two nested git repos registered through `workspaces add`.
- **`scan --force` at the root, no flags:** picks up edits in both nested repos. Its files, symbols and edges for all three repos equal those of `scan --all` on a fresh index.
- **Plain `scan` and plain `sync` at the root:** pick up a nested repo's edits.
- **`--repo frontend`:** leaves both `backend` and the root repo untouched.
- **MCP:** `mapx_sync` and `mapx_scan` with no `repo` cover the nested repos.
- **Folder moved away:** plain `sync` and `scan --force` exit 0 and warn. They index the other repos, and keep the moved repo's file rows unchanged.

**Mutation checks:**
- Restoring the `[config.repos[0].name]` default fails 3 of the first 4 tests. The `--repo` test is a guard and passes either way.
- With the missing-folder skip disabled, the moved-folder test fails with `ENOENT: scandir …/frontend`.

## Independent review (fresh agent, 2026-11-01)

The reviewer confirmed all three criteria, the tests and CLI/MCP/doc parity. Findings:
- **P1, fixed.** One registered repo missing on disk made every plain scan and sync exit 1 with ENOENT, the root repo included. Under the old default only `--all` failed this way. Fixed by the skip above, with a regression test.
- **P2, fixed.** The `--repo` test now also asserts that the root repo is untouched.
- **P2, fixed.** `docs/cli-reference.md` "With `--all`…" lines now say "the default, or `--all`".
- **P2, accepted.** A plain `scan --force` costs what `scan --all` costs, including the multi-repo second pass (`queueEarlyParsed`). For the reviewer's three-repo copy, that was 10.5–11.2 s, against 7.7–9.6 s for three `--repo` runs. This is the documented order-independence of `--all`.
- **P2, open.** `mapx status` without `--all`, and `mapx_status`, still report changed files for the primary repo only. The result is consistent and not wrong, but it differs from the new sync default.

## Limitations

- An index that had nested-repo files under the root repo, from before they were registered, still loses those rows on the root repo's reset. What changed is that the nested repos are now scanned in the same run, so their files come back under their own repos.
- The owner's workspace has not been rescanned here: other projects are not touched. Running `mapx scan --force` in `~/majles` with a build containing this fix re-indexes all three repos.
