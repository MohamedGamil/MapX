# M4-09-R5 report: no test leaves temp folders, and each run checks it

Spec: [iterations/M4-09-R5.md](../iterations/M4-09-R5.md). Started from `develop@f417439`; the change is uncommitted at the time of writing.

## Cause (measured before any change)

Both suites were run with a short private `TMPDIR` and what remained was listed.

| Run | Result | Left in the private TMPDIR |
| --- | --- | --- |
| `TMPDIR=<~120-character path> npx vitest run` | exit 1, 7 failed | `tmp.*`; the failures were `node:net:2368`: tsx puts a unix socket in `$TMPDIR` and the path was too long (limit ~107 bytes). The private folder must be short. |
| `TMPDIR=/tmp/m5t1 npx vitest run` | exit 0, 156 files, 3,235 passed, 4 skipped | `tmp.DmaaLZhlFL/mapx-9.9.9` only |
| `TMPDIR=/tmp/m5t2 npm run test:ui` | exit 1, 47 passed, 1 failed, 6 not run (`arch.spec.ts:85`, also failing without the private TMPDIR) | nothing |
| `npm run check`, later, with the vitest teardown in and `test:skills` unchanged | exit 0 | `baton-review-test-*` x4 and `baton-scan-*` x2, from `npm run test:skills` |

So a passing run leaked from two places, and neither is a `mapx-arch-*`, `mapx-e2e-*` or `mapx-bench-*` folder:
- **`tests/installer-replace.test.ts`** runs the self-extracting installer of `scripts/make-installer.sh`. The installer unpacks the archive into `mktemp -d` and then `exec`s `install.sh`, which drops its EXIT trap, so the folder stays. This is also a bug for real users of `mapx-*-installer.sh` (found, not fixed, see below).
- **`.claude/skills/baton/scripts/baton-scan.test.mjs` and `.claude/skills/baton-review/scripts/review-scope.test.mjs`** (`npm run test:skills`, half of `npm run check`) never removed their folders. They are the largest groups in the shared `/tmp` (1,984 `baton-review-test-*`, 1,206 `baton-scan-*` of 15,600 entries).

The `mapx-arch-*`, `mapx-e2e-*`, `mapx-extrefs-*` and `playwright-artifacts-*` folders of the 2026-11-03 finding do not come from a passing run on this tree: the tests that make them remove them (M4-09-R2, M4-09-R3). They accumulate when a test fails before its cleanup, or a run is interrupted, because `afterEach`/`afterAll` do not run. That is what the private folder fixes: it is removed whole.

The interrupted case was measured: SIGINT on `npx vitest run tests/arch-since.test.ts` (private TMPDIR) left `mapx-cli-*` (the built-CLI mirror), `mapx-e2e-*` and `mapx-arch-since-out-*`.

## Delivered

**Approach: a private temp folder per run, not a snapshot.** Other agent sessions and test runs create `mapx-*` folders in the shared `/tmp` at the same time, it held 15,000+ entries, and a snapshot comparison would flake. A private folder is also removed whole, so failed, killed or interrupted runs stop accumulating, and `npx vitest run tests/x.test.ts` gets the same protection. A cold tsx cache costs nothing measurable (`vue-stores.test.ts`: 20 s with, 32 s without, noisy machine).

- `tests/helpers/run-tmp.ts`:
  - `isolateTmp()` creates `<tmpdir>/mapx-run-tmp-XXXXXX` in the runner's main process and sets TMPDIR, TMP, TEMP and `MAPX_RUN_TMP` before any worker is forked. Verified that `os.tmpdir()` returns it in a vitest fork, in a Playwright worker, and in a spawned `node` child.
  - It removes the folder on SIGINT, SIGTERM and SIGHUP and marks the run interrupted, so the built-CLI mirror (`mapx-cli-*`) of `tests/helpers/e2e.ts` does not survive an interrupt. After the sweep, vitest's setup (`exitOnSignal`) always exits 129/130/143; Playwright's exits only when nothing else listens (review P1).
  - The folder path is absolute (`resolve(tmpdir())`; review P2), and no second folder is nested when `MAPX_RUN_TMP_OWNED` names the current TMPDIR, which `scripts/baton/check-test-cwd.mjs` now sets (review P2). Worst-case tsx socket path: macOS `/var/folders/xx/<30>/T` (~49) + `/mapx-check-cwd-tmp-XXXXXX` (27) + `/mapx-run-tmp-XXXXXX` (20) + `/tsx-501/<pid>.pipe` (~19) = ~115 nested against a 104-byte `sun_path`; ~95 reusing the wrapper's folder; ~88 without the wrapper. Linux: ~50 with the wrapper.
  - `finishTmp()` lists what the run left (not the tools' caches: `node-compile-cache`, `v8-compile-cache*`, `tsx-<uid>`, `playwright-transform-cache-*`), removes the folder, and unless interrupted sets `process.exitCode = 1` and throws. Without the exit code, vitest prints "error during close" and still exits 0 (measured). The message names every leftover, its first entries, and the files that name its prefix, for example `mapx-config-test-wyjJv7/ (repo-detect, repo-edit, repo-lang, …)  <- tests/config.test.ts`.
- `tests/global-teardown.ts` is vitest's `globalSetup` (in `vitest.config.ts`). `tests/ui/global-setup.ts` calls `isolateTmp()` first, `tests/ui/global-teardown.ts` is Playwright's `globalTeardown` (in `playwright.config.ts`).
- `tests/installer-replace.test.ts`: the installer processes run with TMPDIR inside the test's own folder.
- The two skill test files remove their folders in `after`. `npm run test:skills` now runs under `scripts/baton/check-test-cwd.mjs --cmd`, which gives it a private TMPDIR and fails naming a leftover, so `npm run check` asserts it too.
- `tests/helpers/e2e.ts` comment, one line in `.claude/skills/baton/SKILL.md` section 3 (the only place that describes test conventions; there is no tests README), CHANGELOG entry.
- `tests/global-teardown.test.ts` (22 tests) runs real, tiny vitest and Playwright projects in temp folders:
  - vitest: wired in (tests and spawned children see the private folder), clean run passes, leak fails and is named with its likely source file, two leftovers including a child's `mktemp` folder, tools' caches ignored, a folder another process makes in the shared tmpdir does not count, and SIGINT/SIGTERM/SIGHUP leave nothing (a `mapx-cli-mirror` folder and a probe folder are made first);
  - Playwright: wired in (config text), leak fails with exit 1 and is named, clean run passes, and SIGINT/SIGTERM/SIGHUP leave nothing and report no leak.

## Limitations and found, not fixed

- **Installer leak (product):** `scripts/make-installer.sh` `exec`s `install.sh`, which drops the EXIT trap, so every real run of a `mapx-*-installer.sh` leaves its unpacked archive in `$TMPDIR`. The test now contains it. A fix is to run `install.sh` without `exec` and exit with its status.
- **`arch.spec.ts:85` failed on `develop@f417439`** (23 violations, spec expects 16): unrelated to this task, bisected by the integration owner to M2-12 (6498e16) and fixed by M2-12-R1.
- **vitest's own folder:** when SIGINT ends a run, vitest exits at once and leaves its `<tmpdir>/<21 characters>` folder (made before any global setup). Not ours; the interrupt test ignores it.
- **SIGKILL and a crashed runner:** no hook runs; the private folder stays.
- **Old leftovers in the shared `/tmp`** (e.g. `baton-*`, `playwright_chromiumdev_profile-*`) are untouched.
- **The private folder's path must stay short** (tsx socket): it is made under the OS tmpdir, so a run started with a very long `TMPDIR` can hit it, as the first baseline did.
- **Attribution is a guess:** the files named after a leftover are those under `tests/` and `scripts/` that contain its longest literal prefix; `mapx-ui-*` names four.
- `npm test` outside a private-TMPDIR wrapper now also fails on `mapx-*` leftovers from tests that clean up only on success; that is the intent.
