# M2-01 — Fail-closed cross-language name resolution

Date: 2026-10-30.

## Spike: reproducing report item 13

- **Plain calls did not reproduce it** (as already shown in the import review). A two-repo workspace (PHP `Repo::get`/`save`; JS and `.vue` callers of `api.get`, `api.save` and `this.$http.save`) produced 0 cross-language call edges. `resolveReferencesWithMap` always passes `sourcePath`, and `areLanguagesCompatible` filters the candidates.
- **The framework path did reproduce it:**
  - The framework `ScanContext` resolver called `resolveSymbolToFile(name)` without a `sourcePath` (`scanner.ts`, the `localCtx` fallback). With no source language, `filterMatches` returned every candidate, in any language.
  - Repro: a Laravel route `[UserController::class, 'index']`, whose PHP controller isn't indexed, while a frontend `class UserController` exists. The result was a `route` edge `backend/routes/api.php → frontend/src/UserController.js`.
  - In a two-repo Laravel + Vue workspace, every handler, model or facade name that is resolved by name and is shared with the frontend can produce such an edge. This is the most plausible source of the pilot's large cross-language edge count; the pilot itself was not available to confirm the exact number.

## Fix (`src/core/scanner.ts`)

1. The framework `ScanContext.resolveSymbolToFile(name, sourcePath = relPath)` now defaults the source to the file being extracted, so a PHP route resolves only within PHP.
2. `resolveSymbolToFile` **fails closed**: if the source language is unknown, `filterMatches` returns no candidates instead of all of them.
3. `tests/scanner.test.ts` and `tests/scanner-coverage.test.ts`: two tests asserted the old "no source → first match in any language" behaviour. They now assert `null` without a source, and the same match with a same-language source.

## Evidence

| Command | Exit | Result |
| --- | ---: | --- |
| `npx vitest run tests/cross-language-resolution.test.ts`, before the fix | 1 | the route edge PHP → JS was present |
| `npx vitest run tests/cross-language-resolution.test.ts` | 0 | 2 passed: no JS-family ↔ PHP edges; the route keeps `handlerFile = backend/routes/api.php` |
| Mutation: restore both old behaviours, then the same command | 1 | fails |
| `npx vitest run` | 0 | 57 files, 1094 tests |

**Edge-count impact on MapX's own code** (`src/` + `tests/` scanned, with and without fail-closed): `call` 926, `import` 215, `instantiation` 113, `implements` 28, `param_type` 28, `extends` 3. These are identical, so no legitimate edges were lost there.

## Limitations

The JS-family group (`javascript`, `typescript`, `tsx`, `vue`, `svelte`, `astro`) remains mutually compatible by design. Typed cross-language bridges (HTTP pairing) are M2-03 … M2-06.
