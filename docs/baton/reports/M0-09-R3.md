# M0-09-R3 — Agent files: line endings, legacy edited blocks and JSONC merges

Date: 2026-10-31. P1 from review `REVIEW-2026-10-31-fb75474ba377` (M0-09-R1 CRLF defect), plus the P2s listed in the task description. Builds on the review's `needsConsent()`. The "user-written agent files are never replaced without consent" tests still pass unchanged.

## Delivered

`src/agents/generator.ts`:

- **CRLF (P1).**
  - The `#`-style sentinel regex accepts `\r\n`; before, it required `\n`, so `.clinerules`, `.aider.conf.yml` and `.continue/mapx.yaml` got a second block.
  - The body hash and the up-to-date comparison ignore line endings; before, a CRLF block counted as "edited".
  - A block written into an existing file uses that file's line endings.
- **Final newline.** Created files end with a newline, and so do files whose content mapx replaces wholesale (`no_sentinel` with consent). Text appended later starts on its own line.
- **`plan(…, { onlyExisting })`.** `agents update` uses it, so it no longer creates `.agents/rules/instructions.md` or companions such as `.aider.conf.yml`.
- **Hashless legacy blocks.** A block without a hash counts as edited (needs consent) unless its body equals the current template, whatever its version. Before, an edited *and* outdated hashless block was overwritten.
- **Duplicate blocks.** All mapx blocks in a file are found. The first is replaced and later ones are removed, together with one line break each. Any edited block makes the action a conflict that needs consent.
- **YAML key clash.** A YAML template whose top-level key the user already sets outside the block gets the new status `key_conflict`: it is never written, and the output says which lines to merge by hand. This is Aider's `read:`. `needsConsent` is unchanged; `key_conflict` cannot be forced, because writing it would produce a duplicate YAML key.
- **Dropped comments.** MCP merge actions carry `droppedComments`; `droppedCommentsWarning()` is printed by `init`, `agents generate`, `agents mcp` and `mapx_agents_generate`.
- **Companion MCP configs.** `companionMcpConfigs()` reads an explicit `mcpConfigs` list on each provider template (`src/agents/templates.ts`) instead of matching provider names to MCP config names. Zed and antigravity keep the configs they already received.

`src/parsers/static-file-parser.ts`:

- `stripJsoncSyntax` drops trailing commas and quotes unquoted keys during its string-aware scan. Before, it ran regexes over the whole output, which rewrote `"**/[,]"`, `"a,}"` and `"{ key: v }"` inside strings.
- New `hasJsoncComments()`.

`src/cli.ts`, `src/mcp.ts`:

- `key_conflict` is skipped with its note in `init` (both paths), `agents generate`, `agents update` and the MCP tool.
- `agents list` maps the status to "conflicting keys".
- The dropped-comments warning is printed.

Docs: `docs/cli-reference.md` (generate and update behaviour) and `docs/mcp-integration.md` (`mapx_agents_generate` output).

## Changed existing test

`tests/legacy-agents.test.ts`, "keeps text after the block on its own line when updating". This test appends `'\nkeep-after\n'` to the generated file and expected `<!-- /mapx -->\nkeep-after\n`. That expectation only held because the file had no final newline. Now that it does, the input contains a blank line, and update keeps the user's bytes exactly, so the expectation is `<!-- /mapx -->\n\nkeep-after\n`. The guarantee it was protecting (trailing text kept on its own line) is unchanged and is now also covered by AC2.

## Limitations and not done

- **Continue format: not changed; needs an owner decision.** Continue's reference (docs.continue.dev/reference, checked 2026-10-31) documents `config.yaml` with required `name`/`version`/`schema` and the keys `models`, `context` (entries with `provider`), `rules`, `prompts` (invoked as `/` commands), `docs`, `mcpServers` and `data`. It has no `contextProviders`, `slashCommands` or `cmd` provider, and nothing loads `.continue/mapx.yaml`. F17 prescribes exactly `.continue/mapx.yaml` with a context provider and slash commands, so mapx follows the spec, not Continue. Switching to e.g. `.continue/prompts/*.md` plus `.continue/mcpServers/mapx.yaml` contradicts F17 and the M0-09-R2 test, and `specs/` is frozen (D001). The task offers "verify the format or amend F17": the format is verified as non-conforming, and amending F17 is left to the owner.
- **JSONC comments are not preserved,** only reported. A comment-preserving merge would need a JSONC editor (none in the repo).
- **Hashless legacy blocks:** any hashless block whose body is not the current template now needs consent or `--force`. That includes this repo's own `CLAUDE.md` (the review noted its hand-edited legacy sentinel), so regenerating it needs `mapx agents update --force`.
- **`key_conflict` only checks top-level YAML keys** at column 0 (`key:`). Flow-style or quoted keys are not recognised.
- **`src/parsers/parse-worker.ts`** keeps its own copy of the old `stripJsoncSyntax`, on purpose, to stay self-contained in workers. It is outside this task's files, and the bug there only affects `$ref`/`extends` extraction from JSON files with `,}` or `key:` inside strings. Not changed.
