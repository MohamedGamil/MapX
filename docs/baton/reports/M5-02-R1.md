# M5-02-R1 — arch validate-config (CLI and MCP) and loader robustness

Planned in `iterations/M5-02-R1.md`. Source: review 2026-11-02 (`reviews/REVIEW-2026-11-02-b2558df592cf.md`, finding 11 and the drift table). Design input: §3.4 and §3.5 of `docs/research/deptrac/03-mapx-gap-and-integration.md`.

## Delivered

**Loader (`src/arch/config.ts`):**
- **BOM:** a leading U+FEFF is dropped before the JSONC parse, so a document saved with a UTF-8 BOM loads, extended documents included.
- **Filesystem errors:** every one met while loading is a ConfigError issue, never a throw:
  - an `extends` target that cannot be `stat`ed (ELOOP, EACCES) is reported at its `extends` pointer: `extended path "./loop.jsonc" cannot be read: too many symbolic links (a symlink loop) (ELOOP) (.mapx/loop.jsonc)`;
  - a target that is a directory is reported there too (`is a directory, not a file`);
  - ENOTDIR counts as not found, because Node's `throwIfNoEntry` treats it as one;
  - a document that cannot be read (EISDIR, EACCES) is reported at that document;
  - the configuration file itself is `stat`ed the same way. Only ENOENT means "no configuration"; a self-symlinked `architecture.jsonc` is an ELOOP issue.
- **Views:**
  - an empty or blank view name is an error;
  - a view whose file lies outside `.mapx/architecture/` is refused, whether by a `..` segment or through a symlink (both paths are `realpath`ed before the containment check), and the file is never read;
  - a name that only starts with `..` (`..legacy`) is a view like any other.
  - `mapx check --view` exits 3 for all of these.
- **Parameters** (the integration owner's rule, review 2026-11-02):
  - `%name%` is substituted in every string value of a selector.
  - In `name`, `path` and `package`, an undefined `%x%` is an error, as before. In the other keys only a declared parameter is substituted, and an undefined `%x%` stays literal text, so `{"docTag":"format","value":"%s%s"}` and `{"member":"/^%d%x$/"}` still load.
  - `%%` is a literal `%` in every key.
  - Parameter values are resolved: `"root": "%base%/app"`. A reference without a value is an error at `/parameters/<name>`, and a cycle is one error naming the chain (`%a% → %b% → %c% → %a%`).
  - A `framework` value with a parameter skips the structural check and is checked against the framework parts once substituted.
- **`validateArchitectureConfig(dir, { view })`:** returns `{ report: { valid, view, files, issues }, config }`. `formatValidation` gives the text form. A missing configuration is one `not found` issue. Both surfaces use these two functions, so their output is the same.

**CLI (`src/cli.ts`): `mapx arch validate-config [path] [--dir] [--view <name>] [--format text|json]`**
- It is a subcommand of the existing `arch` command, and `mapx arch [path]` still runs the old report (checked by hand).
- It needs no index.
- Text output is one `file#pointer: message` line per problem, then `N problems in <files>.`; a valid configuration prints `Valid: <files> (N layers).`
- Exit codes: 0 when valid; 3 (AR-17) when the configuration has problems or is missing, and for a usage error (`exitOverride`, as `mapx check` does).
- `--dir` works before or after the subcommand's own options. `arch` also defines `--dir`, so the action falls back to the parent's value.

**MCP (`src/mcp.ts`): `mapx_arch_validate_config { dir?, view?, format? }`**
- JSON by default (§3.5), or `text` with exactly the CLI's text.
- An invalid or missing configuration is `isError: true`, the MCP equivalent of exit 3.
- Also listed in the `serve` help's tool list.

## Limitations

- Validation stays index-free: it does not check that a `repo`, `cluster` or `workspacePackage` value names something that exists.
- A view name may contain subfolders inside `.mapx/architecture/` (`team/contexts`); only escaping the folder is refused.
- **`%x%` without a value in the newly covered keys is literal text, by the owner's rule.** A typo such as `repo: "%Backnd%"` is therefore not reported. In a `layer` selector it shows up as an unknown layer instead.
- **ENOTDIR in `extends` is reported as "not found"**, since Node's `stat` treats it as a missing entry.
- `mapx_arch_validate_config` is a separate tool. M5-14 can keep it or fold it into `mapx_arch_check`, and its count starts from 34.

Changelog: `mapx arch validate-config` and the MCP tool `mapx_arch_validate_config` validate `.mapx/architecture.jsonc` (or a view) without an index, listing every problem with its JSON pointer (exit 3), and the loader now accepts a UTF-8 BOM, reports `extends` to a directory and views outside `.mapx/architecture/`, reports unreadable files (symlink loops, permissions) as configuration errors, and substitutes `%parameters%` in every selector key, with `%%` for a literal `%` and parameters inside parameter values (M5-02-R1).
