## Performance (synthetic benchmark, no real code)

`scripts/bench/import-resolution.ts` generates two Java workspaces in a temp dir, identical except that one gives every file K imports (about two-thirds naming other generated classes, the rest `java.util`/`java.io`), runs the real CLI `init` + `scan` on each, and prints scan wall times and the median ratio. `--max-ratio X` makes it exit 1 above X.

"Before" ran the same script against a `git archive` snapshot of `a15dd86` (this task's base); "after" ran against this branch. The machine (16 cores) was shared with other agents (load average 18–62 during the runs), so absolute times vary by run; each pair ran back to back.

| Run | Files × imports | Code | Scan without imports (s) | Scan with imports (s) | Median ratio |
| --- | --- | --- | --- | --- | ---: |
| 1 | 2,000 × 10 | before | 6.14, 5.82, 6.12 | 11.54, 11.66, 12.33 | 1.91 |
| 1 | 2,000 × 10 | after | 8.33, 7.72, 7.08 | 36.23*, 8.64, 7.55 | 1.12 |
| 2 | 2,000 × 10 | before | 8.93, 8.91, 9.34 | 14.34, 17.75, 19.83 | 1.99 |
| 2 | 2,000 × 10 | after (`--max-ratio 1.5`, exit 0) | 12.24, 10.14, 13.19 | 13.28, 11.15, 9.03 | 0.91 |
| 3 | 2,000 × 10 | before | 7.23, 11.91, 11.02 | 28.48, 17.98, 46.86 | 2.59 |
| 3 | 2,000 × 10 | after (`--max-ratio 1.5`, exit 0) | 13.67, 8.24, 7.88 | 11.85, 8.86, 9.00 | 1.09 |
| 4 | 10,000 × 5, `--package-local` | after | 80.70 | 104.02 | 1.29 |
| 4 | 10,000 × 5, `--package-local` | before | 133.22 | 163.20 | 1.23 |

\* load spike from another process; the median ignores it.

**The 10,000-file scan (run 4) proves nothing either way.** It ran once, at load average 44–68. Even without imports, a scan takes 80–133 s at 10,000 files against about 6 s at 2,000, so other scan phases grow faster than linearly and swamp import resolution. That is outside this task.

**Resolver-only timing** (`--resolvers-only`) times this checkout's JVM resolver in-process, on the same generated paths and imports, with no parsing or SQLite. Machine load and other scan phases barely affect it:

| Files × imports | Before (base commit) | After |
| --- | ---: | ---: |
| 2,000 × 10 (20,000 imports, 14,000 resolved) | 6.60 s | 0.12 s |
| 10,000 × 5 (50,000 imports, 40,000 resolved) | 109.72 s (77.18 s in an earlier run) | 0.19 s |

Before, time grew with files × imports. After, it grows with the number of imports alone.

**A pre-existing bug found while benchmarking (not fixed here):** without `--package-local`, the generated 10,000-file graph forms one large cycle. `mapx scan` then fails with `RangeError: Maximum call stack size exceeded` in the recursive `strongConnect` of `src/core/architecture-analyzer.ts`, both on the base commit and on this branch. A real repository with a long dependency chain could hit it. `--package-local` keeps imports inside each ~50-class package, so the large case can be measured at all.

Reproduce:
- `npx tsx scripts/bench/import-resolution.ts --runs 3 --max-ratio 1.5`
- `npx tsx scripts/bench/import-resolution.ts --files 10000 --imports 5 --package-local`
- `npx tsx scripts/bench/import-resolution.ts --files 10000 --imports 5 --resolvers-only`

For "before", run the same script from a `git archive a15dd86` snapshot.

## Limitations

- `.fish` files have no symbols: no fish grammar is bundled. If the owner wants F20's "best-effort bash grammar" instead, it is a one-line change, but the bash grammar mis-parses fish (`function f … end`), so I chose an honest file-only index. Recording this as an F20 amendment in the plan is for the integration owner.
- The root `CLAUDE.md`, `AGENTS.md`, `GEMINI.md` and `AIDER.md` are generated files that still say 32 tools and list only the old three language tools. I did not touch them (`CLAUDE.md` is project instructions); regenerating them with `mapx agents` picks up the new templates.
- Scan-level "once per scan" is shown by the benchmark and the per-phase reset in code; the counting-`Set` test proves it at the resolver level. No test instruments the scanner itself.
- The `tests/legacy-globs.test.ts` directory-pruning test timed out once (30 s) in an earlier full run under machine load. It passed alone (6/6) and in the final full run. It is unrelated to this change.
- At 10,000 files the scan-level ratio could not be measured cleanly (see Performance). The criterion's 2,000-file case was measured, and the resolver-only numbers show resolution is no longer quadratic.

Changelog: Import resolution no longer slows down with repository size (Java/Kotlin/Scala, Go and PHP imports use an index built once per scan), shebang scripts get call edges, `Rakefile`/`Gemfile` index as Ruby and `.fish` files are indexed, and `mapx_lang_info` matches `mapx lang info` (M0-12-R3).
