## Reproduction (before any fix)

Reviewer C's probes, re-pointed at this checkout, reproduced the defects:

- **`p4-order.sh`:** the first `scan --all` and the first `scan --all --force` on an empty index lack `src/app.ts → libs/ui/button.ts instantiation`. Only a second forced scan gives it.

The new tests failed for the same reasons. The ui-first order already passed.

## Delivered

- **`src/core/scanner.ts`:**
  - **Visibility record:** `meta resolution_repos:<repo>` now records the repos with *indexed* files (`indexedRepos`, from `store.getRepoNames()`), written by full scans and by incremental git syncs.
  - **Referrer queue:** `ownReferrers` keeps this repo's referrers and queues another repo's files in `meta pending_referrers:<repo>`. This covers restored files, renames, moved targets and Vue registry users, in the full, git and hash paths. `takePendingReferrers` adds them to that repo's next re-parse, and a git sync with no git changes still processes them.
  - **Second pass:** after every repo of a multi-repo `scan` or `sync`, `needsSecondPass` runs the repo again if a repo of the run is newly visible to it, or if it has queued referrers.
- **`src/core/store.ts`:**
  - `getRepoNames()`.
  - `deleteRepo` deletes the repo's scanner meta (`resolution_repos`, `scan_filters`, `removed_files`, `removed_names`, `pending_referrers`) and removes it from every other repo's `resolution_repos` record.
- **`src/ui-server.ts`:** `loadConfig` applies `applyCollapsedRepos` and reports on stderr, like the CLI and MCP loaders. `/api/status` loads the config before counting.
- **Docs:** `docs/cli-reference.md` (scan `--all` and sync bullets).
- **Tests:**
  - `tests/legacy-workspaces.test.ts`, describe "workspace surface: cross-repo edges independent of order and history (M0-10-R4)", with 7 tests.
  - The three mocked-store unit suites (`tests/scanner.test.ts`, `tests/scanner-coverage.test.ts`, `tests/scanner-hash-incremental.test.ts`) gain `getRepoNames` in their base store mocks.

## Limitations

- **Cost.** A first multi-repo scan on an empty index parses each repo that was resolved before a later repo was indexed twice: the second pass is a full re-parse of that repo. Later scans and syncs pay the second pass only when a repo becomes newly visible or has queued referrers.
- **Single-repo runs.** Queued referrers wait for their own repo's next scan or sync. `mapx sync` of the other repo alone does not re-parse them.
- **Out of scope.** A new symbol in repo B that unchanged files of repo A could now resolve to is not detected without a change in A, as within one repo.
