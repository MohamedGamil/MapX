# M2-06 — Pair client calls with backend routes across repositories

Date: 2026-10-30. The first verification **FAILED**: the independent review found pairing defects in scope, plus extraction and URL defects in already-DONE tasks. Those were fixed in M2-03-R1 and M2-04-R1 (hard dependencies), then here, and everything was re-verified.

## Delivered

- **`src/frameworks/http/pairing.ts`:** `pairCall(record, routes)`.
  - Live backend routes only: not a client-side router (vue-router, react-router, tanstack-router), not `routeType: 'client'` (Next.js, SvelteKit pages), not unreachable, not overridden.
  - Method sets, `ANY` and `ALL` match.
  - Path segments are compared after removing the host, query and hash. Route parameters in any syntax (`{id}`, `{id?}`, `:id`, `<int:id>`, `*`) match any segment; an unknown client segment (`{}`) matches only a route parameter.
  - The best score wins (literal = 2, parameter = 1). With `baseURLUnresolved`, the path is matched as a suffix.
  - Confidence is `exact`, `parametric` or `suffix`.
- **`scanner.ts` `pairHttpCalls()`:** runs after every repo's post-scan. It re-pairs all records against the current `routes.json`, rewrites `http-calls.json`, then deletes and rebuilds every `http` edge (calling file → handler file, `target_symbol` = handler, owned by the calling file's repo, metadata `httpVerb`, `uri`, `route`, `line`, `confidence`). Scan order does not matter.
- `'http'` in `ReferenceType`; `store.deleteEdgesByType`; `graph.dropEdgesByType`.
- **Surface:** `mapx routes --clients [--unmatched] [--json]` and `mapx_routes { clients: "all" | "unmatched" }`. There is deliberately no new MCP tool, which keeps the documented tool count at 32. `docs/cli-reference.md` and `docs/mcp-integration.md` are updated; the CHANGELOG entry cites M2-03 … M2-06.
