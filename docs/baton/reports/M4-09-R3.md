# M4-09-R3 report: the external-refs tests remove every temp workspace, including unreadable ones

## Reproduction

`TMPDIR=<private dir> npx vitest run tests/external-refs.test.ts` at f171ddb exited 0 (235 passed, 2 skipped). It left `mapx-extrefs-sync-e5medp`, which holds `requirements.txt`, `lib/requirements.txt`, `lib/b.py` and `src/a.py`.

That folder is the first workspace of the pypi test "a standard-library module whose backport a manifest lists is the backport; else the built-in":
- The test calls `p.create` twice.
- `project().remove()` removed only the last root.

The 25 leftovers in `/tmp` look the same: `-sync-` folders with Python files. The one `-repos-` folder is most likely from an interrupted run. Its test removes it in a `finally`.

The chmod 000 cases already restored the mode in a `finally`. On Linux a 000 file does not block `rmSync` when its folder is writable. Nothing enforced the restore, though.

## Delivered (tests/external-refs.test.ts only)

- **`tempDir(kind)`:**
  - Every temp workspace of the file comes from this helper: the store test, `scanApp`'s per-app copies, `project()`, the CLI tests and the PHP stubs test.
  - Each is named `mapx-extrefs-<pid>-<kind>…` and recorded.
  - No `mkdtempSync` call is left outside the helper.
- **`unreadable(path)` and `restore(path)`:**
  - They replace the 8 `chmodSync(…, 0o000)` and `chmodSync(…, 0o644)` pairs.
  - `unreadable` records the original mode.
  - `restore` puts it back. The tests keep their `finally` restore, because 4 of them remove the lock mid-test.
- **Top-level `afterEach`:**
  1. Restores every recorded mode.
  2. Removes every folder the test made, including both of a test that called `p.create` twice.
  3. Fails the test with "still unreadable before removal" if a path is still mode 000.
- `project().remove()` and the 12 `afterEach(() => p.remove())` hooks are gone, because the top-level hook does that work.
- **`afterAll`:**
  - Lists the `mapx-extrefs-<pid>-*` entries in `os.tmpdir()` and compares them with those present in `beforeAll`.
  - Removes any new one, then fails and names each.
  - It counts only this run's entries, so other lanes' runs and old leftovers cannot affect it, and it deletes none of theirs.

| Criterion | Met by |
| --- | --- |
| 1. No new `mapx-extrefs-*` entry after the run | `afterAll` count. A private `TMPDIR` run leaves only `node-compile-cache` and `tsx-1001`. |
| 2. Unreadable paths restored in `finally`/`afterEach` before removal; the test fails if the restore is removed | `afterEach` restore and assertion (mutation 2) |
