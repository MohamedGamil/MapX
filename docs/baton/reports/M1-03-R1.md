# M1-03-R1 — Laravel route-file walker: string/comment-aware lexing and brace-less groups

Date: 2026-10-31. Remediation for the review `reviews/REVIEW-2026-10-31-fb75474ba377.md` (M1-03 DEFECTIVE, M1-06 FALSELY COMPLETE on AC2, and the RouteServiceProvider part of M1-07).

## Delivered

- **PHP masking lexer** (`maskPhp` in `src/frameworks/detectors/laravel-mounts.ts`). It returns two same-length copies of a file:
  - `text` blanks comments (`//`, `#` but not `#[`, `/* */`) and inline HTML;
  - `code` also blanks the contents of single-quoted, double-quoted and backtick strings, heredocs and nowdocs, keeping the delimiters.

  Newlines are kept, so offsets and line numbers still match the source.
- **Walker** (`walkRouteFile` in `laravel.ts`). It reads structure from `code`: braces, `Route::`, `require`/`include`, `loadRoutesFrom` and statement ends. Arguments are sliced from `text` through the new `parenAt`, and `parseRouteChain` takes both copies.
  - An include expression now ends at `;`, `,` or an unbalanced closer, and wrapping parentheses are removed. So `fn () => require …)` and `require(…)` both evaluate.
  - Local string assignments and `use` imports are read from the comment-free copy, and assignments that sit inside strings are ignored.
- **Group scope by call extent.** A group frame now ends at the closing parenthesis of its `group(...)` call instead of at a brace depth. Closure bodies, `fn () =>` bodies and inline `->group(fn () => Route::get(…))` are all scoped the same way.
  - The legacy `Route::group($attributes, <path>)` form is now a mount that carries the attributes.
  - `->group(<path>)` keeps working.
- **Interpolation and variable prefixes.** `phpString` evaluates `"$v"`, `"{$v}"` and `"${v}"` from local string variables.
  - A new optional `fallback` replaces only the unresolvable part, for example `"{$x}/a"` gives `{dynamic}/a`.
  - URIs (including `redirect` and `view`), `->prefix(...)` and `'prefix' => …` all go through `pathArg`.
  - Any route whose path contains a `{dynamic}` segment gets `metadata.dynamic = true`. The segment can come from the URI, a group prefix or the mount that loaded the file.
- **Provider reachability** (`liveProviderCode`). This applies to RouteServiceProvider and the other service providers whose class extends an `Illuminate\…` provider.
  - Comments are blanked.
  - Method bodies that can't be reached from `boot`, `map` or `register` through `$this->`, `self::` or `static::` calls are blanked too.
  - Classes that extend a custom base class are left unfiltered, because the base may call back into child methods.

## Limitations

- `{dynamic}` is a sentinel path segment, so a real route parameter named `{dynamic}` would also be flagged dynamic.
- Provider reachability is intra-class and syntactic. Methods reached only through a callable array (`[$this, 'mapX']`), a trait or `app()->call` are treated as dead. Providers extending a non-Illuminate base class are not filtered at all.
- Interpolation resolves only local string variables. Property and array access (`"$a->b"`, `"$a[0]"`) and complex `{$…}` expressions become `{dynamic}`. A double-quoted assignment (`$b = "$a/x";`) is still not recorded as a variable.
- `bootstrap/app.php` `withRouting(...)` is still read from raw text. Commented-out `withRouting` arguments belong to M1-07-R1, which owns that function.
- No real Laravel application was available. All evidence comes from the synthetic fixture and e2e workspaces.

Changelog: Laravel route extraction no longer reads routes, braces or `require` from strings and comments, scopes arrow-function and legacy path groups correctly, evaluates interpolated URIs and variable prefixes (or flags them dynamic), and ignores commented-out or uncalled RouteServiceProvider mounts (M1-03-R1).

## Post-acceptance defect (review 2026-10-31, 2db08bd)

Found by the independent review. `Route::any` URIs skipped evaluation (`if (uriExpr && verb !== 'ANY')`), so `Route::any("a/$unknownVar", …)` gave `/api/a/$unknownVar` and `Route::any('b/' . SOME_CONST, …)` gave raw PHP. The guard only made sense for `fallback()`, which sets no `uriExpr`.

- **Fix:** the guard is dropped (`src/frameworks/detectors/laravel.ts`).
- **Test:** `tests/laravel-mounts.test.ts` "flags unresolvable interpolated URIs…" now includes both `Route::any` forms (`/api/a/{dynamic}`, `/api/b/{dynamic}`, `dynamic: true`); it failed before the fix. Routes scorer unchanged (114 labels, URI 90/90, handler 87/87, 0 FP).

## COMPLETION DISPUTED (review 2026-10-31, 2db08bd)

FALSELY COMPLETE: AC3 ("never emitted as raw PHP") is still unmet for RouteServiceProvider prefixes, which are taken raw: `Route::prefix(config('app.api_prefix'))` gives `/config('app.api_prefix')/users` and `"admin/{$this->version}"` stays literal, neither flagged dynamic. Remediation: M1-07-R2. See `reviews/REVIEW-2026-10-31-2db08bd25e13.md`.
