# M2-09 — JS/TS member-assigned functions are symbols

Planned in `iterations/M2-09.md`. Source: `reports/M4-26.md`. Dispatched at `1e1da86`; reworked after the independent review of `6dcb7b5` (section "Review"); rebased on develop `2a6f86e`.

## Reproduction

A real scan (temp workspace, `mapx init`/`scan`) on `1e1da86`:
- `api.get = function`, `api.post = () =>`, `Foo.prototype.bar = function` and `exports.ping = function` gave no symbol. Only `api` (constant), `Foo`, `helper` and `fetchJson` were extracted.
- The calls in those bodies had `source_symbol = null`.
- A call in another file (`m.ping()` with `const m = require('./api')`) had no edge.

## Decisions (no spec text covers member assignments)

1. **Member function.** A module-level `X.m = <function expression | arrow | generator>`, where `X` is a plain identifier other than `exports`/`module`, gives a `method` `m` with scope `X`.
2. **Prototype method.** `Foo.prototype.bar = <function>`, at any depth, gives a `method` `bar` with scope `Foo`. Prototype code is often wrapped in an IIFE.
3. **CommonJS export.** A module-level `exports.f = <function>` or `module.exports.f = <function>` gives a `function` `f` with scope **`exports`** (revised after review P1-a).
   - It is reached only through its module: `findExport` accepts it, so `const m = require('./m'); m.f()`, `const { f } = require('./m'); f()` and `import { f } from './m'` link to it.
   - It is never a lexical `f`. It does not shadow an import of `f` in its own file, and name lookup never offers it for a bare or untyped call.
4. **Not symbols:**
   - a member assigned a non-function: `api.count = 1`, `api.handler = other.fn`, `module.exports.limit = helper`;
   - `this.x = () => …`, in a constructor or anywhere: an instance value, and class fields already give properties;
   - `module.exports = function () {}`;
   - a deeper receiver `a.b.c = …` (other than `X.prototype.y`), or a computed key `api['k'] = …`;
   - a non-prototype member assignment inside a function or block (`function make() { o.run = … }`, `if (…) { api.later = … }`). That is a local object, as `const f = () => 1` inside a function is (M0-17-R3).
5. **One symbol per scope and name** (review P2-b). A member-assigned symbol is dropped when the file already declares that scope and name, as a class method (`class Foo { bar() {} }` plus `Foo.prototype.bar = …`) or an object-literal member. It is also dropped when an earlier assignment already gave it. The declared member, or the first assignment, is kept.
   - `function wrap` and `exports.wrap = function` are two functions, and now two distinct symbols: `wrap` and `exports::wrap`. The review saw two unscoped `wrap` symbols; scope `exports` separates them, and `mapx node wrap` opens the declared one.
6. **Ranking in name lookup** (review P2-a). Every symbol of rules 1–3 carries the metadata `assigned: true`, stored in `symbols.metadata` and read into the symbol index. A member-assigned function is a name-lookup candidate only when no declared function or method has the name. So no call the parent resolved to a declaration moves to a member-assigned function.
7. **Imported objects** (found while fixing P2-a and P2-d).
   - `import { api } from './api'; api.post()` and `const { api } = require('./api')` resolve to the function that module assigns to `api.post`.
   - `const hooks = require('./hooks'); hooks.start()` with `module.exports = hooks` resolves to `hooks::start`, through `findExport`.
   - A declared `post` elsewhere no longer wins over the imported object's own member.

The extraction rules are query patterns, using `#eq?` and `#not-match?` predicates, in `queries/javascript/symbols.scm` and `queries/typescript/symbols.scm`. The JS and TS parsers sign these symbols with the assignment target and the value up to the body, for example `api.post = (url, body) =>`.

## Delivered

- `queries/javascript/symbols.scm`, `queries/typescript/symbols.scm`: four patterns each (member, prototype, `exports.f`, `module.exports.f`).
- `src/parsers/languages/javascript.ts`: `memberAssignmentSignature`, `memberAssignmentMetadata` and `dropRepeatedAssignments`, shared by `JavaScriptParser` and `TypeScriptParser` (`src/parsers/languages/typescript.ts`).
- **Outside affectedFiles:**
  - `src/parsers/generic-wasm-parser.ts`: a protected `symbolMetadata(node)` hook, which defaults to `{}`.
  - `src/core/scanner.ts`:
    - the `assigned` flag in the symbol index;
    - `exportOnly` (scope `exports`), which is excluded from lexical shadowing and name lookup and accepted by `findExport`;
    - `commonJsMain` (`module.exports = X`) and `assignedMember` (imported object members);

    - `innermostByLine`, a linear replacement for the per-reference scan of every symbol (see Performance).

  - 10 run end to end on one real scan of 18 files (JS and TS).

  - 2 are sync tests (git and content hashes) that end equal to `scan --force`.

## Performance

Reviewer's `ws6`: 20,000 member assignments in two files, timed on this machine under load (load average 13–18, so the times are noisy):

| Version | Scan time (3 runs) | Max RSS | Symbols / call edges |
| --- | --- | --- | --- |
| Parent | 2.45, 2.53, 2.41 s | 492–513 MB | 401 / 10,000 |
| `6dcb7b5` | 4.69, 4.55, 3.99 s | 581–615 MB | 20,401 / 20,000 |
| Parent, re-timed alongside the fix (load average 21–24) | 3.02, 2.66, 2.76 s | 499–520 MB | 401 / 10,000 |
| This fix (`innermostByLine`), on `2a6f86e` (same load) | 3.55, 3.93, 3.80 s | 617–623 MB | 20,401 / 20,000 |

The fix's scan is about 1 s slower than the parent's; `6dcb7b5` was about 1.9 s slower. Memory is about 110 MB higher in both, because of the 20,000 extra symbols. The machine was loaded, so these figures show the direction, not exact costs.

- **Where the time went.** A CPU profile of `6dcb7b5` attributed 489 ms of self time to `resolveReferencesWithMap`. That function finds each reference's source symbol by scanning every symbol of the file, which costs references × symbols: 10k × 20k.
- **The fix.** `innermostByLine` paints each line with its innermost symbol once per file, so the cost is the sum of the symbol spans. The ties are the same as before: the smallest span wins, and the first of equal spans.
- **What remains is inherent.** 20,000 more symbols and 10,000 more edges must be inserted (447 ms in SQLite in the profile) and held in memory.

## Limitations

- **`api.get()` itself links nothing.** `get` (like `find`, `delete`, `set`, `add`, `has`, `map`, …) is in `JS_BUILTIN_METHODS`, and a call of a built-in method name on an untyped receiver is dropped at extraction (M0-01-R1). `api.get` gets its symbol, and `mapx node api.get` opens it, but `api.get('/a')` creates no edge. **Follow-up candidate:** keep such a call when its receiver is bound to a project object.
- **The ranking gives up same-file preference for assigned methods.** A declared method elsewhere beats a member-assigned one in the caller's own file. For example, `this.render()` inside `Widget.prototype.init` links to a class method `render` in another file when one exists, as the parent did. It reaches `Widget::render` only when no declaration has the name. This is the price of moving no edge the parent had right.
- **`exports.validate(x)` inside the module** resolves by name lookup and never to its own `exports::validate`, as before.
- **Name lookup has no receiver types.** `x.handler()` on an untyped receiver can link to the only `handler` there is, member-assigned or not, as with class methods.
- **Not covered:**
  - `require('./m').f()`;
  - calls on a `new` expression (`new Foo().bar()`);
  - non-prototype member functions inside a function, block or IIFE;
  - `this.x = …`;
  - computed or deeper receivers.
- **Edge-case member symbols.** `window.onload = function` and `Object.prototype.toString = function` (a polyfill) are methods of `window` / `Object`. Calls of built-in names on them stay filtered (M0-01-R1, M0-17-R2).
- **Imported objects resolve directly only.** `import { api }` resolves to `api`'s members in that module, not through re-exports.
- **`CHANGELOG.md`** is in affectedFiles, but the lane brief reserves it for the integration owner.

Changelog: In JavaScript and TypeScript, a function assigned to a member (`obj.method = function () {}`, `obj.method = () => …`, `Foo.prototype.bar = function () {}`) is now a method symbol of `obj` / `Foo`, and `exports.f = function () {}` a CommonJS export `f` of its module, so calls through the object or the module link to them and `mapx node obj.method` opens them (M2-09).
