# M2-25 — A called loop variable never links a same-named function elsewhere

Worktree branch `worktree-agent-adf7c89ff0a9af4a0`, on develop `97faf80`.

## Delivered

`boundLocally` (`src/parsers/generic-wasm-parser.ts`) now says what a call through a name bound in an enclosing JS/TS or Python scope is: `local` (no by-name edge), `unproven` (the by-name edge stays, marked inferred) or not bound.

Always local (no edge):

- the variable of a `for … of` / `for … in` statement (identifier or pattern: `[name, cb]`, `{ cb }`), a Python `for` and a Python comprehension variable; the loop's iterable is not in scope of its own variable;
- a C-style `for (let run = …; ; ) run()` variable;
- a `catch (cb)` parameter;
- a `var` declared in a nested block of a function (hoisted to it), as well as plain `const`/`let`/`var`.

Destructured locals (`const { f } = <source>`, in a function or at module level) are classified by their source (`sourceBinding`, the principle of M2-12: no edge only when the source is provably not a project symbol):

| Source | Result |
| --- | --- |
| an object or array literal | local |
| a name imported from a package or builtin, or a call or member of one | local |
| a call given a package or builtin specifier string: `load('bun:sqlite')`, `load('node:worker_threads')` (a scheme, a Node builtin, a scoped package) | local |
| `require(…)`, `import(…)`, a name imported from a project module | not bound: the scanner resolves them (M2-20, M2-08-R3, M5-19 external references) |
| anything else: `this.userService`, a local variable, `useStore()` with no import, a function declared in the file, `new Builder()`, a call result with no specifier | unproven: the by-name edge stays, verifiability `inferred` |

`EXTRACTOR_VERSION` is 22. M2-26 shares this mechanism; its code is in this commit, its tests and report in M2-26's.

## Limitations

- An SFC `<script setup>` still counts as a global script for an ES module's bare, unbound call (the second cause in M5-18-R1): a real unbound bare call reaches it. Not touched, per the task.
- A destructuring whose source the parser cannot prove external keeps a by-name edge marked `inferred`, including `const { render } = load()` (no specifier) from M2-26's wording. Such an edge is ignored by MapX's own check (`policy.inferred: ignore`) but still appears in the graph.
- A one-segment import (`import { x } from 'utils'`) counts as a package; a tsconfig `baseUrl` path with a folder (`stores/user`) does not. A baseUrl import named like a package would lose its by-name edge for destructured calls.
- Destructured parameters (`({ f }) => f()`) stay unbound, as before. The Python comprehension handling has no e2e test.
