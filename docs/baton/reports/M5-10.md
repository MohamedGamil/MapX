# M5-10 — Capture decorators/attributes and doc tags in symbol metadata (tier 1)

Planned in `iterations/M5-10.md`, which fixes the metadata shape and the selector syntax. Sources: `docs/research/deptrac/03-mapx-gap-and-integration.md` §2 (G4) and §3.7, `02-abstract-feature-model.md` AR-04.

## Delivered

**Metadata (`symbols.metadata`, each key only when non-empty):**
- `decorators: [{ name, args, written? }]`:
  - `name`: the name without sigil or arguments, with its qualifier as written. In PHP it is resolved like a class name, through `use` and the namespace.
  - `args`: the raw text between the parentheses (`''` for `()`, `null` without a list), cut at 500 characters.
  - `written`: PHP only, added by the review. The name as written, present when resolution changed it.
- `docTags: [{ tag, value }]`: `@tag` and its text to the next tag, whitespace collapsed, cut at 500 characters.

**Parsers:**
- `src/parsers/annotations.ts` (new): `symbolAnnotations(language, node, resolve?)` reads the syntax tree.

  | Language | Decorators | Doc tags |
  | --- | --- | --- |
  | PHP | `#[A]`, `#[A(…)]`, several per group, FQN via `use` | PHPDoc block tags (Doctrine `@Route(…)` included) |
  | TS, TSX, JS (Vue and Svelte script blocks too) | class decorators before or after `export`, method decorators (class-body siblings), field decorators; not parameter decorators | JSDoc/TSDoc block tags; the doc of `export const f = …` and member assignments |
  | Python | `decorated_definition` decorators | docstring `.. directive::` (with indented body) and `@tag` lines |
  | Java | `marker_annotation`, `annotation` in modifiers | Javadoc block tags |
  | Kotlin | `annotation` in modifiers (`user_type`, `constructor_invocation`) | KDoc block tags, including a doc that the grammar nests in a terminator-less `package` header |
  | C# | `attribute_list` → `attribute`, several per list | `///` XML doc: each top-level element a tag `@<element>`, `name`/`cref` first in the value, `<summary>` excluded |

  Block tags start a line, so inline `{@link X}` and a mid-line `@see` are not tags.
- `src/parsers/generic-wasm-parser.ts`: merges them into every symbol's metadata (after the C#/Scala `namespace` and the JS `assigned` flag).
- `src/parsers/languages/php.ts`: keeps each symbol's declaration node and adds its annotations once the `use` table and `resolveToFqn` exist.
- `src/types.ts`: `SymbolDecorator`, `SymbolDocTag`.
- `src/core/extractor-version.ts`: `EXTRACTOR_VERSION` 7 → 8 (develop + 1).

**Arch:**
- `src/arch/elements.ts`: symbol elements carry `decorators` and `docTags`; overloads (one element) carry the union.
- `src/arch/selectors/decorator.ts` (new): `decoratorMatcher`, `hasDecorator`. The rule, revised by the review, is in "Review" below.
- `src/arch/selectors/doc-tag.ts` (new): `docTagsOf`, `hasDocTag(element, tag, valueTest?)` (for M5-11's `visibility.internalTags`). Python `@deprecated` decorators count as `@deprecated` (AR-04).
- `src/arch/selectors/patterns.ts` (new): `globOrRegex`, `regex`, `nameOrGlob` moved out of `index.ts` (re-exported there) so the new selector modules share them without an import cycle.
- `src/arch/selectors/index.ts`: dispatches `decorator` and `docTag` (symbol-level: inapplicable on files); both removed from `UNSUPPORTED_SELECTORS`.
- `src/arch/config.ts`: a `decorator` written `/…/flags` must compile (as `path`).
- `schemas/architecture.schema.json`, `docs/architecture-rules.md`: the selectors, the per-language table, examples.

**Files beyond `affectedFiles`:** `src/parsers/annotations.ts`, `src/types.ts`, `src/arch/elements.ts`, `src/arch/config.ts`, `src/core/extractor-version.ts`, `schemas/architecture.schema.json`, `docs/architecture-rules.md`, `tests/fixtures/symbol-annotations/**`, and `tests/arch-selectors.test.ts` / `tests/arch-evaluate.test.ts` (they used `docTag` as the example of an unsupported selector; now `member`, still M5-09). `src/parsers/languages/typescript.ts` and `javascript.ts` needed no change: both inherit the generic merge.

## Review (independent review of 4127853: 1 P1, 6 P2, no P0)

Every finding was reproduced on the reviewer's inputs and fixed. Each fix has a test in `tests/symbol-annotations.test.ts` over a new synthetic fixture, `tests/fixtures/symbol-annotations/review/`, with one file each for TS, Java, Kotlin, Python, C# and PHP.

| Finding | Fix | Test |
| --- | --- | --- |
| **P1.** Code samples in doc comments became tags (Javadoc `<pre>` with `@Deprecated`; `@internal` inside a TS `@example`) | `javadocTags` treats as text, never tags: lines in a `<pre>…</pre>` block, a multi-line `{@code …}` / `{@literal …}`, or a ``` fence, and everything after `@example`, which is that tag's value to the end of the comment. `xmlDocTags` skips a top-level C# `<code>` | "Javadoc `<pre>` blocks and multi-line `{@code}`…", "KDoc `<pre>`…", "a JSDoc `@example` runs to the end…", "C# XML `<code>`…" |
| **P2.** Python literal blocks and doctests gave tags | `pythonDocTags` dedents the docstring like `inspect.cleandoc`. It skips lines indented under a paragraph ending in `::`, and doctest examples from `>>>` to the next blank line. A line inside the current tag's indented body is that tag's value before it can be a tag, so a directive's code body is never read as tags | "Python literal blocks … and doctest examples…" |
| **P2.** A comment between decorators dropped the earlier ones (TS) | `jsDecorators` passes over comments between class-body decorators. Java, Kotlin and Python already filtered comments out of modifiers and decorated definitions; the test confirms it | "a comment between decorators keeps the earlier ones (TS, Java, Python)" |
| **P2.** A doc separated from its declaration by a line comment was lost | `precedingDoc` passes over comments that are not `/** */` docs, but never code. The C# XML doc likewise passes over plain `//` comments before the `///` run | "a line comment between a doc and its declaration…", "a C# plain comment…" |
| **P2.** TS overload signatures' docs were lost | `overloadSignatures` collects the same-named `function_signature` statements just before an implementation, and their doc tags are stored on it, signatures first. The report's overload claim now distinguishes this from element-level union | "TS overload signatures give their doc tags to the implementation" |
| **P2.** Qualified decorator selectors missed stored names (`ORM\Entity`, `System.Obsolete` against `[Obsolete]`, aliases) | PHP stores `written` (the name as written) when resolution changed it. New rule, case-insensitive: the value equals the name, or is a suffix of it on a `\` or `.` boundary; the same against `written`; and outside PHP, where names are stored as written, the name is such a suffix of the value. C# `X` ↔ `XAttribute`. `::` is no longer a separator. In PHP, `#[\Entity]` stays distinct from Doctrine's | "PHP keeps the name as written…", "a qualified value matches a name stored as written, except in PHP…" |
| **P2.** C# `[return: NotNull]` was stored on the method; Kotlin `@[A B]` stored only A | C# lists whose target is not `type`, `method`, `property` or `event` are skipped. Each type in a Kotlin multi-annotation is stored | "C# `[return:]` and other foreign targets…", "Kotlin `@[A B(1)]` stores each annotation" |
| **Document only.** A file-header doc followed by a blank line attaches to the first declaration | Documented in `docs/architecture-rules.md` ("A doc comment attaches to the next declaration…"), with the `@internal` leak risk | — |

One expectation changed with the new rule. In the main membership test, the Java `@Entity` class now matches `{decorator: "Doctrine\\ORM\\Mapping\\Entity"}` (`selectors[0]`) instead of `{decorator: "Entity"}` (`selectors[1]`). Java stores `Entity` as written, so the qualified value matches it.

The PHP decorator expectations in the main test now include `written` (`ORM\Entity`, `ORM\Table`, `ORM\Column`, `Route`).

The Kotlin `@[A B]` form was a pre-existing gap in reading the grammar, not a regression. The other findings were all in code this task added.

## Limitations

- **Languages.** Go `// Deprecated:`, Rust attributes and docs, Dart, Swift, Scala, Ruby YARD and the rest of §3.7 store nothing yet, so `decorator` and `docTag` never match their symbols. Follow-up: tier 2.
- **Names.**
  - Only PHP resolves decorator names through imports. TS/JS, Python, Java, Kotlin and C# store the written name (`Controller`, `app.route`). The segment-suffix match, both ways, covers presets such as `nestjs` (`@Controller`).
  - These languages cannot tell two libraries' `@Entity` apart: `javax.persistence.Entity` also matches a TypeORM `@Entity`.
  - An aliased TS import (`import { Controller as C }`) is stored as `C`.
- **Doc comments:**
  - The `/** … */` comment, or the C# `///` run, must come before the declaration and its decorators, with only comments between. A doc placed between a decorator and the declaration is not read.
  - A file-header doc attaches to the first declaration even across blank lines, as in TS and Javadoc tooling. This is documented, with the `@internal` risk.
  - `@example` takes everything after it, so tags written after an `@example` are part of its value.
  - C# `/** */` doc comments and Python Google/NumPy-style "Deprecated:" sections are not parsed.
  - TS abstract classes are not symbols today (unchanged), so they get nothing.
- **Values.** Whitespace is collapsed in tag values. Decorator `args` keep their source text, multi-line included. Both are cut at 500 characters.
- **Symbols only.** A file-level docblock (a PHP file header) is not a file tag. Files join `decorator` and `docTag` layers through their top-level symbols, as with `name`.
- **Index.** `EXTRACTOR_VERSION` is now 8, so existing indexes re-parse once on the next scan or sync. Other lanes bumping in parallel need reconciling.
- **Surface.** The CLI and MCP are unchanged, so `docs/cli-reference.md` and `docs/mcp-integration.md` are too. No new dependencies.

Changelog: Scans now record each symbol's decorators, attributes or annotations and its doc tags for PHP, TypeScript, JavaScript, Python, Java, Kotlin and C#, and architecture layers can select symbols with `decorator` and `docTag` (M5-10).
