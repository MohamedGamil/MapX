## Delivered

**One source of layer violations (§3.3), in `src/core/architecture-analyzer.ts`: `currentSmells(store, dir, repos, { primary, repoPaths })`.**
- **No `.mapx/architecture.jsonc`:** the rows the scan stored, returned as they are: the same objects `Store.getArchSmells` returns, with no `source` field, and nothing evaluated.
- **A configuration:**
  - `layer-violation` smells come from the report `mapx check` builds (`openArchitecture`, `loadBaseline`, `buildReport`), so baselined violations are not smells.
  - There is one smell per source file → target file, the granularity of the role-order smells. Each line names the elements, the layers, the rule and the edge types. `error` is `critical`; `warn` is `warning`.
  - The stored role-order (`FlowValidator`) violations are dropped.
  - Under `policy.alsoInferred: true` they are kept, marked `source: "inferred-roles"`, but only on file pairs the rules decide in no way. `ruledEdges` treats as the rules' every edge whose source is in a layer, and every edge the scope's paths exclude. So an edge the rules allow, report, baseline or exclude is never re-reported.
  - The report's exit-3 errors (a stale baseline entry, a `+` cycle, `config`) become `architecture-config` smells.
  - The other stored smells (cycles, hubs, cluster smells) are unchanged.
- **Composed when read, not at scan time.** An edited configuration applies without a rescan. A multi-repo workspace is evaluated once every repo is indexed, and a configuration problem can never fail a scan. The scan stores exactly what it stored before.
- **One evaluation per command.** `buildReport` takes the context's evaluation (`SkipOptions.evaluation`), which the smells reuse. `mapx arch` computes its smell list once, for both the list and the health line.
- **A configuration or baseline that cannot be loaded** keeps the role-order violations (marked `inferred-roles`) and adds one `architecture-config` smell (`critical`) naming the first problem.
- **Repos:** layer-level smells belong to the primary repo, the others to their source file's repo.

**The AR-18 smells, `src/arch/smells.ts` (new): `ruleSmells(ctx, report)`.** Each is marked `source: "rules"`; the definitions are in `docs/architecture-rules.md#smells`.

| Smell | Definition used |
| --- | --- |
| `layer-cycle` | An SCC of the observed layer graph after the baseline, found with the analyzer's own iterative Tarjan (`shortestCycleThrough` is now exported). The graph is the report's `layerEdges` pairs with an allowed or a reported violating dependency |
| `layer-skip` | AR-18's strict order, written as a `+` chain: each layer's one `+` names the next layer down. An allowed dependency on a layer of the source's chain past the next one is a skip, and the message names every bypassed layer that has elements. Not skips: a layer the source's own rules or the `*` defaults name, and a layer off the chain (a shared kernel reached through `+`) |
| `dead-allowance` | An allowance the source's rules name (`L`, `+L`) with 0 uses, counted as `unusedAllowances` (`mapx arch unused`) counts them. Inherited grants and the `*` wildcard are not rules that can be tightened. A `"*"` default is summed over the layers it serves, and reported once, as `* → L`, only when no layer uses it |
| `weak-allowance` | The same with 1 or 2 uses (`WEAK_ALLOWANCE_USES = 2`, as `mapx arch unused --limit 2`); a default is summed |
| `unstable-layer-dependency` | I(source) < I(target) on an observed pair, after the baseline. I = Ce/(Ca+Ce) per layer, counted in distinct files |
| `abstractness-distance` | D = \|A + I − 1\| > 0.7 for a layer with top-level types and some coupling (I as above). A = interfaces and traits over top-level types |
| `deprecated-usage` | An edge in the configuration's scope into an element tagged `@deprecated` (or a member of one; Python's decorator counts), from outside it. One per using element and deprecated element |

## Limitations

- **Not built:**
  - `vendor-leak`, `undeclared-dependency` and `dev-dependency-in-prod` need package selectors and manifest data (M5-12 was cancelled; M5-21 … M5-24);
  - `orphan-element` and `baseline-debt` are AR-18 rows outside this task's objective.
- **Thresholds are constants:** `WEAK_ALLOWANCE_USES = 2` and `DISTANCE_THRESHOLD = 0.7`, not configuration keys. Uses are stored edges, as in `mapx arch unused`; in TypeScript an import and one use make 2 edges.
- **`unstable-layer-dependency` is strict SDP (`<`), as AR-18 states.** It has no margin, so near-equal layers can be reported.
- **Abstractness.** MapX records no `abstract` modifier on classes. Since M5-09, a TypeScript `abstract class` is indexed as a class, so only interfaces and traits count as abstract. A parser flag for abstract classes would sharpen A.
- **Strict order.** It is read from the rules' `+` chains, because no preset declares an order yet (M5-17). A layer with two `+` allowances ends its chain.
- **`alsoInferred` and edge types.** An edge whose source is in a layer belongs to the rules even when the scope leaves its type out: the configuration covers that code.
- **Layer names in the graph.** The layer graph splits a finding's layers on `, `, as `mapx check --layer` does, so a layer whose name contains `, ` is miscounted there.
- **Cost.** With a configuration, each listing evaluates the edges once (asserted). The edge table is read once more for `deprecated-usage`, and again under `alsoInferred` for `ruledEdges`; neither is an evaluation.
- **The dashboard's graph badges** (`isHub`, `isCycle`) are unchanged. Rule smells reach the smells panel through `/api/smells`. The Architecture view is M5-15.
- **`mapx arch --json`** is documented but does not exist (found by M5-08); it is still unchanged.
