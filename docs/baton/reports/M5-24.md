# M5-24 report: package, builtin and ambient selectors; uncovered and vendor-confinement reporting

## Delivered

- **External elements** (`src/arch/elements.ts`):
  - The element view reads the `external_refs` view (M5-19 to M5-23) into `view.externals` and `view.externalRefs`, apart from the file and symbol elements, so no existing consumer of `view.elements` sees them.
  - There is one element per ecosystem, origin, name, direct and dev. The name is the package (`pg`, `guzzlehttp/guzzle`) or a built-in's package (`node:fs`, `ext-pdo`, `python:os`, `fmt`). An unknown package is named by its specifier.
- **Selectors** (`src/arch/selectors/external.ts`, `index.ts`):
  - `package` (with `dev` and `direct`), `builtin` and `ambient` match external elements only.
  - On an external, only they and `layer` apply. Every other selector is inapplicable (three-valued, like `name` on a file).
  - `*` crosses `/` in package names. A package that no input provides is matched by its name as written, so `*` covers every package (changed in review).
  - Names compare per ecosystem (changed in review): PEP 503 for pypi, case-insensitive for npm and Composer, exact for Go.
  - `UNSUPPORTED_SELECTORS` is now empty.
- **Membership:** it covers externals, so a vendor layer is not empty and `private` package selectors work.
- **Evaluator:**
  - Every external reference from a source in a layer and in scope is decided by the AR-08 chain (`decideEdge`), with its kind as the edge type.
  - Uncovered dependencies follow `policy.uncovered`: externals by default, built-ins and ambient access only with `builtins`.
- **Report:**
  - A target names the external (empty `file`) and carries `external: { ecosystem, origin, package, direct, dev }`. `schemas/arch-report.schema.json` describes it.
  - Layer file counts leave externals out.
  - A Go package import is never subsumed by an external finding.
- **Introspection:** `which`, `allowed` and `mapx_arch_allowed` take `pg` or `npm:pg`; layer listings show `kind: "external"`.
- **Smells** (all three follow directly from the data, about 40 lines):
  - `vendor-leak`: a private-layer violation on an external;
  - `undeclared-dependency`: a known package with `direct` false;
  - `dev-dependency-in-prod`: `dev` true, from a file that is not a test, config, script or tooling file (by role or conventional name).
- **Fixture:**
  - Four new apps (`ts-vendor`, `python-vendor`, `php-vendor`, `go-vendor`), using real packages: pg, lodash, express, sqlalchemy, pytest, flask, doctrine/dbal, fakerphp/faker, guzzlehttp/guzzle, sqlx, testify and logrus. Their 39 external references are labelled in `expected-externals.json`.
  - 72 rows were added to `expected-findings.json`, and no existing row was changed:
    - 52 uncovered rows for the existing apps. They are derived from `expected-externals.json` by the granularity rules, independently of the scanner, and the derivation matched the scan exactly (71 findings by edge type).
    - 20 vendor-app rows: vendor confinement, dev dependency, uncovered, allowed and none, 5 per app.
- **Scorer:** an end can name `external: "<ecosystem>:<name>"`. `externalFindings` scores findings on externals per ecosystem and category.
- **Docs:**
  - `docs/architecture-rules.md` has a delimited section, "External dependencies", plus small edits: the old "not evaluated yet" table and the smells line.
  - `cli-reference.md`, `mcp-integration.md` and `benchmarking.md` are updated.
  - The CLI and MCP descriptions of `allowed`'s target are updated.

## Review

The integration owner reviewed `7aaf2a0` and found no P0. The decision stands: packages that no layer covers are uncovered by default (AR-08). The fixes below are in this commit, rebased onto `cb5fa73`. The conflicts were the M5-15 `layers` field on finding ends, now kept together with `external`.

### P1: `mapx arch init` fails on day one

- **Fix:** every proposal adds a `Packages` layer, `{ "package": "*" }`, when the index has package references. That covers `--from roles`, `--from clusters` and `--preset`/`--from framework`. The layer comes with `"*": ["Packages"]` and a comment naming `policy.uncovered.externals` (`src/arch/infer.ts`, `addPackagesLayer`). For presets it is declared in the generated configuration, merged over the preset, so the shipped preset files are unchanged and `gen-arch-presets.ts --check` exits 0.
- **Why not in the presets:** putting the layer in the preset files made it an `empty-layer` warning on projects without packages.
- **Deviations from the brief:**
  - The selector is `{ package: "*" }`, not `{ package: "*", dev: false }`. With `dev: false`, unlisted packages (dev unknown, such as `left-pad` in the new fixture), dev-only packages and packages no input provides would stay uncovered. No baseline can skip them, so `--fail-on-uncovered` would still fail.
  - To cover packages no input provides, `package` now matches them by their name as written.
  - There is no separate dev-packages layer: test files are usually not indexed, so it would rarely fire. The `dev-dependency-in-prod` smell covers that use.
- **Tests** (`tests/arch-init.test.ts`, fixture `tests/fixtures/arch-init/packages`: express, pg, unlisted left-pad, node:crypto):
  - `--from roles`, `--from clusters` and `--preset layered` each write a configuration with `--baseline --write`, and `check --fail-on-uncovered` then exits 0 with no uncovered finding.
  - Without the layer, the same check exits 2, with express, left-pad and pg uncovered.

### P2s

1. **`dev-dependency-in-prod`:** files with the role test, config, scripts, script or tooling are exempt. So are conventional config names: `*.config.*`, `*.conf.*`, `.*rc*`, `conftest.py`, `setup.py`, `noxfile.py`, `gulpfile`, `Gruntfile`, `magefile.go`. Test: `vitest.config.ts` and `.eslintrc.cjs` importing lodash give no smell.
2. **`arch allowed`:** an external in no layer that `policy.uncovered` does not report is now `out-of-scope`, allowed, at `info`, with a reason naming the flag. A package stays `uncovered`. Test: `node:fs` and `express` on ts-vendor.
3. **Selector names:** PEP 503 applies to pypi package names (`zope.interface`, `Flask_SQLAlchemy`). npm, Composer, built-ins and ambient names ignore case; Go is exact. Tests: unit cases, and `{ package: "PyYAML" }` on the fixture.
4. **`undeclared-dependency`:** one rule for all four ecosystems. It fires only for a known package with `direct` false: `src/arch/smells.ts` and docs.
   - There is one test per ecosystem (ts, php, python, go). Each compares the smells with the labels' known packages with `direct` false.
   - Each also asserts that unattributed packages never fire: `github.com/pkg/errors`, sklearn, acme_missing and `Illuminate\Support\Str`.

## Limitations and follow-ups

- **Ambient globals are not extracted:** `process.env`, `window`, `$_GET` and `os.environ`. That needs parser work and an extractor-version bump, so it is a follow-up task. `ambient` matches only Go's cgo `C` today.
- **No multi-layer warning** for an external in several layers. Each layer is decided.
- **External dependencies are not inherited** under `policy.inheritDependencies`.
- **Agent templates** (`src/agents/templates.ts`) still describe `mapx_arch_allowed`'s `to` as "layer, file or symbol". They were left untouched to avoid regenerating the agent docs.
- **Smells are not scored** by `score-arch`. They are covered by tests only.

Changelog: Architecture rules can select packages, built-ins and ambient access (`package`, `builtin`, `ambient`), and `mapx check` reports vendor-confinement and dev-dependency violations and the smells vendor-leak, undeclared-dependency and dev-dependency-in-prod (M5-24).
Changelog (### Changed): `mapx check` now reports packages that no layer covers as uncovered, and `--fail-on-uncovered` fails on them (`policy.uncovered.externals: false` turns that off); `mapx arch init` adds a `Packages` layer every layer may use (M5-24).
