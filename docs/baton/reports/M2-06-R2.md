# M2-06-R2 — HTTP pairing honours Route::domain

Date: 2026-10-31. Base: `develop@00407d6` plus the integrator's P1 remediation patch (`review2.patch`), after M0-20-R3 in the same lane (no shared files). Iteration: `docs/baton/iterations/M2-06-R2.md`. Finding: review 2026-10-31 (P2 table), `reports/M2-06-R1.md` ("Review").

## Delivered

- **`src/frameworks/http/pairing.ts`:**
  - `pairCall` skips a route that carries `metadata.domain` when the call's URL has a host that domain does not serve.
  - `domainPattern()` (cached per domain) compiles the domain:
    - literal labels compare case-insensitively;
    - `{param}` matches one label (`[^.]+`, like Laravel/Symfony host parameters);
    - an unevaluated `{dynamic}` part matches any text;
    - a scheme or port written in the domain is ignored.
  - Routes without a domain and relative URLs (no host) pair exactly as before.
- **Fixture** (`tests/fixtures/vue-http`). These cases use the existing Laravel route `GET /ops/v3/status` on `Route::domain('ops.example.com')` (labelled L123 by M1-07-R2):
  - new `vue3/src/services/domains.ts`;
  - `VITE_OPS_URL=https://ops.example.com` in `vue3/.env`;
  - labels **L47** `domain-mismatch` (the `api.example.com` client calls `ops/v3/status`, expected unmatched) and **L48** `domain-match` (the ops client calls the same path, expected `HomeController@opsStatus`).
  - The labels state what Laravel does: a domain route does not serve another host. They were written before the fix and not adjusted afterwards.
- **`docs/cli-reference.md`:** one sentence on domain matching in the pairing rules (`mapx routes --clients`).

## Limitations

- A domain that MapX could not evaluate at all (`Route::domain(config('app.admin'))` → `{dynamic}`) serves every host, so such routes pair as before.
- A domain route's host still has to be a workspace host (`.env*`, client `baseURL`, `settings.http.hosts`). A route's own literal domain is not taken as evidence that the host belongs to the workspace.
- When a domain route and a domain-less route share a URI, Laravel serves whichever was registered first. Pairing still breaks that tie lexicographically.
- A call with a local host (`localhost`, `*.test`) does not pair with a route on a literal production domain, as Laravel would not route it. A dev setup that relies on such a pair should list the domain in an env value or in `settings.http.hosts` and call that host.
