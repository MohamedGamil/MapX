# M4-24-R1 — Escaping check without blind spots; XSS spec covers every tab

Planned in `iterations/M4-24-R1.md`. Source: `reviews/REVIEW-2026-11-02-b2558df592cf.md` (M4-24 DEFECTIVE; finding 10). Background: `reports/M4-24.md` (P2-4 and the open item).

## Delivered

- **`scripts/ui/check-escaping.ts`, rewritten:**
  - The source is compiled into a `ts.Program` with the checker; same-folder imports such as `./chrome.js` are resolved, packages are not. Every name is resolved to its declaration, by scope.
  - `NUMERIC_NAMES`, `TRUSTED_NAMES`, the fragment-name pattern and the `SAFE_CALLS` list are gone. `escapeHtml` is the only trusted helper, and only as the module's own top-level declaration whose body escapes `& < > " '` (after review).
  - **Variables are judged by their values:** the initializer and every `=`, `+=`, `||=`, `??=`, `&&=`. For arrays, also every `push`, `unshift`, `splice` or `a[i] =`. `for…of` elements are judged by the array.
  - **Parameters are judged by their arguments** at every call of their function. A function also used as a value, a destructured parameter and a `for…in` key are unsafe. The index parameter of an array callback is numeric; the element parameter is safe when the array's elements are.
  - **Helpers are judged by what they return.** The rest of the old `SAFE_CALLS` list (`renderYesNo`, `num`, `barList`, `getRouteMethodColor`…) now passes on its own return values.
  - Properties of a never-written `const` object literal of safe values are accepted (`SOURCE_BADGE[…]`, `LAYER_TOKENS[…]`).
  - **New scans:**
    - a `+` concatenation with a tag in one of its literals has every operand checked;
    - every value written to `innerHTML`, `outerHTML` or `srcdoc` (by `=` or `+=`), or passed to `insertAdjacentHTML`, `document.write`/`writeln`, `createContextualFragment` or `parseFromString`, must be safe, whether it is a template, a concatenation or a variable.
  - An HTML template or concatenation counts as safe where it is used, because its parts are reported where it stands. Each unsafe value is therefore reported once.
- **`src/ui/main.ts`:** the new check found six values that the old one trusted by name. None reached script with today's server, but none was proven safe:
  - the details panel's `symbolCount` (data: `num(…)`);
  - `barList`'s `n` and `n.toLocaleString()` (`num`, `escapeHtml`);
  - the DSM cell's `val`/`textVal` (`matrix[i][j]`, now `Number(…) || 0`);
  - the DSM legend's `val`. This one comes from `getAttribute('data-val')`, which decodes the escaping: a DOM-based path, now `escapeHtml(val)`.
- **`tests/ui-escaping.test.ts`:** now 16 tests (was 2; 8 were added after the review, below):
  - the check runs on every `.ts` in `src/ui` (`main.ts`, `chrome.ts`, `layout-worker.ts`);
  - synthetic sources cover concatenation and each sink, values under the formerly trusted names, scope shadowing, parameters and helpers, pushed arrays, and const versus written objects.
- **`tests/ui/harness.ts`:** `navTabs(page)` (the tabs the navigation lists) and `openTab(page, tab)`.
- **`tests/ui/xss.spec.ts`:**
  - **Fixture additions**, made by the spec's own build step on top of `xssWorkspace`; `scripts/ui/workspace.ts` is not in this task's files:
    - a handler, `[PageController::class, 'show<payload>']` in `routes/api.php`;
    - a symbol name, a Vuex action keyed `'save<img src=x onerror=__xss=1>'` in `src/store/actions.js`;
    - a registered repo `web<payload>`, a git checkout whose axios calls reach the handler (`/api/orders<payload>`) and miss (`/api/nowhere<payload>`);
    - config values: a user exclude pattern `gen<payload>/**`, an unknown key `colour<payload>` and an invalid `parseWorkers: <payload>`.
  - **The spec, three tests in serial mode:**
    1. The M4-24 views, plus the handler in Routes and the symbol name in the Symbols table and its detail.
    2. Workspace (switcher options, repo rows, cross-repo pair); HTTP (table, flow, pair filter, both ends of the matched call); Config (chip, warning, value, repos table). Then it chooses the payload repo (name in the URL, sidebar, scoped Symbols, current row) and loads `?repo=<payload>`, which falls back to all repos.
    3. Checks that the tabs opened equal the tabs `navTabs` lists. A new tab therefore fails the spec until it is covered.
  - Each payload must show as text, and `window.__xss` must stay unset.

## Limitations

- **The check is an analysis of one folder.** It follows names through `src/ui`, but not through packages or the server.
- **`.length` is always numeric (review P2-9, not fixed).** An object from `/api` JSON with a string `length` key would pass: probe ``el.innerHTML = `<b>${data.length}</b>` `` gives `[]`. Requiring an array or string receiver would flag every `data.items.length` in `main.ts`, and the server never sends such an object.
- **Other gaps the check does not see:**
  - a sink through a computed key (`el[key] = …` with `key` not a literal);
  - a class method overwritten at run time (`this.render = …`);
  - HTML written by a dependency (Cytoscape labels are text).
- **Context-insensitive.** A helper's parameter is judged over all its calls, so one unsafe call makes every call's result unsafe (`wrap("ok")` is reported next to `wrap(row.title)`). This errs toward reporting.
- **Recursion is optimistic.** A value that depends on itself adds nothing new to the check.
- **The symbol-name payload has no dot.** `/api/symbol/:name` (`Store.getSymbolByName`) splits a name on `.` into scope and member, so a symbol named `save<img … onerror=window.__xss=1>` cannot be opened (404) and its detail never renders. The spec uses `onerror=__xss=1`, which sets the same global. This is a lookup defect outside this task; see Follow-up.
- **Outside this task's files:**
  - `CHANGELOG.md` is listed in the task's files, but the lane brief reserves it for the integration owner. The line is below.
  - The new payloads are built in the spec, not in `scripts/ui/workspace.ts`.
