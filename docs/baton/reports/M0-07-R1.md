# M0-07-R1 — Package name and distribution correctness

Date: 2026-10-31. P0 from the M0-41 legacy audit (I07, I09). The priority was raised from P1 because every generated Claude Desktop config ran `npx -y mapx`, which 404s.

## Fixed

- **`src/agents/templates.ts`:** a new `NPM_PACKAGE = '@mgamil/mapx'` constant. The Claude Desktop stanza runs `npx -y @mgamil/mapx`. The `mcpCommand` doc comment no longer claims an npx fallback that never existed (configs use the global `mapx` binary from `npm install -g @mgamil/mapx`). The repo's own generated `CLAUDE.md` is corrected the same way.
- **Native binaries:**
  - `build:linux`, `build:linux-arm`, `build:mac-arm`, `build:mac-x64` and `build:win` now run `tsx scripts/build-all.ts <target>`, which embeds `MAPX_BUILD_VERSION` from `VERSION`.
  - `build-all.ts` accepts target names, skips the WASM rebuild for single targets, and exits 1 when a target fails.
  - **Found here:** the old `build:linux` used `--bytecode`, and with Bun 1.3.14 the resulting binary *crashes at startup* ("Expected CommonJS module to have a function wrapper"). So it was broken outright, not just reporting 0.0.0. The scripts no longer use `--bytecode`, matching the Makefile and `build-all.ts`, whose binaries work.
- **README:** a new "Publishing to npm" section covers the scoped name, owner-initiated releases (D007), the `NPM_TOKEN` automation-token secret, and `version-sync`.
- **D011:** the package is `@mgamil/mapx` and Node ≥ 20.18 is the floor; F13's unscoped name and Node 18 are superseded.
