# M4-04 — Scanner: no redundant walk, and no post-scan when a sync changes nothing indexed

Date: 2026-11-01. Base: `develop@e4fc861`. Owner: claude. Iteration: `docs/baton/iterations/M4-04.md`. The plan was re-scoped from measurement before starting; the original parallel walk and concurrent post-scan steps were dropped (spec, "Measurement before planning").

## Delivered (`src/core/scanner.ts`)

- **Paths-only pre-walk.**
  - `discoverFiles(…, { pathsOnly: true })` returns the files the walk indexes (path and language) without reading, stat-ing or hashing them. It does check readability, so unreadable files are left out, as in the full walk.
  - `scanFull` and `scanIncremental` fill `workspaceFileMap` with it. Before, they read and md5-hashed every file once more for that.
- **Git sync early exit.**
  - **When it applies:** after selecting changes and referrers, `_scanIncrementalForRepo` finishes like its existing no-change return when all of these hold:
    - nothing is to be re-parsed;
    - no indexed file is removed;
    - no listed path is an analysis input;
    - the analysis inputs fingerprint is unchanged.
  - **What it does:** it records `last_scan_commit` and `last_scan_time`, settles the Vue registry, refreshes HTTP pairing if its inputs changed, and skips parsing and post-scan.
  - **What counts as an analysis input:**
    - a manifest framework detection reads by name (`DETECTION_INPUT`: `package.json`, `composer.json`, `go.mod`, `pyproject.toml`, `requirements*.txt`, `Cargo.toml`, `Gemfile`, `pom.xml`, `build.gradle*`, `pubspec.yaml` and others, mostly in the default excludes);
    - a scannable regular file with no parser;
    - a removed file that was never indexed.
- **Analysis inputs fingerprint.**
  - It covers `ANALYSIS_VERSION`, `config.settings` (roles, architecture overrides, graph excludes) and `.mapx/frameworks.json`.
  - `runPostScanAnalysis` records it last, after writing `frameworks.json`.
  - A sync then reruns the analysis when settings or the framework override changed, including in the pre-existing no-change path, which used to ignore such edits. It also reruns after an analysis that threw, and after an upgrade that bumps the version.

## Independent review

One fresh agent reviewed the change, working in its own copy. It found no P0. It confirmed that the tests tell old code from new, and that the early exit leaves state consistent: commit and time meta, `dirty_paths`, `removed_files`, the Vue registry, pending referrers, multi-repo early parsing and the detector cache.

Its findings:
- **P1, pre-existing: an interrupted git sync loses the symbols of the files it started re-indexing.** Blob hashes are stored before parsing, so the next sync skips those files. Both old and new code do this; with this change, the next sync also skips post-scan. Registered as **M0-02-R10** (P1, BACKLOG), a hard dependency of M5-01 and M5-02.
- **P2-1. Settings and `frameworks.json` edits were not applied by a noise-only sync.** Fixed with the analysis inputs fingerprint, which also fixes the older no-change path.
- **P2-2. Unreadable files were in the paths-only walk.** Fixed.
- **P2-3. An untracked nested repo or submodule defeated the early exit.** Fixed: only regular files count.
- **P2-4. A deleted never-indexed manifest did not count, and there were test gaps.** Fixed, and tests added.

My own follow-up found a regression the review missed: the default excludes hold `package.json`, `composer.json`, `go.mod`, `pyproject.toml` and `Cargo.toml`, so those detection inputs were non-scannable and would have been treated as noise. Fixed with `DETECTION_INPUT`, and tested.

## Limitations

- **Detection inputs outside the named set.** A manifest a detector reads that is not in `DETECTION_INPUT`, is excluded from the walk, and is edited with nothing else changing, is treated as noise. The regex lists every file name the detectors read today (grep of `src/frameworks`). A new detector reading a new manifest must add it there.
- **Interrupted syncs.** M0-02-R10, above.
- **Post-scan cost itself.** Cluster metrics and architecture analysis (about 4 s of 7 s at 16,000 files) are unchanged. That is a follow-up, if wanted.
