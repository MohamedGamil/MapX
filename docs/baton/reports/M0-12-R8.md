## Delivered

- **`src/parsers/languages/svelte.ts` (new), `SvelteParser`.**
  - **Script blocks.** Each `<script>` block (instance, `context="module"`, Svelte 5 `module`) goes to the TypeScript parser when `lang="ts"` / `lang="typescript"`, else to the JavaScript parser. The parse uses the `.svelte` path, so the `.vue`-only exceptions in `GenericWasmParser` do not apply and the block reads as a `.ts` / `.js` module.
  - **Lines.** Symbol, reference and error lines are offset into the `.svelte` file. HTML comments are blanked first, keeping offsets, so a commented-out `<script>` is not read.
  - **Component symbol.** One class symbol, named after the file, spans the whole file, so the scanner gives it the references outside any narrower symbol, such as imports.
  - **Props.** `export let` bindings keep the kind a `.ts` binding gets (`variable`, or `function` for a function or call value) and get `metadata.prop: true`. The component's `metadata.props` lists them, as a `.vue` component lists its props.
- **`src/parsers/parser-registry.ts`:** `svelte` → `SvelteParser`. The task's `src/parsers/parser-factory.ts` does not exist; the registry is where parsers are chosen.
- **`queries/svelte/*.scm`:** comments now say they are not used for extraction. The grammar and queries stay, because the parse worker pre-loads every bundled grammar with its queries, and its fallback walk needs them.
- **Scanner:** no change. `isJsOrTs` and `JS_MODULE_SOURCE` already count `.svelte`, so relative and aliased imports, the built-in globals skip and the M0-17-R4 receiver skip apply.
- **`tests/legacy-impact-staleness.test.ts`:** the M0-11-R3 test "extracts no references from a .svelte script, so no globals edge can come from it" pinned the old behaviour (D016). It is replaced by "creates no edge from new Date() in a .svelte script to a user Date class, while its project call links": `View.svelte` imports and calls `now()` from `src/clock.ts`, and does `new Date()`. The call edge to `clock.ts` exists and no edge goes to `src/Date.ts`. This covers the original M0-11-R2 AC4 intent. The neighbouring test "creates no edge from new Date() in .cjs, .cts or .svelte" now tests something for `.svelte` too (see the globals mutation).
- **Docs:**
  - README.md and docs/getting-started.md Svelte rows list what is extracted.
  - docs/framework-integration.md: the alias sentence says "JS, TS, Vue and Svelte imports". A new bullet says SvelteKit `$lib` resolves through the generated `.svelte-kit/tsconfig.json` while it is on disk. "Not read" names `kit.alias`.
  - docs/adding-languages.md (outside affectedFiles) no longer lists Svelte under `GenericWasmParser`.

## Limitations

- **Template not read.** No edges from `{foo()}`, `on:click={bar}` or `<Child/>`. An imported child still gets its import edge.
- **Svelte 5.** `$props()` destructuring is not read as props. `$:` reactive declarations are not symbols.
- **SvelteKit aliases.** `$lib` resolves only while `.svelte-kit/tsconfig.json` exists (after `svelte-kit sync` or a build). `kit.alias` in `svelte.config.js` is not read.
- **Calls into a Svelte file.** An unimported `MAX()` or `title()` in another file links to a `.svelte` constant or variable, though it would not link to one in a `.ts` file. The scanner's `VALUE_SYMBOL_LANGUAGES` lacks `svelte`, and `.vue` has the same gap. See the next section.

## Independent review and fixes

Reviewer N found only P2s in the Svelte parser, all fixed:

| Finding | Fix | Evidence (`tests/svelte.test.ts`, "Svelte script discovery and bindings (review)") |
| --- | --- | --- |
| A `generics="T extends Array<string>"` attribute cut the tag at its `>`, so the block went to the JS parser and `$lib` was lost | `scriptBlocks` reads attributes up to an unquoted `>` | "reads a script whose generics attribute holds `>` with the TS parser" |
| `<script>` text inside `{@html "…"}` was parsed as a script | `scriptBlocks` skips `{…}` template expressions (quote-aware) | "ignores <script> text inside a template expression" |
| A `"<!--"` string inside a script blanked the script up to a later `-->` | HTML comments are skipped only outside scripts | "reads a script holding a \"<!--\" string" |
| A module script's `export let` was listed as a prop | Only instance-script `export let` are props | "lists only instance-script export lets as props, …" |
| Svelte 5 runes bindings (`$state`, `$derived`) were `function` symbols, so an unimported `total()` elsewhere linked to them | A top-level binding initialised by a rune stays a variable | same test |

Mutations: the old script regex fails 2 tests, the module-prop mutation 1, and the runes mutation 1. The HTTP pass's `maskComponent` had the same `<script\b[^>]*>` cut (found by the M3-11-R1 lane) and now reads quoted `>` too (`tests/http-client-calls.test.ts`, "extracts the call of a script whose generic attribute holds `>`"; the mutation fails it).

Second review round (reviewer O), P2 fixed:
- **Findings.** A lone quote in a `<style>` block (`/* don't */`) or in a template expression (`{text.replace(/'/g, '')}`) placed before the script dropped every script block. A `<svelte:head>` script was read as the component's.
- **Fix.** `scriptBlocks` skips `<style>` and `<svelte:head>` regions, and a `'` or `"` in a template expression opens a string only when it closes on the same line.
- **Test.** "finds the script after a stylesheet and a template regex holding a lone quote, and not a head script". The mutations "style/head not skipped" and "lone quote swallows" each fail it.
