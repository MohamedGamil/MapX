# M0-09-R4 — Continue integration in Continue's documented format (D014, amends F17)

Date: 2026-10-31. Owner decision D014 amends F17. The `continue` provider now writes Continue's documented layout instead of `.continue/mapx.yaml`, which Continue never loads (M0-09-R3 limitation). `specs/` is unchanged (D001).

## Delivered

`src/agents/templates.ts`:

- **Server file.** `continue` now writes `.continue/mcpServers/mapx.yaml` with `name: MapxGraph`, `version: '<mapx version>'` and `schema: v1`. Its single `mcpServers` entry is `{ name: mapx, command: mapx, args: [serve, --dir, '<project>'] }`, the same command as the other MCP configs.
- **Prompt files.** Four hidden companion templates write `.continue/prompts/mapx-{impact,callers,context,sync}.md`. Each has `name`, `description` and `invokable: true` front matter. These are the M0-09-R2 slash commands.
- **Dropped context providers.** The old `contextProviders` (`cmd`) entries are gone, because Continue has no `cmd` provider. `mapx_export` and `mapx_status` now come through the MCP server.
- **`legacyFiles: ['.continue/mapx.yaml']`.** New template field.
- **`{{PROJECT_DIR_YAML}}`.** A single-quoted YAML scalar: only `'` needs escaping, so backslashes in Windows paths stay intact.

`src/agents/generator.ts`:

- **New action status `remove`, for legacy files that still carry a mapx block.**
  - The blocks are dropped together with one line break each, and the user's other text is kept byte for byte.
  - The file is deleted when nothing else is left.
  - `note` says why the file was removed and which files replace it.
  - A file without a mapx block gets no action and is left alone.
- **Consent for edited legacy blocks.** `needsConsent` is true for `remove` when a hashed legacy block no longer matches its hash (`edited`). Hashless legacy blocks, which is what released 0.3.x wrote, count as mapx's own: Continue never loaded the file, so an edit there never had any effect.
- **Migration under `onlyExisting`.** A provider being migrated gets its new files created even by `agents update`. Legacy actions come last, after their replacements are written.
- **`revert` (`uninit`).** It also removes legacy files, and deletes generated files reduced to mapx's own front matter. Before, the Continue prompts, and also Cursor/Windsurf rules, were left behind holding only their front matter.
- **Unchanged behaviour.** The new files use the existing sentinel, hash, CRLF, final-newline, front-matter-at-byte-0 and `needsConsent` handling.

`src/cli.ts`, `src/mcp.ts`:

- **`agents generate`, `agents update`, `init` and `mapx_agents_generate`** print `<file>: Removed…` with the note.
- **`agents generate` consent check** now uses `needsConsent()` instead of listing the statuses itself.
- **`agents update`** treats a provider with a legacy file as existing, so it migrates.
- **`agents list`** keys status by file. It lists companion files with `+`, which covers Continue's prompts and also Aider's `.aider.conf.yml`, and a legacy file that will be removed with `-`.

Docs: `docs/cli-reference.md` (`agents list`, `generate`, `update`, `uninit`) and `docs/mcp-integration.md` (`mapx_agents_generate`). The task lists `docs/agents.md`, which does not exist; the agent docs live in those two files.

## Limitations

- **Absolute path in the server block.** `.continue/mcpServers/mapx.yaml` holds the absolute project path, like the other MCP configs mapx writes, so it is not portable when committed. I did not verify whether Continue supports a workspace-folder variable.
- **Front matter edits are not detected.** A front matter edit in a prompt, outside the mapx block, does not count as edited and is not refreshed when the template's front matter changes. This is the existing behaviour for Cursor and Windsurf rules.
- **The mapx sentinel comment is sent to the model.** It sits inside the prompt body (`<!-- mapx v… -->`), after the front matter, so it is part of the prompt Continue sends.
- **Hashless legacy blocks are removed without consent,** even if a user edited them. This is deliberate (see Delivered): Continue never read that file.
- **`init` without a TTY generates only `generic`.** It therefore never migrates Continue files; `agents generate` or `agents update` does.
