Date: 2026-10-31. Owner decision D014 (F20): bundle a licence-compatible tree-sitter fish grammar so `.fish` files yield `function` symbols and call edges. M0-12-R3 had made `.fish` a static language indexed without symbols.

The grammar is not published to npm (`npm view tree-sitter-fish` → E404), so no dependency is added to `package.json`. The WASM is committed under `wasm/` like every other grammar. `scripts/build-wasm.ts` can now rebuild it: a grammar entry may name a pinned source `tarball`, which is unpacked under the ignored `build/` and built with the existing `tree-sitter build --wasm` step. **With the committed file removed, `npm run build:wasm` rebuilt a bit-identical WASM** (same sha256). The first attempt unpacked into `/tmp` and failed with `failed to rename wasm output file … Invalid cross-device link (os error 18)`: `tree-sitter build` renames its output across filesystems. Unpacking under the project fixed it, and a comment in the script records why.

Alternatives found and not used: `@esdmr/tree-sitter-fish` 3.7.1-2 (prebuilt WASM, Unlicense) and `@ndonfris/tree-sitter-fish` 3.6.0 (prebuilt WASM, MIT). Both also load in web-tree-sitter 0.26.9 and produce the same tree for the sample, but they are third-party binaries. A WASM built here from the tagged upstream source has provenance anyone can check.

## Limitations

- Only `function` definitions are symbols. Fish variables (`set`), `abbr` and `alias` are not extracted; D014 asks for functions and calls.
- Every command name is a call reference, builtins included (`echo`, `set`, `test`). They resolve only when a fish function of that name exists, the same as bash.
- A one-line `function deploy; build; end` gets the whole line as its signature (the generic signature regex runs to the end of the line). Multi-line definitions get `function name [options]`.
- The "22 languages" counts in `src/agents/templates.ts` and the generated root files (`CLAUDE.md`, `AGENTS.md`, `GEMINI.md`, `AIDER.md`, `.clinerules`, `.github/copilot-instructions.md`) are unchanged. M0-09-R4 is rewriting those templates in parallel, so the integration owner should bump them to 23 after it lands. The docs this task touched now say 23.
- `package.json` is in the task's `affectedFiles` but is unchanged: there is no npm package of the upstream grammar to depend on.
- Rebuilding the grammar needs emscripten or docker, as for every grammar built from source by `scripts/build-wasm.ts`.
