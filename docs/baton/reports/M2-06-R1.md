### Changes

- **`src/frameworks/http/pairing.ts`**
  - **Literal evidence.** A pair needs at least one literal = literal segment. The only exception is the root path `/` when the whole URL is known (base resolved, not a suffix match).
  - **`{dynamic}` segments.** A `{dynamic}` segment (Laravel M1-03-R1) matches a segment but scores 0, so a real parameter route beats it, and it never counts as evidence.
  - **Hosts.**
    - `pairCall(record, routes, { hosts })` pairs an absolute or protocol-relative URL only on a local development host (`localhost`, `127.x.x.x`, `0.0.0.0`, `[::1]`, `*.localhost`, `*.test`, `*.local`) or one of `hosts`.
    - New helper `urlHost`.
    - `urlSegments` also strips the host from `//host/…` URLs.
  - **Unknown method.** Method `UNKNOWN` never pairs, not even with `ANY` routes.
- **`src/frameworks/http/client-calls.ts`**
  - `objectProperty` reads top-level properties only, so it no longer reads nested `method:` or `baseURL:` keys.
  - New `fetchMethod(init)`. A literal top-level `method` gives that method; no init or no `method` gives GET. A method from a variable, a shorthand `method`, a spread or a non-object init gives `UNKNOWN`.
  - `isHttpSkipped(path)` replaces the `HTTP_SKIP` regex:
    - `node_modules`, `*.min.js` and `*.bundle.js` are always skipped;
    - `public/`, `dist/`, `build/` and `vendor/` are skipped only when no `src/` or `resources/` segment comes before them.
  - `maskCode` no longer reads `</…` or `/>` as the start of a regex literal (JSX).
- **`src/core/scanner.ts`**
  - `pairHttpCalls` passes the workspace hosts. These are collected from:
    - `settings.http.hosts`;
    - the configured clients' `baseURL`;
    - URLs in any `.env*` value of a registered repo.
  - The `.env*` walk is shared with the M2-07 fingerprint.
  - The http edge clearing before the early return is unchanged, and "removes http edges when no call is left" still passes.
- **Config surface:** `src/types.ts` adds `settings.http.hosts`. `docs/cli-reference.md` and `docs/mcp-integration.md` document the pairing rules, hosts and `UNKNOWN`.
- **`scripts/eval/score-http.ts`**
  - New `handler` label field, compared through `shortHandler`.
  - `scanHttpFixture(fixture, { config })`.
- **Fixture.** New files hold the M2-06-R1 cases:

  - `vue3/src/services/external.ts` (L41–L44);

  The handlers came from the Laravel fixture's live route labels (script: one live route per method+URI, else abort). No existing route or URL label changed.

## Limitations

- **Workspace hosts are a heuristic:** local development hosts, hosts named in `.env*` files or `settings.http.clients`, and `settings.http.hosts`. Consequences:
  - an own API host hard-coded in source (`axios.create({ baseURL: 'https://api.myapp.com' })`) is treated as third-party until it is listed in `settings.http.hosts`;
  - a third-party host that happens to appear in a `.env` file is treated as own.
- **The root exception.** `/` with a fully known URL pairs with a root route. That is the only pair without a literal segment.
- **`UNKNOWN` calls.** A `fetch` whose method cannot be read is listed with method `UNKNOWN` and is never paired, even when the request is in fact a GET.
- **No-literal calls.** Calls whose only literal segments are a common prefix still pair; for example, `/api/{}` against `/api/{id}` has the literal `api`.
- **Mutant M14** is not caught (see above).

Changelog: HTTP pairing now needs literal path evidence, ignores calls to third-party hosts (own hosts come from `.env` files or `settings.http.hosts`), reads `fetch` methods only from the top level of the options, and no longer skips source directories named `public/` or `build/`. Also fixed: JSX closing tags hid calls on the same line (M2-06-R1).
