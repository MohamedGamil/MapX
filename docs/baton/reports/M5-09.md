## Delivered

**Parsers (extractor version 11; previous agent, verified here).**
- TS `abstract class` declarations are class symbols with their `extends`/`implements` edges (`queries/typescript/{symbols,references,references-tsx}.scm`).
- TS and PHP `interface A extends B` store `extends` edges.
- PHP trait uses (`use HasUuid, \App\Logs;` in a class, trait or enum body) are stored as `metadata.mixins`, resolved like class names (`src/parsers/languages/php.ts`).
- `src/arch/elements.ts` carries a type's `signature` and `mixins` on its element, and puts the stored `extends`/`implements` edges and the `extends`/`implements`/`import` external-reference candidates on the view (`view.inheritance`).

**Ancestry (`src/arch/selectors/hierarchy.ts`, new).** For each type, the direct bases come from three places:
1. the stored `extends`/`implements` edges, for bases resolved to a workspace type;
2. the base list on the declaration's first line (`declaredBases`), for bases outside the index. Each base is qualified through what the file records:
   - PHP: the M5-19 `extends`/`implements` candidates, fully qualified through `use`;
   - TS and JS: the class's `extends` candidate (`sequelize#Model`) or an import candidate;
   - Python: an import candidate (`models.Model` after `from django.db import models` becomes `django.db.models.Model`);
   - Java, Kotlin and Scala: the file's `import` lines;
   - otherwise the base keeps its name as written, without generics. A qualified name that matches a workspace type links to that type;
3. mixins: PHP `metadata.mixins`, and Scala and Dart `with` clauses. A Scala `with` that the index stored as `extends` becomes a mixin hop.

The base list is read for PHP, TS/JS, Python, Java, Kotlin, Scala, Dart, C#, Swift and Ruby. Closure is a breadth-first search over (type, all-extends, has-implements, last-hop-mixin) states, and each state is visited once. Each state keeps only the state it was reached from, and a path is rebuilt only when shown (since the review). As a result:
- **cycles terminate** (`LoopA extends LoopB extends LoopA`), and a type is never its own ancestor;
- **bases outside the index are leaves**: nothing is known about their own bases;
- the first path found to each ancestor is the shortest, and it becomes the explanation chain.

`inheritanceDepth` is computed once for all types over the strongly connected components of the base graph (iterative Tarjan); a cycle's types count once each (since the review). Everything is computed lazily, once per element view.

**Selectors (`src/arch/selectors/index.ts`, `member.ts`).**
- `extends`: the path has only `extends` hops.
- `implements`: the path has at least one `implements` hop.
- `mixes`: the path's last hop is a mixin.
- `inherits`: any path.
- `inheritanceDepth: N`: the longest chain is at least N.
- `member`: the type has an own member whose name matches the regex. A PHP property's `$` is optional.

Ancestor values match a name or its trailing segments, case-insensitive (segments split at `\` `.` `#` `/` `::`), or `/regex/flags`. An external base that is known only as written also matches a qualified value that ends with it. All six selectors are symbol-level: they are inapplicable to files under the three-valued logic, and since the review a member (method, property …) is judged by the type it belongs to. They are removed from `UNSUPPORTED_SELECTORS`.

**Explanations.**
- A match carries `chain`. `all` and `any` pass it on, and membership stores it on the `TraceEntry`.
- `mapx arch which` prints, for example, `L  ← selectors[0].extends: App\Domain\Order → App\Support\BaseModel → Illuminate\Database\Eloquent\Model`, and `arch layers L --why` does the same.
- In JSON, the chain is `chain` on `trace[]` and on `members[]`.

**Inherited dependencies (`src/arch/evaluate.ts`, `report.ts`).** Under `policy.inheritDependencies`, each top-level type that is in scope and in a layer takes on the evaluated edges of its workspace ancestors:
- The edges are grouped by the reporting type of their source.
- Each edge is decided again with the type as the source, through the same `decideEdge` chain.
- It is derived once per (type, target, edge type), through the shortest path.
- An edge is not derived when the type, or its file, already has it, or when its target is the type or one of its own ancestors (since the review). `via` is shortened past eight names.

`Dependency.via` and `Finding.via` hold the path. The message ends with `, inherited via A → B`. An inherited finding has no line, because the edge is in the ancestor's file. `arch deps` shows `via` too, in both JSON and text. When the policy is off, nothing is derived.

**Configuration, schemas, docs.**
- `src/arch/config.ts` compiles `extends`/`implements`/`inherits`/`mixes` values written `/…/flags`. The `member` value was already checked.

- `schemas/arch-report.schema.json` gains `via`.
- `docs/architecture-rules.md` gains a "Type hierarchy and members" section. It covers sources, closure, cycles and external bases, values, depth, member, explanations and inherited dependencies. The selector table and the introspection JSON are updated, and the "not evaluated yet" row for M5-09 is removed.
- `docs/cli-reference.md` documents `via` and the `which` chain.
- MCP (M5-14 landed during this task):

  - `mapx_arch_explain`'s hand-built `layer.matches` now carries `chain` too (`src/arch/mcp-tools.ts`).

## Limitations and follow-ups

- **The base list is the declaration's first line.** A base list that wraps onto a second line loses the bases on the later lines, unless the index has an edge for them. For PHP, the candidates still supply them.
- **Unread inheritance:**
  - Go structural `implements` (P3 in AR-04);
  - Ruby `include`/`extend`;
  - Rust `impl Trait for` (no source symbol);
  - C++ base lists (wrong stored signatures).
  Go embedding counts as `extends`, as stored.
- **Heuristic hop kinds where the syntax is ambiguous.** C# and Swift treat a class's first base as its superclass, except a C# `IName`. Kotlin uses the constructor call. Python and Ruby treat every base as `extends`.
- **Unqualified JVM bases.** A Java or Kotlin same-package base that is not indexed stays unqualified. It still matches a qualified value that ends with it.
- **External bases are leaves.** `extends Model` reaches a subclass of an external subclass of `Model` only if a workspace type sits in between.
- **Depth within a cycle is an upper bound.** The types of a cycle count once each, even when no single chain passes through all of them.
- **Interface ancestors count for inherited dependencies.** `inheritDependencies` derives through every hop kind, interfaces and traits included. An interface's own dependencies (for example its parameter types) therefore pass to its implementers.
- **Out of scope:** `member` does not see inherited members, and `package`/`builtin`/`ambient` belong to M5-24.
- **`mapx arch allowed` and inherited dependencies.** `allowed` counts inherited dependencies as observed between the type and the target, as `check` does, but its decisions do not name `via`.

Changelog: Architecture layers can select types by ancestry and members (`extends`, `implements`, `inherits`, `mixes`, `inheritanceDepth`, `member`), transitively and across languages, including framework bases outside the workspace, and `policy.inheritDependencies` makes a subclass answer for its bases' dependencies, each finding naming the inheritance path in `via` (M5-09).
