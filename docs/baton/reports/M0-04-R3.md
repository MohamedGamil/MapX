# M0-04-R3: Laravel `->middleware(X::class)` route middleware edges via the route file use table

Date: 2026-10-31. Source: the limitation in `docs/baton/reports/M0-04-R2.md`. Built on develop `6d5142c`, which includes M0-04-R2 (`d6a49eb`).

## Before (reproduced on the unchanged code)

The new e2e test (`tests/laravel-mounts.test.ts`, "M0-04-R3: ->middleware(X::class) through the route file use table") failed both of its cases:

- **Route middleware.** `->middleware(EnsureAdmin::class)` recorded the route middleware as the raw text `EnsureAdmin::class`. The array forms (`->middleware([Mw\Audit::class])` and `Route::middleware([EnsureTeam::class, 'auth'])->group(...)`) dropped the class entirely, because `listArg` and `parseGroupAttributes` keep only quoted names.
- **Edges.** The route file got no `middleware` edge to any class.

A second cause turned up while fixing this. The scanner's framework `ScanContext.resolveSymbolToFile(symbol, sourcePath)` ignored `sourcePath`. Without a source language, resolution fails closed (M2-01), so the route-middleware fallback for class names (M0-05-R2) never resolved anything, even for FQN strings.

## Delivered

- **`src/frameworks/detectors/laravel.ts`**
  - `listArg` and `parseGroupAttributes` keep class constants (`X::class`, `\A\B::class`) alongside quoted names, through the shared `listItems` helper. A single argument already came through as `X::class`.
  - The new `middlewareClassNames` names class constants the way PHP does:
    - a whole-name or first-segment import, aliases included (`Mw\Audit` with `use App\Http\Middleware as Mw`);
    - `\A\B` as written;
    - otherwise relative to the file's namespace, or the global `\X` when the file has none.
  - `walkRouteFile` applies `middlewareClassNames` with the route file's own use table:
    - to every route the file produces (`middlewares` and `metadata.middlewares`);
    - to the mount frames it hands to required files, so a required file inherits FQNs rather than the parent's unresolved tokens.
  - `parseRouteServiceProvider` reads `->middleware(...)` through `listArg` and names its class constants with the provider's own use table.
- **`src/core/scanner.ts`**: the framework `ScanContext.resolveSymbolToFile` passes `sourcePath` through. Route-middleware class names then resolve namespace-strictly from the route file (M0-04-R2 rules).

## Limitations

- **Controller-constructor middleware** (`$this->middleware(X::class)` in controllers, `parseControllerMiddlewares`) is still string-only. It was out of scope.
- **The global `\X` form** in a route metadata list appears only for a class that is neither imported nor qualified in a non-namespaced file. That is what PHP would load, and it resolves only if a global class `X` is indexed.

Changelog: Laravel route middleware given as class constants (`->middleware(EnsureAdmin::class)`, `Route::middleware([X::class])->group(...)`) is now named through the route file's `use` statements and linked to the middleware class (M0-04-R3).
