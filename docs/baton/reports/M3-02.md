Date: 2026-10-31. Base: `develop@580546a` (rebased onto M3-03 and M3-07). Owner: lane-vue-template. Iteration: `docs/baton/iterations/M3-02.md`.

## Delivered

Edge-contract rules 1, 2, 4 and 5 (`docs/baton/iterations/M3-01.md`, "Edge contract"):

- **`src/parsers/languages/vue-template.ts` (new):**
  - `componentSymbol(filePath, source)`: one `class` symbol per `.vue`, named after the file (`TicketRow.vue` → `TicketRow`), scope `null`, lines 1 … last, `metadata: {}`. Exported so M3-04 can add `props` / `emits`.
  - `assignOwners(refs, symbols, component)`: a reference keeps the narrowest named function or member around it. Value declarations (`const prefs = usePrefs()`) and `setup` own nothing, so top-level `<script setup>` code, the body of `setup()` and component options belong to the component.
  - `templateReferences(source, componentName, options?)`: reads the root `<template>`. HTML comments and `<script>` / `<style>` are masked, nested `<template>`s are handled, and Pug is skipped.
    - **Calls:** `@x="save"`, `@x="save(1)"`, `v-on:` with modifiers, calls in `:x` / `v-bind` / `v-if` / `v-show` / `v-for` sources / custom directives, and `{{ }}`. Property reads, member calls (`cart.clear()`), `$`-helpers and keywords are skipped.
    - **Component tags:** one render reference per child. A tag is a component when it is not a native HTML/SVG element (matched case-sensitively, as the SFC compiler does) and not a built-in (`component`, `slot`, `transition`, `keep-alive`, `teleport`, `suspense`, `router-link`, `router-view`).
    - **Local registration:** the `components` option (shorthand, aliased, quoted kebab keys, `require()` and `() => import()` values), or any `<script setup>` import.
  - `globalRegistrations(text)`:
    - `Vue.component('Name', X)` / `app.component('Name', X)`, where X is followed through its import, `require('…').default` or `defineAsyncComponent(() => import('…'))`;
    - the Laravel / Vite auto-registration idiom, `require.context(dir, deep, /\.vue$/)` or `import.meta.glob('./dir/**/*.vue')` together with a `.component()` call whose name is computed;
    - comments are ignored, so Laravel's commented-out default registers nothing.
- **`src/parsers/languages/vue.ts`:** small hooks. It adds the component symbol, analyses the Options API object (M3-03's `analyzeOptionsComponent`) when the SFC has a template, adds the template references and assigns owners.
- **`src/core/scanner.ts`:** a reference that carries `metadata.vue` is resolved only through that hint (`resolveVueReference`), never by global name lookup:
  - **call:** a symbol of the SFC itself; then the hinted module, for a destructured composable function (`const { format } = useCurrency()` → `useCurrency.ts#format`, including renames) or a `<script setup>` named import; then, in an Options API component, M3-03's `resolveThisMember` (mixins in merge order, then map helpers);
  - **render:** the `.vue` file of the local registration, or of the global registry, with `target_symbol` = the child's component symbol.

  The global registry is built once per resolution phase and repo, from the repo's JS/TS files that call `.component(`. The hint is not stored on the edge; template edges keep `metadata.template: true`. `thisMemberContext()` now serves both M3-03's `this.x()` branch and template calls, and `readWorkspaceText()` is shared with the import resolvers' `readText`.
- **Integration with M3-03 and M3-07:** develop moved twice during this lane. M3-07 needed no code change (its whole-fixture scan test passes with the template edges). After rebasing, my own mixin parsing was dropped in favour of M3-03's `vueThisScope`. Template calls in Options API components therefore resolve exactly like `this.x()` (later mixins win, `extends` lowest), and M3-05's map-helper resolution will reach template calls with no further change.
- **Docs:** the Vue rows in `README.md` and `docs/getting-started.md`. The CLI and MCP surfaces are unchanged: `call` and `render` already existed.

## Limitations and not done

- **Template-literal interpolation:** calls inside `${}` in a binding (`` :class="`x-${fmt(1)}`" ``) are not seen. `maskCode` blanks template literals whole.
- **Same-file precedence for template calls:** a template call resolves to any symbol of the SFC first. In an Options API component, a module-level helper function outside `export default` would win over a same-named mixin member. Vue would call the mixin's, since the template cannot see module scope. Rare; the fixture has no such case.
- **Global registry scope:** the registry is per repo, not per M3-07 manifest scope. If two apps in one repo register the same name globally, the first registration found wins for both.
- **Global registry on `sync`:** the registry is read when a `.vue` file is resolved. Editing `main.js` alone does not re-resolve unchanged `.vue` files on `sync`, which is the same as other cross-file resolution today. Building the registry reads every JS/TS file of the repo that contains `.component(` once per phase. On repos with many JS files and an unregistered tag, this costs one read of each JS/TS file per scan.
- **Not handled** (render edges fail closed):
  - `<component :is>`;
  - recursive self-reference through `name`;
  - components re-exported through barrel `index.js` files (the registration resolves to a non-`.vue` file);
  - Nuxt path-prefixed auto-import names;
  - root-absolute `import.meta.glob('/src/…')` patterns;
  - Pug templates.
- **`<router-link>`** is skipped as a built-in; navigation edges are M3-06.
- **No independent review agent was run in this lane.** The review is left to `baton-review`.
