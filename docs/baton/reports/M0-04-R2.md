# M0-04-R2: PHP resolution never maps vendor names to app files; tree-sitter $listen

Date: 2026-10-31. Source: the M0-04 findings in `docs/baton/reviews/REVIEW-2026-10-31-fb75474ba377.md` (P1 and P2) and the post-acceptance defect section of `reports/M0-04-R1.md`. Built on develop `a36681c`, which includes M0-12-R3/R4 (import index, per-language precision) and the Laravel detector rework (M1-03-R1, M1-05-R1/R2, M1-07-R1).

## Before (reproduced on the unchanged code)

The new tests were run against the unchanged `src/` and `queries/` (4 of 9 resolution tests failed). On a stock Laravel skeleton:

- **Self-imports.** These were verified import edges from a file to itself:
  - `use Illuminate\Foundation\Http\Kernel as HttpKernel` in `app/Http/Kernel.php`;
  - the matching lines in `app/Console/Kernel.php`, `app/Exceptions/Handler.php`, `app/Http/Middleware/Authenticate.php`, `app/Http/Middleware/TrustProxies.php` and `app/Providers/EventServiceProvider.php`.
- **Vendor names resolved to app files.** `Illuminate\Auth\Events\Registered` resolved to `app/Events/Registered.php`, and `Illuminate\Support\Collection` to `app/Support/Collection.php`. The import resolver accepted any 2-segment path suffix.
- **Self-edges from the short-name fallback.** `extends HttpKernel`, `extends Middleware` and `extends ExceptionHandler` became `extends` edges from each file to itself. `resolveSymbolToFile` matched the short name and preferred the same file.
- **Middleware routed to Kernel.php.** `->middleware('verified')`, an `Illuminate\…` alias, gave a route-file `middleware` edge to `app/Http/Kernel.php`.
- **Homonym in another namespace.** `use App\Billing\Invoice; new Invoice()` with only `app/Models/Invoice.php` present gave a verified `instantiation` edge to `app/Models/Invoice.php`.
- **`$listen` read from raw text.** A docblock example placed before the property was the only `$listen` read, so 0 bindings were stored. Against the old `php.ts`, the worker test's `$listen` assertion received `[]`.

## Delivered

### Import resolution (`src/core/import-resolvers.ts`)

`resolvePhpImport` tries three sources in order:

1. The file that declares the imported type in the imported namespace. The type comes from the symbol index (`typeFiles`). The namespace comes from a new `ImportContext.fileNamespace` callback.
2. The path that the composer.json `autoload` / `autoload-dev` PSR-4 maps of the importing file's directory and its ancestors give. These maps are cached per file set in the import index.
3. The **whole** FQN as a case-insensitive path suffix.

It never drops namespace segments and never returns the importing file. An FQN with no match resolves to nothing.

### Class resolution (`src/core/scanner.ts`)

- **Strict match for namespaced PHP names.** `resolveSymbolToFile` only accepts a type (or function) declared under that short name in that namespace. Otherwise it returns nothing. This replaces R1's path heuristic (`…/Models/Role.php`), which still fell back to any homonym.
- **Namespace map.** `buildSymbolIndex` builds a file → namespace map from `files.namespace`, replaced by this phase's parse results. The import resolver gets it too.
- **Middleware fallback.** A middleware hook whose class the detector could not resolve falls back to the registering file (Kernel.php). It is no longer registered as the target of route middleware edges.

### PHP parser (`src/parsers/languages/php.ts`, `queries/php/references.scm`)

- **`$listen`.** It is read from the `property_declaration` node, so docblocks and commented-out listeners are ignored. Event keys and listeners may be `X::class` or class-name strings, single- or double-quoted, and `'Class@method'` names the class. String listeners are `inferred`, like string container bindings.
- **`use function` / `use const`.** These stay out of the class table but are still emitted as imports.
- **Comments in argument lists.** A comment before an argument no longer shifts argument positions. The new helper `argValue` skips comments, and relation and binding extraction use it with `classNameOf`.
- **Dispatch through qualified names.** `event(new \App\X)`, `\Event::dispatch(new X)` and `notify(new \App\X)` are dispatch or notify edges. The queries also accept `qualified_name`.
- **Route files keep their namespace** in `fileMetadata`.

### Laravel detector (`src/frameworks/detectors/laravel.ts`)

A closure route whose body mentions `X::class` is no longer `declared`, so its route edge is now `inferred`.

## Changed expectations in other tests

- **`tests/legacy-globs.test.ts` (M0-02-R3/R4).** Three tests asserted that after `UserService.php` moves, the `use App\Services\UserService` imports "no longer resolve (PSR-4 path)". Imports now resolve to the file that declares the class, as parameter types and instantiations already did, so the referrer lists include the two import edges. Each test's sync == `scan --force` check still holds.
- **`tests/legacy-imports.test.ts` (M0-12-R3).** `Acme\Services\UserService` → `vendor/acme/src/Services/UserService.php` used to pass by dropping the `Acme` segment, which is the same defect as `Illuminate\Support\Collection` → `app/Support/Collection.php`. The test now supplies `vendor/acme/composer.json` (`"Acme\\": "src/"`), and the case resolves through PSR-4.

## Limitations and work left

- **`->middleware(X::class)` still makes no edge.** The route walker's `listArg` keeps only quoted strings, and mapping a class constant through the route file's `use` table needs plumbing in the reworked walker. Not done; candidate follow-up.
- **Double-quoted `bind("…")` already worked on develop.** It was captured after the review's `getArgText` fix (verified by running the test against develop's `php.ts`: only the comment case failed). I could not reproduce "not captured at all". The new assertion guards it.
- **Strict namespace matching affects only PHP names containing `\`.** A namespaced reference to a class in a file with no `namespace` declaration no longer falls back to a short-name match. Real Laravel apps declare namespaces, and no fixture or test relied on that fallback.
- **The namespace map relies on stored file metadata.** A file indexed before namespaces were stored, or one whose namespace declaration was removed, is corrected the next time that file is parsed.
- **No real Laravel application was available.** The skeleton is synthetic, modelled on the public laravel/laravel layout.

Changelog: PHP `use` imports and namespaced class references now resolve only to the class declared in that namespace, so stock Laravel apps no longer get self-imports or `Illuminate\…` names linked to app files, and `$listen` is read from the syntax tree (M0-04-R2).

## Post-acceptance defect (review 2026-10-31, 2db08bd)

Found by the independent review. With two Laravel apps in one repo (`admin/`, `backend/`) declaring the same classes, the namespaced branch of `resolveSymbolToFile` returned the first declaration, so `backend/`'s `new User()` and its route handlers linked `admin/` files (verified), while the import edge was right.

- **Fix:** the declarations are sorted and the one nearest the caller wins (`closest`, as `resolvePhpImport` does; `src/core/scanner.ts`, `src/core/import-resolvers.ts`).
- **Test:** `tests/legacy-php-resolution.test.ts` "links instantiations, function calls and routes inside each app": no `backend/` edge reaches `admin/`. It failed before the fix (instantiation, call and route into `admin/`).
- **Mutation check:** first declaration again: the test fails (instantiation and route into `admin/`).
- Middleware edges across two apps (merged Kernel aliases) remain: M0-04-R6.
