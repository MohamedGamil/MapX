### Layering choices

`mapx arch init` (roles, the default) proposed 5 role layers with 53 violations, which does not describe a CLI; the configuration is the §3.9 path map instead, updated for `src/arch/` (new since the research) and `src/branding.ts` (Entry). Deliberate allowances, each commented in the file: Core → Arch (M5-16 makes the rules the one source of layer violations, so `core/architecture-analyzer.ts` imports Arch; a deliberate cycle that `mapx arch --smells` reports as `layer-cycle`), Arch → Exporters (the SVG renderer), Agents → Languages (templates state the language count from the registry, a leaf).

**Imports only.** The first version judged the default edge types (calls, instantiations, type references too) and baselined 70 findings. 33 of them were resolver false positives, and rebasing onto develop `8538298` added 3 more, failing the check on code that imported nothing new: `vue-stores.ts`'s new `join(...)` calls and a `Node` type resolved to `src/core/manifests/pypi.ts#Node`. In TypeScript every dependency on another module starts with an import (type-only imports included), and imports are resolved by module path, so `"types": ["import", "require"]` sees every real layer dependency and none of the name-resolution errors. The final baseline has 8 entries, all real imports, matching an independent static count of relative imports in `src/`.

`policy.inferred: "ignore"`: inferred edges are matched by name alone. Under the default `"warn"` they would be warnings, and `--generate-baseline` freezes warn-level violations too, so a change in the resolver's guesses would fail CI with stale entries. (With all edge types, 51 such edges existed, such as the dashboard's `res.json()` calls inferred as calls to `src/arch/mcp-tools.ts#json`.)

### CI: why no SARIF upload

`github/codeql-action/upload-sarif` needs `permissions: security-events: write`. The workflow runs on `pull_request`, and pull requests from forks get a read-only token, so the upload step would fail there. The job therefore gates on `--format github` (annotations need no permission) and keeps `--format sarif` as the `architecture-sarif` artifact. The SARIF step has `continue-on-error: true` and runs whenever indexing succeeded, so the artifact exists even when the gate fails; the gate is the step before it. `--fail-on-uncovered` makes a dependency on `src/` code in no layer (a new top-level folder) fail too, so the layers keep covering the source.
