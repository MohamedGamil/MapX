# M0-07-R4 — The self-extracting installer removes its unpacked archive

Date: 2026-11-04. Base: `develop@96ed235`. Owner: claude. Found by M4-09-R5.

## Cause

`scripts/make-installer.sh` writes an installer that unpacks into `mktemp -d` with `trap _cleanup EXIT`, then ended with `exec "$_INST" ...`. `exec` replaces the shell, so the trap never ran and every real run left `tmp.*/mapx-<version>` in `$TMPDIR`. On the unfixed script, the 6 new installer tests and the existing installer test (now asserting an empty folder) failed: 8 of 15.

## Delivered

- **`scripts/make-installer.sh`** (sh template): no `exec`. The scope flag and value are folded into `"$@"` with `set --`. `install.sh` runs as a background child with `<&3` (a copy of the caller's stdin, which a background job would otherwise lose; `install.sh` reads prompts from it), then `wait`; the installer exits with its status. INT and TERM traps forward TERM to the child, wait, remove the folder and exit 130 / 143. The EXIT trap removes the folder on every other path (`set -e` exits included).
- **`tests/installer-replace.test.ts`**: the contained `TMPDIR` stays and is asserted empty after the existing installer test. New `describe` with 8 tests around a stub `install.sh`: success, `exit 7`, real `install.sh` with an unknown option (exit 1), arguments with spaces, stdin for the menu and a second prompt, `MAPX_INSTALLER` is the installer file, SIGTERM and SIGINT (143 / 130, folder removed, child process gone).
- **`CHANGELOG.md`**: `### Fixed` entry (M0-07-R4).
- **`docs/baton/iterations/M0-07-R4.md`**, and `acceptanceCriteria` in `TASKS.json` sharpened (3 criteria); `plan:validate` passes.

M0-07-R3 check: `MAPX_INSTALLER` is the installer's own path, computed before the handover and outside the removed folder; a test asserts it exists after the run.

## Probe

- Before: `TMPDIR=<empty> sh installer --local` (stub `install.sh`) left `tmp.XXXX/mapx-9.9.9/` behind.
- After, by hand on a pty (Python `pty`): installer menu answered with `1`, stub `install.sh` prompt answered `yes` on the terminal, args `--local`, status 5 returned, `TMPDIR` empty. No SIGTTIN or stdin loss.

## Limitations

- `SIGKILL` of the installer still leaves the folder (untrappable).
- Not run against a real `make package-linux` build (no binary built here); `scripts/check-package.ts` only inspects `dist/`, not installers. The shell template is exercised through `make-installer.sh` itself, with `sh` (dash) as `/bin/sh`. Not tested on macOS `/bin/sh` (bash 3.2 in POSIX mode); only POSIX constructs are used.
- The signal tests wait on 30 s `sleep` children in the failing mutations only; green runs take about 0.1 s each, extraction tests about 1 s (a `tar` shim that sleeps 1 s makes extraction observable).
- A signal sent to the installer alone during extraction is handled when the foreground `tail | base64 | tar` pipeline ends (shell semantics); Ctrl+C reaches the pipeline too.
