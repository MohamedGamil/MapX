# M3-04 — `<script setup>` macros and composables

Date: 2026-10-31. Base: `develop@6b423af` (rebased onto M0-04-R5 and M3-05 during the lane; started on `0b48551`). Owner: lane-vue-setup. Iteration: `docs/baton/iterations/M3-04.md`.

## Delivered

This task covers rule 1's metadata and the composable part of rule 4 in the edge contract (`docs/baton/iterations/M3-01.md`).

- **`src/parsers/languages/vue-script-setup.ts` (new).** It parses each script block with tree-sitter, through `withScriptTree` from M3-05's `vue-ast.ts`.
  - **Interface.** The component symbol gets `props`, `emits` and `exposes` (`exposes` is not scored):
    - `defineProps<{…}>()`, either as a type literal or through a same-block `interface`, `type` alias or intersection, also inside `withDefaults(…)`. Runtime `defineProps({…})` and `defineProps([…])` also count;
    - `defineEmits<{ (e: 'a' | 'b', …): void }>()`, the 3.3 form `defineEmits<{ a: [x: number] }>()`, and runtime arrays and objects;
    - `defineExpose({…})`;
    - Options API `props:` and `emits:`.
    The lists of all script blocks are merged into one.
  - **Composable hints.** These are M3-02's `metadata.vue` hints, so the scanner never falls back to a name lookup:
    - A call to an imported `useX` (named, aliased or default import) resolves through that import. Pinia's `use…Store` is excluded because rule 8 belongs to M3-05.
    - A call to a name destructured from an imported call (`const { persist, rename: setName } = usePreferences()`) resolves to the inner function in the module's file: `persist`, and `rename` for the alias. This applies only inside the block or program where the destructuring is visible, and value flow is followed no further.
    - References that already carry `vueThis` (M3-03) or `vueStore` (M3-05) are left as they are.
  - `reExportsOf(text, name)` finds `export { name } from`, `export { default as name } from` and `export * from`.
- **`src/parsers/languages/vue.ts`.** Two hooks: each script block is analysed, and the merged interface goes onto `componentSymbol()`'s metadata.
- **`src/core/scanner.ts`.** The `from` lookup in `resolveVueReference` now goes through `moduleMember()`, which adds two things:
  1. It follows up to 3 barrel re-exports.
  2. When an alias specifier does not resolve (`@/x` where `@` is not `src/`, `~/x`, `#/x`), it uses the module in the same repo whose path ends with `/x`, preferring the one with the longest shared directory prefix. Results are cached for each phase.
  Without these, sending composables through their import would lose edges that the name lookup used to find. Laravel projects alias `@` to `resources/js`, and the old resolver maps `@/` to `src/` only. These changes also help M3-02's template hints.
- **Fixture (fixtures before fixes).** Trap files were added: `vue2/src/api/client.js` (`persist`, `addReply`) and `vue3/src/api/money.ts` (`useCurrency`, `format`). Their paths sort before `composables/`, so a name lookup picks them. The new negatives are v2-101, v2-102 and v3-101. On develop, all three fail (see below).
  - The IDs start at 101 so they cannot collide with labels that parallel lanes add. Renumbering is up to the integration owner.
  - The fixture README's trap list is updated.
- **Floors (`tests/vue-sfc.test.ts`):** `script-setup-macro` goes from 0 to `labelledCount`. `composable` stays at `labelledCount`, and its comment now names the traps. No floor was lowered. `minPrecision` stays at M3-05's 0.95.
- **Docs:** the Vue rows in `README.md` and `docs/getting-started.md`. The CLI and MCP surfaces are unchanged, apart from new symbol metadata keys.

`src/parsers/ignored-symbols.ts` (listed in `affectedFiles`) needed no change.

## Limitations

- **Fail-closed cases** (no edge; before this change, a name lookup found the target when its name was unique):
  - a composable imported from a bare package (`vue-router`, `@vueuse/core`): correct, because the target is outside the workspace;
  - a re-export chain deeper than 3;
  - a namespace import (`import * as c from …; c.useX()`), which is a member call and is not hinted;
  - a composable whose file does not declare the inner function as a symbol, for example an arrow function stored in an object literal.
- **Scope:** the destructuring's scope is its enclosing block or program. An inner declaration that shadows a destructured name with the same name is not detected.
- **Template calls** still use M3-02's regex `destructured` map, which ignores scope. Script calls use the scope-aware pass.
- **Alias suffix:** this runs only for Vue hints, and only for the prefixes `@/`, `@@/`, `~/`, `~~/` and `#/`, after the normal resolver fails. Two matches tie-break on the shared directory prefix. tsconfig `paths` are not read.
- **Not modelled:** `defineModel`, `defineSlots`, `defineOptions`, props from imported types (`defineProps<ImportedProps>()` yields no props) and Vue 3.5's destructured props.
- **Cost:** each script block is parsed once more with tree-sitter (it was already parsed for M3-03 and M3-05).
- **No independent review agent was run in this lane.** The review is left to `baton-review`.

## Findings outside this task

- `resolveImportPath` maps `@/` to `<repo>/src/` only, and only for `.vue` sources. Laravel (`resources/js`) and sub-folder apps never resolve, which affects M3-02 render hints and M3-03 mixins too. This lane worked around it only for `from` hints (`resolveAliasBySuffix`). A general fix (reading the Vite or tsconfig alias) could be a separate task.

Changelog: Vue components now expose their `props` / `emits` (from `defineProps`, `withDefaults`, `defineEmits` or the Options API) on the component symbol, and composable `useX()` calls and the functions destructured from them link to the composable's file through the import, including through barrel files and Laravel's `@` alias (M3-04).
