# M4-24 — Escape scanned values in the dashboard HTML

Found during M4-17 and registered then; it blocks M4-20.

## The defect

Templates in `src/ui/main.ts` interpolated values from the index, the scan and the tool-call log straight into `innerHTML`:
- route paths and handlers, hook names;
- symbol, file and directory names, and smell descriptions;
- context results, git changes, custom tags;
- tool names, inputs and errors.

A scanned repository controls these values, and script running in the dashboard's origin can call every `/api` endpoint, including `/api/symbol/…`, which returns source code. A probe on the pre-fix dashboard confirmed it: the file `src/evil<img src=x onerror=window.__xss=1>.ts`, in an import cycle, set `window.__xss` when the Architecture tab rendered its smells. The route path and the tool-log entry render at page load, before the probe reset the flag, so only the Architecture result was observed after a reset.

## Delivered

- **Escaping:** every interpolation in an HTML template in `main.ts` is escaped (122 interpolations wrapped in `escapeHtml`, plus fixes by hand), numeric, or a helper that returns escaped HTML. `highlightMatch` (focus autocomplete) now escapes the text around its highlight, and `escapeHtml` accepts any value.
- **`scripts/ui/check-escaping.ts`:** a static check on the TypeScript AST. It finds each template literal containing a tag and requires every `${…}` in it to be one of:
  - `escapeHtml(…)` or a listed helper;
  - numeric (number literal, arithmetic, `.length`, `.toFixed()`, `.toLocaleString()`, `Math.*`, or a listed numeric name);
  - a constant the code chose;
  - a conditional, `||`/`??` or nested template of those;
  - a `.map(…).join('')` with a safe callback;
  - a local HTML fragment variable (`smellsHtml`, `gitStatusHTML`…) whose every assignment is a string literal, a checked template, a safe map/join or another such fragment.

  `tests/ui-escaping.test.ts` runs it on `main.ts`, and on a synthetic source to show what it flags.
- **`xssWorkspace` fixture (`scripts/ui/workspace.ts`):** a Laravel route path, a TypeScript file name in an import cycle, and a logged tool call (name, input, error), each carrying the payload. All synthetic.
- **`tests/ui/xss.spec.ts`:** a browser test that opens Routes, Symbols (search and details), Architecture, Metrics, Tool log, Context (a build) and the graph's focus autocomplete. Each payload must show as text, and `window.__xss` must stay unset.

## Limitations

The check covers template literals in `src/ui/main.ts`. HTML built by `+` concatenation, or through `insertAdjacentHTML`/`outerHTML`, is not parsed; a search found none of either. New views (M4-21 to M4-23) must go through the same check, which runs in `npm run check`.
