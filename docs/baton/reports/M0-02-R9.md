# M0-02-R9 — Sync follows go.mod module paths and composer.json PSR-4 autoload changes

Date: 2026-11-01. Base: `develop@accfae1`. Owner: claude. Source: the M0-02-R8 report (reviewer N).

## Delivered (`src/core/scanner.ts`)

- **New manifest families.** `configReferrers` (M0-02-R8) now also signs each `go.mod` in every folder above a Go file, and each `composer.json` above a PHP file. These are exactly the files `resolveGoImport` and `psr4Roots` read.
- **Re-parsing.** A changed, added or removed manifest re-parses only that family's files below it.
- **Signature keys.** They are NUL-prefixed (`\0go:<dir>`, `\0php:<dir>`), so no folder name can collide with them.
- **The `#families` marker** lists the families a record holds. A family a record lacks, from an index written before this task, is recorded on its first sync without re-parsing.

## Independent review

One fresh agent reviewed the change, found no P0 or P1, and passed every criterion. Its probes ran on the git path, on the git path with gitignored manifests (the dry-run early exit), and on the hash path:
- nested `go.mod`;
- a root rename with a nested module;
- a removed `go.mod`;
- a subfolder `composer.json`;
- a legacy record.

All gave sync equal to `scan --force`, and a second sync parsed nothing. It found the M4-04 interaction correct: `DETECTION_INPUT` makes the post-scan run. It measured no difference in no-op sync time on 9,000 PHP files.

Its P2s:
1. **Folder keys with a colon** were taken for family keys. Fixed with the NUL prefix.
2. **The marker was compared all-or-nothing.** Fixed: it is compared per family.
3. **Upgrade gap.** A manifest edit made between the last pre-R9 run and the first post-R9 sync is recorded but not re-resolved until `scan --force`. That follows from criterion 3, and is documented in the changelog.
4. **Test gaps.** The reverse direction is now tested.

## Limitations

- **A root manifest change** also re-parses files under nested modules: extra work, not wrong results.
- **The one-time upgrade gap** above.
