# M0-10-R3 — Workspaces: F18 fields, duplicate config cleanup, cross-repo references after workspaces add

Date: 2026-10-31. Sources: the Limitations of `reports/M0-10-R2.md` (missing F18 fields, duplicate entries not cleaned up) and the finding in `reports/M0-03-R4.md` (references stay unresolved after `workspaces add`). Design input: F18 (`RepoSummary`, `mapx_workspaces` response).

## Before (reproduced)

With the new tests and the pre-change `src/` (cli, mcp, scanner, config, workspace-summary), 7 of 30 tests in `tests/legacy-workspaces.test.ts` and `tests/legacy-metrics-edges.test.ts` failed:

- **F18 fields.** `mapx_workspaces` entries had a relative `path` and no `relativePath`, `isRegistered` or `isInitialised`. The uninitialised submodule did not appear in `repos`.
- **Duplicates.** A config listing `lib`, `lib-link` (a symlink to `lib`) and `./lib/` stayed as it was, with no message. The files already indexed under `lib-link/` stayed in the store.
- **Scan after add.** `init`, then `workspaces add libs/ui` (which scans ui while the primary repo has no indexed files), then `scan --all`: there was no `libs/ui/button.ts → src/theme.ts` edge. Only `scan --all --force` produced it. The M0-03-R4 cross-repo edges tests (2 tests) failed once their `--force` workaround was dropped.

I extended the scan case to `update --all`. That check passed on the old code only because the fixture had no commits: an unborn HEAD lists every file as changed. With both repos committed, `update --all` after `workspaces add` exposed two problems:

- it never indexed the primary repo's committed files: a git diff from HEAD lists none of them, and the scan still recorded `last_scan_commit`;
- it left ui's references unresolved.

## Delivered

- **`src/core/config.ts`:** `Config.load` collapses repo entries that name the same folder (`canonicalPath`, so symlinks and other spellings such as `./lib/` count). It keeps the first entry, saves the config, and exposes the dropped entries as `collapsedRepos` (`{ dropped, kept }`).
- **`src/core/workspace-summary.ts`:**
  - `applyCollapsedRepos(config, store)` deletes the stored data of each dropped entry whose name is not kept (`store.deleteRepo`) and returns one message per dropped entry: `Removed duplicate repo entry lib-link (lib-link): same folder as lib (lib).`
  - `repoState(dir, relativePath, type, isRegistered)` returns F18's `path` (absolute), `relativePath`, `isRegistered` and `isInitialised`. `isInitialised` means the folder exists and, for a submodule, has its own `.git`.
- **`src/cli.ts`, `src/mcp.ts` (`loadContext`):** both print the collapse messages on stderr. In MCP, stdout is the stdio transport. Every command collapses, including `workspaces sync`, which loads through `loadContext`.
- **`mapx_workspaces` (`src/mcp.ts`):** each registered entry carries the F18 fields. Unregistered uninitialised submodules follow, as in the `mapx workspaces` table, with `isRegistered: false`, `isInitialised: false`, zero counts, and `null` for `lastScanned` and `headSha`.
- **`src/core/scanner.ts`:**
  - **Visible repos.** Each scan records which other repos' files reference resolution could see (`meta resolution_repos:<repo>`), drawn from the scan's workspace file map.
  - **Full scan.** `_scanFullForRepo` re-parses the whole repo once when a repo is visible now that was not at its last parse. This is the same mechanism as for changed filters (M0-02-R1).
  - **Incremental scan.** `_scanIncrementalForRepo` takes the full-scan path in that case, and also when the repo has nothing indexed yet.
  - **Repos indexed before this change** (no record) are re-parsed once if another repo is visible.
- **Tests:** `tests/legacy-metrics-edges.test.ts` no longer passes `--force` (the M0-03-R4 workaround). The existing `mapx_workspaces` test filters by `isRegistered`.
- **Docs:**
  - `docs/mcp-integration.md`: the F18 fields and the unregistered submodule entries.
  - `docs/cli-reference.md`: the duplicate collapse and its message, re-parsing when a repo becomes visible, and a note on `workspaces add`.

## Limitations

- **Coarse re-parse.** When a repo becomes visible, every file of each repo that could not see it is re-parsed once, not only files with unresolved references (they are not recorded). Files *added* later to an already visible repo still do not trigger a re-parse of other repos' unchanged files. This matches the existing within-repo behaviour.
- **One-time re-parse on upgrade.** Multi-repo workspaces indexed before this change have no `resolution_repos` record, so each repo is re-parsed once on its next scan while another repo is visible. No test covers this fallback.
- **Dashboard.** `src/ui-server.ts` also calls `Config.load`. It collapses and saves the config there, but prints no message and does not delete the dropped entry's data. If the dashboard is the first to load such a config, that data stays until `workspaces remove` or a forced scan.
- **MCP message.** The MCP loader reports collapses on stderr only, not in tool output.
- **Spelling.** `discovered` entries keep their existing `isInitialized` spelling; only the F18 `repos` entries use `isInitialised`.
- **Extra fix beyond the criteria.** `update --all` on a never-indexed git repo used to index none of its committed files and still record `last_scan_commit`. It now takes the full-scan path. This is covered by mutant 11.

Changelog: `mapx_workspaces` now returns F18's absolute `path`, `relativePath`, `isRegistered` and `isInitialised` (and lists uninitialised submodules), duplicate repo entries already in a config are collapsed with a message, and `scan --all` / `update --all` after `workspaces add` resolve the new repo's references into the primary repo without `--force` (M0-10-R3).

## COMPLETION DISPUTED (review 2026-10-31, 2db08bd)

DEFECTIVE (P1): The first `scan --all` depends on repo order: the primary repo is resolved before the other repo's symbols exist, so `src/app.ts → libs/ui/button.ts` instantiation is missing, and `resolution_repos` already marks the repo visible, so a later plain scan never repairs it (AC3's reference result is itself order-dependent). P2: remove + add needs --force; Config.load's duplicate collapse leaves the dropped repo's rows. Remediation: M0-10-R4. See `reviews/REVIEW-2026-10-31-2db08bd25e13.md`.
