Remediation of M5-03 (review 2026-11-02, P1 open). Planned in `iterations/M5-03-R1.md`.

## Delivered

**Parser queries (stored symbols change for every scan):**
- `queries/cpp/symbols.scm`: C++17 `namespace acme::infra { … }` is a namespace symbol named `acme::infra`. Before, it was not captured.
- `queries/ruby/symbols.scm`: `class Billing::Receipt` and `module Billing::Core` are stored, named by the last constant and scoped by the qualifier. Before, the class was dropped and its methods were unscoped.
- `queries/dart/symbols.scm`: `library acme.domain;` is the namespace `acme.domain`. Before, it was `domain`.
- `src/parsers/generic-wasm-parser.ts`: a function inside a Scala `object` is a method scoped to the object.

**`src/arch/elements.ts`:**
- **Scoped rule (C++, Ruby, Elixir):** the qualified name is the enclosing container's qualified name, plus the stored scope when it differs from that container, plus the name. Containers are namespace, module, class, struct, interface, trait and enum symbols. The enclosing one is found from line ranges: the smallest covering range, with namespace before module before type on equal ranges.
  - Gives `acme::domain::Order::run` for an out-of-line `void Order::run()` inside nested namespace blocks.
  - Gives `Billing::Core::Invoice::pay`, `Billing::Receipt::print` and `Billing.Invoice.pay`.
  - A file's own qualified name in these languages is its path.
- **Module roots:** Python module paths start at the nearest `pyproject.toml`, `setup.py` or `setup.cfg`, and Rust at the nearest `Cargo.toml`; otherwise at the repo path.
- **`topLevel` in scoped languages:** not inside a type, and not a member scoped to an owner. A class inside a namespace or module is top-level.

**`src/arch/selectors/index.ts`:**
- **`inapplicable` result:** a `name` selector on a file, and a selector this version cannot evaluate, are not matches. `not` of them is not a match either; `all` with one is not a match; `any` whose every branch is inapplicable is inapplicable.
- **`.tsx`:** `language: typescript`/`ts` matches `.tsx` files (MapX language `tsx`); `tsx` matches only those.

**Docs:** `docs/architecture-rules.md` covers:
- the qualified-name table (C++, Python, Rust, Ruby and Elixir rows), plus a note on the line-range nesting;
- symbol-level selectors on files;
- the AR-01 file rule with the Controller/Domain example;
- top-level symbols and file-private membership.

## Limitations

- **Kotlin:** `package` is still not captured, so Kotlin uses the documented path form.
- **C++ in-class declarations:** a method declared in a class (`void run();`) is not a stored symbol; out-of-line definitions are.
- **Same-line containers:** nesting is by line range. Two namespaces opened on one line with equal ranges are not nested, and neither are two types on one line, unless the parser scoped one to the other.
- **Java and C# nested types:** these keep the `Outer.Inner` form only through the stored scope (`Inner.m`). The full chain is not built, as before.

Every finding was reproduced on a real scan:

| # | Finding | Fix | Test (mutation fails it) |
| --- | --- | --- | --- |
| P1 | `not` over `any` mixing an inapplicable branch and a miss still selected files | Three-valued (Kleene) logic: such an `any` is inapplicable | `not, all and any …`: `{not:{any:[name, path]}}` on a file; layer membership |
| P1 | Elixir module functions counted as top-level, so a Phoenix controller file was in Controller and Domain | An Elixir module is a type for `topLevel`; a nested `defmodule` is still top-level | `AR-01 on an Elixir controller`; topLevel assertions |
| P2 | Same-line containers: `namespace one { class A {}; void freeF() {} }` gave `one::A::freeF` | On one line, a type encloses only a symbol scoped to it | `cpp/oneline.cpp` names and topLevel |
| P2 | Out-of-line members lost their qualifier: `void Outer::Inner::f()` gave `acme::Inner::f` | A member scoped to a type the file declares is named under that type | `cpp/outer.cpp` names |
| P2 | A declaration scoped to its namespace (`using OrderId` in `namespace domain`) was not top-level | Scoped to the enclosing namespace or module counts as file level | topLevel `acme::domain::OrderId` |
| P2 | Ruby `class ::Top::Thing` kept the leading `::` | Leading `::` dropped from the scope | `rb/top.rb` names |

Not fixed, and recorded as limitations:
- **One-line `a::b` namespaces:** a one-line C++ `namespace a::b { void use() { … } }` makes the namespace the source symbol of `use`'s call edges. One-line `namespace a { … }` already did this before this change.
- **`.h` headers:** these are indexed as C, so C++ classes in headers get path-form names (`src/languages/registry.ts`).
- **C# with several namespace blocks:** every symbol in the file takes the first block's namespace.
