# M1-07-R2 — RouteServiceProvider mounts walked like other providers; prefixes, names and domains evaluated

Date: 2026-10-31. Base: `develop@00407d6`. Iteration: `docs/baton/iterations/M1-07-R2.md`.

## Reproduction (develop@00407d6)

Reviewer D's probes were re-run against this worktree before any change:

- `p5-rsp.mjs`: `/shop` (glob loop with `->group($file)`), `/required` (`require`) and `/loaded` (`loadRoutesFrom`) came out `unreachable`, without the mount's prefix and middleware. `/shop` should be `/api/shop` with `api`.
- `p6-rspattrs.mjs`:
  - `GET /config('app.api_prefix')/users name=users`, with no dynamic flag and no `api.` name prefix;
  - `GET /admin/{$this->version}/panel` with no `domain`.

After the fix, the same probes give:

- `/api/shop [api]`, `/required` and `/loaded`, all reachable and `mountedBy` the provider line;
- `/{dynamic}/users name=api.users` with the dynamic flag;
- `/admin/v3/panel` with `domain=admin.example.com`.

## Delivered

- **`laravel.ts`, `buildMountGraph`:** the RouteServiceProvider is walked with `walkRouteFile(…, { provider: true })`, like every other provider. This covers glob loops, `require`, `loadRoutesFrom`, `->group($var)`, evaluated prefixes, `name()`, `domain()`, `withoutMiddleware()` and conditionals.
  - Its mounts are the app's entry points, in walk order. `mountedBy` is `app/Providers/RouteServiceProvider.php:<line>`.
  - Its unresolved mounts join the app's unresolved list, so unmounted route files get reachability `unknown`. They are listed in `unresolvedMounts`.
  - A mount that sets no namespace gets the provider's `$namespace`, or `App\Http\Controllers` without one. This matches the legacy parser.
  - `parseRouteServiceProvider` and `resolveRoutePath` are deleted.
- **Default mounts:** `routes/web.php` and `routes/api.php` are used only when no entry point declares anything. They are no longer used when a mount could not be evaluated. An app whose only mounts are unresolved keeps its graph, so its files are `unknown` instead of falling back to guessed defaults.
- **`chainAttributes`:** `->namespace(<expr>)` is evaluated, so `$this->adminNamespace` reads the property. A null or unknown value sets no namespace. Previously the raw PHP text was used.
- **`laravel-mounts.ts`:**
  - `stringAssignments` records class property declarations as `this->name`, visible to every method whatever their position. Static properties are skipped.
  - With path context, it also records assignments of any expression `phpString` can evaluate (`$routes = base_path('routes/x.php');`).
  - `phpString` and `interpolate` read `$this->p`, `"{$this->p}"` and `"$this->p"` from the properties, never from a local with the same name.
- **Scorer (`scripts/eval/score-routes.ts`):** a live or conditional label may carry `name`, `domain` and `dynamic`. Each one must equal the matched route's value. The scorer reports `attributesLabelled`, `attributesFound` and `attributeRecall`, and `--min-recall` applies to attribute recall too.
- **Fixture (`tests/fixtures/laravel-routes`):** `RouteServiceProvider::mapProviderRoutes()` is called from `map()`. It uses these mount forms:
  - a braced glob loop with `->group($file)`;
  - a brace-less glob loop with `require`;
  - `require` and `loadRoutesFrom`;
  - `->group($routes)`;
  - a `config()` prefix;
  - `"ops/{$this->version}"` with `domain()` and `name()`;
  - `"audit/$this->version"`.

  `$version` is declared after the method that uses it. There are nine route files under `routes/rsp/`. Labels L115–L127 add patterns `rsp-glob`, `rsp-require`, `rsp-load-routes-from`, `rsp-variable-mount`, `rsp-dynamic-prefix`, `rsp-property-prefix` and `rsp-raw-prefix`. The raw-PHP and `{dynamic}` URIs are labelled `absent`. The floors test requires every labelled attribute.

## Limitations

- Routes declared directly inside the provider (`Route::get` in the RSP, or a closure group) are still not collected, as with every other provider.
- An RSP whose mounts are all unresolved no longer gets the `routes/web.php` and `routes/api.php` defaults as reachable. Those files are reported `unknown`, with the name-based prefix and middleware.
- An unevaluable reassignment does not shadow an earlier value, and variables are not scoped per function. Both predate this task.
- The RSP's default namespace keeps the legacy `App\Http\Controllers`, even for Laravel 8+ providers without a `$namespace` property. In those apps, Laravel does not prefix string controllers.
- `LaravelWorkspaceContext.routeServiceProvider` is still never populated. It was not populated before either. `getInitialGroupConfig` always takes its name-based branch.

## Independent review and fixes

Reviewer H reproduced one P1 (and P2s):

- **P1.** A stale variable binding mounted the wrong file. `$path` of `mapApiRoutes()` was still visible in `mapModuleRoutes()`, so `routes/api.php` was mounted a second time under the module prefix (a false route), and `routes/modules/blog.php` was reported unreachable.
- **Fix (`laravel-mounts.ts`).** Every binding is visible only up to the end of the function body that holds it (`Binding.end`, `functionBodies`). An assignment that cannot be evaluated clears the earlier value.
- **Test.** "M1-07-R2 review: variable bindings stay in their method" has three cases:
  - the reviewer's two methods;
  - a method whose `$path` is only a parameter;
  - a reassignment within one method that cannot be evaluated.
- **Mutations.** "no scoping" and "no clearing" each fail the test.
- **Changed unit test.** The existing test "reads $this->prop from class properties, apart from locals of the same name" read a method's local from the end of the file. It now reads inside the method and asserts that the local is not visible after it.
- **Not fixed (P2):**
  - a property reassigned in a method;
  - `Route::name($unknown)` dropped silently;
  - `static public $x` modifier order;
  - no fixture label for an RSP mount that cannot be evaluated (tests cover it);
  - a full controller name without a leading `\` being namespaced twice (a base issue).

  They are recorded here for M1-03-R2.

Second independent review (reviewer J, after the binding fix): variables scoped per method, unevaluable reassignments giving "unknown", closures with `use`, methods called with arguments, loop variables and escaped `$namespace` were all checked and found correct. Remaining P2s, registered under M1-03-R2's criteria:
- `.=`, `??=` and `$this->prop =` assignments are ignored;
- a partly dynamic prefix is not flagged dynamic;
- a name prefix that cannot be evaluated is dropped;
- a closure without `use` sees the enclosing method's variables.
