# M2-12-R1 report: tests/ui/arch.spec.ts counts follow M2-12's call dependencies

This is a post-acceptance defect of M2-12. M4-09-R5 found it on 2026-11-04: `npm run test:ui` failed on `develop@08aab1c` with `tests/ui/arch.spec.ts:88`, where the Violations tile showed 23 against an expected 16. Six serial specs did not run after it.

## Cause

The bisect ran `git bisect run` from `433befe` (good, the spec's last update) to `08aab1c` (bad), on the real Playwright spec. It found `6498e16`: M2-12, "a method called on a new instance links its class's method". The deciding runs were `0b4eeb1` (pass) and `6498e16` (fail, 23).

The fixture `tests/fixtures/arch-rules/ts` writes `new X().run()` throughout. Since M2-12, each such call is a `call` edge to `X#run`, beside the `import` and `instantiation` edges. The view counts one dependency per element pair and edge type, as `mapx check` does. Every pair with such a call therefore gains one dependency.

The diff of `mapx check --format json` on the plain fixture: from `0b4eeb1` to `6498e16`, violations go from 16 to 24 and uncovered from 4 to 6. All eight added violations are `call` findings on pairs that already had one. For example, OrderController → Order (`new Order().run()`), and Result → Money (`new Money().run()`, the pair the spec baselines).

Nothing flagged it at the time because `test:ui` is not part of `npm run check`. M2-12's verification did not run it.

## Delivered

`tests/ui/arch.spec.ts` now expects the engine's current counts. Every value was read from the view (a throwaway probe spec dumped the diagram, the DSM, the drill-downs and the filter counts) and explained by the call dependencies:

| Assertion | Before | Now | Why |
| --- | --- | --- | --- |
| Violations tile | 16 | 23 | 24 violations; the baselined Result → Money call is skipped |
| Baseline debt tile | 2 | 3 | that skipped call |
| Uncovered tile and kind filter | 4 | 6 | `new Clock().run()` and `new Uuid().run()` call the uncovered `src/support` |
| Shared → Domain skipped edge, DSM cell, drill kinds | 2 | 3 | the baselined pair gains its call |
| Controller → Application violation edge | 4 | 6 | two pairs, each with a call |
| Controller → Application drill | 4 / 4 | 6 / 6 allowed / violating | the same per-pair calls |
| `private-layer` rule rows | 4 | 6 | the same two pairs |
| Infrastructure layer, verified rows | 6 | 9 | three pairs, each with a call |

The plugins layer (2 rows) and the unused allowance (Infrastructure → Shared) are unchanged. `new Money()` in `Widget.ts` calls nothing.

## Limitations

- `npm run test:ui` remains outside `npm run check`, so a resolution change can break UI counts unnoticed again. M4-09-R5's verification runs `test:ui`; adding it to the baseline is an owner choice, because it needs browsers and takes several minutes.
