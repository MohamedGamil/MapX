# M4-09-R1 report: the whole test suite leaves the checkout untouched

Remediates M4-09, which the 2026-11-02 review found FALSELY COMPLETE. `tests/mcp-coverage.test.ts` called MCP tools with `dir: '.'`. Its `node:fs` mock does not cover `appendFileSync`, so `UiEventBus` appended to the checkout's `.mapx/tool-calls.jsonl`. `check-test-cwd.mjs` saw only `.mapx/` contents and top-level names.

## Delivered

- **`scripts/baton/check-test-cwd.mjs`:**
  - snapshots, before and after the run, `git status --porcelain=v1 -z --untracked-files=all --ignored=matching`, with a content hash of each listed file and of every file under `.mapx/`; `node_modules`, `dist`, `coverage` and the Playwright outputs are skipped;
  - with no arguments it runs the whole vitest suite;
  - `--cmd <command…>` runs any command instead;
  - it exits with the command's own failure code, else 1 when anything changed, naming each path.
- **`tests/mcp-coverage.test.ts`:** runs from a temporary folder (`beforeAll` chdir, `afterAll` restore and delete), as `tests/cli.test.ts` does since M4-09.
- **`tests/check-test-cwd.test.ts`:** a temporary git repo with an already-modified file and `.mapx/` sentinels. The check passes on a no-op, and passes through the command's own exit code. It fails, naming the path, when the command:
  - edits a top-level tracked file;
  - creates a nested untracked file;
  - appends to `.mapx/tool-calls.jsonl`;
  - edits an already-modified file;
  - deletes a tracked file;
  - changes `.mapx/mapx.db`.

## Verification

All of these ran in a clean clone of `0d29a43` plus this task's files, because the shared checkout holds another session's work in progress (M5-03-R1). The clone held sentinel `.mapx/config.json` and `.mapx/mapx.db` files.

## Mutation checks

The script was restored from a backup and compared with `cmp` after each mutation.

| Mutation | Result |
| --- | --- |
| Status entries without a content hash | "edits a file that was already modified" fails |
| No `.mapx/` walk | the `tool-calls.jsonl` and `mapx.db` cases fail |
| Old listing (`--untracked-files=no`) | "creates a nested untracked file" fails |
| `mcp-coverage` without the chdir hook (the pre-fix file) | the whole-file check exits 1 |

## Limitations

- **Concurrent writers:** the check compares the whole checkout, so another process writing there during the run (another session, an editor) is reported as a change. Run it in a clean clone, as here, when the checkout is shared.
- **Untracked paths:** writes under `node_modules`, `dist`, `coverage` and the Playwright output folders are not checked.
