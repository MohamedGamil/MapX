# M0-20-R1 — NestJS and GraphQL extraction defects

Date: 2026-10-31. P1 from the M0-41 legacy audit (I20).

## Fixed

- **Decorator scope (`nestjs.ts`):** the detector used to take the 1,000 characters before `class X` as its decorators. A plain class after a `@Controller('users')` class therefore inherited the controller (phantom route `GET /users/not-a-route`) and its guards (phantom `UseGuards:AuthGuard` hook). It also located classes with `indexOf('class Name')`, which matches name prefixes. A new `classSegments()` gives each class exactly its own decorator zone (between the previous class's closing brace and its header) and its own body, using balanced braces. Routes and hooks both use it.
- **GraphQL operations:** `decoratorCalls()` reads decorator arguments with balanced brackets. `@Query(() => [User], { name: 'users' })` gives operation `users`; before, `([^)]*)` stopped at the first `)` and produced the name `"("`. A string argument or the method name is the fallback.
- **Hook edges (`scanner.ts`):**
  - edges now carry the hook's own metadata, so `operationType` reaches the stored edge;
  - interface hooks handled in their own file (lifecycle `OnModuleInit`, guard `CanActivate`, …) no longer create a file-to-itself edge. They are still listed by `mapx hooks`.
