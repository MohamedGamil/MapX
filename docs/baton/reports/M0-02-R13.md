# M0-02-R13 report: a package.json edit re-parses only the files its change affects

## Cause

`configReferrers` (M0-02-R8) hashed package.json and pnpm-workspace.yaml into one signature per folder, together with the folder's other configs. A change to that signature re-parsed every JS/TS/Vue/Svelte/Python file under the folder, nested packages included. The manifests above the workspace root (`^` keys, M3-05-R3) re-parsed every source.

A probe on `develop@9ea18f4` measured this: a root `version` bump re-parsed 4 of 5 sources in a synthetic workspace, and 598 of 700 files on a tree of npm packages. See the spec, [iterations/M0-02-R13.md](../iterations/M0-02-R13.md), for the probe and for every package.json reader in `src/`.

## Delivered

- **`src/core/scanner.ts`:** `manifestInputs` and `manifestReferrers` replace the package.json part of the folder signature. Each folder with a manifest gets two kinds of entry:
  - **`\0view:<dir>`:** the store-library gate bits, plus a hash of the auto-import flag, the nearest app and package folders, the jest declaration and the `NODE_PATH` declaration.
  - **`\0pkg:<dir>`:** the package name, the registry or local kind of each dependency, and the entry fields.

  Each file is compared against its own old and new view. A file that quotes a package name is re-parsed when the nearest manifest's answer for that name changed, or when the workspace package table moved for it.
- **Detector ignore lists:** `ignoreActivation` and `ignoreReferrers` cover the vue-router ignore list (review P1-1, P1-2). Gaining or losing `vue`/`vue-router` re-parses the files, of any language, whose text holds a name that the change added to or removed from their ignore set. A nested manifest covers its own folder only.
- **Older records:** a record without the `#manifests` marker is compared the way it was written, for one sync. That sync recomputes the old-style folder hashes, so a tsconfig or bundler edit made in the window is still followed (review P2-1).
- **New workspace packages:** `manifestInputs` also sees the files a sync adds, so a workspace package that arrives with its files is in the name table when its importers are judged (review P2-2).
- **`src/core/js-aliases.ts`:** exports `manifestRootKind`, `packageModuleRoots` and `RootDecl`. The resolvers and the tracking now share one computation, so they cannot drift apart.
- **`src/parsers/languages/vue-stores.ts`:** `storeGateMatters`, the hint test split out of `storePass`.
- **`src/frameworks/framework-registry.ts`:** `detectActiveFrameworks` takes `only`.
- **Tests:** `tests/scanner-config-referrers.test.ts` (41 tests, e2e, git and hash sync, each compared with `scan --force`).

There is no extractor-version bump and no schema change, because a full scan indexes exactly as before.

## Independent review

A fresh reviewer checked the first version against the spec and the diff. All findings were fixed, and the reviewer's own repro scripts (`scratchpad/review-M0-02-R13/scen2.cjs`, `scen3.cjs`, `scen5.cjs`, `legacy.cjs`) now report sync equal to `scan --force` in every scenario, under git and hash sync.

| Rank | Finding | Resolution |
| --- | --- | --- |
| P1-1 | Adding or removing `vue`/`vue-router` toggles the vue-router ignore list passed to every parse; the change re-parsed nothing, so sync diverged from `scan --force` | `ignoreActivation` / `ignoreReferrers`; tests "after vue or vue-router is added to or removed from package.json" |
| P1-2 | The same for Python and other non-JS files | every language is a referrer for the ignore signal only; the test covers a Python file |
| P2-1 | The older-record guard hid a tsconfig or other config edit made in the window | the old-style folder hash is recomputed for that sync; test "with another config edited in the window" |
| P2-2 | A workspace package added in the same sync as its files was missed by importers elsewhere | `manifestInputs` includes arriving files; test "after a workspace package arrives with its files" |
| P2-3 | No test caught dropping `module`, `types` or `optionalDependencies` | tests added; the mutations above fail them |
| P2-4 | All file texts were held in memory | `ignoreReferrers` reads each candidate once and keeps nothing; nothing is read when no entry moved |
| P2-5 | The `#` key filter skipped folders whose name starts with `#` | only the marker keys are skipped; test "a folder whose name starts with #" |

## Limitations

- Sync is per repo, so a manifest in one registered repo that governs importers in another is not followed. This was already the case before the change.
- The tsconfig, bundler-config and `__init__.py` signatures still re-parse everything below their folder.
- A lockfile or `node_modules` listing created after a long-running `mapx serve` started is not seen (M3-05-R3 process caches).
