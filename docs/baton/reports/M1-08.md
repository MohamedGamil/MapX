# M1-08 — Detect nested Laravel roots and honour frameworks.json

Date: 2026-10-30. Delivered together with M1-02 … M1-09 as one detector rework (`src/frameworks/detectors/laravel.ts`, the new `laravel-mounts.ts`, and the scanner's route pass). This report covers this task's part.

## Delivered

- `LaravelDetector.detect` also looks on disk for Laravel app roots (`artisan`, or `composer.json` requiring `laravel/framework`) up to 3 levels below the scanned root (`findLaravelRoots`). Neither file is in the scanned file list (artisan has no extension, and composer.json is excluded by default).
- The mount graph is built per app root, so `backend/routes/api.php` gets `/api`.
- `.mapx/frameworks.json` is now an override: frameworks listed there stay active even when detection misses them, and the file is rewritten as the union, not replaced.

Limitation: nested **git** repositories that aren't registered are still skipped by the scanner by design, with a warning; register them with `mapx workspaces add`.

## Acceptance

1. A workspace whose Laravel app sits in backend/ (artisan + composer.json with laravel/framework) detects Laravel, even though composer.json is in the default excludes.
2. A user-written frameworks.json listing ["laravel"] is not overwritten by detection.
3. The M1-01 scorer shows no regression in any other pattern.

All are met. They are covered by `tests/laravel-mounts.test.ts` (end-to-end scans through the real CLI) and by the M1-01 fixture, now with floors at 100% and exact parameter names.
