# M1-04 — Read provider route mounts generally

Date: 2026-10-30. Delivered together with M1-02 … M1-09 as one detector rework (`src/frameworks/detectors/laravel.ts`, the new `laravel-mounts.ts`, and the scanner's route pass). This report covers this task's part.

## Delivered

Mounts are now discovered in every `*ServiceProvider.php` by the same walker:
- `Route::prefix(..)->middleware(..)->namespace(..)->group(<path>)`;
- `$this->loadRoutesFrom(<path>)` inside an enclosing `Route::prefix()->group(function () { … })`.

Entry points come from `bootstrap/app.php` `withRouting(web:, api:, apiPrefix:)`, or from `RouteServiceProvider`, or from the `routes/web.php` and `routes/api.php` defaults. The hard-coded empty `packageRoutes` prefix is gone.

A latent bug was fixed too: `->group(<path>)` inside a route file used to push a group frame that never closed, leaking its prefix onto later routes.

## Acceptance

1. A module provider mounting Routes/api.php under Route::prefix('api/external/v1') yields URIs starting /api/external/v1.
2. packageRoutes never hard-codes an empty prefix when the provider declares one.
3. The M1-01 scorer shows no regression in any other pattern.

All are met. They are covered by `tests/laravel-mounts.test.ts` (end-to-end scans through the real CLI) and by the M1-01 fixture, now with floors at 100% and exact parameter names.
