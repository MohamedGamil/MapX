# M5-15 — Dashboard Architecture view and /api/arch endpoints

Planned in `iterations/M5-15.md`. Source: §3.6 of `docs/research/deptrac/03-mapx-gap-and-integration.md`. Built on the M4 dashboard (M4-16 to M4-24-R1) and on M5-05, M5-08, M5-13 and M5-16.

## Delivered

**API: `src/ui-arch.ts` (new), wired in `src/ui-server.ts` as `/api/arch/*`.** Nothing is decided here. Each answer starts from the report `mapx check` builds (`openArchitecture`, `loadBaseline`, `buildReport` over `ctx.evaluation()`, the M5-16 single-evaluation pattern of `/api/smells`). The other pieces reuse:
- the M5-13 reporters (`layerGraph`, `drawnEdges`, `layerDsm`);
- M5-16's `ruleSmells`, on the same report;
- M5-08's introspection (`layerMembers`, `layerDependencies`, `unassignedElements`, `unusedAllowances`);
- `check.ts`'s `shownReport`.

| Endpoint | Answer |
| --- | --- |
| `/api/arch/report` | `graph` (the `mapx arch graph --format json` object), `drawn` (its edges per status), `dsm`, `unusedAllowances` (the DSM's faint cells), `health` (violations, warn-level violations, warnings (check's "Warnings"), baseline debt, uncovered, unassigned, rule smells, config errors, `trend: null`), `counts`, `findings` (what `mapx check --report-uncovered --report-skipped` shows; allowed dependencies are only counted) and `smells` |
| `/api/arch/layers` | `layers` and `groups` (from the graph), `files` (each file's non-overlay layers, for the overlay), `unassigned` (files). With `layer=L`: `layerMembers(…, { why: true })` |
| `/api/arch/edges?from=A&to=B` | the pair's findings as the report counts them on the pair (`counts`: allowed, violations, warnings, skipped, uncovered), each with the concrete dependencies it stands for (`dependencies`, as `mapx arch deps` lists them). See Review, P1 |

- **States:** without a configuration, each endpoint answers 200 `{ configured: false, hint }`, and the hint names `mapx arch init`. An invalid configuration or baseline (a `ConfigError`, or rules that cannot be expanded) answers 200 `{ configured: true, valid: false, errors }`. An unknown layer answers 404, `edges` without `from` 400, an unknown `/api/arch/*` route 404, and any method but GET or HEAD 405 with `Allow`.
- **Read-only:** nothing in the path writes. The config is loaded as `/api/smells` loads it.
- **Staleness and caching** (see Review): every answer carries `stale` and, when stale, `staleReason`; one evaluation serves a batch of requests.
- **Repos (M4-21):** `scopeOf(config, 'all')`, so an unknown repo answers 404. The rules cover the whole workspace, as `mapx check` does. `repo=<name>` narrows the findings, members, `files`, `unassigned` and the dependencies to that repo; the graph, DSM and health stay the workspace's. The view says so.

**View: the Architecture tab has two sub-tabs, "Overview" (the existing content, unchanged and the default) and "Layer rules" (new).** In `src/ui/index.html`, `main.ts` and `styles.css`:
- **Health tiles:** `statTiles`, plus a line saying there is no trend: no snapshot records architecture counts.
- **Layer diagram:** a second Cytoscape instance (already bundled; preset positions, so no layout engine runs).
  - **Placement:** groups are compound nodes; there is a column per group, then one for the ungrouped layers, as M5-13's built-in SVG does.
  - **Edges:** one per status of a pair, labelled with its count: allowed grey, violation red, warn-level orange, skipped amber dashed. Edges in one column bend aside, farther the more layers they pass.
  - **Selection:** selecting an edge lists the pair's findings, counted as the DSM counts them, each with its dependencies (file:line); selecting a layer lists its members and the selector that matched each.
- **Layer DSM:** each cell is coloured by its worst status. An allowance no dependency uses is a faint 0, titled "may depend on …, and nothing does". Cells and row headers are `<button>`s that open the same drill-down, so every pair and layer can be reached from the keyboard; the canvas cannot.
- **Findings table:** filters for kind, rule, layer (matched as `mapx check --layer` matches) and verifiability, with a count. Each row's file badge opens the file in the graph's existing details panel (the `data-go-id` mechanism).
- **Graph overlay:** a "Declared layers" toggle in the graph toolbar (`aria-pressed`). It colours each file by its first declared layer (the layer's own `color`, else a palette by position) and shows a legend; files in no layer are grey (`--graph-node`). Without a configuration, the legend gives the `mapx arch init` hint.
- **Sub-tabs:** each tab list now switches only its own panes. Before, a click hid every `.subtab-pane` on the page, which would have hidden Routes' panes. Arrow keys move within one list.
- **Repo switch:** reloads the rules and the overlay once they have been opened (the `repoGeneration` guard).
- **Theme switch:** restyles the diagram.
- **Escaping:** every layer name, path, message, rule and selector goes through `escapeHtml`, and `scripts/ui/check-escaping.ts` passes. Colours use theme tokens: `check-tokens` passes, and the diagram uses `t()`.

**Tests**

## Limitations

- **No trend.** The health tiles have no trend: no snapshot records architecture counts, so `trend` is null and the view says so. Adding counts to snapshots would be a store change of its own.
- **Repo scope.** With a repo chosen, only the lists are narrowed; the diagram, DSM, tiles and rule smells are the workspace's, because the rules are evaluated over the workspace (as `mapx check`).
- **Cache and pagination.** One evaluation serves every request while the watched files are unchanged (at most 30 s). A change to a file the configuration reads that is not watched (for example a preset outside `.mapx/`) is seen after 30 s at most. There is no pagination: `/api/arch/report` sends every non-allowed finding, and the view draws the first 500.
- **The diagram is a canvas.** Keyboard users reach every pair and layer through the DSM's buttons, as the caption says.
- **Views.** The default configuration only; `.mapx/architecture/<view>.jsonc` is not selectable in the dashboard.
- **Caps.** The findings table and drill-down lists draw at most 500 rows (the count says so; the CLI lists them all).

Changelog: The dashboard's Architecture tab has a Layer rules view for `.mapx/architecture.jsonc` (health tiles, a layer diagram whose edges and layers drill down to file:line dependencies and selector-matched members, a layer DSM, filterable findings), the graph can colour files by declared layer, and `/api/arch/report`, `/api/arch/layers` and `/api/arch/edges` serve them read-only and flag a stale index; `mapx check --layer` now matches layer names that contain a comma (M5-15).
