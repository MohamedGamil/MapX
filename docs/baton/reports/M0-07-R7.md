# M0-07-R7 report: install.sh reads the installed version without GNU grep -P

## Delivered

`scripts/templates/install.sh` `check_existing` now reads the installed version with POSIX `sed` instead of `grep -oP`:
- it takes the first run of digits and dots;
- it says `unknown` when there is none;
- `|| true` keeps a failing `--version` from aborting under `set -euo pipefail`.

Three tests are added to `tests/installer-replace.test.ts`:
- a `grep` shim that rejects `-P` (standing in for BSD grep) with an existing `mapx 0.3.8`;
- a broken existing binary;
- a static check that no `grep -P` remains.

## Limitations

- Not run on a real Mac: the shim reproduces BSD grep's refusal of `-P` only. `sed -n 's/…/\1/p'` and `head -n 1` are POSIX and behave the same on BSD.

## Independent review

A fresh agent ran the new pipeline under `bash -euo pipefail` against 15 kinds of stub output, read all of `install.sh` for macOS-only breakage, and ran the tests. It found no P0, P1 or P2.
- **Version strings:** `v` prefixes, banners, multi-line output, CRLF, no newline, empty output, a failing exit and 200k lines are all parsed or defaulted correctly.
- **SIGPIPE:** `head -n 1` with `pipefail` can kill `sed` with status 141; `|| true` covers it, and the captured value is kept.
- **BSD sed:** the expression is plain POSIX BRE.
- **Rest of `install.sh`:** no other GNU-only construct on a path a macOS user hits. `readlink -f` has a fallback; `mktemp`, `cp -r`, `read -rp` and `[[ =~ ]]` work in bash 3.2.
- **Note:** a banner whose first digits are not the version (`node22 mapx 0.3.9`) gives `22`; the old code gave multi-line junk. The value is only used in the warning.
