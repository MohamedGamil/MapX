# M4-30 report: CLI-spawning arch tests stay within their timeouts under load

Finding of 2026-11-03: at load 25–59, `tests/arch-reporters.test.ts`, `tests/arch-baseline.test.ts` and `tests/legacy-metrics-edges.test.ts` hit vitest's 30 s timeout 1 to 3 times per full run, and passed when run alone.

## Measurement first

Each file run alone on a quiet machine (load 5), with a `--require` preload that logs every `mapx` process (`M4-30-spawnlog.cjs`):

| File | Wall | `mapx` spawns | init / scan |
| --- | --- | --- | --- |
| arch-reporters | 81.3 s | 119 (103 `check`) | 8 / 8 |
| arch-baseline | 47.6 s | 69 (57 `check`) | 5 / 5 |
| legacy-metrics-edges | 36.5 s | 51 (24 `edges`, 14 `metrics`) | 3 / 3 |

- **Per spawn:** ~630 ms, whatever the command (`check` 626 ms, `metrics` 605 ms, `scan` 776 ms).
- **Setup is not the cost.** Init and scan are 22 s of the 165 s; the other ~127 s are the assertions' own CLI calls.
- **The cost is tsx.** A CPU profile of `src/main.ts --version` under tsx spent 333 ms in tsx itself, resolving and loading the sources. tsx starts a one-line file in ~200 ms; the CLI takes ~600 ms.
- **The tests that time out** are the ones on the default 30 s, the slowest of which took 5–6 s quiet: "exit 3: a missing or invalid baseline…" 6.4 s, "a stale entry in a baseline outside the workspace…" 6.3 s, and "invalid --top / --format values…" 5.1 s. At load 25–59 that grows past 30 s. The heaviest tests (16.6 s) already had their own 120–300 s timeouts.

## Delivered

- **`tests/helpers/built-cli.ts` (new):** `buildCli()`. esbuild (a devDependency) transpiles src/ in ~120 ms:
  - unbundled ESM, as tsup does for the npm build;
  - into a temporary mirror of the repository, with src/ as `.js` beside its non-TypeScript files (the presets, the agents stub);
  - the other top-level entries (node_modules, wasm, queries, VERSION, package.json…) as symlinks, so the `import.meta.url` lookups resolve as in a checkout.

  The sources are read at build time, so each run tests the current src/ (the mutation check below goes through this path).
- **`tests/helpers/e2e.ts`:** `useBuiltCli()`. It is opt-in per file, like `useParseWorkers`: a `beforeAll` builds the mirror, and an `afterAll` deletes it. While a file uses it, `mapx`, `mapxEnv`, `mapxWithStderr`, `mapxResult` and `mapxResultEnv` start `node <mirror>/src/main.js` instead of `node --import tsx src/main.ts`. A start then takes ~170 ms instead of ~600 ms. Other files are unchanged.
- **The three files** call `useBuiltCli()`.
- **Shared scans:**
  - **arch-baseline:** one scan of APP serves both describes that need one, and each gets its own copy (`scannedApp()`). The "separate scan elsewhere" in the byte-stability test stays a separate scan.
  - **arch-reporters:** "an invalid report.codeclimate…" copies the scanned workspace and writes the invalid configuration, which only `check` reads, instead of a fresh init and scan.
  - **Kept separate:** the golden "other directory" scan, the three repository layouts and the three legacy fixtures. Each is a different input the assertions depend on.
- **Timeouts:** each file has a comment with the measured worst case. No timeout changed (see AC1).
- **Assertions:** none changed. Only setup and comments changed. Each file still has 28, 22 and 16 tests, all passing.

## Mutation check

Each mutation was applied to src/, run, and then reverted with `git checkout`:

- **Reporter:** in `src/arch/reporters/sarif.ts`, `uri: encodeUri(where.path)` became `encodeUri('/' + where.path)`. In `tests/arch-reporters.test.ts`, 7 tests failed and 21 passed. Six of the failures go through the real CLI: the golden sarif test, the schema test, "a stale entry in a baseline outside the workspace", and the three repository-path tests. So the transpiled copy runs the edited source.
- **Baseline rule:** in `src/arch/baseline.ts` `stale()`, `if (this.matched.has(e)) continue;` became `if (this.matched.has(e) || true) continue;`, so a stale entry is never reported. In `tests/arch-baseline.test.ts`, "deleting the offending import gives one stale-entry error, exit 3" failed, and 21 passed.

## Limitations

- **Two ways to run src/.** The three files now run the source transpiled by esbuild (what tsup ships) instead of tsx. A difference that only tsx shows, such as its resolution of the `.js` → `.ts` specifiers, is still covered by every other e2e file.
- **A crashed test process** leaves its mirror (`$TMPDIR/mapx-cli-*`, a few MB) behind, because `afterAll` does not run.
- **The full suite was not stressed.** The stress runs cover the three files together, not the whole suite under 16 loops. The original failure case, a full run at load 25–59, was not reproduced directly. The margin argument (a worst case of 5.1 s at load 26 against 30 s) is what covers it.
- **Other e2e files** still start the CLI under tsx. Many could opt in to `useBuiltCli()` for the same saving; that is out of scope here.
