# M2-10 report: Lua method calls with `:` and `self` give call edges

This task now also delivers M2-11 ("Lua locals and self fields are not module constants"). The integration owner folded it in after the independent review.

## Finding (before the change)

- **Method symbols:** `function Account:withdraw(n)` declares the function symbol `Account:withdraw`, scope null.
- **Method calls:** `self:log(n)` and `acct:withdraw(1)` were already extracted as calls, because `(call (variable))` matches a method call too. Their target names were `self:log` and `acct:withdraw`, which match no symbol, so neither call gave an edge.
- **Global functions:** `function run()` gave no symbol at all; `queries/lua/symbols.scm` captured only `function T.f` and `local function f`.
- **Locals and self fields:** `self.balance = …` and `local x = …` inside a function became constants. A call on such a line was credited to the constant (`run::acct -> Account.new`).

## Delivered

### Receiver tables (parser): `src/parsers/languages/lua.ts`

A `:` call names its receiver's table, and where that table lives, when the file tells it. Names resolve through the enclosing functions, innermost first, as Lua scopes them. Each function's bindings are collected once, with a tree cursor that does not enter nested functions.

- **`self`:**
  - it is `T` inside `function T:m()` or `function T.m(self)`;
  - an inner function with its own `self` parameter is not `T`'s method.
- **A parameter** is unknown.
- **A name the function assigns** is bound by every assignment there:
  - `{…}` makes it a table: `local`, or global when nothing declares it local;
  - `T.new()`, `T:new()` and `setmetatable(…, T)` make it an instance of `T`;
  - `require(…)` makes it a module;
  - a loop variable, any other value (a string, `io.open()`), or assignments that disagree make it unknown;
  - `local x` without a value only declares it.
- **A name declared nowhere in the file** is a global table.
- **Result:** the target is `T:m`, with the reference metadata `luaTable` set to `local`, `global` or `require`. A receiver that is not a plain name (`("x"):rep`, `io.stdout:write`, `self.items:insert`), or an unknown one, keeps its text without `luaTable`.

`src/parsers/generic-wasm-parser.ts` applies this to Lua call references and records `luaTable` in the reference metadata.

### Method resolution (scanner): `src/core/scanner.ts`, `resolveLuaMethodCall`

It matches `function T:m` or `function T.m(self)`, with no method-name fallback:
- `local`: in the calling file only;
- `global`: in the calling file, else in the nearest file of the same repo that does not declare `T` local at top level (column 0);
- `require`: the exact name (`T:m`, else `T.m`) through `resolveSymbolToFile`, as before M2-10;
- no `luaTable` (an unknown receiver): no edge.

### Symbols (M2-11): `queries/lua/symbols.scm`

- Constants come from top-level statements only: `local M = {}`, `M.VERSION = 1` (named `VERSION`, as before) and `Global = {}`.
- A local function value inside a function (`local g = function() … end`) stays a symbol, like `local function g()`.
- `function run()` is now a function symbol.

## `.luau`

The Lua grammar has no Luau syntax. `type X = …`, `export type …` and the annotations `x: number` and `): T` give ERROR nodes. Error recovery keeps the functions and their calls, so `self:dot()` in `Vec:len` links (tested). It also gives junk constants: `type Point = …` declares a constant `Point`, and `export type` declares a constant `export`.

A real fix needs a Luau grammar, a new bundled wasm, so this is not trivial. It stays a known limitation.

## Limitations

- **`require` is not resolved to a project file.** `resolveRequirePath` handles PHP-style paths only. A require-bound receiver keeps the parent's exact-name match, which may pick a homonym module (ws11).
- **Inheritance is not followed.** That covers metatable inheritance and a table made by `setmetatable({}, Base)`, whose methods are taken as its own.
- **Approximate block scopes.**
  - Block scopes inside a function (`do … end`, `if`) count as the function's scope.
  - An assignment to an upvalue inside a nested function counts as that function's binding.
  - The top-level-local check for global tables reads `local` at column 0.
- **`self.f()` (a dot call on `self`)** targets `T.f` and resolves like any dotted name, as the review confirmed.
- **Sync does not re-check calls resolved through a global table.** A sync that adds a global table's method in another file does not re-parse unchanged callers. This is the same as other name-based resolution.
