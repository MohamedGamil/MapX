### Changes

- **`src/frameworks/http/url-resolver.ts`**
  - `fileBindings(file, content)` lists every binding with the source range it is visible in:
    - `const` / `let` / `var` declarations, including destructuring and non-literal initialisers. Scope is the innermost `{…}` block, or the whole file.
    - parameters of functions, methods and arrows (block-bodied and brace-less) and of `catch`.
    
    It reads the masked source, so declarations in comments, strings and SFC templates no longer count. Before this change, `// const url = '/old'` was taken as a constant.
  - `constantsAt(bindings, offset, imported)`: the innermost binding of each name around the offset wins. A binding with no literal value, or same-scope bindings that disagree, make the name unknown, even when an import or an outer constant has it.
  - `constantsAnywhere` is for a client's `baseURL`, whose position is unknown. It takes top-level constants plus names that every binding in the file agrees on. Without it, a `baseURL` constant declared inside a function, which resolved before this change, would have regressed.
  - `fileConstants` now returns top-level constants only; exports are taken from it. `visibleConstants` takes an optional offset, and `importedConstants` is split out.
  - `parseDotenv` follows dotenv 16 / Node `parseEnv` (Vite), and `expandDotenv` follows dotenv-expand as bundled in Vite 8.
- **`src/frameworks/http/client-calls.ts`:** `HttpCallSite.offset`, the call's position in its file.
- **`src/core/scanner.ts`**
  - Looks up each call's constants at its offset.
  - Strips `offset` from the persisted records, so the D008 shape is unchanged. A test asserts no record has `offset`.
  - Expands env values across the env files consulted for the file. For example, `.env.development` can reference `.env`.
- **Fixture**
  - `vue2/src/services/scopedService.js` holds four calls (L33–L35, L38): two functions each with `const url`, a top-level `path`, and a function shadowing `path`.
  - `vue3/src/services/envClients.ts` holds two clients (L36, L37).
  - New `vue3/.env` keys: `VITE_SHOP_URL="/shop" # storefront` and `VITE_BILLING_URL=${VITE_API_URL}/billing`.
  - The labels were added without changing any existing label.
  - `tests/http-pairing-fixture.test.ts` now requires the three new patterns.
- **`tests/http-client-calls.test.ts`:** one exact-object assertion now includes `offset`.

## Limitations

- **Unset variables.** A reference to a variable that no env file defines leaves the value unknown, so the base is unresolved and pairing falls back to suffix matching. Vite substitutes `''`, or the value from the build's shell environment, which static analysis cannot see. `${X:-default}` uses the default; `${X:+alt}` with an unset `X` is unknown.
- **Vue CLI.** Vue CLI 4/5 uses dotenv 8–10 (no inline comments) and dotenv-expand 5. One Vite-compatible parser serves both, so a Vue CLI value with `# …` after it is read without the comment.
- **Process env.** Vite lets `process.env` override file values; that is not modelled.
- **Scope approximations.**
  - A scope is a `{…}` block, not a full parse.
  - `for (const x …)` heads are scoped to the enclosing block.
  - Parameter lists longer than 400 characters are not read.
  - Over-collection (for example default-value identifiers in destructuring) only hides constants; it never invents one.
  - `let` / `var` with a literal are treated as unknown, since they may be reassigned.
  - Further declarators after a non-literal one (`const a = f(), b = '/b'`) are still not bound (as in M2-04-R1).
- **Out of scope.** Calls with no literal segment pairing with arbitrary routes are M2-06-R1 (pairing.ts), not started.

Changelog: Frontend HTTP URLs now resolve function-local constants in their own scope, and `.env` values are read like Vite: quotes before a trailing `# comment`, and `${VAR}` expansion (M2-04-R2).
