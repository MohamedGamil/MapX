# M2-04-R1 — Fix URL resolution defects found in the M2 review

Date: 2026-10-30. Post-acceptance defects of M2-04 and M2-05, from the independent review.

## Fixed

| Severity | Defect | Fix |
| --- | --- | --- |
| P1 | `const BASE = '/api' + VERSION` was taken as `'/api'`, so `BASE + '/users'` confidently resolved to `/api/users` | `fileConstants` accepts a literal only when it is the whole initialiser (it must not be followed by an operator, member access, call or index, even on the next line) |
| P1 | `` fetch(`${import.meta.env.VITE_API}/users`) `` and `API + '/orders'` with a runtime `API` resolved to `{}/…` and never paired | The request path is evaluated with the file's env too. A path that still starts with an unknown part keeps the rest and sets `baseURLUnresolved`, so M2-06 pairs it as a suffix |
| P2 | `envCandidates` looped forever on absolute paths, ignored its `root`, and checked `.env.local` before `.env.development.local` | It terminates on `/`, stops at the repo root (the scanner passes the repo path), and follows Vite / Vue CLI precedence: `.env.development.local` > `.env.development` > `.env.local` > `.env`, then `.env.production` |

The task's third criterion originally stated the wrong precedence (`.env.local` before `.env.development`). It was corrected to match Vite before closing, and the old M2-05 test that encoded the wrong order was updated.
