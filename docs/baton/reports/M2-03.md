# M2-03 — HTTP client call-site extraction

Date: 2026-10-30.

## Delivered

- `src/frameworks/http/client-calls.ts` (pure text analysis):
  - `collectProviders`: exported `axios.create` instances, named and default-exported factories, and `const x = axios.create(); export default x / export { x }`, each with its raw `baseURL` expression.
  - `resolveImport`: relative specifiers and the `@/` / `~/` → `<app>/src/` alias.
  - `extractHttpCalls`: per file, finds receivers (axios import, local instances, imported instances, factory calls `F()`, aliases `const api = F()`, receivers configured in `settings.http.clients`) and records each `recv.get|post|put|patch|delete|head|options(...)` and `fetch(...)` / `window.fetch(...)`. Each record holds the call-start line, the method (from `{ method: '…' }` for fetch, otherwise GET) and the raw first argument (balanced across lines, strings and template literals).
  - A top-level ternary URL becomes one call site per branch (`urlBranches`).
- `src/frameworks/http/http-registry.ts`: `.mapx/http-calls.json`, replaced per repo file set (D008).
- `scanner.ts`: a new post-scan step `scanHttpCalls(repo)` after routes. `src/types.ts`: `settings.http.clients`.

### Scorer correction (M2-02 follow-up)

The M2-02 scorer matched a label to a record within ±2 lines. With the conditional call (two labels on one line), the second label borrowed the next line's record and pushed the misses onto other labels. Labels and records both carry the call-start line, so matching is now exact. There is a new scorer unit test for the two-labels-on-one-line case. No labels changed.

## Results on the M2-02 fixture

Call sites **32/32 (100%)**, up from 0. URL recall stays at 0% (M2-04 and M2-05) and pairing at 0% (M2-06). There is 1 unlabelled record: the `window.fetch` inside the `apiService` wrapper itself, a real but dynamic call.

## Limitations

- Receivers passed through function parameters, class fields (`this.http`) or re-exported through barrels more than one level deep are not followed.
- Calls through Vuex action names are not resolved.
