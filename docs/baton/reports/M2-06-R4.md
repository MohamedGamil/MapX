## Delivered

- **`src/frameworks/http/pairing.ts`:**
  - `routeDomainHosts(routes)` returns a map: each host that live routes name literally in `metadata.domain`, with the app roots (`metadata.appRoot`) of the routes that declare it. The host is lower-cased and loses any scheme or port written in the domain.
  - A domain with a `{param}` or `{dynamic}` part names no single host and is skipped.
  - So are the domains of routes no request reaches: unmounted, overridden and client-side page routes (the same `live()` test that `pairCall` uses).
  - `domainHost()` is the host normalisation `domainPattern()` already did, now shared.
  - `PairOptions.routeHosts` carries that map into `pairCall`. A host found only there (not in `hosts`) is a workspace host, but only some routes serve it:
    - any route of an app that declares it (domain-less, or on a matching domain);
    - a route of another app only when that route's domain matches the host and has no `{dynamic}` part.
  - A host that `hosts` also names (`.env*`, client base URL, `settings.http.hosts`) keeps the M2-06-R2 behaviour: any domain-less route serves it.
- **`src/core/scanner.ts`:** `workspaceHosts()` is unchanged in what it collects (`settings.http`, client base URLs, `.env*` URLs). `pairHttpCalls` passes `{ hosts: workspaceHosts(), routeHosts: routeDomainHosts(routes) }`.
- **Effect:**
  - `axios.get('https://partners.example.com/feed')` pairs with the route on `Route::domain('partners.example.com')` with no `.env` naming the host.
  - The declaring app's domain-less routes also serve that host, as Laravel serves them on any host that reaches the app.
  - Domain-less routes of other apps do not serve it. This is the fix for the review's P1, below.
  - Calls to other hosts stay third-party calls.
- **Sync:** no change was needed. Every sync that parses a file runs the post-scan analysis, which re-extracts the routes and re-pairs every call with hosts recomputed from them. A test proves that a domain added or removed by a sync gives the same records and `http` edges as `scan --force`.
- **Scorer fixture (`tests/fixtures/vue-http`):** L47, L48 and `VITE_OPS_URL` are unchanged. L48's client also needs `VITE_OPS_URL` to resolve its base URL. The new synthetic case:
  - `partners-api/` is a minimal second Laravel app: `artisan`, `FeedController`, and `routes/web.php` with `Route::domain('partners.example.com')` → `GET partners/v1/feed`;
  - `vue3/src/services/partners.ts` calls `https://partners.example.com/partners/v1/feed`;
  - label **L49** `route-domain-host` expects `FeedController@index`;
  - label **L50** `route-domain-foreign` (review P2) calls `https://partners.example.com/api/notices/latest` and expects unmatched. Only the backend app (`laravel-routes`) serves that path, with no domain; it does not declare the host;
  - no `.env` or setting names the host;
  - a README line explains the second app.
- **`tests/http-pairing-fixture.test.ts`:**
  - "pairs only with live routes of the Laravel fixture or the partners-api app" now scans `partners-api/` alone with the real CLI (`init`, `scan`, `routes --json`). Its live routes join the allowed set, so they are no longer hard-coded (review P2).
  - The pattern-coverage test lists `route-domain-host` and `route-domain-foreign`.
- **Docs:**

## Blast radius

`pairCall` and `routeDomainHosts` are reached only through `pairHttpCalls`. That method runs from `runPostScanAnalysis` and `refreshHttpIfInputsChanged`, which means every scan and every sync. The only outcomes that change are absolute-URL calls on a host that a live route names literally and nothing else names. Those calls used to be unmatched as third-party calls. They now pair only with routes of the declaring apps, or with other apps' routes on a matching domain that has evidence. Hosts named by `.env*`, client base URLs or `settings.http.hosts` pair exactly as before (mutation D, and the 48-label fixture totals).

## Limitations

- **`{param}` domains** (`{account}.example.com`) are not hosts on their own. A call to `https://acme.example.com/...` still needs a `.env` URL or `settings.http.hosts` entry before it pairs. The reason is that a pattern such as `{sub}.{domain}.com` would admit third-party hosts. Matching patterns with a literal suffix of at least two labels would be a possible follow-up.
- **`{dynamic}` domains** (`config(...)`, `env(...)`) never become hosts, as required.
- **App identity** is Laravel's `metadata.appRoot` (the app's artisan root). A declaring route without one adds the host but no app, so only routes on a matching domain serve it. Routes of other frameworks carry no app root and never serve a host that only route domains name. Only Laravel emits `domain`, so other frameworks cannot declare such a host anyway.
- **A sync that changes no indexed file** does not re-pair from routes. Today that cannot change a route domain, because route domains come from PHP files that sync parses.
- The task lists `CHANGELOG.md`, but the lane brief reserves it for the integration owner, so it is not touched. The sentence is below.
