# M4-05 — Build the dashboard only for release and serve, not on every install

Date: 2026-11-01. Base: `develop@ac26e66`. Owner: claude. Iteration: `docs/baton/iterations/M4-05.md`. Decision: D020.

## Delivered

- **`package.json` scripts.** The old `prepare` ran `build:npm`, so every `npm ci` bundled the dashboard (690 KB gzipped).

  | Script | Before | Now |
  | --- | --- | --- |
  | `prepare` | `npm run build:npm` | `tsup` |
  | `prepack` | none | `npm run build:ui` |
  | `build:ui` | none | `tsx scripts/build-ui.ts` |
  | `build:npm` | `tsup && tsx scripts/build-ui.ts` | `tsup && npm run build:ui` |
- **`tsup.config.ts`.** It now cleans with `['!ui/**']`. `npm pack` and `npm publish` run `prepack` (the dashboard) before `prepare` (tsup), and tsup's old `clean: true` deleted the bundle that had just been built. This was found by measurement in a scratch clone.
- **`scripts/build-ui.ts`** logs to stderr, because npm prints lifecycle output on stdout, inside `npm pack --json`.
- **Development build, `src/ui-server.ts`.**
  - **When it runs:** `uiBundleStale(root)` is true when `dist/ui/main.js` or `index.html` is missing, or when a file under `src/ui/`, `scripts/build-ui.ts` or `package-lock.json` is newer than the bundle. `startUiServer({ devBuild: true })` builds a stale bundle first, from source only, resolving tsx through `createRequire`.
  - **Who asks for it:** `mapx ui` and `mapx serve --ui` set `devBuild`. Tests that start the server from source do not, so they never build.
  - **Failures:** a failed build is logged and the server starts anyway, so `serve --ui` keeps its MCP server. `MAPX_NO_UI=1` skips the build.
  - **Missing bundle:** a server that starts without a bundle prints how to build it.
- **CI, the `test` job.**
  - It runs `npm run build:npm` before `scripts/check-package.ts`.
  - A new step packs with lifecycle scripts from a tree without `dist/ui`: `rm -rf dist/ui && npm pack --dry-run --json | node scripts/check-pack-ui.mjs`. It fails unless the tarball holds `dist/ui/main.js` and `index.html`.
- **Docs.** `docs/getting-started.md` covers `build:ui`, and says that git, `npm link` and `file:` installs need it (D020). The root `CHANGELOG.md` has an Unreleased entry.

## Independent review

One fresh agent reviewed the change in its own copy. It confirmed that installs no longer bundle the dashboard and that packing from a checkout works. It confirmed that tsup's array `clean` keeps `dist/ui`, that compiled binaries and installed `dist/*.js` never build, that `serve --ui` keeps MCP stdout clean during a build, and that no other CI step depended on `prepare` building the dashboard.

Its findings:
- **P1. Git-dependency installs lost the dashboard.** npm runs only `prepare` there, and the spec had wrongly claimed `prepack` covered them. Owner decision D020: document it. Done, and the server now prints the hint when the bundle is missing.
- **P2-1. Nothing guarded the tsup `clean` setting.** Fixed with the CI pack step and a test.
- **P2-2. A failed dev build crashed `mapx ui` and `serve --ui`,** and tsx was found by a hard-coded path. Fixed: the failure is caught, and tsx is resolved with `createRequire`.
- **P2-3. Staleness ignored the build script and the lockfile,** and missed a partial `dist/ui`. Fixed. `MAPX_NO_UI` also skips the build now.
- **P2-4. `npm link` and `file:` installs.** Covered by D020.
- **P2-5. Orphaned files in `dist/ui` survive tsup.** Kept: a release build rewrites `main.js`, `index.html` and `styles.css`, and CI starts fresh. Listed under limitations.
- **P2-6. Test gaps.** Fixed: `cli-coverage` asserts `devBuild: true` for `ui` and `serve --ui`, and the hook list is complete.

## Limitations

- **Git, link and file installs** have no dashboard until `npm run build:ui` (D020).
- **Leftover files in `dist/ui`.** An extra file left in a local `dist/ui` would be packed, because tsup no longer deletes it. Release CI starts from a fresh checkout.
- **Clock skew.** A bundle whose timestamp is in the future is never considered stale.
- **Pre-existing, not changed here.** `serve --ui` prints "Mapx UI Server running at …" to stdout (`src/ui-server.ts`), ahead of MCP traffic.
