# M5-25-R1 — Go package-qualified calls, and generic, slice and map literals of imported types

Planned in `iterations/M5-25-R1.md`. Source: `reports/M5-25.md` (Limitations). Revised after the independent review of 796c927 (see "Review" below).

## Delivered

- **`queries/go/references.scm`:** one pattern captures a composite literal whose type is a `generic_type`, `slice_type`, `array_type`, `implicit_length_array_type` or `map_type`, and the parser takes the element type from it.
- **`src/parsers/generic-wasm-parser.ts`:**
  - `goLiteralElement` unwraps the literal's type through generic arguments, slice and array elements, map values, pointers and parentheses, down to the type it names: `Box[int]`, `[]*domain.Item`, `[2]Item`, `map[K][]domain.Item`, `map[K]*domain.Box[int]`.
    - It skips predeclared types (`[]string{}`) and type parameters of the enclosing function, type or method receiver (`goTypeParameter`).
    - It skips type literals (`[]struct{…}`).
    - Map keys are not taken.
  - `goSelectorCall`:
    - A call `pkg.F()` whose qualifier is named by an import of the file carries that import path (`goPackage`), unless a local shadows the name (`goBoundLocally`).
    - `pkg.T{}.M()`, `(&pkg.T{}).M()` and `pkg.G[X]{}.M()` carry the literal's import path and type (`goType`).
    - A qualifier that names no import (a variable: `svc.Run()`) carries nothing and resolves by name as before.
  - `goBoundLocally` (Go's counterpart of `boundLocally`, whose JS/Python node types do not apply) finds a qualifier that is a local:
    - a parameter, receiver or named result of an enclosing function, method or function literal;
    - a variable declared before the use in an enclosing block or statement header (`x := …`, `var x`, `for _, x := range`, `for x := …;`, `if x := …;`, `switch x := v.(type)`).

    `user := user.New()` still calls the package, because the variable's scope starts after its declaration.
  - `goImportPath` takes the qualifier text, so types and calls share it.
- **`src/core/import-resolvers.ts`:**
  - `resolveGoImport` also follows a go.mod `replace M [v] => ./dir` with a local directory, and the modules of the nearest `go.work` (its `use` directories and local replaces). Nothing outside the workspace is read.
  - New: `goImportOutsideProject` tells whether an unresolved import is known to be outside the project. That is the case for a standard-library path (no dot in its first element; `C` included), and for any path once a go.mod or go.work is found at or above the importer's folder.
- **`src/core/scanner.ts`, `resolveGoQualifiedType`:**
  - `pkg.F()` links the package-level declaration `F` in the imported package's directory: a function, a function variable, or a type it converts to (`domain.ID(s)`).
  - `pkg.T{}.M()` links the method `M` of `T` in that directory. A method `T` does not declare is looked up on the types `T` embeds without a qualifier in the same package (`goEmbeddedTypes` reads the struct body from the declaring file), breadth first, up to 4 levels. If none declares it, nothing is linked.
  - When an import resolves to no package:
    - If it is known to be outside the project, nothing is linked.
    - Otherwise it may be the project's own package: no go.mod in the workspace, or the workspace root is below it. The declaration is then found by name, never in the calling package (a qualified name is another package's). The one folder that declares it wins; if several do, the one whose path ends the import path (`example.com/shop/domain` → `domain/`); otherwise nothing.
  - `goType` is dropped from stored edge metadata, as `goPackage` is.
- **`src/core/extractor-version.ts`:** `EXTRACTOR_VERSION` 3 → 4 (develop + 1).
- **`docs/adding-languages.md`:** the Go resolution paragraph covers calls, literals, go.work and local replaces, shadowing, and the no-go.mod fallback.
- **`tests/go-qualified-instantiation.test.ts`:** 9 new tests over five synthetic workspaces, each scanned with the real CLI:
  - `calls`: `domain`, `legacy` and the calling `app` declare the same names; a by-name match picked `app/local.go` before the fix.
  - `shadow`: locals named like imports.
  - `work` and `replaced`: two modules joined by a go.work, or by a go.mod `replace`, with a homonym package in the importing module.
  - `noMod`: no go.mod.

**Files outside `affectedFiles`:** `src/core/import-resolvers.ts` (P1-a), `src/core/extractor-version.ts` (lane rule) and `docs/adding-languages.md`. `CHANGELOG.md` is in `affectedFiles`, but the lane brief gives it to the integration owner; the line is at the end of this report.

## Limitations

- Calls on a variable of an imported type (`o := domain.Order{}; o.Run()`) and chained calls (`domain.NewOrder().Run()`) still resolve by name. That needs local type inference.
- Methods of a generic type (`func (p Pair[K, V]) Swap()`) are not extracted as symbols by `queries/go/symbols.scm` (a pre-existing gap, outside this task's files), so `gen.Pair[string, int]{}.Swap()` links nothing.
- A promoted method is found only through embedded types of the same package, up to 4 levels. A method promoted through a qualified embed (`struct{ log.Logger }`) links nothing.
- `goEmbeddedTypes` reads the struct from text. A struct type declared inside a function body, or a field line that is a single identifier inside a nested anonymous struct after brace stripping, could mislead it. In both cases the result is no edge or an embedded-type candidate that must still declare the method.
- A package-level `var` or `func` named like an import in the same file is not treated as a shadow (only function-local declarations are).
- `goImportOutsideProject` takes any first path element without a dot for the standard library, as the Go tool does. A GOPATH-style project without go.mod that imports `myproj/domain` gets no edge.
- Edge targets name the method alone (`Run`), as by-name edges do.
- `[]Interface{}` is recorded as an instantiation of the interface (decision above).

Changelog: Go package-qualified calls (`domain.NewOrder()`) and methods on a qualified literal (`domain.Order{}.Run()`) link the declaration in the imported package, across go.work and local `replace` modules, and generic, slice, array and map literals (`domain.Box[int]{}`, `[]domain.Item{{}}`, `map[string]domain.Item{}`) link their element type (M5-25-R1).
