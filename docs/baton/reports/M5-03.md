# M5-03 — Element view, core selectors and layer membership with selector trace

Sources: `docs/research/deptrac/02-abstract-feature-model.md` AR-01, AR-03, AR-04, AR-12. Planned in `iterations/M5-03.md`, written this session to close the plan gap.

## Delivered

**`src/arch/elements.ts`: `buildElementView(store, dir)`**
- **Elements:** one per indexed file and per symbol. Package clauses are not elements: they give the file its namespace.
- **Element fields:**
  - `qualifiedName`;
  - from the file: repo, language, role and confidence, clusters (from `cluster_membership`), and framework parts derived from stored edges (`route` and `http` targets → `route-handler`, `relation` sources → `model`, and so on, as in AR-04's table);
  - `topLevel` (no enclosing scope).
- **`workspacePackage(path)`:** the nearest manifest's name, read lazily (`package.json`, `composer.json`, `pyproject.toml`, `go.mod`, `Cargo.toml`).
- **`qualifiedName(language, input)`:** one rule per built-in language (`QUALIFIED_NAME_RULES`):

  | Rule | Languages |
  | --- | --- |
  | Namespace plus scope plus name, with each language's separator | PHP (file `namespace`, `::` before a member), Java/Kotlin/Scala/C#/Dart/C++ (the file's `namespace` symbol) |
  | Module path | Go (`go.mod` module plus directory), Python (module path, without `src/` and `__init__`), Rust (`crate::`, with `lib`/`main`/`mod` naming their directory) |
  | Module nesting | Ruby (`::`), Elixir (`.`) |
  | `path#Scope.Name` | everything else, including JS/TS/Vue/Svelte, and a namespace language whose file declares none |

  Kotlin's `package` is not captured by its query yet, so Kotlin uses the path form; this is documented.

**`src/arch/selectors/index.ts`:**
- **Selectors:** `matchSelector` evaluates `path` (glob, or `/regex/`), `name` (+`kind`; symbols only; case-insensitive unless `/…/flags`), `repo`, `language` (with aliases such as `ts` and `c#`), `role` (+`confidence`), `cluster`, `workspacePackage`, `framework`, `layer`, `all`, `any` and `not`.
- **Results:** each returns the path of the deciding sub-selector, for example `any[1].layer`.
- **Not yet evaluated:** `extends`, `docTag`, `package` and the like are listed in `UNSUPPORTED_SELECTORS` with the task that adds them, and never match.

**`src/arch/membership.ts`:**
- **`computeMembership(view, config)`:** follows AR-01's granularity. A symbol is in the layers its selectors match, with file-level selectors judged on its file. A file is in the layers its selectors match, plus its top-level symbols' layers. Membership never flows between symbols. `layer` selectors are evaluated with a cycle guard.
- **Results:** `of`, `primaryOf` (without overlays), `privateIn` (AR-07 `private` selectors), `members`, `explain` (layer, selector path, and `via`, the top-level symbol that put a file in a layer), `emptyLayers` (non-overlay), `multiLayer` (AR-12), `unsupported`.
- **`getMembership(store, dir, config, key)`:** caches the element view per index and scan stamp (last scan time plus file, symbol and edge counts), and the membership per (scan, hash of the layers); at most 8 entries.

**Docs:** `docs/architecture-rules.md`, a new reference for the configuration document, qualified names, selectors and membership, marked in progress.

`tests/arch-selectors.test.ts` scans the M5-01 PHP, TypeScript, Python and two-repo apps. Against the criteria:

1. **Selectors** (each with negative cases):
   - `path` (glob and regex, judged on a symbol's file);
   - `name` (case-insensitive by default, case-sensitive with `/…/`, `kind` filtering, never a file);
   - `all`, `any`, `not`;
   - `language` (aliases);
   - `repo` (exact, glob; workspace repos);
   - `role` (case, confidence threshold);
   - `cluster` (exact, glob);
   - `workspacePackage` (composer, package.json and pyproject names; workspace repos);
   - `framework` (`route-handler` on the Laravel controller and `http-client` on the frontend, none in the single-language apps);
   - `layer` (an `any` of two layers, with its trace).
2. **Qualified names:** a table test over every registry language (29, at least 22). Each has a rule; the expected file and `Shop.Order` names for each style and the path fallback; edge cases (`__init__`, `mod.rs`, `lib.rs`, a repo path, Go without `go.mod`, a namespace language without a namespace). The scanned apps carry those names (`App\Domain\Order::run`, `app.domain.order.Order.run`, `src/domain/Order.ts#Order.run`).
3. **Caching:**
   - the same scan and configuration return the same object, and the computation counter rises by one;
   - another configuration is computed again;
   - a `sync` after an edit is computed again, on a new view that holds the new class.
4. **The fixture apps:**
   - each of the 18 classes per language, and its file, is in exactly the layers the M5-01 design implies;
   - the private ones are private to Application;
   - `Reporting` is the only empty layer, and `OrderId` the only multi-layer class;
   - no unsupported selectors are used.

   Traces: `App\Domain\Order` is in Domain by `selectors[0].name`; its file is in Domain *via* that class; `OrderId` is in Domain by `name` and in Shared by `selectors[1].path`.

## Limitations

- **Go:** M5-01 found that cross-package references are mostly unresolved. Membership of Go files and symbols is right, but evaluating Go edges (M5-04) will miss what the index does not hold.
- **Framework parts are file-level:** a file holding a route handler is a `route-handler`, even if it also holds other classes.
- **`path` is matched on the workspace-relative path,** which is what the index stores, not the repo-relative path. In a multi-repo workspace, patterns start with the repo's folder (`backend/app/**`).
