# M5-13 — Layer graph reporters: DOT, SVG, Mermaid and layer DSM

Planned in `iterations/M5-13.md`. Sources: AR-16 in `docs/research/deptrac/02-abstract-feature-model.md`, and §6 (formatters) of `01-deptrac-capabilities.md`. Rebased onto develop `2555276` (M5-20).

## Delivered

**`mapx arch graph --format dot|svg|mermaid|dsm|json`** (`src/cli.ts`). It has `-o/--output`, `--baseline`, `--no-graphviz`, `--view`, `--sync` and `-d`. It exits 0 (it is not a gate), 3 for a configuration or usage error (an unknown format, a missing baseline file), and 4 for the index. It is built on M5-08's `archQuestion`, which now takes a list of formats and `--output`. The existing subcommands are unchanged: they keep `text|json`.

**Library: `layerGraph(report, config)`** (`src/arch/reporters/graph.ts`, exported from `src/arch/reporters/index.ts` with `layerDsm` and `renderLayerGraph`).
- **Input.** It builds the graph from the `ArchReport` that `mapx check` builds, baseline included. Every count and status is therefore `check`'s own decision, through `decideEdge`. M5-15 and M5-14 can call it directly.
- **Output.** `--format json` prints it: `{ version, view, layers[{name, overlay, elements, files, group, color, hidden, uncovered}], groups[{name, layers, pointTo}], edges[{from, to, allowed, violations, warnings, skipped, hidden}], totals }`.
- **Drawing rules:**
  - each status of a pair is its own edge, labelled with its count: allowed grey, violations red, warn-level violations amber, skipped (baselined) dashed;
  - groups are subgraphs: the first `report.groups` entry that lists a layer, else the layer's own `group`;
  - `report.hidden` layers are not drawn, but the totals include them, by number only;
  - with `report.pointToGroups` (a new boolean config key), an edge into the layer named like its group points at the group (DOT `lhead`, Mermaid edge to the subgraph). An edge from inside the group still reaches the layer;
  - a layer's `color` is used when it is `#rrggbb`, `#rrggbbaa` or a colour name;
  - overlay layers have a dashed border.
- **Order.** Nodes and edges follow the configuration's layer order, so output does not depend on the order of the report.

**Renderers** (`src/arch/reporters/{dot,mermaid,dsm,svg}.ts`)
- **DOT:** every ID and label goes through `dotQuote`, which escapes `"` and `\`, writes line breaks as `\n` and drops other control characters.
- **Mermaid:** IDs are `layer_<name>` and `group_<name>`, with everything outside `[A-Za-z0-9]` turned into `_`. A clash takes `_2`, `_3` and so on, and the prefix keeps keywords such as `end` out. Labels use entity codes (`#quot;`, `#lt;`, `#gt;`, `#amp;`, `#35;`, `#96;`). Styles go through `linkStyle <index>`, and skipped edges are drawn `-.->`.
- **DSM:** a matrix of the visible layers, printed through `formatDsmText`, which is now shared with `mapx arch --dsm`. A cell shows its count, marked `!` (violations), `~` (warn-level only) or `s` (skipped only).
- **SVG:** it uses Graphviz (`graphvizSvg`, `dot -Tsvg`) when it is installed and `--no-graphviz` is not given, and the built-in renderer otherwise.
  - **No new dependency.** The built-in renderer is deterministic. Each group is a column, and ungrouped layers share one column.
  - **Edges.** Each edge end has its own port. Curves within a column run on the right going down and on the left going up. A curve that passes a column in between runs below the columns.
  - **Escaping.** All text goes through `escapeXml`.

**Reuse.** The existing exporters' output is unchanged.
- **`src/exporters/dot-exporter.ts`:** exports `dotQuote`. `DotExporter` does not use it, so its output stays byte-identical.
- **`src/exporters/svg-exporter.ts`:** `graphvizSvg` (the existing `dot -Tsvg` call, extracted; `SvgExporter` now calls it) and `escapeXml`.
- **`src/core/metrics.ts`:** `formatDsmText`, extracted from the `mapx arch --dsm` printer.
  - **Golden.** The cluster DSM output is unchanged. M5-08's legacy golden `arch-dsm.txt` passes.
  - **`alignRows`.** The option pads layer rows correctly. The cluster DSM keeps its historic padding.

**Report: `layerEdges[].warnings`** (`src/arch/report.ts`, `schemas/arch-report.schema.json`).
- **What it counts.** Of a pair's violations, the ones reported at `warn`.
- **Per pair.** The count is kept per pair, so a source in two layers can be advisory on one pair and an error on the other.
- **Compatibility.** The field is additive. `mapx check --format json` now includes it.

**Config: `report.pointToGroups`.** Added to `src/arch/schema.ts` (`REPORT_KEYS`, types), validated in `src/arch/config.ts` (boolean, otherwise exit 3) and in `schemas/architecture.schema.json`.

## Limitations and notes

- **What counts are.** Edge counts are `layerEdges` units: dependencies per element pair and edge type (findings), not stored edges. A finding against two target layers counts once on each pair, and once in the totals, which are `mapx check`'s counts.
- **The report's JSON gains `layers[].uncovered`** (review of M5-13), next to `layerEdges[].warnings`. Both are additive, and the schema has both.
- **Uncovered dependencies.** A target in no layer has no node, so these are not drawn. They are counted per source layer (`layers[].uncovered`) and in the totals.
- **`layerGraph` takes the full report.** The totals' `warnings` count the report's findings, so a report filtered by `--layer` or `--rule` would undercount them. The CLI builds the full report.
- **The built-in SVG layout** is a simple column layout, meant as a readable fallback, not a Graphviz replacement. Within a column, curves are arcs; across non-adjacent columns, they pass below.
- **Graphviz SVG bytes** depend on the installed Graphviz version. `--no-graphviz` is byte-stable everywhere. This is documented.
- **No MCP tool draws the graph.** M5-14 has landed without one; a follow-up can expose `layerGraph` and `renderLayerGraph`. `docs/mcp-integration.md` is unchanged.
- **The report's JSON gains `layerEdges[].warnings`.** The change is additive and the schema is updated, but any consumer that validates `mapx check` JSON with an older copy of the schema would reject it.
- **Colours.** A `color` that is neither hex nor a name is ignored rather than reported as an error. Validation is unchanged.
- **A finding outside this task.** The full suite's only failure was `tests/worker-pool.test.ts` under load; it passes alone.
- **Commit hygiene.** The `node_modules` symlink was kept out of the commit, as in M5-08.
