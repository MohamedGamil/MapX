# M2-20 report: a CommonJS `require` of a local module gives import edges

Found by M5-17-R1: a CommonJS `require` of a local module gave no file-to-file edge. Planned in `iterations/M2-20.md`. Dispatched at develop `76842a9`, rebased onto develop `ef6a79e` (M5-23-R1, M5-21-R1, M5-07-R2).

## Reproduced first

`tests/commonjs-require.test.ts` was written and run against the unchanged code: 5 of its 6 tests failed. The sixth, "keeps a package or builtin require external", passed, as it should before the change. A probe of the same app (`scratchpad/M2-20-probe.mjs`) showed the old graph:
- no import edge for any `require`;
- `new Logger()` and `make()` linked the requiring file's own `const Logger = require(…)` declarator (`src/app.js#Logger`, `#make`), which the parser makes a function symbol (M0-17-R5);
- `math.twice()` linked `decoy.js#twice` by name;
- `require('./util').parseQty()` gave no reference at all.

## Delivered

- **Import edges** (`queries/javascript/references.scm`, `queries/typescript/references.scm`, `references-tsx.scm`). A `require('<string>')` call is an `import` reference (`#eq? "require"`), resolved by `resolveImportPath` as an ES specifier. A top-level require is the file's (`source_symbol` null, `fileLevel`), and one inside a function is that function's. A computed `require(name)` or `require('./' + x)` gives none, and neither does a call of another function with a string argument.
- **`require('./m').f()`.** A query pattern, and `metadata.required` from the parser (`generic-wasm-parser.ts`). The scanner links f as `findExport` finds it in the required module. A module outside the project gives no edge, and an external-reference candidate (`call express#json`).
- **Bindings** (`importBindings`):
  - `const f = require('./m').f` binds the export f.
  - A whole-module binding called bare (`new Logger()`, `make()`) resolves to what `module.exports = X` exports. If there is no named export, there is no edge: name lookup could only find a homonym, or the declarator itself.
  - The declarator symbol on the require's own line no longer shadows the binding.
  - An ES default import of a CommonJS module takes its `module.exports = X`.
- **Exports:**
  - `module.exports = function makeThing() {}` and `module.exports = class Widget {}` declare `makeThing` / `Widget` (JS symbols query). `commonJsMain` reads both forms.
  - In `module.exports = { a, b: c, m() {} }`, `b` resolves to `c`. A key whose value is no declaration (`twice: function () {}`) links nothing (`'absent'`) instead of a homonym. `exports.k = local` is the same rename.
  - `exports.f = …` and `module.exports.f = …` were already symbols (M2-09).
- **Barrels:**
  - `module.exports = require('./a')` is followed for a named export and for the whole export.
  - A required name passed on (`const { f } = require('./a'); module.exports = { f }`, `const L = require('./l'); module.exports = L`) is followed to the required module.
  - Both forms count as barrels in `isBarrel`, so sync walks through them (D032).
- **Externals (M2-08-R3):** a package or builtin require is unchanged. It gets no edge, `join`/`Router`/`readFileSync`/`express()` link no `decoy.js` symbol, and the external rows are kept.
- `EXTRACTOR_VERSION` goes to 20, with a comment line (18 and 19 are Lane E's M5-23-R1 and M5-21-R1, at the integration owner's request).

## Limitations

- **Not followed (name lookup, as before):** `module.exports = { ...require('./a') }` spreads, `Object.assign(module.exports, …)`, `exports[k] = …` and compiled `__exportStar`.
- **Anonymous whole exports:** `module.exports = function () {}` declares no symbol, so `const f = require('./f'); f()` gives no edge.
- **`require('./m').f` as a value:** a bare call through `const f = require('./m').f` is linked. Other uses of a required member (passed as a callback, say) are references M2-20 does not add.
- **Reading is textual:** bindings and export shapes are read from the comment-free text (`jsText`), as `importBindings` was.
- **CommonJS files are scripts for M2-08-R3's global rule:** an ES module's bare global name may still reach a CJS module's top-level function by name, as before.
- **Repeated requires:** each `require` of the same module is its own import edge, as each ES `import` statement is.
- **Out of scope:** `require.resolve`, `require.context`, AMD `define`. TS `import x = require()` is unchanged.
- `src/core/import-resolvers.ts` (Lane E) is untouched. JS specifiers resolve through scanner.ts's `resolveImportPath`.

Changelog: A CommonJS `require('./x')` of a project module is now an import edge, and the functions it binds (`const { f } = require(…)`, `const X = require(…)`, `require('./x').f()`) link the module's `module.exports` / `exports.f` declarations, through `module.exports = require(…)` barrels; a package require stays external (M2-20).
