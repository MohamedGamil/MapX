# M4-10 — Workers load only the grammars of the files they parse, once per thread

Decision D025.

## Before

Measured on a generated 3,000-file project with `scripts/bench/workers.ts`. The mix was TS 1,200, PHP 1,050, Vue 300, and Python, Go and Ruby 150 each; synthetic code only.

Every one of the 8 workers made 31 grammar loads, 248 in all:
- **Pre-warm:** 23 grammars and their compiled queries, loaded in `initLanguages()`. They sat in a map that only the fallback capture walk reads.
- **Language parsers:** each grammar a worker used was loaded again through `wasm-parser.ts`.
- **TypeScript three times per thread:** once by the TypeScript parser, once by the JavaScript parser, which shares the grammar file, and once by `vue-ast.ts`.

## Delivered

- **One `Language` per grammar file per thread** (`src/parsers/wasm-parser.ts`):
  - `loadLanguage` memoises a promise per resolved grammar path, so concurrent first uses share one load. A failed load is forgotten and retried.
  - Parsers sharing a grammar share its `Language`, its compiled queries and its pooled parser.
- **No pre-warm** (`src/parsers/parse-worker.ts`):
  - The worker's own `Parser.init`, grammar copies and pre-warm are removed.
  - The generic capture walk, used when a language parser throws, uses `wasm-parser`'s caches. It keeps the old "Failed to load language" error when neither query compiles.
- **Statistics:**
  - Workers answer `{type:'stats'}` with the files they parsed and `grammarLoadCounts()`.
  - The scanner collects them after a parallel run, keeps them as `lastWorkerStats` (reset per scan or sync), and with `MAPX_WORKER_STATS=1` prints `[mapx] worker-stats {…}`. The line holds `started`, `workers[].files`, `workers[].grammars[]`, `handbacks` and `peakRssMb`. `peakRssMb` is the process's peak, workers included.
- **Bench:** `scripts/bench/workers.ts` compares a parallel scan with a `--no-parallel` scan: wall time, peak RSS, worker statistics, and an index digest. It exits 1 if the indexes differ or the scan falls back to one thread. `--bin` runs a compiled binary.
- **Docs:** a "Parallel parsing" section in `docs/configuration.md`, and the CHANGELOG.

The index has 3,001 files, 10,500 symbols and 13,950 edges. Parallel parsing is still no faster than one thread at this size: worker startup (a V8 isolate plus the parser modules, and tsx from source) and dispatching one file per message cost what the parse saves. M4-11 (pool), M4-13 (sizing) and M4-14 (batching) address that.

`tests/worker-pool.test.ts`:
- **Memoisation:** concurrent `loadLanguage` calls of one grammar return one `Language`, and the load count is 1.
- **Real scan of an 18-file PHP, TS and Vue project:**
  - one stats line, and each file is parsed by exactly one worker;
  - grammars are `php` and `typescript` only, each loaded once per worker;
  - no hand-backs, and the index equals `--no-parallel`.
- **Fallback walk:** with `MAPX_TEST_WORKER_FALLBACK=src/m2.ts`, the walk still extracts `f2` (a function).

**Mutation checks:**
- Memoisation off fails 2 tests (two `Language` objects; `loads` 2).
- A pre-warm of every grammar through `loadLanguage` fails the scan test, because `javascript` appears.
- With the walk's symbol captures emptied, the fallback test fails.

## Independent review (fresh agent)

The reviewer found no P0 or P1. Confirmed:
- **Bench, run independently:** before 5,266 ms and 1,314 MB, after 3,299 ms and 802 MB, with identical indexes.
- **The bun binary:** each grammar is loaded once per worker, and workers find their assets without `assetRoot`.
- **No hang** from removing the pre-warm:
  - 24 grammars loaded concurrently in one thread;
  - 16 concurrent workers;
  - 8 workers with `UV_THREADPOOL_SIZE=1`.
- **Shared parsers and queries are safe.** No `setLanguage` is called on a pooled parser, and trees are not held across awaits. The query cache is keyed by language and source.

**P2s, all fixed:**
- **Fallback walk untested:** now covered by the `MAPX_TEST_WORKER_FALLBACK` test above. The "no query" error behaviour is restored.
- **Stale `lastWorkerStats`** after a failed parallel run: reset per scan or sync.
- **Criterion wording** said "workers line": updated to `worker-stats`.

**Not changed:** `peakRssMb` is the process's peak since it started. In `mapx serve` that spans calls; it is documented as the process's peak.
