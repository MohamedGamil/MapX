# M0-02-R10 — An interrupted sync loses the symbols of the files it started re-indexing

Date: 2026-11-01. Base: `develop@b70ac18`. Owner: claude. Iteration: `docs/baton/iterations/M0-02-R10.md`. Found by the M4-04 review.

## Delivered

- **`Store.setFileHashes(path, contentHash, gitBlobHash)`.** An `UPDATE` of the two hashes and `last_scanned`, leaving `metadata` and `namespace` as they are.
- **Both sync paths (git and hash).** Re-indexed files are upserted with null hashes and `last_scanned` at the epoch (`UNSCANNED`) before parsing. Their hashes and scan time are set right after each file's parse result is written, in the resolve transaction. A sync interrupted before that leaves the files reading as new or unscanned. The hash sync's discovery treats them as new, and `mapx status` lists them through its mtime check.
- **Git sync.**
  - It re-parses indexed files of the repo whose `content_hash` is null. That covers a referrer the interrupted sync cleared, which git does not list because it is unchanged against HEAD.
  - An indexed file that can no longer be read leaves the index, as the walk drops it.
  - An unreadable file is no analysis input (M4-04).
- **Test mocks** gain `setFileHashes`.

## Independent review

One fresh agent reviewed the change in its own copy, and found no P0 or P1. It checked:
- every other reader of the hash columns: discovery, `skipUnchanged`, `ignoredChanges`, the full scan's incomplete-file logic, staleness;
- that the hash values are the same as before;
- an aborted sync followed by a non-force scan, which equals `--force`;
- double aborts.

Its P2s, both fixed:
1. A file left by an interrupted sync that becomes unreadable was retried, with post-scan, on every sync. Fixed by dropping it from the index and ignoring unreadable files as analysis inputs. Tested, and mutation-checked.
2. `mapx status` hid an interrupted sync's files, because `last_scanned` was set to now before parsing. Fixed with the epoch stamp. Tested, and mutation-checked.

A first attempt at fix 2 counted every file with a null hash as stale. That broke the CLI and MCP mocks, and would have listed every file of a database that predates the `content_hash` column, so it was reverted.
