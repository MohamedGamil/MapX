# M0-02-R1 — Glob filter defects

Date: 2026-10-31. P1 from the M0-41 legacy audit (I02, I04).

## Fixed

- **Re-included files lost their inbound edges for good:** files excluded and then re-included were re-indexed, but their referrers were unchanged and never re-parsed, so the edges into them never came back without `--force`. The scanner now records the effective filters per repo (`meta scan_filters:<repo>`) and re-parses every file once when they change.
- **`--exclude "dir/*"` pruned subdirectories:** `shouldExcludeDir` pruned a directory when the directory path itself matched the pattern, so `app/Http/*` dropped `app/Http/Controllers/*`, while `export` with the same glob kept them. A directory is now pruned only when a deep path beneath it is excluded (`app/Http/**`, `**/tests/**`), when the pattern names it exactly without globs, or when it is a bare segment name (`node_modules`).
- **Filtered exports leaked clusters:** the new `exporters/cluster-filter.ts` keeps only clusters that contain an exported file, or are ancestors of one. It is used by the LLM `## Structure` section and the TOON `clusters` table.
- **Laravel default excludes only at init:**
  - `LARAVEL_DEFAULT_EXCLUDES` (`config.ts`) now applies at scan time to `framework: laravel` repos, scoped to the repo path, even when the config lists no globs (F10);
  - a suggestion declined at init (`--no-suggestions`) is remembered as `settings.laravelDefaultExcludes: false` and respected.

## Post-acceptance defect (review 2026-10-31)

P1 regression: the new directory pruning matched a synthetic file name, so `--exclude "**/_*"` indexed no file below the root and `**/generated` / `packages/*/generated` stopped excluding. Fixed in `shouldExcludeDir` (directory-path match except for a trailing bare `/*`). Regression test "prunes directories named by a pattern, and only those" in `tests/legacy-globs.test.ts`; it fails on the pre-fix scanner. See `reviews/REVIEW-2026-10-31-fb75474ba377.md`.
