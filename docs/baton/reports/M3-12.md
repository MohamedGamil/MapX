# M3-12 — HTTP pass and vue-router detector use the shared alias resolver

Date: 2026-10-31. Base: `develop@71cb757` (rebased onto M3-11 and M3-10 during the lane). Owner: lane-vue-setup. Iteration: `docs/baton/iterations/M3-12.md`.

## Delivered

- **HTTP pass** (`src/frameworks/http/client-calls.ts`, `url-resolver.ts`, `scanner.scanHttpCalls`):
  - `resolveImport(fromFile, spec, files, readText?)` handles a relative specifier itself; every other specifier goes through `jsAliasTargets` from M3-09.
  - The scanner passes `readText = readWorkspaceText` to `collectProviders`, `extractHttpCalls` (`ctx.readText`) and `importedConstants`. `visibleConstants` takes it as an optional trailing parameter.
  - The HTTP pass's own guess (`@/` and `~/` → the nearest `src` folder) is removed.
  - `collectProviders` now builds its path set once, instead of once per re-export. The alias cache is keyed on that set.
- **vue-router:** `withSrcAlias` is deleted from `src/parsers/languages/vue-navigation.ts`. The scanner gives the vue-router detector (`ScanContext.resolveImport`) and the navigation route table plain `resolveImportPath`, which already resolves aliases through the shared resolver.
- **Shared fallback** (`src/core/js-aliases.ts`): with no matching alias, `@/x` tries, in order:
  1. `src/x` under the nearest package.json folder;
  2. **new:** `src/x` under the `src` folder that encloses the importing file;
  3. `src/x` at the workspace root.

  Step 2 is the old guess from the HTTP pass and `withSrcAlias`, moved into the shared resolver. It applies only when no config declares the alias. It keeps the HTTP unit inputs (`app/src/...` with no package.json) and the scorer fixtures resolving.
- The detector file `src/frameworks/detectors/vue-router.ts` (listed in `affectedFiles`) needed no change. It calls `ctx.resolveImport`, which the scanner supplies.

## Limitations

- `~/x` without a config no longer resolves to `src/x` in the HTTP pass. Nuxt's `~` is the project root, so that guess was not reliable.
- The HTTP pass reads configs from disk through the scanner's per-phase text cache. A direct unit caller without `readText` gets only the fallback.
