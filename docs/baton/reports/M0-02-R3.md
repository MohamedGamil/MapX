# M0-02-R3: git renames, nested-repo diffs and symlinked nested repos in incremental sync

Date: 2026-10-31. Sources: the limitations in `docs/baton/reports/M0-02-R2.md` (renames, subdirectory repos) and `docs/baton/reports/M0-10-R2.md` (the scanner's nested-repo skip compares with `resolve`). Built on develop `d904c68`.

## Before (reproduced on the unchanged code)

- **Renames.** `getChangedFiles` kept only the last field of `R<score>\told\tnew`, so `sync` indexed the new path and left the old one, with its symbols and edges, until a full scan.
- **Stale file map on removal (found while fixing renames).** `scanIncremental` fills `workspaceFileMap` from the store before the sync removes anything. Referrers re-parsed in the same sync could resolve to a removed path and recreate edges into a file that no longer exists. A manual repro after `git mv` showed `User.php -> UserService.php import` after `sync`, while `scan --force` had no edge.
- **Nested repo.** In a MapX workspace at `api/` inside a larger checkout, `git diff --name-status` printed `api/app/Models/User.php` and listed `web/` changes too. The scanner resolved those paths against `api/`, so the changed file was never re-indexed. On the old code, the new test's `Profile` symbol query returned `[]`.
- **Symlinked repo.** Repos registered as `web-link` and `ui-link` (symlinks to `packages/web` and `libs/ui`) were not recognised at their real folders. The main repo indexed `packages/web/index.ts` a second time, and the scan printed "Found unregistered nested git repository" for `libs/ui`.
- **legacy-globs slowness.** A CPU profile of one `scan --force` on a two-file PHP workspace showed 259 ms in `new Query(...)` inside `parseWithQueries`. The main-thread parser compiled both tree-sitter queries again **for every file**, and every scan or sync of 10 files or fewer parses on the main thread. Measured in-process: compiling both queries costs 189 ms for PHP and 142 ms for TypeScript. Parsing a small file with compiled queries costs 0.6 ms and 0.3 ms. The rest of the per-call cost is process start-up (tsx plus the CLI import graph, about 300 ms unloaded), multiplied by about 75 CLI spawns, some of them redundant.

## Delivered

- **`src/core/git-tracker.ts`**
  - `GitFileStatus.oldPath`, plus a shared `parseNameStatus` that keeps the old path of an `R` line. `C` (copy) stays `modified`, and its source is untouched.
  - Both `git diff` calls use `--relative`. Paths are now repo-relative and limited to the repo folder, as `git ls-files --others` and `git ls-tree` already were.
- **`src/core/scanner.ts`**
  - Git sync removes each rename's `oldPath`, and re-parses the files that had edges into it, so by-name references (here a PHP parameter type) find the class at its new path, as `scan --force` does.
  - `removeFiles` drops removed paths from `workspaceFileMap`.
  - `discoverFiles` compares registered roots by `canonicalPath` (M0-10-R2's helper). Walked directories get their canonical path from their parent's plus their name, with no extra syscalls, because the walk never follows symlinks.
- **`src/parsers/wasm-parser.ts`:** compiled queries are cached per (language, query text), as the parse workers already do. The "no query" handling is kept.
- **`tests/legacy-globs.test.ts`**
  - Three new e2e tests.
  - Fewer CLI spawns, with no assertion dropped:
    - the `glob filters` block scans once in `beforeAll`, and its tests no longer rescan to establish the unfiltered state (−3 spawns);
    - the normalisation test compares each variant with the unfiltered paths minus `app/Services/`, not with an extra canonical scan (−1);
    - the Laravel block shares one default-settings scan (−3).
- **`tests/git-tracker.test.ts`:** a unit test for rename parsing and the `--relative` commands.
- **`tests/parser-pool.test.ts`:** a test that each query is compiled once per language and reused, checked through the `this` of `Query.prototype.captures`.
- **Docs:**
  - `docs/cli-reference.md`: the rename behaviour, and nested-repo scoping, under `sync`.
  - `docs/mcp-integration.md`: the rename behaviour in the `mapx_sync` entry.

## Limitations and findings

- **Plain `scan` and non-git `sync` see a rename as a delete plus an add.** The referrers of the old path are recorded, but they are only re-parsed if that same path comes back. A by-name reference to the moved class (as in the rename test) therefore stays missing until `--force`. Found by reading the code, not tested, and out of this task's scope (git sync).
- **A `./`-only normalisation mutant survives,** in the original test as well. Dropping `.replace(/^(\.\/)+/, '')` from `normalizePattern` passes, probably because the matcher already accepts a leading `./`. This was pre-existing and is left as it was.
- **Out of scope: blob hashes for non-root repos.** `getGitBlobHashes` returns repo-relative paths, but the full scan looks them up by workspace-relative path. A repo with `path` other than `.` therefore stores `git_blob_hash = null`. No reader depends on it today.
- **Remaining legacy-globs cost is process start-up.** About 70 CLI spawns at roughly 300 ms each unloaded (tsx alone is about 350 ms of a cold start). Making `cli.ts` load its imports lazily would cut it for every e2e test, but that is a wider change than this task.
- **Paths git quotes** (`core.quotePath`, unusual characters) are still parsed as printed.

Changelog: `sync` now drops the old path of a git rename and re-links its referrers, picks up changes in a repo nested inside a larger git checkout, treats a symlink to a registered repo as that repo, and small scans and syncs no longer recompile tree-sitter queries for every file (M0-02-R3).
