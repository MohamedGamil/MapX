# M5-02 — Architecture config: JSONC schema, loader, extends/parameters, validation

Sources: `docs/research/deptrac/02-abstract-feature-model.md` AR-11, AR-14, AR-05 and AR-04 (the selector keys).

## Delivered

**`src/arch/schema.ts`:**
- **Types:** the `ArchitectureDocument` as written, and the loaded `ArchitectureConfig` (merged, parameters applied, defaults filled).
- **Vocabularies:** edge types (MapX's `ReferenceType`), symbol kinds, framework parts, the 23 primary selector keys of AR-04 and their modifiers (`kind` for `name`, `value` for `docTag`, `dev`/`direct` for `package`, `confidence` for `role`), and every section's keys.
- **Defaults:** the AR-06 structural scope, `policy.inferred: warn`, uncovered externals reported and builtins not, `@internal`/`@mapx-internal`.

**`src/arch/config.ts`:**
- **`loadArchitectureConfig(dir, { view?, presets? })`:** reads `.mapx/architecture.jsonc`, or `.mapx/architecture/<view>.jsonc` for a view. It returns null when there is none, and otherwise either a config or a `ConfigError` listing every problem as `{ file, pointer, message }`. M5-05 maps that error to exit code 3.
- **JSONC:** the tsconfig/`workspaces` dialect. `parseJsonc` (`src/core/js-aliases.ts`) was split into `stripJsonc` plus a parse. The stripper blanks comments in place and drops trailing commas outside strings, so a syntax error reports its line and column. The old trailing-comma regex also rewrote `, ]` inside strings; that is fixed, and the 231 existing alias and tsconfig tests pass unchanged.
- **`extends`:** relative files and `mapx:preset/<id>` (the `PRESETS` registry ships empty; M5-17 fills it).
  - **Order:** depth-first, each document once, extended documents before the extending one.
  - **Merging:** later documents override layers by name, in the position the layer first had. Rule lists merge per source layer without duplicates. Scope, policy, visibility, baseline and report are overridden key by key.
  - **Errors:** circular `extends` names the whole cycle (`a → b → a`); a missing file and an unknown preset are reported at their `extends` entry; a preset can only extend presets.
- **`%parameters%`:** merged first, then substituted in `name`, `path` and `package` values, including inside `all`/`any`/`not` and `private`. An unresolved parameter is an error at that value's pointer.
- **Validation:** all problems at once, sorted into document order by each pointer's position in its document.
  - **Structural:** unknown keys at any level; wrong types; unknown edge types and symbol kinds.
  - **Selectors:** exactly one primary key ("combine them with `all`" otherwise); a modifier without its primary.
  - **Allowance strings:** `"L"`, `"+L"`, `"!L"`, `"*"`; `+*`/`!*` are refused.
  - **Allowance objects:** `allow` or `to`, never both; `types`; `severity`.
  - **Semantic, on the merged config:**
    - duplicate layer names within a document;
    - unknown layers in rules (source or target), `layer` selectors and report groups (with "did you mean" for case or one-edit typos);
    - an overlay layer as a rule source, or as a `+` target;
    - `+` in `*` defaults;
    - `+` cycles and `layer`-selector cycles, each named once (`Service → Repo → Service`);
    - regexes that don't compile (after substitution).

**`schemas/architecture.schema.json`** (JSON Schema draft-07):
- generated once from the vocabularies, with descriptions for editor completion;
- listed in `package.json` `files`, and `check-package` fails if it exists but is not packed;
- a test keeps its keys equal to the loader's at every level, and validates the AR-11 example with `ajv`. `ajv` was already installed through the MCP SDK and is now an explicit dev dependency (MIT).

**Found on the way:** `make package-linux` (the v0.3.8 build) leaves binaries, tarballs and installers in `dist/release/`, and `package.json` `files: ["dist/"]` packed them. `npm pack` would have made a 185 MB tarball instead of 4.7 MB. `files` now excludes `dist/release/`, `check-package` fails on any packed release artifact, and `tests/legacy-distribution.test.ts` covers both. Nothing was published, so nothing shipped this way.

The criteria against `tests/arch-config.test.ts`:
1. **All errors at once, in document order:** `documents/four-errors.jsonc` gives exactly four entries, in order:
   - `/layers/0/selectors/0/paht` (unknown key);
   - `/layers/1/selectors/0/layer` (unknown layer, "did you mean Http");
   - `/rules/Http/0` (unknown target);
   - `/rules/Service/0` (`"+" allowances form a cycle: Service → Repo → Service`).

   A 15-problem document gives its 15 pointers in order. A three-layer `+` cycle is named once. `*`, `!` and plain allowances never form a cycle.
2. **`extends`:**
   - `chain/` (`a ← b ← architecture`): files in that order; `Shared` overridden by `b` in `a`'s position; `App` rules merged (`+Domain`, `Shared`); `policy.inferred` from the last document; defaults filled.
   - `cycle/`: exactly one issue, naming both files.
   - A view extends the main document. A missing file and an unknown preset are reported, and a registered preset (text or document) resolves.
3. **Parameters:** they apply across the chain (the last value wins), in `name` and `package`. Unresolved ones in `all` (`name`, `package`) are reported at their pointers.
4. **Schema:** shipped and listed by `check-package`. It validates the AR-11 example and rejects a typo'd selector key and an allowance with both `allow` and `to`. The AR-11 example also loads with its base document and a stub `laravel` preset, as written.

## Limitations

- **The JSON Schema is looser than the loader:** it cannot say "exactly one primary key per selector" or check layer names across sections. The loader is the authority, and the schema serves editors.
- **No command yet:** M5-05 adds `mapx check` and `arch validate-config`.
