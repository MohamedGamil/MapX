## Before (reproduced on the baseline)

The four new tests failed on the baseline code: registered files exit 1, 4 failed and 52 passed.

- **Parameters.** `->middleware(EnsureRole::class.':editor')` gave the raw text `EnsureRole::class.':editor`. `[EnsureRole::class . ':admin', 'auth']` gave `App\Http\Middleware\EnsureRole` plus a bogus `:admin` entry. `Route::middleware(EnsureRole::class.":owner")` kept the raw text, and `['middleware' => EnsureRole::class.':staff']` dropped `:staff`.
- **Short-name guessing.** The scanner split on `:` and resolved the bare part by short class name. `Unimported::class.':admin'` (no `use`; PHP reads `\Unimported`) linked `app/Http/Middleware/Unimported.php`, and `'Thing'` linked `app/Other/Thing.php` (`App\Other\Thing`). - **Variadic and group use.** `->middleware('auth', 'verified')` kept only `auth`. `use App\Http\Middleware\{Grouped as U2, Audit};` was not read, so `U2::class` and `Audit::class` became `\U2` and `\Audit`, with no edge.
- **Two apps** (`admin/`, `backend/`, each with `app/Http/Kernel.php`; reproduced first, as the lane asked). The workspace context merged both Kernels:
  - `admin/app/Http/Kernel.php` emitted backend's `auth` alias, with an edge to `admin/app/Http/Middleware/Authenticate.php`.
  - admin's route expanded `auth` with backend's alias.
  - The group member alias in `'portal' => ['team', …]` was never expanded, so `portal` had no edge to EnsureTeam.

## Delivered

- **`src/frameworks/detectors/laravel.ts`**
  - `listItem` reads one list entry as Laravel does: a quoted name, a class constant, or a class constant with concatenated parameters (`EnsureRole::class.':editor'` → `EnsureRole::class:editor`). A name that can't be read statically (`$mw`) is no entry.
  - `listArg` reads every argument (`Route::middleware(...$middleware)`, `RouteRegistrar::middleware`) unless the first is an array. `withoutMiddleware` reads only the first argument. The `'middleware' =>` and `'excluded_middleware' =>` group attributes use the same reader. Arrays are split into entries (`phpArrayEntries`), so `EnsureRole::class.':admin'` is no longer two matches.
  - `middlewareClassNames` keeps whatever follows the named class: `App\Http\Middleware\EnsureRole:editor`, which is what `EnsureRole::class.':editor'` evaluates to.
  - `parseUseImports` reads group use: `use A\{B, C as D};`.
  - **One Kernel per app.** `wctx.kernels` maps each Laravel root to its own Kernel (empty without one).
    - `parseKernel` names class constants through the Kernel's `use` table and namespace, and ignores commented-out entries.
    - `resolveMiddleware` is Laravel's `MiddlewareNameResolver`: groups and nested groups expand, an alias becomes its class, and parameters follow the class (`role:manager` → `App\Http\Middleware\EnsureRole:manager`).
    - `resolveRouteMiddlewares` uses the Kernel of the route file's app and records that app as `metadata.appRoot`.
  - **Kernel hooks.**
    - Parsed from the Kernel file being extracted and nothing else, each with `metadata.appRoot`.
    - Group members expand through that Kernel's aliases.
    - Only a namespaced class name is resolved.
    - Each name and class pair is declared once.
    - The match is now `(^|/)app/Http/Kernel.php`, not any path ending `app/http/kernel.php`.
- **`src/core/scanner.ts`**: only the route-middleware edge code changed.
  - Hook targets are keyed by app root (`metadata.appRoot`) and name, so a route uses only its own app's Kernel entries. Hooks without an app root (NestJS) keep their own key space.
  - For a PHP route file, only a name with a namespace separator falls back to class resolution, which is namespace-strict (M0-04-R2). Non-PHP route middleware keeps the previous capitalised-name fallback.
- **`docs/cli-reference.md`** (`routes --json`): one sentence on how Laravel middleware names are resolved.

## Limitations

- **Route output.** A Kernel alias with parameters now shows as its class with the parameters (`throttle:60,1` → `Illuminate\Routing\Middleware\ThrottleRequests:60,1` when the app's Kernel declares `throttle`), as Laravel resolves it. Without a Kernel alias, the name stays as written.
- **New metadata.** Routes and Kernel hook edges carry `metadata.appRoot`.
- **Bare names.** A bare middleware name that is neither an alias nor a group gives no edge, even when a global class of that name exists. Linking it would need a global-only lookup for bare names, and the scanner cannot tell those apart from function names (`auth`).
- **Out of scope, unchanged:**
  - controller-constructor `$this->middleware(...)` and `#[Middleware]` attributes (string-only);
  - Laravel 11 `bootstrap/app.php` `->withMiddleware()` aliases;
  - `listArg` evaluates with a literal scope, so `->middleware($var)` gives no entry (it used to give `$var`).
