## Delivered

- **`src/core/scanner.ts`:**
  - `nestedRepoTest`: git sync drops listed paths, and rename sources, that lie under another registered repo nested in this one. Paths are compared by canonical path, as the walk compares them, so a repo registered through a symlink is covered.
  - The rename guard: a rename's old path that still exists on disk stays indexed.
  - `settleMovedNames` settles per name.
  - `resolveSymbolToFile`: with several declaring files, the pick is the one nearest the caller (`closest` on the sorted unique files), not index order.
  - `ignoredChanges` plus `discoverFiles(…, from)`: gitignored entries that pass the walk's rules are compared by content with the index.
    - It skips an ignored folder that is a dot or default-ignored folder, a pruned folder or an unregistered nested git repo, as well as symlinks.
- **`src/core/git-tracker.ts`:** `getIgnoredEntries`.
- **`src/core/file-rules.ts`:** `buildPathFilter` and `isScannableDir`.
- **`src/cli.ts`, `src/mcp.ts`:** the export path filter. This was listed under `src/exporters/graph-exporter.ts` in `affectedFiles`, but the filter lives in the two entry points, so the exporter needed no change.
- **Docs:**
  - `docs/configuration.md`: new "Gitignored files" section;
  - `docs/cli-reference.md`: sync bullets, scan bullets on name resolution, and export `--exclude`;
  - `docs/mcp-integration.md`: the `update` tool and the export `exclude`.

## Limitations

- **Gitignored files.**
  - Git sync now reads every gitignored file the walk would reach on each sync, to compare content. The default ignores (`node_modules`, `vendor`, `dist`, `build`, `coverage` and others), dot folders and excludes keep this set small in practice. A repo with a large gitignored folder that is not excluded pays for reading it, as `scan` already does.
  - `.gitignore` files are still not a scan rule. To leave generated files out, use `excludePatterns`, which `docs/configuration.md` now says.
- **Name resolution.** The nearest-file pick changes which file an ambiguous bare name resolves to when several files declare it. It is now deterministic and prefers the caller's own folder tree, but it is still a name-based guess. Receiver-typed resolution is M0-17-R4.

## Findings outside this task

None new.

Changelog: `mapx sync` in a git repository gives the index `mapx scan --force` gives in more cases:
- a registered folder repo inside the primary checkout keeps its own files;
- a class re-added elsewhere re-links its referrers even after an unrelated file declared one of its method names;
- `git mv` that leaves a copy keeps both files;
- gitignored files are indexed as `scan` indexes them.

A name declared in several files resolves to the one nearest the caller, so scan and sync agree. `export --exclude '**/Http'` (CLI and MCP) leaves out the folder as at scan time (M0-02-R7).

Final review round (reviewer I):
- **P1, fixed.** A no-op sync was quadratic in gitignored files: `existsExactly` read the folder listing for every uncommitted indexed file, and `picomatch.isMatch` recompiled every glob on every call.
  - **Fix:** folder listings are cached per sync, globs are compiled once (`globMatch` in `file-rules.ts`), and the exact-case check first asks `existsSync`.
  - **Measurement:** with the reviewer's `perf3.sh` (100 tracked files plus 8000 gitignored files in one folder; load average about 10–25), a no-op sync now takes 2.4 s on the first run and 16.5 s on the second. Base takes 22.1 s and 23.1 s. The reviewer measured the patched tree before this fix at 47–54 s.
- **P2, fixed.** A same-size gitignored file with an older mtime (`cp -p`) was skipped. The skip now uses the later of mtime and ctime. Test: "re-indexes a gitignored file replaced by same-size content with an older mtime (cp -p)". The mtime-only mutation fails it.
- **Not changed, documented:** adding a nearer declaration of an already-resolved name, and removing a symbol from a changed file, leave old edges. Both happen on base as well.

Last review round (reviewer L): performance was confirmed. On an 18,000-file repo, a no-op sync takes 2.5–3.5 s (base 5.8–6.3 s) and a no-op scan 12 s (base 18 s); gitignored same-size edits with an old mtime and new ignored files are picked up. Registered as M0-02-R8 (P2): `mapx status` does not report an edit to a gitignored indexed file, and re-resolution after manifest changes.
