# M1-05-R3 — Laravel routes: withoutMiddleware, implicit binding fields on plain routes, repeated chained attributes

Date: 2026-10-31. Follow-up of M1-05-R2 (its Limitations section), promoted to P2 by D014. Built on develop `5d605ef`, which includes M0-04-R3.

## Ground truth

The expected route lists come from Laravel's own router, as in M1-05-R2. `laravel/framework` v12.70.2 was installed fresh with `composer require laravel/framework:^12` into this session's scratchpad (`m105r3/oracle-vendor`). Nothing was loaded from any other project or its `vendor/`. Two scratch oracle scripts register synthetic route files only:

- `m105r3/oracle/oracle.php` mounts one route file the way the default `routes/api.php` is mounted (`middleware('api')->prefix('api')->namespace('App\Http\Controllers')`). The route file is byte-for-byte the test's `routes/api.php`.
- `m105r3/oracle/oracle-mount.php` runs the test's RouteServiceProvider chain on the test's `routes/portal.php`, which mounts `routes/portal-admin.php`.

For every route both print method, URI, name, action, domain and the non-null `Route::bindingFields()`. The middleware they print is what `Router::gatherRouteMiddleware` keeps: `Router::resolveMiddleware(Router::uniqueMiddleware($route->middleware()), $route->excludedMiddleware())`, with no aliases or groups registered. They also print the raw `middleware()` and `excludedMiddleware()` lists. The e2e `EXPECTED` lists were copied from that output. The new fixture block was run through `oracle.php` too, and gives `api/articles/{article}` with `{"article":"slug"}` and `api/authors/{author}/books/{book?}` with `{"author":"uuid","book":"isbn"}`. The framework source in the same vendor directory was read to choose the rules (`Route`, `RouteUri`, `RouteRegistrar`, `RouteGroup`, `Router::resolveMiddleware`, `ResourceRegistrar`, `PendingResourceRegistration`, `PendingSingletonResourceRegistration`).

What the oracle showed:

- **Excluded middleware.** `withoutMiddleware` before the verb is a RouteRegistrar attribute that accumulates across repeated calls. After the verb, `Route::withoutMiddleware()` appends. A group's excluded middleware applies to every route inside it, and to middleware those routes add themselves. Nested groups and the `excluded_middleware` key of a group or action array merge like `middleware`. Removal matches the exact name: `withoutMiddleware('throttle')` keeps `throttle:60,1`. `withoutMiddleware('api')` removes the mount's own `api` middleware. Class constants resolve through the file's `use` statements.
- **Resources.** `->withoutMiddleware()` accumulates into `excluded_middleware`. `->withoutMiddlewareFor($methods, $mw)` replaces those actions' entries. Each action's entry is merged after `excluded_middleware` and de-duplicated. A `Route::withoutMiddleware()` attribute before the resource verb becomes the `excluded_middleware` option. The same rules apply to singletons.
- **Repeated attributes before the verb or group** (`RouteRegistrar::attribute`): `middleware`, `prefix`, `namespace` and `name` are replaced, so the last call wins. `Route::middleware('a')->middleware('b')->get(...)` gives `b`. An action array's `middleware` key replaces a chained middleware attribute (`array_merge($attributes, $action)`). `->middleware()` after the verb appends.
- **Implicit binding fields.** `RouteUri::parse` strips `{post:slug}` to `{post}` and `{post:slug?}` to `{post?}`, and records `{post: slug}`. It runs on the full URI, so a group prefix's fields count too. Resources keep the fields parsed from their prefix unless `scoped()` replaces them through `setResourceBindingFields`. A `->prefix()` called after the verb re-parses the already stripped URI, so `Route::get('tags/{tag:name}', ...)->prefix('v2')` loses its binding field.

## Delivered (`src/frameworks/detectors/laravel.ts`)

- **Excluded middleware.** Group frames, mount frames (`RouteMount.excluded`), RouteServiceProvider configs, chain attributes, action arrays and resource options (`excluded`, `excludedFor`) now carry excluded middleware beside middleware. Class constants are named through the route file's use table with M0-04-R3's `middlewareClassNames`, in the same places as `middleware`. Routes record the list in `metadata.excludedMiddlewares`. `resolveRouteMiddlewares` resolves both lists through the Kernel aliases and groups and drops exact matches. Middleware edges follow the reported list, so a route no longer links a middleware class it excludes.
- **Resources.** `->withoutMiddleware()`, `->withoutMiddlewareFor()`, and the `excluded_middleware` / `excluded_middleware_for` options follow PendingResourceRegistration and ResourceRegistrar. This covers singletons too.
- **Repeated chained attributes.** `processRouteChain` splits middleware into an attribute before the verb (last one wins) and calls after the verb (appended). The action's `middleware` / `excluded_middleware` keys replace the attributes. Group `prefix` and `namespace` attributes are last-wins too. The same rules apply to `->group(<path>)` mounts (`chainAttributes`) and to RouteServiceProvider chains (`parseRouteServiceProvider`, where `prefix` used to stack and `withoutMiddleware` was ignored).
- **Implicit binding fields.** A new `parseRouteUri` mirrors `RouteUri::parse`. Plain routes report the stripped URI with `metadata.bindingFields`, and model the `->prefix()`-after-the-verb reset. Resources strip a group prefix's fields and keep them unless `scoped()` is used.

## Limitations

- **Subclass exclusion is not modelled.** `Router::resolveMiddleware` also removes a middleware whose class extends an excluded class. MapX removes exact names only, after Kernel alias and group resolution.
- **Domain binding fields are not modelled.** `->domain('{account:slug}.example.com')` is reported as written. Laravel strips the field when `domain()` is called on the route, but not when the domain comes from an action key or a group.
- **`update` stays two routes**, PUT and PATCH, by design.
- **New metadata field.** Routes with excluded middleware now carry `metadata.excludedMiddlewares` (as written, class constants named), next to the already-filtered `middlewares`. Plain routes may now carry `metadata.bindingFields`, as resources already did. The CLI and MCP surface is unchanged.
- **Behaviour changes for users.**
  - A repeated `Route::middleware('a')->middleware('b')` or `Route::prefix('a')->prefix('b')` before a route, group or mount now keeps only the last attribute. A RouteServiceProvider prefix chain is included.
  - An action array's `'middleware'` key now replaces a chained middleware attribute.
  - `{post:slug}` URIs are now reported as `{post}`.
  - Each of these is what Laravel registers. No existing test or fixture label used these forms.
- **Oracle files are not in the repository.** The oracle scripts and the scratch vendor directory stay in the session scratchpad. Their output is frozen into the tests' expected lists.

Changelog: Laravel routes now honour `withoutMiddleware`/`withoutMiddlewareFor` (routes, groups, resources, the `excluded_middleware` keys), report `{post:slug}` as `{post}` with its binding field, and keep only the last of a repeated chained `middleware`/`prefix`/`namespace` attribute, as Laravel's router does (M1-05-R3).
