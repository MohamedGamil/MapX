# M0-07-R5 — The documented `curl … | sh` install works

Date: 2026-11-04. Base: `develop@81ee4d0`. Owner: claude. Found by the M0-07-R4 review.

## Cause

The self-extracting installer found its payload with `awk … "$0"` and `tail -n +N "$0"`. Piped (`curl … | sh`), `$0` is the shell, so it failed with `awk: cannot open sh` (also `dash`, `bash`), including on the real 79 MB `dist/release/mapx-linux-x64-installer.sh`. README.md documented exactly that command.

## Decision

(a), make it work piped, not (b) change the docs to download-then-run. `curl | sh` is the conventional and already documented path; the risk (shells read their script ahead) is contained by a pad and by tests under dash, bash and busybox sh. Trade-off and table in `docs/baton/iterations/M0-07-R5.md`.

## Delivered

- **`scripts/make-installer.sh`** (sh template): the logic is one function, `_mapx_installer`, called on the last line before `exit 1`, so the shell has parsed it all before it runs and never parses the payload. `$0` is the installer file when it contains `# mapx-installer-header` (else the script is on stdin). On stdin, the payload is the text after the `__PAYLOAD__` line (awk) piped into `base64 -d | tar xz`, no spool file. The marker follows a 160 KiB pad of comment lines after the `exit`, because a shell has read some of its script ahead (dash 8 KiB; bash on a pipe none); the bytes it took are gone, and the pad absorbs them. fd 3 is the prompt input and `install.sh`'s stdin: the caller's stdin for a file run (as M0-07-R4), `/dev/tty` when piped, `/dev/null` with no terminal; then no menu is shown, the install is `--local`, and a line says how to choose. The menu `read`s take the default on end of input. `MAPX_UNINSTALL_HINT` carries `curl -fsSL …/mapx-<platform>-installer.sh | sh -s -- --uninstall` when piped (`MAPX_INSTALLER` for a file run, M0-07-R3). The M0-07-R4 traps, child with `<&3`, `wait`, exit status and folder removal are unchanged.
- **`scripts/templates/install.sh`**: a `read` at end of input (the three prompts: overwrite, shell-config, remove data) is a no, not a silent `set -e` exit; declining to overwrite says to pass `--force`; the uninstall hint prefers `MAPX_UNINSTALL_HINT`.
- **`README.md`, `docs/getting-started.md`**: the two documented commands stay; added what the prompts do when piped, the `sh -s --` form, the four published platforms, an install with `--prefix "$HOME/bin" --force`, an uninstall (`--uninstall --force`), and the command in getting-started. There is no PowerShell installer command in the docs (grep `irm|iex|\.ps1` of README.md and docs/*.md), so nothing to verify there; the ps1 template extracts from an embedded here-string, not from `$PSCommandPath`.
- **Tests**: `tests/installer-replace.test.ts` (21 to 53 tests), `tests/docs-surface.test.ts` (21 to 26 tests), `tests/helpers/installer-docs.ts` (reads the commands out of the docs).
- **`CHANGELOG.md`** `### Fixed` entry (M0-07-R5); `docs/baton/iterations/M0-07-R5.md`; `TASKS.json` planning fields sharpened (description, sources, outputs, affectedFiles, 4 acceptance criteria); `plan:validate` passes.

Not a file and `[ -t 0 ]` now stops at once with "No installer payload to read: run the downloaded file …, or pipe it", before any prompt or unpacking. ## Limitations

- A download cut inside the header comments, or right after the function's closing brace and before the `_mapx_installer "$@"` line (a window under 100 bytes), runs nothing and exits 0: the standard `curl | sh` trade-off. Every other cut fails with "Failed to extract archive" (reviewer tried 20 truncation points).
- The payload is unpacked before the menu, so a user who answers `q` or `u` has waited for the download and unpack (about 1 s for the 79 MB installer); the sender is not cut off any more (P2-4).

- Shells tried: dash, bash, busybox sh. Not run on macOS (`/bin/sh` is bash 3.2 in POSIX mode, which reads a pipe byte by byte) or zsh/ksh; the 160 KiB pad assumes no shell reads more than that ahead (a pipe holds 64 KiB).
- The pad adds 160 KiB to each installer.
- With no terminal and no `--force`, an existing `mapx` makes the piped installer fail (exit 1) rather than overwrite; a CI upgrade needs `sh -s -- --force`. The README says so.
- Piped with a terminal, the prompts read `/dev/tty`; piped from a background job with a terminal, a read could stop on SIGTTIN (not tested; same as any `/dev/tty` reader).
- The signal tests for a piped run cover extraction; the piped run during `install.sh` uses the same code as M0-07-R4's file-run tests.
- Not run against `make package-linux` output in CI; the manual probe used the 0.3.9 archive.
- The PowerShell installer was only read (no docs command exists), not run.

## Found, not fixed

- Typing an empty custom prefix at menu option 3 gives `--prefix` with no value and `install.sh` stops with an unbound `$2` (pre-existing, untouched).
- `install.sh` uses `grep -oP`, which macOS grep lacks (pre-existing, only on the existing-install path).
