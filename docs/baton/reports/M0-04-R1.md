# M0-04-R1 — PHP name resolution: use imports, namespaces, facades, qualified names

Date: 2026-10-31. P1 from the M0-41 legacy audit (I04; also I06 P1-a). Each of the auditor's inputs was reproduced with a parser probe before fixing.

## Fixed

- **`php.ts` `resolveToFqn` follows PHP's rules:**
  - `\X` is fully qualified;
  - a first segment imported by `use` expands, which covers aliases and partial names (`Contracts\Foo` with `use App\Contracts`);
  - any other name is relative to the file's own `namespace`;
  - `self`/`static`/`parent` are untouched.

  Before, unqualified names stayed short and qualified names were taken as absolute. So `Role::class` in `App\Models` could resolve to `App\Admin\Role`.
- **Facade rewrite:** applies only to the facade class itself (`Illuminate\Support\Facades\X`) or a global alias (unqualified in a non-namespaced file). Before, any class whose *short* name was Cache/Event/Response/File… was rewritten, even an imported `App\Support\Cache` or `App\Models\Event`.
- **Type hints:** `Request`, `Response`, `Collection` and `Builder` are no longer treated as scalars. Framework types are skipped by resolved FQN (`Illuminate\…`), so `handle(): Response` with `use App\Http\Response` is a `return_type` edge.
- **`queries/php/references.scm`:** `extends`, `implements`, `new` and static-call scopes also match `qualified_name`. Before, `extends \App\Other\Z` and `implements Contracts\Foo` produced nothing.
- **PHP `use` → import edges:** a new PSR-4 resolver (`resolvePhpImport`) takes the longest case-insensitive path suffix (`App/Services/UserService.php`, then `Services/UserService.php`). Before, 0 import edges reached the store.
- **`scanner.ts`:** for a namespaced target, the homonym whose path follows the namespace (`…/Models/Role.php`) wins.
