# M1-03 — Follow require/include in route files with inherited group stack

Date: 2026-10-30. Delivered together with M1-02 … M1-09 as one detector rework (`src/frameworks/detectors/laravel.ts`, the new `laravel-mounts.ts`, and the scanner's route pass). This report covers this task's part.

## Delivered

A workspace-level **mount graph** (`buildMountGraph`) replaces name-based configuration. `walkRouteFile` detects `require`/`include`(`_once`) statements and evaluates their path with `phpString` (`__DIR__`, `base_path()`, `dirname(__DIR__)`, local variables). Each loaded file is registered with the group stack in force at that point (prefixes, middlewares, namespaces, controller). A file mounted twice gets one mount per load, and its routes are emitted once per mount.

## Acceptance

1. routes/api.php with Route::group(['middleware' => 'auth'], fn () => require __DIR__.'/api/users.php') yields /api/users with middleware [api, auth].
2. A file required twice under different groups yields both mounts.
3. require-mounted URI recall on the fixture is 100%.
4. The M1-01 scorer shows no regression in any other pattern.

All are met. They are covered by `tests/laravel-mounts.test.ts` (end-to-end scans through the real CLI) and by the M1-01 fixture, now with floors at 100% and exact parameter names.
