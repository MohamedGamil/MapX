## Delivered

- **`src/parsers/languages/vue-navigation.ts`:**
  - **`routerBindings`** (split out of `routerCalls`): the receivers M3-11 already knew, plus `push` / `replace` destructured from `useRouter()`, `this.$router` or a receiver (`const { push, replace: go } = useRouter()`). A call to such a local is a navigation; a member call (`list.push(`, `list. push(`) or a `function push(` declaration is not.
  - **Template sees `<script setup>`.** `navigationReferences` collects the router bindings of `<script setup>` blocks and passes them to the template's expressions: `@click="router.push(…)"` and `@click="push(…)"`. A plain `<script>`'s bindings are not the template's.
  - **Pinia `this.router`.** `this.router.push` / `replace` is a navigation in a file that calls `defineStore` (the router a store plugin adds), nowhere else.
  - **Guard redirects (`guardRedirects`).** In a guard: `next(target)` (the guard's third parameter, also from a callback inside it) and a returned target (`return { name }`, `return '/path'`), not the returns of a function nested in the guard (arrows, `function`, methods, also with a TS return type). Guards:
    - the function given to `beforeEach` / `beforeResolve` on a router receiver or on a `…router` / `…Router` local (a router parameter, a `./index` import); a same-file function passed by name is followed;
    - `onBeforeRouteLeave` / `onBeforeRouteUpdate`;
    - a record's `beforeEnter` (a function, a same-file function's name, or an array of these);
    - in-component `beforeRouteEnter` / `beforeRouteUpdate` / `beforeRouteLeave`;
    - any function with the `(to, from, next)` signature, which a guards module exports for the router file.
  - **Route modules.** `routeRecords` also reads `export default [ … ]` (also `export default <RouteRecordRaw[]>[` and `[ … ] satisfies …`) when one of its records has a component. A relative-path record there is a child of a parent in another file; its full path is unknown, so it is left out. The router file's `...adminRoutes` element needs nothing: the module's records are in the app's route table as its own file's (`buildRouteTable`, and `vue_registry` facts on sync, are per file). `mayDefineRoutes` accepts such a file.
  - **`mayNavigate(source)`**, exported: the pre-filter of `moduleNavigationReferences` and `navigatesTo`. It adds guard files that name no router (`beforeEnter`, `beforeRoute…`, the `(to, from, next)` signature) to the old `router` test.
- **`src/parsers/languages/vue-template.ts`** (outside `affectedFiles`, see below): new `scriptBlocks(source)`, whose opening-tag pattern allows quoted attribute values holding `>` (`generic="T extends Record<string, unknown>"`). `scriptBindings` uses it, so the template sees a generic `<script setup>`'s imports.
- **`src/parsers/languages/vue.ts`:** the script-block loop uses `scriptBlocks` (symbols, references and their lines for a generic `<script setup>`).
- **Scanner:** unchanged in this diff. Companion patch `M3-11-R1-scanner-companion.patch` (scratchpad), see "Scanner companion".

## Scanner companion (not in this diff)

`vueScopeMoves` re-parses, on a scope move, the files its regex says navigate: `$router`, `router.push|replace`, `useRouter(`, `<router-link`, `<RouterLink`, `next({`. Guard redirects added here can name none of these: `next('/x')` in a guards module, `return { name }` in `router.beforeEach` on an installed router. After `apps/a` gains a package.json, such a guard keeps its stale navigate edge on sync while `scan --force` drops it. The patch (`/tmp/claude-1001/-home-mgamil-mapx/41a6413c-dab3-4adb-a8ee-58b4c522412c/scratchpad/M3-11-R1-scanner-companion.patch`) replaces the regex with `mayNavigate(text)` (one import, one line) and adds `tests/vue-navigation-sync.test.ts` (drop on manifest added, sync = scan --force, restore on manifest removed). Destructured `push` (`useRouter(`), template `router.push` and Pinia `this.router.push` (`router.push`) were already matched. `mayNavigate` over-matches more than the old regex (any file naming "router"), which only costs re-parses on a scope move.

## Limitations and not done

- **Route modules:** records spread into a parent's `children` from another file have relative paths and are left out (their full path is unknown), including for navigation by name. A module with `export default [ … ]` counts whether or not a router spreads it (it must have a record with a component).
- **The vue-router detector's `route` edges** do not cover `export default [ … ]` modules: `src/frameworks/detectors/vue-router.ts` parses route arrays on its own (outside `affectedFiles`). Navigate edges use `routeRecords` and are unaffected.
- **Text analysis, file-wide:** a destructured `push` and the router receivers apply to the whole file or `<script setup>`, not to their scope; a `next` shadowed inside a guard is still read; a guard's returned location in an expression-bodied arrow (`(to) => ({ name: 'x' })`) or behind a ternary is not read.
- **Still not receivers:** a router passed as a parameter for `push` (it is for `beforeEach`), as M3-11 recorded.
- **No independent review agent was run in this lane.**

## Independent review and fixes

Reviewer O (fresh agent) checked these and found them correct: sync after retargeting, deleting and re-adding route modules and after guard changes equals `scan --force`; guard-body detection (if/else, try, switch, nested functions excluded); `generic` attributes holding `>`. Fixed:

- **P1, precision regression.** Any `export default [{ path, component }]` file became a route table. A sidebar menu config stole `/settings` from the routed view.
  - **Fix.** In `buildRouteTable`, a route module counts only when a router file of the table (one that calls `createRouter` or `new Router`, or holds a `routes` array) imports it.
  - **Test.** "links a router-link to the routed view, never to a menu config's icon component". The mutation fails it.
- **Not changed, documented here:**
  - a nested function's return type holding `{`, a literal union or a function type makes its `return` count as the guard's;
  - any `(to, from, next)` function and any `…Router` local's `beforeEach` count as guards;
  - shadowed `next` and `push` and template-scope shadowing are not modelled;
  - `this.router.push` counts in any class of a file that calls `defineStore`.

  All are heuristics of text-based analysis.
