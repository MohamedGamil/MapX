# M0-12-R4 — Import resolution precision for Ruby, Java, Python, C#, Rust and Go

Date: 2026-10-31. P2 from review 2026-10-31 (`reviews/REVIEW-2026-10-31-fb75474ba377.md`), against M0-12-R1. Builds on M0-12-R3's once-per-scan `ImportIndex`.

## Delivered

Every case in the task description has an e2e test in `tests/legacy-imports.test.ts`, block "import precision (M0-12-R4)". Each test runs real `init` + `scan` on one synthetic workspace and asserts the exact set of `target_file [target_symbol]` rows of the source's `import`/`require` edges. An empty list means no edge.

| Case (description) | Fix | Exact expected edges (test) |
| --- | --- | --- |
| Ruby `require_relative 'missing'` links `../missing.rb` | The parser marks `require_relative 'x'` as `./x` (`markImportTarget`). The resolver resolves `./`/`../` only against the file's directory. | `lib/mygem.rb`: only `lib/mygem/version.rb [mygem/version]`; the root `missing.rb` is not linked. `app/models/user.rb`: `app/models/concern.rb [concern]`. |

## Limitations

- Ruby: an explicit `require './x'` is treated like `require_relative` (relative to the file, where Ruby uses the working directory). Load paths are inferred (`lib`, `spec`, `test`), not read from a gemspec or `$LOAD_PATH` changes.
- Python: when two absolute roots both hold the module, the shallowest root still wins, as before. Which one Python picks depends on how the program is started.
- C#: the "types used" choice uses simple names from calls, instantiations and base types. Field and parameter types are not references in the C# query, so a file used only through a field type falls back to the first declaring file.
- Rust `use a::{B, C}` is still one edge to the longest module prefix; `#[path]` attributes are ignored.
- I interpreted "sibling packages" as relative siblings and src-layout sibling packages. The review gave no reproduction.

Changelog: Import edges are more precise: Ruby `require_relative` vs `require`, the right Java module in multi-module builds, Python aliased and multi-name imports, C# `using static`/aliases/nested namespaces, Rust `mod foo;` and uniform paths, and Go nested modules; import edges now name the imported module in `target_symbol` (M0-12-R4).
