# M7-03 report: landing page

Delivered 2026-11-07. Spec: `docs/baton/iterations/M7-03.md`.

## Delivered

- **Home page:** the default theme's hero (MapX, "Local code graph memory for LLMs", Get started and View on GitHub), then a `Landing` component with a numbers strip, four capability cards, an install block with copy buttons, the Claude Desktop MCP configuration, a grid of every supported language, the agent tools `mapx init` writes for, and a closing call to action. Light and dark themes, 360 px to desktop.
- **Facts from the code (`scripts/site/site-facts.ts`):** run by `npm run site:sync`, which writes the gitignored `site/.vitepress/facts.json`. The counts come from the MCP server (`listTools()`), `supportedLanguageCount()`, `FrameworkRegistry`, `PRESETS` and `AgentGenerator.listProviders()`. Today: 39 MCP tools, 23 languages, 22 framework detectors, 20 presets, 10 agent tools. VitePress never imports `src/`, so the site build needs no native modules.
- **Install text from the README:** the commands and the MCP configuration are the README's own fenced blocks. The quick start shows `init`, `scan`, `export`, `query`, `callers`, `impact`, `arch init`, `check` and `sync`, so copying it works, with a note that `UserService` and `findUser` belong to the README's sample project.
- **Guards:** a language or agent without a display name stops the sync (it caught `c-sharp` on the first run); a failed run deletes the old `facts.json`; a missing `facts.json` fails the config with "run `npm run site:sync`"; the README is read with CRLF normalised.
- **Head tags:** `description`, Open Graph title, description, type, an absolute `og:image` and a per-page `og:url` on every page (the home-page URL no longer leaks onto the docs pages).
- **Accessibility:** copy buttons are labelled, announce "Copied to the clipboard" in a status region, and each code block is a named, focusable region.

## Independent review

A fresh reviewer, given the criteria and the diff, found no P0 and two P1s.

- **P1, fixed:** no test checked that the landing page's own links resolve. The M7-02 crawl only covered `docs/`. The home page is now crawled (at least 10 internal references, the four guide cards by name, the hero image), and a renamed guide fails it.
- **P1, fixed:** the quick-start block on the page ended with `mapx check` and no configuration, so `mapx check` exits 3 when copied, and the test pinned that list. `arch init` now comes before `check`, and the test asserts the order.
- **P2, fixed:** a stale `facts.json` survived a failed generator run; a missing one gave an unhelpful Vite error; CRLF in the README leaked `\r` into the page; agent targets re-implemented the generator's filter; the "works without a clipboard" test could not fail, and nothing checked what was copied (it now reads the clipboard and compares); prose counts were not asserted (they are now, and no other count may appear); `og:url` was the home URL on every page; the copy state was not announced and the code blocks had no accessible name.
- **Found by the browser run after the fixes:** the quick-start wrapper overflowed at 360 px (`min-width: 0`), and the region test also matched the "Install and try it" section.
- **Not changed:** the landing component and `facts.json` ship in the main bundle of every page (`defineAsyncComponent` would avoid it): M7-06 sets the size budgets and decides. A Windows runner is not covered.
