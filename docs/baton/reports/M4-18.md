# M4-18 — New MapX logo: dashboard, favicons, docs, and the mapx init banner

Decision D028: the owner supplied `mapx-logo.png` (1024×1024, transparent) and `mapx-logo.txt`, with the colour `#ff02fe` for the text art.

## Delivered

- **Sources:** `assets/brand/mapx-logo.png` and `assets/brand/mapx-logo.txt`, moved from the repo root.
- **`scripts/brand/logo-assets.sh` (ImageMagick):**
  - trims the symbol's transparent padding (655×619 of the 1024×1024);
  - centres it on a square 6% larger;
  - writes `src/ui/assets/mapx-logo-128.png` (20 KB), `favicon-32.png`, `favicon-16.png`, `apple-touch-icon.png` (180 px), and `docs/images/mapx-logo.png` (256 px).

  The outputs are committed, so builds never need ImageMagick.
- **Dashboard:**
  - the header shows the symbol (32 px) beside the MapX wordmark;
  - `index.html` links the favicons and the apple-touch icon;
  - `scripts/build-ui.ts` copies `src/ui/assets` into `dist/ui/assets`, which the npm package and the binary installer already ship (both copy `dist/ui` recursively).
- **README:** the logo at the top, 128 px.
- **CLI (`src/branding.ts`):**
  - `LOGO_ART` is the text art without its 26 blank lines, its trailing spaces (lines were up to 210 columns) and its 18-column common indent: 23 lines, 64 columns.
  - `renderBanner` / `printBanner` print it in `#ff02fe`: `\x1b[38;2;255;2;254m` when `COLORTERM` is `truecolor` or `24bit`, else the nearest 256-colour code (201); plain under `NO_COLOR`.
  - Nothing is printed when stdout is not a terminal, when the terminal is narrower than 64 columns, or with `MAPX_NO_BANNER`.
  - `mapx init` calls it first, before any other output.
  - The art is embedded, so no file is read at run time (npm package and compiled binary).
- **Docs:** `docs/cli-reference.md` (init) and the CHANGELOG.
