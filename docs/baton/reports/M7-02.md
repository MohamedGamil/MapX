# M7-02 report: documentation section built from docs/

Delivered 2026-11-07. Spec: `docs/baton/iterations/M7-02.md`.

## Delivered

- **Guides:** the 11 allowlisted guides publish under `/docs/`, with a grouped sidebar (Start, Reference, Architecture rules, Guides, Internals) built from the same `GUIDE_META` list that decides what is published, and a generated index.
- **Link rewriting (`rewriteLinks` in `scripts/site/sync-docs.ts`):** a link to an unpublished repo file becomes a GitHub `blob` or `tree` URL; a link to a file that is missing, untracked by git or outside the repo stops the sync with `docs/<guide>.md:<line>`. It handles linked images, quoted and parenthesised titles, angle-bracket targets, queries, reference definitions in lists and blockquotes, footnotes, fenced code of any length, inline code and multi-line HTML comments.
- **Site features:** local search, an "Edit this page on GitHub" link on every guide, the package version as a nav link to the changelog, `ignoreDeadLinks` off.
- **Heading anchors:** the site uses GitHub's slugs (`githubSlug`). The crawl test found that VitePress's defaults differ for headings with an apostrophe, slash or plus sign, which broke 8 in-site links such as `#mapxs-own-rules`.
- **Browser tests:** `playwright.site.config.ts`, `tests/site/serve.ts` (a static server that imitates GitHub Pages: base path, folder redirects, 404.html with status 404) and `tests/site/docs.spec.ts`. The footer credit is visible beside the sidebar at 1280 px and 360 px, and nothing covers its link. M7-06 reuses the config and server.
- **Race fixed:** two test files building at once wiped each other's generated `site/docs/`. `tests/helpers/site-build.ts` serialises every test build with a lock inside `site/` (gitignored), taken over after 10 minutes if a process died.

## Independent review

A fresh reviewer, given the criteria and the diff, found no P0 and one P1. It confirmed the real guides are clean: all 390 internal links and fragments resolve, and no GitHub URL points at an untracked file.

- **P1, fixed:** the criterion "a build with a bad link fails" was only tested through `syncDocs`, and nothing pinned `ignoreDeadLinks`. A throwaway-project build now fails on a dead link and passes when fixed. I had also dropped "or heading" from the criterion when refining it; it is restated honestly: a missing heading is caught by the crawl test and `tests/docs-surface.test.ts`, not by `site:build`.
- **P2, fixed in `rewriteLinks`:** a backtick "fence" with backticks in its info string swallowed the rest of the file; `<!--` inside inline code opened a comment; a linked image was rewritten to a broken URL; single-quote and parenthesised titles, nested brackets, list and blockquote definitions and queries were missed; footnotes, `<…>` targets and `../..foo` raised false errors; an ignored file such as `.env` got a GitHub URL. Each has a unit test.
- **P2, fixed in the tests:** the crawl could pass with zero links (now at least 200 are required), matched `data-id`, accepted folders, and ignored images; the search test omitted the client's boost and 16-result cut-off; the version test matched any mention; the lock covered only one run and had no stale recovery; the static server threw on a malformed `%` and leaked its temp folder on a failed build; the footer test did not prove nothing covers the link.
- **Not changed:** inline code that spans two lines, 4-space indented code with a link and escaped `\[` still raise a loud false error instead of passing (the guides contain none; the failure names the line). Case-insensitive filesystems accept `../Readme.md` (Linux CI rejects it). At 1440 px and wider the footer is slightly off-centre under the content (cosmetic).

## Limitations

- A hand-run `npm run site:build` does not take the test lock.
- The search box itself is not driven in a browser (M7-06); the test checks the built index with the client's options.
- The `ignoreDeadLinks` test builds a second, throwaway VitePress project (about 5 s).
