## Delivered

- **Shared builders.** The CLI and MCP render through the same functions, so their output matches.
  - `src/core/metrics.ts`: `buildMetricsReport`, `formatMetricsText`, `parseTop`, `parseFormat`, `METRICS_DEFAULT_TOP = 20`, and an `exclude` option on `calculateMetrics`.
  - `src/core/edge-view.ts`: `fileEdges`, `formatFileEdgesText` and `directionError`.
- **`mapx metrics` / `mapx_metrics`:**
  - JSON is the D012 envelope `{ dir, generatedAt, summary { files, edges, density }, files[{ path, language, inDegree, outDegree, totalDegree, instability, pagerank }] }`.
  - Text is the F02 header, the ranked `RANK FILE IN OUT TOTAL INSTABILITY` table, a `... N more` line when rows are cut, and the instability legend. The layout matches the owner's sample, including the rule width.
  - `--top` defaults to 20 for text and JSON; `0` lists every file.
  - `--exclude <glob,...>` (MCP `exclude`) removes matching files and their edges. It uses `scan --exclude` semantics: a glob or a bare path segment.
  - `format` accepts `text`, `llm` (the F02 alias) and `json`.
- **`mapx edges <file>` / `mapx_edges` with a file:**
  - JSON is `{ file, direction, incoming[{ sourceFile, … }], outgoing[{ targetFile, targetRepo, … }] }`. Both row types carry `type`, `sourceSymbol`, `targetSymbol`, `verifiability`, `weight` and `line`; `line` comes from the edge metadata's `startLine`, falling back to `line`.
  - Text uses `Incoming (n)` / `Outgoing (n)` sections with ←/→ arrows. A file with no edges prints `No edges for <file>.` and exits 0.
  - Without a file, the flat list is unchanged.
- **Validation (exit 1 with a message on stderr; MCP returns `isError: true`):**
  - `--top abc`, `-1` or `1.5`;
  - `--format yaml` (metrics and edges);
  - an unknown `--direction`;
  - `--direction` without a file, including when the positional is a directory. Commander no longer supplies a default, so an explicit flag can be detected.
- **`store.queryEdges({ type })`** accepts an array or a comma string. The `mapx_edges.type` schema is an array, as in F04.
- **Consumers updated:**
  - MCP handlers and schemas.
  - The dashboard's `/api/metrics` `fileMetrics`: D012 rows, every file, using the PageRank the scan stored.
  - `docs/cli-reference.md`, `docs/mcp-integration.md`, the README command table, `src/agents.stub.md`, and the CLI lines in `src/agents/templates.ts` and `AGENTS.md`.
  - Mocked unit tests in `tests/cli.test.ts` and `tests/mcp.test.ts`. The dead `calculateMetrics` mock was removed, and the tests now assert the new table and the `--lang` empty case.

## Limitations

- **Text-only additions beyond the samples:**
  - Inferred edges end in `  (inferred)` in edges text.
  - A cross-repo target is shown as `repo:path`.
  - `... N more (--top 0 lists every file)` follows a cut table.
  - The owner samples show none of these cases.
- **Last-scan time** in the metrics header is the stored ISO time, shown as UTC `YYYY-MM-DD HH:MM`.
- **Rounding:**
  - `instability` is rounded to 4 decimals.
  - `pagerank` and `density` are rounded to 4 and 3 significant digits, so small values on large graphs do not collapse to 0.
  - `density` = edges / (files × (files − 1)), as in F02's example and `calculateGraphMetrics`. The owner's sample figure 0.667 for 3 files and 6 edges is illustrative; this formula gives 1.0 for it.
- **PageRank** is still the graph's file score, not recomputed under `--verified-only` / `--exclude`. The same applies to the dashboard's stored score.
- **Not-indexed files.** `edges <file>` for a file that is not in the index prints the same "No edges" message; it does not say the file is unknown.
- **Cross-repo incoming edges.** Edges stored under another repo of a workspace that target this file are not listed, because `queryEdges` stays per repo.
- **`--lang`** selects rows only; degrees and `summary` count every language.

## Post-acceptance defect (2026-10-31)

Found by the integration owner after acceptance. `summary.density` divided the raw edge-row count by files × (files − 1). Edge rows are symbol-level, so an import, an instantiation and a call between the same two files counted three times. For the 3-file graph api→service, api→store, service→store (6 edges), `Graph density` printed `1` instead of 0.5. Two files with ten edges between them printed 5. The Limitations note above ("this formula gives 1.0") described the defect without flagging it.

- **Fix (`buildMetricsReport`, `src/core/metrics.ts`).** Density counts distinct directed file pairs and divides by files × (files − 1). Self-edges are left out, and so are edges whose source or target is not in the counted file set (after `--exclude`). The value stays in [0, 1].
- **Unchanged:** `summary.edges` still counts edge rows, after `--exclude` and `--verified-only`, so several symbol-level edges between the same two files each count.
- **Documented** in `docs/cli-reference.md`. Its examples now show 0.5 for the 3-file, 6-edge sample.

**Tests:**
- `tests/legacy-metrics-edges.test.ts` "summary.density counts distinct directed file pairs…": real scan, CLI and MCP.
  - `--exclude leaves,src/lonely.ts` gives `{ files: 3, edges: 6, density: 0.5 }`, and the text shows `Graph density: 0.5`.
  - Also excluding `src/api.ts` gives `{ files: 2, edges: 3, density: 0.5 }`.
  - The D012 envelope and text tests now expect 3/650 on the 26-file fixture.
- `tests/metrics.test.ts` "counts distinct directed file pairs…": ten a→b edges, two self-edges and one edge to an unindexed file give `{ files: 2, edges: 13, density: 0.5 }`.

**Mutation check:** 3 mutants, all caught (exit 1).
- D1: back to the raw edge count (the defect). 4 tests fail.
- D2: self-pairs counted. 1 test fails.
- D3: pairs to files outside the set counted. 1 test fails.

D2 and D3 are caught only by the unit test, because the e2e fixture has no self-edges or edges to unindexed files.
