# M4-19 — Browser test harness for the dashboard

Decision D027 (`@playwright/test` as a dev dependency, Apache-2.0).

## Delivered

- **`npm run test:ui`** runs `playwright.config.ts`: Chromium, one worker. The global setup builds the dashboard.
- **`scripts/ui/workspace.ts`** holds the fixture generator, scan and `mapx ui` serving, moved out of the M4-16 audit so the audit and the tests share them. `smokeWorkspace` adds a Laravel app with two routes and a Vue component calling it with axios, so every tab has something to show.
- **`tests/ui/smoke.spec.ts`:** one test per tab, plus a check that the sidebar lists exactly the covered tabs. Each test opens the dashboard, waits for the graph, opens its tab, and checks the panel's content:

  | Tab | Content checked |
  | --- | --- |
  | graph | layout finished, canvas present |
  | symbols | rows and page info |
  | routes | both `/orders` routes |
  | architecture | profile naming Laravel, DSM table, smells loaded |
  | context | a build that lists files |
  | metrics | summary, TypeScript in languages, top files |
  | tool log | the seeded `mapx_query` entry |

  Each test also fails on any console error, page error or failed `/api` request.
- **`tests/ui/perf.spec.ts`:** the median of three cold loads (a fresh browser context each) of the generated 500-file fixture, from navigation start to the first finished layout. It must stay within `tests/ui/budgets.json`: the M4-16 baseline of 720 ms (the slowest of the audit's three runs) plus 20%, which is 864 ms. `MAPX_UI_PERF_SCALE` multiplies the budget.
- **Test hooks in the dashboard (`src/ui/main.ts`):**
  - `markGraph()` sets `<body data-graph>` to `loading`, `layout`, `ready`, `empty` or `error`, and records a `mapx:graph-ready` performance mark when a layout finishes.
  - The first layout now runs after its listener is attached (`layout: preset`, then `layout(...).one('layoutstop').run()`). Before, `cy.one('layoutstop')` was attached after the constructor had already run a synchronous layout, so the event was missed and the overlay was hidden only because the container's contents were replaced.
- **No browser:** the specs skip (`test.skip(browserMissing(), …)`), and the global setup prints that Chromium is not installed and how to install it. Exit code 0.
- **CI:** a `UI` job installs Chromium (`npx playwright install --with-deps chromium`) and runs `npm run test:ui` with `MAPX_UI_PERF_SCALE=2`, because shared runners are slower than this machine. It uploads `test-results/ui/` on failure.
- **Docs:** "Dashboard browser tests" in `docs/benchmarking.md`, and the CHANGELOG.

## Measurements

The perf test measured 633, 628 and 630 ms (median 630 ms against the 864 ms budget) at a load average of about 9. The first version reused one page, and its warm reloads took 159–168 ms: the bundle was cached. Fresh contexts measure what the baseline measured.

## Limitations

- The perf budget is absolute. On a much busier machine, or a slower CI runner, it needs `MAPX_UI_PERF_SCALE`. CI's factor of 2 is a judgment; the job has not run on GitHub from this session.
- The `/api/graph` rate limit (10 per minute per client) allows the smoke spec's 8 loads plus the perf spec's 3 on separate servers. More page loads per server in one minute would get 429s; M4-20 owns `/api/graph`.
