# M5-19 — External references store: capture unresolved out-of-workspace references

Date: 2026-11-03. Base: `develop@e7cd4d6`. Owner: lane agent. Iteration: `docs/baton/iterations/M5-19.md`. Decomposed from epic M5-12 (D019); gap G3 of `docs/research/deptrac/03-mapx-gap-and-integration.md`. The review of the first commit (`3f6db5b`) is answered in "Review"; this report describes the amended commit.

## Delivered

- **Store: migration 10** (`src/core/store.ts`).
  - Table `external_ref_candidates` has one row per reference that gave no edge and may name something outside the workspace:
    - `file_path`, `repo` and `line`;
    - `source_symbol`, the enclosing function, method or class (`Class::method`), or null at module level;
    - `specifier`, as the file names it;
    - `symbol`, the name used from it;
    - `kind`, the reference type;
    - `ecosystem`: `npm`, `composer`, `pypi` or `go`;
    - `external` (0/1), decided against the workspace as it stands;
    - `metadata` (JSON): a PHP function's namespaced candidates, a facade's target class;
    - nullable columns for M5-20 … M5-23: `package`, `origin` (`package`, `builtin` or `ambient`), `direct`, `dev` and `attribution` (`lock` or `manifest`). They are added now so the four ecosystem lanes need no migrations of their own that would collide on the schema version.
  - View `external_refs` holds the candidates decided external, so a reader never sees an undecided or internal row.
  - Indexes on file, repo and specifier.
  - Store methods:
    - `replaceExternalRefs`, `getExternalRefs` (the view), `getExternalCandidates`, `setExternalDecisions`, `deleteOrphanExternalCandidates` and `getPhpDeclaredNames`;
    - candidates are deleted with the file's edges (`deleteEdgesForFile`), the file (`deleteFile`) and the repo (`resetRepoForScan`, `deleteRepo`).
- **Capture** (`src/core/scanner.ts`; helpers in the new `src/core/external-refs.ts` and in `src/core/import-resolvers.ts`). Candidates are written in the transaction that writes the file's edges, after `deleteEdgesForFile` cleared both. The kill-safety rules of M0-02-R10/R11/R12 hold unchanged.
  - **JS/TS/Vue/Svelte:**
    - imports, export-from statements and `require`s whose specifier has a package's form (`jsCandidateSpecifier`). Excluded are relative and absolute paths, `#` subpath imports, `~`, `@/` and `$` aliases (SvelteKit `$lib`, `$app`; no npm name starts with `$`), and URLs or schemes other than `node:`;
    - calls, instantiations, bases and constructor parameter types whose name or receiver such an import binds. The symbol is the exported path: `Client.connect`, `readFileSync`, `default`, or `default.create` for `axios.create()` on a default import.
  - **Python:** absolute imports that no indexed file satisfies, and the calls, instantiations and bases they bind. The call receiver is read from the line, as M2-08 does, now in the shared `pythonReceiver` (a mechanical extraction from `resolveImportedCall`).
  - **Go:** every import that gave no edge, and package-qualified calls and literals.
  - **PHP:**
    - `use` statements, bases, static calls, instantiations and parameter and return types;
    - function calls, under the global name with the namespaced candidates in `metadata`;
    - a facade call (`DB::transaction()`) is stored as the file names it (`Illuminate\Support\Facades\DB`), with the facade's target class in `metadata.facadeTarget`;
    - member calls (`$x->send()`) and language constructs (`isset`, `empty`, `unset`, `list`, `array`, `echo`, `print`, `die`, `exit`, `eval`, `include*`, `require*`) are never candidates.
- **Decision** (`decideExternal`). A candidate is external:
  - **npm:** when no tsconfig or bundler alias, workspace package name or indexed file satisfies the specifier;
  - **Python:** when its top-level name is no module and no folder holding Python files, on any root the import searches;
  - **Go:** when it is outside every workspace module (go.mod paths, local replaces, go.work; the new `goImportInWorkspaceModule`), is known to be outside the project (`goImportOutsideProject`), and resolves to no package;
  - **PHP:** a class is external when no workspace class, interface, trait or enum has its qualified name and no PSR-4 root of the file's composer.json covers it. A function is external when no workspace function has any of its candidate names; PSR-4 loads classes only.
- **Decision again at the end of every run** (`decideExternalRefs`, called by `scanFull` and `scanIncremental`, so all three paths).
  - The pass reads the files index as the run leaves it. It drops candidates of files no longer indexed, decides each candidate once per ecosystem, folder and specifier, and updates only the rows whose decision changed. Nothing is parsed.
  - Other files decide a candidate: package names, aliases, Python packages, PHP declarations, PSR-4 and go.mod. A sync that does not re-parse the importing file therefore still ends equal to `scan --force`.
- **`EXTRACTOR_VERSION` 9** (8 is M5-10, rebased onto it): an index built before this re-parses once, so its external references fill without `--force`.
- **Fixture** (synthetic, labelled):
  - one new file per app: `ts/src/infrastructure/HttpGateway.ts`, `python/app/infrastructure/http_gateway.py`, `go/infrastructure/http_gateway.go` and `php/app/Infrastructure/HttpGateway.php`;
  - negatives: `app.domain.missing`, `example.com/shop/missing`, `App\Domain\Missing`, `$client->send()` and `isset()`;
  - `tests/fixtures/arch-rules/expected-externals.json` labels 46 rows across 6 apps (`php-broken-cycle` has none). The labels were written by hand from the sources (review).

Files beyond the task's `affectedFiles` (`scanner.ts`, `store.ts`, `tests/external-refs.test.ts`):

## Cost of the decision pass

The pass was timed in process, 5 runs each, on a scanned index (`M5-19-decide-bench.mts`):

| Workspace | Files | Candidates | Pass |
| --- | --- | --- | --- |
| MapX (`develop@916bbc1` tree) | 906 | 1799 | 18–34 ms |
| Synthetic, no real code (`M5-19-large.sh`): 16,000 files, a quarter each of TS, PHP, Python and Go, each with external imports and uses | 16,000 | 64,000 | 186–215 ms |

On the synthetic workspace a full scan took 28.6 s and a no-op hash sync 2.9–3.0 s. The pass therefore adds about 0.2 s (about 7 %) to a no-op sync of 16,000 files. It runs on every completed run, because inputs it reads are not indexed files: go.mod, go.work, a manifest's contents.

## Review

The independent review of `3f6db5b` found 1 P1 and 4 P2s. Each is fixed or answered below, with a test that fails without the fix (see Mutation checks).

**P1: sync differs from `--force` when another file decides.**
- Fixed by the design the integration owner gave: every candidate is stored with its decision inputs and decided again at the end of every scan and sync, without parsing. The `external_refs` view shows only rows decided external.
- The eight cases run on git and hash ("a … sync, when another file decides"):
  - the reviewer's four: workspace package `pg`, a file of another PHP namespace added, the only file of a namespace deleted, a `requests/` package added;
  - the first report's two: a root `pg.ts`, a Python package deleted;
  - tsconfig paths added and a go.mod added.
- The reviewer's harness (`review-m5-19/h.cjs`, 11 scenarios) gives sync = force on every scenario.
- With the per-class PHP rule below, the two PHP namespace cases no longer depend on the other file. The tests check that the row is there before and after, equal to `--force`.

**P2: coarse workspace checks.**
- Python: only a folder holding `.py` files hides a module (`pythonFoldersOf`). `types/index.ts` and `http/client.ts` no longer hide `types` and `http.client`.
- PHP: decided per name, by a workspace declaration with that qualified name or a PSR-4 root, never by a shared namespace. Tests: "a Python standard-library module external although…" and "a PHP class per name…".

**P2: wrong rows.**
- URL imports (`https://…`) and other schemes than `node:` are not candidates: they are no npm packages, and no ecosystem task attributes them. This is documented in `jsCandidateSpecifier`.
- `$`-prefixed specifiers (SvelteKit `$lib`, `$app`) are not candidates: they are aliases or framework virtual modules, and no npm name starts with `$`.
- PHP constructs are excluded.
- A facade is stored as the file names it, with `metadata.facadeTarget`. Test: "no URL, SvelteKit `$` alias or PHP construct…; a facade as the file names it".

**P2: downgrade.**
- An older MapX's sync on a v10 index neither deletes nor rewrites candidates, and leaves `extractor_version` at 8.
- Candidates of files it deleted are dropped by the next run (`deleteOrphanExternalCandidates`; test "drops the candidates an older MapX left for a file it deleted").
- Candidates of files it re-parsed stay as the last M5-19 parse left them until the file is next parsed or `--force`. Downgrades are unsupported, and this is listed under Limitations.

**P2: tests.**
- The import test now compares real scan output with an oracle that reads the fixture sources independently of the scanner.
- The labels were rewritten by hand from the sources, and the code was fixed where it disagreed:
  - a row's source is the enclosing function, method or class, never a variable the statement assigns. `require` at module level now gives null, not `yaml`. The PHP parameter type gives `HttpGateway::run`, not the parser's `run`.
  - TypeScript extracts parameter types of constructors only (dependency injection, `queries/typescript/references.scm`), for edges as for externals. `run(logger: Logger)` therefore gives no row. Extracting method parameter types would add TS `param_type` edges and change the graph, which this task must not do; that is a parser decision for its own task.
  - The fixture now has a constructor parameter (`constructor(private readonly logger: Logger)`), which gives the `param_type` row `HttpGateway::constructor`, and `isset()` as a PHP negative.

## Limitations

- **Languages:** only the four ecosystems with attribution tasks (JS/TS/Vue/Svelte, PHP, Python, Go) are captured. Java, Kotlin, Scala, Rust, Ruby, C#, Dart and the others keep their unresolved imports uncaptured until a task covers their manifests.
- **Not extracted, so not captured:**
  - dynamic `import()`;
  - TypeScript parameter types other than a constructor's;
  - ambient globals (`process.env`, `window`, `$_GET`), which M5-20 and M5-21 own;
  - a Go qualified name whose qualifier matches several unaliased imports;
  - the method of a PHP static call: the parser reports the class only, so the row's symbol is the class's short name.
- **Not candidates by design:** URL and scheme imports other than `node:`, `$` aliases, PHP constructs.
- **Sync parity** comes from the end-of-run decision for every case where another file decides, plus the re-parse of edited, deleted, renamed and added files. A reference that gave an edge is no candidate. When its target goes away, its file is re-parsed only when MapX's existing referrer tracking re-parses it, which is the same as for its edge.
- **Downgrade:** after an older MapX syncs a v10 index, the candidates of files it re-parsed stay stale until those files are next parsed or `--force` runs. Downgrades are unsupported.
- **Cost:** the decision pass runs on every completed scan and sync, about 0.2 s at 64,000 candidates.
- **Size:** MapX's own index gains 1799 rows, with no edge or metric change.
