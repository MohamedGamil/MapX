# M0-32-R3 — Architecture tab data: cycle smells name the real cycle; the profile ignores graph-excluded frameworks

Found on 2026-11-01 by the dashboard audit (M4-16, `docs/research/dashboard-ux-audit.md`, finding 6).

## Defects

1. **Wrong cycle path.** The Architecture tab listed critical "Cyclic dependency detected: js-aliases.ts -> js-aliases.ts" smells.
   - **Cause:** `detectCycles` (`src/core/architecture-analyzer.ts`) kept a file's edges to itself, which come from calls between its own functions. The strongly connected component it found was a real multi-file cycle. But `shortestCycleThrough(scc[0])` returned the one-step self-loop whenever the first file of the component called its own functions, so the message and the involved files named the wrong cycle.
2. **Fixture frameworks in the profile.** The profile listed Laravel and vue-router next to "Has Backend: no".
   - **Cause:** both frameworks were found only in fixture apps under `tests/` (graph-excluded by default). The archetype ignores graph-excluded files, but the framework list did not.

## Delivered

- **Cycles:** `detectCycles` ignores edges from a file to itself.
- **Profile filter:** `runPostScanAnalysis` (`src/core/scanner.ts`) gives the profile only the frameworks with at least one folder holding an indexed file of this repo that is not graph-excluded. Folders are judged by their files, so any glob shape works. A framework's folders are found in one of three ways:
  - its manifest scopes (M3-07);
  - otherwise the new optional `FrameworkDetector.appRoots(projectRoot, files, repoPrefix)` (`src/types.ts`);
  - otherwise none, meaning the whole repo, and it is kept.
- **Laravel's `appRoots`:** mirrors its `detect()`: the folders of indexed `artisan` files, plus `findLaravelRoots` on disk. That function skips `tests/`, which is why an `artisan` file under `tests/` is found only through the indexed files.
- **Unchanged:** detection itself, ignore lists and route extraction still cover graph-excluded folders.

## Independent review (fresh agent)

The reviewer confirmed:
- both criteria;
- no side effects from the cycle change: a self-loop never forms a multi-file component, and the hub detector reads edges on its own;
- that only the three display spots read `detectedFrameworks`;
- that apps at a repo root and at a nested repo's root are kept.

Findings:
- **P1, fixed: stale data after an upgrade.** `ANALYSIS_VERSION` was not bumped, so a sync over an index from the old code kept the old smells and profile. It is now 2, so the post-scan analysis reruns on the next sync (M4-04 mechanism).
- **P1, fixed: test gap.** A filter dropping every framework passed both tests, and the `repoPrefix` join was untested. Three e2e tests were added:
  - an app outside excluded folders, beside a fixture app, keeps Laravel;
  - a nested registered repo's app is in that repo's profile and not in the primary repo's;
  - `graphExcludePatterns: ['**/fixtures/*']` keeps an app whose deeper files it does not match.
- **P2, fixed:** `getAllFiles` ran once per framework without a scope. The paths are now read once, and only when a folder must be tested.
- **P2, fixed: the probe path judged folders wrongly** for file globs (`**/_*`) and one-level globs (`**/fixtures/*`). Folders are now judged by their indexed files.
- **Also fixed** while making the tests discriminate: `findLaravelRoots` walks into nested repo folders, so the primary repo "found" the nested repo's Laravel app. A folder now counts only if it holds one of this repo's own files.
- **P2, accepted:** the profile keeps a framework from the workspace-wide `frameworks.json` that no detector of this repo found. That file is also the user's override, and it is unchanged behaviour.
- **P2, accepted:** only Laravel and the manifest-scoped frameworks are filtered. Detectors that activate on marker files anywhere (Django's `manage.py`, Rails, Symfony and others) still list fixture apps until they implement `appRoots`.
- **Accepted:** the default `tests/**` does not match `web/tests/...` in nested repos. This is consistent with how graph exclusion works.
