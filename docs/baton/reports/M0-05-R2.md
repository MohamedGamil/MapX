# M0-05-R2 — Laravel structure surface (F07–F09)

Date: 2026-10-31. Decomposed from the M0-03-R1 epic per D010. The last M0 remediation item before M3.

## Before (probe on an 11-file Laravel app)

- `mapx query User` printed the class and its signature, but no relationships.
- `Route::resource('orders', …)->middleware('auth')` produced middleware edges only from `Kernel.php` (the alias map), with nothing from `routes/web.php`.
- The LLM export had no models section and printed one Dependencies line per controller **action** (`…OrderController@index (1 routes …)`, `@create`, …).
- `mapx deps AppServiceProvider` showed `→ PaymentGateway.php (binding)`, but not the concrete class.

## Delivered

- **`src/core/relations.ts`** (new): `modelRelations(store, {file, repo})` reads the `relation` edges.
  - The declaring method is the innermost method symbol around the edge's `startLine`.
  - The relationship call and type come from the edge metadata (M0-05-R1).
  - `describeRelation` renders `team → belongsTo App\Models\Team (many-to-one)`.
- **`mapx query`:** class results list their `relationships:`.
- **Route → middleware edges** (`src/core/scanner.ts`):
  - While extracting hooks, middleware hooks fill a name → class map: Kernel aliases (`auth`) and FQCNs.
  - After a detector's routes are final, every route middleware (parameters after `:` dropped) is resolved through that map, then through symbol resolution for class names.
  - The result is one verified `middleware` edge per (route file, middleware), with `routeCount` and `routes` in the metadata.
- **LLM export** (`src/exporters/llm-exporter.ts`):
  - A `## Models (N)` section: one line per model, with its relationships.
  - Route groups are keyed by controller class, stripping `@action` and `::action`, so a resource controller is one line, e.g. `OrderController (8 routes: …)`.
- **`mapx deps`:** a `Bindings (abstract → concrete)` block from the binding edges' `concreteClass`. Closures show as `(closure)`, and `$listen` bindings read `Event → Listener (listen)`.

## Findings outside scope (not fixed)

- Hook edges, including the Kernel's alias → middleware edges, are always stored `inferred`, even when the detector marks them `confidence: declared`. The new route → middleware edges are `verified`, so the two kinds of middleware edge disagree. This is a P2 consistency defect for a later task.
- A route middleware that is neither a known alias nor a resolvable class (for example a middleware group name such as `web`) gets no edge. Groups are not expanded.
