# M5-24-R2 report: external elements get the multi-layer warning and inherited dependencies

Planned in `iterations/M5-24-R2.md`. Built on develop `accf69f`. Sources: the M5-24 and M5-09 reports (their limitations: no multi-layer warning for externals, external dependencies not inherited).

## Delivered

- **Multi-layer warning for external elements** (`src/arch/membership.ts`, `src/arch/report.ts`):
  - `LayerMembership.multiLayerExternal` lists the external elements in more than one non-overlay layer.
  - `buildReport` makes each one that is the target of a decided dependency a `multi-layer` finding: a warning, an error under `policy.strictLayers`, message `pg is in 2 layers: Database, Drivers`.
  - It is reported once per (ecosystem, origin, name, layer set). The same package used from two manifests (production and dev) is two elements but one warning, with one fingerprint.
  - The source end has an empty `file` and carries `external`; the schema already allowed both. The table reporter omits the empty file line. SARIF and the other CI formats already fall back to the configuration file for a finding without a file.
  - An overlay does not count, as for any element.
- **Inherited external dependencies** (`src/arch/evaluate.ts`): the external-reference loop is now `evaluateExternal`, called for each stored reference and, under `policy.inheritDependencies`, for each reference of a workspace ancestor of a type:
  - once per (type, external element, reference kind), through the shortest path, with `via` and no line;
  - not when the type or its file has the same reference itself (its own finding stands, without `via`);
  - `extends` and `implements` references are not derived: a base class outside the workspace is the inheritance itself, decided where it is declared, as a workspace ancestor is for internal targets.
  - With the policy off, nothing is derived.
- **Docs:** `docs/architecture-rules.md` (the external "Several layers" bullet, the inherited-dependencies sentence, the `multi-layer` warning bullet).
- **Fixture:** `tests/fixtures/arch-hierarchy/external` (synthetic): `BaseRepo` (Support) extends `pg.Client`, imports `pg` and instantiates `Pool`; `Order` and `Special` (Domain) inherit through one and two levels; `Invoice` also uses `pg` itself; `Plain` extends nothing.

## Limitations

- **The warning is per external element that a layered source depends on.** An external in several layers that no layered source uses is not reported, as a symbol-less internal file is reported only when it is a dependency end.
- **A `pg` element differing in direct or dev status** is a separate element for selectors (`dev: true` layers), so two layers can see different elements of one package. Each is judged on its own layers; the warning is per layer set.
- **Smells:** the `multi-layer` warning is not a smell, as before. Inherited external findings flow into `vendor-leak` and the other finding-based smells unchanged.

Changelog: An external element (package, built-in or ambient access) that several layers select gets the `multi-layer` warning, and `policy.inheritDependencies` makes a subclass answer for the packages its base classes use, with the inheritance path in `via` (M5-24-R2).
