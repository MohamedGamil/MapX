# M0-07-R2 — Binary build test writes outside the repo; package check rejects binaries

Date: 2026-10-31. P2 from review `REVIEW-2026-10-31-fb75474ba377`: `npm test` rebuilt the 96 MB `dist/mapx-linux-x64` in the repo whenever bun was present.

## Delivered

- **`scripts/build-all.ts`**
  - `--outdir <dir>` (default `dist/`, resolved against the caller's directory).
  - `--dry-run`, which prints each `bun build` command (with the `MAPX_BUILD_VERSION` define and quoted `--outfile`) without running it and skips the WASM rebuild.
  - Target names still select targets; flags work through the npm scripts (`npm run build:linux -- --outdir <dir>`).
- **`tests/legacy-distribution.test.ts`**
  - The bun test runs `npm run build:linux -- --outdir <temp>`, checks that the temp binary prints `VERSION`, and checks that the repo's `dist/mapx-linux-x64` is unchanged: still absent, or the same mtime.
  - A new bun-independent test checks the dry-run plan: all 5 outfiles land in the requested directory, each command carries the VERSION define, and `build:linux` plans exactly one target there. The review's "without bun the criterion is not tested" is now partly covered: the VERSION define and the output paths are tested without bun, but running a real binary still needs bun.
  - New tests run `scripts/check-package.ts` in a throwaway package (`files: ["dist/"]`) in a temp directory.
- **`scripts/check-package.ts`** fails for any packed file whose first bytes are a native executable: ELF, Mach-O (32/64-bit, either byte order, universal) or PE (`MZ`). It reports `FAIL native <kind> binary packed: <path> (<size> bytes)`. Detection is by content, not by name.
- **README** ("Publishing to npm"): documents `--outdir` and `--dry-run`, and says the package check rejects binaries.

## Acceptance criterion

| Criterion | Met | Evidence |

| The binary test builds into a temporary directory | yes | "a built linux binary reports the VERSION file, built into a temp dir and not into the repo" (it ran; bun 1.3.14 is installed). After the full suite, `dist/` has no `mapx-*` file. |

On the real repo, copying the actual 96 MB binary into `dist/` after `build:npm` gives `FAIL native ELF binary packed: dist/mapx-linux-x64 (96159872 bytes)`, exit 1. |

## Reproduction (before the fix)

- **The test wrote into the repo.** My earlier full-suite runs in this worktree, on the M0-07-R1 test, had left `dist/mapx-linux-x64` (96,159,872 bytes, ELF, written 04:24) in the worktree's `dist/`.
- **The check accepted the binary.** With that binary copied back after `npm run build:npm`, the old `check-package.ts` printed `Package: 257 files, 40581801 bytes packed` and **exited 0**.

## Limitations

- The real-binary run still needs bun and is skipped without it. The dry-run test covers the VERSION define and the output paths without bun.
- `package.json` `files` still includes all of `dist/`; it was not in this task's files. `prepare` (tsup `clean: true`) wipes `dist/` before a real pack, and the package check, which CI runs (`.github/workflows/ci.yml`), now fails if a binary is ever listed. Adding `"!dist/mapx-*"` to `files` would be a cheap second guard for the owner to consider.
- PE detection uses the 2-byte `MZ` signature, so a packed text file that happens to start with "MZ" would be flagged. No such file is packed today.
