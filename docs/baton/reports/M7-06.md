# M7-06 report: site quality: SEO, accessibility, links and size budgets

Delivered 2026-11-07. Spec: `docs/baton/iterations/M7-06.md`.

## Delivered

- **Sitemap, canonical URLs, robots.txt:** `sitemap.xml` lists the home page, the docs index and every guide with absolute URLs under the configured origin and base (not the 404 page). Every page except 404 has one canonical link, equal to its `og:url` and its sitemap entry, in the form GitHub Pages serves without a redirect. `robots.txt` is written at build time with the same absolute sitemap URL. A build with `SITE_URL=https://example.org` and `SITE_BASE=/x/` is checked as well, so nothing is hard-coded.
- **Descriptions and Open Graph:** every page has its own meta and Open Graph description of 50 to 160 characters (each guide's is written in `GUIDE_META`, none states a count), a title, an absolute `og:image` with width, height and alt text, and `twitter:card=summary_large_image`. The 404 page has no canonical link and no `og:url`.
- **The card:** `site/public/og-card.png`, 1200 x 630 px and 100 KiB, drawn by `npm run site:og` (`scripts/site/gen-og-card.ts`) in headless Chromium. The output is committed, so a site build never needs Chromium.
- **Whole-site crawl (`tests/helpers/site-crawl.ts`):** from `index.html` it follows every link, image, script and stylesheet as a browser would (single, double or no quotes; script bodies excluded; percent-encoded paths decoded), and reports missing files, missing `#fragment` ids and built pages that nothing links to. Its unit tests use a fixture with each kind of defect. The built site has 13 pages, more than 400 references checked, nothing broken and no orphan.
- **Accessibility:** axe-core reports no serious or critical violation on the home page, the docs index and all 11 guides in both colour schemes, on the home page and a guide at phone width, and on the 404 page in both schemes (43 browser tests with the earlier ones). The 404 page is checked in a browser: status 404, the footer credit, a link home.
- **Size budgets (`tests/site/budgets.json`):** measured 4,023,819 bytes for the whole site and 148,468 bytes gzipped for what the home page loads (HTML, scripts, styles and the hero image); budgets are those plus about 10 percent (4,430,000 and 163,000).
- **Fontless theme:** the site uses `vitepress/theme-without-fonts`, which removed 640 KB of Inter files the site never used (4.66 MB to 4.02 MB) and the font preload.

## Defects found by the checks and fixed

- Code-block labels in the light theme were 2.9:1 (`--vp-c-text-3`); now 5.3:1 or better.
- Syntax colours of VitePress's GitHub themes were below 4.5:1: keywords (4.2), parameters (3.2), comments (4.45 light, 3.5 dark) and tag names (4.3). Each is darkened or lightened just enough in `brand.css`. This was found only after the axe run was widened from three pages to every guide.
- The search button's accessible name ("Search") lacked its visible text plus the key hint the theme adds at load. The hint is now hidden in CSS (Ctrl+K and Cmd+K still open the search), so the visible text is exactly "Search" at every width.
- The 404 page's home link had an `aria-label` ("go to home") that did not contain its visible text; `notFound.linkLabel` now matches it.

## Independent review

A fresh reviewer, given the criteria and the diff, found no P0 and two P1s.

- **P1, fixed:** removing the search button's `aria-label` with a script left it with no accessible name below 768 px, where only its icon shows, and every axe run was at desktop width. The script is gone; the key hint is hidden in CSS instead, and axe now also runs at 390 px.
- **P1, fixed:** the 404 page was never run through axe and had a label/text mismatch. It is now in the axe runs and its label is fixed.
- **P2, fixed:** every page had the same description (now unique, 50 to 160 characters, tested); the 404 page had an `og:url` for an address that does not exist; the home-page budget ignored the hero image and the icon stylesheet; the sitemap expectation was derived from the built files (it now names the home page, the docs index and every guide); the crawler missed single-quoted attributes, matched `data-href`, threw on a malformed fragment and did not decode paths (and, once stricter, misread the footer link in the page's embedded JSON, so script bodies are excluded); the font test checked only preload links (it now also checks for `@font-face` rules and font files); a `SITE_URL` exported on a developer machine could change a test build (the build helper clears it).
- **Also found while fixing:** a `walk` helper from M7-01 returned paths relative to each subfolder, which weakened the "nothing internal is published" test; it now returns paths from the output root.
- **Not changed:** axe's `incomplete` results (for example contrast over the hero gradient) are not asserted, and the open search dialog and the mobile menu are not run through axe. A link to `/mapx/docs` without the trailing slash passes the crawl though GitHub Pages answers it with a redirect (none exists). The total budget will need raising when the guides grow; its note says so. The card is drawn with the machine's system fonts, so redrawing it elsewhere changes it slightly, and no test ties the committed PNG to the script.

## Limitations

- `robots.txt` has effect only at a host root. Under `https://mohamedgamil.github.io/mapx/` crawlers ignore it; it is right for a custom domain or `SITE_BASE=/`.
- The landing component and `facts.json` still ship in every page's main bundle (the home transfer is 148 KB gzipped, most of it the hero image and the framework); the budget guards the growth.
- Lighthouse scores and real-network timings are not measured.
