# M2-23 — Laravel database/ and resources/views/ PHP files get edges

Spec: `iterations/M2-23.md`. Source: `reports/M5-17-R1.md` ("Finding (review round)"). Built on develop `41a94ed`.

## Cause

Probed with a copy of `tests/fixtures/arch-init/laravel11` (init `--no-suggestions`, `scan --force`):

- `database/factories/OrderFactory.php` and `database/seeders/DatabaseSeeder.php` were indexed with their symbols and **0 edges**, though `use App\Models\Order;`, `new Order(...)` and `Order::factory()` are in them. The same lines in `app/` give edges, and a seeder moved to `app/Seeders/` still had none: the content, not the folder.
- `php.ts` (F10) set `references.length = 0` for a class classified as migration, seeder or factory (by folder or `extends Migration|Seeder|Factory`), and returned `{ symbols: [], references: [] }` for every `.blade.php` file. The Blade view had no symbols and no edges.
- `Config.init` added `**/migrations/**` (`PHP_INIT_EXCLUDES`) to any project with a root `composer.json`, also to a Laravel app that declined the Laravel excludes, so the migration was not in the index at all.
- `X::class` is no reference in PHP: `$this->call(OrderSeeder::class)` (same namespace, no `use`), `$model = Order::class` and `@inject` gave no edge.
- By default, `mapx init` on a Laravel app (non-TTY, or the prompt's default yes) puts `database/{migrations,seeders,factories}/**`, `resources/views/**` and `**/*.blade.php` in the excludes (F10), so a real index has empty Database and Views layers.

## Delivered

- **Class edges kept** in migrations, seeders, factories and any file under `resources/views/` (`php.ts`): every reference. `use`, `extends`, `new X`, `X::m()`, type hints, function calls, relations, dispatches and bindings stay.
- **Member calls** (review round, P2-1) link the class the syntax gives and never fall back to name lookup. The scanner has no receiver typing for PHP: in `app/` every `$x->m()` links by name (`inferred`) and only `(new X())->m()` is `verified`. So, in these files only, the parser types the receiver itself (`typedReceiver` in `php.ts`): `$this` (the class around; walked as `self::m()`, `selfCall`), a parameter with a class type (`Mailer`, `?Mailer`; not a union, built-in, `self`, by-reference or written in the function; a closure reads it through `use`, an arrow function directly), `$this->prop` declared with a class type or promoted from the constructor, and `(new X())->m()`. Each gets `newClass` plus `noFallback`, and the scanner (`resolveNewReceiverCall`) links the method the class chain declares or nothing: the open chain past Eloquent's vendor `Model` no longer falls back to name lookup, which is what linked `(new Order())->save()` to an unrelated `Order::save` in the first self-scan. The edge is `verified` (in `app/` the same typed calls are `inferred`). Any other member call (an untyped `$x->m()`, `$table->id()`, `Order::query()->where()->total()`, `$this` in a view or an anonymous class) is dropped. Decision: the reviewer listed `$m->send()`, `$this->mailer->dispatchMail()`, `$this->helper2()`, `(new Mailer())->dispatchMail()` and `Order::query()->where(1)->total()`; the first four are restored, verified; the last is a by-name link in `app/` too (the builder's return type is unknown) and stays out.
- **A method of a migration, seeder or factory is no by-name target** (P2-2): symbol-index entries of kind `method` whose file has a `laravelRole` of migration, seeder or factory (anonymous migration classes included) are skipped by name lookup, from the parsed results and from the stored symbols (sync). The class walk of `$this->m()` and `self::m()` still sees them. Before, an untyped `$app->down()` or `$m->up()` in app code linked `database/migrations/…_m1.php#down` / `#up` once the migrations were indexed, and `$s->run()` a seeder's `run`.
- **`X::class`** (`queries/php/references.scm`, new capture `ref.target_class_constant`): in those files, an `import` reference to the class, resolved through `use` and the namespace (`metadata.classConstant`). In other PHP files it is still no reference.
- **Blade** (`src/parsers/languages/blade.ts`, new, about 150 lines): the source is turned into PHP with its lines kept, then read by the PHP parser. Read: `@php … @endphp`, `@php(…)`, `{{ }}`, `{{{ }}}`, `{!! !!}`, `@use('C'[, 'Alias'])`, `@inject('n', 'C')`, raw `<?php … ?>`. A directive starts at a non-word character (P2-3: `webmaster@php.net` is text), and `@php`, `@use` and `@inject` take their parenthesis after spaces or tabs only (P2-4: `@php`, a newline, `(` is a block). Blanked: `{{-- --}}`, `@verbatim`, `@{{ }}`. Other directives stay text. Decision: parse, not exclude. It costs one small module and no grammar, and it gives the Views layer what its rule checks (`Views: ["Models"]`); view names (`@include`, `view()`), `@extends`, `<x-component>` and directive arguments (`@if`) are not read (follow-up).
- **`Config.init`** (`config.ts`): a Laravel app that declined the suggestion no longer gets `**/migrations/**` and `**/seeds/**` (only `**/storage/**`). The init prompt (`cli.ts`) no longer says Blade is "not yet supported" and says how to index the directories.
- **The default exclusion is unchanged and documented**: `LARAVEL_DEFAULT_EXCLUDES` still lists `database/*` and the views. `docs/configuration.md` ("Laravel default excludes") says how to index them (decline, or list the defaults to keep in `laravelDefaultExcludes`) and what they then give; `docs/architecture-rules.md` replaces the "get no edges" limit with the exclusion fact; `docs/framework-integration.md` and the CHANGELOG (Fixed and Changed entries) follow.
- **`EXTRACTOR_VERSION` 32.**
- `tests/arch-init.test.ts`: the laravel case's `Database` count 2 → 3 (the migration is now indexed on a declined-excludes Laravel app); nothing else changed there.

## Limitations and findings

- **Owner decision, not made here:** the default still excludes `database/*`, the views and `*.blade.php` for a Laravel app (`mapx init`'s prompt defaults to yes, non-TTY always accepts). The preset's Database and Views layers are therefore empty (`empty-layer`) on a default index until the user declines or lists the defaults to keep. Flipping the default changes every existing Laravel index (file counts, clusters, roles, PageRank).
- Not read in Blade: directive arguments (`@if ($a)`, `@foreach`, `@can`), view names (`@include`, `@extends`, `view('x')`), `<x-component>` and Livewire tags. A `{{ expr }}` that is not PHP (`{{ $a or 'b' }}`) is read as the grammar recovers it; a fuzz of unclosed or odd Blade scanned without error.
- `Order::factory()` links `Order`, not `Database\Factories\OrderFactory` (Laravel's naming convention, not followed). `Foo::m()` links the class, not the method (M2-28). A one-line anonymous migration class takes no method as source (M2-22); a multi-line one takes its method (`up`), with no class scope.
- The rule is by folder and by `extends`, as F10's was: a Doctrine or Phinx migration under `/migrations/` takes it too (its class edges are now kept). A top-level `migrations/x.php` (no parent folder in the path) is not matched by the folder test, as before.
- `X::class` is an edge only in these files; elsewhere in PHP it is still none (a generic `::class` edge would change every PHP index).
- Found, not fixed: `(new X())->m()` on a class whose chain ends in a vendor base falls back to name lookup and can link an unrelated project class's method (M2-12's design), in any PHP file; and in any PHP file outside these roles, `$x->m()` links every by-name candidate, `inferred`. Only migrations, seeders, factories and views take `noFallback`.
- Member calls in these files: `$this->m()` inside an anonymous class (a Volt component, `return new class extends Migration { $this->helper() }`) and in a view, `$x = new X(); $x->m()`, a method's return type and a builder chain (`Order::query()->where()->total()`) are not typed, so they give no edge (M2-22 owns anonymous-class attribution). `$this` is the class around, so a subclass override is not followed (as for `self::`).
- `{{{ }}}` support changes no edge today (the grammar recovers); it is kept because the converted text is right, and pinned by a unit test of `bladeToPhp`.
