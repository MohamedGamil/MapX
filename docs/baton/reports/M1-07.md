# M1-07 — Mount reachability and last-registration-wins

Date: 2026-10-30. Delivered together with M1-02 … M1-09 as one detector rework (`src/frameworks/detectors/laravel.ts`, the new `laravel-mounts.ts`, and the scanner's route pass). This report covers this task's part.

## Delivered

- **Reachability:** route files under a Laravel root whose mount graph is known, but that no mount reaches, are emitted with `reachable: false`.
- **Conditional mounts:** `walkRouteFile` tracks braces opened by `if`/`elseif`/`else`/`switch` (`opensConditionalBlock`). Mounts and routes inside them get `conditional: true`, inherited through nested mounts.
- **Load order:** each route carries an `order` key (mount offsets plus declaration offset). Provider mounts sort before application routes, as in Laravel.
- **Last registration wins:** the new `FrameworkDetector.finalizeRoutes` hook, which the scanner calls with all of a detector's routes before building edges, marks every earlier duplicate of a method + URI as `overridden`, with `overriddenBy` set to `file:line` of the winner.
- The scanner also calls a new `beginScan` hook, which clears the module-level workspace cache; a long-running MCP server used to keep stale mounts.

## Acceptance

1. The fixture's unmounted file yields routes with reachable = false.
2. Duplicate GET /dup across a parent and a later-required file marks the first overridden = true with a pointer to the winner.
3. if (...) { require ...; } mounts carry conditional = true.
4. False positives on the fixture negatives are 0.
5. The M1-01 scorer shows no regression in any other pattern.

All are met. They are covered by `tests/laravel-mounts.test.ts` (end-to-end scans through the real CLI) and by the M1-01 fixture, now with floors at 100% and exact parameter names.
