# M4-11 — A persistent, controlled worker pool

Decision D025.

## Before

`parseWithWorkers` started its workers, and terminated them, for every parse batch. A scan or sync makes several batches:
- one per repo;
- re-resolution passes;
- the post-scan re-parse.

So each batch paid worker startup and grammar loading again. A 3-repo `scan --all --force` (1,200 generated files, 5 batches) started 40 workers. Per-run context travelled in `workerData`, fixed when a worker started.

## Delivered

- **`src/core/worker-pool.ts`, `ParseWorkerPool`:**
  - **Startup:** workers start lazily, up to the pool's size.
  - **Batches queue:** batches run one at a time in call order, so concurrent callers queue. Each batch's context is applied when the batch starts.
  - **Context:** goes to each worker as a versioned `{type:'context'}` message, only when it differs from what that worker last got.
  - **Idle workers:** unref'd, so they never keep the process alive, and closed after `idleMs` without work.
  - **Crashes:** a worker that dies is replaced, and its file goes to another worker. A file that kills two workers is handed back to the main thread. At most `size × 2` replacements per batch; after that, the batch's remaining files are handed back.
  - **Close:** `close()` ends the lanes of a batch in progress, with no replacements. Dead workers are pruned.
  - `createParsePool()` builds a pool for this build of MapX (source/tsx, npm or binary), and `parseWorkerUrl` moved here with it.
- **Scanner:**
  - one pool per `scanFull`/`scanIncremental` run, made on first use and closed in `finally` with the stats recorded;
  - or a shared pool given through the `pool` option, which stays alive after the run.
  - The stats line becomes one per run, with `batches`.
- **MCP:** `mcpParsePool()` is one pool for the server process, used by `mapx_scan` and `mapx_sync`. Its idle timeout is `MAPX_WORKER_IDLE_MS`, default 60 s.
- **Worker** (`parse-worker.ts`):
  - context from messages, with `workerData` as the starting value;
  - the parser cache is cleared when a run's user-language definitions differ;
  - test hook `MAPX_TEST_WORKER_EXIT=<file>`.
- **Docs:** `docs/configuration.md` "Parallel parsing" and `docs/mcp-integration.md`.

## Independent review (fresh agent)

- **P1, fixed:** concurrent MCP calls leaked one workspace's settings into another. `setContext` ran before the one-batch check, so 593 of 600 files of a workspace without a facade map got facade edges, and the second scan fell back to one thread with a misleading warning. Fixed:
  - batches queue;
  - the context is passed into `parse()` and applied when the batch starts;
  - a concurrency test was added, and the reviewer's exact bug was mutation-checked.
- **P2, fixed:**
  - The claim that idle workers never keep `mapx serve` alive is now tested by the real-serve test, and fails without `unref`.
  - Parsers cached by language name across workspaces with different user languages: workers clear the cache when the definitions differ. The main thread of `mapx serve` keeps its existing behaviour.
  - Dead workers are pruned, and no replacements start during `close()`.
- **Accepted:** with concurrent runs on a shared pool, each run's `started`/`batches` deltas can include the other run's work.
- **Confirmed by the reviewer:**
  - Criteria 1–5.
  - On the bun binary, an identical index over 1,500 files, 40 grammar loads, and crash replacement (10 workers started: 8 plus 2 replacements, exit 0).
  - No infinite respawn, and no double-counted results.
