# M2-12 report: a method called on a new-expression gets a call edge (`new X().m()`)

Found by M4-28: `new UserService().find(id)` gave an instantiation edge but no call edge to `find`. Planned in `iterations/M2-12.md`.

## Reproduced first

`tests/new-expression-calls.test.ts` was written and run against the unchanged code (dispatch base `ec44845`). Every case failed except the "no edge to Invoice" guard, which passes trivially when there is no edge at all.

| Case | Before | After |
| --- | --- | --- |
| TS/JS `new Order().total()` | instantiation `Order` only, no call edge | + call `order.ts#total`, verified |
| PHP `(new Order())->total()` | call `Invoice.php#total` (name lookup picked the wrong class), inferred | call `Order.php#total`, verified |
| Java `new Order().total()` | call `Invoice.java#total`, verified (wrong) | call `Order.java#total`, verified |
| C# `new Order().Total()` | call `Invoice.cs#Total`, verified (wrong) | call `Order.cs#Total`, verified |
| Python `Order().total()` | call `invoice.py#total`, verified (wrong) | call `order.py#total`, verified |

## Delivered

- **Queries** (`queries/javascript/references.scm`, `queries/typescript/references.scm`, `references-tsx.scm`): a call pattern for a member call on `new X()` or `(new X())`. Before this, JS/TS captured member calls only on an identifier or `this`.
- **Parsers** record the instantiated class as `metadata.newClass`:
  - `generic-wasm-parser.ts`, `newReceiverClass`:
    - JS/TS: `Order`, or `ns.Order`. Type arguments sit in their own field, so `new Order<T>()` gives `Order`.
    - Java and C#: `object_creation_expression`, with generics and qualifiers dropped.
    - Python: `X().m()` where X is CapWords, as the instantiation query reads it.
    - Parentheses are looked through.
  - `php.ts`: `(new X())->m()`, as the fully qualified name (`use` and the namespace applied).
- **Scanner** (`resolveNewReceiverCall`): the class resolves as its instantiation does.
  - In JS/TS, a class bound by an import from outside the project gives no edge (M2-08-R3). This covers `new lib.Order()` through a package namespace import too.
  - An imported project class resolves to the declaration the import names. This covers aliases, and `new ns.Order()` through `import * as ns`.
  - Otherwise the class is found by name lookup.
  - If the class declares the method (same file, method scope = class), the call links that method, verified.
  - If the project does not declare the class (`new StringBuilder()`, `\Vendor\Client`), there is no edge.
  - If the class does not declare the method, the first base that does, depth first and left first: PHP traits before the parent, then the Java superclass before its interfaces. Each base is resolved from its own class's file. A C# partial class counts as all its declarations, and a C# extension method of a class in the chain counts.
  - If no class in the chain declares the method, the answer depends on whether the chain is **closed**: every base resolved to a project class, and no `__call` / `__getattr__`. A closed chain gives no edge. An open one (a library or unnamed base, magic, a factory function, an extension method of another type) keeps name lookup, inferred, as before M2-12. JS/TS gave no call on a new instance before M2-12, so it gives none (reviews).
- `newClass` is not stored in edge metadata.
- `EXTRACTOR_VERSION` goes 15 → 16, with a comment line.

## Limitations

- `const o = new Order(); o.total()` still resolves by name (inferred), and can pick `Invoice#total`, as before. The objective's premise that this form links X#m holds only when the name is unique.
- `new ns.Order()` has no instantiation edge (none before either). Only its method call is linked.
- Bases are walked through what each parser records:
  - JS/TS `extends`;
  - the Java superclass and interfaces;
  - every C# base-list entry;
  - Python bases;
  - PHP `extends` and traits.
- The method order is depth-first-left, which is not a full Python C3 linearisation.
- An open chain falls back to name lookup and can still pick an unrelated class's method, as before M2-12. For example, `new MyList().add()` where MyList extends `ArrayList`.
- A C# extension method on an interface or a generic `this T` opens the chain rather than linking.
- Python and Java package-import shadowing (`from stripe import Order`) is M2-08-R5.
- PHP 8.4 `new X()->m()` without parentheses is handled only if the grammar parses it as a member call on an object creation. Not tested.
- The edge's target symbol is the bare method name (`total`), as for every method call.

Changelog: A method called on a new instance (`new Order().total()`, `(new Order())->total()`, Python `Order().total()`) now links the method that class declares, or one of its bases, in TS/JS, PHP, Java, C# and Python, instead of no edge or a same-named method of another class; PHP methods in a file of several classes now carry their own class (M2-12).
