## Delivered

- **`src/parsers/languages/vue-navigation.ts`:**
  - **`moduleNavigationReferences(source, symbols)`.** The parser side for plain JS/TS modules. It reuses M3-06's `routerCalls` (receiver detection and target parsing).
    - Each `navigate` reference is owned by the narrowest enclosing `function` or `method` symbol, by its bare name (edge-contract rule 2, as M3-05 does for store code). Outside any function it has no owner, and the scanner's usual fallback applies.
    - A cheap pre-filter (`push(` / `replace(` and `router` in the text) keeps it off unrelated files.
  - **One new receiver kind, for every caller:** a local holding the router the file creates (`const router = createRouter(…)`, `new VueRouter(…)` / `new Router(…)`, optionally typed). This covers guards written in the router file itself.
  - Unchanged receivers: `useRouter()` locals, `this.$router` / `$router`, `useRouter()` itself, and the router module's import.
  - An object that is none of these (`items.push('/x')`, `queue.push(…)` on a local object) gives no reference.
- **`src/parsers/languages/javascript.ts`, `typescript.ts`:** a one-line hook each, after M3-05's store pass. It skips `.vue` paths: SFC script blocks go through the TS parser with the `.vue` path and are already read by M3-06's `navigationReferences`.
- **Scanner:** unchanged. `navigate` references resolve through M3-06's route table whatever the source file.

## Limitations and not done

- **Navigation without `push` / `replace`:** a guard's return value (`return { name: 'login' }`) and `next('/x')` / `next({ name })` are not read.
- **Owners:**
  - an anonymous guard (`router.beforeEach((to) => router.push(…))`) has no named owner, so the edge's source symbol is whatever the scanner's line fallback finds (none at the top level);
  - the owner is chosen by line span, so two functions on one line resolve to the narrower one.
- **Receivers not recognised:** a router injected into Pinia stores by a plugin (`this.router`), a router passed as a parameter, and `const { push } = useRouter()`.
- `@/` aliases (M3-09), the case-insensitive name lookup (M3-10) and route renames on `sync` (M3-08) are left to their tasks, as instructed.
