## Delivered

### Scoped template locals (`svelteTemplateReferences`, `src/parsers/languages/svelte.ts`)

The one file-wide `locals` set is gone. The template walk keeps a stack of scopes:
- `{#each}`, `{#await}`, `{#if}`, `{#key}` and `{#snippet}` each open a scope. The scope's body starts after the header, and `{/…}` closes it, together with any element left open inside it (`<li>` without `</li>`).
- A branch (`{:else}`, `{:else if}`, `{:then}`, `{:catch}`) ends the current branch's scope and opens the next one. So an each alias does not reach `{:else}`, and a `{:then}` value does not reach `{:catch}`.
- An element that is neither void nor self-closing is a scope up to its closing tag:
  - void elements are the lowercase HTML tags only, so `<Input>` and `<Link>` are components;
  - a closing tag never ends scopes past a block;
  - a stray closing tag is ignored.

Each binding hides its name over an offset range. The ranges are applied after the walk:
- **each aliases** hide from their pattern on, so the source expression (`{#each rows() as rows}`) is read outside them, as a Vue `v-for` source is. A Svelte 5 index-only `{#each { length: 8 }, rank}` binds `rank`.
- **`{:then}` / `{:catch}` values and snippet parameters** hide from their header.
- **`{@const}` names** hide in the body of their enclosing block, but not in its header (`{#each total() as row}{@const total = …}`). Svelte orders a block's `{@const}` declarations itself, which is why the whole body is covered.
- **`let:` names** hide in their element:
  - a plain element's attributes are covered too;
  - a component's own attributes are not (`<List items={items()} let:items>`), because Svelte reads them in the parent scope.
- **A snippet name** hides in its enclosing scope, before its declaration too, because snippets are hoisted.

Patterns (`patternNames`) now leave out object keys (`{ children: kids }` binds `kids`), defaults and TS types (`row(item: Item)` binds `item`).

**Cost.** Opening and closing a scope never walks the stack: open blocks and open elements are indexed per tag name. Each name's ranges are merged into sorted, disjoint ranges, so a lookup is a binary search. See Performance below.

### Quoted handlers

A quoted attribute value that is exactly one balanced `{…}` (`on:click="{close}"`, `onclick="{save}"`) is read as the unquoted value. A handler named by itself is therefore a call, and `let:x="{y}"` and `this="{Card}"` read as their unquoted forms. Values that mix text and expressions (`title="{a()} and {b()}"`) are read as before.

## Limitations

- These M0-12-R10 limitations remain:
  - calls in template literals are not read;
  - a quoted attribute holding nested quotes or braces is not read (`onclick="{() => go("x")}"`);
  - default-imported functions and namespace member calls are not read.
- An each source holding a TS `as` cast (`{#each (getItems() as Item[]) as item}`) splits at the first ` as `. The source is still read for calls, but the cast type is taken as a binding inside the block.
- Element scopes follow tags as written. An element left open (HTML implicit closing) keeps its `let:` names until an enclosing tag or block closes it. That errs towards hiding, as the old behaviour did.
- A `{:else}` written directly inside a component's children (`{#if}<List let:x>{:else}…</List>{/if}`) ends the component's scope with the `{#if}` branch. That is invalid Svelte nesting anyway.
