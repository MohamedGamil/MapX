## Delivered

**Five MCP tools (34 → 39), in `src/arch/mcp-tools.ts`.** `src/mcp.ts` lists them after `mapx_arch_validate_config` and dispatches them. Each one wraps the library function behind a CLI command:

| Tool | Library | CLI it equals |
| --- | --- | --- |
| `mapx_arch_check` | `runArchitecture`, `shownReport`, `exitCode` | `mapx check --format json`, plus `exitCode`, `total`, `limit` and `truncated` |
| `mapx_arch_layers` | `layerSummaries`, `layerMembers`, `unassignedElements` | `mapx arch layers [L] [--why] --json`, `mapx arch unassigned --json` |
| `mapx_arch_allowed` | `isAllowed` | `mapx arch allowed <from> <to> --json` |
| `mapx_arch_explain` | `whichLayers`, `isAllowed` | `element` = `mapx arch which --json`; `dependency` = `mapx arch allowed --json` |
| `mapx_arch_init` | `proposeFromRoles` (new, `src/arch/propose.ts`) | none yet (`mapx arch init` is M5-17) |

- **Defaults and caps.** Every tool returns JSON by default. Lists are capped and report their totals: findings (`limit`, default 50, 0 for all) and layer members or unassigned elements (default 100). `mapx_arch_check` also takes `format: "text"`, which returns the CLI's whole table, uncapped: the table's summary counts errors among the findings it lists, so a capped table would misreport them.
- **Errors (AR-17).** A failure is a tool result with `isError: true`, never a JSON-RPC error. Its JSON is `{ error, exitCode, issues?, candidates? }`:
  - `exitCode` 3 for configuration and usage errors. Examples: no configuration, an invalid one, an unknown layer or rule, an element nothing resolves, an ambiguous name, a bad `type`, `limit`, `file` or `since`, and `mapx_arch_init` over an existing file.
  - `exitCode` 4 for an index that is missing, unscanned, stale or outdated.

  A violation (`exitCode` 1) or a refused dependency is an answer, not an error.
- **`mapx_arch_check` filters.**
  - `view`, `layer`, `rule`, `failOn`, `report*` and `failOnUncovered`, as on the CLI.
  - `file`, MCP only: a path prefix or glob over finding ends. A path that matches no indexed file is exit 3.
  - `since`, MCP only: a git ref, through `changedSince`, the function behind `mapx arch changed --since`.

  Configuration errors stay in the report whatever the filter, and the exit code is computed on the filtered report.
- **AR-19 `alternatives` on `allowed` (in `src/arch/introspect.ts`, so the CLI has them too).**
  - **What they are.** For a refused dependency on a file or symbol, they list the source's own and allowed layers that already expose a matching symbol.
  - **Matches.** A symbol matches as a `supertype`, a class or interface the target extends or implements transitively, found through stored edges resolved with the evaluator's `endResolver`. It can also match by `name`: the same name, or the end of the target's name, at least 4 characters long.
  - **Eligibility.** A symbol is listed only when all its layers are usable, and it is not private to another layer.
  - **The cap.** At most 10 per layer, with `total`.
  - **The CLI.** `mapx arch allowed` prints them as `instead, in <layer>: …`.
- **`mapx_arch_init`.**
  - **The proposal.** One layer per MapX role in the archetype's `LAYER_ORDER` (from the scan's codebase profile; `mixed` without one), selected with `{ "role": … }`. Each layer may depend on the layers after it in that order, as `FlowValidator` judges direction.
  - **Unplaced roles.** Roles with no place in the order, such as `other`, are listed as `unplaced` and named in a header comment.
  - **Validation.** The proposal is validated with `validateArchitectureText`.
  - **Writing.** It writes `.mapx/architecture.jsonc`, or `.mapx/architecture/<view>.jsonc`, only with `write: true`. It never writes over an existing file, and never when the proposal has issues.
  - **The index.** A stale index is accepted, since roles are what it reads. A missing or outdated one is exit 4.
- **One index gate.** `openCurrentIndex` moved from `src/cli.ts` into `src/arch/index-gate.ts` as `indexGate`. It returns the messages instead of printing them. The CLI wrapper prints them unchanged (the `arch-cli` and `arch-introspect` tests, which pin them, pass), and the MCP tools say `` `mapx_sync` `` and `` `sync: true` `` instead.

**A bug the no-write test caught.** The dispatch in `src/mcp.ts` first returned `runArchTool(…)` without `await`. The `finally` that closes the call's store therefore ran before the store was opened, so every arch tool call leaked a SQLite connection. The visible symptom was `mapx.db-wal` and `mapx.db-shm` left in `.mapx/`. It is now `return await`, and the snapshot test fails without it (see the mutation check).

## Acceptance criteria

1. **Each tool has an MCP round-trip test on the fixture. Met.** `tests/mcp-arch.test.ts` uses a real in-memory MCP client on scanned temp copies of `tests/fixtures/arch-mcp/ts` (with a two-commit git history for `since`) and `tests/fixtures/arch-rules/ts`. There is one `describe` per tool:
   - `mapx_arch_check`: the JSON equals `mapx check --format json` (exit 1), with the three violations by identity. Layer and rule filters equal the CLI; `text` equals the CLI table; the cap reports its total. `file` (prefix and glob) and `since` (`HEAD~1` keeps the Controller → Domain finding; `HEAD` keeps none) work. Usage and configuration errors are exit 3.
   - `mapx_arch_layers`: the summary, `Domain --why` and `unassigned` equal the CLI; caps are reported; an unknown layer gives its candidates.
   - `mapx_arch_allowed`: below. The answers equal the CLI on four pairs of the M5-01 app. An unknown, ambiguous or bad argument is exit 3, with candidates.
   - `mapx_arch_explain`: `element` equals `which`, `dependency` equals `allowed`, and `layer` gives membership with its selector. An unknown element is exit 3.
   - `mapx_arch_init`: below.
   - The index gate: a stale index is exit 4 with the MCP advice, `sync: true` recovers, and a folder with no index is exit 4 and is left empty.
2. **`mapx_arch_allowed` returns `allowed: false` with rule and allowed alternatives for a disallowed pair. Met.** `PlaceOrder → SqlOrderRepository` returns `allowed: false`, `rule: disallowed-layer`, `severity: error`, `exitCode: 1`, `allowedLayers: ['Domain']`, and `alternatives: [{ layer: 'Domain', total: 1, symbols: [OrderRepository (interface), match: 'supertype'] }]`. This is not a tool error. The answer equals the CLI's JSON (exit 1), and the CLI text names the alternative. A file target gives the same alternative.
3. **`mapx_arch_init` never writes files unless `write: true` (the test asserts no fs change). Met.** The test hashes every file under the workspace before and after three dry runs (no `write`, `write: false`, and a `view`). The snapshots are equal, which also checks the store left no WAL files. With `write: true`:
   - the file is written with exactly the returned `config`;
   - `mapx arch validate-config` exits 0;
   - `mapx check` exits other than 3 (1: the proposal flags `Data → Service`), with `counts.error` 0 and no `configErrors`;
   - `mapx_arch_check` agrees.

   A second `write: true` is exit 3 ("already exists") and leaves the tree unchanged.

## Limitations and notes

- **`mapx_arch_init` is the role-based slice of AR-15 only.** It has no clusters, framework presets, observed layer graph or baseline: those are M5-17. On the fixture, the proposal's own check finds a violation (`SqlOrderRepository`, role `data`, implements `OrderRepository`, role `service`). That is the "day one is green" gap M5-17's baseline closes. M5-17 can replace `src/arch/propose.ts` and should give `mapx arch init` and `mapx_arch_init` one engine.
- **Alternatives are heuristic.** `supertype` relies on stored `extends`/`implements` edges, and `name` on name suffixes. A target's subtypes, or symbols that merely play the same part, are not found. Matching is exact on names, case aside; there is no fuzzy matching.
- **A file that does not exist yet still cannot be named** in `mapx_arch_allowed` (the M5-08 limitation). Name its layer instead.
- **No baseline on MCP.** `mapx_arch_check` applies the configuration's baseline, but has no `--baseline`, `--generate-baseline` or `--compare`. Those stay on the CLI.
- **Tool-call logging (revised after the review).** The MCP server logs calls to `.mapx/tool-calls.jsonl` of the first workspace it is called on that already has a `.mapx/` folder, and creates no folder. Dry-run `mapx_arch_init` calls are never logged. This changes one older behaviour: `mapx serve --dir X` on a folder with no `.mapx/` no longer creates `X/.mapx/` at start.
- **`since` refuses some valid revisions.** A revision with whitespace, quotes or shell characters (for example `HEAD^{/fix (urgent)}`) is refused even though git would accept it. That is defence in depth on top of M5-08-R1.
- **Root agent files** still say 32 or 34 tools until regenerated with `mapx agents`.

Changelog: Five MCP tools give agents the architecture rules: `mapx_arch_check`, `mapx_arch_layers`, `mapx_arch_allowed` (a pre-flight check that names allowed alternatives), `mapx_arch_explain` and `mapx_arch_init` (a role-based proposal that writes only with `write: true`). They answer as `mapx check` and `mapx arch …` do, and the generated agent instructions say to call `mapx_arch_allowed` before adding an import across modules (M5-14).
