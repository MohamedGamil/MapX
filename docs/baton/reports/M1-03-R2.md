## Delivered

- **Mount graph (`laravel.ts`, `buildMountGraph`).** The BFS queue became a depth-first `load` in PHP's execution order: providers, then entry points, each file's mounts in source order.
  - `loaded` mirrors PHP's included-files table. A `require_once`/`include_once` (`MountRequest.once`, set by `mountAt`) of a file already loaded is skipped. After a conditional load only, it is kept and flagged conditional.
  - `chain` holds the files still loading. A mount of one of them (a require cycle, by any include form) is skipped, so each route is reported once.
  - The `(file, order)` dedup and the depth cap (8) remain.
  - `MountEntry` names the entry type; entries carry `once`.
- **Route keys (`processRouteChain`).** The prefix and URI parts are joined without empty parts (`Router::prefix` trims the joined URI). `'/'` under `admin` is `/admin`, and `finalizeRoutes` now sees it as the same key as a later `get('admin')`. `Route::get('', …)` is a route (`uri !== null`). A resource still needs a name.
- **Resources (`expandResourceRoute`).** A segment containing `{dynamic}` gets the wildcard `{dynamic}`, not `Str::singular('{dynamic}')`.
- **`Route::match`.** The first argument is read as a PHP array or a single string. Each verb is evaluated with `phpString` and uppercased; duplicates are dropped. A verb that can't be evaluated makes the method `ANY`, flagged dynamic.
- **Invokable controllers.** In this order:
  - `X::class` as the handler gives `X@__invoke` (FQN through the use table and group namespace, as for arrays);
  - a class-name string (read from `handlerRaw`, the argument with its quotes) outside a `Route::controller()` group gives `X@__invoke`;
  - inside such a group, the string is still a method name.
- **Dynamic flag.** `r.path.includes('{dynamic}')`, so partly dynamic segments count.
- **Names (`nameArg`).** `->name()`/`->as()` (chain attribute, route suffix, group), the group array's `'as'` and the action array's `'as'` are evaluated with the `{dynamic}` fallback, never dropped.
- **Bindings (`laravel-mounts.ts`).**
  - `functionBodies` returns `{ start, open, close, uses }`. `stringAssignments` adds a scope barrier (`Binding.keep` = the `use` list) per function or closure body. `varsAt` hides every non-`this->` binding the barrier does not keep. Arrow functions have no barrier.
  - The expression pass matches `$x =`, `$x .=`, `$x ??=` and `$this->x =` / `.=` / `??=`. `.=` appends to a known value, otherwise the value is unknown.
  - `??=` keeps a known value. It assigns the right-hand side only inside a function or closure where `$x` does not appear before it, from the `function` keyword on, which covers parameters and `use`. Otherwise the value is unknown, top-level code included.
  - A written property gets an "unknown" binding at index -0.5 (after the declarations at -1). Its write holds from the write to the end of that body.
- **Fixture (`tests/fixtures/laravel-routes`).**
  - `routes/api.php` gets the M1-03-R2 block, with `api/once.php`, `api/cycle-a.php` and `api/cycle-b.php`.
  - The RouteServiceProvider gets `mapAssignedRoutes()` and `$edition`, with `routes/rsp/{area,tier,edition,zone}.php`.
  - `app/Http/Controllers/ShowProfile.php` is new, and HomeController gets its new methods.
  - Labels L128–L145 add patterns `require-once`, `require-once-wrong`, `require-cycle`, `trailing-slash`, `trailing-slash-overridden`, `invokable`, `dynamic-resource`, `rsp-compound-assignment(-wrong)`, `rsp-property-assignment(-wrong)` and `rsp-partly-dynamic`. Negative labels sit in their own patterns, the fixture's convention, because the floors require every label of a pattern with live labels.

## Limitations

- `??=` is conservative: at top level, or after any mention of the variable in its function, the value is unknown even when PHP would assign.
- A property written in any method is unknown in every other method, `__construct` included, and before the write in its own method. Methods may run in any order, so MapX does not order them.
- `require_once` after a conditional load is kept and flagged conditional. No test covers it.
- `Route::match` with an unknown verb reports `ANY` (pairing accepts any method), flagged dynamic. Laravel's automatic HEAD for GET is still not reported.
- `['uses' => 'X']` without `@` is not read as invokable.
- Integer class properties (`protected $num = 3`) are still not evaluated, so `"n{$this->num}"` is `n{dynamic}` (now flagged dynamic).

Changelog: Laravel routes load as PHP loads them: a file `require_once`'d twice is mounted once and a require cycle reports each route once; `'/'` under a prefix is the prefix itself (and is overridden by a later route of that URI); an unevaluable resource name gets `{dynamic}` wildcards; `Route::match` verbs are evaluated (double quotes, single strings); single-action controllers get `__invoke`; partly dynamic URIs are flagged dynamic, unevaluable name prefixes are kept as `{dynamic}`, and RouteServiceProvider `.=`, `??=`, `$this->prop =` assignments and closure scope follow PHP (M1-03-R2).
