# M4-09-R4 report: store-coverage tests keep their databases out of tests/

## Finding

Verifying M5-24 in a clean clone, the first `npm run check` failed in `tests/fixtures-tracked.test.ts`:

```
expected [ Array(2) ] to deeply equal []
+   "tests/store-coverage-temp.db",
+   "tests/store-coverage-temp.db-wal",
```

`tests/store-coverage.test.ts` (since `f91f005`) opened its SQLite database at `path.join(__dirname, 'store-coverage-temp.db')`, and its Bun case at `store-bun-temp.db`, both under `tests/`. While those tests run, the database and its `-wal` file exist there, and git ignores them. When fixtures-tracked (added by the 2026-11-02 review) ran at the same time, it listed them. The `npm run check` rerun passed (2,914 tests), so this was a race, not a defect of M5-24.

## Delivered

`tests/store-coverage.test.ts`:
- both databases live in a `mapx-store-coverage-*` folder under `os.tmpdir()`, made once per file;
- an `afterAll` removes that folder recursively, `-wal` and `-shm` files included;
- a new test asserts that both database paths are outside `tests/` and that no `store-*-temp.db*` file is in `tests/`.

| --- | --- |

A first version that only checked `tests/` in `afterAll` did not fail on the first mutation: `afterEach` already deletes the database, so nothing is left by then, though the file exists under `tests/` while the tests run. The assertion now checks the paths themselves.
