## Delivered

### `src/languages/registry.ts`: when a `.h` header is C++ (`isCppHeader(text)`)

The rule is conservative (the integration owner's decision after the review). A C header must never turn into C++.

1. **Read the text.** `headerLines` makes one linear pass. It joins `\`-continued lines, drops comments and string and character literals (keeping `"C++"`), and trims each line.
2. **Track conditionals.** It follows the depth of `#if`/`#ifdef`/`#ifndef` … `#endif`. Anything inside a conditional never counts, whatever it tests: `__cplusplus`, `0`, or a feature macro, in any branch (`#elif` and `#else` included).
3. **Treat an include guard as depth 0.** The guard is `#ifndef G` or `#if !defined(G)` (after any `#pragma` lines), then `#define G`. Its `#endif` must be the last line, with no `#else` or `#elif` of its own.
4. **Look for C++-only syntax at depth 0,** on a trimmed line:
   - `namespace X {`, with the brace on that line or the next;
   - a `class X {` or `class X :` declaration with a body, export macros and `final` allowed;
   - `template <`;
   - `public:`, `protected:` or `private:`;
   - `using namespace`;
   - `extern "C++"`.

   `class A;`, `namespace = 0;` and `int class;` do not count.
5. **Use only the file itself.** No sibling `.cpp`/`.hpp` lookup, so a header's language does not change when a neighbour appears.

`getLanguageForFile` is pure again: it does no I/O, and `.h` maps to C.

### `src/core/scanner.ts`: the decision is made from content the scan already read

- `headerLanguage(relPath, language, content, hash)` runs in `discoverFiles`, after the file is read and hashed, and in `getFileInfo` (sync).
- It is cached per path and content hash within a run.
- An unchanged file that a rescan skips is never read for it.
- `languageOf` prefers the stored language for `.h` files, so C and C++ headers resolve with their own language.

### `src/parsers/generic-wasm-parser.ts`

**C# and Scala namespaces from the syntax tree.** Each C# and Scala declaration stores `metadata.namespace`:
- the file-level clauses before it (`namespace X;`, body-less `package a`);
- then each enclosing block (`namespace A { … }`, `package b { … }`), joined with dots;
- `''` outside every block (the global namespace).

**One-line functions as source symbols.**
- A reference inside a function or method that sits on one line gets that function as its source symbol, from the syntax tree, labelled as the scanner labels it (`scope::name`).
- Before, the scanner's line-range rule picked the first of several equal one-line ranges, so the namespace or type won.
- Multi-line functions, references outside any function, and Vue SFC scripts are left to the existing rules. Vue's rule 2 owns its references.

### `src/arch/elements.ts`

- A symbol's namespace is its stored `metadata.namespace`. `''` means the global namespace, which gives the path form.
- Without one, the symbol takes the file's first namespace: other namespace languages, and indexes from before this change.
- The line-range block lookup of the first commit is gone, along with its "longer name wins" tie-break.

## Limitations

- **C++ headers the conservative rule misses** stay C, with path-form names and a C parse. These are headers whose only C++ is any of the following, or anything inside a conditional:
  - `virtual`, `enum class`, `constexpr`, `nullptr`, `static_cast`, `operator`, `friend`, references (`int&`);
  - `#include "x.hpp"` and `<vector>`-style includes, `std::`;
  - `struct S : public B`, `class A;` forward declarations, `inline namespace`, `template<…>` behind a macro.
- **Access labels** (`public:`) count at depth 0, as the rule specifies. A C function body in a header with a goto label named `public`, `private` or `protected` would be read as C++. We know of no real case.
- **Scala** is handled for nested blocks and chained clauses. Kotlin's `package` is still not captured (an M5-03-R1 limitation).
- **One-line source symbols** come from the syntax tree only when the enclosing function is on one line. Multi-line functions keep the scanner's line-range rule, which already picks them correctly.
- **The rest of the M5-03-R1 limitations stand:** C++ in-class declarations are not stored, and Java and C# nested-type chains are not built (`A.B.C.Inner`, not `A.B.C.Z.Inner`).
- **Indexes built before this change** have no `metadata.namespace`, so they keep the first-namespace behaviour until rescanned. The extractor version bump makes them count as stale.

Changelog: C++ classes in `.h` headers now get C++ symbols and qualified names (C headers stay C), symbols in C# files with several namespace blocks and in nested Scala packages take their own block's namespace, and calls inside a one-line C++ namespace come from their function (M5-03-R2).
