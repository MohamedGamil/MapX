## Delivered

**Evaluation (AR-08 step 5).** `decideLayers` in `src/arch/evaluate.ts` now has an `internal-element` step after `disallowed-layer` and before `private-layer`. When the target is internal to this reference and the source layer is not one of the target's non-overlay layers, the dependency is a violation.
- Severity follows the other violations: inferred edges give `warn` under the default policy.
- `TargetLayers.internal` computes the marker lazily, and `LayerDecision.internal` carries the marked element and the marker into the finding.
- For a Go package import, the package is internal when every in-scope file of it is internal to the reference.
- `mapx check` and `mapx arch allowed` both decide through `decideEdge`, so they agree. `arch allowed` also checks internal markers for a hypothetical dependency between two elements, and explains it: "… is internal to Domain (visibility)".

**Markers (`src/arch/visibility.ts`, new).** `internalMarkers(view, visibility, ownerOf, imports)` returns `check(reference)` and `native(element)`. A reference is internal-element when the target carries one of these markers:
- **A doc tag from `visibility.internalTags`** (default `@internal`, `@mapx-internal`), compared through M5-10's `hasDocTag`. This is MapX's own layer rule, whatever the compiler says.
- **A native marker** (`visibility.nativeMarkers`, off by default). Since the review, a native marker counts only for a reference the language itself refuses. Where MapX cannot see the boundary, it reports nothing:

**Parsers (`src/parsers/annotations.ts`).**
- **Go doc comments give doc tags:**
  - the comments counted are the `//` or `/* */` lines directly above the declaration, each starting its own line, with no blank line between;

## Limitations

- **Unknown boundaries give no finding.** A C# project without a `.csproj`, Kotlin without a Gradle or Maven file, Dart without `pubspec.yaml`, or TS without a `package.json` name is never flagged. Go uses import paths, and falls back to directories without a `go.mod`.
- **Go:**
  - unexported names are not marked, because the compiler already confines them;
  - a Go reference the compiler accepts is never an internal-element finding, so the Go native marker flags only code that would not compile across those boundaries.
- **Python:** a module's private status is judged on its workspace path. The re-export rule relies on stored import edges.
- **C#:**
  - `InternalsVisibleTo` is read from the `.csproj` and from `[assembly: …]` attributes in the project's indexed `.cs` files;
  - the assembly name is `<AssemblyName>` or the `.csproj` file name;
  - public keys are ignored.
- **Rust:** `pub(in path)` paths not starting with `crate`, `self` or `super` give no finding.
- **Kotlin qualified names** are path-based, because the parser stores no package. This is documented and outside this task.
- **Lifting:** a class reached through an internal member and through a public one has both an allowed and an internal-element finding; the message names the member.
- **`nativeMarkers` is all or nothing:** AR-11 specifies a boolean, so there is no per-language list.
- **Doc comments in JS/TS, Java, Kotlin and PHP still attach across blank lines,** as M5-10 documented (TypeScript and Javadoc tooling behave this way). Go requires the comment directly above.
- **Index:** `EXTRACTOR_VERSION` is 10, so existing indexes re-parse once.
- **Flakes:** the worker-pool "4 workers" failure is the known flake M4-12-R1.
- No new dependencies.

Changelog: Architecture checks now report `internal-element` violations for symbols tagged `@internal` or `@mapx-internal` (configurable with `visibility.internalTags`), and with `visibility.nativeMarkers` also for references a language's own module visibility refuses, such as Go `internal/` packages, Python `_private` modules and names, Kotlin and C# `internal`, Java package-private and Rust `pub(crate)` (M5-11).
