# M2-08-R1 report: attempt 1 reverted; owner decision needed

Status: BLOCKED, not DONE. The first attempt passed its registered tests, but an independent review reproduced two P1 regressions and a large sync-cost increase, so it was reverted. Its diff is kept in `docs/baton/reports/M2-08-R1/attempt-1.patch` for the next attempt.

## What attempt 1 did

1. **Barrel import edges:** `queries/{typescript,javascript}/references*.scm` gave `export … from` / `export *` an `import` reference, so a barrel has import edges, and sync reached the barrel's importers when a module behind it changed.
2. **Absent names:** `findExport` returned "absent" when the imported project module did not contain the name as a whole word, had no CommonJS exports, and every `export *` target was absent too. The call then got no edge, instead of the name-lookup fallback.

Registered checks: `tests/import-bound-calls.test.ts` passed (4 new or changed cases failed before), `npm run eval` held every floor, and `npm run check` passed in a clean clone. Mutation checks: removing the TS capture failed the 2 barrel cases; mapping absent back to null failed 4.

## Why it was reverted (independent review, all reproduced against HEAD)

- **P1, real edges lost: comments.** `stripComments` is not string- or regex-aware. A `/*` inside `'image/*'` or `/\/*$/` swallows the text up to the next `*/`, so real `export … from` lines disappeared and real exports read as absent. HEAD linked these calls.
- **P1, real edges lost: default exports.** `defaultExportName` reads the raw text, so a commented-out `// export default function legacyBuild` made `import build …; build()` absent.
- **P2, CommonJS:** compiled and dynamic CommonJS exports (`__exportStar(require(…), exports)`, `Object.assign(exports, …)`, `exports[k] =`) slipped past the guard.
- **P2, resolution order:** `probeModule` tries `utils/index.*` before `utils.ts`, the opposite of Node and TypeScript. The fallback used to hide this.
- **P2, sync cost:** 20 modules behind one `export *` index with 300 importers: a body-only edit of one leaf went from "Updated 1 files" to "Updated 302 files".
- **P2, sync ≠ `scan --force`:**
  - after deleting an imported module, or the module behind an `export *` barrel;
  - after adding a missing module;
  - for import-then-export barrels (`import { run } from './impl'; export { run }`), which `isBarrel` doesn't recognise (pre-existing).
- **P2, untested conditions:** each of the absent rule's four conditions survived mutation of the registered test file.

## What a correct fix needs

- A string-, template- and regex-aware comment stripper, used by `findExport`, `defaultExportName` and `isBarrel`.
- Extensions tried before `/index.*` in import resolution (affects all resolution; needs scorer evidence).
- Gating the barrel walk on changed exported names, or a decision that the sync cost is acceptable.
- Importers of deleted modules re-parsed, and unresolved imports that a new file satisfies.
- Tests for each "absent" condition, plus the reviewer's shapes (two-star barrel, `module.exports = require`, `export * from 'pkg'`, `export { a as run }`).

## Owner decision needed

Whether sync may re-parse every importer of a barrel when a module behind it changes (correct, but costly in barrel-heavy repos), or must re-parse them only when the module's exported names change (cheaper, more code). Until then the pre-change behaviour stands: a stale edge in the transient "re-export written before the declaration" case.
