# M2-08-R1 report: import-bound calls through barrels, and no fallback past a project import

Attempt 1 was reverted after its independent review (history below). Attempt 2 follows the owner's decision D032: sync re-parses a barrel's importers only when a module's exported names change.

## Delivered (attempt 2)

- **Barrel import edges:** `queries/{typescript,javascript}/references*.scm` give `export … from` and `export *` an `import` reference, so a barrel has import edges to the modules it re-exports.
- **`src/core/js-source.ts` (new):**
  - `scanJs`: JS/TS text without comments, found outside string, template (with `${…}` nesting) and regex literals.
    - Regex and division are told apart by the preceding token.
    - In `.tsx`, `.jsx` and `.js` files, JSX elements are read: attribute strings are literals, `{…}` is code, and text between tags is blanked.
    - An unterminated `/*` is text.
    - It returns a mask with literal contents blanked, and whether the mask's braces balance.
  - `scanModule`: the same, reading only a `.vue` or `.svelte` file's `<script>` blocks.
  - `exportSkeleton`: the top level, with function, method and arrow bodies emptied (a `{` after `)`, `=>` or a return type `): T`). An unbalanced scan keeps everything, so any edit changes the signature.
  - `jsExportSignature`: a hash of the skeleton, every declared function, class, interface, enum and type-alias name (the index holds nested declarations without a scope, so `findExport` finds them), and whether the module has CommonJS exports.
- **The absent rule (`findExport`):** a name is absent, so the call gets no edge, when all of these hold:
  - the scan balanced its braces, and the name does not occur in the module's skeleton;
  - the module has no `exports` anywhere (CommonJS and compiled forms) and no `export =`;
  - every `export *` target resolves in the project and lacks it too.

  Anything uncertain keeps the name-lookup fallback. `defaultExportName`, `isBarrel` and `importBindings` read text through `scanJs`.
- **D032:**
  - every parse of a JS/TS file records `files.metadata.exportSig`;
  - `importerReferrers` re-parses a changed JS/TS module's importers, and the importers behind its barrels, only when the module is imported and its signature differs from the recorded one, or none is recorded;
  - a changed barrel among them is still walked through, even when its own signature is unchanged;
  - other languages keep the M2-08 walk.
- **Deleted modules:** `removeFiles` queues the importers of a removed module, and those behind its barrels, in `pending_referrers:<repo>` in the removal transaction. The same sync takes them: the hash sync and the full path take them after removal, and the git sync takes them a second time.
- **Barrels:** `import { x } from …; export { x }` counts as one.
- **Resolution order:** `probeModule` tries extensions before `/index.*`, as Node and TypeScript do.

## Limitations

- **New file:** a new file satisfying an import that did not resolve before does not re-parse the importer (pre-existing). Registered as **M2-08-R2**.
- **Python, Vue and Svelte:** these keep the ungated M2-08 walk.
- **Watch-mode race:** the signature is computed from a fresh read when the parse result is written. A save between the parse and the write could record the newer signature (unreproduced).
- **Mis-scanned TSX type positions:** a generic function type at an expression start in `.tsx` (`x: <T>(a: T) => T`) still reads as JSX. A mis-scan unbalances the braces, which makes the module's signature and absent rule conservative.
- **Conservative signature:** it changes on any top-level edit, such as an object literal's contents or a class's member list, so those edits still re-parse importers. That is the safe direction.

## History: attempt 1 (reverted)

Attempt 1 passed its registered tests, but an independent review reproduced these, all against HEAD:

- **P1, lost edges: comments.** The comment stripper was not string- or regex-aware: a `/*` in `'image/*'` or `/\/*$/` hid real `export … from` lines.
- **P1, lost edges: default exports.** A commented-out `// export default function legacyBuild` made a default import absent.
- **P2, CommonJS:** compiled CommonJS exports slipped past the guard.
- **P2, resolution order:** `utils/index.*` was resolved before `utils.ts`.
- **P2, sync cost:** a body-only edit behind an `export *` index with 300 importers went from 1 re-parsed file to 302.
- **P2, sync ≠ `scan --force`:** after deleting a module, and for import-then-export barrels.
- **P2, untested conditions:** each "absent" condition survived mutation.

Its diff is kept in `M2-08-R1/attempt-1.patch`. Attempt 2 fixes each item above except the added-module case (M2-08-R2). The owner's answer on sync cost is D032.
