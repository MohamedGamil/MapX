# M0-01-R1 — Edge verifiability for JS/TS member calls and DOT styling

Date: 2026-10-31. P2 from the M0-41 legacy audit (I01).

## Fixed

- **Untyped receiver calls:** `obj.method()` with a plain identifier receiver is now captured in the JS, TS and TSX reference queries. The generic parser labels these calls `inferred`, because they're resolved by name only (F01). Before, they produced no reference at all, so TS projects had 0 inferred edges. Built-in method names on JS values (`map`, `filter`, `push`, `then`, `get`, `set`, `join`, `log`, …; `JS_BUILTIN_METHODS`) are skipped to avoid noise.
- **DOT styling:** `dashed` is reserved for inferred edges (F01). Verified `implements` and `binding` edges are `solid` and verified `dispatch` is `bold`, still told apart by their colours. This deviates from F12, which drew dispatch dashed; F01's meaning of dashed takes precedence, because otherwise dashed no longer signals "inferred".

## Impact measured on MapX's own `src/`

Call edges: verified 1,195 → 1,195 (unchanged), inferred 22 → 364. The top new inferred targets are real receiver calls (`resolveSymbolToFile`, `load`, `register`, `getMeta`, …). They can be excluded with `--verified-only` where supported.
