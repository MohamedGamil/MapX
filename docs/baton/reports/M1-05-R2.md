# M1-05-R2 — Laravel resources: singleton, scoped, middlewareFor, per-route prefix/domain keys

Date: 2026-10-31. Follow-up of M1-05-R1 (its Limitations section). Built on develop d904c68.

## Ground truth

The expected route lists come from Laravel's own router. `laravel/framework` v12.70.2 (commit 4dc928b47c05) was installed fresh with `composer require laravel/framework:^12` into a scratch directory in the session scratchpad (`m105r2/oracle-vendor`). Nothing was loaded from any other project or its `vendor/`. A scratch oracle script (`m105r2/oracle/oracle.php`) registers a synthetic route file inside an `api` prefix + middleware group with the real `Illuminate\Routing\Router`. For every route it prints method, URI, name, action, `Route::middleware()`, `Route::getDomain()` and the non-null `Route::bindingFields()`. The e2e `EXPECTED` and the new fixture labels were copied from that output. The framework source under the same vendor directory was read to choose the rules. It was not used as the expected output.

What the oracle showed:

- **Singletons.** `singleton()` registers `show`, `edit` and `update` at the resource URI itself, with no wildcard of its own. `->creatable()` adds `create`, `store` and `destroy`; `->destroyable()` adds `destroy`. `apiSingleton()` defaults `only` to `store, show, update, destroy`, so a plain apiSingleton gives `show` and `update`. `teams.logo` becomes `teams/{team}/logo`. Prefixes, `parameters`, `names`, `as` and `middleware` behave as they do for resources.
- **`->scoped([...])` does not change the URI.** `Route::uri()` keeps plain wildcards. `ResourceRegistrar::setResourceBindingFields` gives each route the binding fields of the wildcards in its own URI: `users/{user}/notes` gets `{user: uuid}`, and `users/{user}/notes/{note}` gets `{user: uuid, note: slug}`.
- **`middlewareFor($methods, $mw)` replaces `middleware` for those actions.** When `middleware` was already set, the two lists are merged: middleware first, deduplicated. A later `->middleware()` replaces `middleware` and is appended to every `middlewareFor` entry. `['middleware_for' => [...]]` in the options array is used as given.
- **A route-level prefix goes in front of the group prefix.** `Router::createRoute` applies the group prefix to the URI first. The Route constructor then prepends the action's `prefix`. Inside `Route::group(['prefix' => 'inner'])` in `routes/api.php`, `Route::get('pong', ['prefix' => 'outer', ...])` is `/outer/api/inner/pong`. A `prefix` attribute chained before the verb (`Route::prefix('lead')->get(...)`) ends up in the same action key, and so does `->prefix()` called on the route after the verb. The action array's `prefix` wins over a chained attribute (`array_merge($attributes, $action)`).
- **A route's `domain` key replaces the group domain** (`RouteGroup::merge` unsets the old domain).

## Delivered (`src/frameworks/detectors/laravel.ts`)

- **Singletons.** The verbs `singleton`, `apiSingleton`, `singletons([...])` and `apiSingletons([...])` are recognised, along with the chain calls `creatable()` and `destroyable()`. `expandResourceRoute` takes a `singleton` flag that switches to Laravel's singleton action list (show, edit, update, then create, store, destroy) and URIs, and to the apiSingleton `only` default. Shallow names apply to edit, update and destroy, as in `addSingleton*`. Routes carry `resourceType` `singleton` or `apiSingleton`. Plural forms register one singleton per `name => controller` entry with the shared options. A `::class` controller is `declared`.
- **`scoped()`.** `->scoped([...])` and a `bindingFields` option are stored on the options. Each expanded route records `metadata.bindingFields` for the wildcards in its URI, in URI order. Routes without any are unchanged.
- **`middlewareFor`.** `->middlewareFor()`, the `middleware_for` option and the `->middleware()` merge follow PendingResourceRegistration, with `Router::uniqueMiddleware`. This applies to resources and singletons.
- **Route-level prefix and domain.** Action arrays now read `prefix` and `domain`. A route's path is built as: the `->prefix()` calls after the verb (the last call goes outermost), then the action `prefix` or else the last chained `prefix` attribute, then the group prefixes, then the URI. The domain is a `->domain()` after the verb, else the action `domain`, else a chained attribute, else the group domain. Groups are unchanged: `Route::prefix('x')->group(...)` still nests `x` inside the enclosing prefixes.

## Limitations

- `update` stays two routes, PUT and PATCH, rather than one `PUT|PATCH` route.
- Not modelled: `withoutMiddleware`, `withoutMiddlewareFor` and `excluded_middleware`. Laravel keeps these in `Route::middleware()` and removes them only when gathering, so the reported lists still match `Route::middleware()`. Also not modelled: `Route::resourceParameters()`, `ResourceRegistrar::verbs()`, `->missing()`, `->withTrashed()` and `->where()`.
- Repeated chained RouteRegistrar attributes on a route now follow last-wins for `prefix` only. `Route::middleware('a')->middleware('b')->get(...)` still reports both, where Laravel keeps `b`. Groups still stack repeated chained prefixes.
- An explicit `{post:slug}` in a plain route URI is reported as written. Laravel's `uri()` strips the field into `bindingFields`. The fixture has no such route.
- Behaviour change to note for users: a per-route `Route::prefix('v1')->get(...)` or `['prefix' => 'v1', ...]` inside `routes/api.php` is now reported as `/v1/api/...`, which is what Laravel registers. MapX used to report `/api/v1/...`. No existing test or fixture label used this form.
- The oracle and its scratch vendor directory are not part of the repository. Their output is frozen into the test's `EXPECTED`.

Changelog: Laravel `Route::singleton`/`apiSingleton` (with `creatable`/`destroyable` and the plural forms), `->scoped()` binding fields, `->middlewareFor()` and route-level `prefix`/`domain` keys now match Laravel's router, including its placement of a route's own prefix before the group prefix (M1-05-R2).
