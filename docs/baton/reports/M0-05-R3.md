# M0-05-R3 — Hook edges honour declared confidence (verifiability)

Date: 2026-10-31. Source: M0-05-R2's "Findings outside scope" and F01 (edge verifiability).

## Before (reproduced by the new test, scanner unchanged)

In a temp workspace with a Laravel Kernel alias `'auth' => \App\Http\Middleware\Authenticate::class` and a NestJS `@UseGuards(AuthGuard)`, a real `init` + `scan` stored:

- both Kernel edges (`app/Http/Kernel.php → app/Http/Middleware/Authenticate.php`, hook names `auth` and the FQCN) as `inferred`, although their metadata said `confidence: declared`;
- the NestJS guard edge as `inferred` with `confidence: inferred`.

`mapx metrics --verified-only --format json` therefore gave the Kernel file out-degree 0 and Authenticate in-degree 0. The declared middleware edge was dropped, while the M0-05-R2 route → middleware edge was verified.

## Delivered

`src/core/scanner.ts`: a hook edge's verifiability now follows the rule route edges already use. `confidence: 'declared'` gives `verified`; anything else (absent, `inferred` or numeric) gives `inferred`. The same value goes to the stored edge and to the in-memory graph edge. The stored `confidence` metadata is unchanged. This is the only place hook edges are built (`extractHooks` has a single call site).

Laravel is the only detector that declares hooks today: Kernel aliases, groups and their qualified entries. Service-provider hooks point at their own file, so they produce no edge. NestJS, Symfony and the other detectors are unaffected and stay inferred.

| Acceptance criterion | Test (`tests/legacy-hook-verifiability.test.ts`) | Status |
| --- | --- | --- |
| 1. A Kernel `$routeMiddleware` alias edge (declared) is stored verified; a hook with confidence inferred stays inferred. | `stores a declared Kernel alias edge verified and an inferred NestJS guard edge inferred`. It checks the exact Kernel edge list: two `middleware` edges to `Authenticate.php`, both `verified`, with hook names `auth` and `App\Http\Middleware\Authenticate`. It also checks the exact NestJS list: one `src/auth.guard.ts` edge, `inferred`, `UseGuards:AuthGuard`. | met |
| 2. `metrics --verified-only` keeps declared middleware edges. | `metrics --verified-only keeps the declared middleware edge and drops the inferred guard edge`. With `--verified-only`, Kernel is `[in 0, out 1]` and Authenticate `[1, 0]`, the same as without the flag. `src/auth.guard.ts` goes from `[1, 0]` to `[0, 0]`, because the guard is not imported and its only edge is the inferred hook. | met |

## Mutation check

| Mutation in `scanner.ts` | Result |
| --- | --- |
| A: `hookVerifiability = 'inferred'` (the old behaviour) | both tests fail |
| B: `hookVerifiability = 'verified'` (ignore confidence) | both tests fail: the NestJS edge becomes verified and the guard keeps in-degree 1 under `--verified-only` |

The fix was restored afterwards, and the registered command passed again (exit 0).

## Limitations

- Numeric hook confidence (for example `1.0`) still maps to `inferred`, as it does for route edges. No detector emits numeric confidence today.
- Middleware group expansion on routes (the other M0-05-R2 finding) is still open and out of scope here.
- No CLI, MCP or schema change, so `docs/cli-reference.md` and `docs/mcp-integration.md` are unchanged.

Changelog: Framework hook edges declared by their detector (such as Laravel Kernel middleware aliases) are now stored as verified, so `metrics --verified-only` keeps them (M0-05-R3).
