## Delivered

- **`scripts/eval/floors.json`, the single record of floors.** The values are those measured on `develop@ccfbad5`:

  | Scorer | Floors |
  | --- | --- |
  | Routes | URI, handler and attribute recall 1, precision 1, `flagged` ≥ 35 and `exactParams` ≥ 112 (both added after review), false positives 0, `strictParams` |
  | HTTP | call-site, URL and pairing recall 1, pairing precision 1 |
  | Edges | recall 1, precision 0.99, false positives ≤ 1; per pattern (`"*"`) recall 1 and false positives 0, except `composable` ≤ 1 |

  The edges precision floor rises from the test's 0.95 to 0.99 (measured 117/118 = 0.9915).
- **`scripts/eval/run-eval.ts` (`npm run eval`).**
  - Runs the three scorers' existing scan and score functions in process, then `checkFloors` per scorer.
  - Prints a table per scorer, with a note when a floor could be raised.
  - `--json` prints a machine-readable result, and `--floors <file>` uses another floors file.
  - Appends a Markdown table to `$GITHUB_STEP_SUMMARY` when that variable is set.
  - `validateFloors` rejects these before anything is scanned:
    - unknown scorers, keys, metrics and patterns (patterns are read from the fixture's labels);
    - a recall or precision floor outside [0, 1];
    - a count floor that is not a non-negative integer.
  - The metric lists are typed against each scorer's `Score` interface, so a renamed field fails the typecheck.
  - Exit codes: 0 when every floor holds, 1 on a regression, 2 on a usage, floors-file or scan error.
- **The fixture tests read their floors from `floors.json`:**
  - `tests/laravel-routes-fixture.test.ts`: totals, and `strictParams`. It now also asserts `attributeRecall`.
  - `tests/http-pairing-fixture.test.ts`: totals.
  - `tests/vue-sfc.test.ts`: the per-pattern found floor is the recall floor times the labelled count, and the false-positive ceilings and minimum precision also come from the file.

  Checks that are not floors stay in the tests: exact params, flagged negatives, per-pattern label counts.
- **CI:** a new `Eval` job (`needs: lint`) runs `npm ci --legacy-peer-deps`, then `npm run eval`.
- **Also changed:**
  - `tests/eval-floors.test.ts`: 10 tests;
  - `docs/benchmarking.md`: an "Accuracy scoring (fixtures)" section;
  - root `CHANGELOG.md`: an Unreleased entry;
  - `package.json`: the `eval` script.

## Independent review

One fresh agent reviewed the change, given the acceptance criteria and the files but not these conclusions. It reproduced every criterion as met. It confirmed the floors against direct scorer runs, and confirmed that no fixture test was weakened: per-pattern counts are the same, and precision went from 0.95 to 0.99. It also reproduced its own detector mutations; each made `npm run eval` exit 1:
- a Laravel `match` route;
- the `fetch` regex;
- the Vue `mixins` key.

Its findings, all fixed:
- **P1: the Eval job missed a route liveness regression.**
  - Losing the `conditional` flag (`meta.conditional = true` → `void 0` at `laravel.ts:560` and `:1974`) changed no recall or precision. Eval passed while the routes test failed.
  - Fix: `routes.min.flagged` 35 and `routes.min.exactParams` 112 were added to `floors.json`, and the routes test reads both.
  - Mutation check after the fix, with the same change: `npm run eval -- --floors <routes only>` exited 1 with `FAIL routes: flagged 33 < 35`. Restored afterwards.
- **P2: malformed floors files were accepted and checked nothing.** Examples: `"min": 1`, `null`, `"patterns": 5`, `"*": 1`, a string `strictParams`, a `null` scorer, and a scorer with no bounds. `validateFloors` now rejects each of these, and each has a case in `tests/eval-floors.test.ts`.
- **P2: float overshoot in `tests/vue-sfc.test.ts`.** With a fractional recall floor, the found count could round one too high (0.28 × 25 → 8). Now `Math.ceil(x * n - 1e-9)`. This was latent: every floor is 1.
- **P2: smaller runner fixes.**
  - A missed ratio floor printed as "1 < 1". A value equal to its floor at four decimals now prints at full precision (tested: `recall 0.99996 < 1`).
  - `--floors` now resolves against `INIT_CWD`, the directory npm was invoked from.
  - A scan error no longer exits mid-loop. The other scorers still report and the step summary is written, then the run exits 2. Checked: a syntax error in `laravel.ts` gave exit 2, three "scan failed" lines on stderr and three in the summary; restored afterwards.
  - The docs now say `fixture` is relative to the repository root, and that a scan failure exits 2.

The reviewer also noted that `build` needs only `test`, so a failing Eval job fails the workflow without stopping the build job. That is left as is: every job here is independent except through `needs`.

## Limitations

- **Duplicate scans.** CI scans each fixture twice: once in the vitest fixture tests in the `test` job, and once in `npm run eval` in the `Eval` job (about 26 s locally). The two read the same floors, so they cannot disagree.
- **Per-pattern floors.** Route and HTTP floors are on totals only. With every recall floor at 1, a per-pattern regression still fails the totals. The routes test keeps its per-pattern label-count checks.
- **Floors are not raised automatically.** The runner prints a note when a value exceeds its floor.
