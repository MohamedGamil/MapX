# M0-03-R4 — edges/deps parity: cross-repo incoming edges, unindexed-file message, MCP path matching

Date: 2026-10-31. Sources: the Limitations of `reports/M0-03-R3.md` (cross-repo incoming edges, not-indexed files) and `reports/M0-05-R4.md` (`mapx_dependencies` takes only an exact path). Output contract: D012.

## Before (reproduced)

- **Cross-repo edges.** A two-repo workspace: the primary repo has `src/theme.ts` and `src/app.ts`; `libs/ui` is a second registered repo whose `button.ts` imports `../../src/theme` and whose `icon.ts` imports `./button`. After `scan --all --force`, the store holds `libs/ui/button.ts → src/theme.ts` (repo `ui`, target_repo primary). `mapx edges src/theme.ts --format json` returned `incoming: []`, and `mapx edges libs/ui/button.ts` listed only the primary repo's two edges, not icon.ts's. Cause: `queryEdges` was always filtered to `repo = <primary>`, and edges are stored under their source repo.
- **Not-indexed file.** `mapx edges nope.ts` printed `No edges for nope.ts.` and exited 0, the same as an indexed file with no edges.
- **`mapx_dependencies`.** `{ file: "AppServiceProvider" }` printed `No dependencies found`, while `mapx deps AppServiceProvider` resolved the file.

With the new tests and the pre-change `src/cli.ts`, `src/mcp.ts` and `src/core/edge-view.ts`, 4 of 22 tests failed: the three new tests and the D012 neighbourhood test (which now expects `sourceRepo`).

## Delivered

- **`src/core/edge-view.ts`:**
  - Incoming rows gain `sourceRepo`, mirroring `targetRepo`: the edge's repo when it is a cross-repo edge (target_repo set and different from the edge's repo), else `null`. The key order is `sourceFile, sourceRepo, type, …`.
  - Text shows a cross-repo source as `repo:path`, as outgoing rows already did.
  - `notIndexedMessage(file)`: `File "<file>" is not indexed. Run mapx files to list tracked files, or mapx scan to index it.`
- **`mapx edges <file>` / `mapx_edges {file}`** (`src/cli.ts`, `src/mcp.ts`): with a file, `queryEdges` is no longer limited to the primary repo, so every registered repo's edges to or from the file are listed. Without a file, the flat list keeps its primary-repo scope. A file that is not in `files` and has no matching edges gives the not-indexed message: CLI on stderr with exit 1 (text and JSON), MCP with `isError: true`. An indexed file with no edges still prints `No edges for <file>.` (exit 0).
- **`src/core/file-resolve.ts`** (new): `resolveFilePaths` (exact, glob, partial name) moved out of `src/cli.ts` unchanged, plus `fileNotFoundMessage`. The CLI `deps` command uses both; its output is unchanged.
- **`mapx_dependencies`:** resolves `file` through the shared resolver. Several matches each get a `── path ──` section, the same headers as `mapx deps`. No match returns the CLI's `File "…" not found in index.` and tip with `isError: true` (it used to print `No dependencies found`). `crossRepo` uses the resolved paths too. The schema description names the accepted forms.
- **Docs:** `docs/cli-reference.md` (`edges`: cross-repo neighbourhood, `repo:path`, not-indexed exit 1, `sourceRepo` in the JSON example) and `docs/mcp-integration.md` (`mapx_edges`: `sourceRepo`, workspace-wide neighbourhood, not-indexed error; `mapx_dependencies`: path forms and the no-match error).

## Limitations

- **Not-indexed rule.** "Not indexed" means: not in `files` and no matching edge rows. A path that only appears as an edge target (not in `files`) still lists those edges. With `--type` / `--verified-only` filters that leave no rows, an unindexed path reports "not indexed", which is still true.
- **`edges <file>` does not resolve partial names or globs**; it still takes an indexed path (relative or absolute). Not part of the criteria.
- **Flat list scope.** `edges` without a file (`--from` / `--to` / `--type`) still lists only the primary repo's edges.
- **Text renderers.** The CLI `deps` and MCP `mapx_dependencies` texts still differ slightly as before (the CLI prints a blank line before `Depended on by:` and prints `No dependencies found` when there are only reverse dependencies). Only resolution and the multi-match headers were aligned.
- **Finding outside this task.** In a workspace, `mapx workspaces add <repo>` scans the new repo before the primary repo is indexed, so its references into the primary repo are not resolved; a later `scan --all` without `--force` keeps those files cached and still has no edge (`libs/ui/button.ts → src/theme.ts` appeared only after `scan --all --force`). The e2e test uses `--force` and says why.

Changelog: `mapx edges <file>` / `mapx_edges` now list edges from every repo of a workspace (incoming rows carry `sourceRepo`) and report a path that is not indexed instead of "No edges", and `mapx_dependencies` accepts globs and partial names like `mapx deps` (M0-03-R4).
