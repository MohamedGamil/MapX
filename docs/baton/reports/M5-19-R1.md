# M5-19-R1 — An attribution-rules version re-decides external references without a re-parse

Planned in `iterations/M5-19-R1.md`. Sources: `reports/M5-19.md` (candidates, decided again at the end of every run) and `reports/M5-21-R1.md` ("Findings outside this task"). Based on develop `03ca6f6`, after M5-25-R4 and M5-25-R3 on this branch.

## Delivered

- **`src/core/extractor-version.ts`:** `ATTRIBUTION_VERSION` = 2, documented beside `EXTRACTOR_VERSION`, with a comment history.
  - The comment says when to bump it: a change that attributes unchanged inputs differently. It also says when not to: a change to what a scan extracts bumps `EXTRACTOR_VERSION` instead, and evaluation rules need no version.
  - **1:** M5-20 to M5-23, the attribution as first shipped. A record without a version counts as 1.
  - **2 (the one bump):** the rule changes that shipped without a version, M5-21-R1 (PECL names ambient; vendor/composer classmap and files names) and M5-23-R1 (the module path of an unreadable go.mod from the folder layout). It also covers this branch's M5-25-R3 (a directory replacement is `lock` when go.sum is complete). That change would otherwise reach a stored row (an absolute `replace` target) only on a forced scan.
- **`src/core/manifests/inputs.ts`:** `ExternalInputs.rules`, the version of the pass that recorded the inputs. `parseExternalInputs` reads a record without one as 1.
- **`src/core/scanner.ts` (`decideExternalRefs` only; nowhere near the JS/TS import code):**
  - A stored attribution is kept only when the record's `rules` equals `ATTRIBUTION_VERSION` and its inputs stand, as before.
  - Every pass records `rules`, including the "no candidates" record.
  - When the version differs, the pass is the one a changed input already gave. Externality is decided as on every run, and every external candidate of every repo is attributed again from its stored row, with no file parsed.
- **`docs/architecture.md`:** the storage paragraph mentions the version.
- **`tests/external-refs.test.ts`:** 3 tests, each on the git and the hash sync (6 runs).

No CLI or MCP surface change. No schema change: `rules` is a field of the JSON in `meta`. No new dependency.

## M5-24-R4's opt-in: an evaluation rule

`policy.uncovered.externals` (D039) is resolved by the architecture loader from the configuration, which asks whether a layer has a positive `package` selector. `mapx check`, `arch allowed` and the MCP tools then apply it to the stored rows at check time. It never changes a stored `package`, `origin`, `direct`, `dev` or `attribution`, so it is an **evaluation rule** and needs no `ATTRIBUTION_VERSION` bump. The version's comment records this distinction.

## Review

The coordinator's review of `464f03e` found one P2 for this task (outdated attribution not reported). It is fixed in the amended commit, rebased onto develop `11eb634`.

- **`src/core/extractor-version.ts`:** `outdatedAttribution(store)` is true when the inputs record names an earlier `ATTRIBUTION_VERSION`. `outdatedIndexRepos` is `outdatedRepos` plus, for every scanned repo, an outdated attribution (the record is the workspace's), and `outdatedIndexWarning` reports it with the same text: "The index of … was built by an older MapX: … to rebuild it." `outdatedRepos` is unchanged, because the scanner uses it to decide a re-parse, which older attribution rules must not cause.
- **Gate:** `indexGate` (`src/arch/index-gate.ts`) uses `outdatedIndexRepos`, before and after the sync. Without `--sync`, `check` and the other gated commands exit 4 with that message. With it, the sync attributes again and the gate passes, with no file parsed.
- **`mapx status` and `mapx_status`:** both print the warning and recommend a sync (`mapx status` did not report an outdated extractor before either). The other CLI commands and the MCP tool results already print `outdatedIndexWarning`, so they now include it.
- **`decideExternalRefs`:** a record with no candidates left is rewritten at the current version too. Otherwise an index with an older record and no external references would stay outdated after every sync.
- **`ATTRIBUTION_VERSION` 2** comment: M5-25-R3's change now reads "attributed `manifest`", not `lock`.
