## Delivered

**One engine, `src/arch/infer.ts`, which replaces `src/arch/propose.ts` (removed).** `runInit(store, workspace, request)` is what `mapx arch init` and `mapx_arch_init` both call, so they return the same JSON and write the same bytes (a test compares them).

- **The proposal.** `inferArchitecture` builds the document, loads it through `config.ts` (with `extends` and presets resolved, by the new `loadArchitectureText`), and evaluates it on the index with `buildReport`. Its `issues` are therefore what `mapx arch validate-config` and `mapx check` would report, and its counts are `mapx check`'s.
- **Sources.**
  - `from: roles` (default): unchanged from M5-14. There is one layer per role in `LAYER_ORDER[archetype]`, with `{ role }` selectors and "may depend downward" rules.
  - `from: clusters`: one layer per primary cluster (`{ cluster }`). A first evaluation with no allowances gives the observed cluster graph, and the rules allow exactly those pairs, so a new cross-cluster dependency fails.
  - `from: framework`: the preset of the framework the codebase profile detected (`laravel`, `nestjs`, `django`). Exit 3 when none is detected.
  - `preset: <id>`: a document that `extends` `mapx:preset/<id>`. Each folder parameter the preset declares (`root`) is inferred from the indexed code paths. The engine picks the folder, the repo root or up to three levels down, under which the most of the preset's layers have files, then the most files, the shortest, and the first by name. For `ddd-contexts`, every folder under `root` outside the shared kernel becomes a context layer. A preset tied to a framework that was not detected gets a note.
- **The observed layer graph.** It goes into the JSONC comments: each layer's files and its dependencies on other layers today, and which of them the rules refuse. The JSON's `observed: [{ from, to, dependencies, violations }]` carries the same data.
- **Baseline.** `baseline: true` renders the proposal's violations with `renderBaseline` and writes them to the default baseline path (`.mapx/architecture.baseline.json`, or the view's), which `mapx check` picks up without configuration. It needs a current index (exit 4 when stale, `--sync` / `sync: true`). Without it, a stale index is accepted as before.
- **Writing (`runInit`).** A dry run is the default. The refusals are all checked before any file is written, each exit 3 with a message:
  - an existing configuration, or a baseline it would replace, without `force`;
  - a view outside `.mapx/architecture/`, by name or through a symlink (`viewProblem`, now exported from `config.ts`);
  - a proposal with issues.

  An empty baseline is written only to replace an existing one. Without `--baseline`, an existing baseline that will apply to the new configuration gets a warning.
- **Stable output.** Layers follow the archetype's order, or are sorted by cluster or folder name. Rules follow layer order. There are no timestamps. Every comment comes from the index, and control characters are replaced, so a folder name cannot break the JSONC.

**Presets: `src/arch/presets/*.jsonc`.** The eight are `layered`, `clean`, `hexagonal`, `ddd-contexts`, `feature-sliced`, `laravel`, `nestjs` and `django`, each with a comment on every layer. They are registered as `PRESETS` in `config.ts` (the registry M5-02 left empty).
- **Why they are embedded.** tsup does not bundle (`bundle: false`) and the bun binary has no source tree. So `scripts/gen-arch-presets.ts` embeds the files in `src/arch/presets/index.ts`, and a test fails when the two differ (`--check` too).
- **What they select by.** Presets use paths, file-name suffixes, decorators (`@Module`, `@Controller`) and framework parts. They do not use the hierarchy selectors: M5-09 landed on develop while this task was in progress (it is the rebase base), and presets built on it are a follow-up.
- **Laravel's route files.** `Http` takes `framework: route-handler` only outside `routes/`. Route files hold closures that are route handlers too, and without the exclusion `routes/*.php` landed in both Routes and Http (multi-layer warnings, and 7 false Http → Routes violations on the M1-01 fixture). A mutation check below pins this. The review of 4e5d5fb reworked the preset for idiomatic Laravel 11; see that section.

**CLI: `mapx arch init [path] [--from roles|clusters|framework] [--preset <id>] [--baseline] [--write] [--force] [--view v] [--sync] [--format text|json] [--json]`.**
- A dry run prints the JSONC on stdout and a one-line summary on stderr, so `mapx arch init > file` works. When the file exists, the summary says so and names `--force`.
- `--write` prints what it wrote.
- Exit 0 on success, 3 for usage errors and refused writes, 4 for the index.

The "no configuration" message of `mapx check` now points at `mapx arch init` instead of saying it is not available yet.

**MCP `mapx_arch_init`** gains `from`, `preset`, `baseline`, `force` and `sync`. They are validated before the index gate, as M5-14 does for the other arguments. Its contract stays:
- it writes only with `write: true`;
- it refuses `../`;
- it never overwrites without `force: true`;
- a dry run is not logged.

The result keeps M5-14's keys and adds `source`, `preset`, `parameters`, `observed`, `violations`, `baseline`, `notes` and `warnings`.

## Limitations and notes

- **Presets are a first wave.** Eight of AR-15's twenty are here. Onion, MVC, MVVM, Symfony, Express, FastAPI, Rails, Spring, ASP.NET, Flutter, Next.js and Vue are left for later.
- **Presets do not use the hierarchy selectors yet** (M5-09 landed during this task). A Laravel model outside `app/Models` that has no relation edge is not in Models unless the configuration adds an `inherits` selector.
- **Two rules are not enforced.** Feature-sliced's "no imports between slices of one layer" and ddd-contexts' "only through Contracts" need per-slice layers or private selectors. The presets say so in their comments and in the docs.
- **Empty layers.** A preset layer that matches nothing is an `empty-layer` warning; on the M1-01 Laravel fixture, 8 of 11 layers are empty. The proposal's header lists them, and `mapx arch init` warns when most layers are empty. A proposal whose every layer is empty is refused (exit 3) unless `--force` (review of 4e5d5fb).
- **Laravel folders in no layer.** Mail, Notifications, Policies and Enums: dependencies on them are uncovered, which never fails a check.
- **Root inference is a heuristic.** It looks up to three folders deep, and only at parameters that prefix the preset's paths (`%root%…`). When nothing matches, it keeps the preset's default (or `""` when there is no `src/`) and says so in the header.
- **`--from clusters` uses primary memberships** (the directory clusters). A cluster whose name contains glob characters is left out with a note, because the `cluster` selector would read it as a glob.
- **`--from framework` picks the first detected framework** in the order laravel, nestjs, django, and notes the others.
- **The rules count dependencies as findings.** Counts are findings per layer pair (`layerEdges`), not raw edges, as `mapx check` counts them.
- **Root agent files** (`CLAUDE.md`, `AGENTS.md`) still describe `mapx_arch_init` as role-only until they are regenerated with `mapx agents`.

Changelog: `mapx arch init` proposes `.mapx/architecture.jsonc` from MapX roles, clusters, the detected framework or one of eight shipped presets (layered, clean, hexagonal, ddd-contexts, feature-sliced, laravel, nestjs, django), shows today's layer dependencies in its comments, and with `--baseline` writes a baseline so `mapx check` passes on day one; it writes only with `--write` and never over an existing file without `--force`, and `mapx_arch_init` gains the same options (M5-17).
