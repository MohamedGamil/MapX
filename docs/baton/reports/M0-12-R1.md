# M0-12-R1 — Import resolution for Java, Rust, Go, Python, Ruby and C#

Date: 2026-10-31. P0 from the M0-41 legacy audit (I12/I17): none of these languages produced import edges.

## Delivered

- **`src/core/import-resolvers.ts` (new, pure):** one resolver per language, dispatched from `scanner.ts` `resolveImportPath` by source language (`require` references too):
  - **Java / Kotlin / Scala:** a qualified name becomes a path suffix (`com/ex/lib/Bar.java`) under any source root, preferring the same top-level directory. Static members and nested classes fall back one segment; wildcard imports are skipped.
  - **Rust:** `crate::` from the nearest `main.rs`/`lib.rs` directory; `self::` and `super::` (repeatable) from the file's module directory; the longest module prefix resolves to `x.rs` or `x/mod.rs`; `std::` and external crates are external.
  - **Go:** the module path comes from the nearest `go.mod`, read from disk because it is excluded from indexing. A package directory resolves to its first non-test `.go` file.
  - **Python:** relative dots; absolute imports tried from the workspace root down through every ancestor (src layouts); `from pkg import mod` prefers the submodule `pkg/mod.py`, else `pkg/__init__.py`; the standard library is external.
  - **Ruby:** relative to the file, then `lib/`, `app/`, `src/` and the root.
  - **C#:** the namespace resolves to its declaring file via the in-memory symbol index. Files of the current scan aren't in the store yet; the store is a fallback.
- **Queries:**
  - Python `from … import …` captures the whole statement. Before, the module and names were separate refs and relative dots were lost.
  - C# `using` matches `using_directive` without the alias `name` field. The old field pattern never matched, so C# had **no** import references.
  - C# file-scoped namespaces (`namespace X;`) are now symbols.

A test expectation of mine was wrong and was corrected: from `src/net/client.rs`, `super::util` is `net::util`, so `src/util.rs` needs `super::super::util`.

## Limitations

- A Go import edge targets one file of the package; MapX's graph is file-level.
- C# `using static` and Java wildcard imports produce no edge.
- Kotlin/Scala imports use the JVM resolver but are not separately end-to-end tested.

## COMPLETION DISPUTED (review 2026-10-31)

DEFECTIVE: import resolution is quadratic (2,000 Java files: 16.6 s vs 5.9 s without imports) and has precision gaps. Remediation: M0-12-R3, M0-12-R4. See `reviews/REVIEW-2026-10-31-fb75474ba377.md`.
