# M0-11-R2 — Staleness uses the scanner file rules; precise import-only dependants and callee lines

Date: 2026-10-31. Source: review `REVIEW-2026-10-31-fb75474ba377.md` (P1 staleness/scanner rules; P2 import-only dependants, callee homonyms, globals test coverage; surviving mutants "staleness ignoring excludes" and "callee homonym").

## Delivered

- **Shared file rules (`src/core/file-rules.ts`, new).**
  - The scanner's rules moved out of `scanner.ts` unchanged: `DEFAULT_IGNORE`, `shebangLanguage`, `buildMatcher` (still re-exported from `scanner.ts`), `isExcludedDir` (the directory pruning) and `effectiveExcludesFor` (config and CLI excludes plus Laravel's defaults).
  - New `isScannablePath(rel, excludes, includes)` answers "would the scan walk reach this file?": no ignored or dot-prefixed segment, no pruned ancestor directory, and the include/exclude matcher accepts it.
  - The scanner now calls the shared functions, so the two cannot drift apart.
- **Staleness (`src/core/staleness.ts`).**
  - A new untracked file is reported `(new)` only if a scan would index it.
  - The file is attributed to the registered repo with the longest matching path prefix.
  - Filters come from that repo's last scan (`scan_filters:<repo>` meta, which includes CLI `--include` / `--exclude`), falling back to `.mapx/config.json` through `effectiveExcludesFor`.
  - Language check: `getLanguageForFile`, or the shebang for extensionless files.
  - Before, only `settings.excludePatterns` applied, so files outside `includePatterns`, Laravel default excludes, dotfiles and `DEFAULT_IGNORE` directories were flagged forever.
- **Impact (`src/core/impact-analyzer.ts`).**
  - An import-only dependant is listed only when its source mentions the symbol's short name as a whole word. The import edge stores only the module specifier, so this text check is the only signal available.
  - Unreadable files keep the old file-level answer.
- **Callee lines (`store.getSymbolLineInFile`, CLI `callees`, MCP `mapx_callees`).**
  - With one declaration of the name in the file, its line is used.
  - With several, the declaration whose scope matches `Scope::name` wins. Failing that, the single one whose scope is among the names the same caller references in that file (`calleeScopeHints` in `edge-view.ts`): `new B(); b.save()` resolves to `B::save`.
  - If nothing qualifies, the line is null.
  - The `meta.startLine ?? 1` call-site fallback is removed, and a null line prints `@ file`.
  - The review's PHP namespace fix still holds: its regression test passes.
- **Docs:** `docs/cli-reference.md` documents the callee line rule, the import-only rule and a new "Staleness warning" section.

## Limitations

- **Text check for import-only dependants.**
  - It is a whole-word match anywhere in the file, comments included.
  - A default or namespace import that never names the symbol (`import x from './core'` for `export default function direct`) is no longer listed.
  - A file that mentions the name for an unrelated reason is still listed.
- **Hint matching for callee homonyms.** When the caller references no class in the callee file, for example a method called on a parameter typed elsewhere, the line is omitted rather than guessed. The parser still records method calls without a receiver type.
- **No line in the MCP output.** `mapx_callees` with a null line prints `@ file`. No test covers the MCP text separately from the CLI; it uses the same store call and the same helper.
- **Gitignored files.** Staleness still lists untracked files with `git ls-files --exclude-standard`, so gitignored files are never reported, even though the scan walk does not read `.gitignore`.
- **User-defined languages.** Staleness detects languages with the built-in registry only; user-defined languages from config are not consulted, as before.

Changelog: The "graph may be stale" warning now applies the scanner's own file rules, so files a scan never indexes (outside `includePatterns`, Laravel default excludes, dotfiles, `node_modules`/`coverage`) no longer keep it on; `impact` lists import-only dependants only when they import the symbol, and `callees` shows the called method's own line (or none) instead of a same-named method's or the call site's (M0-11-R2).
