## Delivered

- **`src/parsers/generic-wasm-parser.ts`:**
  - A module-level JS/TS declarator or Python assignment whose value is a call, a name, a member (or a Python lambda), seen through parentheses and `as`/`satisfies`/`!`, is a `function`. Literals, objects, arrays, operators and `new` stay `constant`/`variable`. Vue SFCs are excluded (rule 2 of `vue-template.ts`: value declarations own nothing; `tests/vue-template.test.ts` pins it).
  - A local-binding guard (`boundLocally`): in JS/TS (outside `.vue`) and Python, `name()` / `new name()` makes no reference when `name` is a plain parameter or a plain local of an enclosing function or block. Without it the promotion would reopen M0-17-R2's AC1 (`config()` on a parameter) for call-made bindings. The self-scan showed this happening before the guard was added.
  - Function-valued declarators inside a block are skipped (`insideFunctionOrBlock`; a TS namespace body is module level). A class-valued declarator is a `class` symbol.
  - C++: a qualified definition is named by its innermost name at any depth, and a destructor keeps its `~`.
  - Go: a package-qualified embedded type (struct or interface) carries `metadata.goPackage`, the import path matched by alias or by package name (the last path element without `vN`, `.vN`, `go-` or `-go`). It is null when no import matches.
- **`queries/cpp/symbols.scm`:** one `(qualified_identifier) @symbol.name` alternative replaces the four fixed-depth patterns.
- **`src/core/scanner.ts` (companion patch, not in the worktree diff):** `resolveGoQualifiedType`. A `goPackage` reference resolves its import through the Go import resolver. A hit links the same-named type declared in that package's directory; no hit (standard library, third party, unmatched) links nothing. `goPackage` is removed from the stored edge metadata. The patch is 31 changed lines, in the scratchpad as `M0-17-R5-companion.patch`.
- **`docs/adding-languages.md`:** "Constants as call targets" now states the rule the code applies (it claimed that function-valued bindings were the only callable ones), with the Vue exception and the local-binding guard. A new section, "Qualified names", covers C++ and Go.

## Limitations

- "Literal" is approximated by node type. Call, name and member values (and Python lambdas) are callable; everything else is a value. A ternary or `await f()` that returns a function stays a value. A call-made value that is not callable (`const app = express()`, `logger = logging.getLogger()`) is now labelled `function`.
- The local-binding guard covers plain parameters and plain `const`/`let`/`var` (Python assignments) of enclosing functions and blocks. It does not cover destructured bindings, `catch (e)`, loop variables, Python `for`/`with` targets or comprehension variables.
- Go's package name is guessed from the import path when the import has no alias. A package whose name differs from its directory (e.g. `github.com/x/foo-bar` declaring `package foobar`) is unmatched and links nothing.
- The Go fix needs the scanner companion. Without it the parser's `goPackage` metadata is stored on the edge and the old name-only link remains.

## Post-acceptance defect (review 2026-11-02, `reviews/REVIEW-2026-11-02-b2558df592cf.md`)

- **P1, regression, fixed in the review:** the qualifier of an embedded `pkg.Type` was matched only against the package name guessed from the import path. An unaliased `example.com/m/api/v1` (`package v1`) or `internal/db` (`package database`) gave no `extends` edge, where the base commit linked both (common gRPC `v1.Unimplemented…Server`). When no import matches by name, the parser now passes the unaliased imports as candidates, and the scanner links only when exactly one candidate project package declares the type. `tests/legacy-language-accuracy.test.ts` adds both cases and an ambiguous negative (two candidates declaring `Logger` give no edge); it failed before the fix.
