## Delivered

- **`laravel.ts`, `walkRouteFile`:** a group whose routes argument is an array literal mounts each element in order, as `Router::group` does through `Arr::wrap`. This covers `->group([a, b])` and the legacy `Route::group($attributes, [a, b])`.
  - Each element is evaluated like any mount path and gets its own sub-position (`[offset, k]`, as glob loops use). A later file's route therefore overrides an earlier file's route with the same URI.
  - An element that cannot be evaluated records the statement's line as unresolved. The line is recorded once, however many elements fail. The other elements still mount.
  - **Closures (review fix):** a closure in the list (`function`, `fn`, `static function`, `static fn`) is a group body. The file elements still mount, and the group is then walked as before, so the closures' routes get the group's attributes. `static::file('a.php')` is a call, not a closure: it is evaluated like any element, and recorded unresolved when it can't be.
  - **Spreads (review fix):** a literal spread (`...[a, b]`) is flattened in place (`phpListItems`). A spread that is not a literal (`...$files`) is recorded unresolved.
  - `chainAttributes` still passes such a list to `parseGroupAttributes`. That is harmless, because positional entries set no attribute.
- **`laravel-mounts.ts`, `stringAssignments`:**
  - **foreach:** every variable a `foreach (… as …)` head binds is unknown from the head to the end of its function. This includes the key, the value, `[$a, $b]` destructuring and `&$v`. A value the variable held before the loop is never used.
  - **Conditions and loops:** an assignment under a condition or loop holds until that block ends, then the variable is unknown. The end is the `;` of a brace-less `if (…) $x = …;`, or the closing brace of the innermost enclosing if / elseif / else / for / foreach / while / switch block. Inside the block the value is still known.
  - **Loop bodies (review fix):** a variable or `$this->` property assigned anywhere in the body of a for, foreach, while or do loop is unknown from the start of the body. The next pass sees the later assignment, so `while (…) { mount($w); $w = 'w1'; }` gives `{dynamic}`, not `w0`.
  - **Not a condition:** `if (! $this->app->routesAreCached())` does not count as a condition, as in the walker (`opensConditionalBlock`). Nor does a `do` body, which always runs once (review fix). An assignment in it holds after the loop, while inside the body the loop-body rule applies.
  - **Refactor:** `conditionalAt` became `conditionalEnd`, which also returns where the block ends. The compound-assignment rule from M1-03-R2 uses it unchanged (`!== null`).
- **Fixture (`tests/fixtures/laravel-routes`):** all rows are new and synthetic. No existing row was relabelled.

## Limitations

- A `foreach` over a literal array is not expanded into one mount per value. The prefix is `{dynamic}`, and the file is mounted once, so fixture label L150 is a placeholder. Expanding the loop would need the walker to evaluate one statement once per element. That means re-evaluating the chain attributes and the mount path with the loop variable bound, and ordering nested loops and lists. It was not cheap enough for this remediation. Inline routes in such a loop (`Route::get("$l/home")`) have the same limitation.
- An assignment inside a loop or condition is unknown after the block even when every branch assigns the same value. A `do … while (false)` body is treated as a loop, so a value assigned after a mount in it is `{dynamic}` at that mount. Both are conservative.
- PHP's alternative syntax (`if (…): … endif;`, `while (…): … endwhile;`) and assignments in a `for (…; …; …)` head with a brace-less body are not recognised. This predates the task.
- A keyed array as the only argument of `->group([...])` is read as a list of files, as `Arr::wrap` does. `Route::group(['prefix' => 'x'])` with no routes argument is a PHP error in Laravel. MapX evaluates its values as paths, and a non-`.php` value mounts nothing.
- In a list that mixes closures and files, the file mounts are ordered at the statement and the closure routes at their own offsets. When a closure's route and a later file's route share a URI, the override can come out in the wrong order.

## Independent review (2026-11-02) and fixes

The review of the first commit found no P0, one P1 and five P2s, all reproduced with cases c1–c9 in the coordinator's scratchpad. Each item and how it was handled:

- **P1, fixed.** A list holding a closure, or a `static::` call (matched by `/^(…|static\b)/`), was walked as a group. Its files were neither mounted nor recorded unresolved, so they read as unreachable.
  - Closures are now group bodies and files still mount; `static::` is a call.
  - c9 now gives `/mix/inline` and `/mix/t`, and c8 gives `/mix/t [web] reachable`.
  - c7 gives `/st/t` reachable and `/s` `unknown`, listed in `unresolvedMounts`.
  - Covered by tests and fixture rows L153 and L154.
- **P2, fixed.** An assignment later in a loop body, which the next pass sees, was ignored.
  - The loop-body rule above fixes it. c2 now gives `{dynamic}` for r2 (while), r3 (for) and r4 (foreach).
  - Covered by tests and fixture row L156.
- **P2, fixed.** Spread elements were not flattened. Literal spreads are now flattened: c1 gives `/sp/s1` and `/sp/s2` reachable. Non-literal spreads stay unresolved. Covered by a test and fixture row L155.
- **P2, documented.** L150 is shaped by the implementation. Literal loops were not expanded (see Limitations). The placeholder is noted here and in the fixture comments.
- **P2, fixed.** The `/{dynamic}/k` e2e case did not discriminate. `$key = 'k0'` now precedes the loop, and M6 now also fails that test.
- **P2, fixed.** A `do` body was treated as conditional. It no longer is: `$d = 'd0'; do { $d = 'd1'; } while (…);` gives `d1` after the loop.
