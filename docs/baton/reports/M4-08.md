# M4-08 — Strict flag handling in score-routes and score-http

Date: 2026-11-01. Base: `develop@1391d31`. Owner: claude. Iteration: `docs/baton/iterations/M4-08.md`.

## Before

`score-http.ts tests/fixtures/vue-http` with each of these flags:

| Flags | Exit |
| --- | --- |
| `--min-recal 1` | 0, threshold ignored |
| `--min-recall=1` | 0, ignored |
| `--min-recall abc` | 0, `NaN` passes every comparison |
| `--min-recall 1.5` | 1, reported as a missed threshold, not a usage error |

`score-routes.ts` parsed the same way.

## Delivered

- **`scripts/eval/args.ts`: `parseScorerArgs(args, { booleans, thresholds, requiredFile })`.** It takes one fixture plus known flags, each at most once. Thresholds are `ratio` (in [0, 1]) or `count` (an integer ≥ 0), and flags are looked up as own keys only. It throws, naming the flag, on:
  - an unknown option, or the `--name=value` form;
  - a repeat;
  - a missing value or a value that is not a number;
  - a value out of range;
  - an extra positional argument, a missing fixture, or a fixture without `labels.json`.
- **`parseRoutesArgs` and `parseHttpArgs`.** Each scorer exports one, and `main` calls it before reading labels or scanning, exiting 2 with the message and the usage line. The threshold comparisons are unchanged.
- **Tests.** Each fixture test file gets three tests: valid command lines, rejected ones, and a spawned CLI that exits 2 within 5 s. The HTTP CLI test also passes a missing fixture together with a bad flag, so a version that read the labels or scanned first would fail it.

## Independent review

One fresh agent reviewed the change, working in its own copy. It found no P0 or P1. It compared old and new CLIs on the documented command lines, with the fixture before and after the flags, and the exit codes matched. `1e0`, `0x1` and `' 1'` are still accepted as 1, as `Number()` did before.

Its P2s:
1. **Inherited property names as flags.** `--constructor` and `--toString` were reported as "given twice" instead of unknown. Fixed with `Object.hasOwn`; tested and mutation-checked.
2. **A fixture path starting with `-` is now rejected**, and so is the `--` separator. Kept: this matches `score-edges.ts`, and `./-fx` works.
3. **The HTTP "before scanning" test leaned on timing.** It now also runs a missing fixture with a bad flag.

It also reported an older issue outside this task: a missing fixture crashed with a stack trace and exit 1. Fixed here: the fixture must hold `labels.json`, otherwise the scorer exits 2 with `<fixture>: no labels.json`.
