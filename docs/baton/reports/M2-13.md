# M2-13 report: calls inside a one-line PHP class are indexed

Found smoke-testing v0.3.9. On one line, `<?php class User { public function name() { return $this->id(); } private function id() { return 1; } }` gave no callee for User::name. Planned in `iterations/M2-13.md`. This commit sits on M2-12 (`4527279`).

## Cause and reproduction

The PHP parser emits its member, scoped, instantiation and function-call references with `sourceSymbol: null`. The scanner then attributes each one by line (`innermostByLine`). On one line, the class and its methods have equal spans, so the first symbol wins: the class.

`tests/php-one-line.test.ts` was written first and run against the unchanged parser. The PHP cases failed:
- `User.php` gave `User -> php/User.php#id`, not `User::name -> …`.
- A second line-based rule appeared too. `currentNamespace` is read with `/^\s*namespace …/m`, which misses `<?php namespace App;` on one line. In such a file every class and function name resolved in the global namespace, so `helper()` and `new Order()` linked nothing.

JS, TS and Java passed before the fix. So did Python's one-line methods and module-level lambda, and JS one-line arrow functions. The generic parser's `oneLineSource` (M5-03-R2) already sources them from the syntax tree. Python cannot put two methods on one line, and a class-attribute lambda is not a symbol, so it is attributed to the class on any layout.

## Delivered (`src/parsers/languages/php.ts`)

- **Source by position** (`sourceOf`). Each declaration node maps to its symbol. A reference takes its source from its nearest enclosing declaration if that declaration is on one line: a method or function (`User::name`, `top`), or a class for `class B extends A` beside A. The label matches the scanner's. A reference in no declaration (a template's `<?php echo tplf(); ?>`) is marked `fileLevel`, and the scanner then gives it no source symbol rather than a declaration on its line. This is the PHP equivalent of `oneLineSource`. It applies to the main reference loop and to function calls. Multi-line declarations keep the line rule, which already picks them.
- **Namespace by position** (`namespaceAt`). A name resolves in the namespace in force where it is written: its enclosing `namespace X { … }` block, else the last `namespace X;` statement before it. This holds on one line or several, for every name the parser resolves. The file-wide line-start regex is gone.
- `EXTRACTOR_VERSION` goes 16 → 17, with a comment line.

## An existing expectation that encoded the bug

`tests/binary-workers.test.ts` (`EXPECTED_PROTOTYPE_CALLS`) expected source `Runner` for the three calls in `app/Runner.php`:

`class Runner { public function run(Text $t) { return $t->toString() . $t->valueOf() . $t->constructor(); } }`

This is a one-line class, and the calls sit inside `run`, so `Runner::run` is the true source. The multi-line form gives the same. The expectation now says `Runner::run`, with a comment; the test is about worker threads, not attribution. No arch fixture has a one-line PHP class: the arch edges are identical with and without M2-13 (`scratchpad/M2-arch`, `diff` exit 0), and `score-arch` is unchanged.

## Limitations

- `self::make()` / `static::` calls give no edge in PHP on any layout. This was the case before, and is not this task.
- External-reference rows (`codeSymbol`, M5-19) still take their source by line.
- The file row still records one namespace (the last block's). Symbols carry their own namespace since the re-review, and resolution uses theirs.
- `use` imports are file-wide, while PHP scopes them to their namespace block.

Changelog: References inside a PHP class, method or function written on one line now come from it, a template's top-level calls come from the file, and PHP names resolve in the namespace block or statement where they are written (M2-13).
