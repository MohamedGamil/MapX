# M3-01 — Vue SFC fixture set (2.7 and 3.x)

Date: 2026-10-31. Base: `develop@3668a63`. Records the baseline; no parser or detector change.

## Delivered

- **`tests/fixtures/vue-sfc/`** (54 files, all code invented):
  - `vue2/` is a Vue 2.7 helpdesk app (Vuex 3, Vue Router 3, Pinia with `PiniaVuePlugin`);
  - `vue3/` is a Vue 3.4 shop app (Vuex 4, Vue Router 4, Pinia);
  - each app has its own `package.json`.
  - Styles: Options API, Composition API `setup()` and `<script setup>` (runtime and type-based macros, including Vue 2.7 `lang="ts"`).
- **`expected.json`:** 127 labels over 15 patterns, every pattern in both versions:
  - 100 positive edges;
  - 11 component-symbol labels (5 carry `props` / `emits` metadata);
  - 16 negatives (`"expect": "absent"`).

  The traps are:
  - same-named members in other components and stores (`save`, `checkout`, `clear`, `touch`);
  - a registered component used only inside an HTML comment;
  - a mixin that defines the same member but is not mixed in;
  - `FETCH_ALL` defined in two Vuex namespaces;
  - a route whose name matches a different component (`Dashboard` renders `HomeView`);
  - a `<router-link>` target, which is navigation and not render;
  - a self-call that is really `formatter.format()` or `cart.checkout()`.
- **Edge contract:** in `docs/baton/iterations/M3-01.md`, which defines:
  - the component symbol (one `class` symbol per `.vue`, named after the file, with `props` / `emits` metadata);
  - that the template, top-level `<script setup>` code and the `setup()` body belong to the component symbol;
  - bare member names as `target_symbol` (`save`, `FETCH_ALL`, `checkout`), as the store holds them today;
  - `render` edges to the child's component symbol;
  - `this.x()` precedence (own member, then mixin, then map helper);
  - a new `navigate` edge type for router navigation.
- **`scripts/eval/score-edges.ts`:** a generic edge scorer modelled on `score-routes.ts` / `score-http.ts`.
  - It copies each `roots` folder to a temp dir, runs the real `mapx init` + `scan`, reads `.mapx/mapx.db` and prefixes paths with the root.
  - Matching is exact on `edge_type`, `source_symbol` and `target_symbol`; files match by path.
  - It reports per pattern and per version: found/labelled, recall, negatives and false positives.
  - It reports totals: recall, precision over distinct `call` / `render` / `navigate` edges between fixture files, false positives and the unlabelled-edge list.
  - Flags: `--json`, `--min-recall R|pattern=R`, `--max-fp N|pattern=N`, `--min-precision P`.
  - Unknown, repeated, out-of-range or empty flag values exit 2. A missed threshold exits 1.
- **`tests/vue-sfc.test.ts` (14 tests):**
  - label well-formedness: ≥30 positive edges, ≥3 negatives, every pattern in both versions, files exist, symbols are component names or identifiers present in the file, valid `expect`, no duplicate or contradictory labels, render/navigate targets are component symbols;
  - 8 scorer unit tests: exact edge-type and symbol matching, negatives as false positives, unscored types ignored, de-duplication, symbol metadata, per-version counts, flag validation and thresholds;
  - a real-scan floor test against `FLOORS`: `found` per pattern, `falsePositives` per pattern, and `minPrecision`. Each of M3-02 … M3-06 raises the floors for its own patterns. `labelledCount(pattern)` is the target.

## Independent review

A fresh agent got the acceptance criteria and the diff. It traced every label and confirmed that all positives and negatives are correct and that no fixture syntax is invalid for its Vue version. Its findings and what was done:

- **P0: the yardstick ran with Vue detection off.**
  - The fixture root had no `package.json`. `hasPackageJsonDependency` only reads the root one when sub-folder `package.json` files are not in the scanned list, so the vue-router detector and its ignore list never ran.
  - **Fixed:** `expected.json` gains `roots: ["vue2", "vue3"]`, and the scorer scans each app as its own project. Re-baselined: precision went from 70.8% to 62.5%, composable from 4 to 2.
  - The ignore list drops `setup`, so the contract now gives the `setup()` body to the component symbol, as `<script setup>`. The labels v3-038, v3-053 and v2-043 were changed.
- **P1: `route` is the wrong type for navigation.** Detect-phase `deleteFrameworkEdgesForRepo` wipes `route` edges, and the CLI and MCP read them as backend endpoints.
  - **Fixed:** the contract uses a new `navigate` type, scored instead of `route`. The detector's own `route` edges are unscored.
- **P1: threshold flags could pass silently.** This covered `--x=v`, typos, empty values, an unchecked per-pattern precision, and last-wins repeats.
  - **Fixed** with `parseArgs` / `parseThresholds` validation and unit tests.
  - `score-routes.ts` / `score-http.ts` share the pattern and were not changed here.
- **P1: the `emit()` labels inflated `script-setup-macro`.**
  - **Fixed:** they moved to the new pattern `script-setup-call`, and rule 4 now covers calls to `<script setup>` function constants. `script-setup-macro` now measures only the M3-04 symbol metadata (0/5).
- **P1: contract gaps.** These were script-side composable returns (`prefs.persist` reached only through property assignment), the `this.x()` precedence, and whether `components` / `mixins` produce edges.
  - **Fixed:** rules 2, 4 and 6 now state them. `usePreferences` returns `{ prefs, persist }`.
- **P2, fixed:**
  - the comment-tag negatives now name components that are registered in that parent;
  - `v-on:` and a kebab-case tag were added to vue3;
  - labels with an invalid `expect`, duplicate labels, and labels with neither edge nor symbol are now rejected or reported;
  - the floor comments note which baseline hits come from unique-name luck.
- **P2, not done:**
  - no fixture cases for `mapState`, `mapMutations`, `router.replace`, a component `commit('ns/X')` or `defineExpose`. The contract states these forms; a later task can add cases.

## Limitations and follow-ups (MapX defects found, not fixed here)

- **Sub-folder `package.json` ignored for detection.** A `package.json` in a sub-folder that is not its own registered repo does not enable framework detection: `hasPackageJsonDependency` falls back to the root file. Monorepo-style layouts lose Vue detection.
- **Router components resolved to the router file.** The vue-router detector resolves statically imported route components to the router file itself (`vue2/src/router/index.js#- -route-> vue2/src/router/index.js#HomeView`). Only lazy `import()` components point at the `.vue` file.
- **`setup` on the ignore list.** `src/parsers/ignored-symbols.ts` puts `setup` (and `computed`, `watch`) on the vue-router ignore list. Today, references inside `setup()` lose their owner; the contract's component-symbol attribution (M3-04) avoids depending on it.
