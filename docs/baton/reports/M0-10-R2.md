## Delivered

- **`src/core/workspace-manager.ts`:** `canonicalPath()` (`realpathSync`, falling back to `resolve`) and `WorkspaceManager.repoKey(dir, path)`.
- **`src/core/workspace-summary.ts`:**
  - `RepoType` gains `folder`.
  - `repoType` compares by `repoKey`, and types a registered directory without its own `.git` as `folder`.
  - `summarizeRepos` reports a HEAD only for the primary repo and real checkouts (`hasOwnGit`).
  - New `workspaceExport()` (shared by `export --all` and `mapx_export {all}`). It demotes each repo's export headings two levels under `## <repo>`.
  - New `crossRepoDependencies()` (shared by `deps --cross-repo` and `mapx_dependencies {crossRepo}`).
- **`src/core/config.ts`:** `addRepo` refuses a path whose canonical folder is already registered, and returns whether it added the repo.
- **`src/cli.ts`:**
  - Every registered-path comparison in init and in `workspaces list/discover/sync/add` uses `repoKey`.
  - init does not offer a `.code-workspace` folder that is the same folder as an offered submodule.
  - `add` reports a symlinked duplicate as already registered.
  - `sync` without a TTY skips the nested-repo and monorepo prompts with a hint, and registers the rest; it scans only the repos it actually added.
  - `status --all` shows `unscanned`.
- **`src/mcp.ts`:**
  - `mapx_workspaces` returns `root`, and `headSha` instead of `headCommit`; its discoveries are compared by `repoKey`.
  - `mapx_export` takes `all`, and `mapx_dependencies` takes `crossRepo`.
- **Docs:** `docs/cli-reference.md` (Changed column, `folder` type, symlink de-dup, non-TTY sync, `export --all` nesting) and `docs/mcp-integration.md` (`root`, `headSha`, `folder`, `all`, `crossRepo`).
- **Mocked suites:** `tests/cli.test.ts`, `tests/cli-coverage.test.ts` and `tests/mcp.test.ts` gained `repoKey`/`canonicalPath` stubs in their `workspace-manager` mocks.

## Limitations

- **A primary repo inside an enclosing checkout reports that checkout's HEAD.** This is deliberate: it is the checkout its incremental scans use. Only non-primary folders need their own `.git`.
- **`Config.addRepo`'s canonical de-dup is defence in depth.** `sync`, `add` and init already de-duplicate by `repoKey` before calling it, so no test kills a mutant of `addRepo` alone.
- **Existing duplicate entries are not cleaned up.** Configs that already contain a symlinked duplicate keep it.
- **The scanner's nested-repo skip still compares with `resolve`** (`registeredRoots` in `scanner.ts`).
- **`mapx_workspaces.path` stays relative.** F18's absolute `path`, `relativePath`, `isRegistered` and `isInitialised` were not added (scope; see Follow-up in the iteration).
- **`headCommit` is gone.** It was renamed to `headSha`, with no alias, because M0-10-R1 introduced it in this unreleased cycle.

Changelog: The workspace table, `status --all` and `mapx_workspaces` now show no HEAD and the type `folder` for a registered directory without its own checkout, mark never-scanned repos `unscanned`, and no longer register a symlink to a registered repo twice. `export --all` nests each repo's sections, `workspaces sync` without a TTY still registers its discoveries, and MCP gains `root`, `headSha`, `mapx_export {all}` and `mapx_dependencies {crossRepo}` (M0-10-R2).
