# M2-06-R3 — HTTP edges into another repo record their target repo

Found while building the M4-21 multi-repo fixture.

## Defect

`pairHttpCalls` (`src/core/scanner.ts`) builds one `http` edge per paired call, from the calling file to the route handler. It stored every one with `target_repo` null, though it already maps each file to its repo. So:
- a frontend repo's calls into a backend repo were not cross-repo edges;
- `mapx status --all` (cross-repo edge counts), `deps --cross-repo` and the dashboard missed them.

On the fixture, the three paired calls from `web/src/api/orders.ts` to `api/app/Http/Controllers/OrderController.php` all had `target_repo` null.

## Fix

The edge's `targetRepo` is the handler file's repo when that differs from the caller's.
