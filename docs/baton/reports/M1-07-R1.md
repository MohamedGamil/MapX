# M1-07-R1 — Laravel reachability is unknown, not false, for unevaluated mounts; registry keeps both duplicates

Date: 2026-10-31. Remediation for the review `reviews/REVIEW-2026-10-31-fb75474ba377.md`. It covers M1-07 (DEFECTIVE), M1-04 (the mount forms), M1-08 (a test not sensitive to mutation) and M1-09 (FALSELY COMPLETE on attribute-route lines). Built on develop aa0c60a (M1-03-R1 integrated).

## Delivered

- **More mount forms are evaluated** (`laravel-mounts.ts`, `laravel.ts`):
  - `phpString` understands `DIRECTORY_SEPARATOR`, `$this->prop` (read from the class's string property declarations) and nwidart's `module_path(name, path)`, which resolves to `<root>/Modules/<name>/<path>`.
  - `foreach (glob(<pattern>) as $f)` followed by `require $f;`, braced or not, is expanded on disk (`expandGlob`, PHP glob order). Each file becomes its own mount; a new `MountRequest.sub` keeps their load order.
  - `withRouting(...)` in `bootstrap/app.php` is read through the masking lexer, so a commented-out call or argument mounts nothing.
  - Its `then:` closure (and `using:`, which replaces `web:`/`api:`) is walked like a route file, and its mounts follow the `web:`/`api:` entries, as in Laravel.
- **Unknown reachability.** Every mount that can't be evaluated is recorded per app root (`wctx.unresolved`, `file:line`). This covers provider walks, `then:` closures, mounted files and `withRouting` arguments.
  - While any exist, a route file that nothing visibly mounts gets `metadata.reachability = 'unknown'`, with `unresolvedMounts` listing up to 5, instead of `reachable: false`.
  - HTTP pairing (`reachable !== false`) therefore keeps these routes.
  - `finalizeRoutes` leaves them out of overrides, because their load order is unknown.
- **Route view and CLI.** `toRouteView` adds `reachability` (`reachable` / `unreachable` / `unknown`), and `domain` when there is one. `reachable` stays a boolean that is false only when unreachability is proven.
  - The `mapx routes` text table flags `[reachability unknown]`.
  - MCP `mapx_routes` uses the same view.
  - `docs/cli-reference.md` and `docs/mcp-integration.md` are updated.
- **Registry keeps both duplicates.** The `RouteRegistry.addRoute` dedup key now includes the declaring file, line and load order. An overridden route and its winner, even with the same handler, both reach `routes.json`.
- **Override key.** It now uses the exact URI (`{id}` and `{slug}` are different routes in Laravel's collection) and the domain. Domain comes from `Route::domain()`, `'domain' =>` in group arrays, and frames inherited through mounts.
- **Conditionals:**
  - a brace-less `if (...) require …;` or `if (...) Route::…;` is conditional;
  - `if (! $this->app->routesAreCached())` (and `app()->` / `App::`) is not, because Laravel loads the same routes from its cache otherwise.
- **Attribute routes** (`#[Get]` and the others) get `line` and `metadata.line`: the attribute's own line.
- **Route edges** keep `dynamic`, `domain`, `mountedBy` and `reachability: 'unknown'`.
- **Scorer** (`score-routes.ts`):
  - An `overridden` or `unreachable` label is credited only when its route is reported with the flag, and with the label's handler when one is given. An absent route is now a miss.
  - A new `absent` expectation means the route must not be reported at all. It is used for route code inside comments, strings and heredocs, and for a file under a prefix that never mounts it.

## Limitations

- Unknown reachability is per app root. One unevaluable mount makes every unmounted route file in that app unknown, because which file it loads can't be known.
- nwidart's modules directory is the default `Modules`; `config/modules.php` is not read. `$this->prop` is resolved from any `$prop = '…';` string declaration earlier in the file, not by scope.
- `expandGlob` supports `*`, `?` and `[…]`, not `GLOB_BRACE` `{a,b}`. Other loops, such as `File::allFiles()` or `array_map(…, glob(…))`, are not expanded: they count as unresolved mounts, which gives unknown rather than false.
- Routes declared directly inside the `then:` closure, and `withRouting(health: …)`, are not emitted.
- Two routes with different parameter names (`items/{id}`, `items/{slug}`) are both reported live. Laravel matches the first one registered, so the second is shadowed in practice; shadowing is not modelled.
- Because load order is now part of the registry identity, a file mounted twice under the same group yields two identical routes. The earlier one is marked overridden by the later one, which matches Laravel's last-registration-wins behaviour but shows up as two entries.

Changelog: Laravel routes behind mounts MapX cannot evaluate are now reported with unknown reachability instead of unreachable (and still pair with HTTP calls), `module_path()`, `withRouting(then:)`, glob-loop and `DIRECTORY_SEPARATOR` mounts are followed, overridden routes and their winners both appear in `routes.json`, and attribute routes carry their line (M1-07-R1).
