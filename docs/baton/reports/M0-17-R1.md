# M0-17-R1 — Language extraction accuracy (F33)

Date: 2026-10-31. From the M0-41 legacy audit (I17, FALSELY COMPLETE). Every audited input was reproduced with a parser probe before fixing it.

| Language | Before (probe) | After | Fix |
| --- | --- | --- | --- |
| Ruby | `extends:< Base`; `extends:Greet` and `call:include` for `include Greet` | `extends:Base`, `implements:Greet`, no call | `queries/ruby/references.scm`: superclass constant, include → implements, class-body keywords excluded from calls (`#not-match?`) |
| C++ | `function:inside`, `function:run`, a symbol named by the template's whole source | `method:Foo::inside`, `method:Foo::run`, `function:maxOf` | `class_specifier` added to method promotion; `Foo::run` scoped from its `qualified_identifier`; template_declaration patterns removed (the inner definitions already match) |
| C# | `extends:IRun` | `extends:Base`, `implements:IRun` (structs implement; interfaces extend) | `csharpBaseType`: only the first base-list entry of a class can be a class; `I[A-Z]` names are interfaces |
| Dart | no call refs | `call:helper`, `call:run` | queries for `identifier . selector(argument_part)` (Dart has no call node) |
| Python | `call:Bar`; 4 kinds | `instantiation:Bar`; `property:Bar::size`; `variable:items`; 6 kinds with a plain method | CapWords call → instantiation; `@property`/`@cached_property` → kind property; module-level assignments → variable |
| Go | no embedding refs | `extends:Reader`, `extends:Writer`, `extends:Base` (struct), none for `int \| float64` | single-type `type_elem` and unnamed `field_declaration` patterns |
| Kotlin | `class:Shape`, `class:Color` | `interface:Shape`, `enum:Color` | kind from the `interface` / `enum` keyword of `class_declaration` |
| JavaScript | 3 kinds | 6 kinds: constant, variable, property added (`const`/`let`/`var` at top level, class fields) | new patterns; function-valued declarators stay functions. The function patterns now sit on the declarator, so the name binds to the same node whichever pattern claims it, and a function-valued declarator is skipped as constant without being marked seen |
| Rust | `struct:Point` plus one `class:Point` per impl | `struct:Point` only; methods still scoped (`impl<T> W<T>` → `W`) | impl_item pattern removed; generics stripped from impl scope |
| Swift | `method:Box::init(size: Int) {}` | `method:Box::init` | name from the anonymous `init` token |
| Scala | `import:import com.ex.lib.{Bar, Baz}` | `import:com.ex.lib.Bar`, `import:com.ex.lib.Baz`, `import:com.ex._` | `scalaImportTargets` expands the import node |

## Limitations

- C# extends/implements uses the `I`-prefix convention and C#'s "base class first" rule. A first entry `Foo` that is really an interface without the prefix is recorded as extends.
- Python instantiation uses the CapWords convention, so a function named in CapWords is recorded as an instantiation.
- Dart `Widget()` without `new` is a call, not an instantiation.
- TypeScript `const`/`let` bindings were not changed (out of scope; the criterion names JS).
