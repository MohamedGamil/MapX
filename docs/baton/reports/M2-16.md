# M2-16 report: PHP `self::m()`, `static::m()` and `parent::m()` link the enclosing class's method

Found by M2-13: PHP `self::m()` gave no edge on any layout. Planned in `iterations/M2-16.md`. Dispatch base: develop `cf39a4b`.

## Cause and reproduction

A synthetic workspace (`scratchpad/M2-16/probe`) was scanned with the real CLI on the unchanged code. It held `User::name` calling `self::id()` and `static::tag()`, a one-line `OneLine`, `Child extends Base` calling `parent::boot()`, `self::base()` and `static::base()`, and a one-line `Child2`. The only edges were the two `extends`. No call edge existed for any of them, on one line or several.

The cause is the reference query, not the resolver. `queries/php/references.scm` captured a scoped call only when its scope is a `name` or `qualified_name`. In the PHP grammar `self`, `static` and `parent` are a `relative_scope` node, so no reference was extracted at all.

`tests/php-self-calls.test.ts` was written first and run against the unchanged code: 13 of its 15 first-draft tests failed (the two that passed were the "nothing links" guards, which pass trivially when there is no edge).

## Delivered

- **Query** (`queries/php/references.scm`): a pattern for a `scoped_call_expression` whose scope is a `relative_scope` and whose name is a plain `name` (`ref.target_self_call`). `self::K`, `self::$x`, `self::class`, `self::$f()` and `self::{'x'}()` do not match.
- **Parser** (`php.ts`): for each capture, the class around the call is read from the syntax tree. It looks through closures and arrow functions (they bind `self` to their class). An anonymous class between the call and a named class, or no class at all, gives no reference (M2-22 owns anonymous classes). `self::` and `static::` record the enclosing class's name. `parent::` records the class the `extends` names, resolved as every class name is (`use`, aliases, the namespace in force), and nothing when the class extends nothing or is a trait or enum. The reference is a verified `call` to the method name, with `metadata.newClass` and `metadata.selfCall`.
- **Scanner** (`scanner.ts`): the M2-12 walk of `resolveNewReceiverCall` is reused: the class, its traits, then its parent, depth first. For `selfCall`:
  - a method the chain does not declare links **nothing**, closed chain or open. There is no inferred name lookup, which `(new X())->m()` keeps: `static::query()` or `parent::boot()` of a class extending `Illuminate\Database\Eloquent\Model` links no project method or function, even when the project declares `App\Support\Model` with the same methods;
  - such a call is no external-reference row either (a bare method name is not a package class);
  - the edge is verified, and `newClass` and `selfCall` are not stored in the edge metadata.
- `EXTRACTOR_VERSION` goes 29 to 30 for the references, and to 31 after the review (a PHP class now stores `traitRules`), with comment lines.
- **Trait conflict resolution (review P2-2).** The parser records `use A, B { B::x insteadof A; A::x as ax; }` as `traitRules` in the class metadata. The walk tries the `insteadof` winner first, and looks an alias up as the aliased trait method (in the trait written, else in `use` order) before the parent. A visibility-only rule (`x as protected`) is ignored.
- **Member map (review P2-1).** `resolveNewReceiverCall` read a class's members by scanning every same-named method of the workspace for each reference and walk level. It now reads a per-(file, owner) map built once per resolution phase from the symbol index (`classMembers`, invalidated with the index). It speeds M2-12's `new self` walk too.
- **`static::m()` and overrides.** `static::m()` links the method the enclosing class's chain declares (late static binding is not followed). A subclass that overrides `m` is not linked, though the call may run it. Test: `P::m -> P#hook`, with `Q extends P` overriding `hook`.

## Limitations and found, not fixed

- **`Foo::m()` and `\Ns\Foo::m()`** (an explicit class on the left) still extract a reference naming the class `Foo`, not the method `m`, so `Base::boot()` links the class and not `Base::boot`. Not this task; worth a follow-up (it is the same shape of gap for the explicit-class form).
- **Sync gaining an edge:** a method added to a parent does not link an unchanged child until the child is re-parsed, in a workspace that is no git repository or whose files are committed. Reproduced again after the review (`scratchpad/M2-16/p8nogit`, `p8git`, `p9`: after `sync`, `Kid::k` has no `newm` edge; `scan --force` gives it); the same holds for `(new Mid())->newm()` of M2-12. In a repository with no commit (the reviewer's `s7`) every file counts as changed and sync re-parses all of them, so it matches `scan --force` there. Removal works (tested).
- **Interfaces:** `static::make()` declared only by an interface the class implements gives no edge. The walk takes traits, then the parent; interfaces are not walked, as at HEAD (review P2-3).
- **Trait aliases:** an unqualified alias of a method several traits declare (`y as zz`) takes the first trait in `use` order; PHP rejects that as ambiguous, so the case does not occur in valid code. Trait `abstract` / `static` modifiers and aliases in traits that use other traits resolve through the same walk.
- **Two classes of one simple name in one file, in different namespaces:** a method's scope carries no namespace, so the walk takes the first class. Rare; not observable when the method names differ.
- **A trait's `self::m()`** where only the using class declares `m`: no edge (the trait is walked alone). Likewise `static::m()` implemented by a subclass.
- **`Closure::bind` and `Closure::fromCallable`** rebinding `self` is not modelled; a closure binds `self` to its lexical class.
- **Existing inferred edge, not this task:** a member call by name such as `->where('a', 1)` on the result of `static::query()` links a project method `where` by name (inferred), as any `->m()` does.
