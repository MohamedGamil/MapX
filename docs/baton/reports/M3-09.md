# M3-09 — JS/TS import aliases from tsconfig/jsconfig paths and Vite/webpack alias config

Date: 2026-10-31. Base: `develop@e5a49ff` (rebased onto M3-06 during the lane). Owner: lane-vue-setup. Iteration: `docs/baton/iterations/M3-09.md`.

## Delivered

- **`src/core/js-aliases.ts` (new).** `jsAliasTargets(target, sourcePath, ctx)` returns the workspace paths an aliased specifier may name. Extension probing is left to the caller.
  - **tsconfig.json / jsconfig.json.** The files are read as JSON with comments and trailing commas.
    - `compilerOptions.paths` resolve relative to `baseUrl`, else relative to the config that declares them.
    - Relative `extends` is followed, as a string or an array. A child's `paths` replace the parent's; `baseUrl` is inherited.
    - When the root config has no `paths`, the configs it lists in `references` are read (create-vue's `tsconfig.app.json`).
  - **vite.config.\*, vue.config.\*, webpack.config.\*, webpack.mix.js.** These are read statically: comment and string masking, then bracket matching. Nothing is executed. The forms read are:
    - `alias: { k: v }` and `alias: [{ find: 'k', replacement: v }]`;
    - `mix.alias({ … })`;
    - `config.resolve.alias.set('k', v)`.

    `v` must be one of: a string (a leading `/` is relative to the config's folder, Laravel's `'@': '/resources/js'`), `path.resolve` / `path.join(__dirname | process.cwd(), '…')`, or `fileURLToPath(new URL('…', import.meta.url))`. Any other value is skipped.
  - **Order.** The lookup walks up from the importing file's folder. The first folder whose configs declare a matching alias decides. Within one folder, compiler `paths` come before bundler aliases. Matching follows TypeScript: an exact pattern wins, then the longest wildcard prefix. A bundler key `k` covers `k` and `k/…`; `k$` covers `k` only.
  - **Fallback.** Without a matching alias, `@/x` resolves to `<nearest package.json folder>/src/x`, then `src/x` (the old behaviour). Relative specifiers and scoped packages (`@vue/…`) never match an alias.
  - Results are cached per file set and folder, so each phase reads each config once.
- **`src/core/scanner.ts`.**
  - `resolveImportPath` now tries the alias targets for every JS/TS/Vue/Svelte source, then the specifier itself. The old rule, `.vue` sources only, `@/` → `src/`, is gone.
  - Extension probing moved, unchanged, into `probeModule()`.
  - Import edges, M3-02 render hints, M3-03 mixins, M3-04 composables (`moduleMember`) and M3-06 route components all inherit the change.
- **M3-04's path-suffix fallback (`resolveAliasBySuffix`) is removed.** It could produce wrong edges:
  - It matched any module in the repository whose path ended with the alias path, even when the configured alias points somewhere else.
  - Example: two apps in one repo, each with `@/utils/format`, where one app's alias target lacks the file. The fallback would have linked it to the other app's file.
  - Now that configs are read, an alias that does not resolve means the file is not where the project says, and no edge is the right answer.
  - The M3-04 Laravel end-to-end test has changed to match. Its app now lives in `laravel/` with the `vite.config.js` that a working Laravel project needs for `@/` imports. Without that config, `@/` means `src/` by design.
- **Docs:** the Vue row in `README.md`, and the Imports bullet in `docs/getting-started.md`. The CLI and MCP surfaces are unchanged.

`src/core/import-resolvers.ts` (listed in `affectedFiles`) is unchanged. JS/TS imports are path-style and resolved in the scanner, so the new logic sits in its own module next to it.

## Limitations

- **Walk-up rule.** The lookup keeps walking upwards when a folder's configs declare no matching alias. TypeScript instead stops at the nearest tsconfig. The difference matters only when a nested project relies on a parent folder's alias.
- **Not read:**
  - `extends` from npm packages (`@vue/tsconfig/…`);
  - `package.json` `imports` (`#x`);
  - nuxt / svelte / quasar configs;
  - aliases computed at runtime;
  - RegExp `find` keys;
  - tsconfig `include` / `files`, so a config applies to every file below its folder.
- **Cost.** Up to 13 file-existence checks per folder per phase, one per config name, all cached.

## COMPLETION DISPUTED (review 2026-10-31, 2db08bd)

DEFECTIVE (P1): The alias lookup walks upwards past a nested app's own boundary: a Laravel root's vite alias `'@'` → `resources/js` applies to `frontend/` (a Vue CLI app with its own package.json and no alias config), so `frontend/src/App.vue`'s `@/views/Home.vue` links `resources/js/views/Home.vue`. `tests/legacy-imports.test.ts` asserts the root `~` applies to `web/` although `web/` has its own vite.config.js. P2: chained `.set()` aliases, backslash `path.resolve` segments. Remediation: M3-09-R1. See `reviews/REVIEW-2026-10-31-2db08bd25e13.md`.
