# M5-25-R4 — Go: a parenthesised receiver type is indexed

Planned in `iterations/M5-25-R4.md`. Source: `reports/M5-25-R2.md` (Limitations). Based on develop `03ca6f6`.

## Delivered

- **`queries/go/symbols.scm`:** the method pattern takes six more receiver types, one pair of parentheses outside or inside the pointer, for a plain and a generic type: `(Box)`, `(Box[T])`, `(*Box)`, `(*Box[T])`, `*(Box)`, `*(Box[T])`. The scope is the bare type name. The tree-sitter-go shapes were checked by parsing (`(parenthesized_type (generic_type …))`, `(parenthesized_type (pointer_type …))`, `(pointer_type (parenthesized_type …))`). Each receiver type node matches one alternative only, so no method is captured twice.
- **`src/parsers/generic-wasm-parser.ts`:** `goTypeParameter` looks through pointers and parentheses of the receiver type. Without it, `[]T{}` in `func (b (Box[T])) Get()` linked a project type named `T` in another package.
- **`src/core/extractor-version.ts`:** `EXTRACTOR_VERSION` 21 with its comment line (develop has 19; Lane F takes 20).
- **`tests/go-qualified-instantiation.test.ts`:** one new test over a synthetic workspace, scanned with the real CLI.

## Limitations

- One pair of parentheses only. `((Box))` or `(*(Box))` is legal Go that gofmt leaves as written but nobody writes; a tree-sitter query cannot recurse, and each further level would double the alternatives.
- Unchanged from M5-25-R2: interface methods are no symbols.
