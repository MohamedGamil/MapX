## Changed existing test

`tests/architecture-scc.test.ts` "reports the same cycle smells on the known graph as before" pinned the sorted `involvedFiles` (`[d, e, e]` …), the behaviour this task changes. That expectation moved, updated to path order, into the new AC1 test; the descriptions and severity pins stay. The 20,000-file test's set-equality check became an exact path-order check.

## Limitations

- The dedup also stopped reordering other smells' files: a layer violation's `[source, target]` now stays in that order instead of being sorted. Nothing in the repo relied on the sorted order (all other tests pass), and the dedup key is unchanged (type plus the sorted set).
- AC2 is a timing test. The margins are about 4.5x on both sides of the CPU budget (linear about 0.33 s, quadratic about 4.1 s) plus the ratio check, but a much faster or much slower machine moves both.
- The worker still has its own markdown/HTML/CSS/YAML/JSON reference extractors next to `StaticFileParser`; only the JSONC normaliser is shared now. Not in this task's findings.

Changelog: Cyclic-dependency smells now list their files in cycle order, each once, and JSON/JSONC files with `key:`-like text inside strings keep their `$ref`/`extends` links when parsed in worker threads (M0-32-R2).
