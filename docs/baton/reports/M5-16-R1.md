# M5-16-R1 report: score-arch scores smells

Planned in `iterations/M5-16-R1.md`. Built on develop `accf69f` plus M5-24-R2 and M5-16-R2.

## Delivered

- **Labels** `tests/fixtures/arch-rules/expected-smells.json` (76 rows), apart from `expected-findings.json`, so another lane can add pypi rows to the findings without touching it. `complete[app]` lists, for each of the 10 apps, the kinds whose labels are complete: `layer-violation`, `vendor-leak`, `layer-cycle`, `layer-skip`, `deprecated-usage`, `undeclared-dependency`, `dev-dependency-in-prod`, `baseline-debt`, `architecture-config`, `orphan-element`. Every row has an `evidence` string.
- **Scorer** `scripts/eval/score-arch.ts`: `scoreSmells` pairs rows and smells one to one by type, involved files and layers (as sets), and a description substring where the identity is a package. Only the complete kinds of each app count. `--json` gains `smells` (`kinds` with expected, reported, matched, recall, precision; `misses`; `extras`); the text output has a line per kind; `--min-recall` and `--min-precision` apply.
- **Defect found by the labels and fixed** (`src/arch/smells.ts`): `dev-dependency-in-prod` flagged Go test files (`infrastructure/http_gateway_test.go`, `domain/order_test.go`) because their role is not `test`. Three false positives, precision 12/15. A test file is not production code, so the smell now also exempts test files by conventional name (`_test.go`, `test_*.py`, `*_test.py`, `*.spec.ts`, `*Test.php` and similar). No label was changed.
- **Docs:** `docs/benchmarking.md`, `docs/architecture-rules.md` (the exemption).

## Limitations

- Four smell kinds are unlabelled (above).
- The smells are read in process (`currentSmells`) after the CLI scan and `check`, not by parsing `mapx arch --smells`; the function is what the CLI, MCP and dashboard call.
- A kind with no rows has precision `null`; a false positive shows in `extras` and fails the fixture test, but not the thresholds.

## Review

Changes after the review of d6c4945 (the sections above describe the first delivery; where they differ, this one is current).

- **Label evidence.** 70 of 76 rows cited only other label files. Now all 90 rows cite the fixture line (`path:line` and the line's text) that makes them true: the importing or instantiating source line and the rule line of the source layer's configuration for a violation; the import line and the manifest or lock lines for a package row; the edges of every cycle; the baseline lines for baseline-debt and the stale entry. The citations are looked up in the files by script (`path:N` checked to exist by `tests/arch-fixture.test.ts`), the truth of each row still comes from the labels of `expected-findings.json` and `expected-externals.json` and from reading the sources. Rows for the apps develop added (`python-pip`, `python-poetry`, `python-poetry-legacy`) are included: 90 rows, not 76.
- **`left-pad` (ts, `Tooling.ts`).** The first evidence said "a known package with direct false". It is in no manifest and no lock file; the label stays, because AR-18 defines `undeclared-dependency` as a package that is "not a direct dependency in the manifest (transitive only), or is missing entirely". The evidence now says so, and for the transitive ones (semver, the Go modules, urllib3) it cites the lock or `go.mod` line where they appear without being a direct dependency.
- **Zero-row kinds.** `vendor-leak`, `layer-skip`, `deprecated-usage` and `orphan-element` had no row. A small smell-only app, `tests/fixtures/arch-rules/ts-smells` (listed under `apps` in `expected-smells.json`, so `expected-findings.json` is untouched and lane J and K can keep adding rows there), now carries one positive for each: Controller imports `pg`, which Repository keeps private; Controller reaches Repository past Service on a `+` chain; Service calls a `@deprecated` helper; `src/legacy/Dead.ts` is in no layer and nothing imports it. All ten kinds now have positives, so none has precision `null`. The "orphan-element: none" claim for the other apps is backed by the orphan exemptions and positives of M5-16-R2 and by precision on those apps (any report is an extra and fails the run).
- **Floors.** I made the registered command enforce them: with `expected-smells.json` present, a missed row or a smell of a complete kind that no row labels is a failure (`failures`, exit 1) with or without thresholds. Test: `tests/arch-fixture.test.ts` "a missed row and an unlabelled smell each fail the run" (a copy of the fixture with the skip row removed, and with its layers changed). `floors.json` is unchanged, because score-arch is not in `npm run eval`.
- **Test files, one definition.** `dev-dependency-in-prod` no longer has its own list of test file names (which missed `*.cy.ts`, `e2e/`, `src/testing/`, `test-utils`, `vitest.setup`, `*.e2e-spec.ts`, `*IT.java`, `*_spec.rb`, `*.spec.vue`, `tests.py`). It relies on the `test` role, and the role classifier's test rule is now `isTestPath` (`src/core/role-classifier.ts`, M5-16-R2's commit), which has those names. Roles are recomputed at the end of every scan and sync, so no extractor bump. Tests: `tests/role-classifier.test.ts` (a table of 27 test paths and 14 non-tests, `Latest.java` and `Wait.java` among them) and `tests/external-refs.test.ts` "test files, by their conventional names". Mutation: the old rule in `isTestPath` fails both.
- **Scorer.** `--app` accepts a smell-only app. Mutations: the two floor failures removed, smell-only apps not scanned and the `complete` filter ignored each fail the fixture tests.
